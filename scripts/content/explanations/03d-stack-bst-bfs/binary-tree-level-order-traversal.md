## Задача простыми словами

Дан корень двоичного дерева. Нужно вернуть значения узлов **по уровням**: массив массивов, где `i`-й внутренний массив — значения узлов глубины `i` слева направо.

Пример: `[3, 9, 20, null, null, 15, 7]` → `[[3], [9, 20], [15, 7]]`.

```
    3         уровень 0: [3]
   / \
  9   20      уровень 1: [9, 20]
     /  \
    15   7    уровень 2: [15, 7]
```

## Наивный подход

Можно сначала найти высоту дерева `h`, а затем для каждой глубины `d` от `0` до `h - 1` отдельным рекурсивным обходом собирать узлы этой глубины:

```ts naive
for (let d = 0; d < height(root); d++) {
  const level: number[] = [];
  collect(root, d, level); // DFS, кладёт узлы на глубине d слева направо
  result.push(level);
}
```

Это верно, но каждый проход заново спускается от корня через все верхние уровни. Для сбалансированного дерева выходит `O(n log n)`, для вырожденного — `O(n²)`. Лишняя работа — повторное посещение верхних уровней ради каждого нижнего.

## Ключевое наблюдение

Если у нас уже есть **все узлы одного уровня** слева направо, то следующий уровень получается из них за один проход: это дети этих узлов, взятые в порядке «по родителям слева направо, у каждого левый перед правым». Значит, можно хранить уровень целиком в массиве `level`, выписывать его значения в ответ и строить из него массив `next`. Каждый массив — ровно один уровень, так что границу уровня даже не нужно искать.

## Техники

### Обход в ширину (BFS) по уровням: текущий и следующий массив

**Что это.** BFS посещает узлы в порядке возрастания расстояния от корня — уровень за уровнем. Вместо одной общей очереди здесь два массива: `level` — текущий уровень, `next` — собираемый следующий. Подробнее — во вкладке «Теория».

**Типичный шаблон.** Его стоит выучить наизусть — он же решает Right Side View, Zigzag, Average of Levels:

```ts naive
let level = [root];
while (level.length > 0) {
  обработать(level); // весь уровень сразу
  const next = [];
  for (const node of level) {
    if (node.left) next.push(node.left);
    if (node.right) next.push(node.right);
  }
  level = next;
}
```

**Когда применять.** Любая задача, где важны уровни дерева или кратчайшие расстояния в невзвешенном графе.

### Почему не `shift()`

В JavaScript нет встроенной очереди. Классический BFS с одной очередью и `queue.shift()` платит `O(n)` за каждое извлечение, потому что `shift` сдвигает все элементы. С двумя массивами мы ничего не извлекаем из начала — только читаем `level` циклом `for...of` и делаем `push` в `next`, всё за `O(1)` на узел.

## Разбор кода

```ts
function levelOrder(root: TreeNode | null): number[][] {
  const result: number[][] = [];
  if (root === null) return result;
```

Пустое дерево — пустой ответ (не `[[]]`!). Дальше корень гарантированно есть.

```ts
  // Обходим дерево по уровням, каждый уровень — слева направо
  let level: TreeNode[] = [root];
```

Нулевой уровень — один корень. `let`, потому что в конце каждой итерации массив заменяется следующим уровнем.

```ts
  while (level.length > 0) {
    // Значения текущего уровня — очередной массив ответа
    result.push(level.map((node) => node.val));
```

Пока уровень не пуст, превращаем его узлы в значения через `map` и кладём в ответ. Порядок в `level` — слева направо, поэтому и в ответе он такой же. `map` создаёт **новый** массив на каждом уровне, так что уровни не смешиваются.

```ts
    // Собираем следующий уровень в том же порядке: слева направо
    const next: TreeNode[] = [];
    for (const node of level) {
      if (node.left !== null) next.push(node.left);
      if (node.right !== null) next.push(node.right);
    }
```

Проходим по узлам уровня слева направо и у каждого добавляем сначала левого, потом правого ребёнка. Пустых детей пропускаем — в `next` попадают только настоящие узлы.

```ts
    level = next;
  }

  return result;
}
```

Переходим к следующему уровню. Когда у последнего уровня нет детей, `next` пуст, `level.length === 0`, и цикл завершается.

## Трассировка

Дерево `[3, 9, 20, null, null, 15, 7]`.

1. `level = [3]`.
   - `result = [[3]]`.
   - Дети `3`: `9`, `20` → `next = [9, 20]`.
2. `level = [9, 20]`.
   - `result = [[3], [9, 20]]`.
   - У `9` детей нет; у `20` — `15`, `7` → `next = [15, 7]`.
3. `level = [15, 7]`.
   - `result = [[3], [9, 20], [15, 7]]`.
   - Детей нет → `next = []`.
4. `level = []` — цикл завершён.

Ответ: `[[3], [9, 20], [15, 7]]`.

## Почему это работает

Инвариант: в начале каждой итерации `while` массив `level` содержит **все** узлы одной глубины `d` и только их, слева направо.

- Для `d = 0` это `[root]`.
- Каждый узел глубины `d + 1` — ребёнок ровно одного узла глубины `d`, поэтому `next` содержит все узлы глубины `d + 1` и ничего лишнего. Порядок «по родителям слева направо, у каждого левый перед правым» — это и есть порядок слева направо на уровне `d + 1`.

Значит, `i`-я итерация выписывает ровно уровень `i`, и уровни добавляются в ответ сверху вниз.

## Пограничные случаи

- **Пустое дерево**: `[]`.
- **Один узел**: `[[root.val]]`.
- **Вырожденное дерево-«палка»** (`[1, null, 2, null, 3]`): `n` уровней по одному узлу — `[[1], [2], [3]]`.
- **Неполные уровни** (пропуски `null`): в уровень попадают только существующие узлы, пустот в ответе нет.
- **Широкое дерево**: на нижнем уровне до `n/2` узлов — все в одном массиве.

## Сложность

- **Время `O(n)`**: каждый узел ровно один раз попадает в `next` и один раз обрабатывается в `map` и в цикле `for`.
- **Память `O(w)`** без учёта ответа: одновременно живут только `level` и `next`, каждый не больше максимальной ширины уровня `w` (до `n/2` для полного дерева). Сам ответ — `O(n)`.

На собеседовании часто пишут вариант с **одной очередью** и «снимком размера уровня» `levelSize = queue.length` перед циклом — он эквивалентен. В JS его делают с указателем головы `head` вместо `shift()`, иначе получится `O(n²)`.

## Типичные ошибки

1. **Добавлять детей прямо в `level`**, по которому сейчас идёт цикл, → уровни сливаются, а цикл обходит всё дерево за одну итерацию.
2. **Забыть `level = next`** → бесконечный цикл на первом уровне.
3. **Возвращать `[[]]` для пустого дерева** вместо `[]`.
4. **Добавлять в `next` `null`-детей** без проверки → обращение к `null.val` на следующем уровне.
5. **Сначала правый, потом левый ребёнок** → каждый уровень выйдет зеркально.

## Как узнать такую задачу

- В условии фигурируют **уровни** дерева: «по уровням», «слой за слоем», «на каждой глубине».
- Ответ — массив массивов, сгруппированный по глубине.
- Кратчайшее число шагов в невзвешенном графе — тот же BFS.
- Похожие задачи: Level Order Traversal II (снизу вверх), Zigzag Level Order Traversal, Binary Tree Right Side View, Average of Levels in Binary Tree, Minimum Depth of Binary Tree, N-ary Tree Level Order Traversal.
