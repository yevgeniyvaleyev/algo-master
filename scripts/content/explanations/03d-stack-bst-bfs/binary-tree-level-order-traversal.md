## Задача простыми словами

Дан корень двоичного дерева. Нужно вернуть значения узлов **по уровням**: массив массивов, где `i`-й внутренний массив — значения узлов глубины `i` слева направо.

Пример: `[3, 9, 20, null, null, 15, 7]` → `[[3], [9, 20], [15, 7]]`.

```
    3         уровень 0: [3]
   / \
  9   20      уровень 1: [9, 20]
     /  \
    15   7    уровень 2: [15, 7]
```

## Наивный подход

Можно сначала найти высоту дерева `h`, а затем для каждой глубины `d` от `0` до `h - 1` отдельным рекурсивным обходом собирать узлы этой глубины:

```ts naive
for (let d = 0; d < height(root); d++) {
  const level: number[] = [];
  collect(root, d, level); // DFS, кладёт узлы на глубине d слева направо
  result.push(level);
}
```

Это верно, но каждый проход заново спускается от корня через все верхние уровни. Для сбалансированного дерева выходит `O(n log n)`, для вырожденного — `O(n²)`. Лишняя работа — повторное посещение верхних уровней ради каждого нижнего.

## Ключевое наблюдение

Если обходить дерево **в ширину** с очередью, узлы и так выходят из очереди уровень за уровнем: все узлы глубины `d` раньше всех узлов глубины `d + 1`. Остаётся только понять, **где кончается уровень**. Для этого перед обработкой уровня достаточно зафиксировать, сколько узлов сейчас в очереди: ровно столько узлов и составляют текущий уровень, а всё, что добавится во время обработки, — уже следующий.

## Техники

### Обход в ширину (BFS) с очередью и фиксацией размера уровня

**Что это.** BFS посещает узлы в порядке возрастания расстояния от корня. Реализуется через **очередь** (FIFO): достаём из начала, детей добавляем в конец. Подробнее — во вкладке «Теория».

**Типичный шаблон.** «Снимок размера уровня»:

```ts naive
while (очередь не пуста) {
  const size = длина очереди; // столько узлов на текущем уровне
  for (let i = 0; i < size; i++) {
    const node = извлечь из очереди;
    обработать(node);
    добавить детей node в конец очереди;
  }
  // здесь уровень полностью обработан
}
```

**Когда применять.** Любая задача, где важны уровни или кратчайшие расстояния в невзвешенном графе.

### Очередь на массиве с указателем головы

В JavaScript нет встроенной очереди. `Array.prototype.shift()` удаляет первый элемент, но **сдвигает** все остальные — это `O(n)` на операцию и `O(n²)` на весь обход. Вместо этого массив только растёт, а «голову» очереди показывает индекс `head`: извлечение — это `queue[head++]`, `O(1)`. Цена — элементы не удаляются из памяти, но для одного обхода дерева это всё равно `O(n)`.

## Разбор кода

```ts
function levelOrder(root: TreeNode | null): number[][] {
  const result: number[][] = [];
  if (root === null) return result;
```

Пустое дерево — пустой ответ (не `[[]]`!). Дальше корень гарантированно есть.

```ts
  // Очередь на массиве с указателем головы: shift() был бы O(n)
  const queue: TreeNode[] = [root];
  let head = 0;
```

Очередь начинается с корня. Элементы `queue[head..]` — ещё не обработанные узлы; всё левее `head` — уже обработано.

```ts
  while (head < queue.length) {
    // Все узлы между head и концом очереди — ровно текущий уровень
    const levelSize = queue.length - head;
    const level: number[] = [];
```

Очередь непуста, пока `head < queue.length`. В начале каждой итерации в очереди лежат только узлы одного уровня (это инвариант, см. ниже), поэтому их количество `queue.length - head` — размер уровня. Запоминаем его в `levelSize` **до** того, как начнём добавлять детей, иначе граница уровня «поплывёт».

```ts
    for (let i = 0; i < levelSize; i++) {
      const node = queue[head++];
      level.push(node.val);
```

Ровно `levelSize` раз извлекаем узел из головы очереди (`head++` сдвигает голову) и записываем его значение в массив уровня. Узлы извлекаются в том порядке, в каком добавлялись, — слева направо.

```ts
      // Дети попадают в конец очереди — это уже следующий уровень
      if (node.left !== null) queue.push(node.left);
      if (node.right !== null) queue.push(node.right);
    }
```

Дети добавляются в конец: сначала левый, потом правый. Они окажутся **после** всех оставшихся узлов текущего уровня, поэтому не попадут в текущий `level` — цикл `for` ограничен заранее зафиксированным `levelSize`.

```ts
    result.push(level);
  }

  return result;
}
```

Уровень готов — добавляем его в ответ. Когда у последнего уровня нет детей, после цикла `head === queue.length`, и `while` завершается.

## Трассировка

Дерево `[3, 9, 20, null, null, 15, 7]`.

1. `queue = [3]`, `head = 0`. `levelSize = 1`.
   - Извлекаем `3` (`head = 1`), `level = [3]`. Добавляем `9`, `20`: `queue = [3, 9, 20]`.
   - `result = [[3]]`.
2. `head = 1`, `levelSize = 3 - 1 = 2`.
   - Извлекаем `9` (`head = 2`), детей нет. `level = [9]`.
   - Извлекаем `20` (`head = 3`), добавляем `15`, `7`: `queue = [3, 9, 20, 15, 7]`. `level = [9, 20]`.
   - `result = [[3], [9, 20]]`.
3. `head = 3`, `levelSize = 5 - 3 = 2`.
   - Извлекаем `15` (`head = 4`), затем `7` (`head = 5`). Детей нет. `level = [15, 7]`.
   - `result = [[3], [9, 20], [15, 7]]`.
4. `head = 5 = queue.length` — цикл завершён.

Ответ: `[[3], [9, 20], [15, 7]]`.

## Почему это работает

Инвариант: в начале каждой итерации `while` участок `queue[head..]` содержит **все** узлы одной глубины `d` и только их, слева направо.

- Для `d = 0` это `[root]`.
- За итерацию мы извлекаем ровно `levelSize` узлов — весь уровень `d` — и добавляем в конец их детей. Каждый узел глубины `d + 1` — ребёнок ровно одного узла глубины `d`, поэтому после итерации в `queue[head..]` лежат все узлы глубины `d + 1`. Порядок «левый, затем правый, по родителям слева направо» даёт порядок слева направо.

Значит, `i`-я итерация собирает ровно уровень `i`, и уровни добавляются в ответ сверху вниз.

## Пограничные случаи

- **Пустое дерево**: `[]`.
- **Один узел**: `[[root.val]]`.
- **Вырожденное дерево-«палка»**: `n` уровней по одному узлу.
- **Неполные уровни** (пропуски `null`): в уровень попадают только существующие узлы, пустот в ответе нет.
- **Широкое дерево**: на нижнем уровне до `n/2` узлов — все в одном массиве.

## Сложность

- **Время `O(n)`**: каждый узел ровно один раз добавляется в очередь и один раз извлекается; все операции — `O(1)` благодаря указателю `head`.
- **Память `O(n)`**: массив `queue` в итоге содержит все `n` узлов (мы не удаляем обработанные), и ответ тоже хранит `n` значений.

## Типичные ошибки

1. **Не фиксировать `levelSize`** и писать `for (...; i < queue.length - head; ...)` → граница меняется по ходу цикла, уровни сливаются.
2. **`queue.shift()` в цикле** → `O(n)` на каждое извлечение, `O(n²)` на больших деревьях.
3. **Возвращать `[[]]` для пустого дерева** вместо `[]`.
4. **Добавлять в очередь `null`-детей** без проверки → обращение к `null.val`.
5. **Создавать `level` вне цикла `while`** → все уровни пишутся в один и тот же массив.

## Как узнать такую задачу

- В условии фигурируют **уровни** дерева: «по уровням», «слой за слоем», «на каждой глубине».
- Ответ — массив массивов, сгруппированный по глубине.
- Кратчайшее число шагов в невзвешенном графе — тот же BFS.
- Похожие задачи: Level Order Traversal II (снизу вверх), Zigzag Level Order Traversal, Binary Tree Right Side View, Average of Levels in Binary Tree, Minimum Depth of Binary Tree, N-ary Tree Level Order Traversal.
