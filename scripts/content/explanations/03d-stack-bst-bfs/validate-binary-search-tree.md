## Задача простыми словами

Дан корень двоичного дерева. Нужно проверить, является ли оно корректным **двоичным деревом поиска** (BST): для каждого узла все значения в левом поддереве **строго меньше** его значения, все значения в правом поддереве **строго больше**, и оба поддерева тоже BST.

Пример: дерево `[2, 1, 3]` — корректное BST (`1 < 2 < 3`). А вот дерево ниже — **нет**, хотя каждый узел правильно сравнивается со своими детьми:

```
    5
   / \
  4   6
     / \
    3   7
```

Узел `3` лежит в **правом** поддереве узла `5`, значит, должен быть больше `5`. Это нарушение не видно, если смотреть только на пару «родитель — ребёнок» (`3 < 6` — порядок).

## Наивный подход

Первая (неверная) идея — проверить каждый узел только с прямыми детьми: `left.val < node.val < right.val`. Пример выше показывает, что этого **недостаточно**: условие BST касается всего поддерева.

Корректная лобовая версия — для каждого узла найти максимум левого поддерева и минимум правого:

```ts naive
function isValid(node: TreeNode | null): boolean {
  if (!node) return true;
  if (node.left && maxOf(node.left) >= node.val) return false;
  if (node.right && minOf(node.right) <= node.val) return false;
  return isValid(node.left) && isValid(node.right);
}
```

Здесь `maxOf`/`minOf` обходят всё поддерево. Каждый узел просматривается заново для каждого своего предка — `O(n · h)`, а на вырожденном дереве `O(n²)`. Лишняя работа в том, что одни и те же поддеревья снова и снова обходятся в поисках минимума и максимума.

## Ключевое наблюдение

Посмотрим на условие «сверху вниз». Каждый предок накладывает на узел ограничение: если мы ушли от предка влево — узел должен быть меньше предка, если вправо — больше. Все эти ограничения сжимаются в **один открытый интервал** `(low, high)`:

- `high` — значение ближайшего предка, от которого мы ушли влево;
- `low` — значение ближайшего предка, от которого мы ушли вправо.

Передавая интервал вниз по рекурсии, мы проверяем каждый узел **за `O(1)`** против всех предков сразу. При спуске влево верхняя граница становится `node.val`, при спуске вправо — нижняя.

## Техники

### Рекурсивный DFS с передачей ограничений вниз

**Что это.** Обход в глубину, где рекурсивная функция получает не только узел, но и **контекст от предков** — здесь допустимый интервал значений. Информация течёт сверху вниз (top-down), а результат — снизу вверх.

**Типичный шаблон.** `dfs(node, state)`: проверить узел относительно `state`, затем вызвать `dfs(child, newState)` для детей. Так решают задачи «сумма пути от корня», «максимальная разница предок–потомок», «хорошие узлы» (Count Good Nodes).

**Как применяется здесь.** `state` — пара `(low, high)`. Для левого ребёнка интервал сужается сверху, для правого — снизу.

### Свойство BST

**Что это.** BST требует порядка для **всех** узлов поддерева, а не только для детей. Эквивалентная формулировка: in-order обход выдаёт строго возрастающую последовательность — это даёт альтернативное решение (обход с запоминанием предыдущего значения). Подробнее — во вкладке «Теория».

Вспомогательная функция `check` отвечает на вопрос: «является ли поддерево с корнем `node` корректным BST, все значения которого строго внутри `(low, high)`?». Границы — обычные числа; для корня используются `-Infinity` и `Infinity`. Комментарий напоминает, почему это безопасно: значения узлов могут быть равны `-2³¹` и `2³¹ - 1`, и в других языках используют `null` или `long`, чтобы граница не совпала с реальным значением. В JS бесконечность строго больше любого числа.

```ts
    // Пустое поддерево — корректное BST
    if (node === null) return true;
```

База рекурсии: пустое поддерево ничему не противоречит.

```ts
    // Узел должен быть строго между границами, заданными всеми предками
    if (node.val <= low || node.val >= high) return false;
```

Проверка против **всех** предков сразу. Неравенства нестрогие (`<=`, `>=`), потому что BST в задаче требует строгого порядка: дубликаты запрещены. Узел со значением, равным границе, — нарушение.

```ts
    // Слева всё меньше node.val, справа — всё больше
    return check(node.left, low, node.val) && check(node.right, node.val, high);
  };
```

Левое поддерево наследует нижнюю границу, а верхняя становится `node.val`. Правое — наоборот. Оператор `&&` вычисляется лениво: если левое поддерево некорректно, правое даже не проверяется.

```ts
  return check(root, -Infinity, Infinity);
}
```

Корень ничем не ограничен.

## Трассировка

Дерево из условия (некорректное):

```
    5
   / \
  4   6
     / \
    3   7
```

1. `check(5, -∞, +∞)`: `-∞ < 5 < +∞` — ок. Идём влево.
2. `check(4, -∞, 5)`: `4 < 5` — ок. Оба ребёнка `null` → `true`.
3. Левое поддерево корректно, идём вправо: `check(6, 5, +∞)`: `5 < 6` — ок.
4. `check(3, 5, 6)`: `3 <= 5` → **`false`**.
5. `&&` в шаге 3 получает `false`, узел `7` не проверяется. Ответ `false`.

Корректное дерево `[2, 1, 3]`:

1. `check(2, -∞, +∞)` — ок.
2. `check(1, -∞, 2)` — ок, дети `null`.
3. `check(3, 2, +∞)` — ок, дети `null`.

Ответ `true`.

## Почему это работает

Инвариант: при вызове `check(node, low, high)` интервал `(low, high)` — это **в точности** множество значений, допустимых для `node` всеми его предками.

- Для корня предков нет — интервал `(-∞, +∞)`.
- Если `node` допустим, его левый ребёнок должен удовлетворять тем же ограничениям **и** быть меньше `node.val` — это `(low, node.val)`; правый — `(node.val, high)`. Так как `low < node.val < high`, интервалы непусты и вложены.

Дерево — BST тогда и только тогда, когда каждый узел удовлетворяет условиям всех предков (для каждого предка узел лежит в нужном поддереве). Функция проверяет ровно это для каждого узла, поэтому ответ верен в обе стороны.

## Пограничные случаи

- **Один узел**: всегда BST.
- **Дубликаты** (`[2, 2, 2]`): `2 >= 2` → `false`; дубликаты в этой задаче запрещены.
- **Крайние значения** (`[2147483647]` или `[-2147483648]`): бесконечные границы строго за их пределами, ответ `true`.
- **Нарушение глубоко внизу** (как в примере): ловится, потому что границы передаются через все уровни.
- **Вырожденное дерево-«палка»**: глубина рекурсии `n`; при `n ≤ 10⁴` это допустимо для стека JS.

## Сложность

- **Время `O(n)`**: каждый узел проверяется ровно один раз за `O(1)` (при раннем `false` — ещё меньше).
- **Память `O(h)`**: глубина рекурсии равна высоте дерева — от `O(log n)` для сбалансированного до `O(n)` для вырожденного.

## Типичные ошибки

1. **Сравнивать только с прямыми детьми** → пропускается нарушение «внук правее деда» (пример выше).
2. **Строгие сравнения `<`/`>` вместо `<=`/`>=`** в проверке нарушения → дубликаты ошибочно принимаются.
3. **Границы `-2³¹` и `2³¹ - 1`** вместо бесконечностей → узел с крайним допустимым значением (например, `[2147483647]`) отвергается проверкой `>=`.
4. **In-order со сравнением с `prev`, где `prev` начально `0` или `-1`** → неверно для деревьев с отрицательными значениями; нужен `-Infinity` или `null`.
5. **Перепутать, какую границу обновлять**: для левого ребёнка меняется `high`, а не `low`.

## Как узнать такую задачу

- Нужно проверить **свойство, зависящее от всех предков** узла (порядок BST, ограничения по пути).
- Условие формулируется через «все узлы поддерева», а не «дети» — сигнал передавать ограничения сверху вниз.
- Альтернативный признак: «проверить отсортированность» дерева → in-order обход.
- Похожие задачи: Kth Smallest Element in a BST, Recover Binary Search Tree, Count Good Nodes in Binary Tree, Maximum Difference Between Node and Ancestor, Largest BST Subtree.
