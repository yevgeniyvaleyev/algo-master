## Задача простыми словами

Дано арифметическое выражение в **обратной польской записи** (RPN) — массив токенов `tokens`, где оператор пишется **после** своих операндов. Операторы: `+`, `-`, `*`, `/`; деление целочисленное с округлением **к нулю**. Нужно вычислить значение выражения.

Пример: `["2", "1", "+", "3", "*"]` означает `(2 + 1) * 3 = 9`. Скобки не нужны: порядок вычислений полностью задан порядком токенов.

## Наивный подход

Можно действовать «как человек на бумаге»: найти в массиве первый оператор, вычислить его над двумя токенами перед ним, заменить эти три токена результатом и повторять, пока не останется одно число.

```ts naive
while (tokens.length > 1) {
  const i = tokens.findIndex((t) => '+-*/'.includes(t) && t.length === 1);
  const value = apply(tokens[i], Number(tokens[i - 2]), Number(tokens[i - 1]));
  tokens.splice(i - 2, 3, String(value));
}
```

Это работает, но каждая итерация заново ищет оператор с начала массива (`O(n)`) и сдвигает хвост при `splice` (`O(n)`). Операторов до `n/2`, итого `O(n²)`. Лишняя работа — повторный просмотр уже обработанного начала массива: всё, что левее найденного оператора, мы уже видели, и там нет операторов, которые можно применить.

## Ключевое наблюдение

В RPN оператор всегда применяется к **двум последним готовым операндам**, которые стоят перед ним. «Последние готовые» — это вершина стека. Значит, достаточно одного прохода слева направо:

- число — кладём в стек;
- оператор — снимаем два верхних значения, вычисляем, кладём результат обратно (он сам становится операндом).

В конце в стеке остаётся одно число — ответ.

## Техники

### Стек для вычисления выражений

**Что это.** Стек (LIFO) — массив с `push`/`pop` за `O(1)`. Подробнее — во вкладке «Теория».

**Типичный шаблон.** Стек операндов — стандартный способ вычислять постфиксные выражения. Для обычной (инфиксной) записи применяют алгоритм Дейкстры «сортировочная станция» (shunting-yard), который переводит выражение в RPN, используя второй стек для операторов. RPN — уже «готовый» результат этого перевода, поэтому хватает одного стека.

**Как применяется здесь.** Стек хранит числа и результаты вычисленных подвыражений. Каждое подвыражение «сворачивается» в одно число, как только встречен его оператор.

### Порядок операндов у некоммутативных операций

Для `-` и `/` важно, какой операнд левый. Первым из стека снимается **правый** (он был положен последним), затем левый. Перепутать их — самая частая ошибка.

### Деление с округлением к нулю

В JS `/` — дробное деление. Для целочисленного деления «к нулю» нужен `Math.trunc`, а не `Math.floor`: `-7 / 2 = -3.5`, `Math.trunc` даёт `-3` (как требуется), а `Math.floor` — `-4`.

## Разбор кода

```ts
function evalRPN(tokens: string[]): number {
  // Стек операндов: числа и уже вычисленные подвыражения
  const stack: number[] = [];
```

Стек сразу хранит числа (`number`), а не строки, — переводим токен в число один раз при добавлении.

```ts
  for (const token of tokens) {
    if (token === '+' || token === '-' || token === '*' || token === '/') {
```

Один проход по токенам. Проверка оператора — **точным сравнением** строк. Это важно: токен `"-11"` начинается с минуса, но это число, и проверка вида `token[0] === '-'` ошибочно приняла бы его за оператор.

```ts
      // Оператор применяется к двум последним операндам.
      // Порядок важен: сначала снимаем ПРАВЫЙ операнд, затем левый
      const b = stack.pop()!;
      const a = stack.pop()!;
      let result: number;
```

Снимаем два операнда. `b` — правый (положен позже), `a` — левый. Восклицательный знак `!` говорит TypeScript, что `pop` не вернёт `undefined`: выражение по условию корректно, операндов всегда хватает.

```ts
      switch (token) {
        case '+':
          result = a + b;
          break;
        case '-':
          result = a - b;
          break;
        case '*':
          result = a * b;
          break;
        default:
          // Деление с округлением к нулю (Math.floor для отрицательных дал бы не то)
          result = Math.trunc(a / b);
      }
```

Вычисляем `a op b` именно в таком порядке. `default` — это `/` (других операторов внутри этой ветки нет). `Math.trunc` отбрасывает дробную часть, округляя к нулю для обоих знаков. По условию деления на ноль не бывает.

```ts
      // Результат подвыражения — снова операнд
      stack.push(result);
```

Результат кладём обратно: для следующих операторов он — обычный операнд. Так подвыражение любой сложности «сворачивается» в одно число на стеке.

```ts
    } else {
      // Число (в том числе отрицательное, например "-11")
      stack.push(Number(token));
    }
  }
```

Всё, что не оператор, — число. `Number("-11")` корректно даёт `-11`.

```ts
  // В корректном выражении в стеке остаётся ровно одно значение
  return stack[0];
}
```

Каждый оператор уменьшает размер стека на 1 (снял два, положил одно), каждое число увеличивает на 1. В корректном выражении чисел на одно больше, чем операторов, — в конце в стеке ровно одно значение.

## Трассировка

`tokens = ["4", "13", "5", "/", "+"]` (это `4 + 13 / 5`):

1. `"4"` → `push(4)`. Стек `[4]`.
2. `"13"` → `push(13)`. Стек `[4, 13]`.
3. `"5"` → `push(5)`. Стек `[4, 13, 5]`.
4. `"/"` → `b = 5`, `a = 13`, `Math.trunc(13 / 5) = Math.trunc(2.6) = 2`. Стек `[4, 2]`.
5. `"+"` → `b = 2`, `a = 4`, `4 + 2 = 6`. Стек `[6]`.

Ответ: `6`.

Проверка порядка операндов на `["3", "10", "-"]`: `b = 10`, `a = 3`, `a - b = -7` (а не `7`). Это и есть `3 - 10`.

## Почему это работает

Инвариант: после обработки префикса токенов стек содержит значения всех **полностью готовых** подвыражений этого префикса, ещё не использованных как операнды, — в порядке их появления слева направо.

- Число — готовое подвыражение из одного токена; кладём его в конец.
- Оператор в RPN относится к двум **ближайшим слева** готовым подвыражениям — это две вершины стека. Мы заменяем их одним готовым подвыражением, сохраняя порядок.

Когда токены закончились, всё выражение — одно готовое подвыражение, и оно единственное на стеке.

## Пограничные случаи

- **Одно число** (`["18"]`): сразу `push`, ответ `18`.
- **Отрицательные числа** (`"-11"`): не путаются с оператором `-` благодаря точному сравнению.
- **Деление отрицательных** (`-7 / 2`): `Math.trunc` даёт `-3`, как требует условие.
- **Деление с результатом меньше единицы** (`6 / -132`): `Math.trunc(-0.045...) = -0`. В JS `-0 === 0`, и дальнейшие вычисления не ломаются.

## Сложность

- **Время `O(n)`**: каждый токен обрабатывается один раз, каждая операция стека — `O(1)`.
- **Память `O(n)`**: в худшем случае (сначала все числа, потом все операторы) в стеке около `n/2` значений.

## Типичные ошибки

1. **Перепутать порядок операндов**: `a = pop(); b = pop(); a - b` → для `-` и `/` знак и значение неверны.
2. **`Math.floor` вместо `Math.trunc`** → неверный ответ при отрицательном частном.
3. **Определять оператор по первому символу** → `"-11"` воспринимается как минус.
4. **`parseInt(a / b)`**: работает в большинстве случаев, но для очень маленьких дробей вроде `1e-7` `parseInt` получает строку `"1e-7"` и возвращает `1`. `Math.trunc` надёжнее.
5. **Хранить в стеке строки** и складывать их через `+` → конкатенация `"2" + "1" = "21"`.

## Как узнать такую задачу

- Выражение задано в **постфиксной** записи («оператор после операндов», «reverse polish»).
- Нужно вычислить вложенное выражение, где результат вычисления сам становится операндом.
- Любой «разбор выражений»: стек операндов (и, для инфиксной записи, стек операторов).
- Похожие задачи: Basic Calculator I/II/III, Decode String, Parse Lisp Expression, построение дерева выражения по постфиксной записи.
