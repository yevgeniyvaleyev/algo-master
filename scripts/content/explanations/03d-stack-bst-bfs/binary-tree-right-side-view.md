## Задача простыми словами

Дан корень двоичного дерева. Представьте, что вы стоите **справа** от дерева и смотрите на него. Нужно вернуть значения узлов, которые вы видите, сверху вниз. На каждом уровне виден ровно один узел — **самый правый** на этом уровне.

Пример: `[1, 2, 3, null, 5, null, 4]` → `[1, 3, 4]`.

```
    1        ← виден 1
   / \
  2   3      ← виден 3
   \   \
    5   4    ← виден 4
```

Важно: самый правый узел уровня не обязательно лежит в правом поддереве корня. В дереве `[1, 2, 3, 4]` узел `4` — левый ребёнок узла `2`, но на своём уровне он единственный, поэтому виден: ответ `[1, 3, 4]`.

## Наивный подход

Частая первая попытка — просто идти от корня всё время вправо:

```ts naive
const result: number[] = [];
for (let node = root; node; node = node.right) result.push(node.val);
```

Это **неверно**: для `[1, 2, 3, 4]` получится `[1, 3]` — узел `4` потерян, потому что правая «ветка» короче левой.

Корректная лобовая версия — для каждой глубины `d` отдельно обходить всё дерево и искать самый правый узел на этой глубине. Это `O(n · h)` (на вырожденном дереве — `O(n²)`): дерево обходится заново для каждого уровня, хотя за один обход можно узнать узлы всех уровней сразу.

## Ключевое наблюдение

«Самый правый на каждом уровне» — это вопрос **про уровни**. Если обходить дерево по уровням (в ширину), и узлы каждого уровня держать **слева направо**, то ответ для уровня — просто его последний элемент. Каждый узел обрабатывается один раз.

## Техники

### Обход дерева в ширину (BFS) по уровням

**Что это.** BFS посещает узлы в порядке удалённости от корня: сначала корень, потом все узлы глубины 1, потом глубины 2 и так далее. Подробнее — во вкладке «Теория».

**Типичный шаблон.** Классическая реализация — очередь, в которой фиксируется размер текущего уровня. Здесь использован эквивалентный и очень наглядный вариант — **два массива**: `level` (текущий уровень) и `next` (следующий):

```ts naive
let level = [root];
while (level.length) {
  обработать уровень(level);
  const next = [];
  for (const node of level) { добавить детей node в next; }
  level = next;
}
```

Границы уровней получаются «бесплатно»: каждый массив — ровно один уровень.

**Когда применять.** Любые вопросы «на каждом уровне»: вид справа/слева, среднее по уровням, максимум в строке, зигзаг, связывание соседей на уровне.

**Как применяется здесь.** Если в `next` добавлять сначала левого, затем правого ребёнка, каждый уровень упорядочен слева направо, и правый край — `level[level.length - 1]`.

## Разбор кода

```ts
function rightSideView(root: TreeNode | null): number[] {
  const result: number[] = [];
  if (root === null) return result;
```

Для пустого дерева ничего не видно — возвращаем пустой массив. Дальше `root` гарантированно не `null`.

```ts
  // Обходим дерево по уровням, каждый уровень — слева направо
  let level: TreeNode[] = [root];
```

Первый уровень состоит из одного корня.

```ts
  while (level.length > 0) {
    // Справа виден последний узел уровня
    result.push(level[level.length - 1].val);
```

Пока уровень непуст, берём его последний узел — он самый правый, потому что уровень упорядочен слева направо. Уровень непуст, так что индекс корректен.

```ts
    // Собираем следующий уровень в том же порядке: слева направо
    const next: TreeNode[] = [];
    for (const node of level) {
      if (node.left !== null) next.push(node.left);
      if (node.right !== null) next.push(node.right);
    }
    level = next;
  }
```

Проходим текущий уровень слева направо и собираем детей: для каждого узла сначала левого, потом правого. Так в `next` дети левых узлов стоят раньше детей правых — следующий уровень тоже упорядочен слева направо. Когда у последнего уровня нет детей, `next` пуст, и цикл завершается.

```ts
  return result;
}
```

В `result` — по одному значению на уровень, сверху вниз.

## Трассировка

Дерево `[1, 2, 3, null, 5, null, 4]`:

```
    1
   / \
  2   3
   \   \
    5   4
```

1. `level = [1]`. Последний — `1`, `result = [1]`. Дети: `2`, `3` → `next = [2, 3]`.
2. `level = [2, 3]`. Последний — `3`, `result = [1, 3]`. Дети: у `2` только правый `5`, у `3` только правый `4` → `next = [5, 4]`.
3. `level = [5, 4]`. Последний — `4`, `result = [1, 3, 4]`. Детей нет → `next = []`.
4. `level = []` — цикл завершён.

Ответ: `[1, 3, 4]`.

Дерево `[1, 2, 3, 4]` (узел `4` — левый ребёнок `2`):

1. `level = [1]` → `result = [1]`, `next = [2, 3]`.
2. `level = [2, 3]` → `result = [1, 3]`, `next = [4]`.
3. `level = [4]` → `result = [1, 3, 4]`.

Узел из левого поддерева виден, потому что на своём уровне он самый правый.

## Почему это работает

Инвариант: в начале каждой итерации `level` содержит **все** узлы одной глубины `d`, упорядоченные слева направо.

- Для `d = 0` это `[root]`.
- Каждый узел глубины `d + 1` — ребёнок ровно одного узла глубины `d`, поэтому попадает в `next` ровно один раз. Узлы правее на уровне `d + 1` — дети узлов правее на уровне `d` (или правые дети того же узла), поэтому порядок «левый ребёнок, затем правый, по узлам слева направо» сохраняет порядок слева направо.

Смотрящий справа видит на каждой глубине самый правый узел, то есть последний элемент `level`. Цикл проходит все глубины сверху вниз.

## Пограничные случаи

- **Пустое дерево**: `[]`.
- **Один узел**: `[root.val]`.
- **Только левые дети** (палка влево): каждый уровень из одного узла, все видны.
- **Левое поддерево глубже правого**: нижние уровни видны через левое поддерево.
- **Полное дерево**: виден правый край.

## Сложность

- **Время `O(n)`**: каждый узел один раз попадает в `next` и один раз обрабатывается в цикле `for`.
- **Память `O(w)`**: одновременно живут два соседних уровня; `w` — максимальная ширина уровня (до `n/2` для полного дерева). Ответ занимает `O(h)`.

## Типичные ошибки

1. **Идти только по правым ссылкам** → теряются узлы, видимые через левое поддерево.
2. **Добавлять детей в порядке «правый, затем левый»**, но брать последний элемент → получится вид **слева**. (Можно и так, но тогда брать первый элемент.)
3. **Брать первый элемент уровня** вместо последнего → вид слева.
4. **Очередь с `shift()`** в классической реализации → `O(n)` на каждое извлечение и `O(n²)` в худшем случае; два массива уровней или указатель головы этого избегают.
5. **Забыть проверку пустого дерева** → `level = [null]` и обращение к `null.val`.

## Как узнать такую задачу

- Вопрос сформулирован **по уровням**: «на каждом уровне», «по слоям», «вид сбоку», «самый правый/левый в строке».
- Ответ — массив длины, равной высоте дерева.
- Альтернатива — DFS «сначала правый ребёнок» с записью первого узла на каждой новой глубине (`O(h)` памяти).
- Похожие задачи: Binary Tree Level Order Traversal, Zigzag Level Order Traversal, Average of Levels, Find Largest Value in Each Tree Row, Populating Next Right Pointers.
