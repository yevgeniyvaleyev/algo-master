## Задача простыми словами

Дан абсолютный путь в стиле Unix (начинается с `/`). В нём могут встречаться лишние слеши (`//`), текущий каталог `.` и переход к родителю `..`. Нужно вернуть **канонический** путь: начинается с одного `/`, имена разделены ровно одним `/`, нет `.` и `..`, нет завершающего слеша (кроме случая, когда путь — просто корень `/`).

Пример: `path = "/home//foo/../bar/./"` → `"/home/bar"`. Заходим в `home`, затем в `foo`, `..` возвращает в `home`, затем в `bar`, а `.` ничего не меняет.

Важная деталь: `...` (три точки и больше) — это **обычное имя** каталога, а не специальная команда.

## Наивный подход

Первая идея — править строку на месте: заменять `//` на `/` в цикле, вырезать `/./`, искать `/..` и удалять предыдущий сегмент вместе с ним, повторяя, пока строка меняется.

```ts naive
let prev = '';
while (prev !== path) {
  prev = path;
  path = path.replace('//', '/').replace('/./', '/');
  path = path.replace(/\/[^/]+\/\.\.(\/|$)/, '/'); // «имя/..» → ''
}
```

Проблем сразу несколько. Каждая замена создаёт новую строку за `O(n)`, а проходов может быть `O(n)` — итого `O(n²)`. Хуже того, такие регулярки легко ошибаются на краях: `..` в корне, `...` как имя, `..` в конце без слеша, `/../..`. Лишняя работа здесь в том, что мы снова и снова сканируем всю строку, хотя каждый сегмент пути влияет только на **последний** открытый каталог.

## Ключевое наблюдение

Путь — это последовательность шагов по дереву каталогов. Текущее положение описывается списком имён от корня: `[home, foo]`. Каждый сегмент меняет только **конец** этого списка:

- имя — добавить в конец (спуститься);
- `..` — убрать последний элемент (подняться);
- `.` и пустой сегмент — ничего не делать.

«Добавить в конец / снять с конца» — это ровно операции **стека**. Один проход по сегментам — и в стеке лежит канонический путь.

## Техники

### Стек (LIFO)

**Что это.** Стек хранит элементы так, что последним положенный снимается первым. В TypeScript это обычный массив: `push` кладёт на вершину, `pop` снимает с вершины, обе операции за `O(1)`.

**Когда применять.** Когда последнее «открытое» состояние должно «закрыться» первым: вложенные скобки, вызовы функций, вложенные выражения, пути в файловой системе. Если операция «отменяет» предыдущий шаг — почти наверняка нужен стек.

**Как применяется здесь.** В стеке лежат имена каталогов от корня до текущего. `..` — это отмена последнего спуска, то есть `pop`. Подробнее — во вкладке «Теория».

### Разбиение строки на токены

Вместо посимвольного разбора используем `path.split('/')`. Это превращает задачу со строкой в задачу с **последовательностью токенов**. Лишние слеши при этом не нужно обрабатывать особо: они дают пустые строки, которые мы просто пропускаем.

## Разбор кода

```ts
function simplifyPath(path: string): string {
  // Стек имён каталогов от корня до текущего
  const stack: string[] = [];
```

`stack` — текущее положение в дереве каталогов. Пустой стек означает корень `/`.

```ts
  // Разбиваем по '/': пустые части появляются из-за '//' и слешей по краям
  for (const part of path.split('/')) {
```

`split('/')` режет строку по каждому слешу. Для `"/a//b/"` получится `["", "a", "", "b", ""]`: первый пустой элемент — от ведущего `/`, средний — от `//`, последний — от завершающего `/`. Все пустые части означают «ничего не произошло».

```ts
    if (part === '' || part === '.') {
      // Пустая часть или '.' — остаёмся в текущем каталоге
      continue;
    }
```

Пустая часть и `.` не меняют положения — пропускаем их. Именно эта строка автоматически убирает дублирующиеся слеши.

```ts
    if (part === '..') {
      // Поднимаемся на уровень выше; из корня подняться нельзя — pop на пустом стеке ничего не делает
      stack.pop();
```

`..` снимает последний каталог. Удобная особенность JS: `pop()` на пустом массиве просто возвращает `undefined` и ничего не ломает. Это ровно семантика Unix — `..` из корня оставляет нас в корне. Отдельная проверка `if (stack.length)` не нужна.

```ts
    } else {
      // Обычное имя (в том числе '...') — спускаемся в каталог
      stack.push(part);
    }
  }
```

Всё остальное — имя каталога, включая `...`, `..a`, `.hidden`. Сравнение строгое (`=== '..'`), поэтому никакой токен, кроме ровно двух точек, не считается переходом вверх.

```ts
  // Собираем канонический путь; для пустого стека получится "/"
  return '/' + stack.join('/');
}
```

`join('/')` склеивает имена через один слеш, ведущий `/` добавляем сами. Для пустого стека `join` даёт `""`, и результат — `"/"`. Завершающего слеша не бывает: `join` не ставит разделитель после последнего элемента.

## Трассировка

`path = "/home//foo/../bar/./"`. После `split('/')`:

```
["", "home", "", "foo", "..", "bar", ".", ""]
```

1. `""` → пропуск. Стек `[]`.
2. `"home"` → `push`. Стек `[home]`.
3. `""` (от `//`) → пропуск. Стек `[home]`.
4. `"foo"` → `push`. Стек `[home, foo]`.
5. `".."` → `pop`. Стек `[home]`.
6. `"bar"` → `push`. Стек `[home, bar]`.
7. `"."` → пропуск.
8. `""` (от завершающего `/`) → пропуск.

Результат: `"/" + "home/bar"` = `"/home/bar"`.

Ещё пример: `"/../"` → части `["", "..", ""]`. `..` делает `pop` на пустом стеке — ничего не происходит. Ответ `"/"`.

## Почему это работает

Инвариант: после обработки первых `t` сегментов стек содержит ровно канонический список каталогов от корня до того места, куда привели эти `t` сегментов.

- В начале стек пуст — мы в корне, инвариант верен.
- Имя добавляет каталог в конец пути — `push` делает то же.
- `..` убирает последний каталог (или остаётся в корне) — `pop` делает то же, в том числе на пустом стеке.
- `.` и пустой сегмент не меняют положения — и стек не меняется.

После последнего сегмента стек описывает итоговый каталог, а `'/' + join('/')` — его единственная каноническая запись.

## Пограничные случаи

- **Корень `"/"`**: части `["", ""]`, стек пуст, ответ `"/"`.
- **`..` выше корня** (`"/../../a"`): лишние `pop` ничего не делают, ответ `"/a"`.
- **Три точки** (`"/.../a/../"`): `...` — имя, ответ `"/..."`.
- **Много слешей подряд** (`"///a///"`): пустые части пропускаются, ответ `"/a"`.
- **Имена с точками** (`"/.hidden/a.b"`): обычные имена, остаются как есть.

## Сложность

- **Время `O(n)`**: `split` проходит строку один раз, каждая часть обрабатывается за `O(1)` (сравнение коротких строк, `push`/`pop`), `join` — ещё один линейный проход.
- **Память `O(n)`**: массив частей после `split` и стек в сумме не длиннее исходной строки.

## Типичные ошибки

1. **Проверять `part.startsWith('.')` или `includes('..')`** вместо точного сравнения → `...` или `..a` ошибочно трактуются как переход вверх.
2. **Возвращать `stack.join('/')` без ведущего `/`** → для пустого стека получится `""` вместо `"/"`.
3. **Забыть пропускать пустые части** → в стек попадут `""`, и в ответе появятся `//`.
4. **Править строку заменами в цикле** → `O(n²)` и хрупкая логика на краях.
5. **Падать на `..` в корне** — в других языках `pop` пустого стека бросает исключение, нужна проверка; в JS она не нужна, но о ней стоит помнить.

## Как узнать такую задачу

- Последовательность команд, где одна команда **отменяет** результат предыдущей (`..`, «назад», «undo», `Backspace`).
- Нужно упростить / нормализовать вложенную структуру: пути, скобки, теги.
- Состояние описывается списком, который меняется только **с конца** — это стек.
- Похожие задачи: Backspace String Compare (`#` как удаление), Valid Parentheses, Crawler Log Folder, Remove All Adjacent Duplicates In String.
