## Задача простыми словами

Нужно спроектировать класс-стек `MinStack` с четырьмя операциями: `push(val)` — положить значение, `pop()` — снять верхнее, `top()` — посмотреть верхнее, `getMin()` — вернуть **минимум среди всех элементов стека**. Каждая операция должна работать за `O(1)`.

Пример: `push(-2)`, `push(0)`, `push(-3)`, `getMin()` → `-3`, `pop()`, `top()` → `0`, `getMin()` → `-2`. После снятия `-3` минимумом снова становится `-2` — и это нужно узнать мгновенно.

## Наивный подход

Самое очевидное — обычный стек, а `getMin` считает минимум перебором:

```ts naive
getMin(): number {
  let min = Infinity;
  for (const v of this.values) min = Math.min(min, v);
  return min;
}
```

Это `O(n)` на каждый вызов `getMin`, а требуется `O(1)`.

Вторая попытка — хранить одну переменную `min` и обновлять её в `push`. С `push` всё хорошо, но ломается `pop`: если сняли именно минимум, то каким стал новый минимум? Одной переменной это не узнать — пришлось бы снова перебирать весь стек. Лишняя работа именно в этом: после `pop` мы **заново вычисляем** минимум, который уже когда-то знали — ведь стек вернулся в состояние, в котором уже был раньше.

## Ключевое наблюдение

Стек меняется только с вершины. Значит, после `pop` стек оказывается **ровно в том состоянии**, в каком был до соответствующего `push`. А минимум того состояния мы уже знали!

Поэтому достаточно для каждой позиции стека запомнить «минимум стека, когда эта позиция — вершина». Храним эти минимумы во втором, параллельном стеке `mins`. Тогда:

- `push` кладёт `min(новое значение, текущий минимум)`;
- `pop` снимает вершину с обоих стеков — предыдущий минимум «восстанавливается сам»;
- `getMin` смотрит на вершину `mins`.

## Техники

### Стек (LIFO)

**Что это.** Структура «последним пришёл — первым ушёл»; в TypeScript — массив с `push`/`pop` за `O(1)`. Подробнее — во вкладке «Теория».

### Вспомогательный стек с агрегатом (prefix-минимум)

**Что это.** Общий приём: рядом с основным стеком хранится второй стек, где на позиции `i` лежит **агрегат** (минимум, максимум, сумма…) всех элементов от дна до `i`. Это префиксный агрегат, который удобно поддерживать именно для стека, потому что элементы меняются только с конца.

**Когда применять.** Нужна статистика по всему содержимому стека, а операции идут только с вершины. Тот же приём работает для `getMax`, а в очереди на двух стеках — для минимума в скользящем окне.

**Как применяется здесь.** `mins[i]` — минимум среди `values[0..i]`. Каждый `push` дописывает один агрегат за `O(1)`, каждый `pop` выбрасывает один — пересчитывать ничего не нужно.

### Проектирование класса

Это design-задача: важна не одна функция, а **согласованность всех методов**. Главный инвариант — `values` и `mins` всегда одинаковой длины и меняются вместе.

## Разбор кода

```ts
class MinStack {
  // Сами значения
  private values: number[] = [];
  // mins[i] — минимум среди values[0..i], то есть минимум стека,
  // когда на вершине лежит values[i]
  private mins: number[] = [];

  constructor() {}
```

Два параллельных массива. `values` — обычный стек. `mins` — стек префиксных минимумов. Конструктор пустой: оба массива уже проинициализированы в полях.

```
values: [-2,  0, -3]
mins:   [-2, -2, -3]
          ↑ минимум, пока вершина здесь
```

```ts
  push(value: number): void {
    this.values.push(value);
    // Новый минимум — меньшее из нового значения и прежнего минимума
    const prevMin = this.mins.length > 0 ? this.mins[this.mins.length - 1] : value;
    this.mins.push(Math.min(value, prevMin));
  }
```

Кладём значение в основной стек. Затем берём текущий минимум — вершину `mins`. Если стек был пуст, «прежнего минимума» нет, и в качестве `prevMin` берём само `value` (тогда `Math.min(value, value) = value`). В `mins` кладём меньшее из двух: либо новое значение стало минимумом, либо минимум не изменился.

Обратите внимание: если значение равно текущему минимуму, мы всё равно кладём запись. Именно поэтому дубликаты минимума обрабатываются корректно — каждой позиции `values` соответствует своя позиция `mins`.

```ts
  pop(): void {
    // Снимаем значение вместе с «его» минимумом — прежний минимум восстанавливается сам
    this.values.pop();
    this.mins.pop();
  }
```

Снимаем вершину с обоих стеков. После этого вершина `mins` — минимум для стека без снятого элемента, то есть ровно новый правильный минимум. Ничего пересчитывать не нужно.

```ts
  top(): number {
    return this.values[this.values.length - 1];
  }
```

Вершина основного стека. По условию `top`, `pop` и `getMin` вызываются только на непустом стеке, поэтому проверки нет.

```ts
  getMin(): number {
    // Минимум всего стека хранится на вершине mins
    return this.mins[this.mins.length - 1];
  }
}
```

`mins[last]` по определению — минимум среди `values[0..last]`, то есть всего стека. `O(1)`.

## Трассировка

Операции: `push(-2)`, `push(0)`, `push(-3)`, `getMin()`, `pop()`, `top()`, `getMin()`.

1. `push(-2)`: `mins` пуст → `prevMin = -2`, кладём `min(-2, -2) = -2`. `values = [-2]`, `mins = [-2]`.
2. `push(0)`: `prevMin = -2`, кладём `min(0, -2) = -2`. `values = [-2, 0]`, `mins = [-2, -2]`.
3. `push(-3)`: `prevMin = -2`, кладём `min(-3, -2) = -3`. `values = [-2, 0, -3]`, `mins = [-2, -2, -3]`.
4. `getMin()` → вершина `mins` = `-3`.
5. `pop()`: `values = [-2, 0]`, `mins = [-2, -2]`.
6. `top()` → `0`.
7. `getMin()` → `-2`. Минимум «вернулся» без пересчёта.

## Почему это работает

Инвариант: `values.length === mins.length`, и для каждого `i` значение `mins[i]` равно минимуму `values[0..i]`.

- `push` сохраняет инвариант: новый `mins[i] = min(values[i], mins[i-1]) = min(values[i], min(values[0..i-1])) = min(values[0..i])`.
- `pop` удаляет последний элемент из обоих массивов; для оставшихся позиций ни `values[0..i]`, ни `mins[i]` не изменились — инвариант верен.
- `top` и `getMin` ничего не меняют.

Следовательно, `getMin` всегда возвращает `mins[last]` — минимум всего стека.

## Пограничные случаи

- **Первый `push`**: прежнего минимума нет, берём само значение.
- **Повторяющийся минимум** (`push(1)`, `push(1)`, `pop()`): у каждой единицы своя запись в `mins`, после `pop` минимум по-прежнему `1`.
- **Стек опустел и снова заполняется**: `mins` пуст, следующий `push` снова начинает «с нуля».
- **Отрицательные и большие значения** (до `±2³¹`): обычные числа JS, переполнения нет.

## Сложность

- **Время `O(1)`** на каждую операцию: `push`/`pop` массива амортизированно `O(1)`, чтение вершины — `O(1)`, никаких циклов.
- **Память `O(n)`**: два массива по `n` элементов. Можно экономить, кладя в `mins` только новые минимумы (и снимая их, когда снимается равное значение), но асимптотика та же.

## Типичные ошибки

1. **Одна переменная `min`** → после `pop` минимума неизвестно, как его восстановить.
2. **Экономная версия `mins` без учёта дубликатов**: класть в `mins` только при `value < min` (строго) — после снятия одного из двух равных минимумов `mins` потеряет минимум, хотя второй ещё в стеке. Нужно `<=`.
3. **`pop` только из `values`** → массивы рассинхронизируются, `getMin` начинает врать.
4. **`prevMin = 0` или `Infinity` по умолчанию без проверки**: `Infinity` работает, а `0` — нет (для положительных значений минимумом окажется ноль, которого в стеке нет).
5. **Сортировка или куча** — дают `O(log n)`, а не `O(1)`, и сложнее удалять «вершину стека».

## Как узнать такую задачу

- Design-задача: «спроектируйте структуру данных», и **все** операции должны быть `O(1)`.
- Нужен агрегат (минимум / максимум) по содержимому, которое меняется только **с одного конца**.
- Подсказка «после удаления состояние возвращается к прежнему» — значит, прежние ответы можно хранить, а не пересчитывать.
- Похожие задачи: Max Stack, Implement Queue using Stacks, Sliding Window Maximum (монотонная очередь), Online Stock Span.
