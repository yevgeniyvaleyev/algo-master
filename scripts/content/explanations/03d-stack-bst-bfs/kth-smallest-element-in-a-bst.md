## Задача простыми словами

Дан корень **двоичного дерева поиска** (BST) и число `k`. Нужно вернуть `k`-е по величине наименьшее значение в дереве (нумерация с 1). Гарантируется `1 ≤ k ≤ n`.

Пример: дерево ниже, `k = 3` → `3`. По возрастанию значения идут `1, 2, 3, 4, 5, 6`, третье — `3`.

```
        5
       / \
      3   6
     / \
    2   4
   /
  1
```

## Наивный подход

Можно забыть, что дерево — BST: обойти все узлы любым способом, сложить значения в массив, отсортировать и взять элемент `k - 1`.

```ts naive
const values: number[] = [];
const dfs = (node: TreeNode | null) => {
  if (!node) return;
  values.push(node.val);
  dfs(node.left);
  dfs(node.right);
};
dfs(root);
values.sort((a, b) => a - b);
return values[k - 1];
```

Это `O(n log n)` времени и `O(n)` памяти. Лишняя работа двойная: мы **сортируем** то, что в BST уже упорядочено самой структурой дерева, и обходим **все** `n` узлов, хотя ответ известен, как только мы увидели `k` наименьших.

## Ключевое наблюдение

Симметричный обход (in-order: левое поддерево → узел → правое поддерево) двоичного дерева поиска выдаёт значения **строго по возрастанию**. Значит, `k`-й посещённый в in-order узел — это и есть ответ. Сортировка не нужна: достаточно **считать** посещённые узлы и запомнить значение, когда счётчик дойдёт до `k`. А раз ответ уже найден, остальную часть дерева можно не обходить.

## Техники

### Свойство BST и in-order обход

**Что это.** В BST для каждого узла все значения левого поддерева меньше его, а правого — больше. Отсюда in-order обход посещает узлы в отсортированном порядке. Подробнее — во вкладке «Теория».

**Типичный шаблон.** Множество задач на BST сводятся к «пройди in-order и работай как с отсортированным массивом»: `k`-й элемент, минимальная разница соседних значений, проверка корректности BST, итератор BST.

```ts naive
const inorder = (node) => {
  if (node === null) return;
  inorder(node.left);
  посетить(node); // узлы приходят по возрастанию
  inorder(node.right);
};
```

### Состояние во внешней переменной (замыкание)

**Что это.** Рекурсивная функция объявлена внутри основной и видит её локальные переменные. Счётчик `count` и результат `answer` живут снаружи рекурсии — их не нужно передавать параметрами и возвращать из каждого вызова.

**Как применяется здесь.** «Посетить» = `count++`; на `count === k` — записать `answer`.

### Ранняя остановка через условие в начале

**Что это.** Чтобы прервать рекурсию, не нужен специальный флаг или исключение: достаточно в начале функции выходить, если работа уже сделана (`count >= k`). Все оставшиеся вызовы завершатся сразу.

## Разбор кода

```ts
function kthSmallest(root: TreeNode | null, k: number): number {
  // Сколько узлов уже посетили в порядке in-order (то есть по возрастанию)
  let count = 0;
  let answer = -1;
```

`count` — сколько узлов уже посещено в порядке возрастания. `answer` — сюда запишем ответ; начальное `-1` по условию никогда не вернётся, потому что `k ≤ n`.

```ts
  const inorder = (node: TreeNode | null): void => {
    // Пустое поддерево или ответ уже найден — дальше не идём
    if (node === null || count >= k) {
      return;
    }
```

Базовый случай рекурсии — пустое поддерево. Вторая часть условия — ранняя остановка: как только посещено `k` узлов, ни один новый вызов ничего не делает, и обход быстро «сворачивается».

```ts
    // Сначала все меньшие значения
    inorder(node.left);
```

Все значения левого поддерева меньше `node.val`, поэтому по возрастанию они идут раньше — обходим их первыми.

```ts
    // Текущий узел — следующий по возрастанию
    count++;
    if (count === k) {
      answer = node.val;
    }
```

Левое поддерево пройдено — значит, `node` — следующий по величине. Увеличиваем счётчик; если это `k`-й узел, запоминаем его значение. Если ответ уже нашёлся в левом поддереве, `count` станет `k + 1` и условие `=== k` просто не сработает — `answer` не перезапишется.

```ts
    // Затем все большие значения
    inorder(node.right);
  };
```

Правое поддерево — значения больше текущего. Если ответ уже найден, вызов сразу вернётся из-за проверки `count >= k`.

```ts
  inorder(root);
  return answer;
}
```

Запускаем обход от корня и возвращаем найденное значение.

## Трассировка

Дерево из примера, `k = 3`.

1. `inorder(5)` → `inorder(3)` → `inorder(2)` → `inorder(1)` → `inorder(null)` — возврат.
2. В узле `1`: `count = 1`, не `3`. `inorder(1.right = null)` — возврат.
3. Обратно в `2`: `count = 2`, не `3`. `inorder(null)` — возврат.
4. Обратно в `3`: `count = 3` → `answer = 3`. `inorder(4)`: `count >= k` — сразу возврат.
5. Обратно в `5`: `count = 4`, условие `=== 3` ложно, `answer` не меняется. `inorder(6)`: `count >= k` — сразу возврат.

Ответ: `3`. Узлы `4` и `6` не посещены: обход остановился раньше.

Если бы было `k = 5`: после `3` (`count = 3`) заходим в `4` (`count = 4`), затем возвращаемся в `5` — `count = 5`, `answer = 5`; `inorder(6)` сразу возвращается.

## Почему это работает

In-order обход BST посещает узлы в порядке возрастания значений: по индукции, для каждого узла сначала посещаются все меньшие значения (левое поддерево), потом сам узел, потом все большие (правое). Значит, в момент `count === k` текущий узел имеет ровно `k - 1` меньших значений в дереве — это `k`-й наименьший.

Ранняя остановка не ломает ответ: после `count === k` счётчик может только расти, а `answer` записывается лишь при равенстве ровно `k`, то есть один раз.

## Пограничные случаи

- **`k = 1`**: ответ — самый левый узел; спускаемся к нему по левым детям.
- **`k = n`**: обходится всё дерево, ответ — самый правый узел.
- **Дерево из одного узла**: `k = 1`, ответ — корень.
- **Вырожденное дерево-«палка» влево** (`[3, 2, null, 1]`): глубина рекурсии `n` — для `n ≤ 10^4` из условия это допустимо.
- **Дерево-«палка» вправо**: глубина рекурсии растёт по мере движения вправо.

## Сложность

- **Время `O(h + k)`**: спуск к минимуму — `h` шагов, затем `k` посещений; после нахождения ответа каждый оставшийся вызов возвращается сразу, а подъём к корню — не больше `h` шагов. В худшем случае `O(n)`.
- **Память `O(h)`**: стек рекурсии хранит путь от корня — не больше высоты дерева `h` (от `log n` для сбалансированного до `n` для вырожденного).

Вариант для собеседования: **итеративный** in-order с явным стеком (влево до упора, `pop`, `k--`, на нуле `return node.val`, перейти вправо) — та же асимптотика, но останавливается простым `return` и не рискует переполнить стек вызовов.

**Follow-up из условия**: если дерево часто меняется, а запросов `k`-го много, в каждом узле хранят размер его поддерева — тогда ответ ищется спуском за `O(h)`: если размер левого поддерева `≥ k`, идём влево, если равен `k - 1` — ответ текущий узел, иначе идём вправо с `k - leftSize - 1`.

## Типичные ошибки

1. **Сортировать значения** вместо in-order — лишний `O(n log n)`, свойство BST не используется.
2. **Нет ранней остановки** → обходится всё дерево; ответ верный, но работа `O(n)` вместо `O(h + k)`.
3. **Путать in-order с pre-order** (узел до левого поддерева) → значения идут не по возрастанию.
4. **Передавать `count` параметром** (`inorder(node, count)`) → у каждого вызова своя копия числа, счёт из левого поддерева теряется. Счётчик должен быть общим — во внешней переменной.
5. **Проверять `count === k` до `count++`** или начинать с `count = 1` → ответ сдвинут на один элемент.

## Как узнать такую задачу

- Дано **BST**, а спрашивают про порядок значений: `k`-й наименьший, медиана, соседние значения, минимальная разница.
- Отсортированность «спрятана» в структуре — in-order достаёт её за `O(n)` без сортировки.
- Нужно остановиться на середине обхода → счётчик и ранний выход, либо итеративный обход со стеком.
- Похожие задачи: Binary Search Tree Iterator, Minimum Absolute Difference in BST, Validate Binary Search Tree, Two Sum IV (BST), Recover Binary Search Tree.
