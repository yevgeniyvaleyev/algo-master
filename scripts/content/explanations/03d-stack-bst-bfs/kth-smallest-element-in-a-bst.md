## Задача простыми словами

Дан корень **двоичного дерева поиска** (BST) и число `k`. Нужно вернуть `k`-е по величине наименьшее значение в дереве (нумерация с 1). Гарантируется `1 ≤ k ≤ n`.

Пример: дерево ниже, `k = 3` → `3`. По возрастанию значения идут `1, 2, 3, 4, 5, 6`, третье — `3`.

```
        5
       / \
      3   6
     / \
    2   4
   /
  1
```

## Наивный подход

Можно забыть, что дерево — BST: обойти все узлы любым способом, сложить значения в массив, отсортировать и взять элемент `k - 1`.

```ts naive
const values: number[] = [];
const dfs = (node: TreeNode | null) => {
  if (!node) return;
  values.push(node.val);
  dfs(node.left);
  dfs(node.right);
};
dfs(root);
values.sort((a, b) => a - b);
return values[k - 1];
```

Это `O(n log n)` времени и `O(n)` памяти. Лишняя работа двойная: мы **сортируем** то, что в BST уже упорядочено самой структурой дерева, и обходим **все** `n` узлов, хотя ответ известен, как только мы увидели `k` наименьших.

## Ключевое наблюдение

Симметричный обход (in-order: левое поддерево → узел → правое поддерево) двоичного дерева поиска выдаёт значения **строго по возрастанию**. Значит, `k`-й посещённый в in-order узел — это и есть ответ. Сортировка не нужна, а обход можно **остановить** сразу на `k`-м узле.

Чтобы остановиться в любой момент без «протаскивания» флага через рекурсию, обход сделан итеративным, с явным стеком.

## Техники

### Свойство BST и in-order обход

**Что это.** В BST для каждого узла все значения левого поддерева меньше его, а правого — больше. Отсюда in-order обход посещает узлы в отсортированном порядке. Подробнее — во вкладке «Теория».

**Типичный шаблон.** Множество задач на BST сводятся к «пройди in-order и работай как с отсортированным массивом»: `k`-й элемент, минимальная разница соседних значений, проверка корректности BST, итератор BST.

### Итеративный in-order обход со стеком

**Что это.** Рекурсия неявно хранит путь от корня в стеке вызовов. Итеративная версия хранит его в явном массиве. Шаблон:

```ts naive
while (node || stack.length) {
  while (node) { stack.push(node); node = node.left; } // влево до упора
  node = stack.pop();  // посетить
  node = node.right;   // перейти в правое поддерево
}
```

**Когда применять.** Когда нужна возможность прервать обход в любой момент (как здесь), или выдавать узлы по одному (BST Iterator), или рекурсия может быть слишком глубокой.

**Как применяется здесь.** «Посетить» = уменьшить `k`; на нуле — вернуть значение.

## Разбор кода

```ts
function kthSmallest(root: TreeNode | null, k: number): number {
  // Итеративный симметричный обход (in-order): левое поддерево, узел, правое.
  // В BST он выдаёт значения строго по возрастанию
  const stack: TreeNode[] = [];
  let node = root;
```

`stack` хранит узлы, которые мы уже прошли по пути вниз, но ещё **не посетили**: их левое поддерево ещё обрабатывается. `node` — текущий узел, с которого нужно начать обход поддерева (или `null`, если такого нет).

```ts
  while (node !== null || stack.length > 0) {
```

Обход продолжается, пока есть либо поддерево для обработки (`node`), либо отложенные узлы в стеке.

```ts
    // Спускаемся влево до упора, запоминая путь
    while (node !== null) {
      stack.push(node);
      node = node.left;
    }
```

Наименьший узел поддерева — самый левый. Идём влево, складывая все узлы пути в стек: каждый из них нужно будет посетить после его левого поддерева.

```ts
    // Вершина стека — наименьший ещё не посещённый узел
    node = stack.pop()!;
    k--;
```

Левее идти некуда — значит, верхний узел стека — следующий по величине. Посещаем его: уменьшаем счётчик `k`, который показывает, сколько узлов ещё осталось посетить до ответа.

```ts
    if (k === 0) {
      // Это k-й по счёту узел обхода — останавливаемся сразу
      return node.val;
    }
```

Если это `k`-й посещённый узел — он и есть ответ. Остальная часть дерева не обходится вовсе.

```ts
    // Следующие по величине значения — в правом поддереве
    node = node.right;
  }
```

После узла в порядке возрастания идут значения его правого поддерева. Переходим туда; на следующей итерации внешнего цикла снова спустимся влево до упора — уже внутри правого поддерева. Если правого поддерева нет (`null`), внутренний цикл не выполнится, и мы сразу снимем следующий узел со стека — это предок, у которого мы были в левом поддереве.

```ts
  // По условию k <= n, сюда не дойдём
  return -1;
}
```

Заглушка для TypeScript: функция должна возвращать число на всех путях.

## Трассировка

Дерево из примера, `k = 3`.

1. `node = 5`. Спуск влево: кладём `5`, `3`, `2`, `1`. Стек `[5, 3, 2, 1]`, `node = null`.
2. `pop` → `1`, `k = 2`. Не ноль. `node = 1.right = null`.
3. Внутренний цикл пропущен. `pop` → `2`, `k = 1`. `node = 2.right = null`.
4. `pop` → `3`, `k = 0` → возвращаем `3`.

Узлы `4`, `5`, `6` не посещены: обход остановился раньше. Стек к этому моменту `[5]`.

Если бы было `k = 5`: после `3` переходим в `node = 4`, кладём `4`, снимаем его (4-й посещённый, `k = 1`), `node = null`, снимаем `5` (5-й, `k = 0`) — ответ `5`.

## Почему это работает

Итеративный обход в точности повторяет рекурсивный in-order: стек хранит цепочку предков, для которых мы находимся в левом поддереве. Узел снимается со стека только после того, как всё его левое поддерево уже посещено, а правое поддерево обрабатывается после него.

По свойству BST in-order посещает узлы в порядке возрастания значений. Значит, после `k` посещений последний посещённый узел имеет ровно `k - 1` меньших значений в дереве — это `k`-й наименьший.

## Пограничные случаи

- **`k = 1`**: ответ — самый левый узел; мы спускаемся к нему и сразу возвращаем.
- **`k = n`**: обходится всё дерево, ответ — самый правый узел.
- **Дерево из одного узла**: `k = 1`, ответ — корень.
- **Вырожденное дерево-«палка» влево**: в стек попадут все `n` узлов — память `O(n)`, но без риска переполнить стек вызовов.
- **Дерево-«палка» вправо**: стек всё время из одного узла.

## Сложность

- **Время `O(h + k)`**: спуск к минимуму — `h` шагов, затем `k` посещений; суммарная работа по спускам в правые поддеревья ограничена числом посещённых узлов плюс высотой. В худшем случае `O(n)`.
- **Память `O(h)`**: стек хранит путь от корня — не больше высоты дерева `h` (от `log n` для сбалансированного до `n` для вырожденного).

**Follow-up из условия**: если дерево часто меняется, а запросов `k`-го много, в каждом узле хранят размер его поддерева — тогда ответ ищется спуском за `O(h)`: если размер левого поддерева `≥ k`, идём влево, если равен `k - 1` — ответ текущий узел, иначе идём вправо с `k - leftSize - 1`.

## Типичные ошибки

1. **Сортировать значения** вместо in-order — лишний `O(n log n)`, свойство BST не используется.
2. **Рекурсивный обход без досрочной остановки** → обходится всё дерево; а ранний `return` из глубокой рекурсии требует флага или переменной-результата.
3. **Путать in-order с pre-order** (узел до левого поддерева) → значения идут не по возрастанию.
4. **Ошибка «на единицу»**: проверять `k === 0` до уменьшения или считать с нуля → ответ сдвинут на один элемент.
5. **Условие внешнего цикла только `stack.length > 0`** → в самом начале стек пуст, и цикл не запустится вовсе.

## Как узнать такую задачу

- Дано **BST**, а спрашивают про порядок значений: `k`-й наименьший, медиана, соседние значения, минимальная разница.
- Отсортированность «спрятана» в структуре — in-order достаёт её за `O(n)` без сортировки.
- Нужно остановиться на середине обхода или выдавать элементы по одному → итеративный обход со стеком.
- Похожие задачи: Binary Search Tree Iterator, Minimum Absolute Difference in BST, Validate Binary Search Tree, Two Sum IV (BST), Recover Binary Search Tree.
