## Задача простыми словами

Даны два **отсортированных** массива `nums1` (длины `m`) и `nums2` (длины `n`). Нужно найти **медиану** всех чисел вместе — как будто массивы слили в один отсортированный.

- Если всего чисел нечётное количество — медиана это средний элемент: для `[1, 2, 3]` это `2`.
- Если чётное — среднее двух средних: для `[1, 2, 3, 4]` это `(2 + 3) / 2 = 2.5`.

Главное ограничение: время `O(log(m + n))`. Просто слить массивы нельзя — это уже `O(m + n)`.

## Наивный подход

Слить два отсортированных массива двумя указателями (как в merge sort) и взять середину:

```ts naive
const merged: number[] = [];
let a = 0, b = 0;
while (a < nums1.length || b < nums2.length) {
  if (b >= nums2.length || (a < nums1.length && nums1[a] <= nums2[b])) merged.push(nums1[a++]);
  else merged.push(nums2[b++]);
}
const mid = merged.length >> 1;
return merged.length % 2 ? merged[mid] : (merged[mid - 1] + merged[mid]) / 2;
```

Это верно и просто, но `O(m + n)`. Лишняя работа: мы **выписываем по порядку все элементы**, хотя нужно знать только, **где проходит середина**. Можно даже не хранить слияние, а остановиться на середине — всё равно линейно.

## Ключевое наблюдение

Медиана делит объединённый массив на **левую половину** и **правую половину**, причём каждый элемент левой не больше каждого элемента правой. Пусть левая половина имеет размер `half = ⌈(m + n) / 2⌉`.

Левая половина объединённого массива состоит из **какого-то префикса `nums1`** и **какого-то префикса `nums2`** (ведь оба массива отсортированы). Если из `nums1` берём первые `i` элементов, то из `nums2` — ровно `j = half - i`. Значит, нужно найти **одно число `i`** — где «разрезать» `nums1`.

Проверить разрез легко, а «слишком много / слишком мало» — монотонно. Поэтому `i` ищется **бинарным поиском** на `[0, m]` — `O(log m)` шагов.

## Техники

### Бинарный поиск по ответу (по монотонному условию)

**Что это.** Бинарный поиск работает не только «найти элемент в отсортированном массиве». Его можно применять к **любому диапазону кандидатов**, где условие ведёт себя монотонно: для кандидатов левее правильного ответа условие нарушено в одну сторону, правее — в другую. Тогда, проверив середину, мы отбрасываем половину кандидатов.

**Типичный шаблон:**

```ts naive
let lo = MIN, hi = MAX;
while (lo <= hi) {
  const mid = (lo + hi) >> 1;
  if (подходит(mid)) return mid;
  if (слишкомМного(mid)) hi = mid - 1;
  else lo = mid + 1;
}
```

**Как применяется здесь.** Кандидаты — `i` от `0` до `m` (сколько элементов `nums1` в левой половине). Если взяли из `nums1` слишком много — большой элемент `nums1` «залез» влево, двигаем разрез влево; слишком мало — вправо. Подробнее — во вкладке «Теория» (бинарный поиск).

### Разрез (partition) двух отсортированных массивов

Разрез задаётся парой `(i, j)` с `i + j = half`. Рядом с линией разреза стоят четыре числа:

```
nums1:  ... left1 | right1 ...      left1 = nums1[i-1], right1 = nums1[i]
nums2:  ... left2 | right2 ...      left2 = nums2[j-1], right2 = nums2[j]
```

Внутри каждого массива порядок уже правильный (`left1 <= right1`, `left2 <= right2`). Поэтому разрез корректен, если выполнены два **перекрёстных** условия: `left1 <= right2` и `left2 <= right1`.

### Сторожевые значения ±∞

Если `i = 0`, слева от разреза в `nums1` пусто; если `i = m` — пусто справа. Вместо отдельных веток кода подставляем `-Infinity` слева и `+Infinity` справа: такие значения никогда не нарушают условий. Приём «сторожей» (sentinels) убирает целый класс граничных случаев, включая пустой массив.

## Разбор кода

```ts
function findMedianSortedArrays(nums1: number[], nums2: number[]): number {
  // Бинарный поиск ведём по более короткому массиву
  if (nums1.length > nums2.length) return findMedianSortedArrays(nums2, nums1);
```

Меняем массивы местами, чтобы `nums1` был короче. Это даёт две вещи: время `O(log(min(m, n)))` и гарантию, что `j = half - i` всегда попадает в `[0, n]` (при длинном `nums1` значение `j` могло бы стать отрицательным).

```ts
  const m = nums1.length;
  const n = nums2.length;
  // Размер левой половины объединённого массива (при нечётной сумме — на 1 больше)
  const half = (m + n + 1) >> 1;
```

`half = ⌈(m + n) / 2⌉`. `>> 1` — целочисленное деление на 2. Когда всего чисел нечётное количество, левая половина на один элемент больше — и медиана окажется **максимумом левой половины**.

```ts
  // i — сколько элементов nums1 попадает в левую половину (от 0 до m)
  let lo = 0;
  let hi = m;
```

Диапазон кандидатов для `i` — включая `0` (из `nums1` ничего) и `m` (весь `nums1`).

```ts
  while (lo <= hi) {
    const i = (lo + hi) >> 1;
    // Остальные элементы левой половины берём из nums2
    const j = half - i;
```

Пробуем разрез посередине диапазона; `j` однозначно определяется через `i`.

```ts
    // Соседи по линии разреза; за границами массива — ±бесконечность
    const left1 = i > 0 ? nums1[i - 1] : -Infinity;
    const right1 = i < m ? nums1[i] : Infinity;
    const left2 = j > 0 ? nums2[j - 1] : -Infinity;
    const right2 = j < n ? nums2[j] : Infinity;
```

Четыре числа у линии разреза, со сторожами на краях.

```ts
    if (left1 <= right2 && left2 <= right1) {
      // Разрез правильный: всё слева <= всего справа
      const maxLeft = Math.max(left1, left2);
      if ((m + n) % 2 === 1) return maxLeft;
      const minRight = Math.min(right1, right2);
      return (maxLeft + minRight) / 2;
    }
```

Оба перекрёстных условия выполнены — разрез найден. Наибольший элемент левой половины — `max(left1, left2)`, наименьший правой — `min(right1, right2)`. При нечётной сумме медиана — `maxLeft`, при чётной — среднее `maxLeft` и `minRight`.

```ts
    if (left1 > right2) {
      // Взяли из nums1 слишком много — сдвигаем разрез влево
      hi = i - 1;
    } else {
      // Взяли из nums1 слишком мало — сдвигаем разрез вправо
      lo = i + 1;
    }
  }
```

Если `left1 > right2`, в левую половину попал слишком большой элемент `nums1` — `i` надо уменьшить. Иначе нарушено `left2 > right1`: из `nums2` взято слишком много, то есть из `nums1` — слишком мало, `i` увеличиваем.

```ts
  // Для отсортированных массивов сюда не попадаем
  return 0;
}
```

Правильный разрез всегда существует, поэтому цикл завершается через `return`. Строка нужна только компилятору.

## Трассировка

`nums1 = [1, 3, 8]`, `nums2 = [2, 4, 5, 6, 7]`. `m = 3`, `n = 5`, всего 8 (чётно), `half = (8 + 1) >> 1 = 4`.

1. `lo = 0`, `hi = 3` → `i = 1`, `j = 3`.
   `left1 = 1`, `right1 = 3`, `left2 = nums2[2] = 5`, `right2 = nums2[3] = 6`.
   `left1 <= right2` (1 ≤ 6) — да, `left2 <= right1` (5 ≤ 3) — **нет**. Из `nums1` взяли мало → `lo = 2`.
2. `lo = 2`, `hi = 3` → `i = 2`, `j = 2`.
   `left1 = 3`, `right1 = 8`, `left2 = 4`, `right2 = 5`.
   3 ≤ 5 и 4 ≤ 8 — разрез правильный.
   `maxLeft = max(3, 4) = 4`, `minRight = min(8, 5) = 5`, сумма чётная → `(4 + 5) / 2 = 4.5`.

Проверка слиянием: `[1, 2, 3, 4 | 5, 6, 7, 8]` — медиана `4.5`. Верно.

Пример с пустым массивом: `nums1 = []`, `nums2 = [2, 3]`. `m = 0`, `half = 1`, `i = 0`, `j = 1`: `left1 = -∞`, `right1 = +∞`, `left2 = 2`, `right2 = 3` — условия выполнены сразу, ответ `(2 + 3) / 2 = 2.5`. Сторожа сработали без отдельных веток.

## Почему это работает

**Корректность найденного разреза.** Если `left1 <= right2` и `left2 <= right1`, то каждый элемент левой части (префиксы `nums1[0..i)` и `nums2[0..j)`) не больше каждого элемента правой: внутри массивов это следует из сортировки, между массивами — из перекрёстных условий. Левая часть имеет размер `i + j = half`, значит, это ровно первые `half` элементов слияния, и медиана вычисляется из `maxLeft` / `minRight`.

**Монотонность.** С ростом `i` значение `left1` растёт, а `right2` падает (так как `j` уменьшается). Поэтому условие `left1 > right2` («слишком много из `nums1`») выполняется для всех `i` правее некоторой точки, а `left2 > right1` («слишком мало») — для всех левее. Правильный `i` лежит между ними, и каждая проверка отбрасывает половину кандидатов.

**Существование.** Правильный разрез есть всегда: это реальная граница половин слияния.

## Пограничные случаи

- **Один массив пустой**: благодаря обмену пустым оказывается `nums1`, `i = 0`, сторожи `±∞` делают условия истинными.
- **Все элементы одного массива меньше всех элементов другого** (`[1, 2]` и `[3, 4]`): разрез на краю (`i = m` или `i = 0`), снова помогают сторожа.
- **Нечётная общая длина**: левая половина на 1 больше, ответ — `maxLeft`.
- **Одинаковые элементы**: условия с `<=`, равенства не мешают.
- **Отрицательные числа**: сравнения работают для любых знаков.

## Сложность

- **Время `O(log(min(m, n)))`**: бинарный поиск по диапазону `[0, m]`, где `m` — длина короткого массива; каждая итерация — `O(1)`. Это даже лучше требуемого `O(log(m + n))`.
- **Память `O(1)`**: несколько переменных, без копий массивов. Рекурсивный вызов для обмена — максимум один уровень.

## Типичные ошибки

1. **Бинарный поиск по длинному массиву** → `j` уходит в отрицательные значения или больше `n`, обращение за границы.
2. **`half = (m + n) >> 1` без `+ 1`** → при нечётной сумме медиана оказывается в правой половине, и `maxLeft` даёт неверный ответ.
3. **Диапазон `hi = m - 1`** вместо `m` → не рассматривается разрез «весь `nums1` слева».
4. **Обработка краёв ветками `if`** вместо `±Infinity` → много кода и легко пропустить случай.
5. **Перепутать направление сдвига**: при `left1 > right2` нужно уменьшать `i` (`hi = i - 1`), а не увеличивать.

## Как узнать такую задачу

- Два (или несколько) **отсортированных** массива и вопрос о **k-м элементе**, медиане или позиции в объединении.
- Требование **логарифмического** времени при отсортированных данных — сильный сигнал к бинарному поиску, часто «по ответу» или «по разрезу», а не по значению.
- Если «проверить кандидата» легко, а ошибка однозначно говорит, в какую сторону сдвигаться, — это монотонное условие, и кандидата ищут бинарным поиском. Родственные задачи: k-й наименьший элемент двух массивов, Split Array Largest Sum.
