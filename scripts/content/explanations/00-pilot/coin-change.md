## Задача простыми словами

Есть монеты нескольких номиналов (`coins`), и каждой — сколько угодно штук. Нужно набрать сумму `amount` **наименьшим числом монет**. Если сумму набрать нельзя — вернуть `-1`.

Пример: `coins = [1, 2, 5]`, `amount = 11`. Оптимально `5 + 5 + 1` — три монеты. Пример «нельзя»: `coins = [2]`, `amount = 3` — из двоек нечётную сумму не собрать, ответ `-1`.

## Наивный подход

**Жадность** — «бери самую крупную монету, пока влезает» — кажется естественной (так работают реальные деньги), но в общем случае **неверна**. Для `coins = [1, 3, 4]`, `amount = 6` жадно получится `4 + 1 + 1` (3 монеты), а оптимально `3 + 3` (2 монеты).

**Полный перебор** — рекурсия «попробовать каждую монету последней»:

```ts naive
function minCoins(x: number): number {
  if (x === 0) return 0;
  let best = Infinity;
  for (const coin of coins) {
    if (coin <= x) best = Math.min(best, minCoins(x - coin) + 1);
  }
  return best;
}
```

Это верно, но экспоненциально: одна и та же сумма (например, `minCoins(5)`) вычисляется заново на огромном числе путей (`11 → 10 → 5`, `11 → 6 → 5`, `11 → 9 → 7 → 5`…). Вот она, лишняя работа: **перекрывающиеся подзадачи**.

## Ключевое наблюдение

Ответ для суммы `x` зависит только от ответов для **меньших** сумм: если последняя монета в оптимальном наборе — `coin`, то остальные монеты оптимально набирают `x - coin`. Значит, достаточно один раз посчитать ответ для каждой суммы от `0` до `amount` и хранить его в таблице.

Сумм всего `amount + 1`, для каждой перебираем `k` монет — полиномиальное время вместо экспоненты.

## Техники

### Динамическое программирование (ДП)

**Что это.** ДП применимо, когда у задачи есть:

- **оптимальная подструктура** — оптимальный ответ собирается из оптимальных ответов подзадач;
- **перекрывающиеся подзадачи** — одни и те же подзадачи встречаются много раз.

Тогда каждую подзадачу решаем **один раз** и записываем ответ в таблицу.

**Как формулировать ДП — четыре вопроса:**

1. **Состояние**: что означает `dp[x]`? Здесь — минимальное число монет для суммы `x`.
2. **База**: что известно сразу? `dp[0] = 0` — нулевая сумма набирается нулём монет.
3. **Переход**: как `dp[x]` выражается через меньшие? Перебираем последнюю монету: `dp[x] = min(dp[x - coin] + 1)` по всем `coin <= x`.
4. **Ответ и порядок**: считаем `x` по возрастанию (все `x - coin` уже готовы), ответ — `dp[amount]`.

**Как применяется здесь.** Таблица `dp` длины `amount + 1`, заполнение снизу вверх (табуляция). Подробнее о ДП — во вкладке «Теория».

### Неограниченный рюкзак

Эта задача — частный случай **unbounded knapsack**: предметы (монеты) можно брать сколько угодно раз. Признак такого ДП — одномерная таблица по «ёмкости» (сумме), а во внутреннем цикле перебираются все предметы. Порядок монет в наборе не важен, поэтому нам не нужно помнить, какие монеты уже использованы.

### `Infinity` как «невозможно»

Ненабираемые суммы помечаем `Infinity`. Это удобно: `min` с `Infinity` работает естественно, а `Infinity + 1` — всё ещё `Infinity`, так что невозможность «протекает» по переходам без отдельных проверок.

## Разбор кода

```ts
function coinChange(coins: number[], amount: number): number {
  // dp[x] — минимальное число монет для суммы x; Infinity — «набрать нельзя»
  const dp: number[] = new Array(amount + 1).fill(Infinity);
  // Сумма 0 набирается нулём монет
  dp[0] = 0;
```

Создаём таблицу на суммы `0..amount`. Изначально считаем все суммы ненабираемыми (`Infinity`), кроме базы `dp[0] = 0`.

```ts

```

Перебираем суммы **по возрастанию** — так к моменту вычисления `dp[x]` все меньшие значения уже готовы. Для каждой суммы пробуем каждую монету в роли последней.

```ts
      // Последняя монета — coin, остаток x - coin должен быть набираем
      if (coin <= x && dp[x - coin] + 1 < dp[x]) {
        dp[x] = dp[x - coin] + 1;
      }
    }
  }
```

Переход. Условие `coin <= x` отсекает монеты крупнее суммы (иначе индекс станет отрицательным). Если остаток `x - coin` ненабираем, `dp[x - coin] + 1` — это `Infinity`, и сравнение `<` не пройдёт. Иначе берём минимум.

```ts
  // Если сумма так и осталась ненабираемой — -1
  return dp[amount] === Infinity ? -1 : dp[amount];
}
```

Ответ — `dp[amount]`; `Infinity` превращаем в `-1`, как требует условие.

## Трассировка

`coins = [1, 2, 5]`, `amount = 6`:

```
x=0: база                                        dp[0]=0
x=1: 1→dp[0]+1=1                                 dp[1]=1
x=2: 1→dp[1]+1=2, 2→dp[0]+1=1                    dp[2]=1
x=3: 1→dp[2]+1=2, 2→dp[1]+1=2                    dp[3]=2
x=4: 1→dp[3]+1=3, 2→dp[2]+1=2                    dp[4]=2
x=5: 1→dp[4]+1=3, 2→dp[3]+1=3, 5→dp[0]+1=1       dp[5]=1
x=6: 1→dp[5]+1=2, 2→dp[4]+1=3, 5→dp[1]+1=2       dp[6]=2
```

Ответ `2` (`5 + 1`). Монета `5` для `x < 5` не рассматривается — её отсекает `coin <= x`.

Пример с невозможностью, `coins = [2]`, `amount = 3`: `dp[1] = ∞` (монета 2 не влезает), `dp[2] = dp[0] + 1 = 1`, `dp[3] = dp[1] + 1 = ∞`. Ответ `-1`.

## Почему это работает

По индукции по `x`. База: `dp[0] = 0` верно. Пусть все `dp[y]` для `y < x` верны. В любом наборе монет на сумму `x` есть **последняя** монета `coin`; остальные монеты набирают `x - coin`, и их не меньше `dp[x - coin]`. Значит, любой набор содержит не меньше `dp[x - coin] + 1` монет, а набор такого размера реально существует (оптимальный для `x - coin` плюс `coin`). Перебрав все `coin`, получаем точный минимум. Если ни один вариант невозможен — `dp[x]` остаётся `Infinity`.

## Пограничные случаи

- **`amount = 0`**: цикл не выполняется, ответ `dp[0] = 0`.
- **Сумма ненабираема**: `dp[amount]` остаётся `Infinity` → `-1`.
- **Огромные номиналы** (до `2^31 - 1`): отсекаются условием `coin <= x`, не участвуют и не ломают индексы.
- **Монета `1` в наборе**: тогда любая сумма набираема, `-1` невозможен.
- **Повторяющиеся номиналы в `coins`**: просто лишняя проверка, ответ не меняется.

## Сложность

- **Время `O(amount · k)`**, где `k` — число номиналов: два вложенных цикла, тело — `O(1)`. При `amount = 10⁴` и `k = 12` — около 120 000 операций.
- **Память `O(amount)`**: одна таблица `dp`.

## Типичные ошибки

1. **Жадный алгоритм** — неверен для произвольных номиналов (`[1, 3, 4]`, `6`).
2. **Инициализация нулями** вместо `Infinity` → `min` всегда выбирает «0 монет».
3. **Использовать `-1` как «невозможно» внутри таблицы** → `min` начинает предпочитать `-1`; нужен `Infinity` (или `amount + 1`) и замена на `-1` только в конце.
4. **Забыть `coin <= x`** → обращение к `dp` с отрицательным индексом (`undefined + 1 = NaN`).
5. **Путать с задачей «число способов»** (Coin Change II): там суммируют варианты и важен порядок циклов (монеты снаружи), а здесь ищем минимум.

## Как узнать такую задачу

- Нужно **минимальное/максимальное** количество чего-то, чтобы набрать «ёмкость» (сумму, длину, вес), а «предметы» можно брать **многократно**.
- Жадность «брать самое большое» не очевидно верна — проверьте контрпримером.
- Ответ для большого значения складывается из ответов для меньших → ДП по значению (неограниченный рюкзак). Похожие задачи: Perfect Squares, Word Break, Combination Sum IV.
