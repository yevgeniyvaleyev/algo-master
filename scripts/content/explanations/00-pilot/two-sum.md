## Задача простыми словами

Есть массив чисел `nums` и число `target`. Нужно найти **два разных элемента**, сумма которых равна `target`, и вернуть их **индексы**. Гарантируется, что такая пара ровно одна.

Пример: `nums = [2, 7, 11, 15]`, `target = 9`. Подходят `2` и `7` (`2 + 7 = 9`), они стоят на позициях `0` и `1` — ответ `[0, 1]`.

## Наивный подход

Самое очевидное — перебрать все пары:

```ts naive
for (let i = 0; i < nums.length; i++) {
  for (let j = i + 1; j < nums.length; j++) {
    if (nums[i] + nums[j] === target) return [i, j];
  }
}
```

Это `O(n²)`: при `n = 10⁴` — около 50 миллионов сравнений. Где здесь лишняя работа? Для каждого `i` внутренний цикл **заново просматривает массив**, чтобы ответить на один и тот же по сути вопрос: «есть ли где-то число, равное `target - nums[i]`?». Мы ищем конкретное значение линейным поиском — а поиск по значению умеет делать быстрее другая структура данных.

## Ключевое наблюдение

Для текущего элемента `nums[i]` партнёр определён **однозначно**: это `need = target - nums[i]`. Значит, задача сводится к вопросу «встречалось ли уже число `need`, и если да — на каком индексе?».

Если по ходу прохода складывать уже просмотренные числа в хеш-таблицу «значение → индекс», то этот вопрос решается за `O(1)`. Один проход слева направо — и пара найдена.

## Техники

### Хеш-таблица (Map) для поиска «партнёра»

**Что это.** Хеш-таблица хранит пары «ключ → значение» и умеет за амортизированное `O(1)` проверить, есть ли ключ, достать значение и добавить новую пару. В JavaScript/TypeScript это `Map` (или обычный объект, но `Map` надёжнее: ключи любого типа, нет конфликтов с прототипом).

**Типичный шаблон «complement lookup».** Когда нужно найти два элемента с заданным отношением (`a + b = target`, `a - b = k`, `a * b = x`), второй элемент выражается через первый. Тогда:

1. идём по массиву один раз;
2. для текущего элемента вычисляем, **какой партнёр нужен**;
3. смотрим, есть ли партнёр в таблице уже просмотренных;
4. кладём текущий элемент в таблицу.

Мы обмениваем память `O(n)` на время: вместо `O(n)` поиска на каждом шаге — `O(1)`.

**Как применяется здесь.** Ключ — значение элемента, значение — его индекс (индекс нужен для ответа). Подробнее о хеш-таблицах — во вкладке «Теория».

### Однопроходная проверка «до вставки»

Важная деталь шаблона — **порядок действий**: сначала ищем партнёра, потом добавляем текущий элемент. Благодаря этому таблица в момент проверки содержит только элементы **левее** `i`, и элемент не может составить пару сам с собой.

## Разбор кода

```ts
function twoSum(nums: number[], target: number): number[] {
  // Значение -> индекс, для уже просмотренных элементов
  const seen = new Map<number, number>();
```

`seen` — наша «память»: для каждого просмотренного числа храним индекс, где оно встретилось. Изначально таблица пуста — мы ещё ничего не видели.

```ts
  for (let i = 0; i < nums.length; i++) {
    // Какое число нужно в пару к текущему
    const need = target - nums[i];
```

Один проход по массиву. Для `nums[i]` сразу вычисляем недостающее слагаемое: если `nums[i] + x = target`, то `x = target - nums[i]`.

```ts
    const j = seen.get(need);
    if (j !== undefined) {
      // Пара найдена: j — более ранний индекс
      return [j, i];
    }
```

`seen.get(need)` возвращает индекс партнёра или `undefined`, если такого числа ещё не было. Сравнение именно с `undefined`, а не `if (j)`: индекс `0` — ложное значение в JS, и проверка `if (j)` потеряла бы партнёра на позиции `0`. Если партнёр найден — он стоит левее, поэтому возвращаем `[j, i]`.

```ts
    // Запоминаем текущий элемент ПОСЛЕ проверки,
    // чтобы не сложить элемент сам с собой
    seen.set(nums[i], i);
  }
```

Только теперь кладём текущий элемент в таблицу. Если бы мы сделали это до проверки, то при `nums[i] = 3`, `target = 6` нашли бы `need = 3` — самого себя — и вернули `[i, i]`.

```ts
  // По условию решение всегда существует
  return [];
}
```

До этой строки выполнение не дойдёт (ответ гарантирован), но TypeScript требует вернуть значение на всех путях.

## Трассировка

`nums = [3, 2, 4]`, `target = 6`:

1. `i = 0`, `nums[0] = 3`, `need = 3`. В `seen` пусто → не нашли. Кладём `3 → 0`. `seen = {3: 0}`.
2. `i = 1`, `nums[1] = 2`, `need = 4`. Числа `4` в `seen` нет. Кладём `2 → 1`. `seen = {3: 0, 2: 1}`.
3. `i = 2`, `nums[2] = 4`, `need = 2`. `seen.get(2) = 1` → возвращаем `[1, 2]`.

Обратите внимание на шаг 1: `need = 3` совпадает с самим `nums[0]`, но таблица ещё пуста — поэтому ложной пары `[0, 0]` нет.

Пример с дубликатами, `nums = [3, 3]`, `target = 6`:

1. `i = 0`: `need = 3`, таблица пуста. Кладём `3 → 0`.
2. `i = 1`: `need = 3`, `seen.get(3) = 0` → ответ `[0, 1]`.

## Почему это работает

Пусть правильная пара — индексы `a < b`. Когда цикл доходит до `i = b`:

- элемент `nums[a]` уже лежит в таблице, потому что `a < b` и мы добавляем каждый элемент после его проверки;
- `need = target - nums[b] = nums[a]`, значит `seen.get(need)` вернёт индекс со значением `nums[a]`.

Раньше `b` ответ не вернётся по ошибке: возвращаем только когда нашли реального партнёра левее, а пара по условию единственная. Если одно значение встречается несколько раз, `seen.set` перезапишет индекс на более поздний — это не мешает, нам подходит любой индекс с нужным значением.

## Пограничные случаи

- **Одинаковые числа** (`[3, 3]`, `target = 6`): работают, потому что первый `3` уже в таблице, когда проверяется второй.
- **Элемент «в пару сам себе»** (`[3, 2, 4]`, `target = 6`): не возвращается благодаря порядку «проверка → вставка».
- **Отрицательные числа и ноль**: формула `target - nums[i]` работает для любых знаков.
- **Партнёр на индексе 0**: проверка `j !== undefined`, а не `if (j)`.

## Сложность

- **Время `O(n)`**: один проход, на каждом шаге — `get` и `set` у `Map`, каждая за амортизированное `O(1)`.
- **Память `O(n)`**: в худшем случае (пара в самом конце) в таблицу попадут почти все элементы.

Сравните с перебором: `O(n²)` времени и `O(1)` памяти. Классический обмен памяти на скорость.

## Типичные ошибки

1. **Вставка до проверки** → элемент складывается сам с собой, ответ `[i, i]`.
2. **`if (j)` вместо `j !== undefined`** → теряется партнёр с индексом `0`.
3. **Сортировка + два указателя** без сохранения исходных индексов: сортировка перемешивает позиции, а вернуть нужно индексы исходного массива.
4. **Хранить в таблице индекс → значение** (наоборот): тогда искать по значению снова придётся перебором.
5. **Заранее заполнить всю таблицу**, а потом искать: так тоже можно, но нужно отдельно проверять, что найденный индекс не равен `i`.

## Как узнать такую задачу

- Нужно найти **пару** элементов с условием вида `a + b = X` (или `a - b`, `a ^ b`), где второй элемент **однозначно вычисляется** по первому.
- Требуется лучше, чем `O(n²)`, а массив **не отсортирован** (или нужны исходные индексы).
- Вопрос «встречалось ли раньше значение Y?» — сигнал к хеш-таблице просмотренных элементов. Тот же приём лежит в основе задач про подмассивы с заданной суммой (префиксные суммы + `Map`).
