## Задача простыми словами

Дана строка `s`. Нужно найти длину самого длинного **непрерывного куска** строки (подстроки), в котором ни один символ не повторяется.

Пример: `s = "abcabcbb"`. Подстрока `"abc"` подходит (все символы разные), а `"abca"` — уже нет (`a` дважды). Длиннее 3 ничего не найти — ответ `3`.

Важно: именно **подстрока** (подряд идущие символы), а не подпоследовательность. В `"pwwkew"` ответ `3` (`"wke"`), а не `4` (`"pwke"` — символы не подряд).

## Наивный подход

Перебрать все подстроки и для каждой проверить, что символы различны:

```ts naive
let best = 0;
for (let i = 0; i < s.length; i++) {
  const seen = new Set<string>();
  for (let j = i; j < s.length; j++) {
    if (seen.has(s[j])) break; // дальше от i расширять бессмысленно
    seen.add(s[j]);
    best = Math.max(best, j - i + 1);
  }
}
```

Даже с ранним `break` это `O(n · k)`, где `k` — размер алфавита, а без него — `O(n²)` и хуже. Где лишняя работа? Когда от начала `i` мы дошли до повтора и начинаем заново с `i + 1`, мы **заново проверяем** почти те же символы, про которые уже всё знаем: они различны.

## Ключевое наблюдение

Если подстрока `s[left..right]` не содержит повторов, то и любая её часть тоже. Поэтому не нужно начинать каждый раз заново: достаточно поддерживать **окно** `[left, right]` без повторов и двигать его границы только вперёд.

Когда новый символ `s[right]` уже есть в окне на позиции `prev`, любое окно, содержащее и `prev`, и `right`, плохое. Значит, левую границу можно **сразу перенести** на `prev + 1` — все промежуточные начала заведомо хуже.

Чтобы знать `prev` мгновенно, храним для каждого символа индекс его **последнего вхождения**.

## Техники

### Скользящее окно (sliding window)

**Что это.** Две границы `left` и `right` задают текущий отрезок массива/строки. `right` идёт вперёд и «добавляет» элементы, `left` идёт вперёд и «убирает» их, когда окно перестаёт удовлетворять условию. Каждая граница проходит путь не больше `n`, поэтому весь алгоритм линейный.

**Типичный шаблон («самое длинное окно с условием»):**

1. расширяем окно: `right++`;
2. пока окно невалидно — сужаем: `left++` (или прыжком);
3. окно валидно — обновляем ответ `right - left + 1`.

**Когда применять.** Задача про **непрерывный** подмассив/подстроку, условие «монотонно»: если окно хорошее, то и все вложенные в него окна хорошие (или наоборот для «плохих»). Здесь условие — «нет повторов» — как раз такое.

**Как применяется здесь.** Окно `[left, right]` всегда без повторов. Подробнее — во вкладке «Теория» (скользящее окно).

### Хеш-таблица «символ → последний индекс»

**Что это.** `Map`, где для каждого символа записан индекс, на котором он встречался последним. Это позволяет не сдвигать `left` по одному символу, а **перепрыгнуть** сразу за повтор.

**Альтернатива.** Можно хранить `Set` символов окна и при повторе удалять символы слева по одному, пока повтор не уйдёт. Это тоже `O(n)` суммарно, но с прыжком код короче и шагов меньше.

## Разбор кода

```ts
function lengthOfLongestSubstring(s: string): number {
  // Для каждого символа — индекс его последнего вхождения
  const lastSeen = new Map<string, number>();
  let left = 0; // начало окна без повторов
  let best = 0;
```

- `lastSeen` — где мы видели каждый символ в последний раз (во всей строке, не только в окне).
- `left` — левая граница текущего окна. Правая граница будет переменной цикла.
- `best` — лучший найденный ответ; для пустой строки останется `0`.

```ts
  for (let right = 0; right < s.length; right++) {
    const ch = s[right];
    const prev = lastSeen.get(ch);
```

Правая граница обходит строку один раз. `prev` — где символ `ch` встречался раньше (или `undefined`, если не встречался вовсе).

```ts
    // Символ уже есть внутри окна — переносим левую границу сразу за него.
    // Проверка prev >= left важна: старые вхождения левее окна не мешают
    if (prev !== undefined && prev >= left) {
      left = prev + 1;
    }
```

Сердце алгоритма. Два условия:

- `prev !== undefined` — символ вообще встречался;
- `prev >= left` — и встречался **внутри текущего окна**. Если `prev < left`, то это вхождение уже «выпало» из окна и повтора нет.

Тогда новое окно должно начинаться сразу после старого вхождения: `left = prev + 1`. Все начала между старым `left` и `prev` содержали бы оба вхождения `ch`.

```ts
    lastSeen.set(ch, right);
    best = Math.max(best, right - left + 1);
  }

  return best;
}
```

Запоминаем новое последнее вхождение `ch` и обновляем ответ длиной текущего окна. После этого шага окно `[left, right]` гарантированно без повторов.

## Трассировка

`s = "abba"`:

```
right=0 'a': prev=—        left=0  lastSeen={a:0}            окно "a"    best=1
right=1 'b': prev=—        left=0  lastSeen={a:0,b:1}        окно "ab"   best=2
right=2 'b': prev=1 ≥ 0 →  left=2  lastSeen={a:0,b:2}        окно "b"    best=2
right=3 'a': prev=0 < 2 →  left=2  lastSeen={a:3,b:2}        окно "ba"   best=2
```

Шаг 4 показывает, зачем нужна проверка `prev >= left`: последнее `a` было на позиции `0`, но оно уже вне окна. Без проверки мы бы поставили `left = 1` — **сдвинули окно назад**, и в окно `"bba"` попал бы повтор `b`.

`s = "abcabcbb"` кратко: окна `"a"`, `"ab"`, `"abc"` (best=3), затем на каждом следующем символе окно перепрыгивает, оставаясь длины 3 или меньше — ответ `3`.

## Почему это работает

**Инвариант:** после каждой итерации окно `[left, right]` не содержит повторов, и это **самое длинное** окно без повторов, заканчивающееся в `right`.

- Без повторов: мы убрали единственный возможный повтор — старое вхождение `ch` (остальные символы окна были различны до шага).
- Самое длинное: любое окно, заканчивающееся в `right` и начинающееся левее нового `left`, содержит либо старый повтор (который был до этого шага), либо два вхождения `ch`.

Ответ — максимум по всем `right` из самого длинного окна, заканчивающегося в `right`. Значит, мы рассмотрели лучшего кандидата для каждого конца — и нашли общий максимум.

`left` никогда не уменьшается (благодаря `prev >= left`), так что окно только «едет» вправо.

## Пограничные случаи

- **Пустая строка** `""`: цикл не выполнится, ответ `0`.
- **Все символы одинаковые** `"bbbbb"`: каждый шаг окно сжимается до одного символа, ответ `1`.
- **Все символы разные**: `left` всегда `0`, ответ — длина строки.
- **Старое вхождение вне окна** (`"abba"`): обрабатывается проверкой `prev >= left`.
- **Пробелы, цифры и знаки**: это обычные символы, `Map` работает с любыми.

## Сложность

- **Время `O(n)`**: `right` проходит строку один раз, каждая итерация — `O(1)` операций с `Map`. `left` только прыгает вперёд, без внутреннего цикла.
- **Память `O(min(n, k))`**, где `k` — размер алфавита: в `lastSeen` не больше одной записи на каждый различный символ.

## Типичные ошибки

1. **Забыть `prev >= left`** → на строках вроде `"abba"` окно уезжает назад, ответ получается слишком большим.
2. **`left = prev` вместо `prev + 1`** → повторяющийся символ остаётся в окне.
3. **Обновлять `best` до сдвига `left`** → в ответ попадает длина невалидного окна.
4. **Путать подстроку с подпоследовательностью** и считать просто число различных символов.
5. **Удалять из `lastSeen` символы при сдвиге `left`** — лишнее: проверка `prev >= left` и так отсекает устаревшие записи.

## Как узнать такую задачу

- Речь о **непрерывном** куске массива или строки («подстрока», «подмассив», «отрезок»).
- Нужно найти самый длинный/короткий кусок с условием, которое **не портится при сужении** («без повторов», «не больше k различных», «сумма не больше X» для неотрицательных чисел).
- Перебор всех отрезков даёт `O(n²)`, а ограничение `n` до `10⁵` намекает на линейное решение — почти всегда это скользящее окно.
