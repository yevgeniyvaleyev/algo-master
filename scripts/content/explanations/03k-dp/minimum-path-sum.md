## Задача простыми словами

Дана сетка `grid` из неотрицательных чисел размером `m × n`. Нужно пройти из левого верхнего угла в правый нижний, двигаясь **только вправо или вниз**, так, чтобы сумма чисел на пути (включая начало и конец) была минимальной.

Пример:

```
1 3 1
1 5 1
4 2 1
```

Лучший путь `1 → 3 → 1 → 1 → 1` (вправо, вправо, вниз, вниз), сумма `7`.

## Наивный подход

Рекурсивно перебрать все пути: из каждой клетки — вправо или вниз.

```ts naive
function best(i: number, j: number): number {
  if (i >= m || j >= n) return Infinity;
  if (i === m - 1 && j === n - 1) return grid[i][j];
  return grid[i][j] + Math.min(best(i + 1, j), best(i, j + 1));
}
```

Путей `C(m + n − 2, m − 1)` — при `200 × 200` это астрономическое число. Лишняя работа: в клетку `(1, 1)` можно попасть и через `(0, 1)`, и через `(1, 0)`, и рекурсия решает «лучший путь от `(1, 1)` до финиша» заново для каждого способа туда прийти. Хотя ответ от способа прихода не зависит.

Жадный выбор («иди туда, где меньше») ломается: дешёвый шаг может завести в дорогой угол.

## Ключевое наблюдение

В клетку `(i, j)` можно прийти **только двумя способами**: сверху из `(i − 1, j)` или слева из `(i, j − 1)`. Значит, лучший путь до неё — лучший из этих двух плюс её собственное число:

```
dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])
```

Ходы только вправо и вниз, поэтому обход строк сверху вниз, а внутри строки слева направо гарантирует: оба соседа уже посчитаны. А поскольку строка зависит лишь от предыдущей строки и от самой себя, таблицу можно сжать до **одного массива**.

## Техники

### ДП на сетке

**Что это.** Классический вид двумерного ДП: `dp[i][j]` описывает лучший путь до клетки `(i, j)`, а переход перебирает клетки, из которых сюда можно сделать ход.

- **Состояние**: `dp[i][j]` — минимальная сумма пути от `(0, 0)` до `(i, j)`.
- **База**: `dp[0][0] = grid[0][0]`.
- **Переход**: число клетки + минимум из «сверху» и «слева».
- **Порядок**: строки сверху вниз, внутри — слева направо.
- **Ответ**: `dp[m-1][n-1]`.

Подробнее о многомерном ДП — во вкладке «Теория».

### Одна строка вместо таблицы

Храним массив `dp` длины `n`. Трюк в том, что **до перезаписи** `dp[j]` всё ещё хранит значение из предыдущей строки — это «сверху», а `dp[j − 1]` уже обновлён на этой строке — это «слева». Один массив одновременно содержит обе нужные строки.

### `Infinity` за границей сетки

Чтобы не писать отдельные ветки для первой строки (прийти можно только слева) и первого столбца (только сверху), «несуществующих» соседей считаем равными `Infinity`. `min` с `Infinity` выбирает реальный вариант автоматически.

## Разбор кода

```ts
function minPathSum(grid: number[][]): number {
  const m = grid.length;
  const n = grid[0].length;
  // dp[j] — минимальная сумма пути до клетки (i, j) текущей строки.
  // Перед обновлением dp[j] хранит значение «сверху» (строка i - 1).
  const dp: number[] = new Array(n).fill(Infinity);
```

Массив на одну строку. Заполнен `Infinity`: перед первой строкой «строка сверху» не существует, и ход сверху для неё невозможен — `Infinity` это и выражает.

```ts
  for (let i = 0; i < m; i++) {
    for (let j = 0; j < n; j++) {
      if (i === 0 && j === 0) {
        // Стартовая клетка
        dp[j] = grid[0][0];
        continue;
      }
```

Обход в правильном порядке. Стартовая клетка — особая: к ней ниоткуда не приходят, её стоимость — само число. Без этой ветки получилось бы `grid[0][0] + min(∞, ∞) = ∞`.

```ts
      // Сверху — старое dp[j], слева — уже обновлённое dp[j - 1].
      // За границей сетки — Infinity, такой ход невозможен.
      const up = dp[j];
      const left = j > 0 ? dp[j - 1] : Infinity;
      dp[j] = grid[i][j] + Math.min(up, left);
    }
  }
```

`up` читается до перезаписи, поэтому это значение строки `i − 1` (или `Infinity` на первой строке). `left` — уже посчитанная клетка слева в текущей строке; в первом столбце левого соседа нет — `Infinity`. Новое `dp[j]` — число клетки плюс лучший из двух входов.

```ts
  // Правый нижний угол
  return dp[n - 1];
}
```

После последней строки `dp[n − 1]` — лучший путь до правого нижнего угла.

## Трассировка

`grid = [[1, 3, 1], [1, 5, 1], [4, 2, 1]]`, старт: `dp = [∞, ∞, ∞]`.

```
i=0:
  j=0: старт                         dp=[1, ∞, ∞]
  j=1: up=∞, left=1 → 3 + 1 = 4      dp=[1, 4, ∞]
  j=2: up=∞, left=4 → 1 + 4 = 5      dp=[1, 4, 5]
i=1:
  j=0: up=1, left=∞ → 1 + 1 = 2      dp=[2, 4, 5]
  j=1: up=4, left=2 → 5 + 2 = 7      dp=[2, 7, 5]
  j=2: up=5, left=7 → 1 + 5 = 6      dp=[2, 7, 6]
i=2:
  j=0: up=2, left=∞ → 4 + 2 = 6      dp=[6, 7, 6]
  j=1: up=7, left=6 → 2 + 6 = 8      dp=[6, 8, 6]
  j=2: up=6, left=8 → 1 + 6 = 7      dp=[6, 8, 7]
```

Ответ `dp[2] = 7`. В последней клетке выиграл вход сверху (`6`): это путь по верхней строке и затем по правому столбцу.

## Почему это работает

Индукция по порядку обхода. Любой путь до `(i, j)`, кроме стартовой клетки, последним шагом приходит из `(i − 1, j)` или `(i, j − 1)`, и его часть до этой клетки — путь до соседа, стоимость которого не меньше оптимальной для соседа. Значит, `grid[i][j] + min(up, left)` — нижняя граница, и она достигается (оптимальный путь до лучшего соседа плюс шаг). Оба соседа посчитаны раньше: верхний — на прошлой строке, левый — на этой. Несуществующие соседи дают `Infinity` и не выбираются.

## Пограничные случаи

- **Сетка `1 × 1`**: только стартовая ветка, ответ `grid[0][0]`.
- **Одна строка**: `up` всегда `Infinity`, путь — просто сумма строки.
- **Один столбец**: `left` всегда `Infinity`, путь — сумма столбца.
- **Нули в сетке**: формула не меняется.
- **Вход не портится**: пишем только в `dp`.

## Сложность

- **Время `O(m · n)`**: каждая клетка обрабатывается один раз за `O(1)`.
- **Память `O(n)`**: одна строка `dp`. Можно писать прямо в `grid` и получить `O(1)`, но это меняет входные данные.

## Типичные ошибки

1. **Жадный выбор** меньшего соседа на каждом шаге — не даёт оптимума.
2. **Забыть стартовую клетку**: с `dp`, заполненным `Infinity`, без отдельной ветки ответ станет `Infinity`.
3. **Заполнить `dp` нулями** вместо `Infinity` — на первой строке «сверху» окажется бесплатный вход, и первая строка получит неверные (заниженные) суммы.
4. **Прочитать `dp[j]` после перезаписи** — потеряется значение «сверху».
5. **Применять Дейкстру/BFS** — работает, но избыточно: при ходах только вправо/вниз граф ацикличен, и простого ДП достаточно.

## Как узнать такую задачу

- Сетка, ходы **только вправо и вниз** (или другое направленное множество ходов без циклов), нужна минимальная/максимальная сумма или число путей.
- Ответ для клетки определяется ответами её «входных» соседей → ДП на сетке, обычно с одной строкой памяти.
- Если ходы во все четыре стороны — это уже кратчайший путь в графе (Дейкстра, 0-1 BFS).

Родственные задачи: Unique Paths, Unique Paths II, Triangle, Dungeon Game, Cherry Pickup, Minimum Falling Path Sum.
