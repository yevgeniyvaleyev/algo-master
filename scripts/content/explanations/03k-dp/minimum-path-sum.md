## Задача простыми словами

Дана сетка `grid` из неотрицательных чисел размером `m × n`. Нужно пройти из левого верхнего угла в правый нижний, двигаясь **только вправо или вниз**, так, чтобы сумма чисел на пути (включая начало и конец) была минимальной.

Пример:

```
1 3 1
1 5 1
4 2 1
```

Лучший путь `1 → 3 → 1 → 1 → 1` (вправо, вправо, вниз, вниз), сумма `7`.

## Наивный подход

Рекурсивно перебрать все пути: из каждой клетки — вправо или вниз.

```ts naive
function best(i: number, j: number): number {
  if (i >= m || j >= n) return Infinity;
  if (i === m - 1 && j === n - 1) return grid[i][j];
  return grid[i][j] + Math.min(best(i + 1, j), best(i, j + 1));
}
```

Путей `C(m + n − 2, m − 1)` — при `200 × 200` это астрономическое число. Лишняя работа: в клетку `(1, 1)` можно попасть и через `(0, 1)`, и через `(1, 0)`, и рекурсия решает «лучший путь от `(1, 1)` до финиша» заново для каждого способа туда прийти. Хотя ответ от способа прихода не зависит.

Жадный выбор («иди туда, где меньше») ломается: дешёвый шаг может завести в дорогой угол.

## Ключевое наблюдение

В клетку `(i, j)` можно прийти **только двумя способами**: сверху из `(i − 1, j)` или слева из `(i, j − 1)`. Значит, лучший путь до неё — лучший из этих двух плюс её собственное число:

```
dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])
```

Ходы только вправо и вниз, поэтому обход строк сверху вниз, а внутри строки слева направо гарантирует: оба соседа уже посчитаны. Первая строка и первый столбец — особые: туда можно прийти только с одной стороны, и там стоят обычные префиксные суммы.

## Техники

### ДП на сетке

**Что это.** Классический вид двумерного ДП: `dp[i][j]` описывает лучший путь до клетки `(i, j)`, а переход перебирает клетки, из которых сюда можно сделать ход.

- **Состояние**: `dp[i][j]` — минимальная сумма пути от `(0, 0)` до `(i, j)`.
- **База**: `dp[0][0] = grid[0][0]`; первая строка `dp[0][j] = dp[0][j-1] + grid[0][j]`, первый столбец `dp[i][0] = dp[i-1][0] + grid[i][0]`.
- **Переход**: `dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])`.
- **Порядок**: строки сверху вниз, внутри — слева направо.
- **Ответ**: `dp[m-1][n-1]`.

Подробнее о многомерном ДП — во вкладке «Теория».

### Префиксные суммы на краях

В первую строку можно попасть только слева, поэтому `dp[0][j]` — сумма `grid[0][0..j]`, то есть префиксная сумма строки. Аналогично первый столбец — префиксная сумма столбца. Если посчитать края заранее, основной цикл обходится без проверок границ: у каждой внутренней клетки есть оба соседа.

## Разбор кода

```ts
function minPathSum(grid: number[][]): number {
  const m = grid.length;
  const n = grid[0].length;
  // Состояние: dp[i][j] — минимальная сумма пути из (0, 0) в клетку (i, j)
  const dp: number[][] = Array.from({ length: m }, () => new Array(n).fill(0));
```

Полная таблица того же размера, что и сетка. `Array.from` с функцией создаёт **отдельный** массив для каждой строки (а `new Array(m).fill(new Array(n))` положил бы во все строки одну и ту же ссылку).

```ts
  // База: стартовая клетка
  dp[0][0] = grid[0][0];
  // Первая строка: прийти можно только слева — префиксные суммы
  for (let j = 1; j < n; j++) dp[0][j] = dp[0][j - 1] + grid[0][j];
  // Первый столбец: прийти можно только сверху
  for (let i = 1; i < m; i++) dp[i][0] = dp[i - 1][0] + grid[i][0];
```

База целиком. Стартовая клетка стоит своё число — к ней ниоткуда не приходят. Каждая клетка первой строки — предыдущая плюс своё число; так же для первого столбца. Если сетка из одной строки или одного столбца, соответствующий цикл просто не выполнится.

```ts
  // Порядок: строки сверху вниз, внутри строки слева направо —
  // верхний и левый соседи к этому моменту уже посчитаны
  for (let i = 1; i < m; i++) {
    for (let j = 1; j < n; j++) {
      // Переход: приходим из лучшего соседа — сверху или слева
      dp[i][j] = grid[i][j] + Math.min(dp[i - 1][j], dp[i][j - 1]);
    }
  }
```

Основной цикл начинается с `(1, 1)`: края уже заполнены. Для каждой внутренней клетки оба соседа существуют и посчитаны — верхний на прошлой строке, левый на этой. Берём лучший вход и добавляем число клетки.

```ts
  // Ответ: правый нижний угол
  return dp[m - 1][n - 1];
}
```

Ответ — ячейка финиша.

## Трассировка

`grid = [[1, 3, 1], [1, 5, 1], [4, 2, 1]]`.

**База.** `dp[0][0] = 1`. Первая строка: `dp[0][1] = 1 + 3 = 4`, `dp[0][2] = 4 + 1 = 5`. Первый столбец: `dp[1][0] = 1 + 1 = 2`, `dp[2][0] = 2 + 4 = 6`.

```
1 4 5
2 . .
6 . .
```

**Основной цикл.**

```
(1,1): 5 + min(up=4, left=2) = 7
(1,2): 1 + min(up=5, left=7) = 6
(2,1): 2 + min(up=7, left=6) = 8
(2,2): 1 + min(up=6, left=8) = 7
```

Итоговая таблица:

```
1 4 5
2 7 6
6 8 7
```

Ответ `dp[2][2] = 7`. В последней клетке выиграл вход сверху (`6`): это путь по верхней строке и затем по правому столбцу. Чтобы восстановить сам путь, можно идти от финиша назад, каждый раз в соседа с меньшим `dp`.

## Почему это работает

Индукция по порядку обхода. Любой путь до `(i, j)`, кроме стартовой клетки, последним шагом приходит из `(i − 1, j)` или `(i, j − 1)`, и его часть до этой клетки — путь до соседа, стоимость которого не меньше оптимальной для соседа. Значит, `grid[i][j] + min(up, left)` — нижняя граница, и она достигается (оптимальный путь до лучшего соседа плюс шаг). Оба соседа посчитаны раньше: верхний — на прошлой строке, левый — на этой. Для клеток первой строки и первого столбца вход единственный, и префиксная сумма — единственный (а значит, лучший) путь.

## Пограничные случаи

- **Сетка `1 × 1`**: циклы не выполняются, ответ `grid[0][0]`.
- **Одна строка**: работает только цикл первой строки, путь — сумма строки.
- **Один столбец**: работает только цикл первого столбца, путь — сумма столбца.
- **Нули в сетке**: формула не меняется.
- **Вход не портится**: пишем только в `dp`.

## Сложность

- **Время `O(m · n)`**: каждая клетка обрабатывается один раз за `O(1)`.
- **Память `O(m · n)`**: полная таблица `dp`. При `200 × 200` это 40 тысяч чисел — пустяк.

**Follow-up на собеседовании: «а меньше памяти?»** Строка `i` зависит только от строки `i − 1`, поэтому хватает одного массива длины `n`: до перезаписи `dp[j]` хранит значение «сверху», а `dp[j − 1]` уже обновлён — это «слева».

```ts naive
const dp = new Array(n).fill(Infinity);
for (let i = 0; i < m; i++) {
  for (let j = 0; j < n; j++) {
    if (i === 0 && j === 0) dp[j] = grid[0][0];
    else dp[j] = grid[i][j] + Math.min(dp[j], j > 0 ? dp[j - 1] : Infinity);
  }
}
return dp[n - 1];
```

Память `O(n)`. А если разрешено портить вход, можно писать прямо в `grid` — `O(1)`.

## Типичные ошибки

1. **Жадный выбор** меньшего соседа на каждом шаге — не даёт оптимума.
2. **Забыть края**: если начать основной цикл с `(0, 0)` без проверок, обращение к `dp[-1]` даст `undefined`, а `Math.min` с ним — `NaN`.
3. **Края нулями**: оставить первую строку `0` вместо префиксных сумм — пути по краю окажутся «бесплатными».
4. **`new Array(m).fill(new Array(n))`** — все строки станут одним и тем же массивом.
5. **Применять Дейкстру/BFS** — работает, но избыточно: при ходах только вправо/вниз граф ацикличен, и простого ДП достаточно.

## Как узнать такую задачу

- Сетка, ходы **только вправо и вниз** (или другое направленное множество ходов без циклов), нужна минимальная/максимальная сумма или число путей.
- Ответ для клетки определяется ответами её «входных» соседей → ДП на сетке: таблица `m × n`, края — база, внутренние клетки — переход.
- Если ходы во все четыре стороны — это уже кратчайший путь в графе (Дейкстра, 0-1 BFS).

Родственные задачи: Unique Paths, Unique Paths II, Triangle, Dungeon Game, Cherry Pickup, Minimum Falling Path Sum.
