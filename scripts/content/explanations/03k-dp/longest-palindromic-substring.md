## Задача простыми словами

Дана строка `s`. Нужно вернуть её самую длинную **подстроку** (идущие подряд символы), которая читается одинаково слева направо и справа налево — палиндром.

Пример: `s = "babad"` → `"bab"` (подходит и `"aba"`, годится любой из ответов одинаковой длины). Для `s = "cbbd"` ответ `"bb"` — палиндром чётной длины.

## Наивный подход

Перебрать все подстроки и проверить каждую:

```ts naive
let best = s[0];
for (let i = 0; i < s.length; i++) {
  for (let j = i + 1; j <= s.length; j++) {
    const sub = s.slice(i, j);
    if (sub.length > best.length && sub === [...sub].reverse().join('')) best = sub;
  }
}
```

Подстрок `O(n²)`, проверка каждой — `O(n)`, итого `O(n³)`: при `n = 1000` это порядка миллиарда операций. Лишняя работа: проверка `"xabax"` заново сравнивает внутренность `"aba"`, хотя мы уже знаем, что она палиндром. Палиндромы **вложены** друг в друга: `"xabax"` — это `"aba"`, обёрнутый одинаковыми буквами.

## Ключевое наблюдение

Каждый палиндром симметричен относительно своего **центра**. Если зафиксировать центр и расширяться в обе стороны, пока символы совпадают, мы за один проход найдём **самый длинный** палиндром с этим центром — и заодно все более короткие (они вложены).

Центров всего `2n − 1`: `n` символов (палиндромы нечётной длины, `"aba"`) и `n − 1` промежутков между символами (чётной длины, `"abba"`). Перебрав все центры, найдём ответ за `O(n²)` без лишней памяти.

## Техники

### Расширение от центра (два указателя наружу)

**Что это.** Два указателя `left` и `right` стартуют в центре и одновременно шагают наружу, пока выполняется условие симметрии `s[left] === s[right]`. Это вариант техники двух указателей, где указатели движутся **в разные стороны** от общей точки.

**Когда применять.** Когда структура симметрична относительно центра (палиндромы), и для каждого центра достаточно найти максимальный радиус.

**Как применяется здесь.** Функция `expand(left, right)` возвращает длину максимального палиндрома с данным центром. Вызов `expand(i, i)` — центр в символе, `expand(i, i + 1)` — центр между символами.

### Связь с ДП

Классическое решение через двумерное ДП: `dp[i][j] = true`, если `s[i..j]` — палиндром, с переходом `dp[i][j] = s[i] === s[j] && dp[i+1][j-1]`. Расширение от центра использует **ту же самую** зависимость (палиндром = палиндром внутри + одинаковые края), но проходит её «изнутри наружу» вдоль одной диагонали таблицы за раз — поэтому таблица не нужна, и память падает с `O(n²)` до `O(1)`. Подробнее о многомерном ДП — во вкладке «Теория».

## Разбор кода

```ts
function longestPalindrome(s: string): string {
  // Границы лучшего найденного палиндрома: s.slice(bestStart, bestEnd)
  let bestStart = 0;
  let bestEnd = 1;
```

Лучший ответ хранится как полуинтервал `[bestStart, bestEnd)`. Стартуем с первого символа: строка непустая по условию, а любой одиночный символ — палиндром длины 1. Хранить индексы, а не саму подстроку, дешевле: `slice` делаем один раз в конце.

```ts
  // Расширяем палиндром от центра (left, right), пока символы совпадают.
  // Возвращаем длину самого длинного палиндрома с этим центром.
  const expand = (left: number, right: number): number => {
    while (left >= 0 && right < s.length && s[left] === s[right]) {
      left--;
      right++;
    }
    // После цикла left и right на шаг вышли за границы палиндрома
    return right - left - 1;
  };
```

Пока оба указателя внутри строки и символы под ними равны, шагаем наружу. Цикл останавливается, когда указатели стоят на **первой несовпадающей паре** (или за границей строки). Значит, палиндром — это `s[left + 1 .. right − 1]`, и его длина `(right − 1) − (left + 1) + 1 = right − left − 1`.

Для чётного центра `expand(i, i + 1)`: если `s[i] !== s[i + 1]`, цикл не выполнится ни разу, и функция вернёт `(i + 1) − i − 1 = 0` — «чётного палиндрома с этим центром нет».

```ts
  for (let i = 0; i < s.length; i++) {
    // Нечётная длина: центр — символ i ("aba")
    const odd = expand(i, i);
    // Чётная длина: центр между i и i + 1 ("abba")
    const even = expand(i, i + 1);
    const len = Math.max(odd, even);
```

Для каждой позиции проверяем два центра и берём лучший из двух палиндромов. Так перебираются все `2n − 1` центров (для последнего `i` чётный центр выходит за строку и даёт `0`).

```ts
    if (len > bestEnd - bestStart) {
      // Восстанавливаем начало по центру i и длине len
      bestStart = i - Math.floor((len - 1) / 2);
      bestEnd = bestStart + len;
    }
  }
```

Если палиндром длиннее лучшего, вычисляем его начало. Формула `i − ⌊(len − 1) / 2⌋` работает для обоих типов центра:

- нечётная длина `len = 2r + 1` с центром в `i`: слева от `i` ровно `r = (len − 1) / 2` символов;
- чётная длина `len = 2r` с центром между `i` и `i + 1`: левая половина — `s[i − r + 1 .. i]`, начало `i − r + 1 = i − ⌊(2r − 1) / 2⌋`.

```ts
  return s.slice(bestStart, bestEnd);
}
```

Вырезаем лучший палиндром один раз.

## Трассировка

`s = "babad"`, старт: `bestStart = 0`, `bestEnd = 1` (`"b"`).

1. `i = 0`: `expand(0, 0)` — шаг до `left = −1`, `right = 1`, длина `1`. `expand(0, 1)`: `'b' ≠ 'a'`, длина `0`. `len = 1`, не лучше.
2. `i = 1`: `expand(1, 1)` — `(1,1)` совпало, `(0,2)`: `'b' = 'b'`, совпало, дальше `left = −1` — стоп при `left = −1`, `right = 3`, длина `3`. `expand(1, 2)`: `'a' ≠ 'b'`, `0`. `len = 3 > 1` → `bestStart = 1 − ⌊2/2⌋ = 0`, `bestEnd = 3` (`"bab"`).
3. `i = 2`: `expand(2, 2)` — `(1,3)`: `'a' = 'a'`, `(0,4)`: `'b' ≠ 'd'` — стоп при `left = 0`, `right = 4`, длина `3`. Чётный — `0`. `len = 3`, не больше `3`.
4. `i = 3`: `expand(3, 3)` — `(2,4)`: `'b' ≠ 'd'`, длина `1`. Чётный `'a' ≠ 'd'` — `0`.
5. `i = 4`: нечётный — `1`, чётный — `right = 5` вне строки, `0`.

Ответ `"bab"`. Палиндром `"aba"` той же длины не заменил его из-за строгого `>`.

Чётный случай, `s = "cbbd"`: при `i = 1` `expand(1, 2)` — `'b' = 'b'`, затем `(0,3)`: `'c' ≠ 'd'`, длина `3 − 0 − 1 = 2`. `bestStart = 1 − ⌊1/2⌋ = 1`, `bestEnd = 3` → `"bb"`.

## Почему это работает

У самого длинного палиндрома `s[a..b]` есть центр — символ (если длина нечётна) или промежуток (если чётна). Когда цикл доходит до этого центра, `expand` расширяется как минимум до `[a, b]`: все симметричные пары внутри совпадают, поэтому цикл не остановится раньше. Длиннее он тоже не станет — иначе нашёлся бы палиндром длиннее максимального. Значит, ответ будет найден и зафиксирован в `bestStart`/`bestEnd`. Ни один найденный кандидат не может быть не палиндромом — `expand` расширяется только по совпадающим парам.

## Пограничные случаи

- **Один символ**: начальные `bestStart = 0`, `bestEnd = 1` уже ответ.
- **Вся строка — палиндром** (`"racecar"`): расширение от центра дойдёт до краёв.
- **Все символы одинаковые** (`"aaaa"`): лучший — чётный центр посередине, длина `4`.
- **Нет палиндромов длиннее 1** (`"abcd"`): возвращается первый символ.
- **Несколько ответов одинаковой длины**: возвращается самый левый (строгое `>`), что допустимо.

## Сложность

- **Время `O(n²)`**: `2n − 1` центров, каждое расширение — до `O(n)` шагов. В худшем случае (`"aaaa…"`) так и выходит; в типичных строках расширения короткие.
- **Память `O(1)`**: несколько индексов; подстрока создаётся один раз в конце.

Для сравнения: ДП-таблица даёт то же время, но `O(n²)` памяти. Алгоритм Манакера решает задачу за `O(n)`, но на собеседованиях его почти не требуют.

## Типичные ошибки

1. **Забыть чётные палиндромы** — проверять только `expand(i, i)`; тогда для `"cbbd"` ответ будет `"c"`.
2. **Неверная длина после цикла**: `right − left + 1` вместо `right − left − 1` — указатели уже вышли за палиндром.
3. **Неверная формула начала**: `i − len / 2` даёт сдвиг на единицу для чётных длин.
4. **Путать подстроку и подпоследовательность**: Longest Palindromic Subsequence — другая задача с другим ДП.
5. **Сравнивать со строкой-разворотом** всю строку (`s` против `reverse(s)`) через LCS — общая подстрока строки и её разворота не обязана быть палиндромом.

## Как узнать такую задачу

- Речь о **палиндромах в подстроках**: самый длинный, количество (Palindromic Substrings), проверка множества отрезков.
- Свойство «большой объект = маленький такой же объект + одинаковые края» → либо ДП по отрезкам `dp[i][j]`, либо расширение от центра.
- Ограничение `n ≤ 1000–5000` намекает на `O(n²)`.

Родственные задачи: Palindromic Substrings, Longest Palindromic Subsequence, Palindrome Partitioning II, Shortest Palindrome.
