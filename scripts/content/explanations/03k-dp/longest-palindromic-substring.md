## Задача простыми словами

Дана строка `s`. Нужно вернуть её самую длинную **подстроку** (идущие подряд символы), которая читается одинаково слева направо и справа налево — палиндром.

Пример: `s = "babad"` → `"bab"` (подходит и `"aba"`, годится любой из ответов одинаковой длины). Для `s = "cbbd"` ответ `"bb"` — палиндром чётной длины.

## Наивный подход

Перебрать все подстроки и проверить каждую:

```ts naive
let best = s[0];
for (let i = 0; i < s.length; i++) {
  for (let j = i + 1; j <= s.length; j++) {
    const sub = s.slice(i, j);
    if (sub.length > best.length && sub === [...sub].reverse().join('')) best = sub;
  }
}
```

Подстрок `O(n²)`, проверка каждой — `O(n)`, итого `O(n³)`: при `n = 1000` это порядка миллиарда операций. Лишняя работа: проверка `"xabax"` заново сравнивает внутренность `"aba"`, хотя мы уже знаем, что она палиндром. Палиндромы **вложены** друг в друга: `"xabax"` — это `"aba"`, обёрнутый одинаковыми буквами.

## Ключевое наблюдение

Подстрока `s[i..j]` — палиндром тогда и только тогда, когда её **крайние символы равны** и **середина** `s[i+1..j-1]` — тоже палиндром. Ответ для длинной подстроки выражается через ответ для подстроки на 2 символа короче.

Значит, если запомнить ответ «палиндром или нет» для каждой пары `(i, j)`, проверка любой подстроки станет `O(1)`: одно сравнение символов плюс один взгляд в таблицу. Пар `O(n²)` — это и есть итоговое время.

## Техники

### Двумерное ДП по отрезкам

**Что это.** ДП, где состояние — отрезок `[i, j]` строки или массива, а переход выражает отрезок через более короткие отрезки внутри него. Так решаются задачи про палиндромы, разбиение отрезков, игры на краях массива.

**Пять вопросов:**

1. **Состояние**: `dp[i][j]` — является ли `s[i..j]` (включительно) палиндромом.
2. **База**: отрезки длины 1 (`j = i`) и 2 (`j = i + 1`) — палиндромы, если `s[i] === s[j]` (для длины 1 это всегда так). Середины у них нет или она пустая.
3. **Переход**: `dp[i][j] = s[i] === s[j] && dp[i + 1][j - 1]` для длины `≥ 3`.
4. **Порядок**: `dp[i][j]` зависит от `dp[i + 1][j - 1]` — ячейки на **строку ниже**. Поэтому строки заполняем снизу вверх: `i` от `n − 1` до `0`, а внутри строки `j` от `i` вправо.
5. **Ответ**: самый длинный отрезок с `dp[i][j] = true` — запоминаем его по ходу заполнения.

Базу и переход удобно записать одной формулой:

```
dp[i][j] = s[i] === s[j] && (j - i < 2 || dp[i + 1][j - 1])
```

Подробнее о многомерном ДП — во вкладке «Теория».

### Почему именно такой порядок

Можно заполнять и «по возрастанию длины» (сначала все отрезки длины 1, потом 2, …) — это тоже корректно. Обход `i` с конца проще: два обычных цикла, и к моменту расчёта строки `i` строка `i + 1` уже полностью готова, а нужная ячейка `dp[i + 1][j - 1]` в ней есть.

## Разбор кода

```ts
function longestPalindrome(s: string): string {
  const n = s.length;
  // Состояние: dp[i][j] — является ли подстрока s[i..j] (включительно) палиндромом
  const dp: boolean[][] = Array.from({ length: n }, () => new Array(n).fill(false));
  // Лучший найденный палиндром: начало и длина
  let bestStart = 0;
  let bestLen = 1;
```

Таблица `n × n` из `false`. Используется только верхний треугольник (`j ≥ i`). Лучший ответ храним как начало и длину; стартуем с первого символа — строка непустая, а любой символ — палиндром длины 1.

```ts
  // Порядок: i от конца к началу — строка dp[i + 1] к этому моменту готова
  for (let i = n - 1; i >= 0; i--) {
    for (let j = i; j < n; j++) {
```

Внешний цикл идёт снизу вверх по строкам таблицы, внутренний — по правой границе отрезка, начиная с самого короткого отрезка `[i, i]`.

```ts
      // Переход: крайние символы равны, а середина s[i + 1..j - 1] — палиндром.
      // База: длины 1 и 2 (j - i < 2) — хватает равенства крайних символов
      dp[i][j] = s[i] === s[j] && (j - i < 2 || dp[i + 1][j - 1]);
```

Сердце решения. Сначала сравниваем края: если они разные, отрезок точно не палиндром. Если равны и отрезок короче трёх символов — это база, палиндром. Иначе смотрим на середину. Благодаря короткому замыканию `||` при `j - i < 2` к `dp[i + 1][j - 1]` мы не обращаемся — а при `i = n − 1` строки `dp[n]` и не существует.

```ts
      // Запоминаем самый длинный палиндром
      if (dp[i][j] && j - i + 1 > bestLen) {
        bestStart = i;
        bestLen = j - i + 1;
      }
    }
  }
```

Если отрезок — палиндром и он длиннее рекорда, обновляем ответ. Длина отрезка `[i, j]` включительно — `j − i + 1`.

```ts
  // Ответ: вырезаем лучший палиндром
  return s.slice(bestStart, bestStart + bestLen);
}
```

`slice` делаем один раз в конце — хранить индексы дешевле, чем копировать подстроки.

## Трассировка

`s = "cbbd"` (`n = 4`), стартовый ответ `"c"`. Строки таблицы считаем снизу вверх.

```
i=3: j=3 'd'='d', длина 1                 → T
i=2: j=2                                  → T
     j=3 'b'≠'d'                          → F
i=1: j=1                                  → T
     j=2 'b'='b', длина 2 (j-i<2)         → T   рекорд: start=1, len=2
     j=3 'b'≠'d'                          → F
i=0: j=0                                  → T
     j=1 'c'≠'b'                          → F
     j=2 'c'≠'b'                          → F
     j=3 'c'≠'d'                          → F
```

Таблица (`.` — не используется):

```
      j=0 j=1 j=2 j=3
i=0    T   F   F   F
i=1    .   T   T   F
i=2    .   .   T   F
i=3    .   .   .   T
```

Ответ `s.slice(1, 3) = "bb"`.

`s = "babad"`: при `i = 2` отрезок `[2, 4]` — `'b' ≠ 'd'`, `F`. При `i = 1`: `[1, 3]` — `'a' = 'a'` и середина `dp[2][2] = T` → `T`, рекорд `"aba"` (start 1, len 3). При `i = 0`: `[0, 2]` — `'b' = 'b'` и `dp[1][1] = T` → `T`, но длина `3` не больше рекорда; `[0, 4]` — `'b' ≠ 'd'`. Ответ `"aba"` — тоже правильный (подходит любой палиндром максимальной длины).

## Почему это работает

Индукция по длине отрезка. Отрезки длины 1 и 2 — палиндромы ровно тогда, когда крайние символы равны: это база. Для длины `≥ 3` строка — палиндром ровно тогда, когда `s[i] = s[j]` (первая и последняя буквы совпадают) и середина читается одинаково в обе стороны. Середина короче на 2 и лежит в строке `i + 1`, которая посчитана раньше (обход `i` с конца), — по предположению индукции её значение верно. Мы просматриваем **все** пары `i ≤ j`, поэтому самый длинный палиндром будет встречен и записан в `bestStart`/`bestLen`.

## Пограничные случаи

- **Один символ**: таблица `1 × 1`, `dp[0][0] = T`, ответ — сама строка (`bestLen = 1` с самого начала).
- **Вся строка — палиндром** (`"racecar"`): последним заполнится `dp[0][n-1] = T`.
- **Все символы одинаковые** (`"aaaa"`): все ячейки верхнего треугольника `T`, ответ — вся строка.
- **Нет палиндромов длиннее 1** (`"abcd"`): возвращается первый символ.
- **Несколько ответов одинаковой длины**: возвращается тот, что найден первым при обходе (для `"babad"` — `"aba"`), что допустимо.

## Сложность

- **Время `O(n²)`**: заполняем `n · (n + 1) / 2` ячеек, каждая за `O(1)`.
- **Память `O(n²)`**: таблица `dp`. При `n ≤ 1000` это миллион булевых значений — допустимо.

**Follow-up на собеседовании: память `O(1)`.** Каждый палиндром симметричен относительно центра — символа (`"aba"`) или промежутка между символами (`"abba"`), всего `2n − 1` центров. Для каждого центра расширяемся наружу, пока символы совпадают: это та же зависимость «края + середина», пройденная изнутри наружу вдоль одной диагонали таблицы, поэтому сама таблица не нужна.

```ts naive
const expand = (left: number, right: number): number => {
  while (left >= 0 && right < s.length && s[left] === s[right]) {
    left--;
    right++;
  }
  return right - left - 1; // длина палиндрома с этим центром
};
```

Время то же `O(n²)`, память `O(1)`. Алгоритм Манакера решает задачу за `O(n)`, но на собеседованиях его почти не требуют.

## Типичные ошибки

1. **Неверный порядок обхода**: `i` от `0` вверх — тогда `dp[i + 1][j - 1]` ещё не посчитан и всегда `false`, найдутся только палиндромы длины 1–2.
2. **Забыть базу длины 2**: условие `j - i < 1` вместо `j - i < 2` — для `"bb"` переход посмотрит на `dp[i + 1][i]` (пустая середина, `false`), и `"cbbd"` даст `"c"`.
3. **Длина `j − i` вместо `j − i + 1`** — отрезок включительный.
4. **Путать подстроку и подпоследовательность**: Longest Palindromic Subsequence — другая задача с другим переходом (`dp[i+1][j-1] + 2` или `max` соседей).
5. **Сравнивать строку с её разворотом** через общую подстроку — общая подстрока `s` и `reverse(s)` не обязана быть палиндромом.

## Как узнать такую задачу

- Речь о **палиндромах в подстроках**: самый длинный, количество (Palindromic Substrings), проверка многих отрезков.
- Свойство «большой объект = маленький такой же объект + одинаковые края» → ДП по отрезкам `dp[i][j]` с обходом от коротких отрезков к длинным.
- Ограничение `n ≤ 1000–5000` намекает на `O(n²)`.

Родственные задачи: Palindromic Substrings, Longest Palindromic Subsequence, Palindrome Partitioning II, Shortest Palindrome.
