## Задача простыми словами

Дан массив цен акции по дням `prices`. Можно совершить **не более двух сделок** (сделка = купить, потом продать), причём одновременно держать можно только одну акцию: перед новой покупкой нужно продать предыдущую. Нужно вернуть максимальную прибыль.

Пример: `prices = [3, 3, 5, 0, 0, 3, 1, 4]`. Покупаем по `0`, продаём по `3` (+3), покупаем по `1`, продаём по `4` (+3) — итого `6`. Если цены только падают (`[7, 6, 4, 3, 1]`), лучше ничего не делать — ответ `0`.

## Наивный подход

Две сделки не пересекаются во времени, значит, есть день-разрез `i`: первая сделка целиком в днях `0..i`, вторая — в днях `i..n−1`. Для каждого разреза можно отдельно найти лучшую одиночную сделку слева и справа (как в Stock I — проход с минимумом цены):

```ts naive
function oneTrade(a: number[], from: number, to: number): number {
  let minPrice = Infinity, best = 0;
  for (let i = from; i <= to; i++) {
    minPrice = Math.min(minPrice, a[i]);
    best = Math.max(best, a[i] - minPrice);
  }
  return best;
}
let ans = 0;
for (let i = 0; i < n; i++) ans = Math.max(ans, oneTrade(prices, 0, i) + oneTrade(prices, i, n - 1));
```

Это `O(n²)`: при `n = 10⁵` — 10 миллиардов операций. Лишняя работа: для соседних разрезов `i` и `i + 1` левая часть отличается всего на один день, но каждый раз пересчитывается с нуля. То же самое с правой частью. (Ещё хуже — перебор всех четвёрок дней покупки/продажи, `O(n⁴)`.)

## Ключевое наблюдение

Лучшая одиночная сделка в днях `0..i` получается из лучшей сделки в днях `0..i−1` за `O(1)`: либо она была раньше, либо мы продаём **сегодня** по самой низкой цене, встреченной до сих пор. Значит, ответы для **всех** префиксов можно посчитать одним проходом слева направо и сложить в массив `left`.

Симметрично, лучшая сделка в днях `i..n−1` получается из ответа для `i+1..n−1`: либо она будет позже, либо мы покупаем **сегодня** и продаём по самой высокой цене справа. Один проход справа налево — массив `right`.

После этого каждый разрез стоит `O(1)`: `left[i] + right[i]`. Итого три линейных прохода.

## Техники

### ДП по префиксам и суффиксам

**Что это.** Если ответ складывается из «левой» и «правой» частей относительно точки разреза, заранее считаем ответ для каждого префикса (`left`) и для каждого суффикса (`right`) — каждое отдельным линейным ДП. Затем перебираем точку разреза. Тот же приём — в Product of Array Except Self и Trapping Rain Water.

**Пять вопросов** (для `left`; `right` — зеркально):

1. **Состояние**: `left[i]` — лучшая прибыль одной сделкой в днях `0..i`; `right[i]` — в днях `i..n−1`.
2. **База**: `left[0] = 0`, `right[n−1] = 0` — за один день ничего не заработать.
3. **Переход**: `left[i] = max(left[i−1], prices[i] − minPrice)`, где `minPrice` — минимум `prices[0..i]`; `right[i] = max(right[i+1], maxPrice − prices[i])`, где `maxPrice` — максимум `prices[i..n−1]`.
4. **Порядок**: `left` — слева направо, `right` — справа налево.
5. **Ответ**: `max(left[i] + right[i])` по всем `i`.

Подробнее о ДП — во вкладке «Теория».

### Общий день разреза

Обе половины включают день `i`. Это не нарушает правило «не держать две акции»: если первая сделка продаёт в день `i`, а вторая в тот же день покупает, это всё равно что одна длинная сделка — такая комбинация не даёт больше, чем допускают две честные сделки. А любой реальный план из двух сделок попадает в какой-то разрез — например, в день продажи первой акции.

## Разбор кода

```ts
function maxProfit(prices: number[]): number {
  const n = prices.length;
  // Состояние: left[i] — лучшая прибыль одной сделкой в днях 0..i,
  // right[i] — лучшая прибыль одной сделкой в днях i..n-1.
  // База: left[0] = 0 и right[n - 1] = 0 — за один день ничего не заработать
  const left: number[] = new Array(n).fill(0);
  const right: number[] = new Array(n).fill(0);
```

Две таблицы длины `n`, заполненные нулями. Нули — это и база, и «ничего не делать», и нижняя граница любой ячейки: прибыль одной сделки не бывает отрицательной, ведь сделку можно не совершать.

```ts
  // Проход слева направо: помним самую низкую цену покупки до дня i
  let minPrice = prices[0];
  for (let i = 1; i < n; i++) {
    minPrice = Math.min(minPrice, prices[i]);
    // Переход: либо продаём сегодня, либо лучшая сделка была раньше
    left[i] = Math.max(left[i - 1], prices[i] - minPrice);
  }
```

Это ровно решение Stock I, только ответ запоминается для каждого префикса. `minPrice` обновляется **до** перехода, поэтому включает и сегодняшний день — тогда `prices[i] − minPrice` может быть `0` (купили и продали сегодня), но не отрицательным.

```ts
  // Проход справа налево: помним самую высокую цену продажи после дня i
  let maxPrice = prices[n - 1];
  for (let i = n - 2; i >= 0; i--) {
    maxPrice = Math.max(maxPrice, prices[i]);
    // Переход: либо покупаем сегодня, либо лучшая сделка будет позже
    right[i] = Math.max(right[i + 1], maxPrice - prices[i]);
  }
```

Зеркальный проход. Идём с конца, помним максимальную цену справа — лучший день продажи для покупки сегодня. `right[i + 1]` — лучшая сделка, которая целиком позже.

```ts
  // Ответ: разрезаем по дню i — первая сделка в 0..i, вторая в i..n-1.
  // Общий день не мешает: продать и купить в один день — всё равно что не продавать
  let best = 0;
  for (let i = 0; i < n; i++) {
    best = Math.max(best, left[i] + right[i]);
  }
  return best;
}
```

Перебираем все разрезы. Одна сделка или ни одной — частные случаи: при разрезе в последний день `right[n−1] = 0`, и получаем просто лучшую одиночную сделку.

## Трассировка

`prices = [3, 3, 5, 0, 0, 3, 1, 4]`.

**Проход слева** (`minPrice` старт `3`):

```
i=1 p=3: min=3, max(0, 0) = 0
i=2 p=5: min=3, max(0, 2) = 2
i=3 p=0: min=0, max(2, 0) = 2
i=4 p=0: min=0, max(2, 0) = 2
i=5 p=3: min=0, max(2, 3) = 3
i=6 p=1: min=0, max(3, 1) = 3
i=7 p=4: min=0, max(3, 4) = 4
```

**Проход справа** (`maxPrice` старт `4`):

```
i=6 p=1: max=4, max(0, 3) = 3
i=5 p=3: max=4, max(3, 1) = 3
i=4 p=0: max=4, max(3, 4) = 4
i=3 p=0: max=4, max(4, 4) = 4
i=2 p=5: max=5, max(4, 0) = 4
i=1 p=3: max=5, max(4, 2) = 4
i=0 p=3: max=5, max(4, 2) = 4
```

**Таблицы и сумма:**

```
i:       0  1  2  3  4  5  6  7
prices:  3  3  5  0  0  3  1  4
left:    0  0  2  2  2  3  3  4
right:   4  4  4  4  4  3  3  0
sum:     4  4  6  6  6  6  6  4
```

Ответ `6`. Например, разрез `i = 2`: слева сделка `3 → 5` (+2), справа `0 → 4` (+4). Разрез `i = 5`: слева `0 → 3` (+3), справа `1 → 4` (+3). Оба варианта дают `6` — это два разных оптимальных плана.

Падающие цены `[7, 6, 4, 3, 1]`: `prices[i] − minPrice` всегда `0`, и `maxPrice − prices[i]` тоже `0` — обе таблицы из нулей, ответ `0`.

## Почему это работает

**Таблицы верны** по индукции. Лучшая сделка в днях `0..i` либо не продаёт в день `i` — тогда она целиком в `0..i−1`, и это `left[i−1]`; либо продаёт в день `i` — тогда выгоднее всего покупать по минимальной цене в `0..i`, это `prices[i] − minPrice`. Для `right` — зеркально.

**Перебор разрезов верен.** Любой план из двух непересекающихся сделок: первая продаёт в день `d`, вторая покупает не раньше `d`. Разрез `i = d` содержит первую сделку слева и вторую справа, поэтому `left[d] + right[d]` не меньше прибыли этого плана. Обратно, каждая сумма `left[i] + right[i]` достижима: две сделки в `0..i` и в `i..n−1` пересекаются максимум в одном дне, а «продать и купить в один день» эквивалентно одной сделке. Значит, максимум сумм — ровно ответ.

## Пограничные случаи

- **Один день**: оба цикла-прохода не выполняются, `left[0] + right[0] = 0`.
- **Цены только падают**: ответ `0`.
- **Цены только растут** (`[1, 2, 3, 4, 5]`): лучший разрез — край, одна сделка `1 → 5`, ответ `4`.
- **Нулевые цены**: никаких особых случаев.
- **Одинаковые цены подряд**: таблицы просто не растут.

## Сложность

- **Время `O(n)`**: три линейных прохода.
- **Память `O(n)`**: массивы `left` и `right`.

**Follow-up на собеседовании: память `O(1)`.** Конечный автомат из четырёх этапов: держим первую акцию → продали первую → держим вторую → продали вторую. Для каждого этапа храним лучший баланс и обновляем его на каждой цене `p`:

```ts naive
let buy1 = -Infinity, sell1 = 0, buy2 = -Infinity, sell2 = 0;
for (const p of prices) {
  buy1 = Math.max(buy1, -p);
  sell1 = Math.max(sell1, buy1 + p);
  buy2 = Math.max(buy2, sell1 - p);
  sell2 = Math.max(sell2, buy2 + p);
}
return sell2;
```

Один проход, четыре переменные. Этот же автомат обобщается на `k` сделок (задача Stock IV).

## Типичные ошибки

1. **Взять две лучшие непересекающиеся «восходящие серии»** — не работает: оптимум может склеить несколько серий в одну сделку (`[1, 5, 4, 8, 1, 3]` — серии `+4`, `+4`, `+2`, две лучшие дают `8`, а `1→8` и `1→3` дают `9`).
2. **`right[i]` через минимум** вместо максимума: справа мы ищем день **продажи** для покупки сегодня, а не день покупки.
3. **Требовать ровно две сделки** — ответом может быть одна сделка или ни одной; нули в таблицах (база и «не торговать») это учитывают автоматически.
4. **Пересчитывать половины для каждого разреза** — возврат к `O(n²)`.
5. **Разрез «строго между днями»** (`left[i] + right[i + 1]`) — тоже верно, но требует аккуратности с границами; с общим днём проще.

## Как узнать такую задачу

- Ответ — **две независимые части** до и после какой-то точки: две сделки, два непересекающихся подмассива, «лучшее слева + лучшее справа».
- Каждая часть — известная задача, решаемая одним проходом → считаем её для всех префиксов и суффиксов, затем перебираем разрез.
- Ограничение «не более `k` раз» при больших `k` — уже дополнительное измерение ДП (Stock IV).

Родственные задачи: Best Time to Buy and Sell Stock (I, II, IV), Maximum Sum of Two Non-Overlapping Subarrays, Product of Array Except Self, Trapping Rain Water.
