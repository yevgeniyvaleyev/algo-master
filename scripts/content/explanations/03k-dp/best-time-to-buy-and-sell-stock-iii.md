## Задача простыми словами

Дан массив цен акции по дням `prices`. Можно совершить **не более двух сделок** (сделка = купить, потом продать), причём одновременно держать можно только одну акцию: перед новой покупкой нужно продать предыдущую. Нужно вернуть максимальную прибыль.

Пример: `prices = [3, 3, 5, 0, 0, 3, 1, 4]`. Покупаем по `0`, продаём по `3` (+3), покупаем по `1`, продаём по `4` (+3) — итого `6`. Если цены только падают (`[7, 6, 4, 3, 1]`), лучше ничего не делать — ответ `0`.

## Наивный подход

Две сделки не пересекаются во времени, значит, есть день-разрез `k`: первая сделка целиком до него, вторая — после. Для каждого разреза можно найти лучшую одиночную сделку слева и справа (как в Stock I — проход с минимумом цены):

```ts naive
function oneTrade(a: number[], from: number, to: number): number {
  let minPrice = Infinity, best = 0;
  for (let i = from; i < to; i++) {
    minPrice = Math.min(minPrice, a[i]);
    best = Math.max(best, a[i] - minPrice);
  }
  return best;
}
let ans = 0;
for (let k = 0; k <= n; k++) ans = Math.max(ans, oneTrade(prices, 0, k) + oneTrade(prices, k, n));
```

Это `O(n²)`: при `n = 10⁵` — 10 миллиардов операций. Лишняя работа: для соседних разрезов `k` и `k + 1` левая и правая части почти одинаковы, но каждый раз пересчитываются с нуля. (Ещё хуже — перебор всех четвёрок дней покупки/продажи, `O(n⁴)`.)

## Ключевое наблюдение

В каждый момент мы находимся в одном из **этапов**: ещё ничего не купили → держим первую акцию → продали первую → держим вторую → продали вторую. Для каждого этапа достаточно помнить **один** лучший баланс (прибыль в деньгах), с которым можно оказаться в нём к текущему дню. С новым днём каждый этап либо остаётся как есть, либо получается из предыдущего этапа одной операцией по цене `p`.

Получаем четыре числа, которые обновляются за `O(1)` на каждый день, — `O(n)` времени и `O(1)` памяти.

## Техники

### ДП как конечный автомат состояний

**Что это.** Многие задачи «последовательность дней + ограничения на действия» описываются автоматом: набор состояний и переходы между ними по одному элементу входа. ДП хранит для каждого состояния лучшее значение, а на каждом шаге применяет переходы. Это двумерное ДП «день × состояние», где измерение «день» сжато до текущего значения, потому что новый день зависит только от предыдущего.

```
         -p           +p           -p           +p
старт ───────▶ buy1 ───────▶ sell1 ───────▶ buy2 ───────▶ sell2
                ↺            ↺              ↺             ↺
            (ничего не делаем — остаёмся в состоянии)
```

**Как применяется здесь.** Состояний четыре (`buy1`, `sell1`, `buy2`, `sell2`), значение — максимальный баланс. Переход «остаться» — `max` с самим собой. Подробнее о многомерном ДП — во вкладке «Теория».

### Баланс вместо прибыли

Удобно считать не «прибыль сделки», а **текущий баланс кошелька**, начиная с `0`: покупка по цене `p` — это `−p`, продажа — `+p`. Тогда второй покупке не нужно знать, какой была первая сделка: она стартует с баланса `sell1`.

## Разбор кода

```ts
function maxProfit(prices: number[]): number {
  // Четыре состояния — лучший баланс после каждого этапа:
  // buy1  — купили первую акцию
  // sell1 — продали первую (одна сделка завершена)
  // buy2  — купили вторую
  // sell2 — продали вторую (две сделки завершены)
  let buy1 = -Infinity;
  let sell1 = 0;
  let buy2 = -Infinity;
  let sell2 = 0;
```

Начальные значения — до первого дня. Состояния «держим акцию» недостижимы (ещё ничего не куплено) — `-Infinity`, чтобы они не выигрывали ни одного `max`. Состояния «продали» стартуют с `0`: это одновременно и «ничего не делали», и «совершили пустую сделку» — баланс тот же.

```ts
  for (const p of prices) {
    // В каждом состоянии либо ничего не делаем, либо переходим из предыдущего.
    // Порядок обновления не мешает: «купить и продать в тот же день» даёт 0 прибыли
    buy1 = Math.max(buy1, -p); // первая покупка: отдаём p
    sell1 = Math.max(sell1, buy1 + p); // первая продажа: получаем p
```

Для каждой цены `p` обновляем состояния по порядку этапов. `buy1` — лучший из вариантов «уже держали» и «покупаем сегодня» (баланс `0 − p`). По сути `buy1` — это минус минимальная цена на данный момент. `sell1` — «уже продали раньше» или «продаём сегодня то, что держим».

```ts
    buy2 = Math.max(buy2, sell1 - p); // вторая покупка на деньги после первой сделки
    sell2 = Math.max(sell2, buy2 + p); // вторая продажа
  }
```

Вторая сделка устроена так же, но стартует не с нуля, а с баланса после первой (`sell1`). Так прибыль первой сделки «переносится» во вторую.

Тонкость — обновление «на месте»: `sell1` использует уже **сегодняшний** `buy1`, хотя формально должен вчерашний. Разница возникает, только если `buy1` обновился сегодня, то есть мы «купили сегодня» — тогда `buy1 + p` означает «купили и продали в тот же день»: баланс не меняется, такая пустая сделка ничего не портит. То же для `buy2` и `sell2`.

```ts
  // sell2 >= sell1 >= 0: одна сделка или ни одной — частные случаи
  return sell2;
}
```

Почему ответ — `sell2`, а не максимум из `0`, `sell1`, `sell2`? Благодаря пустым сделкам «одна реальная сделка» — это две сделки, одна из которых пустая; поэтому `sell2` всегда не меньше `sell1`, а `sell1` — не меньше `0`.

## Трассировка

`prices = [3, 3, 5, 0, 0, 3, 1, 4]`, старт: `buy1 = −∞`, `sell1 = 0`, `buy2 = −∞`, `sell2 = 0`.

```
p=3: buy1=max(−∞,−3)=−3  sell1=max(0,0)=0   buy2=max(−∞,−3)=−3  sell2=max(0,0)=0
p=3: buy1=−3             sell1=0            buy2=−3             sell2=0
p=5: buy1=−3             sell1=max(0,2)=2   buy2=max(−3,−3)=−3  sell2=max(0,2)=2
p=0: buy1=max(−3,0)=0    sell1=max(2,0)=2   buy2=max(−3,2)=2    sell2=max(2,2)=2
p=0: buy1=0              sell1=2            buy2=2              sell2=2
p=3: buy1=0              sell1=max(2,3)=3   buy2=max(2,0)=2     sell2=max(2,5)=5
p=1: buy1=0              sell1=3            buy2=max(2,2)=2     sell2=5
p=4: buy1=0              sell1=max(3,4)=4   buy2=max(2,0)=2     sell2=max(5,6)=6
```

Ответ `6`. Интересно, что автомат нашёл другой оптимальный план: `buy2 = 2` при `p = 0` — это «продали первую по 5 (купив по 3), купили вторую по 0», а затем продажа по 4 даёт `2 + 4 = 6`. Сделки `3→5` и `0→4` в сумме тоже `6`.

Падающие цены `[7, 6, 4, 3, 1]`: `buy1` растёт до `−1`, но `buy1 + p` никогда не больше `0` — `sell1` и `sell2` остаются `0`.

## Почему это работает

**Инвариант:** после обработки дня `t` каждая переменная равна максимальному балансу среди всех допустимых последовательностей действий за дни `0..t`, заканчивающихся в соответствующем этапе (с разрешёнными пустыми сделками в один день).

Индукция по дням: в этап можно попасть к дню `t`, либо уже находясь в нём к дню `t − 1` (ничего не делаем), либо выполнив сегодня операцию из предыдущего этапа. Ровно эти два варианта и сравнивает каждый `max`. Использование сегодняшнего значения предыдущего этапа добавляет только варианты с пустой сделкой в один день — они допустимы и баланс не увеличивают сверх реальных возможностей. Итог — максимум по всем планам с не более чем двумя сделками.

## Пограничные случаи

- **Один день**: любая сделка пустая, ответ `0`.
- **Цены только падают**: ответ `0` — `sell`-состояния не растут выше начального нуля.
- **Цены только растут** (`[1, 2, 3, 4, 5]`): лучшая — одна сделка `1 → 5`, ответ `4`; вторая сделка «пустая».
- **Нулевые цены**: `-p = 0`, никаких особых случаев.
- **Одинаковые цены подряд**: состояния просто не меняются.

## Сложность

- **Время `O(n)`**: один проход, четыре `max` на день.
- **Память `O(1)`**: четыре переменные.

## Типичные ошибки

1. **Взять две лучшие непересекающиеся «восходящие серии»** — не работает: оптимум может склеить несколько серий в одну сделку (`[1, 5, 4, 8, 1, 3]` — серии `+4`, `+4`, `+2`, две лучшие дают `8`, а `1→8` и `1→3` дают `9`).
2. **Инициализировать `buy1`/`buy2` нулём** — получится «бесплатная» акция, продажа даст прибыль `p` из воздуха.
3. **`buy2 = max(buy2, -p)`** вместо `sell1 − p` — прибыль первой сделки теряется, сделки становятся независимыми.
4. **Бояться обновления «на месте»** и копировать все переменные во временные — корректно, но лишне; важно понимать, почему и без этого верно.
5. **Ответ `max(sell1, sell2)`** — не ошибка, но избыточно: `sell2 >= sell1` всегда.

## Как узнать такую задачу

- Последовательность цен/событий и **ограничение на действия**: число сделок, «остывание» после продажи, комиссия. Состояние описывается этапом → ДП-автомат с несколькими переменными.
- Любое ограничение вида «не более `k` раз» — дополнительное измерение состояния.

Родственные задачи: Best Time to Buy and Sell Stock (I, II, IV), Stock with Cooldown, Stock with Transaction Fee. Задача IV обобщает это решение с двух сделок на `k`.
