## Задача простыми словами

Робот стоит в левом верхнем углу сетки `m × n` и хочет попасть в правый нижний угол, двигаясь **только вправо или вниз**. Некоторые клетки заняты препятствиями (`1`), через них ходить нельзя. Нужно вернуть **число различных путей**.

Пример:

```
0 0 0
0 1 0
0 0 0
```

Препятствие в центре оставляет два пути: «вправо, вправо, вниз, вниз» и «вниз, вниз, вправо, вправо». Ответ `2`.

## Наивный подход

Перебрать все пути рекурсией и посчитать дошедшие до финиша:

```ts naive
function count(i: number, j: number): number {
  if (i >= m || j >= n || grid[i][j] === 1) return 0;
  if (i === m - 1 && j === n - 1) return 1;
  return count(i + 1, j) + count(i, j + 1);
}
```

Число путей может достигать `2 · 10⁹`, а рекурсия проходит каждый из них по отдельности — экспоненциальное время. Лишняя работа: «сколько путей от клетки `(i, j)` до финиша» не зависит от того, как робот в неё попал, но пересчитывается при каждом приходе.

## Ключевое наблюдение

В свободную клетку `(i, j)` можно прийти **только сверху или слева**. Пути через верхнего соседа и пути через левого соседа различаются последним шагом, поэтому их количества просто **складываются**:

```
dp[i][j] = 0                          если (i, j) — препятствие
dp[i][j] = dp[i-1][j] + dp[i][j-1]    иначе
```

Препятствие «обнуляет» клетку, и через неё ничего не «протекает» дальше. Строка зависит только от предыдущей строки и от самой себя — хватит одного массива длины `n`.

## Техники

### ДП на сетке: подсчёт путей

**Что это.** Двумерное ДП, где `dp[i][j]` — количество способов добраться до клетки. Переход — **сумма** по всем клеткам, из которых можно сделать ход сюда (в задачах на оптимум была бы сумма → минимум/максимум).

- **Состояние**: `dp[i][j]` — число путей от старта до `(i, j)`.
- **База**: в старт ведёт один путь (пустой), если старт свободен.
- **Переход**: сверху + слева; препятствие → `0`.
- **Порядок**: строки сверху вниз, внутри строки слева направо.
- **Ответ**: `dp[m-1][n-1]`.

Это правило суммы из комбинаторики: множества путей через разных соседей не пересекаются. Подробнее о многомерном ДП — во вкладке «Теория».

### Одна строка и «прибавить на месте»

Храним массив `dp` длины `n`. До обновления `dp[j]` — число путей до клетки **сверху** (прошлая строка), а `dp[j − 1]` уже пересчитан для текущей строки — это **слева**. Поэтому переход `dp[i][j] = dp[i-1][j] + dp[i][j-1]` превращается в короткое `dp[j] += dp[j - 1]`.

### Фиктивный вход в стартовую клетку

Вместо отдельной ветки «если это старт» перед первой строкой кладём `dp[0] = 1` — как будто в старт ведёт один путь «сверху». Если старт свободен, это значение сохранится; если там препятствие, оно сразу обнулится — и ответ корректно станет `0`.

## Разбор кода

```ts
function uniquePathsWithObstacles(obstacleGrid: number[][]): number {
  const m = obstacleGrid.length;
  const n = obstacleGrid[0].length;
  // dp[j] — число путей до клетки (i, j) текущей строки.
  // Перед обновлением dp[j] хранит число путей до клетки сверху.
  const dp: number[] = new Array(n).fill(0);
  // Фиктивный «вход» в стартовую клетку: если она свободна, путей туда 1
  dp[0] = 1;
```

Массив на одну строку, заполненный нулями: строки «над сеткой» не существует, путей оттуда нет. Единственное исключение — `dp[0] = 1`, фиктивный вход в старт.

```ts
  for (let i = 0; i < m; i++) {
    for (let j = 0; j < n; j++) {
      if (obstacleGrid[i][j] === 1) {
        // Через препятствие пройти нельзя — путей ноль
        dp[j] = 0;
```

Обход в порядке зависимостей. Препятствие: путей до этой клетки ноль, и это значение «перекроет» поток как вниз (следующая строка прочитает `0` сверху), так и вправо (следующая клетка прочитает `0` слева).

```ts
      } else if (j > 0) {
        // Пути сверху (старое dp[j]) + пути слева (новое dp[j - 1])
        dp[j] += dp[j - 1];
      }
      // При j === 0 приходим только сверху: dp[0] остаётся как есть
    }
  }
```

Свободная клетка не в первом столбце: к путям сверху (то, что лежит в `dp[j]`) прибавляем пути слева (`dp[j − 1]`). В первом столбце соседа слева нет, поэтому `dp[0]` не меняется — путей столько же, сколько до клетки сверху. Для самой первой клетки это и есть фиктивная единица.

```ts
  return dp[n - 1];
}
```

После последней строки `dp[n − 1]` — число путей до правого нижнего угла (или `0`, если он — препятствие).

## Трассировка

`obstacleGrid = [[0, 0, 0], [0, 1, 0], [0, 0, 0]]`, старт: `dp = [1, 0, 0]`.

```
i=0:
  j=0: свободна, j=0 → без изменений    dp=[1, 0, 0]
  j=1: dp[1] += dp[0] → 0 + 1 = 1       dp=[1, 1, 0]
  j=2: dp[2] += dp[1] → 0 + 1 = 1       dp=[1, 1, 1]
i=1:
  j=0: без изменений                    dp=[1, 1, 1]
  j=1: препятствие → 0                  dp=[1, 0, 1]
  j=2: dp[2] += dp[1] → 1 + 0 = 1       dp=[1, 0, 1]
i=2:
  j=0: без изменений                    dp=[1, 0, 1]
  j=1: dp[1] += dp[0] → 0 + 1 = 1       dp=[1, 1, 1]
  j=2: dp[2] += dp[1] → 1 + 1 = 2       dp=[1, 1, 2]
```

Ответ `2`. На строке `i = 1` видно, как препятствие «отрезает» центр: в `(1, 2)` пришёл только путь сверху.

Препятствие в старте, `[[1]]`: `dp = [1]`, при `i = 0, j = 0` клетка — препятствие, `dp[0] = 0`. Ответ `0`.

Пример `[[0, 1], [0, 0]]`: после первой строки `dp = [1, 0]` (правая клетка — препятствие), после второй `dp = [1, 0 + 1] = [1, 1]`. Ответ `1`.

## Почему это работает

Каждый путь до свободной клетки `(i, j)` (кроме самого старта) делает последний шаг либо сверху, либо слева; эти множества путей не пересекаются, и любой путь до соседа, продолженный одним шагом, — путь до `(i, j)`. Значит, число путей — сумма чисел путей до соседей. По порядку обхода оба соседа уже посчитаны: верхний остался в `dp[j]` с прошлой строки, левый только что записан в `dp[j − 1]`. В препятствие путей нет — `0`. Фиктивная единица задаёт базу «в старт ведёт ровно один путь».

## Пограничные случаи

- **Препятствие в старте**: `dp[0]` обнуляется на первой же клетке, дальше всё нули — ответ `0`.
- **Препятствие в финише**: последняя клетка получает `0`.
- **Сетка `1 × 1`**: `1`, если клетка свободна, иначе `0`.
- **Препятствие в первой строке**: все клетки правее получают `0` — до них можно дойти только по первой строке.
- **Препятствие в первом столбце**: `dp[0]` обнуляется и остаётся `0` для всех строк ниже.
- **Большие ответы**: по условию не больше `2 · 10⁹`, это точно представимо в `number`.

## Сложность

- **Время `O(m · n)`**: каждая клетка — одна проверка и одно сложение.
- **Память `O(n)`**: одна строка `dp`.

## Типичные ошибки

1. **Инициализировать первую строку и столбец единицами**, как в Unique Paths без препятствий, — забывают, что после препятствия на краю путей уже `0`.
2. **Не проверить старт**: жёстко поставить `dp[0][0] = 1`, даже если там препятствие.
3. **Обновлять `dp[0]` при `j === 0` как `dp[0] += dp[-1]`** — `undefined` и `NaN`.
4. **Сравнивать ячейку с `'1'`** (строкой) — во входе числа, препятствие не распознается.
5. **Рекурсия без мемоизации** — экспоненциальное время.

## Как узнать такую задачу

- Вопрос «**сколько способов**» дойти до цели по сетке с ограниченным набором ходов (вправо/вниз) и, возможно, запрещёнными клетками.
- Способы различаются последним шагом → сумма по входам, ДП на сетке.
- Без препятствий у задачи есть формула `C(m + n − 2, m − 1)`; препятствия её ломают, и остаётся ДП.

Родственные задачи: Unique Paths, Minimum Path Sum, Unique Paths III (обход всех клеток — backtracking), Knight Probability in Chessboard, Out of Boundary Paths.
