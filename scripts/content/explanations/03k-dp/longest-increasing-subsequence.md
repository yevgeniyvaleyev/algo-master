## Задача простыми словами

Дан массив `nums`. Нужно найти длину самой длинной **строго возрастающей подпоследовательности** — набора элементов, взятых в исходном порядке (не обязательно подряд), где каждый следующий больше предыдущего.

Пример: `nums = [10, 9, 2, 5, 3, 7, 101, 18]`. Подходит `[2, 3, 7, 101]` (или `[2, 5, 7, 18]`) — длина `4`. Для `[7, 7, 7]` ответ `1`: равные элементы «строго возрастающими» не считаются.

## Наивный подход

Перебрать все подпоследовательности: каждый элемент либо берём, либо нет — это `2ⁿ` вариантов, и для каждого проверяем возрастание.

```ts naive
function best(i: number, prev: number): number {
  if (i === nums.length) return 0;
  // Пропускаем nums[i]
  let res = best(i + 1, prev);
  // Берём nums[i], если он больше предыдущего взятого
  if (nums[i] > prev) res = Math.max(res, 1 + best(i + 1, nums[i]));
  return res;
}
best(0, -Infinity);
```

При `n = 2500` это немыслимо. Где лишняя работа? Рекурсия много раз решает одну и ту же подзадачу: «какая самая длинная цепочка заканчивается на этом элементе?». Ответ на этот вопрос не зависит от того, как мы к элементу пришли, — значит, его можно посчитать **один раз** и запомнить.

## Ключевое наблюдение

Возрастающую подпоследовательность удобно описывать **её последним элементом**. Если известна длина лучшей цепочки, кончающейся на `nums[j]`, и `nums[j] < nums[i]`, то к ней можно дописать `nums[i]` и получить цепочку на единицу длиннее, кончающуюся на `nums[i]`.

Любая возрастающая подпоследовательность, кончающаяся на `nums[i]`, — это либо один элемент `nums[i]`, либо какая-то цепочка, кончающаяся на меньшем `nums[j]` левее, плюс `nums[i]`. Поэтому достаточно перебрать все `j < i` — и задача сводится к одномерной таблице.

## Техники

### Динамическое программирование «заканчивается на i»

**Что это.** ДП хранит ответы на подзадачи и строит из них ответ на большую задачу. Для подпоследовательностей классическая форма состояния — «лучший ответ, который **заканчивается ровно** в позиции `i`». Так переход знает последний элемент цепочки и может проверить, можно ли её продолжить.

**Пять вопросов:**

1. **Состояние**: `dp[i]` — длина самой длинной возрастающей подпоследовательности, кончающейся на `nums[i]`.
2. **База**: `dp[i] = 1` для всех `i` — элемент сам по себе цепочка длины 1.
3. **Переход**: `dp[i] = max(dp[i], dp[j] + 1)` для всех `j < i`, где `nums[j] < nums[i]`.
4. **Порядок**: `i` слева направо — к расчёту `dp[i]` все `dp[j]` с `j < i` готовы.
5. **Ответ**: `max(dp)` — лучшая цепочка может кончаться где угодно.

Таблица для `[10, 9, 2, 5, 3, 7, 101, 18]`:

```
i:      0   1   2   3   4   5   6    7
nums:  10   9   2   5   3   7  101  18
dp:     1   1   1   2   2   3   4    4
```

Подробнее о ДП — во вкладке «Теория».

### Почему ответ — максимум, а не последняя ячейка

В отличие от ДП по префиксам (где `dp[n]` — ответ для всей строки), здесь `dp[i]` описывает цепочки, которые **обязаны** кончаться на `nums[i]`. Самая длинная цепочка может кончаться не на последнем элементе: в `[1, 2, 0]` `dp = [1, 2, 1]`, ответ `2`, а не `dp[2] = 1`.

## Разбор кода

```ts
function lengthOfLIS(nums: number[]): number {
  const n = nums.length;
  // Состояние: dp[i] — длина самой длинной возрастающей подпоследовательности,
  // которая заканчивается ровно на nums[i].
  // База: каждый элемент сам по себе — подпоследовательность длины 1
  const dp: number[] = new Array(n).fill(1);
```

Таблица сразу заполняется базой: единицами. Это одновременно и «нет подходящего предшественника» — если ни одно `nums[j]` не меньше `nums[i]`, `dp[i]` так и останется `1`.

```ts
  // Порядок: i слева направо — все dp[j] для j < i уже готовы
  for (let i = 1; i < n; i++) {
    // Перебираем предыдущий элемент подпоследовательности
    for (let j = 0; j < i; j++) {
```

Внешний цикл выбирает элемент `nums[i]`, которым кончается цепочка. Начинаем с `i = 1`: для `i = 0` предшественников нет, и база `dp[0] = 1` уже верна. Внутренний цикл перебирает кандидатов на роль предпоследнего элемента — все позиции левее.

```ts
      // Переход: nums[i] можно приписать к подпоследовательности, кончающейся на nums[j]
      if (nums[j] < nums[i]) {
        dp[i] = Math.max(dp[i], dp[j] + 1);
      }
    }
  }
```

Сердце перехода. Строгое `<` — это и есть «строго возрастающая»: равный элемент не продолжает цепочку. Из всех подходящих `j` выбираем ту цепочку, что длиннее, — `Math.max` накапливает лучший вариант.

```ts
  // Ответ: подпоследовательность может кончаться где угодно — берём максимум
  return Math.max(...dp);
}
```

Ответ — максимум по таблице. При `n ≤ 2500` spread-оператор безопасен (лимит аргументов функции гораздо больше).

## Трассировка

`nums = [10, 9, 2, 5, 3, 7, 101, 18]`, сначала `dp = [1, 1, 1, 1, 1, 1, 1, 1]`.

1. `i = 1` (`9`): `10 < 9`? нет. `dp[1] = 1`.
2. `i = 2` (`2`): `10`, `9` не меньше `2`. `dp[2] = 1`.
3. `i = 3` (`5`): подходит только `j = 2` (`2 < 5`) → `dp[3] = dp[2] + 1 = 2`.
4. `i = 4` (`3`): подходит `j = 2` (`2 < 3`) → `dp[4] = 2`.
5. `i = 5` (`7`): `j = 2` → 2; `j = 3` (`5 < 7`) → `dp[3] + 1 = 3`; `j = 4` (`3 < 7`) → 3. `dp[5] = 3`.
6. `i = 6` (`101`): все левее меньше; лучший — `j = 5` → `dp[6] = 4`.
7. `i = 7` (`18`): `101` не подходит, лучший — `j = 5` (`7 < 18`) → `dp[7] = 4`.

Итог `dp = [1, 1, 1, 2, 2, 3, 4, 4]`, ответ `max = 4`.

Для `[7, 7, 7]`: условие `7 < 7` никогда не выполняется, `dp = [1, 1, 1]`, ответ `1`.

## Почему это работает

Индукция по `i`. Пусть все `dp[j]` для `j < i` верны. Любая возрастающая подпоследовательность, кончающаяся на `nums[i]`, либо состоит из одного `nums[i]` (длина 1 — база), либо имеет предпоследний элемент `nums[j]` с `j < i` и `nums[j] < nums[i]`. Без последнего элемента это цепочка, кончающаяся на `nums[j]`, её длина не больше `dp[j]`. Значит, длина всей цепочки не больше `dp[j] + 1`, и внутренний цикл рассмотрит этот `j`. Наоборот, каждое значение `dp[j] + 1` достижимо: берём лучшую цепочку для `j` и дописываем `nums[i]`. Ответ задачи — лучшая цепочка с любым концом, то есть `max(dp)`.

## Пограничные случаи

- **Один элемент**: `dp = [1]`, ответ `1` (внешний цикл не выполняется ни разу).
- **Строго убывающий массив**: ни один переход не срабатывает, ответ `1`.
- **Строго возрастающий массив**: `dp = [1, 2, …, n]`, ответ `n`.
- **Одинаковые элементы**: строгое `<` не даёт им продолжать друг друга.
- **Отрицательные числа**: сравнения работают для любых знаков.

## Сложность

- **Время `O(n²)`**: два вложенных цикла, около `n² / 2` сравнений. При `n ≤ 2500` — примерно 3 миллиона шагов, это быстро.
- **Память `O(n)`**: массив `dp`.

**Follow-up на собеседовании: `O(n log n)`.** Вместо `dp[i]` для каждой позиции храним массив «хвостов»: `tails[k]` — наименьший последний элемент среди возрастающих подпоследовательностей длины `k + 1`. Он строго возрастает, поэтому место для очередного `x` ищется бинарным поиском (первый хвост `>= x`): если такого нет — `push`, иначе замена.

```ts naive
const tails: number[] = [];
for (const x of nums) {
  let lo = 0, hi = tails.length;
  while (lo < hi) {
    const mid = (lo + hi) >> 1;
    if (tails[mid] < x) lo = mid + 1;
    else hi = mid;
  }
  if (lo === tails.length) tails.push(x);
  else tails[lo] = x;
}
return tails.length;
```

Важно: `tails` — не сама подпоследовательность, верна только его длина.

## Типичные ошибки

1. **Вернуть `dp[n - 1]`** вместо максимума по всем `dp[i]` — лучшая подпоследовательность не обязана заканчиваться последним элементом.
2. **`<=` вместо `<`** — равные элементы начнут продолжать друг друга: `[7, 7, 7]` даст `3`.
3. **Забыть базу**: заполнить `dp` нулями — тогда все длины занижены на 1.
4. **Путать подпоследовательность с подмассивом** — элементы не обязаны идти подряд; сравнивать только с соседом `nums[i - 1]` неверно.
5. **Состояние «лучшая цепочка среди первых `i` элементов»** без привязки к концу — тогда непонятно, можно ли продолжить её числом `nums[i]`.

## Как узнать такую задачу

- Нужна самая длинная **цепочка** элементов в исходном порядке с условием между соседями цепочки (возрастание, делимость, «помещается внутрь»).
- Состояние «ответ, заканчивающийся на `i`» + перебор предыдущего `j < i` — универсальный шаблон за `O(n²)`.
- Ограничение `n` до `10⁵` или явный follow-up про `O(n log n)` — сигнал к методу хвостов.

Родственные задачи: Number of Longest Increasing Subsequence, Largest Divisible Subset, Russian Doll Envelopes, Increasing Triplet Subsequence, Longest Common Subsequence.
