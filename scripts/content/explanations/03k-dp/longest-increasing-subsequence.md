## Задача простыми словами

Дан массив `nums`. Нужно найти длину самой длинной **строго возрастающей подпоследовательности** — набора элементов, взятых в исходном порядке (не обязательно подряд), где каждый следующий больше предыдущего.

Пример: `nums = [10, 9, 2, 5, 3, 7, 101, 18]`. Подходит `[2, 3, 7, 101]` (или `[2, 5, 7, 18]`) — длина `4`. Для `[7, 7, 7]` ответ `1`: равные элементы «строго возрастающими» не считаются.

## Наивный подход

Перебор всех `2ⁿ` подпоследовательностей отпадает сразу. Классическое ДП за `O(n²)`: `dp[i]` — длина самой длинной возрастающей подпоследовательности, **заканчивающейся** на `nums[i]`.

```ts naive
const dp = new Array(n).fill(1);
for (let i = 0; i < n; i++) {
  for (let j = 0; j < i; j++) {
    if (nums[j] < nums[i]) dp[i] = Math.max(dp[i], dp[j] + 1);
  }
}
return Math.max(...dp);
```

Это верно и при `n ≤ 2500` даже проходит, но задача просит `O(n log n)`. Где лишняя работа? Для каждого `i` мы перебираем **все** предыдущие элементы, хотя среди подпоследовательностей одной длины нас интересует только одна — та, что заканчивается **наименьшим** числом: её проще всего продолжить. Остальные — балласт.

## Ключевое наблюдение

Для каждой длины `k + 1` достаточно помнить **наименьший возможный последний элемент** — «хвост» `tails[k]`. Если две подпоследовательности длины 3 заканчиваются на `7` и на `5`, то всё, что продолжает первую, продолжает и вторую — хранить `7` незачем.

Эти хвосты **строго возрастают** по длине: самая маленькая концовка длины 3 больше самой маленькой концовки длины 2 (ведь перед концом длины 3 стоит элемент, который сам завершает подпоследовательность длины 2). А в отсортированном массиве место для нового числа ищется **бинарным поиском** за `O(log n)`.

## Техники

### ДП с «жадным» состоянием (метод хвостов, patience sorting)

**Что это.** Иногда состояние ДП можно сжать: вместо «ответ для каждой позиции» хранить «лучший представитель для каждого значения ответа». Здесь вместо `dp[i]` для каждого `i` храним по одному лучшему хвосту для каждой длины. Таблица становится отсортированной, и переход сводится к поиску в ней.

**Как применяется здесь.** Новый элемент `x` либо удлиняет самую длинную подпоследовательность (если он больше всех хвостов), либо улучшает (уменьшает) хвост какой-то длины. Подробнее о ДП — во вкладке «Теория».

### Бинарный поиск «первый элемент `>= x`» (lower bound)

**Шаблон** на полуинтервале `[lo, hi)`:

```ts naive
let lo = 0, hi = arr.length;
while (lo < hi) {
  const mid = (lo + hi) >> 1;
  if (arr[mid] < x) lo = mid + 1;
  else hi = mid;
}
// lo — первая позиция с arr[lo] >= x (или arr.length)
```

Условие `arr[mid] < x` монотонно: истинно на префиксе отсортированного массива и ложно дальше. Поиск сходится к границе. Если такой позиции нет, `lo` равно длине массива.

## Разбор кода

```ts
function lengthOfLIS(nums: number[]): number {
  // tails[k] — наименьший возможный последний элемент
  // среди всех возрастающих подпоследовательностей длины k + 1.
  // Массив tails всегда строго возрастает.
  const tails: number[] = [];
```

`tails` начинается пустым: пока не просмотрено ни одного элемента, нет ни одной подпоследовательности. Длина `tails` в любой момент — длина лучшей найденной подпоследовательности.

```ts
  for (const x of nums) {
    // Бинарный поиск: первая позиция, где tails[pos] >= x
    let lo = 0;
    let hi = tails.length;
    while (lo < hi) {
      const mid = (lo + hi) >> 1;
      if (tails[mid] < x) lo = mid + 1;
      else hi = mid;
    }
```

Для каждого числа ищем позицию `lo` — первый хвост, который **не меньше** `x`. Все хвосты левее `lo` строго меньше `x`, то есть `x` может продолжить любую из этих подпоследовательностей; лучше всего — самую длинную из них, длины `lo`. Тогда получится подпоследовательность длины `lo + 1`, заканчивающаяся на `x`.

Именно `<` (а не `<=`) в условии делает подпоследовательность **строго** возрастающей: равный элемент найдёт позицию своего двойника и заменит его, а не встанет после.

```ts
    if (lo === tails.length) {
      // x больше всех хвостов — удлиняем самую длинную подпоследовательность
      tails.push(x);
    } else {
      // Заменяем хвост: подпоследовательность длины lo + 1 теперь
      // заканчивается меньшим числом, и её легче продолжить
      tails[lo] = x;
    }
  }
```

Две ветки. Если `x` больше всех хвостов, появилась подпоследовательность новой, рекордной длины — дописываем хвост. Иначе `x <= tails[lo]`, и подпоследовательность длины `lo + 1` теперь можно закончить числом `x` — не большим, чем прежний хвост. Замена сохраняет сортировку: `tails[lo - 1] < x <= tails[lo] < tails[lo + 1]`.

```ts
  // Число хвостов — длина самой длинной возрастающей подпоследовательности
  return tails.length;
}
```

Ответ — количество длин, для которых нашёлся хвост.

## Трассировка

`nums = [10, 9, 2, 5, 3, 7, 101, 18]`:

```
x=10   tails=[]            lo=0 = длина → push      tails=[10]
x=9    tails[0]=10 >= 9    lo=0 → замена            tails=[9]
x=2    tails[0]=9 >= 2     lo=0 → замена            tails=[2]
x=5    tails[0]=2 < 5      lo=1 = длина → push      tails=[2,5]
x=3    mid=1: 5>=3 hi=1; mid=0: 2<3 lo=1 → замена   tails=[2,3]
x=7    mid=1: 3<7 lo=2 = длина → push               tails=[2,3,7]
x=101  больше всех → push                           tails=[2,3,7,101]
x=18   mid=2: 7<18 lo=3; mid=3: 101>=18 hi=3        tails=[2,3,7,18]
```

Ответ `4`. На шаге `x = 3` хвост длины 2 улучшился с `5` до `3`; на шаге `x = 18` хвост длины 4 улучшился с `101` до `18` — теперь любое число больше `18` удлинило бы ответ до 5.

**Важно:** `tails` — не сама подпоследовательность. Для `[3, 4, 1]` получим `tails = [1, 4]`, а `[1, 4]` в исходном порядке не встречается. Верна только длина.

Для `[7, 7, 7]`: каждая следующая `7` находит `lo = 0` (`tails[0] = 7 >= 7`) и заменяет саму себя. Ответ `1`.

## Почему это работает

**Инвариант:** после обработки префикса `tails[k]` — минимальный последний элемент среди возрастающих подпоследовательностей длины `k + 1` в этом префиксе, и `tails` строго возрастает.

Пусть приходит `x`, и `lo` — первая позиция с `tails[lo] >= x`.

- Для длины `lo + 1`: подпоследовательность длины `lo` с хвостом `tails[lo - 1] < x` продолжается числом `x`, давая хвост `x <= tails[lo]`. Значит, новый минимум — `x`.
- Для больших длин `x` бесполезен: чтобы закончить подпоследовательность длины `l + 1 > lo + 1` числом `x`, нужна подпоследовательность длины `l` с хвостом меньше `x`, а все `tails[l - 1] >= tails[lo] >= x`.
- Для меньших длин `x` не улучшает хвост: там `tails[k] < x`.

Итак, меняется ровно одна ячейка, инвариант сохраняется. Длина `tails` в конце — максимальная длина, для которой подпоследовательность существует.

## Пограничные случаи

- **Один элемент**: `tails = [x]`, ответ `1`.
- **Строго убывающий массив**: каждый элемент заменяет `tails[0]`, ответ `1`.
- **Строго возрастающий массив**: каждый элемент делает `push`, ответ `n`.
- **Одинаковые элементы**: заменяют друг друга благодаря поиску `>= x`.
- **Отрицательные числа**: сравнения работают для любых знаков.

## Сложность

- **Время `O(n log n)`**: для каждого из `n` элементов — бинарный поиск по массиву длины не больше `n`, плюс `O(1)` на запись.
- **Память `O(n)`**: массив `tails` в худшем случае (возрастающий вход) содержит все элементы.

## Типичные ошибки

1. **Поиск первого `> x`** (upper bound) вместо `>= x` — равные элементы начнут удлинять ответ, получится нестрого возрастающая подпоследовательность: `[7, 7, 7]` даст `3`.
2. **Считать `tails` ответом-подпоследовательностью** — он хранит лучшие хвосты разных длин, перемешанные во времени. Для восстановления самой подпоследовательности нужны индексы и ссылки на предшественника.
3. **В `O(n²)`-версии вернуть `dp[n - 1]`** вместо максимума по всем `dp[i]` — лучшая подпоследовательность не обязана заканчиваться последним элементом.
4. **`hi = tails.length - 1`** в этом шаблоне — тогда позиция «после всех» (сигнал для `push`) недостижима.
5. **Путать подпоследовательность с подмассивом** — элементы не обязаны идти подряд.

## Как узнать такую задачу

- Нужна самая длинная **цепочка** элементов в исходном порядке с монотонным условием (возрастание, вложенность, «помещается внутрь»).
- Ограничение `n` до `10⁵` или явный follow-up про `O(n log n)` — сигнал к методу хвостов с бинарным поиском.
- Задачи «сортируем по одному измерению, по второму ищем LIS»: Russian Doll Envelopes, Maximum Length of Pair Chain.

Родственные задачи: Number of Longest Increasing Subsequence, Increasing Triplet Subsequence (частный случай с двумя хвостами), Longest Common Subsequence.
