## Задача простыми словами

Даны строка `s` и словарь `wordDict`. Нужно ответить: можно ли разрезать `s` на кусочки так, чтобы **каждый кусочек был словом из словаря**? Слова можно использовать сколько угодно раз.

Пример: `s = "leetcode"`, `wordDict = ["leet", "code"]` → `true` (`"leet" + "code"`). А `s = "catsandog"` со словарём `["cats", "dog", "sand", "and", "cat"]` → `false`: после `"cat sand"` или `"cats and"` остаётся `"og"`, которого в словаре нет.

## Наивный подход

Перебор всех разрезов: пробуем каждое слово-префикс и рекурсивно проверяем остаток.

```ts naive
function can(start: number): boolean {
  if (start === s.length) return true;
  for (let end = start + 1; end <= s.length; end++) {
    if (words.has(s.slice(start, end)) && can(end)) return true;
  }
  return false;
}
```

Верно, но в худшем случае экспоненциально: для `s = "aaaa…ab"` и словаря `["a", "aa", "aaa"]` число способов разрезать префикс из `a` растёт как у чисел Фибоначчи/трибоначчи, и все они упираются в `"b"`. Лишняя работа — в том, что `can(start)` для одной и той же позиции вызывается заново из каждого способа до неё добраться. А ответ для позиции **не зависит от того, как мы туда пришли**.

## Ключевое наблюдение

Важно только одно: **можно ли разбить префикс `s[0..i)`** — да или нет. Префиксов всего `n + 1`. Префикс `s[0..i)` разбивается, если у него есть «последнее слово» `s[j..i)` из словаря, а всё, что перед ним, `s[0..j)`, тоже разбивается.

Кроме того, последнее слово не длиннее самого длинного слова словаря `maxLen`, поэтому начало `j` достаточно искать только среди последних `maxLen` позиций.

## Техники

### Динамическое программирование по префиксам

**Что это.** ДП хранит ответ для каждой подзадачи и строит большие ответы из меньших. Для строк самая частая форма — **ДП по префиксам**: `dp[i]` описывает первые `i` символов.

**Четыре вопроса:**

1. **Состояние**: `dp[i]` — можно ли разбить `s[0..i)` на слова.
2. **База**: `dp[0] = true` — пустая строка разбивается на ноль слов.
3. **Переход**: `dp[i] = true`, если есть `j < i` с `dp[j] === true` и `s.slice(j, i)` в словаре.
4. **Ответ**: `dp[n]`; считаем `i` по возрастанию, чтобы все `dp[j]` для `j < i` были готовы.

По структуре это родственник неограниченного рюкзака (как Coin Change): «ёмкость» — длина префикса, «предметы» — слова, каждое можно брать многократно. Подробнее о ДП — во вкладке «Теория».

### Множество (`Set`) для быстрой проверки слова

Проверка «есть ли строка в словаре» через массив стоила бы `O(|wordDict| · L)`. `Set` хеширует строку и отвечает за `O(L)` — время вычисления хеша куска длины до `L`.

### Ограничение перебора длиной самого длинного слова

Слово длиннее `maxLen` в словаре заведомо отсутствует, поэтому смотреть на `j < i - maxLen` бессмысленно. Это превращает внутренний цикл из `O(n)` в `O(L)`, где `L ≤ 20` по условию.

## Разбор кода

```ts
function wordBreak(s: string, wordDict: string[]): boolean {
  const n = s.length;
  // Множество для проверки слова за O(1)
  const words = new Set(wordDict);
  // Длина самого длинного слова: дальше назад смотреть бессмысленно
  let maxLen = 0;
  for (const w of wordDict) maxLen = Math.max(maxLen, w.length);
```

Подготовка. `words` — словарь в виде `Set` для быстрых проверок (комментарий говорит «за O(1)» — точнее, за время, пропорциональное длине куска). `maxLen` — длина самого длинного слова: она задаёт, насколько далеко назад имеет смысл искать начало последнего слова.

```ts
  // dp[i] — можно ли разбить префикс s[0..i) на слова словаря
  const dp: boolean[] = new Array(n + 1).fill(false);
  // Пустой префикс разбивается всегда (ноль слов)
  dp[0] = true;
```

Таблица на `n + 1` префиксов (от пустого до всей строки). По умолчанию «нельзя», база `dp[0] = true` — от неё «прорастают» все остальные `true`.

```ts
  for (let i = 1; i <= n; i++) {
    // Перебираем начало j последнего слова s[j..i)
    for (let j = i - 1; j >= Math.max(0, i - maxLen); j--) {
```

Внешний цикл — конец префикса `i`. Внутренний перебирает начало `j` последнего слова: от самого короткого кандидата (`s[i-1..i)`, один символ) до самого длинного допустимого (длины `maxLen`). `Math.max(0, …)` не даёт уйти в отрицательные индексы в начале строки.

```ts
      // Префикс до j разбивается, а s[j..i) — слово из словаря
      if (dp[j] && words.has(s.slice(j, i))) {
        dp[i] = true;
        break; // одного способа достаточно
      }
    }
  }
```

Сердце перехода. Порядок условий в `&&` выбран не случайно: дешёвая проверка `dp[j]` идёт первой, и дорогой `s.slice` + хеширование выполняются только для «достижимых» `j`. Если нашли хоть одно подходящее `j`, префикс разбивается — дальше искать незачем, `break`.

```ts
  return dp[n];
}
```

Ответ — можно ли разбить всю строку.

## Трассировка

`s = "leetcode"`, `wordDict = ["leet", "code"]`, `maxLen = 4`, `dp[0] = true`.

1. `i = 1`: `j = 0` — `dp[0]` true, но `"l"` не слово. `dp[1] = false`.
2. `i = 2`: `j = 1` — `dp[1]` false; `j = 0` — `"le"` не слово. `dp[2] = false`.
3. `i = 3`: `j = 2, 1` — false; `j = 0` — `"lee"` не слово. `dp[3] = false`.
4. `i = 4`: `j = 3, 2, 1` — false; `j = 0` — `"leet"` есть! `dp[4] = true`.
5. `i = 5`: `j` от `4` до `1`. `j = 4` — `dp[4]` true, `"c"` не слово; остальные `dp[j]` false. `dp[5] = false`.
6. `i = 6`: `j = 4` — `"co"` не слово. `dp[6] = false`.
7. `i = 7`: `j = 4` — `"cod"` не слово. `dp[7] = false`.
8. `i = 8`: `j` от `7` до `4`. `j = 7, 6, 5` — false; `j = 4` — `dp[4]` true и `"code"` есть. `dp[8] = true`.

Ответ `true`. Заметьте: при `i = 8` значение `j` не опускается ниже `4` — это и есть отсечение по `maxLen`.

Для `"catsandog"`: `dp[3] = true` (`"cat"`), `dp[4] = true` (`"cats"`), `dp[7] = true` (`"sand"` от `3` или `"and"` от `4`). Но `dp[9]` требует слова `s[j..9)` с `dp[j] = true` при `j ∈ [5, 8]`: `dp[7]` даёт `"og"` — не слово, а `dp[5]`, `dp[6]`, `dp[8]` равны false. Ответ `false`.

## Почему это работает

Индукция по `i`. Если `dp[i] = true`, то есть `j` с разбиваемым `s[0..j)` и словом `s[j..i)` — склеив разбиение и слово, получаем разбиение `s[0..i)`. Обратно: если `s[0..i)` разбивается, у разбиения есть последнее слово `s[j..i)`; его длина не больше `maxLen`, значит `j` попадает в диапазон перебора, а `s[0..j)` разбивается (это остальная часть разбиения), и по предположению индукции `dp[j] = true`. Цикл найдёт такое `j`.

## Пограничные случаи

- **Вся строка — одно слово**: `dp[n]` станет true при `j = 0` (если `n ≤ maxLen`).
- **Слова-префиксы друг друга** (`"cat"` и `"cats"`): ДП рассматривает оба варианта, жадный выбор не нужен.
- **Строка длиннее любой комбинации**: последние `dp` остаются false.
- **Одна буква не встречается ни в одном слове**: никакой префикс, включающий её, не разбивается — ответ `false`.
- **Повтор слова** (`"applepenapple"`): ничто не запрещает использовать `"apple"` дважды.

## Сложность

- **Время `O(n · L²)`**: для каждого из `n` концов перебираем до `L` начал, а `s.slice` и хеширование куска стоят `O(L)`. Без отсечения по `maxLen` было бы `O(n² · L)`, а в наивной рекурсии — экспонента. Плюс `O(суммарной длины словаря)` на построение `Set`.
- **Память `O(n + размер словаря)`**: таблица `dp` и `Set` со словами.

## Типичные ошибки

1. **Жадный выбор** самого длинного (или самого короткого) слова-префикса: на `"catsandog"`/`"cats and dog"` выбор между `"cat"` и `"cats"` решает всё.
2. **Забыть `dp[0] = true`** — ни одно `dp[i]` не станет true.
3. **Таблица длины `n`** вместо `n + 1` и путаница «`dp[i]` про символ `i`» против «про префикс длины `i`» — ошибки на единицу.
4. **Рекурсия без мемоизации** — TLE на строках вида `"aaaa…ab"`.
5. **Проверять слово через `wordDict.includes`** — лишний множитель размера словаря.

## Как узнать такую задачу

- Строку нужно **разрезать на части**, каждая из которых удовлетворяет условию (слово словаря, палиндром, число в диапазоне), и спрашивается «можно ли», «сколько способов» или «минимум частей».
- Ответ для префикса определяется последним куском и ответом для меньшего префикса → ДП по префиксам.
