## Задача простыми словами

Дан числовой треугольник: в строке `i` ровно `i + 1` чисел. Начинаем на вершине и на каждом шаге спускаемся на строку ниже — в клетку **с тем же индексом** `j` или **со следующим** `j + 1`. Нужно найти минимальную сумму чисел на пути до нижней строки.

Пример:

```
     2
    3 4
   6 5 7
  4 1 8 3
```

Лучший путь `2 → 3 → 5 → 1`, сумма `11`.

## Наивный подход

Перебрать все пути: на каждой строке два варианта, значит, путей `2ⁿ⁻¹`.

```ts naive
function best(i: number, j: number): number {
  if (i === triangle.length - 1) return triangle[i][j];
  return triangle[i][j] + Math.min(best(i + 1, j), best(i + 1, j + 1));
}
return best(0, 0);
```

При `n = 200` это `2¹⁹⁹` вызовов — безнадёжно. Лишняя работа: клетку `(2, 1)` можно достичь и из `(1, 0)`, и из `(1, 1)`, и рекурсия **дважды** считает лучший путь от неё вниз; на нижних строках повторов становится экспоненциально много. А лучший путь **от клетки вниз** вообще не зависит от того, как мы в эту клетку пришли.

Жадность («иди в меньшего соседа») тоже неверна: маленькое число сверху может вести в ветку с огромными числами внизу.

## Ключевое наблюдение

Определим `dp[i][j]` — минимальную сумму пути **от клетки `(i, j)` вниз до последней строки**. Для нижней строки это само число. Для остальных:

```
dp[i][j] = triangle[i][j] + min(dp[i+1][j], dp[i+1][j+1])
```

Считаем **снизу вверх** — и ответ окажется ровно в вершине `dp[0][0]`, без поиска минимума по нижней строке. Клеток всего `n(n + 1) / 2`, каждая считается один раз.

Второе наблюдение: строка `i` зависит только от строки `i + 1`. Поэтому хватит **одного массива** длины `n`, который мы перезаписываем «на месте», поднимаясь вверх.

## Техники

### Двумерное ДП (на треугольной сетке)

**Что это.** Состояние описывается двумя координатами — строкой и позицией. Решение строится по шаблону: состояние → база → переход → порядок обхода → ответ.

- **Состояние**: `dp[i][j]` — лучший путь от `(i, j)` вниз.
- **База**: последняя строка, `dp[n-1][j] = triangle[n-1][j]`.
- **Переход**: число клетки плюс минимум двух нижних соседей.
- **Порядок**: строки снизу вверх — нижние значения готовы к моменту использования.
- **Ответ**: `dp[0][0]`.

Почему снизу вверх удобнее сверху вниз: у вершины одна клетка, а у основания — `n`. При обходе сверху вниз пришлось бы обрабатывать краевые клетки с одним «родителем» и в конце искать минимум по всей нижней строке. Подробнее о многомерном ДП — во вкладке «Теория».

### Сжатие таблицы до одной строки

Если строка таблицы зависит только от соседней, вместо матрицы хранят один массив. Главное — **порядок перезаписи**: нужно не затереть значение, которое ещё понадобится. Здесь `dp[j]` для строки `i` читает `dp[j]` и `dp[j + 1]` строки `i + 1`. Идём по `j` **слева направо**: перезаписав `dp[j]`, мы больше не читаем его на этой строке (следующему `j + 1` нужны `dp[j + 1]` и `dp[j + 2]`, ещё старые).

## Разбор кода

```ts
function minimumTotal(triangle: number[][]): number {
  const n = triangle.length;
  // dp[j] — минимальная сумма пути от клетки (i, j) до низа треугольника.
  // Начинаем с последней строки: от неё до низа путь — она сама.
  const dp: number[] = [...triangle[n - 1]];
```

База: копия нижней строки. Копия (`[...]`), а не ссылка, — чтобы не портить входной массив `triangle`. Длина `dp` равна `n`, этого хватает для любой строки выше (в них меньше элементов).

```ts
  // Поднимаемся снизу вверх
  for (let i = n - 2; i >= 0; i--) {
    for (let j = 0; j <= i; j++) {
```

Внешний цикл идёт от предпоследней строки к вершине. В строке `i` ровно `i + 1` клеток, поэтому `j` пробегает `0..i`. Если строка одна (`n = 1`), цикл не выполняется ни разу.

```ts
      // Из (i, j) идём в (i+1, j) или (i+1, j+1) — берём лучший.
      // dp[j] и dp[j + 1] ещё хранят значения для строки i + 1,
      // а dp[j] перезаписываем уже для строки i (слева направо — безопасно)
      dp[j] = triangle[i][j] + Math.min(dp[j], dp[j + 1]);
    }
  }
```

Переход: значение клетки плюс лучший из двух нижних путей. В момент вычисления `dp[j]` и `dp[j + 1]` ещё относятся к строке `i + 1` — мы их пока не трогали на этой итерации. После присваивания `dp[j]` уже описывает строку `i`. Элементы правее `i` (например, `dp[i + 1]`) остаются от нижних строк, но больше никогда не читаются как «строка `i`».

```ts
  // Вершина треугольника — ответ
  return dp[0];
}
```

После последней итерации (`i = 0`) в `dp[0]` — минимальная сумма от вершины до низа.

## Трассировка

`triangle = [[2], [3, 4], [6, 5, 7], [4, 1, 8, 3]]`, старт: `dp = [4, 1, 8, 3]`.

```
i=2 (строка 6 5 7):
  j=0: 6 + min(4, 1) = 7    dp=[7, 1, 8, 3]
  j=1: 5 + min(1, 8) = 6    dp=[7, 6, 8, 3]
  j=2: 7 + min(8, 3) = 10   dp=[7, 6, 10, 3]
i=1 (строка 3 4):
  j=0: 3 + min(7, 6) = 9    dp=[9, 6, 10, 3]
  j=1: 4 + min(6, 10) = 10  dp=[9, 10, 10, 3]
i=0 (строка 2):
  j=0: 2 + min(9, 10) = 11  dp=[11, 10, 10, 3]
```

Ответ `11`. Видно, как работает порядок: при `i = 2, j = 1` мы читаем `dp[1] = 1` (ещё старое, строка 3), хотя `dp[0]` уже перезаписан значением `7` для строки 2.

## Почему это работает

Индукция по строкам снизу вверх. Для нижней строки `dp[j]` — путь из одной клетки, верно. Пусть для строки `i + 1` все `dp[j]` верны. Любой путь из `(i, j)` вниз начинается с клетки `(i, j)`, затем проходит через `(i+1, j)` или `(i+1, j+1)` и дальше идёт каким-то путём вниз — не дешевле оптимального от этой клетки. Значит, минимум равен `triangle[i][j] + min(dp[j], dp[j + 1])`, и он достижим. Перезапись слева направо гарантирует, что оба прочитанных значения относятся к строке `i + 1`.

## Пограничные случаи

- **Одна строка** (`[[-10]]`): цикл не выполняется, ответ `dp[0] = -10`.
- **Отрицательные числа**: `min` честно выбирает меньшую сумму, никаких «неотрицательных» допущений нет.
- **Одинаковые суммы** у двух веток: всё равно, какую выбрать.
- **Вход не меняется**: работаем с копией нижней строки.

## Сложность

- **Время `O(n²)`**: каждая из `n(n + 1) / 2` клеток обрабатывается один раз за `O(1)`.
- **Память `O(n)`**: один массив длины `n` — ровно то, что просит follow-up. Если разрешено портить вход, можно писать прямо в `triangle` и получить `O(1)` дополнительной памяти.

## Типичные ошибки

1. **Жадный спуск** в меньшего соседа — локально выгодный шаг не гарантирует глобальный минимум.
2. **Сверху вниз без аккуратных краёв**: у клетки `(i, 0)` один родитель `(i-1, 0)`, у `(i, i)` — один родитель `(i-1, i-1)`; обращение к `dp[i-1][i]` даёт `undefined` и `NaN`. Плюс в конце нужен минимум по нижней строке.
3. **Обход справа налево** при снизу-вверх-сжатии: тогда `dp[j + 1]` будет уже перезаписан значением строки `i` — неверный результат.
4. **`dp = triangle[n - 1]` без копии** — алгоритм испортит входные данные.
5. **Перебор всех путей** — `2ⁿ⁻¹`, TLE уже при `n ≈ 30`.

## Как узнать такую задачу

- Путь по сетке/треугольнику с **фиксированным набором ходов** (вниз, вниз-вправо), нужна минимальная или максимальная сумма.
- Ходы не образуют циклов → можно обходить по слоям, а ответ слоя зависит только от соседнего слоя → ДП с одной строкой памяти.
- Если у цели одна клетка, а у старта много (или наоборот), выгодно считать **от «многих» к «одной»**.

Родственные задачи: Minimum Path Sum, Minimum Falling Path Sum, Unique Paths, Pascal's Triangle, Cherry Pickup.
