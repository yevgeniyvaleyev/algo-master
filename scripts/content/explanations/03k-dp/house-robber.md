## Задача простыми словами

Вдоль улицы стоят дома, в каждом лежит сумма `nums[i]`. Можно ограбить любые дома, но **никакие два соседних** — иначе сработает сигнализация. Нужно вернуть максимальную сумму, которую получится унести.

Пример: `nums = [2, 7, 9, 3, 1]`. Берём дома с суммами `2`, `9` и `1` (позиции `0`, `2`, `4`) — итого `12`. Взять `7` и `9` одновременно нельзя: они соседи.

## Наивный подход

Для каждого дома есть два решения — грабить или нет. Перебор всех вариантов — рекурсия «решаем судьбу дома `i`»:

```ts naive
function best(i: number): number {
  if (i >= nums.length) return 0;
  // пропустить дом i или ограбить его и перепрыгнуть соседа
  return Math.max(best(i + 1), nums[i] + best(i + 2));
}
```

Это верно, но дерево вызовов растёт как числа Фибоначчи — примерно `O(1.6ⁿ)`. При `n = 100` это нереально. Лишняя работа видна сразу: `best(5)` вызывается и из `best(4)` (пропустили дом 4), и из `best(3)` (ограбили дом 3), и ещё много раз с более ранних уровней. **Одни и те же подзадачи** решаются снова и снова.

Жадность («берём самый богатый дом, вычёркиваем соседей») тоже не работает: для `[2, 3, 2]` жадно возьмём `3` и получим `3`, а оптимум — `2 + 2 = 4`.

## Ключевое наблюдение

Посмотрим на **последний** дом среди первых `i + 1`. В оптимальном наборе он либо **не ограблен** — тогда ответ такой же, как для первых `i` домов, либо **ограблен** — тогда сосед `i - 1` точно не тронут, и к деньгам дома прибавляется лучший результат для первых `i - 1` домов:

```
dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])
```

Каждое `dp[i]` зависит только от **двух предыдущих** значений. Значит, таблицу целиком хранить не нужно — хватит двух переменных, которые «едут» вдоль массива.

## Техники

### Динамическое программирование (линейное)

**Что это.** ДП применяют, когда ответ собирается из ответов на меньшие подзадачи (оптимальная подструктура), а сами подзадачи повторяются (перекрытие). Каждую подзадачу считаем один раз.

**Четыре вопроса:**

1. **Состояние**: `dp[i]` — максимум, который можно украсть из домов `0..i`.
2. **База**: до первого дома добыча `0` (`dp[-1] = dp[-2] = 0`).
3. **Переход**: `dp[i] = max(dp[i - 1], dp[i - 2] + nums[i])` — «пропустить» или «взять».
4. **Порядок и ответ**: идём слева направо, ответ — последнее значение.

Это классический шаблон **«взять или пропустить»** с запретом на соседей. Подробнее о ДП — во вкладке «Теория».

### Сжатие памяти до «скользящего окна»

Если переход смотрит только на `k` предыдущих значений, массив `dp` заменяется `k` переменными. Здесь `k = 2`: `prev1` (= `dp[i - 1]`) и `prev2` (= `dp[i - 2]`). После вычисления нового значения окно сдвигается на одну позицию — так же, как при подсчёте чисел Фибоначчи.

## Разбор кода

```ts
function rob(nums: number[]): number {
  // prev2 — лучший результат для домов до i-2 включительно
  // prev1 — лучший результат для домов до i-1 включительно
  let prev2 = 0;
  let prev1 = 0;
```

Две переменные — это последние два значения воображаемой таблицы `dp`. Обе равны `0`: до начала улицы украсть нечего. Такая база избавляет от отдельной обработки первого и второго дома.

```ts
  for (const money of nums) {
    // Либо пропускаем текущий дом (prev1),
    // либо грабим его и добавляем лучший результат без соседа (prev2 + money)
    const cur = Math.max(prev1, prev2 + money);
```

Для каждого дома считаем `cur` = `dp[i]`. Вариант «пропустить» — это просто лучший результат для предыдущих домов, `prev1`. Вариант «ограбить» — деньги дома `money` плюс лучший результат, в котором **гарантированно** нет соседа, то есть `prev2`. Берём максимум.

Индекс дома не нужен — используется `for...of`, потому что переход зависит только от суммы в доме и двух «прошлых» ответов.

```ts
    // Сдвигаем «окно» из двух последних значений
    prev2 = prev1;
    prev1 = cur;
  }
```

Сдвиг окна: то, что было `dp[i - 1]`, становится `dp[i - 2]` для следующего шага, а только что посчитанное `cur` — новым `dp[i - 1]`. Порядок присваиваний важен: если сначала записать `prev1 = cur`, старое значение `prev1` потеряется, и `prev2` получит неверное число.

```ts
  // prev1 — ответ для всех домов
  return prev1;
}
```

После цикла `prev1` хранит `dp[n - 1]` — лучший результат для всей улицы.

## Трассировка

`nums = [2, 7, 9, 3, 1]`, старт: `prev2 = 0`, `prev1 = 0`.

1. `money = 2`: `cur = max(0, 0 + 2) = 2`. Теперь `prev2 = 0`, `prev1 = 2`.
2. `money = 7`: `cur = max(2, 0 + 7) = 7`. Теперь `prev2 = 2`, `prev1 = 7`.
3. `money = 9`: `cur = max(7, 2 + 9) = 11`. Теперь `prev2 = 7`, `prev1 = 11`.
4. `money = 3`: `cur = max(11, 7 + 3) = 11` — дом с `3` выгоднее пропустить. Теперь `prev2 = 11`, `prev1 = 11`.
5. `money = 1`: `cur = max(11, 11 + 1) = 12`. Теперь `prev2 = 11`, `prev1 = 12`.

Ответ `12` — это `2 + 9 + 1`. На шаге 5 `prev2 = 11` означает «лучшее из первых трёх домов» (`2 + 9`), и к нему законно добавить последний дом.

Контрпример к жадности, `nums = [2, 3, 2]`: `cur = 2`, затем `max(2, 0 + 3) = 3`, затем `max(3, 2 + 2) = 4`. Ответ `4`.

## Почему это работает

Индукция по числу домов. Пусть `prev1` и `prev2` верно хранят оптимумы для префиксов длины `i` и `i - 1`. Любой допустимый набор домов из первых `i + 1`:

- либо **не содержит** дом `i` — тогда это допустимый набор из первых `i` домов, и он не лучше `prev1`;
- либо **содержит** дом `i` — тогда в нём нет дома `i - 1`, а остальное — допустимый набор из первых `i - 1` домов, не лучше `prev2`; итого не больше `prev2 + money`.

Третьего варианта нет, и оба значения реально достижимы. Значит, `max(prev1, prev2 + money)` — точный оптимум.

Есть и полезный инвариант: `prev1 >= prev2` всегда (больше домов — не меньше добычи), поэтому ответ никогда не уменьшается по ходу прохода.

## Пограничные случаи

- **Один дом**: `cur = max(0, 0 + nums[0]) = nums[0]` — правильно.
- **Два дома**: второй шаг даёт `max(nums[0], nums[1])`.
- **Нули в массиве**: формула работает, нулевой дом просто не влияет на сумму.
- **Все суммы одинаковые**: возьмём каждый второй дом, `⌈n / 2⌉ · x`.
- Отрицательных сумм по условию нет; если бы были, `max` с вариантом «пропустить» всё равно не дал бы их взять.

## Сложность

- **Время `O(n)`**: один проход, на каждом шаге `max` и два присваивания.
- **Память `O(1)`**: две переменные вместо таблицы `dp` длины `n`.

## Типичные ошибки

1. **Жадный выбор** самого богатого дома или «все чётные против всех нечётных» — неверно: `[2, 1, 1, 2]` даёт оптимум `4` (дома `0` и `3`), а ни чётные, ни нечётные индексы его не дают.
2. **Неправильный порядок сдвига**: `prev1 = cur; prev2 = prev1;` — обе переменные станут равны `cur`.
3. **Переход `dp[i] = dp[i - 2] + nums[i]`** без варианта «пропустить» — теряются наборы, где пропущено два дома подряд.
4. **Особые ветки для `n = 1` и `n = 2`** с обращением к `nums[1]` — легко выйти за границу; база `0, 0` делает их ненужными.
5. **Ответ `max(prev1, prev2)`** вместо `prev1` — не ошибка, но признак непонимания: `prev1` и так не меньше.

## Как узнать такую задачу

- Последовательность элементов, нужно выбрать подмножество с **максимальной суммой**, и есть **запрет на соседей** (или на элементы ближе `k`).
- Решение для каждого элемента бинарное: «взять / не взять», и выбор влияет только на ближайших соседей.
- Переход смотрит на фиксированное число предыдущих состояний → память `O(1)`.

Родственные задачи: House Robber II (дома по кругу — два прогона без первого и без последнего), Delete and Earn (сводится к House Robber по значениям), Climbing Stairs, Min Cost Climbing Stairs.
