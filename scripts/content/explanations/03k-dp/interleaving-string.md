## Задача простыми словами

Даны три строки `s1`, `s2`, `s3`. Нужно понять, можно ли получить `s3`, **перемешав** символы `s1` и `s2` так, чтобы порядок символов внутри каждой из них сохранился. Это как слить две колоды карт в одну, не меняя порядок карт внутри каждой колоды.

Пример: `s1 = "aabcc"`, `s2 = "dbbca"`, `s3 = "aadbbcbcac"` → `true`: `"aa" + "dbbc" + "bc" + "a" + "c"`. Строгое определение в условии про `|n − m| <= 1` пугает, но по сути ничего не добавляет: соседние куски из одной строки просто склеиваются, поэтому любое слияние с сохранением порядка можно записать в нужном виде.

## Наивный подход

Рекурсия: очередной символ `s3` берём из `s1` или из `s2`, если он подходит.

```ts naive
function can(i: number, j: number): boolean {
  if (i === s1.length && j === s2.length) return true;
  const c = s3[i + j];
  return (i < s1.length && s1[i] === c && can(i + 1, j))
      || (j < s2.length && s2[j] === c && can(i, j + 1));
}
```

Жадно выбирать нельзя: если `s1[i]` и `s2[j]` оба равны очередному символу, неясно, какой взять, и неправильный выбор всплывёт только много позже. Поэтому перебор ветвится, и в худшем случае (`s1 = "aaaa…"`, `s2 = "aaaa…"`, а в конце несовпадение) — `O(2^(m+n))`. Лишняя работа: состояние полностью описывается парой `(i, j)` — сколько символов уже взято из каждой строки, — а пар всего `(m + 1)(n + 1)`. Рекурсия же приходит в одну и ту же пару разными путями и каждый раз считает заново.

## Ключевое наблюдение

Если из `s1` взято `i` символов, а из `s2` — `j`, то собрано ровно `i + j` первых символов `s3`. Поэтому достаточно знать для каждой пары `(i, j)`: **можно или нет**.

Последний символ собранного префикса `s3[i + j − 1]` пришёл либо из `s1` (тогда это `s1[i − 1]`, и до этого была пара `(i − 1, j)`), либо из `s2` (тогда это `s2[j − 1]`, и была пара `(i, j − 1)`). Это двумерное ДП по префиксам двух строк. А так как строка таблицы зависит только от предыдущей строки и от самой себя, хватает одного массива длины `n + 1` — ровно то, что просит follow-up.

## Техники

### ДП по префиксам двух строк

**Что это.** Типичная форма двумерного ДП для задач про две последовательности: `dp[i][j]` описывает префиксы `a[0..i)` и `b[0..j)`. Так решаются LCS, расстояние редактирования, чередование строк. Переход смотрит на **последний** символ и спрашивает, откуда он взялся.

- **Состояние**: `dp[i][j]` — можно ли из `s1[0..i)` и `s2[0..j)` собрать `s3[0..i+j)`.
- **База**: `dp[0][0] = true` — два пустых префикса дают пустую строку.
- **Переход**: `dp[i][j] = (dp[i-1][j] && s1[i-1] === s3[i+j-1]) || (dp[i][j-1] && s2[j-1] === s3[i+j-1])`.
- **Ответ**: `dp[m][n]`.

Размер `+1` по каждой оси нужен для пустых префиксов. Подробнее о многомерном ДП — во вкладке «Теория».

### Сжатие до одной строки

Переход использует клетку **сверху** (`dp[i-1][j]`) и **слева** (`dp[i][j-1]`). В одномерном массиве до перезаписи `dp[j]` ещё хранит значение строки `i − 1` («сверху»), а `dp[j − 1]` уже обновлён для строки `i` («слева»). Тот же приём, что в задачах на сетке.

## Разбор кода

```ts
function isInterleave(s1: string, s2: string, s3: string): boolean {
  const m = s1.length;
  const n = s2.length;
  // Длины должны сойтись — иначе часть символов лишняя или не хватает
  if (m + n !== s3.length) return false;
```

Быстрая проверка: каждый символ `s3` берётся ровно из одной строки, значит длины обязаны сойтись. Кроме экономии времени, это защищает индексы: дальше `s3[i + j − 1]` всегда существует.

```ts
  // dp[j] — можно ли из первых i символов s1 и первых j символов s2
  // составить первые i + j символов s3 (строка i таблицы, сжатая в одномерный массив)
  const dp: boolean[] = new Array(n + 1).fill(false);
```

Одна строка таблицы на `n + 1` значений (от пустого префикса `s2` до всего `s2`).

```ts
  for (let i = 0; i <= m; i++) {
    for (let j = 0; j <= n; j++) {
      if (i === 0 && j === 0) {
        // Пустые префиксы дают пустую строку
        dp[j] = true;
        continue;
      }
```

Обходим все пары `(i, j)`, включая нулевые: строка `i = 0` — «из `s1` ничего не взято», столбец `j = 0` — «из `s2` ничего». База — клетка `(0, 0)`.

```ts
      // Очередной символ s3 имеет индекс i + j - 1
      const c = s3[i + j - 1];
      // Вариант 1: последний символ взят из s1 — смотрим dp[i - 1][j],
      // это старое значение dp[j] (ещё не перезаписано в строке i)
      const fromS1 = i > 0 && dp[j] && s1[i - 1] === c;
```

`c` — последний символ префикса `s3`, который мы собираем. Вариант «из `s1`» возможен, если из `s1` вообще что-то взято (`i > 0`), предыдущее состояние `(i − 1, j)` достижимо (старое `dp[j]`), и последний взятый символ `s1[i − 1]` совпадает с `c`.

```ts
      // Вариант 2: последний символ взят из s2 — смотрим dp[i][j - 1],
      // это уже обновлённое значение dp[j - 1]
      const fromS2 = j > 0 && dp[j - 1] && s2[j - 1] === c;
      dp[j] = fromS1 || fromS2;
    }
  }
```

Симметрично для `s2`: состояние `(i, j − 1)` лежит в только что обновлённом `dp[j − 1]`. Результат — «хотя бы один вариант возможен». Важно, что `fromS1` вычислен **до** присваивания `dp[j]` — иначе старое значение было бы потеряно.

```ts
  return dp[n];
}
```

После строки `i = m` в `dp[n]` — ответ для полных строк.

## Трассировка

`s1 = "ab"`, `s2 = "ac"`, `s3 = "aacb"`. Длины `2 + 2 = 4` сошлись. `dp = [F, F, F]`.

```
i=0:
  j=0: база                                         dp=[T, F, F]
  j=1: c=s3[0]='a'; fromS2: dp[0]=T, s2[0]='a' ✓    dp=[T, T, F]
  j=2: c=s3[1]='a'; fromS2: dp[1]=T, s2[1]='c' ✗    dp=[T, T, F]
i=1:
  j=0: c=s3[0]='a'; fromS1: dp[0]=T, s1[0]='a' ✓    dp=[T, T, F]
  j=1: c=s3[1]='a'; fromS1: dp[1]=T, s1[0]='a' ✓    dp=[T, T, F]
  j=2: c=s3[2]='c'; fromS1: dp[2]=F;
                    fromS2: dp[1]=T, s2[1]='c' ✓    dp=[T, T, T]
i=2:
  j=0: c=s3[1]='a'; fromS1: dp[0]=T, s1[1]='b' ✗    dp=[F, T, T]
  j=1: c=s3[2]='c'; fromS1: s1[1]='b' ✗;
                    fromS2: dp[0]=F ✗               dp=[F, F, T]
  j=2: c=s3[3]='b'; fromS1: dp[2]=T, s1[1]='b' ✓    dp=[F, F, T]
```

Ответ `dp[2] = true`. Обратите внимание на клетку `(1, 1)`: первые две `'a'` можно взять в любом порядке — именно здесь жадный алгоритм мог бы «выбрать не ту», а ДП учитывает обе возможности.

Пример с несовпадением длин: `s1 = "a"`, `s2 = "b"`, `s3 = "abc"` — `1 + 1 ≠ 3`, сразу `false`.

## Почему это работает

Индукция по порядку обхода. `dp[0][0]` верно. Пусть `s3[0..i+j)` собирается из `s1[0..i)` и `s2[0..j)`. Последний символ такого слияния взят либо из `s1` — тогда это `s1[i−1]`, и остальное — слияние `s1[0..i−1)` и `s2[0..j)`, то есть `dp[i−1][j] = true`; либо из `s2` — симметрично. Обратно, если, например, `dp[i−1][j]` истинно и `s1[i−1] === s3[i+j−1]`, дописав этот символ к слиянию, получаем слияние для `(i, j)`. Клетки «сверху» и «слева» вычислены раньше и лежат в нужных ячейках одномерного массива.

## Пограничные случаи

- **Все строки пустые**: длины `0 + 0 = 0`, `dp[0] = true` — ответ `true`.
- **Одна из строк пустая**: ответ — равна ли другая строка `s3` (ДП проверит это посимвольно по одной строке или столбцу).
- **Несовпадение длин**: отсекается в первой проверке.
- **Одинаковые символы в обеих строках**: ДП перебирает оба источника, жадность не нужна.

## Сложность

- **Время `O(m · n)`**: `(m + 1)(n + 1)` клеток, каждая за `O(1)`.
- **Память `O(n)`**: один массив длины `n + 1` (можно выбрать меньшую из строк в роли `s2` и получить `O(min(m, n))`).

## Типичные ошибки

1. **Жадный выбор**, когда символ подходит из обеих строк, — ломается на примерах вроде `s1 = "ab"`, `s2 = "ac"`.
2. **Забыть проверку длин** — `s3` длиннее, а `dp[m][n]` может оказаться `true` для префикса.
3. **Индекс символа `s3[i + j]`** вместо `s3[i + j − 1]` — ошибка на единицу: `dp[i][j]` описывает **первые** `i + j` символов.
4. **Перезаписать `dp[j]` до вычисления `fromS1`** — потеряется значение «сверху».
5. **Буквально реализовывать условие `|n − m| <= 1`** с подсчётом кусков — бесполезное усложнение.

## Как узнать такую задачу

- Даны **две последовательности**, и нужно что-то сказать об их префиксах одновременно: слияние, общая подпоследовательность, превращение одной в другую.
- Состояние — «сколько уже обработано из каждой» → таблица `(m + 1) × (n + 1)`, переход по последнему символу.
- Жадный выбор неоднозначен, когда символы совпадают в обеих строках.

Родственные задачи: Edit Distance, Longest Common Subsequence, Distinct Subsequences, Shortest Common Supersequence, Regular Expression Matching.
