## Задача простыми словами

Даны три строки `s1`, `s2`, `s3`. Нужно понять, можно ли получить `s3`, **перемешав** символы `s1` и `s2` так, чтобы порядок символов внутри каждой из них сохранился. Это как слить две колоды карт в одну, не меняя порядок карт внутри каждой колоды.

Пример: `s1 = "aabcc"`, `s2 = "dbbca"`, `s3 = "aadbbcbcac"` → `true`: `"aa" + "dbbc" + "bc" + "a" + "c"`. Строгое определение в условии про `|n − m| <= 1` пугает, но по сути ничего не добавляет: соседние куски из одной строки просто склеиваются, поэтому любое слияние с сохранением порядка можно записать в нужном виде.

## Наивный подход

Рекурсия: очередной символ `s3` берём из `s1` или из `s2`, если он подходит.

```ts naive
function can(i: number, j: number): boolean {
  if (i === s1.length && j === s2.length) return true;
  const c = s3[i + j];
  return (i < s1.length && s1[i] === c && can(i + 1, j))
      || (j < s2.length && s2[j] === c && can(i, j + 1));
}
```

Жадно выбирать нельзя: если `s1[i]` и `s2[j]` оба равны очередному символу, неясно, какой взять, и неправильный выбор всплывёт только много позже. Поэтому перебор ветвится, и в худшем случае (`s1 = "aaaa…"`, `s2 = "aaaa…"`, а в конце несовпадение) — `O(2^(m+n))`. Лишняя работа: состояние полностью описывается парой `(i, j)` — сколько символов уже взято из каждой строки, — а пар всего `(m + 1)(n + 1)`. Рекурсия же приходит в одну и ту же пару разными путями и каждый раз считает заново.

## Ключевое наблюдение

Если из `s1` взято `i` символов, а из `s2` — `j`, то собрано ровно `i + j` первых символов `s3`. Поэтому достаточно знать для каждой пары `(i, j)`: **можно или нет**.

Последний символ собранного префикса `s3[i + j − 1]` пришёл либо из `s1` (тогда это `s1[i − 1]`, и до этого была пара `(i − 1, j)`), либо из `s2` (тогда это `s2[j − 1]`, и была пара `(i, j − 1)`). Это двумерное ДП по префиксам двух строк: таблица `(m + 1) × (n + 1)`, где каждая клетка смотрит на соседа **сверху** и **слева**.

## Техники

### ДП по префиксам двух строк

**Что это.** Типичная форма двумерного ДП для задач про две последовательности: `dp[i][j]` описывает префиксы `a[0..i)` и `b[0..j)`. Так решаются LCS, расстояние редактирования, чередование строк. Переход смотрит на **последний** символ и спрашивает, откуда он взялся.

- **Состояние**: `dp[i][j]` — можно ли из `s1[0..i)` и `s2[0..j)` собрать `s3[0..i+j)`.
- **База**: `dp[0][0] = true` — два пустых префикса дают пустую строку.
- **Переход**: `dp[i][j] = (i > 0 && dp[i-1][j] && s1[i-1] === s3[i+j-1]) || (j > 0 && dp[i][j-1] && s2[j-1] === s3[i+j-1])`.
- **Порядок**: строки `i` сверху вниз, внутри строки `j` слева направо — сосед сверху и сосед слева уже посчитаны.
- **Ответ**: `dp[m][n]`.

Размер `+1` по каждой оси нужен для пустых префиксов. Подробнее о многомерном ДП — во вкладке «Теория».

### Нулевая строка и нулевой столбец

Строка `i = 0` означает «из `s1` ничего не взято»: туда можно прийти только слева, и она проверяет, совпадает ли префикс `s3` с префиксом `s2`. Столбец `j = 0` — то же для `s1`. Условия `i > 0` и `j > 0` в переходе не дают заглянуть за край таблицы, поэтому края считаются той же формулой, что и середина.

## Разбор кода

```ts
function isInterleave(s1: string, s2: string, s3: string): boolean {
  const m = s1.length;
  const n = s2.length;
  // Длины должны сойтись — иначе часть символов лишняя или не хватает
  if (m + n !== s3.length) return false;
```

Быстрая проверка: каждый символ `s3` берётся ровно из одной строки, значит длины обязаны сойтись. Кроме экономии времени, это защищает индексы: дальше `s3[i + j − 1]` всегда существует.

```ts
  // Состояние: dp[i][j] — можно ли из первых i символов s1 и первых j символов s2
  // собрать первые i + j символов s3
  const dp: boolean[][] = Array.from({ length: m + 1 }, () => new Array(n + 1).fill(false));
  // База: пустые префиксы дают пустую строку
  dp[0][0] = true;
```

Полная таблица `(m + 1) × (n + 1)`: лишние строка и столбец — для пустых префиксов. Всё `false`, кроме базы `dp[0][0]`.

```ts
  // Порядок: строки сверху вниз, внутри строки слева направо
  for (let i = 0; i <= m; i++) {
    for (let j = 0; j <= n; j++) {
      if (i === 0 && j === 0) continue;
```

Обходим все пары `(i, j)`, включая нулевые строку и столбец. Клетку `(0, 0)` пропускаем — это база, она уже заполнена.

```ts
      // Очередной символ s3 имеет индекс i + j - 1
      const c = s3[i + j - 1];
      // Переход 1: последний символ взят из s1 — без него собрали dp[i - 1][j]
      const fromS1 = i > 0 && dp[i - 1][j] && s1[i - 1] === c;
```

`c` — последний символ префикса `s3`, который мы собираем. Вариант «из `s1`» возможен, если из `s1` вообще что-то взято (`i > 0`), состояние без этого символа `(i − 1, j)` достижимо, и последний взятый символ `s1[i − 1]` совпадает с `c`.

```ts
      // Переход 2: последний символ взят из s2 — без него собрали dp[i][j - 1]
      const fromS2 = j > 0 && dp[i][j - 1] && s2[j - 1] === c;
      dp[i][j] = fromS1 || fromS2;
    }
  }
```

Симметрично для `s2`: смотрим на соседа слева. Результат — «хотя бы один вариант возможен».

```ts
  // Ответ: обе строки использованы целиком
  return dp[m][n];
}
```

Правый нижний угол таблицы — ответ для полных строк.

## Трассировка

`s1 = "ab"`, `s2 = "ac"`, `s3 = "aacb"`. Длины `2 + 2 = 4` сошлись. `dp[0][0] = T`.

```
(0,1): c=s3[0]='a'; слева (0,0)=T, s2[0]='a' ✓                 → T
(0,2): c=s3[1]='a'; слева (0,1)=T, s2[1]='c' ✗                 → F
(1,0): c=s3[0]='a'; сверху (0,0)=T, s1[0]='a' ✓                → T
(1,1): c=s3[1]='a'; сверху (0,1)=T, s1[0]='a' ✓                → T
(1,2): c=s3[2]='c'; сверху (0,2)=F; слева (1,1)=T, s2[1]='c' ✓ → T
(2,0): c=s3[1]='a'; сверху (1,0)=T, s1[1]='b' ✗                → F
(2,1): c=s3[2]='c'; сверху s1[1]='b' ✗; слева (2,0)=F          → F
(2,2): c=s3[3]='b'; сверху (1,2)=T, s1[1]='b' ✓                → T
```

Итоговая таблица:

```
      j=0 j=1 j=2
i=0    T   T   F
i=1    T   T   T
i=2    F   F   T
```

Ответ `dp[2][2] = true`. Путь из `T` от `(0, 0)` до `(2, 2)` — это и есть способ слияния: `(0,0) → (1,0) → (1,1) → (1,2) → (2,2)` означает «`a` из `s1`, `a` из `s2`, `c` из `s2`, `b` из `s1`». Клетка `(1, 1)` достижима двумя путями: первые две `'a'` можно взять в любом порядке — именно здесь жадный алгоритм мог бы «выбрать не ту», а ДП учитывает обе возможности.

Пример с несовпадением длин: `s1 = "a"`, `s2 = "b"`, `s3 = "abc"` — `1 + 1 ≠ 3`, сразу `false`.

## Почему это работает

Индукция по порядку обхода. `dp[0][0]` верно. Пусть `s3[0..i+j)` собирается из `s1[0..i)` и `s2[0..j)`. Последний символ такого слияния взят либо из `s1` — тогда это `s1[i−1]`, и остальное — слияние `s1[0..i−1)` и `s2[0..j)`, то есть `dp[i−1][j] = true`; либо из `s2` — симметрично. Обратно, если, например, `dp[i−1][j]` истинно и `s1[i−1] === s3[i+j−1]`, дописав этот символ к слиянию, получаем слияние для `(i, j)`. Клетки «сверху» и «слева» вычислены раньше благодаря порядку обхода.

## Пограничные случаи

- **Все строки пустые**: длины `0 + 0 = 0`, `dp[0] = true` — ответ `true`.
- **Одна из строк пустая**: ответ — равна ли другая строка `s3` (ДП проверит это посимвольно по одной строке или столбцу).
- **Несовпадение длин**: отсекается в первой проверке.
- **Одинаковые символы в обеих строках**: ДП перебирает оба источника, жадность не нужна.

## Сложность

- **Время `O(m · n)`**: `(m + 1)(n + 1)` клеток, каждая за `O(1)`.
- **Память `O(m · n)`**: полная таблица. При `m, n ≤ 100` это около 10 тысяч значений.

**Follow-up из условия: память `O(s2.length)`.** Переход использует только клетку сверху и клетку слева, поэтому хватает одного массива длины `n + 1`: до перезаписи `dp[j]` хранит значение строки `i − 1` («сверху»), а `dp[j − 1]` уже обновлён для строки `i` («слева»).

```ts naive
const dp = new Array(n + 1).fill(false);
for (let i = 0; i <= m; i++) {
  for (let j = 0; j <= n; j++) {
    if (i === 0 && j === 0) { dp[0] = true; continue; }
    const c = s3[i + j - 1];
    const fromS1 = i > 0 && dp[j] && s1[i - 1] === c; // старое dp[j] — «сверху»
    const fromS2 = j > 0 && dp[j - 1] && s2[j - 1] === c; // новое dp[j - 1] — «слева»
    dp[j] = fromS1 || fromS2;
  }
}
return dp[n];
```

Здесь важно вычислить `fromS1` **до** присваивания `dp[j]`.

## Типичные ошибки

1. **Жадный выбор**, когда символ подходит из обеих строк, — ломается на примерах вроде `s1 = "ab"`, `s2 = "ac"`.
2. **Забыть проверку длин** — `s3` длиннее, а `dp[m][n]` может оказаться `true` для префикса.
3. **Индекс символа `s3[i + j]`** вместо `s3[i + j − 1]` — ошибка на единицу: `dp[i][j]` описывает **первые** `i + j` символов.
4. **Таблица `m × n` без нулевых строки и столбца** — нет места для пустых префиксов, и база не выражается.
5. **Буквально реализовывать условие `|n − m| <= 1`** с подсчётом кусков — бесполезное усложнение.

## Как узнать такую задачу

- Даны **две последовательности**, и нужно что-то сказать об их префиксах одновременно: слияние, общая подпоследовательность, превращение одной в другую.
- Состояние — «сколько уже обработано из каждой» → таблица `(m + 1) × (n + 1)`, переход по последнему символу.
- Жадный выбор неоднозначен, когда символы совпадают в обеих строках.

Родственные задачи: Edit Distance, Longest Common Subsequence, Distinct Subsequences, Shortest Common Supersequence, Regular Expression Matching.
