## Задача простыми словами

Даны два слова `word1` и `word2`. За одну операцию можно **вставить**, **удалить** или **заменить** один символ в `word1`. Нужно найти минимальное число операций, превращающих `word1` в `word2`. Это знаменитое **расстояние Левенштейна**.

Пример: `"horse"` → `"ros"` за 3 операции: заменить `h` на `r` (`"rorse"`), удалить `r` (`"rose"`), удалить `e` (`"ros"`). Быстрее нельзя.

## Наивный подход

Рекурсия по концам строк: сравниваем последние символы; если равны — отбрасываем оба, иначе пробуем все три операции.

```ts naive
function dist(i: number, j: number): number {
  if (i === 0) return j; // осталось вставить j символов
  if (j === 0) return i; // осталось удалить i символов
  if (word1[i - 1] === word2[j - 1]) return dist(i - 1, j - 1);
  return 1 + Math.min(dist(i - 1, j - 1), dist(i - 1, j), dist(i, j - 1));
}
```

Ветвление на 3 при каждом несовпадении даёт до `O(3^(m+n))` вызовов — при длинах до 500 безнадёжно. Лишняя работа: пара `(i, j)` («первые `i` символов против первых `j`») достигается многими разными цепочками операций — например, «удалить, потом вставить» и «вставить, потом удалить» приводят в одну и ту же пару. Различных пар всего `(m + 1)(n + 1)`.

## Ключевое наблюдение

Ответ для префиксов `word1[0..i)` и `word2[0..j)` зависит только от ответов для **чуть более коротких** префиксов. Посмотрим на последние символы `a = word1[i−1]` и `b = word2[j−1]`:

- если `a === b`, они уже стоят на месте — ответ как для `(i − 1, j − 1)`;
- иначе в оптимальном решении с концом что-то делается: `a` **заменяется** на `b` (дальше `(i−1, j−1)`), `a` **удаляется** (дальше `(i−1, j)`) или `b` **вставляется** в конец (дальше `(i, j−1)`).

Записываем ответы всех пар в таблицу `(m + 1) × (n + 1)` и заполняем её от пустых префиксов к полным.

## Техники

### ДП по префиксам двух строк

**Что это.** Двумерное ДП, где `dp[i][j]` описывает пару префиксов. Переход разбирает, что произошло с **последними** символами. Это общий каркас задач LCS, Interleaving String, Distinct Subsequences.

- **Состояние**: `dp[i][j]` — минимум операций, чтобы превратить `word1[0..i)` в `word2[0..j)`.
- **База**: `dp[i][0] = i` (удалить всё), `dp[0][j] = j` (вставить всё).
- **Переход**: при совпадении — `dp[i−1][j−1]`; иначе `1 + min(замена, удаление, вставка)`.
- **Порядок**: строки по возрастанию `i`, внутри — по возрастанию `j`: три зависимости (сверху, слева, по диагонали) уже готовы.
- **Ответ**: `dp[m][n]`.

Подробнее о многомерном ДП — во вкладке «Теория».

### Три направления в таблице = три операции

Полезно запомнить геометрию: в клетке `(i, j)`

```
dp[i-1][j-1]    dp[i-1][j]
       ↘            ↓
dp[i][j-1]  →   dp[i][j]

↘  замена (или бесплатно при совпадении)
↓  удаление word1[i-1]
→  вставка word2[j-1]
```

Диагональ — «обработали по символу из обоих слов», вертикаль — «съели символ `word1`» (удаление), горизонталь — «получили символ `word2`, ничего не потратив из `word1`» (вставка).

## Разбор кода

```ts
function minDistance(word1: string, word2: string): number {
  const m = word1.length;
  const n = word2.length;

  // dp[i][j] — расстояние между первыми i символами word1 и первыми j символами word2
  const dp: number[][] = Array.from({ length: m + 1 }, () => new Array<number>(n + 1).fill(0));
```

Таблица `(m + 1) × (n + 1)`: дополнительные строка и столбец — для пустых префиксов. `Array.from` с фабрикой создаёт **отдельный** массив для каждой строки (в отличие от `new Array(m + 1).fill(new Array(...))`, где все строки были бы одним и тем же объектом).

```ts
  // Из префикса длины i в пустую строку — i удалений
  for (let i = 0; i <= m; i++) dp[i][0] = i;
  // Из пустой строки в префикс длины j — j вставок
  for (let j = 0; j <= n; j++) dp[0][j] = j;
```

База — первый столбец и первая строка. Превратить `i` символов в пустую строку можно только `i` удалениями; получить `j` символов из пустой — только `j` вставками. `dp[0][0] = 0`.

```ts
  for (let i = 1; i <= m; i++) {
    for (let j = 1; j <= n; j++) {
      if (word1[i - 1] === word2[j - 1]) {
        // Последние символы совпали — ничего делать не нужно
        dp[i][j] = dp[i - 1][j - 1];
```

Заполнение по строкам. Индекс символа на единицу меньше индекса таблицы: `dp[i][j]` описывает префикс длины `i`, его последний символ — `word1[i − 1]`. При совпадении последних символов они «бесплатно» выравниваются друг с другом, остаётся решить задачу для префиксов на один короче.

```ts
      } else {
        dp[i][j] =
          1 +
          Math.min(
            dp[i - 1][j - 1], // заменить word1[i-1] на word2[j-1]
            dp[i - 1][j], // удалить word1[i-1]
            dp[i][j - 1], // вставить word2[j-1]
          );
      }
    }
  }
```

Несовпадение: платим одну операцию и выбираем самую дешёвую подзадачу.

- **Замена**: превратили `word1[i−1]` в `word2[j−1]`, остаток — `(i − 1, j − 1)`.
- **Удаление**: выбросили `word1[i−1]`, `word2[0..j)` нужно получить из `word1[0..i−1)`.
- **Вставка**: дописали `word2[j−1]` в конец, теперь `word1[0..i)` должно стать `word2[0..j−1)`.

```ts
  return dp[m][n];
}
```

Ответ — расстояние между полными словами.

## Трассировка

`word1 = "horse"`, `word2 = "ros"`. Таблица (строки — префиксы `horse`, столбцы — префиксы `ros`):

```
        ""  r   o   s
  ""     0  1   2   3
  h      1  1   2   3
  o      2  2   1   2
  r      3  2   2   2
  s      4  3   3   2
  e      5  4   4   3
```

Как получены ключевые клетки:

1. `(h, r)`: `h ≠ r` → `1 + min(0, 1, 1) = 1` (замена).
2. `(o, ro)`: `o = o` → диагональ `dp[1][1] = 1`.
3. `(o, ros)`: `o ≠ s` → `1 + min(dp[1][2]=2, dp[1][3]=3, dp[2][2]=1) = 2` (вставка `s`).
4. `(r, r)`, строка `r`, столбец `r`: `r = r` → `dp[2][0] = 2`.
5. `(r, ros)`: `r ≠ s` → `1 + min(dp[2][2]=1, dp[2][3]=2, dp[3][2]=2) = 2` (замена по диагонали).
6. `(s, ros)`: `s = s` → `dp[3][2] = 2`.
7. `(e, ros)`: `e ≠ s` → `1 + min(dp[4][2]=3, dp[4][3]=2, dp[5][2]=4) = 3` (удаление `e`).

Ответ `dp[5][3] = 3`. Путь назад по таблице: `(5,3)` ← удаление `e` ← `(4,3)` ← совпадение `s` ← `(3,2)` ← удаление `r` ← `(2,2)` ← совпадение `o` ← `(1,1)` ← замена `h` на `r` ← `(0,0)`. Это ровно последовательность из примера.

## Почему это работает

Рассмотрим оптимальную последовательность операций, превращающую `word1[0..i)` в `word2[0..j)`, как выравнивание: каждый символ `word1` либо удалён, либо сопоставлен символу `word2` (с заменой или без), а каждый символ `word2` либо сопоставлен, либо вставлен. Для последних символов возможно ровно четыре ситуации: они сопоставлены друг с другом (бесплатно при равенстве или замена), `word1[i−1]` удалён, или `word2[j−1]` вставлен. В каждой из них остаток — оптимальное решение соответствующей подзадачи, иначе всё решение можно было бы улучшить. Поэтому минимум по вариантам — точный ответ.

Тонкость: при совпадении символов код берёт диагональ **без** сравнения с другими вариантами. Это корректно, потому что `dp[i−1][j−1] <= dp[i−1][j] + 1` и `dp[i−1][j−1] <= dp[i][j−1] + 1` (соседние клетки таблицы отличаются не больше чем на 1), так что сопоставить равные символы никогда не хуже.

## Пограничные случаи

- **Одно слово пустое**: циклы по `i, j ≥ 1` не выполняются, ответ берётся из базы — длина другого слова.
- **Оба пустые**: `dp[0][0] = 0`.
- **Слова равны**: всё идёт по диагонали совпадений, ответ `0`.
- **Нет общих символов**: ответ `max(m, n)` (замены плюс вставки/удаления разницы длин).

## Сложность

- **Время `O(m · n)`**: каждая из `(m + 1)(n + 1)` клеток вычисляется за `O(1)`. При `500 × 500` — 250 000 клеток.
- **Память `O(m · n)`**: полная таблица. Её можно сжать до двух строк (или одной строки и переменной для диагонали) — `O(min(m, n))`, но полная таблица позволяет восстановить сами операции, пройдя от `(m, n)` назад.

## Типичные ошибки

1. **Путать индексы**: `word1[i]` вместо `word1[i − 1]` — таблица сдвинута на единицу относительно строк.
2. **Забыть базу**: заполнить нулями первую строку и столбец — тогда превращение в пустую строку «бесплатно».
3. **Перепутать удаление и вставку** местами — ответ останется верным (операции симметричны), но объяснение и восстановление операций будут неверными.
4. **`new Array(m + 1).fill(new Array(n + 1))`** — все строки ссылаются на один массив, таблица ломается.
5. **Жадное выравнивание** (идти двумя указателями и заменять несовпадения) — не учитывает сдвиги: `"abc"` → `"bc"` жадно дало бы 3 вместо 1.

## Как узнать такую задачу

- Нужно **минимальное число правок** (вставок, удалений, замен), чтобы одна строка/последовательность стала другой; или «похожесть» строк.
- Две последовательности, ответ строится из префиксов → таблица `(m + 1) × (n + 1)`, переход по последним символам.
- Если разрешены только вставки и удаления — ответ `m + n − 2 · LCS`.

Родственные задачи: Longest Common Subsequence, Delete Operation for Two Strings, One Edit Distance, Minimum ASCII Delete Sum, Interleaving String.
