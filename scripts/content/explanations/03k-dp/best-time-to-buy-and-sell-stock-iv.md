## Задача простыми словами

Дан массив цен акции по дням `prices` и число `k`. Можно совершить **не более `k` сделок** (купить → продать), держа одновременно не больше одной акции. Нужно вернуть максимальную прибыль.

Пример: `k = 2`, `prices = [3, 2, 6, 5, 0, 3]`. Покупаем по `2`, продаём по `6` (+4), покупаем по `0`, продаём по `3` (+3) — итого `7`. При `k = 1` ответ был бы `4`.

## Наивный подход

Рекурсия по дням с состоянием «сколько сделок осталось» и «держим ли акцию»:

```ts naive
function best(day: number, left: number, holding: boolean): number {
  if (day === n || left === 0) return 0;
  const skip = best(day + 1, left, holding);
  const act = holding
    ? prices[day] + best(day + 1, left - 1, false) // продаём, сделка закрыта
    : -prices[day] + best(day + 1, left, true);    // покупаем
  return Math.max(skip, act);
}
```

Без кеша каждый день ветвится на два — `O(2ⁿ)`. Лишняя работа видна в сигнатуре: всё, что важно, — тройка `(day, left, holding)`, а таких троек всего `n · (k + 1) · 2`. Рекурсия же посещает одну и ту же тройку экспоненциально много раз. С мемоизацией это уже `O(n · k)` — и решение в коде делает то же самое, но снизу вверх, без рекурсии и с `O(k)` памяти. При `n ≤ 1000` и `k ≤ 100` это всего `10⁵` шагов.

## Ключевое наблюдение

Это прямое обобщение Stock III. Там было четыре состояния `buy1 → sell1 → buy2 → sell2`; здесь для каждой сделки `j = 1..k` два состояния:

- `buy[j]` — лучший баланс, когда держим акцию, купленную в `j`-й сделке;
- `sell[j]` — лучший баланс после завершения `j` сделок.

Цепочка `sell[0] → buy[1] → sell[1] → buy[2] → … → sell[k]` обновляется за `O(k)` на каждый день.

## Техники

### ДП «день × номер сделки» (автомат состояний)

**Что это.** Состояние — это этап процесса (сколько сделок завершено, держим ли акцию), а значение — лучший баланс, с которым можно на этом этапе оказаться к текущему дню. Каждый день каждое состояние либо остаётся как есть, либо получается из предыдущего этапа одной операцией. Измерение «день» сжато: храним только текущие значения, массивы длины `k + 1`.

```
sell[0]=0 ──−p──▶ buy[1] ──+p──▶ sell[1] ──−p──▶ buy[2] ──+p──▶ sell[2] … sell[k]
```

**Как применяется здесь.**

1. **Состояние**: `buy[j]`, `sell[j]` для `j = 0..k` — лучший баланс к текущему дню.
2. **База**: `sell[j] = 0` (ничего не делали — баланс 0), `buy[j] = −∞` (до первого дня держать акцию нельзя).
3. **Переход** для цены `p`: `buy[j] = max(buy[j], sell[j − 1] − p)`, `sell[j] = max(sell[j], buy[j] + p)`.
4. **Порядок**: дни по очереди, внутри дня — `j` от `1` до `k`.
5. **Ответ**: `sell[k]`.

Покупка `j`-й сделки делается на баланс после `j − 1` сделок, продажа закрывает её. Подробнее о многомерном ДП — во вкладке «Теория».

### Полная таблица и её сжатие

Строго говоря, это двумерная таблица `dp[день][сделка]`: `buy[t][j]`, `sell[t][j]`. Но день `t` зависит только от дня `t − 1`, поэтому храним одну «строку» — массивы длины `k + 1`, перезаписываемые каждый день. Эквивалентная запись через прибыль:

```
dp[j][i] = max(dp[j][i-1], prices[i] + max_{t<i}(dp[j-1][t] - prices[t]))
```

Внутренний максимум — это и есть `buy[j]`, поддерживаемый на лету.

## Разбор кода

```ts
function maxProfit(k: number, prices: number[]): number {
  // Состояние: buy[j] — лучший баланс, если держим акцию, купленную в j-й сделке;
  // sell[j] — лучший баланс после завершения j сделок.
  // База: до первого дня купить нельзя (-Infinity), без сделок баланс 0
  const buy: number[] = new Array(k + 1).fill(-Infinity);
  const sell: number[] = new Array(k + 1).fill(0);
```

Массивы длины `k + 1`; индекс `0` используется только у `sell` — `sell[0] = 0`, «ни одной сделки, баланс ноль», база для первой покупки. `buy` заполнен `-Infinity`: до первого дня держать акцию невозможно, и такое состояние не должно выигрывать ни один `max`. `sell[j] = 0` для всех `j` — «сделки были пустыми», баланс не изменился.

```ts
  // Порядок: дни по очереди, внутри дня — сделки j = 1..k
  for (const p of prices) {
    for (let j = 1; j <= k; j++) {
      // Переход: j-я покупка делается на деньги после j - 1 завершённых сделок
      buy[j] = Math.max(buy[j], sell[j - 1] - p);
      // Переход: j-я продажа закрывает j-ю покупку
      sell[j] = Math.max(sell[j], buy[j] + p);
    }
  }
```

Для каждого дня проходим сделки по возрастанию `j`. `buy[j]` — либо уже держим акцию `j`-й сделки, либо покупаем сегодня на баланс после `j − 1` сделок. `sell[j]` — либо `j` сделок уже завершены, либо продаём сегодня акцию `j`-й сделки.

Как и в Stock III, обновление «на месте» безопасно: `sell[j − 1]` может оказаться уже сегодняшним (продали сегодня), а `buy[j]` — сегодняшним (купили сегодня). Это означает «продать и купить в тот же день» или «купить и продать в тот же день» — операции с нулевым эффектом на баланс, которые не создают лишней прибыли.

```ts
  // Ответ: sell не убывает по j, поэтому максимум — в sell[k]
  return sell[k];
}
```

Ответ — `sell[k]`. Он не меньше любого `sell[j]` при `j < k`: недостающие сделки можно сделать пустыми.

## Трассировка

`k = 2`, `prices = [3, 2, 6, 5, 0, 3]`. Старт: `buy = [−∞, −∞, −∞]`, `sell = [0, 0, 0]`.

```
p=3: j=1: buy1=max(−∞, 0−3)=−3   sell1=max(0, −3+3)=0
     j=2: buy2=max(−∞, 0−3)=−3   sell2=max(0, 0)=0
p=2: j=1: buy1=max(−3, −2)=−2    sell1=max(0, 0)=0
     j=2: buy2=max(−3, 0−2)=−2   sell2=0
p=6: j=1: buy1=−2                sell1=max(0, −2+6)=4
     j=2: buy2=max(−2, 4−6)=−2   sell2=max(0, −2+6)=4
p=5: j=1: buy1=max(−2, −5)=−2    sell1=max(4, 3)=4
     j=2: buy2=max(−2, 4−5)=−1   sell2=max(4, −1+5)=4
p=0: j=1: buy1=max(−2, 0)=0      sell1=max(4, 0)=4
     j=2: buy2=max(−1, 4−0)=4    sell2=max(4, 4+0)=4
p=3: j=1: buy1=0                 sell1=max(4, 3)=4
     j=2: buy2=max(4, 4−3)=4     sell2=max(4, 4+3)=7
```

Ответ `sell[2] = 7`. Значение `buy2 = 4` при `p = 0` читается так: «первая сделка дала +4, и на эти деньги купили вторую акцию по 0».

Пример `k = 2`, `prices = [2, 4, 1]`:

```
p=2: buy1=−2  sell1=0  buy2=−2  sell2=0
p=4: buy1=−2  sell1=2  buy2=−2  sell2=2
p=1: buy1=−1  sell1=2  buy2=1   sell2=2
```

Ответ `2`: вторая сделка не нужна — `buy2 = 1` («купили после первой сделки по 1»), но продать её дороже уже негде.

## Почему это работает

Инвариант: после дня `t` значение `buy[j]` (`sell[j]`) — максимальный баланс среди всех планов на днях `0..t`, в которых сделано `j` покупок и сейчас акция на руках (сделано `j` продаж и акции нет). Индукция по дням: в состояние можно попасть, оставаясь в нём, или одной операцией сегодня из предыдущего состояния цепочки — это ровно два аргумента `max`. Обновление «на месте» добавляет лишь пустые операции в один день, не меняющие баланс. Значит, `sell[k]` — лучший баланс при не более чем `k` сделках.

## Пограничные случаи

- **Один день**: можно только купить и продать в тот же день — `sell[j] = max(0, −p + p) = 0`, ответ `0`.
- **Цены только падают**: `buy[j] + p` никогда не превышает `sell[j]`, ответ `0`.
- **`k = 1`**: ДП вырождается в Stock I (минимум цены и лучшая продажа).
- **`k` больше числа полезных сделок** (`k = 100`, шесть дней): лишние сделки остаются пустыми, `sell[k]` равен ответу без ограничений.
- **Нулевые цены**: обычные значения, `−0 = 0` в покупке.

## Сложность

- **Время `O(n · k)`**: для каждого из `n` дней — `k` пар `max`. При `n ≤ 1000`, `k ≤ 100` — `10⁵` операций.
- **Память `O(k)`**: два массива длины `k + 1`.

**Follow-up на собеседовании: очень большое `k`.** Прибыльная сделка занимает минимум два дня, поэтому полезных сделок не больше `⌊n / 2⌋`. Если `k >= n / 2`, ограничения фактически нет, и ответ — сумма всех подъёмов цены, как в Stock II:

```ts naive
if (k >= Math.floor(n / 2)) {
  let profit = 0;
  for (let i = 1; i < n; i++) profit += Math.max(0, prices[i] - prices[i - 1]);
  return profit;
}
```

Это `O(n)` и спасает от огромных массивов в вариантах задачи, где `k` до `10⁹`. При ограничениях этой задачи (`k ≤ 100`) шорткат не нужен.

## Типичные ошибки

1. **`buy[j] = max(buy[j], -p)`** вместо `sell[j − 1] − p` — прибыль предыдущих сделок не переносится, сделки становятся независимыми.
2. **Инициализировать `buy` нулями** — «бесплатная» акция, прибыль из воздуха.
3. **`sell[j] − p` вместо `sell[j − 1] − p`** в покупке — новая покупка не увеличивает счётчик сделок, и ограничение `k` перестаёт действовать.
4. **Цикл `j` от `0`** — `sell[−1]` равно `undefined`, и `buy[0]` превращается в `NaN`.
5. **Возвращать `max(...sell)`** — не ошибка, но лишний проход: `sell[k]` уже максимален.

## Как узнать такую задачу

- Цены/события по дням и ограничение «**не более `k` раз**» что-то сделать → состояние ДП «номер операции», переход по дням.
- Если `k` больше, чем вообще возможно полезных операций, ограничение снимается — это повод для жадного шортката (follow-up).
- Описание через этапы «купил/продал/держу» → ДП-автомат.
