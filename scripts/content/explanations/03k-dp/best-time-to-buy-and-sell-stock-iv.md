## Задача простыми словами

Дан массив цен акции по дням `prices` и число `k`. Можно совершить **не более `k` сделок** (купить → продать), держа одновременно не больше одной акции. Нужно вернуть максимальную прибыль.

Пример: `k = 2`, `prices = [3, 2, 6, 5, 0, 3]`. Покупаем по `2`, продаём по `6` (+4), покупаем по `0`, продаём по `3` (+3) — итого `7`. При `k = 1` ответ был бы `4`.

## Наивный подход

Рекурсия по дням с состоянием «сколько сделок осталось» и «держим ли акцию»:

```ts naive
function best(day: number, left: number, holding: boolean): number {
  if (day === n || left === 0) return 0;
  const skip = best(day + 1, left, holding);
  const act = holding
    ? prices[day] + best(day + 1, left - 1, false) // продаём, сделка закрыта
    : -prices[day] + best(day + 1, left, true);    // покупаем
  return Math.max(skip, act);
}
```

Без кеша каждый день ветвится на два — `O(2ⁿ)`. Лишняя работа видна в сигнатуре: всё, что важно, — тройка `(day, left, holding)`, а таких троек всего `n · (k + 1) · 2`. Рекурсия же посещает одну и ту же тройку экспоненциально много раз. С мемоизацией это уже `O(n · k)` — и решение в коде делает то же самое, но снизу вверх, без рекурсии и с `O(k)` памяти.

## Ключевое наблюдение

Это прямое обобщение Stock III. Там было четыре состояния `buy1 → sell1 → buy2 → sell2`; здесь для каждой сделки `j = 1..k` два состояния:

- `buy[j]` — лучший баланс, когда держим акцию, купленную в `j`-й сделке;
- `sell[j]` — лучший баланс после завершения `j` сделок.

Цепочка `sell[0] → buy[1] → sell[1] → buy[2] → … → sell[k]` обновляется за `O(k)` на каждый день.

Второе наблюдение: прибыльная сделка занимает минимум два дня, поэтому полезных сделок не больше `⌊n / 2⌋`. Если `k` не меньше этого, ограничение фактически отсутствует, и задача сводится к Stock II — **взять каждый рост цены** за `O(n)`.

## Техники

### ДП «день × номер сделки» (автомат состояний)

**Что это.** Состояние — это этап процесса (сколько сделок завершено, держим ли акцию), а значение — лучший баланс, с которым можно на этом этапе оказаться к текущему дню. Каждый день каждое состояние либо остаётся как есть, либо получается из предыдущего этапа одной операцией. Измерение «день» сжато: храним только текущие значения, массивы длины `k + 1`.

```
sell[0]=0 ──−p──▶ buy[1] ──+p──▶ sell[1] ──−p──▶ buy[2] ──+p──▶ sell[2] … sell[k]
```

**Как применяется здесь.** Покупка `j`-й сделки делается на баланс после `j − 1` сделок (`sell[j − 1] − p`), продажа закрывает её (`buy[j] + p`). Подробнее о многомерном ДП — во вкладке «Теория».

### Жадность для неограниченного числа сделок (Stock II)

Если сделок сколько угодно, оптимум — сумма всех положительных разностей соседних дней. Любой подъём `a → b` длиной в несколько дней раскладывается на дневные подъёмы, а дневные падения мы пропускаем. Это и есть шорткат при большом `k`.

## Разбор кода

```ts
function maxProfit(k: number, prices: number[]): number {
  const n = prices.length;

  // Если k >= n / 2, ограничение на число сделок не мешает:
  // берём каждый рост цены (как в Stock II)
  if (k >= Math.floor(n / 2)) {
    let profit = 0;
    for (let i = 1; i < n; i++) {
      profit += Math.max(0, prices[i] - prices[i - 1]);
    }
    return profit;
  }
```

Шорткат. Жадная сумма подъёмов использует не больше `⌊n / 2⌋` сделок: непрерывные подъёмы склеиваются в одну сделку, а разные сделки разделены хотя бы одним днём падения или плато. Значит, если `k` достаточно велико, ответ без ограничений и есть ответ задачи. Помимо скорости, ветка спасает от огромных массивов в версиях задачи, где `k` может быть до `10⁹`.

```ts
  // buy[j]  — лучший баланс, если держим акцию в j-й сделке
  // sell[j] — лучший баланс после завершения j сделок
  const buy: number[] = new Array(k + 1).fill(-Infinity);
  const sell: number[] = new Array(k + 1).fill(0);
```

Массивы длины `k + 1`; индекс `0` используется только у `sell` — `sell[0] = 0`, «ни одной сделки, баланс ноль», база для первой покупки. `buy` заполнен `-Infinity`: до первого дня держать акцию невозможно. `sell[j] = 0` для всех `j` — «сделки были пустыми», баланс не изменился.

```ts
  for (const p of prices) {
    for (let j = 1; j <= k; j++) {
      // j-я покупка делается на деньги после j - 1 завершённых сделок
      buy[j] = Math.max(buy[j], sell[j - 1] - p);
      // j-я продажа закрывает j-ю покупку
      sell[j] = Math.max(sell[j], buy[j] + p);
    }
  }
```

Для каждого дня проходим сделки по возрастанию `j`. `buy[j]` — либо уже держим акцию `j`-й сделки, либо покупаем сегодня на баланс после `j − 1` сделок. `sell[j]` — либо `j` сделок уже завершены, либо продаём сегодня акцию `j`-й сделки.

Как и в Stock III, обновление «на месте» безопасно: `sell[j − 1]` может оказаться уже сегодняшним (продали сегодня), а `buy[j]` — сегодняшним (купили сегодня). Это означает «продать и купить в тот же день» или «купить и продать в тот же день» — операции с нулевым эффектом на баланс, которые не создают лишней прибыли.

```ts
  // sell не убывает по j, поэтому максимум — в sell[k]
  return sell[k];
}
```

Ответ — `sell[k]`. Он не меньше любого `sell[j]` при `j < k`: недостающие сделки можно сделать пустыми.

## Трассировка

`k = 2`, `prices = [3, 2, 6, 5, 0, 3]`. `n = 6`, `⌊6 / 2⌋ = 3`, `k = 2 < 3` — идём в ДП. Старт: `buy = [−∞, −∞, −∞]`, `sell = [0, 0, 0]`.

```
p=3: j=1: buy1=max(−∞, 0−3)=−3   sell1=max(0, −3+3)=0
     j=2: buy2=max(−∞, 0−3)=−3   sell2=max(0, 0)=0
p=2: j=1: buy1=max(−3, −2)=−2    sell1=max(0, 0)=0
     j=2: buy2=max(−3, 0−2)=−2   sell2=0
p=6: j=1: buy1=−2                sell1=max(0, −2+6)=4
     j=2: buy2=max(−2, 4−6)=−2   sell2=max(0, −2+6)=4
p=5: j=1: buy1=max(−2, −5)=−2    sell1=max(4, 3)=4
     j=2: buy2=max(−2, 4−5)=−1   sell2=max(4, −1+5)=4
p=0: j=1: buy1=max(−2, 0)=0      sell1=max(4, 0)=4
     j=2: buy2=max(−1, 4−0)=4    sell2=max(4, 4+0)=4
p=3: j=1: buy1=0                 sell1=max(4, 3)=4
     j=2: buy2=max(4, 4−3)=4     sell2=max(4, 4+3)=7
```

Ответ `sell[2] = 7`. Значение `buy2 = 4` при `p = 0` читается так: «первая сделка дала +4, и на эти деньги купили вторую акцию по 0».

Шорткат, `k = 2`, `prices = [2, 4, 1]`: `⌊3 / 2⌋ = 1`, `k >= 1` — суммируем подъёмы: `max(0, 4 − 2) + max(0, 1 − 4) = 2`. Ответ `2`.

## Почему это работает

**ДП-часть.** Инвариант: после дня `t` значение `buy[j]` (`sell[j]`) — максимальный баланс среди всех планов на днях `0..t`, в которых сделано `j` покупок и сейчас акция на руках (сделано `j` продаж и акции нет). Индукция по дням: в состояние можно попасть, оставаясь в нём, или одной операцией сегодня из предыдущего состояния цепочки — это ровно два аргумента `max`. Обновление «на месте» добавляет лишь пустые операции в один день, не меняющие баланс. Значит, `sell[k]` — лучший баланс при не более чем `k` сделках.

**Шорткат.** Сумма положительных дневных разностей — верхняя граница для любого числа сделок (прибыль любой сделки не больше суммы подъёмов внутри неё, а сделки не пересекаются). Эта граница достигается не более чем `⌊n / 2⌋` сделками, поэтому при `k >= ⌊n / 2⌋` она и есть ответ.

## Пограничные случаи

- **Один день**: `⌊1 / 2⌋ = 0`, `k >= 0` — шорткат, цикл пуст, ответ `0`.
- **Цены только падают**: все разности отрицательны (или `sell` не растёт) — `0`.
- **`k = 1`**: ДП вырождается в Stock I (минимум цены и лучшая продажа).
- **Большое `k`**: шорткат за `O(n)`, массивы не создаются.
- **Нулевые цены**: обычные значения, `−0 = 0` в покупке.

## Сложность

- **Время `O(n · k)`** в ДП-ветке: для каждого из `n` дней — `k` пар `max`. Благодаря шорткату `k < n / 2`, так что в худшем случае `O(n²)`. В ветке шортката — `O(n)`.
- **Память `O(k)`**: два массива длины `k + 1`. Шорткат — `O(1)`.

## Типичные ошибки

1. **Нет шортката для большого `k`** — лишнее время и память (в вариантах с огромным `k` — падение по памяти).
2. **`buy[j] = max(buy[j], -p)`** вместо `sell[j − 1] − p` — прибыль предыдущих сделок не переносится, сделки становятся независимыми.
3. **Инициализировать `buy` нулями** — «бесплатная» акция, прибыль из воздуха.
4. **`sell[j] − p` вместо `sell[j − 1] − p`** в покупке — новая покупка не увеличивает счётчик сделок, и ограничение `k` перестаёт действовать.
5. **Возвращать `max(...sell)`** — не ошибка, но лишний проход: `sell[k]` уже максимален.

## Как узнать такую задачу

- Цены/события по дням и ограничение «**не более `k` раз**» что-то сделать → состояние ДП «номер операции», переход по дням.
- Если `k` больше, чем вообще возможно полезных операций, ограничение снимается — ищите жадное решение для этого случая.
- Описание через этапы «купил/продал/держу» → ДП-автомат.
