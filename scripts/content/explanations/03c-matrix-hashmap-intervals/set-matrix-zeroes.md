## Задача простыми словами

Дана матрица `m x n`. Для каждого **исходного** нуля нужно обнулить всю его строку и весь его столбец. Менять нужно саму матрицу, возвращать ничего не надо.

Пример:

```
1 1 1        1 0 1
1 0 1   →    0 0 0
1 1 1        1 0 1
```

Ноль в центре обнулил среднюю строку и средний столбец.

## Наивный подход

Первая мысль — обнулять «на лету»: встретили ноль — сразу зануляем строку и столбец.

```ts naive
for (let r = 0; r < m; r++)
  for (let c = 0; c < n; c++)
    if (matrix[r][c] === 0) {
      for (let j = 0; j < n; j++) matrix[r][j] = 0;
      for (let i = 0; i < m; i++) matrix[i][c] = 0;
    }
```

Это **неверно**: новые нули неотличимы от исходных. Когда обход дойдёт до только что записанного нуля, он обнулит и его строку со столбцом. В примере выше после центрального нуля появятся нули в `(1, 2)`, `(2, 1)`, и в итоге «зальётся» вся матрица.

Другой вариант — сделать полную копию матрицы и искать нули в ней. Это работает, но тратит `O(m · n)` памяти, хотя на самом деле нам нужно гораздо меньше информации.

## Ключевое наблюдение

Для ответа важно не **где именно** стоят нули, а только **в каких строках и в каких столбцах** они есть. Клетка `(r, c)` в итоге станет нулём тогда и только тогда, когда в строке `r` или в столбце `c` был исходный ноль.

Значит, достаточно запомнить два набора номеров — строки с нулями и столбцы с нулями — а потом одним проходом применить решение. Это `O(m + n)` памяти вместо `O(m · n)` у копии.

## Техники

### Двухпроходная схема «пометить, затем применить»

**Что это.** Когда изменение данных влияет на последующие решения (новый ноль выглядит как исходный), обработку делят на два прохода: первый только **собирает информацию** по исходному состоянию и ничего не меняет, второй **применяет** изменения, уже ничего не ища. Тот же приём лежит в основе Game of Life.

**Как применяется здесь.** Первый проход складывает номера строк и столбцов с нулями в множества, второй обнуляет клетки по этим множествам.

### Множество (`Set`) как набор флагов

**Что это.** `Set` хранит уникальные значения и отвечает на вопрос «есть ли элемент» за `O(1)` в среднем. Повторное `add` того же числа ничего не меняет, поэтому несколько нулей в одной строке не создают дублей. Вместо `Set` подошли бы два булевых массива длины `m` и `n` — это тот же приём. Подробнее о приёмах работы с матрицами — во вкладке «Теория».

## Разбор кода

```ts
function setZeroes(matrix: number[][]): void {
  const m = matrix.length;
  const n = matrix[0].length;
```

Размеры матрицы. Функция ничего не возвращает — меняет `matrix` на месте.

```ts
  // 1. Запоминаем, в каких строках и столбцах есть ИСХОДНЫЕ нули.
  //    Матрицу пока не трогаем, иначе новые нули примем за исходные
  const zeroRows = new Set<number>();
  const zeroCols = new Set<number>();
```

Два пустых множества: в `zeroRows` попадут номера строк, которые надо обнулить, в `zeroCols` — номера столбцов.

```ts
  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      if (matrix[r][c] === 0) {
        zeroRows.add(r);
        zeroCols.add(c);
      }
    }
  }
```

Первый проход по всем клеткам. Встретили ноль в `(r, c)` — запоминаем его строку и столбец. Матрица в этом цикле только **читается**, поэтому каждый найденный ноль гарантированно исходный.

```ts
  // 2. Обнуляем клетку, если её строка или столбец помечены
  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      if (zeroRows.has(r) || zeroCols.has(c)) {
        matrix[r][c] = 0;
      }
    }
  }
}
```

Второй проход: для каждой клетки спрашиваем множества. Если её строка **или** столбец помечены — записываем ноль. Здесь мы уже не смотрим на значения матрицы, поэтому новые нули ни на что не влияют.

## Трассировка

Пример 1: `[[1,1,1],[1,0,1],[1,1,1]]`, `m = n = 3`.

1. Первый проход: единственный ноль в `(1, 1)` → `zeroRows = {1}`, `zeroCols = {1}`.
2. Второй проход:
   - строка 0: `(0,0)` — ни строка 0, ни столбец 0 не помечены → `1`; `(0,1)` — столбец 1 помечен → `0`; `(0,2)` → `1`.
   - строка 1 помечена → все три клетки `0`.
   - строка 2: `(2,0)` → `1`; `(2,1)` — столбец 1 → `0`; `(2,2)` → `1`.

```
1 0 1
0 0 0
1 0 1
```

Ответ совпадает с примером.

Пример 2: `[[0,1,2,0],[3,4,5,2],[1,3,1,5]]`.

1. Первый проход: нули в `(0, 0)` и `(0, 3)` → `zeroRows = {0}`, `zeroCols = {0, 3}`.
2. Второй проход: строка 0 обнуляется целиком; в строках 1 и 2 обнуляются столбцы 0 и 3:

```
0 0 0 0
0 4 5 0
0 3 1 0
```

## Почему это работает

После первого прохода `zeroRows` содержит ровно те строки, где был хотя бы один исходный ноль, а `zeroCols` — ровно те столбцы: матрица в этом проходе не менялась, значит, все увиденные нули — исходные, и ни один исходный ноль не пропущен (обошли все клетки).

По условию клетка `(r, c)` должна стать нулём ⇔ в строке `r` или в столбце `c` есть исходный ноль ⇔ `zeroRows.has(r) || zeroCols.has(c)`. Второй проход проверяет ровно это условие для каждой клетки и не читает значения матрицы, поэтому его собственные записи не искажают результат. Клетки, не попавшие под условие, не трогаются.

## Пограничные случаи

- **Ноль в `(0, 0)`**: обнуляются первая строка и первый столбец — для множеств это обычная клетка, никакой особой обработки.
- **Несколько нулей в одной строке**: `Set` хранит номер строки один раз.
- **Одна строка или один столбец** (`m = 1` или `n = 1`): работает так же; например, `[[1,0,3]]` → `[[0,0,0]]`.
- **Нулей нет**: множества пусты, матрица не меняется.
- **Вся матрица из нулей**: всё и останется нулями.

## Сложность

- **Время `O(m · n)`**: два прохода по всем клеткам, операции `add`/`has` — `O(1)`.
- **Память `O(m + n)`**: в множествах не больше `m` номеров строк и `n` номеров столбцов.

**Follow-up на собеседовании: память `O(1)`.** Условие спрашивает и о константной памяти. Флаги можно хранить в самой матрице: первая строка служит флагами столбцов, первый столбец — флагами строк. Их собственные исходные нули заранее запоминают в двух булевых переменных, а саму первую строку и первый столбец обнуляют последними:

```ts naive
const firstRowZero = matrix[0].some((v) => v === 0);
const firstColZero = matrix.some((row) => row[0] === 0);
for (let r = 1; r < m; r++)
  for (let c = 1; c < n; c++)
    if (matrix[r][c] === 0) { matrix[r][0] = 0; matrix[0][c] = 0; }
for (let r = 1; r < m; r++)
  for (let c = 1; c < n; c++)
    if (matrix[r][0] === 0 || matrix[0][c] === 0) matrix[r][c] = 0;
if (firstRowZero) for (let c = 0; c < n; c++) matrix[0][c] = 0;
if (firstColZero) for (let r = 0; r < m; r++) matrix[r][0] = 0;
```

Идея та же — «пометить, затем применить», меняется только место хранения флагов. Основное решение с множествами стоит рассказать первым, а этот вариант — как улучшение.

## Типичные ошибки

1. **Обнулять сразу при встрече нуля** → новые нули порождают новые обнуления, матрица «заливается» нулями.
2. **Менять матрицу в первом проходе** → второй проход (или сам первый) уже не отличает исходные нули от записанных.
3. **Одно общее множество для строк и столбцов** → номер строки `2` и номер столбца `2` смешиваются, обнуляется лишнее.
4. **Условие `&&` вместо `||`** во втором проходе → обнуляются только пересечения помеченных строк и столбцов.
5. **Маркер вроде `-1` или `Infinity`** вместо множеств → значение может совпасть с реальным: числа занимают весь диапазон `int32`.

## Как узнать такую задачу

- Изменение одной клетки **влияет на решения** о других клетках, а обновлять нужно «по исходному состоянию» → два прохода: пометить, затем применить.
- Ответ зависит только от свойства **строки или столбца** целиком → храним флаги на строку и на столбец, а не на клетку.
- Просят память `O(1)` → те же флаги переносим в первую строку и первый столбец.
- Родственные задачи: Game of Life (считать по старому состоянию), Valid Sudoku (множества на строки/столбцы/блоки), First Missing Positive (массив как хранилище флагов).
