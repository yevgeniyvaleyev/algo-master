## Задача простыми словами

Дана матрица `m x n`. Для каждого **исходного** нуля нужно обнулить всю его строку и весь его столбец. Менять нужно саму матрицу; в идеале — с дополнительной памятью `O(1)`.

Пример:

```
1 1 1        1 0 1
1 0 1   →    0 0 0
1 1 1        1 0 1
```

Ноль в центре обнулил среднюю строку и средний столбец.

## Наивный подход

Первая мысль — обнулять «на лету»: встретили ноль — сразу зануляем строку и столбец. Это **неверно**: новые нули неотличимы от исходных, и при дальнейшем обходе они обнулят свои строки и столбцы. В примере выше так обнулится вся матрица.

Правильная простая версия — сначала **запомнить**, какие строки и столбцы обнулить, а потом применить:

```ts naive
const zeroRow = new Array(m).fill(false);
const zeroCol = new Array(n).fill(false);
for (let r = 0; r < m; r++)
  for (let c = 0; c < n; c++)
    if (matrix[r][c] === 0) { zeroRow[r] = true; zeroCol[c] = true; }
for (let r = 0; r < m; r++)
  for (let c = 0; c < n; c++)
    if (zeroRow[r] || zeroCol[c]) matrix[r][c] = 0;
```

Время `O(m · n)`, память `O(m + n)`. Лишнее — два внешних массива флагов. Условие прямо просит обойтись константной памятью. Пометить клетку «особым значением» тоже нельзя: значения занимают весь диапазон `int32`, свободного маркера нет.

## Ключевое наблюдение

Флаги можно хранить **в самой матрице**. Если строку `r` надо обнулить, её первая клетка `matrix[r][0]` всё равно станет нулём — значит, можно записать туда ноль заранее и использовать как флаг. То же для столбца `c` и клетки `matrix[0][c]`. Первая строка играет роль `zeroCol`, первый столбец — `zeroRow`.

Остаётся конфликт: первая строка и первый столбец сами могут содержать исходные нули, и флаги их перезапишут. Поэтому **до** расстановки флагов запоминаем в двух булевых переменных, нужно ли обнулять их самих, и обрабатываем их **в самом конце**.

## Техники

### Двухпроходная схема «пометить, затем применить»

**Что это.** Когда изменение данных влияет на последующие решения (новый ноль выглядит как исходный), обработку делят на два прохода: первый только **собирает информацию** по исходному состоянию, второй **применяет** изменения. Тот же приём лежит в основе Game of Life.

**Как применяется здесь.** Шаг 1 расставляет флаги, шаг 2 обнуляет внутреннюю часть по флагам, шаг 3 — первую строку и столбец.

### Матрица как собственное хранилище флагов

**Что это.** Трюк для памяти `O(1)`: служебную информацию кладут в ту часть входных данных, которая либо ещё не нужна, либо будет перезаписана предсказуемым образом. Здесь первая строка и первый столбец становятся массивами флагов, а их собственное состояние сохраняется в двух переменных. Подробнее о приёмах «на месте» в матрицах — во вкладке «Теория».

## Разбор кода

```ts
function setZeroes(matrix: number[][]): void {
  const m = matrix.length;
  const n = matrix[0].length;
```

Размеры матрицы. Функция ничего не возвращает — меняет `matrix` на месте.

```ts
  // Первая строка и первый столбец станут флагами для остальных строк/столбцов.
  // Но их собственные нули нужно запомнить отдельно, иначе флаги их затрут
  const firstRowZero = matrix[0].some((v) => v === 0);
  let firstColZero = false;
  for (let r = 0; r < m; r++) {
    if (matrix[r][0] === 0) firstColZero = true;
  }
```

Пока флаги не записаны, смотрим на **исходное** состояние первой строки и первого столбца. `some` возвращает `true`, если в строке 0 есть хотя бы один ноль; цикл делает то же для столбца 0. Клетка `(0, 0)` учитывается в обеих проверках — если она ноль, обнулятся и строка 0, и столбец 0, как и должно быть.

```ts
  // 1. Помечаем: ноль в (r, c) → обнулить строку r и столбец c
  for (let r = 1; r < m; r++) {
    for (let c = 1; c < n; c++) {
      if (matrix[r][c] === 0) {
        matrix[r][0] = 0; // флаг строки
        matrix[0][c] = 0; // флаг столбца
      }
    }
  }
```

Обходим только **внутреннюю** часть (`r >= 1`, `c >= 1`). Для каждого нуля ставим флаг строки в её первую клетку и флаг столбца — в первую клетку столбца. Обратите внимание: исходные нули в первой строке/столбце **уже** работают как флаги (ноль в `matrix[0][c]` честно означает «обнулить столбец `c`»), поэтому их отдельно размечать не нужно.

```ts
  // 2. Обнуляем внутреннюю часть по флагам (флаги пока не трогаем)
  for (let r = 1; r < m; r++) {
    for (let c = 1; c < n; c++) {
      if (matrix[r][0] === 0 || matrix[0][c] === 0) {
        matrix[r][c] = 0;
      }
    }
  }
```

Снова только внутренняя часть: клетка обнуляется, если стоит флаг её строки **или** столбца. Сами флаги (строка 0 и столбец 0) здесь не меняются — они ещё читаются для следующих клеток. Новые нули во внутренней части флагов не ставят, потому что расстановка закончилась на шаге 1.

```ts
  // 3. В самом конце обрабатываем первую строку и первый столбец
  if (firstRowZero) {
    for (let c = 0; c < n; c++) matrix[0][c] = 0;
  }
  if (firstColZero) {
    for (let r = 0; r < m; r++) matrix[r][0] = 0;
  }
}
```

Флаги больше не нужны — теперь можно обнулить первую строку и первый столбец, если в них **исходно** был ноль. Делаем это последним шагом: если бы обнулили строку 0 раньше шага 2, все её клетки стали бы флагами «обнулить столбец», и обнулилась бы вся матрица.

## Трассировка

Пример 1: `[[1,1,1],[1,0,1],[1,1,1]]`, `m = n = 3`.

1. `firstRowZero = false` (в `[1,1,1]` нулей нет), `firstColZero = false` (столбец `1,1,1`).
2. Шаг 1: единственный внутренний ноль `(1, 1)` → `matrix[1][0] = 0`, `matrix[0][1] = 0`.

```
1 0 1
0 0 1
1 1 1
```

3. Шаг 2:
   - `(1, 1)`: флаг строки `matrix[1][0] = 0` → `0` (уже был).
   - `(1, 2)`: флаг строки → `0`.
   - `(2, 1)`: флаг столбца `matrix[0][1] = 0` → `0`.
   - `(2, 2)`: `matrix[2][0] = 1`, `matrix[0][2] = 1` → остаётся `1`.

```
1 0 1
0 0 0
1 0 1
```

4. Шаг 3: оба флага `false`, ничего не делаем. Ответ совпадает с примером.

Пример 2: `[[0,1,2,0],[3,4,5,2],[1,3,1,5]]`. `firstRowZero = true`, `firstColZero = true` (из-за `(0, 0)`). На шаге 1 внутренних нулей нет. На шаге 2 исходный ноль `matrix[0][3]` работает как флаг столбца 3: `(1, 3)` и `(2, 3)` становятся нулями. Шаг 3 обнуляет строку 0 и столбец 0:

```
0 0 0 0
0 4 5 0
0 3 1 0
```

## Почему это работает

После шага 1 для каждой строки `r >= 1` верно: `matrix[r][0] === 0` ⇔ в строке `r` был исходный ноль (внутри — его пометил шаг 1, в столбце 0 — он и есть этот ноль). Аналогично для столбцов `c >= 1` и `matrix[0][c]`. Шаг 2 только читает флаги и пишет во внутреннюю часть, поэтому флаги остаются верными до конца шага 2, и каждая внутренняя клетка обнуляется ровно тогда, когда её строка или столбец содержали исходный ноль.

Для первой строки и первого столбца правильный ответ определяется `firstRowZero` / `firstColZero` (вычислены до порчи) — и флагами для их клеток: клетка `(0, c)` при `c >= 1` уже ноль, если столбец `c` надо обнулить, а `(r, 0)` — если строку `r`. Шаг 3 добавляет недостающее.

## Пограничные случаи

- **Ноль в `(0, 0)`**: оба флага `true`, обнуляются первая строка и первый столбец.
- **Нули только в первой строке/столбце**: внутренняя часть обнуляется по ним как по флагам, а сами они — на шаге 3.
- **Одна строка или один столбец** (`m = 1` или `n = 1`): шаги 1 и 2 не выполняются, всё делает шаг 3.
- **Нулей нет**: ничего не меняется.
- **Вся матрица из нулей**: всё и останется нулями.

## Сложность

- **Время `O(m · n)`**: подготовка `O(m + n)`, шаги 1 и 2 — по одному проходу внутренней части, шаг 3 — `O(m + n)`.
- **Память `O(1)`**: две булевы переменные, флаги — в самой матрице.

## Типичные ошибки

1. **Обнулять сразу при встрече нуля** → новые нули порождают новые обнуления, матрица «заливается» нулями.
2. **Не сохранить `firstRowZero` / `firstColZero` заранее** → после шага 1 уже нельзя отличить исходный ноль от флага.
3. **Обнулить первую строку или столбец до шага 2** → все клетки строки 0 становятся флагами, обнуляется лишнее.
4. **Шаги 1–2 от индекса 0** → флаги перезаписывают сами себя, и логика ломается.
5. **Маркер вроде `-1` или `Infinity`** вместо флагов → значение может совпасть с реальным, а `Infinity` в целочисленной матрице — грязный приём.

## Как узнать такую задачу

- Изменение одной клетки **влияет на решения** о других клетках, а обновлять нужно «по исходному состоянию» → два прохода: пометить, затем применить.
- Требуют **память `O(1)`** при наличии естественных флагов на строку/столбец → храним флаги в первой строке/столбце.
- Родственные задачи: Game of Life (два поколения в одной клетке), First Missing Positive (массив как хеш-таблица), Find All Duplicates in an Array (пометка знаком).
