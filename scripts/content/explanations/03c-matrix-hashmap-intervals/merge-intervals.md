## Задача простыми словами

Дан массив отрезков `[start, end]`. Нужно склеить все пересекающиеся отрезки и вернуть набор **непересекающихся** отрезков, покрывающих то же множество точек. Касающиеся отрезки (`[1,4]` и `[4,5]`) тоже считаются пересекающимися.

Пример: `[[1,3],[2,6],[8,10],[15,18]]` → `[[1,6],[8,10],[15,18]]`. Отрезки `[1,3]` и `[2,6]` перекрываются и сливаются в `[1,6]`.

## Наивный подход

Можно повторять «найти любую пересекающуюся пару и слить её», пока такие пары есть:

```ts naive
let changed = true;
while (changed) {
  changed = false;
  for (let i = 0; i < list.length && !changed; i++)
    for (let j = i + 1; j < list.length && !changed; j++)
      if (overlap(list[i], list[j])) {
        list[i] = [Math.min(list[i][0], list[j][0]), Math.max(list[i][1], list[j][1])];
        list.splice(j, 1);
        changed = true;
      }
}
```

Каждое слияние требует нового перебора пар — `O(n²)` на поиск, до `n` слияний: `O(n³)` в худшем случае. Лишняя работа — мы проверяем **все пары**, хотя большинство отрезков очевидно далеко друг от друга. Без порядка нельзя сказать, с кем отрезок может пересечься, поэтому приходится проверять всех.

## Ключевое наблюдение

Если **отсортировать отрезки по началу**, то отрезки, которые нужно склеить, окажутся **подряд**. Достаточно одного прохода слева направо с «текущим» отрезком-накопителем: следующий отрезок либо пересекается с ним (тогда расширяем накопитель), либо начинается правее его конца — и тогда **никакой** следующий отрезок уже не дотянется до накопителя, ведь их начала ещё правее.

## Техники

### Сортировка по началу + линейный проход

**Что это.** Базовый шаблон почти всех задач на интервалы. После сортировки по `start` для двух отрезков `[a, b]` и `[c, d]` с `a <= c` пересечение проверяется одним сравнением `c <= b`, а объединение — `[a, max(b, d)]`.

**Когда применять.** Слияние, вставка, поиск пересечений, подсчёт перекрытий, свободные окна в расписании. Признак — нужно рассуждать о том, какие отрезки перекрываются.

**Как применяется здесь.** Сортируем, затем держим в `result` уже слитые отрезки и сравниваем каждый новый только с **последним** из них. Подробнее о шаблонах для интервалов — во вкладке «Теория».

### Расширение «последнего» элемента результата

Вместо отдельных переменных `curStart`/`curEnd` накопителем служит последний элемент `result`: его конец меняется на месте. Это убирает отдельный шаг «не забыть добавить последний накопленный отрезок после цикла» — частый источник ошибок.

## Разбор кода

```ts
function merge(intervals: number[][]): number[][] {
  // Сортируем по началу: тогда пересекаться могут только соседние интервалы
  intervals.sort((a, b) => a[0] - b[0]);
```

Сортируем по левой границе. Компаратор `a[0] - b[0]` обязателен: `sort()` без него сравнивает элементы как строки. Заметьте, что сортировка меняет входной массив — для этой задачи это допустимо.

```ts
  const result: number[][] = [];
  for (const [start, end] of intervals) {
    const last = result[result.length - 1];
```

Идём по отрезкам в порядке начала, деструктурируя каждый в `start` и `end`. `last` — последний уже слитый отрезок; для первого отрезка `result` пуст, и `last === undefined`.

```ts
    if (last && start <= last[1]) {
      // Начинается не позже конца последнего — сливаем, расширяя конец.
      // max нужен, если текущий интервал целиком внутри последнего
      last[1] = Math.max(last[1], end);
```

Пересечение: текущий отрезок начинается **не позже** конца последнего (`<=` — чтобы касающиеся `[1,4]` и `[4,5]` склеились). Начало менять не нужно: из-за сортировки `last[0] <= start`. А конец — максимум из двух: если текущий отрезок лежит **внутри** последнего (`[1,10]` и `[2,3]`), конец не должен уменьшиться. `last` — ссылка на массив внутри `result`, поэтому изменение сразу видно в ответе.

```ts
    } else {
      // Разрыв — начинаем новый интервал
      result.push([start, end]);
    }
  }

  return result;
}
```

Разрыв (или первый отрезок) — добавляем новый отрезок. Именно **новый массив** `[start, end]`, а не исходный: дальше мы будем менять его конец, и так входные данные не портятся. После прохода `result` содержит ответ.

## Трассировка

`intervals = [[1,3],[2,6],[8,10],[15,18]]` — уже отсортирован.

1. `[1,3]`: `last` нет → `result = [[1,3]]`.
2. `[2,6]`: `last = [1,3]`, `2 <= 3` → `last[1] = max(3, 6) = 6` → `result = [[1,6]]`.
3. `[8,10]`: `last = [1,6]`, `8 <= 6` — нет → `result = [[1,6],[8,10]]`.
4. `[15,18]`: `last = [8,10]`, `15 <= 10` — нет → `result = [[1,6],[8,10],[15,18]]`.

Пример 3, `intervals = [[4,7],[1,4]]`. После сортировки `[[1,4],[4,7]]`.

1. `[1,4]` → `result = [[1,4]]`.
2. `[4,7]`: `4 <= 4` — касание считается пересечением → `last[1] = max(4, 7) = 7` → `[[1,7]]`.

Вложенный отрезок, `[[1,10],[2,3],[4,12]]`:

1. `[1,10]` → `[[1,10]]`.
2. `[2,3]`: `2 <= 10` → `last[1] = max(10, 3) = 10` — конец не уменьшился.
3. `[4,12]`: `4 <= 10` → `last[1] = max(10, 12) = 12` → `[[1,12]]`.

## Почему это работает

Инвариант: после обработки первых `k` отрезков (в порядке сортировки) `result` — правильное слияние этих `k` отрезков, причём отрезки в `result` упорядочены и не пересекаются.

Новый отрезок `[start, end]` имеет `start >= ` всех предыдущих начал. Он может пересечься только с последним отрезком `result`: все остальные кончаются раньше, чем начинается последний (между ними был разрыв), а значит, раньше `start`. Если `start <= last[1]` — отрезки пересекаются, и их объединение — `[last[0], max(last[1], end)]`. Иначе между `last[1]` и `start` есть дыра, и ни один будущий отрезок (его начало `>= start`) её не закроет — `last` окончателен, начинаем новый.

## Пограничные случаи

- **Один отрезок**: возвращается как есть (копией).
- **Вложенные отрезки** (`[1,10]` и `[2,3]`): спасает `Math.max`.
- **Касание** (`[1,4]` и `[4,5]`): сливаются благодаря `<=`.
- **Неотсортированный вход** (пример 3): сортировка обязательна.
- **Одинаковые отрезки** и **точки** (`[5,5]`): обрабатываются общей логикой.
- **Все отрезки пересекаются**: в ответе один отрезок.

## Сложность

- **Время `O(n log n)`**: сортировка; дальнейший проход линейный, каждый отрезок — `O(1)`.
- **Память `O(n)`**: ответ (до `n` отрезков); сама сортировка в движке JS требует ещё до `O(n)` вспомогательной памяти.

## Типичные ошибки

1. **Забыть отсортировать** → пересекающиеся отрезки могут оказаться не рядом (пример 3).
2. **`last[1] = end` вместо `Math.max`** → вложенный отрезок «укорачивает» объединение.
3. **`<` вместо `<=`** → касающиеся отрезки не склеиваются.
4. **`sort()` без компаратора** → строковая сортировка: `[10, …]` окажется раньше `[9, …]`.
5. **Хранить накопитель в переменных и забыть добавить его после цикла** → теряется последний отрезок.

## Как узнать такую задачу

- Вход — набор отрезков, вопрос о **перекрытиях**: склеить, посчитать, найти покрытие.
- Слова «overlapping», «merge», «union of intervals» → сортировка по началу и один проход.
- Родственные задачи: Insert Interval, Non-overlapping Intervals, Meeting Rooms I/II, Minimum Number of Arrows to Burst Balloons, Interval List Intersections, Summary Ranges.
