## Задача простыми словами

Дан **неотсортированный** массив целых чисел `nums`. Нужно найти длину самой длинной цепочки чисел, идущих подряд (`x, x+1, x+2, …`), если брать числа из массива в любом порядке. Обязательное требование — время `O(n)`.

Пример: `[100, 4, 200, 1, 3, 2]` → цепочка `1, 2, 3, 4`, ответ `4`. Дубликаты не удлиняют цепочку: `[1, 0, 1, 2]` → `0, 1, 2`, ответ `3`.

## Наивный подход

Очевидное решение — отсортировать и пройти один раз, считая длину текущей серии:

```ts naive
const a = [...nums].sort((x, y) => x - y);
let best = 0, cur = 0;
for (let i = 0; i < a.length; i++) {
  if (i > 0 && a[i] === a[i - 1]) continue;       // дубликат
  cur = i > 0 && a[i] === a[i - 1] + 1 ? cur + 1 : 1;
  best = Math.max(best, cur);
}
```

Это `O(n log n)` из-за сортировки — нарушает требование. Сортировка упорядочивает **все** числа, хотя нам нужно знать только одно: «есть ли в массиве число `x + 1`?».

Другая попытка — для **каждого** числа шагать вверх, проверяя `x + 1`, `x + 2`, … в множестве. Каждая проверка `O(1)`, но на массиве `[1, 2, …, n]` от `1` пройдём `n` шагов, от `2` — `n - 1`, и так далее: `O(n²)`. Лишняя работа — одну и ту же цепочку мы просчитываем **с каждой её точки**.

## Ключевое наблюдение

Каждая цепочка однозначно задаётся своим **началом** — числом `x`, у которого нет предшественника `x - 1` в массиве. Если начинать счёт **только от начал**, каждая цепочка будет пройдена ровно один раз, и суммарная работа внутренних циклов — `O(n)`.

Проверить «есть ли `x - 1`» и «есть ли `x + 1`» за `O(1)` позволяет хеш-множество.

## Техники

### Хеш-множество для проверки принадлежности

**Что это.** `Set` отвечает на вопрос «есть ли значение?» за `O(1)` в среднем и автоматически убирает дубликаты. Это заменяет сортировку, когда нужны не порядок, а **соседи по значению** (`x - 1`, `x + 1`).

**Как применяется здесь.** `new Set(nums)` строится за `O(n)`. Дальше все вопросы — «есть ли `x - 1`», «есть ли `x + length`» — по `O(1)`. Подробнее о хеш-таблицах — во вкладке «Теория».

### Старт только с «начала» (амортизированный анализ)

**Что это.** Приём, который превращает вложенный цикл в линейный: внутренний цикл запускается не от каждого элемента, а только от «представителя» группы — здесь от начала цепочки. Тогда каждый элемент посещается внутренним циклом не более одного раза за всю работу алгоритма, и хотя код выглядит как `for` + `while`, суммарно это `O(n)`.

**Когда применять.** Если внутренний цикл проходит «блок» элементов, а один и тот же блок может быть пройден из разных стартовых точек — найдите признак, по которому стартовая точка единственна.

## Разбор кода

```ts
function longestConsecutive(nums: number[]): number {
  // Множество даёт проверку «есть ли число» за O(1) и убирает дубликаты
  const set = new Set(nums);
  let best = 0;
```

Кладём все числа в множество — дубликаты схлопываются. `best = 0` сразу покрывает пустой массив: цикл не выполнится, вернётся `0`.

```ts
  for (const x of set) {
    // Начинаем считать только с НАЧАЛА последовательности:
    // если x - 1 есть, то x — не начало, его посчитают с более раннего числа
    if (set.has(x - 1)) continue;
```

Перебираем **множество**, а не `nums`: так каждое значение рассматривается один раз, даже если в массиве оно повторяется много раз. Если `x - 1` есть в множестве, `x` — середина или конец чьей-то цепочки; эту цепочку посчитают, когда очередь дойдёт до её начала, поэтому `x` пропускаем.

```ts
    // Идём вверх, пока числа подряд есть в множестве
    let length = 1;
    while (set.has(x + length)) {
      length++;
    }
```

`x` — начало цепочки, её длина уже минимум `1`. Проверяем `x + 1`, `x + 2`, … пока числа есть. Удобно, что `length` служит одновременно и длиной, и смещением следующего проверяемого числа: при `length = k` проверяется `x + k` — первое число за пределами уже найденной цепочки `x..x + k - 1`.

```ts
    best = Math.max(best, length);
  }

  return best;
}
```

Обновляем лучший результат и после перебора всех начал возвращаем его.

## Трассировка

`nums = [100, 4, 200, 1, 3, 2]`. `set = {100, 4, 200, 1, 3, 2}` — перебор идёт в порядке вставки.

1. `x = 100`: `99` нет → начало. `101` нет → `length = 1`. `best = 1`.
2. `x = 4`: `3` есть → не начало, пропуск.
3. `x = 200`: `199` нет → начало. `201` нет → `length = 1`. `best = 1`.
4. `x = 1`: `0` нет → начало.
   - `has(2)` да → `length = 2`;
   - `has(3)` да → `length = 3`;
   - `has(4)` да → `length = 4`;
   - `has(5)` нет → стоп. `best = 4`.
5. `x = 3`: `2` есть → пропуск.
6. `x = 2`: `1` есть → пропуск.

Ответ `4`. Числа `2, 3, 4` проверены во `while` ровно один раз — из цепочки от `1`; сами по себе они цикл не запускали.

Пример с дубликатом, `nums = [1, 0, 1, 2]`: `set = {1, 0, 2}`. `x = 1`: `0` есть → пропуск. `x = 0`: `-1` нет → `has(1)`, `has(2)` да, `has(3)` нет → `length = 3`. `x = 2`: пропуск. Ответ `3`.

## Почему это работает

**Корректность.** Любая максимальная цепочка подряд идущих чисел `s, s+1, …, s+L-1` имеет начало `s`, у которого `s - 1` нет в множестве (иначе цепочку можно было бы продлить влево). Когда цикл дойдёт до `x = s`, проверка `has(x - 1)` не сработает, и `while` пройдёт ровно до `s + L - 1` — следующего числа `s + L` в множестве нет (цепочка максимальна). Значит, длина каждой максимальной цепочки будет посчитана, и `best` станет максимумом.

**Линейность.** Каждое число `y` принадлежит ровно одной максимальной цепочке, и `while` проверяет его только при старте от начала этой цепочки — один раз. Плюс по одной «неудачной» проверке на каждое начало. Итого все `while` вместе делают `O(n)` проверок.

## Пограничные случаи

- **Пустой массив**: множество пусто, ответ `0`.
- **Один элемент**: ответ `1`.
- **Дубликаты**: схлопываются в множестве и не удлиняют цепочку.
- **Отрицательные числа и ноль**: `x - 1` и `x + length` работают для любых знаков.
- **Все числа подряд** (`[1..n]`): одно начало, один проход `while` на `n` шагов — без деградации до `O(n²)`.
- **Большие значения** (до `10⁹`): алгоритм не зависит от диапазона значений, в отличие от подсчёта массивом.

## Сложность

- **Время `O(n)`**: построение множества — `O(n)`; внешний цикл — `O(n)` итераций; все `while` в сумме — `O(n)` (каждое число проверяется внутри них не более одного раза).
- **Память `O(n)`**: множество из до `n` уникальных чисел.

## Типичные ошибки

1. **Не проверять `has(x - 1)`** → счёт запускается от каждого числа, `O(n²)` на длинных цепочках.
2. **Перебирать `nums` вместо `set`** → при массе дубликатов начала цепочки пересчитываются многократно (на `[1, 1, …, 1, 2, …, n]` — снова квадрат).
3. **Сортировать** → `O(n log n)`, формально не проходит требование.
4. **Не обработать пустой массив** — если начать с `best = 1`, для `[]` вернётся `1`.
5. **Считать дубликаты частью цепочки** при решении через сортировку (`[1, 1, 2]` → `3` вместо `2`).

## Как узнать такую задачу

- Нужна информация о «соседях по значению» (`x ± 1`), но требуется **`O(n)`**, то есть сортировать нельзя → хеш-множество.
- Внутренний цикл обходит «блоки» элементов → запускать его только от уникального представителя блока (начала).
- Родственные задачи: Longest Consecutive Sequence в дереве, Missing Number, First Missing Positive, Contains Duplicate; альтернативные решения той же задачи — Union-Find и `Map` «граница → длина».
