## Задача простыми словами

Дан **отсортированный** по началу список **непересекающихся** отрезков `intervals` и новый отрезок `newInterval`. Нужно вставить новый отрезок так, чтобы список остался отсортированным и без пересечений — при необходимости склеив его с теми, кого он задевает. Отрезки с общей точкой считаются пересекающимися.

Пример: `intervals = [[1,3],[6,9]]`, `newInterval = [2,5]` → `[[1,5],[6,9]]`. Новый `[2,5]` задевает `[1,3]`, вместе они дают `[1,5]`.

## Наивный подход

Самое простое — добавить новый отрезок в конец и запустить Merge Intervals:

```ts naive
const all = [...intervals, newInterval];
all.sort((a, b) => a[0] - b[0]);
const result: number[][] = [];
for (const [s, e] of all) {
  const last = result[result.length - 1];
  if (last && s <= last[1]) last[1] = Math.max(last[1], e);
  else result.push([s, e]);
}
```

Это верно, но `O(n log n)` из-за сортировки. Лишняя работа — мы **заново сортируем** уже отсортированный массив ради одного элемента и проверяем на пересечение все пары соседей, хотя исходные отрезки друг с другом гарантированно не пересекаются. Меняется только окрестность нового отрезка.

## Ключевое наблюдение

Относительно нового отрезка `[start, end]` все исходные отрезки делятся на **три подряд идущие группы**:

1. **целиком левее** — кончаются до `start`;
2. **пересекаются** с новым;
3. **целиком правее** — начинаются после `end`.

Группы идут именно в таком порядке, потому что список отсортирован и без пересечений. Значит, хватит одного прохода с тремя фазами: скопировать, слить, скопировать. Сортировка не нужна.

## Техники

### Линейный проход по отсортированным интервалам «в три фазы»

**Что это.** Когда данные уже упорядочены, вставка или удаление элемента не требует пересортировки: находим «зону влияния» нового элемента и обрабатываем три участка — до зоны, саму зону, после зоны. Общий указатель `i` переходит из фазы в фазу, не возвращаясь назад.

**Когда применять.** Вставка в отсортированный список интервалов, удаление интервала (Remove Interval), слияние двух отсортированных списков интервалов.

**Как применяется здесь.** Фаза 1 — `while` по условию «кончается до `start`», фаза 2 — «начинается не позже `end`» с расширением `start`/`end`, фаза 3 — остаток. Подробнее о шаблонах для интервалов — во вкладке «Теория».

### Поглощение пересекающихся отрезков

Новый отрезок работает как «накопитель»: каждый задетый отрезок расширяет его до `[min(start, s), max(end, e)]`. Расширение может задеть следующий отрезок — поэтому условие фазы 2 проверяется с **обновлённым** `end`.

## Разбор кода

```ts
function insert(intervals: number[][], newInterval: number[]): number[][] {
  const result: number[][] = [];
  let [start, end] = newInterval;
  let i = 0;
  const n = intervals.length;
```

`start` и `end` — копии границ нового отрезка (деструктуризация копирует числа, сам `newInterval` не меняется). Они будут расти по мере поглощения. `i` — общий указатель для всех трёх фаз.

```ts
  // 1. Интервалы, которые целиком ЛЕВЕЕ нового (кончаются до его начала)
  while (i < n && intervals[i][1] < start) {
    result.push(intervals[i]);
    i++;
  }
```

Пока текущий отрезок кончается **строго** раньше начала нового, они не пересекаются — копируем в ответ как есть. Строгое `<`: если `intervals[i][1] === start`, у отрезков общая точка, и по условию их надо слить — такой отрезок должен попасть в фазу 2.

```ts
  // 2. Интервалы, пересекающиеся с новым (начинаются не позже его конца) —
  //    поглощаем их, расширяя границы нового интервала
  while (i < n && intervals[i][0] <= end) {
    start = Math.min(start, intervals[i][0]);
    end = Math.max(end, intervals[i][1]);
    i++;
  }
  result.push([start, end]);
```

Сюда попадают отрезки, которые кончаются не раньше `start` (иначе их забрала бы фаза 1) и начинаются не позже `end` — то есть пересекаются с новым. Поглощаем: начало может сдвинуться влево (это бывает только у первого задетого отрезка), конец — вправо. Условие цикла каждый раз сравнивает со **свежим** `end`. Когда пересечения кончились, кладём объединённый отрезок. Он добавляется **всегда** — даже если фаза 2 ничего не поглотила, новый отрезок должен попасть в ответ.

```ts
  // 3. Интервалы, которые целиком ПРАВЕЕ нового, — копируем как есть
  while (i < n) {
    result.push(intervals[i]);
    i++;
  }

  return result;
}
```

Все оставшиеся отрезки начинаются правее `end` — копируем. Порядок в `result` сохранён: левые, объединённый, правые.

## Трассировка

`intervals = [[1,2],[3,5],[6,7],[8,10],[12,16]]`, `newInterval = [4,8]`. `start = 4`, `end = 8`.

Фаза 1:

1. `i = 0`, `[1,2]`: `2 < 4` → копируем. `result = [[1,2]]`.
2. `i = 1`, `[3,5]`: `5 < 4` — нет, выходим из фазы 1.

Фаза 2:

3. `i = 1`, `[3,5]`: `3 <= 8` → `start = min(4, 3) = 3`, `end = max(8, 5) = 8`.
4. `i = 2`, `[6,7]`: `6 <= 8` → `start = 3`, `end = max(8, 7) = 8`.
5. `i = 3`, `[8,10]`: `8 <= 8` (касание) → `end = max(8, 10) = 10`.
6. `i = 4`, `[12,16]`: `12 <= 10` — нет. Кладём `[3,10]`. `result = [[1,2],[3,10]]`.

Фаза 3:

7. `i = 4`: копируем `[12,16]`. `result = [[1,2],[3,10],[12,16]]`.

Ответ совпадает с примером 2.

Пустой список: `intervals = []`, `newInterval = [5,7]`. Фазы 1 и 2 сразу не выполняются, кладём `[5,7]`, фаза 3 пуста. Ответ `[[5,7]]`.

## Почему это работает

Так как исходные отрезки отсортированы и не пересекаются, их **концы тоже возрастают**. Поэтому условие «кончается до `start`» выполняется для некоторого префикса — его и забирает фаза 1.

Первый отрезок после фазы 1 имеет конец `>= start`. Если его начало `<= end`, он пересекается с новым; после поглощения `end` только растёт, и следующие отрезки проверяются с правильной границей. Как только встретился отрезок с началом `> end`, он и все последующие (начала возрастают) лежат правее объединённого отрезка — пересечений больше нет. Итог: левые отрезки не пересекаются с объединённым (кончаются до `start`, который мог только уменьшиться до начала первого поглощённого — а тот правее левых), правые — тоже, а объединённый покрывает новый отрезок и всех задетых. Порядок сохранён.

## Пограничные случаи

- **Пустой `intervals`**: ответ `[newInterval]`.
- **Новый левее всех**: фаза 1 пуста, фаза 2 пуста (если не задевает первый), затем всё копируется.
- **Новый правее всех**: фаза 1 забирает всё, затем добавляется новый.
- **Касание** (`[1,2]` и новый `[2,3]`): строгое `<` в фазе 1 отправляет `[1,2]` в фазу 2, они сливаются в `[1,3]`.
- **Новый поглощает все отрезки**: фаза 2 забирает всё, ответ — один отрезок.
- **Новый внутри существующего** (`[[1,10]]`, `[3,4]`): поглощается, ответ `[[1,10]]`.

## Сложность

- **Время `O(n)`**: указатель `i` проходит массив один раз через три фазы, каждая итерация — `O(1)`.
- **Память `O(n)`**: массив ответа; дополнительной памяти, кроме него, — `O(1)`.

## Типичные ошибки

1. **`<=` в фазе 1** → касающийся слева отрезок не сливается, в ответе остаются `[1,2]` и `[2,3]`.
2. **`<` в фазе 2** → не сливается отрезок, начинающийся ровно в `end`.
3. **Забыть `result.push([start, end])`**, когда фаза 2 ничего не поглотила → новый отрезок теряется.
4. **Не обновлять `start` через `min`** → объединение начинается с `newInterval[0]`, хотя задетый слева отрезок начинался раньше.
5. **Пересортировывать** всё ради одного элемента → `O(n log n)` вместо `O(n)`.

## Как узнать такую задачу

- Список интервалов **уже отсортирован и без пересечений**, и в него надо внести одно изменение → линейный проход в три фазы, без сортировки.
- Слова «insert», «add range», «remove range» в контексте отсортированных отрезков.
- Родственные задачи: Merge Intervals, Remove Interval, Range Module, Data Stream as Disjoint Intervals, Interval List Intersections.
