## Задача простыми словами

Дано поле `m x n` из клеток: `1` — живая, `0` — мёртвая. У каждой клетки до 8 соседей (по горизонтали, вертикали и диагоналям). Нужно **на месте** превратить поле в следующее поколение по правилам игры «Жизнь»:

- живая с 2 или 3 живыми соседями выживает, иначе умирает;
- мёртвая с ровно 3 живыми соседями оживает.

Все клетки меняются **одновременно** — новое состояние считается только по старому.

Пример: `[[1,1],[1,0]]` → `[[1,1],[1,1]]`. Мёртвый угол видит трёх живых соседей и оживает, остальные имеют по 2 соседа и выживают.

## Наивный подход

Скопировать поле, считать соседей по копии, а писать в оригинал:

```ts naive
const old = board.map((row) => [...row]);
for (let r = 0; r < m; r++)
  for (let c = 0; c < n; c++) {
    const live = countNeighbors(old, r, c);
    board[r][c] = live === 3 || (old[r][c] === 1 && live === 2) ? 1 : 0;
  }
```

Время `O(m · n)`, но память тоже `O(m · n)` на копию. А без копии, считая соседей прямо по `board`, получим ошибку: левые и верхние соседи уже **обновлены**, и клетка считается по смеси старого и нового поколений. Копия нужна только ради одного бита информации на клетку — «каким было старое состояние».

## Ключевое наблюдение

В клетке хранится `0` или `1` — это один бит, а число вмещает гораздо больше. Положим **оба поколения в одну клетку**:

- бит 0 (`value & 1`) — текущее, старое состояние;
- бит 1 (`value & 2`) — следующее, новое состояние.

Пока идёт первый проход, мы записываем только бит 1, а соседей считаем только по биту 0 — старое состояние остаётся читаемым, сколько бы клеток уже ни было обработано. Вторым проходом сдвигаем `>> 1` — новое состояние встаёт на место старого.

## Техники

### Кодирование нескольких состояний в одном значении (битовые маски)

**Что это.** Если значение использует не все биты, свободные биты можно занять служебной информацией. Операции: `x & 1` — прочитать младший бит, `x |= 2` — установить бит 1, `x >>= 1` — сдвинуть всё на один бит вправо (бит 1 становится битом 0, старый бит 0 отбрасывается).

**Когда применять.** Обновление «на месте», где новое значение зависит от старых значений соседей, а память `O(1)` обязательна. Варианты того же приёма — специальные маркеры-состояния (`2` = «была живой, умрёт», `3` = «была мёртвой, оживёт») или пометка знаком.

### Двухпроходное обновление

Первый проход вычисляет новое состояние всех клеток, ничего не разрушая; второй — применяет. Тот же шаблон, что в Set Matrix Zeroes.

### Перебор 8 соседей с проверкой границ

Два вложенных цикла `dr, dc ∈ {-1, 0, 1}` дают 9 смещений; `(0, 0)` — сама клетка, её пропускаем. Перед чтением проверяем, что сосед внутри поля. Подробнее о соседях клетки и обходе матриц — во вкладке «Теория».

## Разбор кода

```ts
  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {

```

Первый проход по всем клеткам. Возможные значения клетки в процессе: `0` (мёртвая → мёртвая), `1` (живая → мёртвая), `2` (мёртвая → живая), `3` (живая → живая). Бит 0 у них — всегда старое состояние.

```ts
      for (let dr = -1; dr <= 1; dr++) {
        for (let dc = -1; dc <= 1; dc++) {
          if (dr === 0 && dc === 0) continue; // саму клетку не считаем
          const nr = r + dr;
          const nc = c + dc;
          if (nr >= 0 && nr < m && nc >= 0 && nc < n) {
            live += board[nr][nc] & 1;
          }
        }
      }
```

Перебираем 8 соседей. Соседей за краем поля просто нет — проверка границ их отсекает. Ключевая строка — `board[nr][nc] & 1`: берём **только бит 0**. Соседи сверху и слева уже могли получить бит 1 (значение `2` или `3`), но `2 & 1 = 0` и `3 & 1 = 1` — их старое состояние читается правильно.

```ts
      const alive = (board[r][c] & 1) === 1;
      // Живая выживает при 2 или 3 соседях, мёртвая оживает при ровно 3
      if ((alive && (live === 2 || live === 3)) || (!alive && live === 3)) {
        board[r][c] |= 2; // следующее состояние — живая
      }
    }
  }
```

Четыре правила свёрнуты в одно условие «будет живой в следующем поколении». Если оно истинно — ставим бит 1 (`|= 2`), бит 0 при этом не меняется. Если ложно — ничего не делаем: бит 1 и так `0`, то есть «будет мёртвой». Смерть от одиночества и перенаселения отдельно обрабатывать не нужно.

```ts
  // Переходим к новому поколению: сдвигаем бит 1 на место бита 0
  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      board[r][c] >>= 1;
    }
  }
}
```

Второй проход: `>>= 1` превращает `0 → 0`, `1 → 0`, `2 → 1`, `3 → 1`. Старое состояние отбрасывается, новое становится текущим, и поле снова содержит только `0` и `1`.

## Трассировка

Пример 2: `board = [[1,1],[1,0]]`.

Первый проход (в скобках — значения соседей и их `& 1`):

1. `(0, 0)`, живая. Соседи `(0,1)=1`, `(1,0)=1`, `(1,1)=0` → `live = 2` → выживает, `board[0][0] = 1 | 2 = 3`.
2. `(0, 1)`, живая. Соседи `(0,0)=3` (`3 & 1 = 1`), `(1,0)=1`, `(1,1)=0` → `live = 2` → `board[0][1] = 3`.
3. `(1, 0)`, живая. Соседи `(0,0)=3 → 1`, `(0,1)=3 → 1`, `(1,1)=0` → `live = 2` → `board[1][0] = 3`.
4. `(1, 1)`, мёртвая. Соседи `3 → 1`, `3 → 1`, `3 → 1` → `live = 3` → оживает, `board[1][1] = 0 | 2 = 2`.

```
после 1-го прохода:   3 3      после >>= 1:   1 1
                      3 2                     1 1
```

Ответ `[[1,1],[1,1]]` — совпадает с примером. На шагах 2–4 соседи уже имели значение `3`, но `& 1` вернул их старое состояние.

Пример со смертью — строка `[1, 1, 1]` (`m = 1`, `n = 3`):

1. `(0, 0)`: сосед `(0,1)=1` → `live = 1` → умирает, бит 1 не ставим, остаётся `1`.
2. `(0, 1)`: соседи `(0,0)=1`, `(0,2)=1` → `live = 2` → выживает, становится `3`.
3. `(0, 2)`: сосед `(0,1)=3 → 1` → `live = 1` → умирает, остаётся `1`.

После сдвига: `[1, 3, 1] >> 1 = [0, 1, 0]`.

## Почему это работает

Инвариант первого прохода: бит 0 каждой клетки **никогда не меняется** — мы только устанавливаем бит 1 (`|= 2` не трогает бит 0). Значит, `board[x][y] & 1` в любой момент равно старому состоянию клетки, и `live` для каждой клетки считается строго по старому поколению — как будто все правила применяются одновременно.

Бит 1 после первого прохода равен `1` ровно для клеток, живых в новом поколении: условие `(alive && (live === 2 || live === 3)) || (!alive && live === 3)` эквивалентно четырём правилам. Второй проход переносит бит 1 на место бита 0, поэтому итоговое поле — следующее поколение.

## Пограничные случаи

- **Клетки на краях и в углах**: у них 5 или 3 соседа, проверка границ отсекает несуществующих.
- **Поле `1 x 1`**: соседей нет, `live = 0`; живая клетка умирает, мёртвая остаётся мёртвой.
- **Одна строка или один столбец**: работает так же, просто соседей меньше.
- **Всё мёртвое**: ни одна клетка не оживает, поле не меняется.

## Сложность

- **Время `O(m · n)`**: для каждой клетки 8 соседей — константа; плюс второй проход `O(m · n)`.
- **Память `O(1)`**: новое состояние живёт во втором бите той же клетки.

## Типичные ошибки

1. **Писать новое значение `0/1` сразу в `board`** → соседи справа и снизу считаются по смеси поколений.
2. **Читать соседа как `board[nr][nc]`, а не `& 1`** → значение `2` или `3` прибавляет к счётчику лишнее.
3. **Считать саму клетку соседом** (забыть `dr === 0 && dc === 0`) → у живых клеток `live` завышен на 1.
4. **Неверное условие выживания**: например, «живая при `live >= 2`» — забыто перенаселение (`live > 3`).
5. **Забыть второй проход** → в поле остаются значения `2` и `3`.

## Как узнать такую задачу

- Клеточный автомат или любое **одновременное** обновление сетки, где новое значение зависит от старых значений соседей.
- Значения занимают мало бит (`0/1`, маленький диапазон), а требуется память `O(1)` → кодируем старое и новое в одном числе.
- Follow-up про бесконечное поле решается хранением только живых клеток в `Set` координат и подсчётом соседей через `Map`.
- Родственные задачи: Set Matrix Zeroes, Candy Crush, Surrounded Regions (пометка клеток временным маркером).
