## Задача простыми словами

Дан массив `nums`, отсортированный по неубыванию (повторы разрешены), и число `target`. Нужно вернуть индексы **первого и последнего** вхождения `target`, а если его нет — `[-1, -1]`. Время — `O(log n)`.

Пример: `nums = [5, 7, 7, 8, 8, 10]`. Для `target = 8` ответ `[3, 4]`, для `target = 6` — `[-1, -1]`.

## Наивный подход

Найти любое вхождение обычным бинарным поиском, а потом расширяться влево и вправо, пока значения равны `target`:

```ts naive
const i = binarySearch(nums, target);
if (i === -1) return [-1, -1];
let l = i, r = i;
while (l > 0 && nums[l - 1] === target) l--;
while (r < nums.length - 1 && nums[r + 1] === target) r++;
return [l, r];
```

На «обычных» данных это быстро, но в худшем случае — массив из `n` одинаковых чисел — расширение проходит весь массив: `O(n)`. Лишняя работа — **пошаговое** движение к границе, хотя саму границу тоже можно искать бинарным поиском.

## Ключевое наблюдение

Обе границы выражаются через один примитив — **lower bound**: первый индекс `i`, где `nums[i] >= x`.

- **Начало** = `lowerBound(target)` — первый элемент, не меньший `target`. Если там не `target`, значения нет.
- **Конец** = `lowerBound(target + 1) - 1`: первый элемент, строго больший `target`, стоит сразу за последним вхождением. Числа целые, поэтому «`> target`» — то же, что «`>= target + 1`».

Условие `nums[i] >= x` монотонно по `i`: `false, false, …, false, true, …, true`. Найти первую `true` — классическая задача для бинарного поиска.

## Техники

### Бинарный поиск границы (lower bound)

**Что это.** Вариант бинарного поиска, который ищет не конкретное значение, а **точку перехода** монотонного условия: первую позицию, где условие становится истинным. Работает на **полуинтервале** `[lo, hi)`, где `hi = n` означает «такой позиции нет».

**Типичный шаблон:**

```ts naive
let lo = 0, hi = n;            // ответ в [lo, hi]
while (lo < hi) {
  const mid = lo + ((hi - lo) >> 1);
  if (!условие(mid)) lo = mid + 1;
  else hi = mid;
}
return lo;                      // первая позиция с условием, или n
```

**Когда применять.** «Первый/последний элемент, удовлетворяющий…», «куда вставить», «сколько элементов меньше x», границы диапазона повторов. Это самый универсальный вид бинарного поиска; подробнее — во вкладке «Теория».

**Как применяется здесь.** Условие — `nums[mid] >= x`; функцию вызываем дважды, с `x = target` и `x = target + 1`.

### Сведение upper bound к lower bound

Upper bound — первый индекс с `nums[i] > x`. Для целых чисел он равен `lowerBound(x + 1)`. Это позволяет обойтись одной функцией вместо двух почти одинаковых. Для дробных чисел так нельзя — там пишут отдельный поиск с условием `nums[mid] <= x`.

## Разбор кода

```ts
function searchRange(nums: number[], target: number): number[] {
  // lower bound: первый индекс i, где nums[i] >= x (или nums.length, если такого нет)
  const lowerBound = (x: number): number => {
    let lo = 0;
    let hi = nums.length; // полуинтервал [lo, hi)
```

Вспомогательная функция-замыкание. `hi = nums.length`, а не `nums.length - 1`: ответ может быть «за концом массива», если все элементы меньше `x`. Ответ всегда лежит в `[lo, hi]`.

```ts
    while (lo < hi) {
      const mid = lo + ((hi - lo) >> 1);
      if (nums[mid] < x) {
        lo = mid + 1; // граница правее mid
      } else {
        hi = mid; // mid подходит, но граница может быть левее
      }
    }
    return lo;
  };
```

Пока кандидатов больше одного. При `lo < hi` всегда `mid < hi <= nums.length`, так что `nums[mid]` существует. Если `nums[mid] < x`, сам `mid` и всё левее не подходят — `lo = mid + 1`. Иначе `mid` подходит, но первая подходящая позиция может быть левее, поэтому `hi = mid` (не `mid - 1` — иначе потеряем `mid`). Цикл заканчивается при `lo === hi` — это и есть граница.

```ts
  // Первое вхождение — первый элемент >= target
  const start = lowerBound(target);
  if (start === nums.length || nums[start] !== target) return [-1, -1];
```

Первый элемент, не меньший `target`. Две причины, по которым `target` нет: все элементы меньше (`start === nums.length`) или первый не меньший элемент уже больше `target`. Порядок проверок важен: сначала граница, потом чтение `nums[start]`.

```ts
  // Последнее вхождение — элемент перед первым, который > target.
  // Числа целые, поэтому «> target» — это «>= target + 1»
  const end = lowerBound(target + 1) - 1;

  return [start, end];
}
```

Первый элемент, больший `target`, — сразу за последним вхождением; вычитаем `1`. Раз `target` точно есть (проверили выше), `end >= start`.

## Трассировка

`nums = [5, 7, 7, 8, 8, 10]`, `target = 8`.

`lowerBound(8)`, `lo = 0`, `hi = 6`:

```
mid=3: nums[3]=8 < 8? нет → hi=3
mid=1: nums[1]=7 < 8? да  → lo=2
mid=2: nums[2]=7 < 8? да  → lo=3
lo=hi=3 → start=3, nums[3]=8 — target есть
```

`lowerBound(9)`, `lo = 0`, `hi = 6`:

```
mid=3: nums[3]=8  < 9? да  → lo=4
mid=5: nums[5]=10 < 9? нет → hi=5
mid=4: nums[4]=8  < 9? да  → lo=5
lo=hi=5 → end = 5 - 1 = 4
```

Ответ `[3, 4]`.

`target = 6`: `lowerBound(6)` — `mid = 3` (`8`) → `hi = 3`; `mid = 1` (`7`) → `hi = 1`; `mid = 0` (`5 < 6`) → `lo = 1`. `start = 1`, но `nums[1] = 7 ≠ 6` → `[-1, -1]`.

## Почему это работает

Инвариант `lowerBound`: все индексы `< lo` имеют `nums[i] < x`, все индексы `>= hi` (в пределах массива) имеют `nums[i] >= x`. В начале он тривиально верен (`lo = 0`, `hi = n`). Ветка `lo = mid + 1` применяется, когда `nums[mid] < x`, — по сортировке всё до `mid` тоже меньше. Ветка `hi = mid` — когда `nums[mid] >= x`, и по сортировке всё после тоже. Отрезок строго сужается, и при `lo === hi` эта точка разделяет «меньше» и «не меньше» — то есть это первый индекс с `nums[i] >= x`.

Все вхождения `target` образуют непрерывный блок (массив отсортирован). Его начало — первый `>= target`, а первый элемент после блока — первый `>= target + 1` (между `target` и `target + 1` целых нет).

## Пограничные случаи

- **Пустой массив**: `lowerBound` сразу возвращает `0 === nums.length` → `[-1, -1]`.
- **`target` больше всех**: `start = n` → `[-1, -1]` без чтения за границей.
- **`target` меньше всех**: `start = 0`, но `nums[0] !== target` → `[-1, -1]`.
- **Весь массив из `target`**: `start = 0`, `lowerBound(target + 1) = n`, `end = n - 1` — по-прежнему `O(log n)`.
- **`target = 10⁹`**: `target + 1` безопасно помещается в `number`.

## Сложность

- **Время `O(log n)`**: два бинарных поиска по `O(log n)` шагов.
- **Память `O(1)`**: несколько переменных.

## Типичные ошибки

1. **Линейное расширение от найденного вхождения** → `O(n)` на массиве из одинаковых чисел.
2. **`hi = nums.length - 1`** в lower bound → не отличить «граница на последнем элементе» от «всё меньше `x`».
3. **`hi = mid - 1`** в ветке «подходит» → потеря самой границы.
4. **Не проверить `start === nums.length`** перед `nums[start]` → чтение `undefined` (в JS не упадёт, но в других языках — выход за границу).
5. **Применить трюк `target + 1` к дробным числам** → ошибочно, нужен отдельный upper bound.

## Как узнать такую задачу

- «Первое/последнее вхождение», «сколько раз встречается», «диапазон равных» в отсортированном массиве + `O(log n)`.
- Вопрос «где начинается/кончается область, где условие истинно» — бинарный поиск границы.
- Родственные задачи: Search Insert Position (ровно lower bound), First Bad Version, Count of Smaller Numbers, Koko Eating Bananas (граница по ответу), Time Based Key-Value Store.
