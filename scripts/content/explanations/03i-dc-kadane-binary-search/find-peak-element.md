## Задача простыми словами

Дан массив `nums`, в котором соседние элементы никогда не равны. **Пик** — элемент, строго больший обоих соседей; за краями массива мысленно стоит `-∞`. Нужно вернуть индекс **любого** пика за `O(log n)`.

Пример: `nums = [1, 2, 1, 3, 5, 6, 4]`. Пики — `2` (индекс `1`) и `6` (индекс `5`); подходит любой из ответов `1` или `5`. Для `[1, 2, 3, 1]` ответ `2`.

## Наивный подход

Пройти слева направо и вернуть первый элемент, который больше следующего:

```ts naive
for (let i = 0; i < nums.length - 1; i++) {
  if (nums[i] > nums[i + 1]) return i;
}
return nums.length - 1;
```

Это верно (до первого «спуска» массив возрастает, значит, левый сосед меньше), но работает за `O(n)`. Лишняя работа: мы проверяем каждую точку подъёма по очереди, хотя одно сравнение уже говорит, **в какую сторону** точно есть пик, — и всю другую сторону можно не смотреть.

## Ключевое наблюдение

Массив не отсортирован, но бинарный поиск возможен: достаточно сравнить `nums[mid]` с правым соседом.

- `nums[mid] < nums[mid + 1]` — мы **на подъёме**. Идём вправо: значения либо растут до самого конца (тогда последний элемент — пик, ведь за ним `-∞`), либо где-то начнут падать — там и пик. Значит, пик точно есть в `[mid + 1, hi]`.
- `nums[mid] > nums[mid + 1]` — мы **на спуске**. Симметрично пик есть в `[lo, mid]`, причём сам `mid` может им быть.

Каждое сравнение отбрасывает половину, где пик не гарантирован.

## Техники

### Бинарный поиск по монотонному признаку (по «склону»)

**Что это.** Бинарный поиск работает не только на отсортированных данных. Нужно одно: по проверке в середине **однозначно понять, в какой половине ответ гарантированно есть**. Здесь признак — направление склона в точке `mid`.

**Типичный шаблон «сужения до точки»:**

```ts naive
let lo = 0, hi = n - 1;
while (lo < hi) {
  const mid = lo + ((hi - lo) >> 1);
  if (ответСтрогоПравее(mid)) lo = mid + 1;
  else hi = mid;           // mid сам может быть ответом
}
return lo;
```

Условие `lo < hi` и `hi = mid` (без `- 1`) — отрезок сжимается до одной точки, и `mid` не теряется. Подробнее о вариантах бинарного поиска — во вкладке «Теория».

**Как применяется здесь.** «Ответ строго правее» ⇔ `nums[mid] < nums[mid + 1]` (подъём).

### Инвариант «ответ внутри отрезка»

Корректность таких поисков удобно доказывать через утверждение, которое верно до цикла и сохраняется каждой итерацией. Здесь это «на отрезке `[lo, hi]` есть пик», с уточнением: значение сразу за `hi` меньше `nums[hi]` (или это край массива).

## Разбор кода

```ts
function findPeakElement(nums: number[]): number {
  // Пик всегда есть на отрезке [lo, hi]: за его границами
  // значения «спускаются» (по условию nums[-1] = nums[n] = -∞)
  let lo = 0;
  let hi = nums.length - 1;
```

Отрезок поиска — весь массив. Благодаря `-∞` за краями пик в любом непустом массиве существует (например, глобальный максимум).

```ts
  while (lo < hi) {
    const mid = lo + ((hi - lo) >> 1);
```

Цикл, пока в отрезке больше одного элемента. При `lo < hi` середина, округлённая вниз, всегда строго меньше `hi`, поэтому `mid + 1 <= hi` — обращение к `nums[mid + 1]` никогда не выходит за массив.

```ts
    if (nums[mid] < nums[mid + 1]) {
      // Идём в гору: справа от mid обязательно есть пик
      lo = mid + 1;
```

Подъём. Сам `mid` пиком быть не может (правый сосед больше), поэтому исключаем его: `lo = mid + 1`. Пик гарантирован справа.

```ts
    } else {
      // Спускаемся (nums[mid] > nums[mid + 1]):
      // пик — сам mid или левее
      hi = mid;
    }
  }
```

Спуск (равенства нет по условию). `mid` может оказаться пиком, если его левый сосед меньше, поэтому оставляем его в отрезке: `hi = mid`, а не `mid - 1`.

```ts
  // Отрезок сжался до одной точки — это пик
  return lo;
}
```

Когда `lo === hi`, в отрезке один элемент, и по инварианту это пик.

## Трассировка

`nums = [1, 2, 1, 3, 5, 6, 4]`, `lo = 0`, `hi = 6`:

1. `mid = 3`: `nums[3] = 3 < nums[4] = 5` — подъём → `lo = 4`.
2. `mid = 4 + (2 >> 1) = 5`: `nums[5] = 6 < nums[6] = 4`? Нет — спуск → `hi = 5`.
3. `mid = 4 + (1 >> 1) = 4`: `nums[4] = 5 < nums[5] = 6` — подъём → `lo = 5`.
4. `lo = hi = 5` — возвращаем `5` (`nums[5] = 6`, соседи `5` и `4`).

Алгоритм нашёл пик `6`, а не `2` на индексе `1` — оба ответа допустимы.

`nums = [1, 2, 3, 1]`: `mid = 1` (`2 < 3`) → `lo = 2`; `mid = 2` (`3 < 1`? нет) → `hi = 2`. Ответ `2`.

## Почему это работает

Инвариант: в `[lo, hi]` есть пик, причём `nums[lo - 1] < nums[lo]` (или `lo = 0`) и `nums[hi + 1] < nums[hi]` (или `hi = n - 1`). Иными словами, на левой границе отрезка «вход в гору», на правой — «спуск». Отрезок с такими краями обязательно содержит пик: его максимум больше соседей внутри отрезка, а у краёв — больше внешних соседей.

- В начале инвариант верен благодаря `-∞` за краями.
- `lo = mid + 1` при `nums[mid] < nums[mid + 1]`: новая левая граница имеет левого соседа `nums[mid]`, который меньше — условие сохранено.
- `hi = mid` при `nums[mid] > nums[mid + 1]`: у новой правой границы правый сосед меньше — условие сохранено.

Отрезок строго уменьшается, и когда он становится одной точкой, оба её соседа меньше — это пик.

## Пограничные случаи

- **Один элемент**: цикл не выполняется, ответ `0` — элемент больше двух `-∞`.
- **Строго возрастающий массив**: всё время подъём, ответ — последний индекс.
- **Строго убывающий массив**: всё время спуск, ответ `0`.
- **Значения вплоть до `-2³¹`**: сравниваются только соседи между собой, а не с `-∞`, так что крайние значения не мешают.
- **Несколько пиков**: возвращается какой-то один, это разрешено.

## Сложность

- **Время `O(log n)`**: каждая итерация уменьшает отрезок примерно вдвое.
- **Память `O(1)`**: три переменные.

## Типичные ошибки

1. **`hi = mid - 1` на спуске** → можно выбросить сам пик (например, в `[1, 3, 2]` при `mid = 1`).
2. **`while (lo <= hi)` вместе с `hi = mid`** → бесконечный цикл, когда `lo === hi`.
3. **Сравнивать с левым соседом `nums[mid - 1]`** при середине, округлённой вниз → выход за границу при `mid = 0`; если хочется сравнивать слева, середину округляют вверх.
4. **Думать, что нужен глобальный максимум** → он тоже пик, но поиск максимума — `O(n)`.
5. **Сравнивать `nums[mid]` с краями отрезка**, а не с соседом → такая информация не говорит о направлении склона.

## Как узнать такую задачу

- Требуется `O(log n)`, но массив **не отсортирован** — ищите признак, по которому половина гарантированно содержит ответ.
- «Найти любой локальный максимум/минимум», «точку перегиба», «вершину горы».
- Родственные задачи: Peak Index in a Mountain Array, Find a Peak Element II (двумерный вариант), Find Minimum in Rotated Sorted Array, Find in Mountain Array.
