## Задача простыми словами

Дан массив `lists` из `k` связных списков, каждый отсортирован по возрастанию. Нужно слить их в **один** отсортированный список и вернуть его голову. Списков может не быть вовсе, а отдельные списки могут быть пустыми (`null`).

Пример:

```
1 -> 4 -> 5
1 -> 3 -> 4
2 -> 6
результат: 1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6
```

Дальше `N` — общее число узлов во всех списках.

## Наивный подход

Самое простое — сливать списки по одному в накопленный результат:

```ts naive
let result: ListNode | null = null;
for (const list of lists) {
  result = mergeTwo(result, list);
}
return result;
```

Верно, но медленно. Узлы первого списка проходят через **каждое** из `k` слияний, второго — через `k - 1` и так далее. Если списки одинаковой длины `N / k`, суммарно получается `O(N · k)`: при `k = 10⁴` это огромная работа. Лишнее здесь — **растущий результат протаскивается заново** через каждое следующее слияние.

Другой лобовой путь — сложить все значения в массив, отсортировать и собрать новый список: `O(N log N)` времени и `O(N)` памяти, и мы никак не используем то, что списки уже отсортированы.

## Ключевое наблюдение

Это **сортировка слиянием**, у которой «листья» — не отдельные числа, а уже отсортированные списки. Делим массив списков пополам, рекурсивно сливаем левую половину в один список, правую — в другой, и соединяем два результата обычным слиянием двух списков.

Сливаются всегда части примерно **одинакового размера**, поэтому каждый узел участвует не в `k` слияниях, а только в `log k` — по одному на каждый уровень рекурсии. Уровней `⌈log₂ k⌉`, на каждом все `N` узлов сливаются ровно один раз: итого `O(N log k)`.

## Техники

### Разделяй и властвуй (рекурсия по диапазону индексов)

**Что это.** Большую задачу делят на части, решают части тем же способом и объединяют ответы. Сортировка слиянием делит массив пополам до отдельных элементов и сливает обратно.

**Типичный шаблон.** Функция работает с диапазоном `[lo, hi]`:

```ts naive
function solve(lo: number, hi: number) {
  if (lo === hi) return base(lo);          // один элемент — ответ очевиден
  const mid = Math.floor((lo + hi) / 2);
  return combine(solve(lo, mid), solve(mid + 1, hi));
}
```

Если объединение двух частей стоит линейно от их суммарного размера, то сбалансированное деление `k` частей стоит `O(N log k)`, а последовательное — `O(N · k)`. Всегда выгоднее сливать «равные с равными».

**Как применяется здесь.** `merge(lo, hi)` сливает списки `lists[lo..hi]`: база — один список (`lo === hi`), объединение — `mergeTwo`. Мы не копируем подмассивы, а передаём только границы диапазона. Подробнее о схеме — во вкладке «Теория» (разделяй и властвуй).

### Слияние двух отсортированных списков с фиктивной головой

Стандартный примитив: сравниваем головы двух списков, меньшую пришиваем к хвосту результата. Фиктивный узел `dummy` избавляет от отдельной ветки для первого узла. Узлы не копируются, только перевешиваются указатели.

### Альтернатива — мин-куча

В кучу кладут головы всех списков, достают минимум, пришивают его к ответу и добавляют в кучу его `next`. Тоже `O(N log k)`, но нужна память `O(k)` и своя реализация кучи — в JS/TS встроенной нет.

Внутренняя функция `merge` видит `lists` через замыкание, поэтому ей достаточно двух чисел — границ диапазона включительно. Ответ на всю задачу — `merge(0, k - 1)`.

```ts

```

Две базы. `lo > hi` возможно только в самом первом вызове `merge(0, -1)`, когда списков нет: внутри рекурсии половины всегда непусты, потому что `mid` лежит между `lo` и `hi`. Один список (`lo === hi`) уже отсортирован — возвращаем его как есть, даже если это `null`.

```ts

    const mid = Math.floor((lo + hi) / 2);
    return mergeTwo(merge(lo, mid), merge(mid + 1, hi));
  }
```

Сердце алгоритма — одна строка, ровно как в сортировке слиянием. Левая половина `[lo, mid]` и правая `[mid + 1, hi]` каждая превращаются в один отсортированный список, а `mergeTwo` соединяет их. `Math.floor` нужен, потому что `/` в JS даёт дробное число.

```ts

}
```

Запускаем рекурсию на всём массиве. При `lists = []` это `merge(0, -1)` → `null`.

```ts

  // Фиктивная голова: не нужно отдельно выбирать первый узел
  const dummy = new ListNode(0);
  let tail = dummy;
```

`dummy` — фиктивная голова результата, `tail` — его последний узел. Настоящий ответ начнётся с `dummy.next`.

```ts
  while (a && b) {
    // Пришиваем меньший из двух текущих узлов
    if (a.val <= b.val) {
      tail.next = a;
      a = a.next;
    } else {
      tail.next = b;
      b = b.next;
    }
    tail = tail.next;
  }
```

Пока оба списка непусты, пришиваем меньшую голову и сдвигаем её указатель. Каждая итерация «тратит» ровно один узел — отсюда линейное время слияния.

```ts
  // Остаток одного из списков пришиваем целиком
  tail.next = a ?? b;
  return dummy.next;
}
```

Оставшийся хвост уже отсортирован и не меньше всего собранного. Важный побочный эффект: если один из входов `null` (пустой список), цикл не выполнится, и `mergeTwo` просто вернёт другой список — пустые списки обрабатываются без особых проверок.

## Трассировка

`lists = [1->4->5, 1->3->4, 2->6]`, `k = 3`. Вызов `merge(0, 2)`:

1. `mid = 1` → нужно `mergeTwo(merge(0, 1), merge(2, 2))`.
2. `merge(0, 1)`: `mid = 0` → `mergeTwo(merge(0, 0), merge(1, 1))` = `mergeTwo(1->4->5, 1->3->4)`:

```
a=1, b=1: 1<=1 → берём a(1)      1
a=4, b=1: нет  → берём b(1)      1 1
a=4, b=3: нет  → берём b(3)      1 1 3
a=4, b=4: да   → берём a(4)      1 1 3 4
a=5, b=4: нет  → берём b(4)      1 1 3 4 4
b пуст → пришиваем 5             1 1 3 4 4 5
```

3. `merge(2, 2)`: база, возвращаем `2->6`.
4. Возвращаемся в `merge(0, 2)`: `mergeTwo(1->1->3->4->4->5, 2->6)` = `1->1->2->3->4->4->5->6`.

Дерево вызовов:

```
merge(0,2)
├── merge(0,1)
│   ├── merge(0,0) = 1->4->5
│   └── merge(1,1) = 1->3->4
└── merge(2,2) = 2->6
```

Ответ — `1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6`.

## Почему это работает

Докажем индукцией по размеру диапазона, что `merge(lo, hi)` возвращает отсортированное слияние списков `lists[lo..hi]`:

- **База.** Пустой диапазон — пустой список `null`. Один список — он отсортирован по условию.
- **Шаг.** Если диапазон длиннее, обе половины строго короче, поэтому по предположению индукции `merge(lo, mid)` и `merge(mid + 1, hi)` — отсортированные слияния своих половин. `mergeTwo` двух отсортированных списков даёт отсортированный список из всех их узлов.

Корректность `mergeTwo` стандартна: каждый раз берём минимум из двух голов — это минимум всех оставшихся узлов, поэтому результат отсортирован, и ни один узел не теряется (остаток пришивается). Рекурсия завершается, потому что каждый вызов уменьшает диапазон примерно вдвое.

## Пограничные случаи

- **`lists = []`**: `merge(0, -1)` срабатывает на `lo > hi`, ответ `null`.
- **`lists = [null]`**: `merge(0, 0)` возвращает `lists[0] = null`.
- **Часть или все списки пустые**: `mergeTwo(x, null)` возвращает `x`, `mergeTwo(null, null)` — `null`.
- **Один список**: возвращается он сам, без работы.
- **Нечётное `k`**: половины просто получаются разного размера (отличаются на 1) — баланс сохраняется.
- **Повторяющиеся значения**: `<=` сохраняет их все.

## Сложность

- **Время `O(N log k)`**: глубина рекурсии `⌈log₂ k⌉`; на каждом уровне каждый узел попадает ровно в одно слияние, а слияние линейно по числу своих узлов, так что уровень — `O(N)`.
- **Память `O(log k)`**: стек рекурсии глубиной `log k`; новые узлы не создаются (кроме одного `dummy` на слияние) — только перевешиваются указатели.

**Follow-up на собеседовании:** «можно ли без рекурсии, за `O(1)` памяти?» — да, то же самое снизу вверх: раунды с шагом `step = 1, 2, 4, …`, в каждом сливаем `lists[i]` и `lists[i + step]` с результатом на месте `lists[i]`:

```ts naive
for (let step = 1; step < lists.length; step *= 2) {
  for (let i = 0; i + step < lists.length; i += step * 2) {
    lists[i] = mergeTwo(lists[i], lists[i + step]);
  }
}
return lists[0] ?? null;
```

## Типичные ошибки

1. **Последовательное слияние в накопитель** → `O(N · k)`, на больших `k` превышение времени.
2. **Делить на `[lo, mid - 1]` и `[mid, hi]`** при `mid = floor((lo + hi) / 2)` → для диапазона из двух элементов левая половина пустая, правая не уменьшается — бесконечная рекурсия. Правильно: `[lo, mid]` и `[mid + 1, hi]`.
3. **Забыть случай `lists = []`** → без проверки `lo > hi` вызов `merge(0, -1)` уйдёт в бесконечную рекурсию или вернёт `undefined`.
4. **Копировать подмассивы через `slice`** на каждом уровне → лишняя память и время; достаточно передавать границы.
5. **Не пришить остаток** в `mergeTwo` → теряются хвосты списков.

## Как узнать такую задачу

- Нужно объединить **много отсортированных последовательностей** в одну, или найти k-й элемент среди них.
- Есть дешёвая операция «слить две части» → делим пополам и объединяем сбалансированно, ради множителя `log k` вместо `k`. Это тот же каркас, что у Sort List и сортировки слиянием.
- Альтернативный сигнал — «всё время нужен минимум из k кандидатов» → мин-куча.
- Родственные задачи: Merge Two Sorted Lists, Sort List, Find K Pairs with Smallest Sums, Smallest Range Covering Elements from K Lists.
