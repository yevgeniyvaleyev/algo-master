## Задача простыми словами

Дан массив `lists` из `k` связных списков, каждый отсортирован по возрастанию. Нужно слить их в **один** отсортированный список и вернуть его голову. Списков может не быть вовсе, а отдельные списки могут быть пустыми (`null`).

Пример:

```
1 -> 4 -> 5
1 -> 3 -> 4
2 -> 6
результат: 1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6
```

Дальше `N` — общее число узлов во всех списках.

## Наивный подход

Самое простое — сливать списки по одному в накопленный результат:

```ts naive
let result: ListNode | null = null;
for (const list of lists) {
  result = mergeTwo(result, list);
}
return result;
```

Верно, но медленно. Узлы первого списка проходят через **каждое** из `k` слияний, второго — через `k - 1` и так далее. Если списки одинаковой длины `N / k`, суммарно получается `O(N · k)`: при `k = 10⁴` это огромная работа. Лишнее здесь — **растущий результат протаскивается заново** через каждое следующее слияние.

Другой лобовой путь — сложить все значения в массив, отсортировать и собрать новый список: `O(N log N)` времени и `O(N)` памяти, и мы никак не используем то, что списки уже отсортированы.

## Ключевое наблюдение

Сливать надо **парами одинакового размера**, как в турнирной сетке: сначала пары списков, потом пары результатов и т. д. Тогда каждый узел участвует только в `log k` слияниях — по одному на раунд, — а не в `k`.

Раундов `⌈log₂ k⌉`, в каждом раунде каждый узел проходит ровно через одно слияние, значит раунд стоит `O(N)`, а всё вместе — `O(N log k)`.

## Техники

### Разделяй и властвуй (попарное слияние)

**Что это.** Большую задачу делят на части, решают части и объединяют ответы. Сортировка слиянием делит массив пополам до отдельных элементов и сливает обратно. Здесь «листья» уже готовы — это отсортированные списки, — поэтому остаётся только фаза объединения.

**Типичный шаблон.** Если объединение двух частей стоит линейно от их суммарного размера, то сбалансированное попарное объединение `k` частей стоит `O(N log k)`, а последовательное — `O(N · k)`. Всегда выгоднее сливать «равные с равными».

**Как применяется здесь.** Код делает это **итеративно, снизу вверх**: переменная `step` — расстояние между сливаемыми списками в текущем раунде. Подробнее о схеме — во вкладке «Теория» (разделяй и властвуй).

### Слияние двух отсортированных списков с фиктивной головой

Стандартный примитив: сравниваем головы двух списков, меньшую пришиваем к хвосту результата. Фиктивный узел `dummy` избавляет от отдельной ветки для первого узла. Узлы не копируются, только перевешиваются указатели.

### Альтернатива — мин-куча

В кучу кладут головы всех списков, достают минимум, пришивают его к ответу и добавляют в кучу его `next`. Тоже `O(N log k)`, но нужна память `O(k)` и своя реализация кучи — в JS/TS встроенной нет.

## Разбор кода

```ts
function mergeKLists(lists: Array<ListNode | null>): ListNode | null {
  if (lists.length === 0) return null;
```

Пустой массив списков — ответ пустой список. Без этой проверки в конце вернулось бы `lists[0]`, то есть `undefined`, а не `null`.

```ts
  // Сливаем списки парами, как в турнирной сетке:
  // step = 1: (0,1), (2,3), ...; step = 2: (0,2), (4,6), ...; и так далее.
  // Результат каждой пары кладём на место левого списка.
  for (let step = 1; step < lists.length; step *= 2) {
    for (let i = 0; i + step < lists.length; i += step * 2) {
      lists[i] = mergeTwo(lists[i], lists[i + step]);
    }
  }
```

Внешний цикл — раунды. После раунда с шагом `step` «живые» результаты лежат на индексах, кратных `2·step`. Поэтому в следующем раунде шаг удваивается: сливаем `lists[i]` и `lists[i + step]` для `i = 0, 2·step, 4·step, …`. Условие `i + step < lists.length` пропускает список без пары (при нечётном количестве) — он просто дожидается следующего раунда. Цикл заканчивается, когда `step >= lists.length`: значит, весь массив уже собран в `lists[0]`.

Схема для `k = 5`:

```
step=1: (0,1) (2,3)       — 4 без пары
step=2: (0,2)             — 4 всё ещё без пары
step=4: (0,4)
step=8: 8 >= 5 — стоп, всё в lists[0]
```

Заметьте: массив `lists` изменяется на месте — это нормально для задачи, а дополнительной памяти не требуется.

```ts
  // После последнего раунда всё слито в lists[0]
  return lists[0];
}
```

Если список был один, циклы не выполнились — возвращаем его же.

```ts
// Классическое слияние двух отсортированных списков
function mergeTwo(a: ListNode | null, b: ListNode | null): ListNode | null {
  const dummy = new ListNode(0);
  let tail = dummy;
```

`dummy` — фиктивная голова результата, `tail` — его последний узел.

```ts
  while (a && b) {
    if (a.val <= b.val) {
      tail.next = a;
      a = a.next;
    } else {
      tail.next = b;
      b = b.next;
    }
    tail = tail.next;
  }
```

Пока оба списка непусты, пришиваем меньшую голову и сдвигаем её указатель. Каждая итерация «тратит» ровно один узел — отсюда линейное время слияния.

```ts
  // Остаток одного из списков пришиваем целиком
  tail.next = a ?? b;
  return dummy.next;
}
```

Оставшийся хвост уже отсортирован и не меньше всего собранного. Важный побочный эффект: если один из входов `null` (пустой список), цикл не выполнится, и `mergeTwo` просто вернёт другой список — пустые списки обрабатываются без особых проверок.

## Трассировка

`lists = [1->4->5, 1->3->4, 2->6]`, `k = 3`.

1. `step = 1`, `i = 0`: `0 + 1 < 3` → `lists[0] = mergeTwo(1->4->5, 1->3->4)`:

```
a=1, b=1: 1<=1 → берём a(1)      1
a=4, b=1: нет  → берём b(1)      1 1
a=4, b=3: нет  → берём b(3)      1 1 3
a=4, b=4: да   → берём a(4)      1 1 3 4
a=5, b=4: нет  → берём b(4)      1 1 3 4 4
b пуст → пришиваем 5             1 1 3 4 4 5
```

   `i = 2`: `2 + 1 < 3` — ложно, список `2->6` остаётся без пары.
2. `step = 2`, `i = 0`: `0 + 2 < 3` → `lists[0] = mergeTwo(1->1->3->4->4->5, 2->6)` = `1->1->2->3->4->4->5->6`. `i = 4` — выход.
3. `step = 4`: `4 < 3` ложно — раунды закончились.

Ответ — `lists[0] = 1 -> 1 -> 2 -> 3 -> 4 -> 4 -> 5 -> 6`.

## Почему это работает

Инвариант раунда: перед раундом с шагом `step` каждый «живой» элемент `lists[i]` (где `i` кратно `step`) — отсортированное слияние исходных списков с индексами `[i, i + step)` (обрезанных по `k`). В раунде `lists[i]` и `lists[i + step]` объединяются в слияние диапазона `[i, i + 2·step)`; если пары нет, `lists[i]` уже покрывает всё до конца массива. Когда `step >= k`, диапазон `lists[0]` — это `[0, k)`, то есть все списки.

Корректность `mergeTwo` стандартна: каждый раз берём минимум из двух голов — это минимум всех оставшихся узлов, поэтому результат отсортирован, и ни один узел не теряется (остаток пришивается).

## Пограничные случаи

- **`lists = []`**: явная проверка, ответ `null`.
- **`lists = [null]`**: циклы не выполняются, возвращается `lists[0] = null`.
- **Часть списков пустые**: `mergeTwo(x, null)` возвращает `x`, всё работает.
- **Один список**: возвращается он сам, без работы.
- **Нечётное `k`**: непарный список переносится в следующий раунд.
- **Повторяющиеся значения**: `<=` сохраняет их все.

## Сложность

- **Время `O(N log k)`**: раундов `⌈log₂ k⌉`; в каждом раунде каждый узел попадает максимум в одно слияние, а слияние линейно по числу своих узлов, так что раунд — `O(N)`.
- **Память `O(1)`**: новые узлы не создаются (кроме одного `dummy` на слияние), рекурсии нет — только перевешивание указателей.

## Типичные ошибки

1. **Последовательное слияние в накопитель** → `O(N · k)`, на больших `k` превышение времени.
2. **Неверный шаг `i`**: `i += step` вместо `i += step * 2` → один список сливается дважды, а результаты затираются.
3. **Забыть случай `lists.length === 0`** → возвращается `undefined` вместо `null`.
4. **Не пришить остаток** в `mergeTwo` → теряются хвосты списков.
5. **Создавать копии узлов** при слиянии → лишняя память `O(N)`.

## Как узнать такую задачу

- Нужно объединить **много отсортированных последовательностей** в одну, или найти k-й элемент среди них.
- Есть дешёвая операция «слить две части» → объединяем попарно, сбалансированно, ради множителя `log k` вместо `k`.
- Альтернативный сигнал — «всё время нужен минимум из k кандидатов» → мин-куча.
- Родственные задачи: Merge Two Sorted Lists, Sort List, Find K Pairs with Smallest Sums, Smallest Range Covering Elements from K Lists.
