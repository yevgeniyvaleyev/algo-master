## Задача простыми словами

Дан **кольцевой** массив `nums`: после последнего элемента снова идёт первый. Нужно найти непустой непрерывный подмассив с наибольшей суммой, причём каждый элемент можно взять не больше одного раза (нельзя «обойти кольцо дважды»).

Примеры:

- `[1, -2, 3, -2]` → `3`: лучший кусок — просто `[3]`.
- `[5, -3, 5]` → `10`: кусок `[5, 5]` идёт **через край** — последний элемент, затем первый.
- `[-3, -2, -3]` → `-2`: все отрицательные, берём наибольший элемент.

## Наивный подход

Перебрать все стартовые позиции и все длины от `1` до `n`, двигаясь по кольцу с индексом `% n`:

```ts naive
let best = -Infinity;
for (let i = 0; i < n; i++) {
  let sum = 0;
  for (let len = 1; len <= n; len++) {
    sum += nums[(i + len - 1) % n];
    best = Math.max(best, sum);
  }
}
```

Это `O(n²)`: при `n = 3·10⁴` — около 900 миллионов шагов. Лишняя работа та же, что в обычной задаче о максимальном подмассиве: одни и те же суммы пересчитываются для каждого старта. Обычный Кадане за `O(n)` не подходит напрямую — он не видит отрезков, идущих через край.

## Ключевое наблюдение

Лучший отрезок в кольце бывает только двух видов:

```
обычный:     [ . . . ######## . . . ]
через край:  [ #### . . . . . . ### ]
```

1. **Обычный** — лежит внутри массива. Его находит стандартный Кадане.
2. **Через край** — это префикс плюс суффикс. Тогда **невзятые** элементы образуют непрерывный кусок посередине. Сумма взятого = `total - (сумма выброшенного куска)`. Чтобы её максимизировать, выброшенный кусок должен иметь **минимальную** сумму — а её тоже находит Кадане, только с `min` вместо `max`.

Ответ — `max(bestMax, total - bestMin)`, с одной ловушкой: если все числа отрицательны, «выбросить минимальный кусок» означает выбросить весь массив, а пустой ответ запрещён.

## Техники

### Алгоритм Кадане (для максимума и для минимума)

**Что это.** Однопроходное ДП: `cur` — лучшая сумма отрезка, оканчивающегося на текущем элементе; на каждом шаге решаем, продолжить отрезок или начать заново: `cur = max(x, cur + x)`. Ответ — максимум `cur` за весь проход. Заменив `max` на `min`, получаем отрезок с **наименьшей** суммой.

**Когда применять.** Лучший непрерывный отрезок по сумме. Подробнее — во вкладке «Теория» (алгоритм Кадане).

**Как применяется здесь.** В одном цикле одновременно работают два Кадане: `curMax/bestMax` и `curMin/bestMin`, и попутно считается `total`.

### Сведение задачи о кольце к «дополнению»

Общий приём для кольцевых задач: отрезок, идущий через край, — это дополнение к отрезку посередине. Вместо того чтобы искать сложный объект (префикс + суффикс), ищут простой (непрерывный кусок) и вычитают его из целого. Альтернатива — «удвоить» массив и искать лучший отрезок длины не больше `n` (префиксные суммы + монотонная дека), но это сложнее и требует `O(n)` памяти.

## Разбор кода

```ts
function maxSubarraySumCircular(nums: number[]): number {
  let total = 0;
```

`total` — сумма всего массива, понадобится для случая «через край».

```ts
  // Кадане для максимума: лучший обычный (не кольцевой) подмассив
  let curMax = 0;
  let bestMax = -Infinity;
```

Стандартная инициализация Кадане: `curMax = 0` — «пустой отрезок до начала» (на первом шаге `max(x, 0 + x) = x`), `bestMax = -Infinity`, чтобы на массиве из отрицательных чисел ответом стал наибольший элемент, а не `0`.

```ts
  // Кадане для минимума: самый «плохой» подмассив,
  // который выгоднее всего выкинуть из середины
  let curMin = 0;
  let bestMin = Infinity;
```

Зеркально для минимума: `bestMin = Infinity`, чтобы первый же `curMin` его заменил.

```ts
  for (const x of nums) {
    curMax = Math.max(x, curMax + x);
    bestMax = Math.max(bestMax, curMax);

    curMin = Math.min(x, curMin + x);
    bestMin = Math.min(bestMin, curMin);

    total += x;
  }
```

Один проход — три величины. Первая пара строк — обычный Кадане: продолжить отрезок или начать с `x`. Вторая пара — Кадане для минимума: если накопленная сумма **положительна**, она только увеличила бы минимум, и мы начинаем заново с `x`.

```ts
  // Все числа отрицательные: total - bestMin = 0 соответствовал бы
  // пустому подмассиву, а он запрещён. Ответ — просто наибольший элемент
  if (bestMax < 0) return bestMax;
```

Ловушка. Если все числа отрицательные, минимальный отрезок — весь массив, `bestMin = total`, и `total - bestMin = 0`. Это сумма **пустого** подмассива. Признак ситуации — `bestMax < 0` (лучший непустой отрезок отрицателен, значит, все элементы отрицательны). Тогда ответ — `bestMax`, то есть наибольший элемент.

```ts
  // Либо обычный отрезок, либо отрезок «через край»:
  // весь массив минус минимальный отрезок посередине
  return Math.max(bestMax, total - bestMin);
}
```

Выбираем лучший из двух видов отрезков.

## Трассировка

`nums = [5, -3, 5]`:

```
x= 5: curMax=max( 5, 0+5)=5  bestMax=5   curMin=min( 5, 0+5)= 5  bestMin= 5   total=5
x=-3: curMax=max(-3, 5-3)=2  bestMax=5   curMin=min(-3, 5-3)=-3  bestMin=-3   total=2
x= 5: curMax=max( 5, 2+5)=7  bestMax=7   curMin=min( 5,-3+5)= 2  bestMin=-3   total=7
```

`bestMax = 7 ≥ 0`, поэтому считаем `max(7, 7 - (-3)) = max(7, 10) = 10`. Выброшенный кусок — `[-3]`, взяты последний и первый элементы.

`nums = [1, -2, 3, -2]`: `bestMax = 3` (отрезок `[3]`), `bestMin = -2`, `total = 0`, `total - bestMin = 2`. Ответ `max(3, 2) = 3` — здесь выигрывает обычный отрезок.

`nums = [-3, -2, -3]`: `curMax` принимает `-3, -2, -3`, `bestMax = -2 < 0` → сразу возвращаем `-2`. (Для сравнения: `bestMin = -8 = total`, и `total - bestMin = 0` — тот самый запрещённый пустой ответ.)

## Почему это работает

Любой непустой отрезок кольца либо не пересекает границу между `nums[n-1]` и `nums[0]` (обычный), либо пересекает её. Во втором случае его дополнение — непрерывный отрезок `nums[l..r]` внутри массива, и сумма отрезка равна `total - sum(l..r)`. Максимизация суммы равна минимизации `sum(l..r)`, то есть `total - bestMin`.

Тонкость: `bestMin` может оказаться суммой **всего** массива — тогда `total - bestMin` описывает пустой отрезок. Если `bestMax ≥ 0`, это не страшно: `max(bestMax, 0) = bestMax`, а `bestMax` — реальный непустой отрезок. Если `bestMax < 0`, все элементы отрицательны, любой отрезок через край хуже одного наибольшего элемента, и мы возвращаем `bestMax`. Так что в ответ никогда не попадает пустой подмассив.

## Пограничные случаи

- **Все отрицательные**: обрабатывается проверкой `bestMax < 0`.
- **Один элемент**: `bestMax = bestMin = total = x`; если `x < 0` — возврат `x`, иначе `max(x, 0) = x`.
- **Все положительные**: `bestMax = total`, `bestMin` — наименьший элемент, `total - bestMin < total` — ответ весь массив.
- **Нули**: `[0, -1]` → `bestMax = 0`, проверка `< 0` не срабатывает, ответ `max(0, -1 - (-1)) = 0`, что верно (`[0]`).
- **Переполнения нет**: суммы до `9·10⁸`.

## Сложность

- **Время `O(n)`**: один проход, на каждом элементе константа операций.
- **Память `O(1)`**: пять числовых переменных.

## Типичные ошибки

1. **Забыть проверку `bestMax < 0`** → на массиве из отрицательных чисел ответ `0`.
2. **Проверять `total < 0` вместо `bestMax < 0`** → неверно: `[3, -5]` имеет `total < 0`, но ответ `3`.
3. **Наивно удвоить массив и запустить Кадане** → отрезок может оказаться длиннее `n` и взять элемент дважды.
4. **Инициализировать `bestMax = 0`** → тот же провал на отрицательных данных.
5. **Искать `bestMin` только среди «внутренних» отрезков, исключая края** → лишняя сложность; достаточно стандартного Кадане и проверки на «всё отрицательное».

## Как узнать такую задачу

- «Кольцевой массив», «конец соединён с началом» + лучший непрерывный отрезок.
- Объект «префикс + суффикс» — подумайте о дополнении: «целое минус отрезок посередине».
- Родственные задачи: Maximum Subarray (базовый Кадане), House Robber II (кольцо разбивается на два обычных случая), Maximum Product Subarray, Minimum Size Subarray Sum.
