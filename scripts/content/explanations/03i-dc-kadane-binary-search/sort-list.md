## Задача простыми словами

Дана голова `head` односвязного списка. Нужно отсортировать узлы по возрастанию `val` и вернуть новую голову. Список может быть пустым, а узлов — до `5·10⁴`.

Пример:

```
вход:   4 -> 2 -> 1 -> 3
выход:  1 -> 2 -> 3 -> 4
```

Дополнительный вопрос (follow-up) — уложиться в `O(n log n)` времени и `O(1)` памяти.

## Наивный подход

Первое, что приходит в голову, — сортировка вставками, как её делают на списке: берём узлы по одному и вставляем в уже отсортированную часть, каждый раз проходя её от начала.

```ts naive
const dummy = new ListNode(0);
let cur = head;
while (cur) {
  const next = cur.next;
  let p = dummy;
  while (p.next && p.next.val < cur.val) p = p.next;
  cur.next = p.next;
  p.next = cur;
  cur = next;
}
return dummy.next;
```

Это `O(n²)`: при `5·10⁴` узлов — порядка миллиарда шагов в худшем случае. Лишняя работа — каждая вставка **заново ищет место линейным проходом**, а у списка нет случайного доступа, так что бинарный поиск места не поможет.

Другой «лобовой» путь — переписать значения в массив, вызвать `sort` и записать обратно. Это `O(n log n)`, но `O(n)` дополнительной памяти и, по сути, уход от работы со списком.

## Ключевое наблюдение

Для списков идеально подходит **сортировка слиянием**:

- слить два отсортированных списка можно за линейное время **без новой памяти** — только перевешивая указатели `next`;
- разрезать список пополам тоже легко — середину находят быстрым и медленным указателями, а разрез — это одно присваивание `slow.next = null`.

Делим пополам, рекурсивно сортируем половины, сливаем. Глубина деления `log n`, на каждом уровне суммарно `O(n)` работы — итог `O(n log n)`.

## Техники

### Разделяй и властвуй (сортировка слиянием)

**Что это.** Задачу делят на независимые подзадачи того же вида, решают их рекурсивно, а затем **объединяют** ответы. Три шага: разделить, решить, объединить. Если деление идёт пополам, а объединение линейное, время по рекуррентности `T(n) = 2T(n/2) + O(n)` равно `O(n log n)`.

**Когда применять.** Когда ответ для целого легко собрать из ответов для частей: сортировка, подсчёт инверсий, слияние k списков, построение деревьев по отрезкам.

**Как применяется здесь.** Разделить — найти середину и разорвать список; решить — `sortList` на каждой половине; объединить — `merge`. Подробнее — во вкладке «Теория» (разделяй и властвуй).

### Быстрый и медленный указатели

`slow` шагает на один узел, `fast` — на два. Когда `fast` доходит до конца, `slow` оказывается в середине. Это стандартный способ найти середину списка за один проход без подсчёта длины.

### Фиктивная голова (dummy)

При сборке нового списка первый узел — особый случай: у него нет предшественника. Фиктивный узел `dummy` играет роль предшественника, к нему пришиваем узлы через `tail`, а в конце возвращаем `dummy.next`.

## Разбор кода

```ts
function sortList(head: ListNode | null): ListNode | null {
  // Пустой список или один узел уже отсортированы
  if (!head || !head.next) return head;
```

База рекурсии. Список из `0` или `1` узла сортировать не нужно. Без этой проверки рекурсия на одном узле никогда бы не остановилась.

```ts
  // Ищем середину: fast стартует на шаг впереди,
  // поэтому для чётной длины slow остановится на конце левой половины
  let slow: ListNode = head;
  let fast: ListNode | null = head.next;
  while (fast && fast.next) {
    slow = slow.next!;
    fast = fast.next.next;
  }
```

Поиск середины. Ключевая деталь — `fast = head.next`, а не `head`. Для списка из двух узлов `1 -> 2`: условие `fast.next` сразу ложно, `slow` остаётся на первом узле, и список делится на `[1]` и `[2]`. Если бы `fast` стартовал с `head`, то `slow` сдвинулся бы на второй узел, левая половина получилась бы `[1, 2]`, правая — пустой, и рекурсия на `[1, 2]` повторялась бы бесконечно. `slow.next!` — подсказка TypeScript: раз `fast` впереди и не `null`, у `slow` точно есть следующий узел.

```ts
  // Разрезаем список на две половины
  const right = slow.next;
  slow.next = null;
```

Запоминаем начало правой половины и обрываем связь. Теперь `head` — голова левой половины, которая заканчивается на `slow`.

```ts
  // Сортируем половины рекурсивно и сливаем
  return merge(sortList(head), sortList(right));
}
```

Обе половины сортируются независимо, а `merge` объединяет их в один отсортированный список.

```ts
// Слияние двух отсортированных списков
function merge(a: ListNode | null, b: ListNode | null): ListNode | null {
  // Фиктивная голова избавляет от особого случая для первого узла
  const dummy = new ListNode(0);
  let tail = dummy;
```

`tail` всегда указывает на последний узел собранного результата. Изначально результат пуст, и хвост — это `dummy`.

```ts
  while (a && b) {
    // Берём меньший узел (при равенстве — из a, сортировка устойчива)
    if (a.val <= b.val) {
      tail.next = a;
      a = a.next;
    } else {
      tail.next = b;
      b = b.next;
    }
    tail = tail.next;
  }
```

Пока оба списка непусты, сравниваем их головы, меньшую пришиваем к хвосту и продвигаем соответствующий указатель. Новые узлы не создаются — мы переиспользуем существующие. `<=` делает сортировку устойчивой: при равных значениях раньше идёт узел из левой половины.

```ts
  // Остаток одного из списков уже отсортирован — пришиваем целиком
  tail.next = a ?? b;
  return dummy.next;
}
```

Когда один список кончился, второй (если что-то осталось) уже отсортирован и больше всего собранного — подвешиваем его одним присваиванием. Возвращаем `dummy.next` — настоящую голову.

## Трассировка

`head = 4 -> 2 -> 1 -> 3`.

1. `sortList(4,2,1,3)`: `slow = 4`, `fast = 2`. Шаг цикла: `slow = 2`, `fast = 3`. У `fast` нет `next` — стоп. `right = 1`, разрыв после `2`: половины `4 -> 2` и `1 -> 3`.
2. `sortList(4,2)`: `slow = 4`, `fast = 2`, `fast.next = null` — цикл не выполняется. Половины `4` и `2`, обе — база. `merge(4, 2)`: `4 <= 2` нет → берём `2`; `b` пуст → пришиваем `4`. Результат `2 -> 4`.
3. `sortList(1,3)`: аналогично половины `1` и `3`, `merge` даёт `1 -> 3`.
4. `merge(2->4, 1->3)`:

```
a=2, b=1: 2<=1? нет → берём 1        результат: 1
a=2, b=3: 2<=3? да  → берём 2        результат: 1 2
a=4, b=3: 4<=3? нет → берём 3        результат: 1 2 3
b пуст → tail.next = a (4)           результат: 1 2 3 4
```

Ответ `1 -> 2 -> 3 -> 4`.

## Почему это работает

По индукции по длине списка. Списки длины `0` и `1` отсортированы (база). Для длины `n ≥ 2` разрез даёт две **непустые** половины длины меньше `n` (`fast` стартует с `head.next`, поэтому `slow` никогда не становится последним узлом). По предположению индукции рекурсивные вызовы возвращают их отсортированными.

Инвариант `merge`: собранный список `dummy.next..tail` отсортирован и содержит наименьшие из ещё не взятых элементов обоих списков. Каждый раз берём меньшую из двух голов — это минимум всех оставшихся, так что порядок сохраняется. Остаток одного списка не меньше всего взятого, поэтому пришивание целиком корректно.

## Пограничные случаи

- **Пустой список**: `!head` — сразу возвращаем `null`.
- **Один узел**: `!head.next` — возвращаем как есть.
- **Два узла**: благодаря старту `fast = head.next` делятся на два одиночных, бесконечной рекурсии нет.
- **Одинаковые значения**: `<=` в `merge` — порядок равных сохраняется, ничего не теряется.
- **Уже отсортированный или обратный список**: время всё равно `O(n log n)` — сортировка слиянием не зависит от исходного порядка.

## Сложность

- **Время `O(n log n)`**: каждый уровень рекурсии делит списки пополам, уровней `log n`. На каждом уровне поиск середин и слияния суммарно проходят все `n` узлов.
- **Память `O(log n)`**: узлы не копируются, тратится только стек рекурсии глубиной `log n`. Строгое `O(1)` из follow-up достигается восходящей (итеративной) сортировкой слиянием: сливаем отрезки длины 1, 2, 4… без рекурсии.

## Типичные ошибки

1. **`fast = head` вместо `head.next`** → на списке из двух узлов левая половина равна всему списку, бесконечная рекурсия.
2. **Забыть `slow.next = null`** → левая «половина» на самом деле весь список, рекурсия не уменьшается.
3. **Не пришить остаток** (`tail.next = a ?? b`) → хвост одного из списков теряется.
4. **Создавать новые узлы при слиянии** → лишняя память `O(n)`; достаточно перевешивать указатели.
5. **Выбрать быструю сортировку** → у списка нет случайного доступа к опорному, и худший случай `O(n²)`.

## Как узнать такую задачу

- Нужно **отсортировать связный список** или получить `O(n log n)` на структуре без случайного доступа — почти всегда сортировка слиянием.
- Есть операция «объединить две отсортированные части» за линейное время — признак разделяй и властвуй.
- Родственные задачи: Merge Two Sorted Lists (функция `merge`), Merge k Sorted Lists, Middle of the Linked List (быстрый/медленный указатели), подсчёт инверсий в массиве.
