## Задача простыми словами

Был отсортированный по возрастанию массив **различных** чисел, и его прокрутили от `1` до `n` раз (прокрутка на `n` возвращает исходный порядок). Нужно найти минимальный элемент за `O(log n)`.

Примеры: `[3, 4, 5, 1, 2]` → `1`; `[4, 5, 6, 7, 0, 1, 2]` → `0`; `[11, 13, 15, 17]` (прокрутка на `n`, массив «как был») → `11`.

## Наивный подход

Пройти весь массив и взять минимум:

```ts naive
let min = nums[0];
for (const x of nums) min = Math.min(min, x);
return min;
```

Это `O(n)`. Чуть умнее — найти первый «излом» `nums[i] > nums[i + 1]` и вернуть `nums[i + 1]`, но это тоже линейно. Лишняя работа: мы просматриваем элементы, про которые по одному сравнению уже можно сказать, что минимума среди них нет.

## Ключевое наблюдение

Прокрученный массив — два возрастающих куска, причём **все** элементы левого куска больше **всех** элементов правого:

```
[ 4  5  6  7 | 0  1  2 ]
  большие       малые
```

Минимум — первый элемент правого куска. Сравним середину с **правым краем** отрезка:

- `nums[mid] > nums[hi]` — `mid` в левом (большом) куске, излом где-то между `mid` и `hi`. Минимум строго правее `mid`.
- `nums[mid] < nums[hi]` — отрезок `[mid, hi]` возрастает, минимум на нём — сам `nums[mid]`, а настоящий минимум — `mid` или левее.

Каждое сравнение отбрасывает половину.

## Техники

### Бинарный поиск по признаку (сужение до точки)

**Что это.** Бинарный поиск ищет не значение, а **позицию**, где меняется некоторое свойство. Здесь свойство — «элемент меньше или равен `nums[hi]`»: оно ложно на левом куске и истинно на правом, а минимум — первая позиция, где оно истинно.

**Типичный шаблон:**

```ts naive
let lo = 0, hi = n - 1;
while (lo < hi) {
  const mid = lo + ((hi - lo) >> 1);
  if (ответСтрогоПравее(mid)) lo = mid + 1;
  else hi = mid;          // mid ещё может быть ответом
}
return lo;
```

Условие `lo < hi` и `hi = mid` сжимают отрезок до одной точки, не теряя кандидата. Подробнее о вариантах бинарного поиска — во вкладке «Теория».

**Как применяется здесь.** «Ответ строго правее» ⇔ `nums[mid] > nums[hi]`.

### Выбор опорной точки для сравнения

Важно, **с чем** сравнивать середину. Сравнение с левым краем `nums[lo]` неоднозначно: и в неповёрнутом массиве, и когда `mid` в левом куске, выполняется `nums[lo] < nums[mid]`, но минимум в первом случае слева, а во втором — справа. Правый край такой неоднозначности не даёт: `nums[mid] > nums[hi]` возможно только при изломе между ними.

## Разбор кода

```ts
function findMin(nums: number[]): number {
  let lo = 0;
  let hi = nums.length - 1;
```

Отрезок поиска — весь массив, обе границы включены.

```ts
  // Минимум всегда лежит на отрезке [lo, hi]
  while (lo < hi) {
    const mid = lo + ((hi - lo) >> 1);
```

Цикл, пока кандидатов больше одного. Середина округляется вниз, поэтому при `lo < hi` всегда `mid < hi`, и `mid` никогда не совпадает с `hi` — сравнение `nums[mid]` с `nums[hi]` всегда сравнивает два разных элемента.

```ts
    if (nums[mid] > nums[hi]) {
      // Между mid и hi есть «излом» — минимум строго правее mid
      lo = mid + 1;
```

Середина больше правого края — значит, на отрезке `[mid, hi]` значения где-то «падают», `mid` лежит в большом куске и минимумом быть не может. Исключаем его: `lo = mid + 1`.

```ts
    } else {
      // Отрезок [mid, hi] возрастает — минимум это mid или левее
      hi = mid;
    }
  }
```

Иначе (`nums[mid] < nums[hi]`, равенства нет — элементы различны) отрезок `[mid, hi]` возрастает, и всё правее `mid` больше `nums[mid]`. Отбрасываем правую часть, но **оставляем** `mid`: `hi = mid`, а не `mid - 1`.

```ts
  return nums[lo];
}
```

Отрезок сжался до одного элемента — это минимум. Возвращаем значение, а не индекс.

## Трассировка

`nums = [4, 5, 6, 7, 0, 1, 2]`, `lo = 0`, `hi = 6`:

```
mid=3: nums[3]=7 > nums[6]=2 → излом правее, lo=4
mid=5: nums[5]=1 > nums[6]=2? нет → hi=5
mid=4: nums[4]=0 > nums[5]=1? нет → hi=4
lo=hi=4 → ответ nums[4]=0
```

`nums = [3, 4, 5, 1, 2]`: `mid = 2` (`5 > 2`) → `lo = 3`; `mid = 3` (`1 > 2`? нет) → `hi = 3`. Ответ `1`.

`nums = [11, 13, 15, 17]` (не прокручен): `mid = 1` (`13 > 17`? нет) → `hi = 1`; `mid = 0` (`11 > 13`? нет) → `hi = 0`. Ответ `11` — всё время срабатывает вторая ветка, и поиск доходит до начала.

## Почему это работает

Инвариант: индекс минимума лежит в `[lo, hi]`.

- В начале это весь массив.
- Если `nums[mid] > nums[hi]`, то на `[mid, hi]` есть спад, то есть `mid` — в большом куске, а минимум (начало малого куска) — правее `mid` и не правее `hi`. Сдвиг `lo = mid + 1` его сохраняет.
- Если `nums[mid] < nums[hi]`, то на `[mid, hi]` спада нет (иначе `nums[hi]` был бы в малом куске, а `nums[mid]` — в большом, и тогда `nums[mid] > nums[hi]`). Значит, `[mid, hi]` возрастает, минимум отрезка `[lo, hi]` лежит в `[lo, mid]`. Сдвиг `hi = mid` его сохраняет.

Отрезок строго уменьшается (`lo` растёт или `hi` уменьшается, так как `mid < hi`), и при одном оставшемся элементе это минимум.

## Пограничные случаи

- **Массив не прокручен** (прокрутка на `n`): всегда вторая ветка, ответ `nums[0]`.
- **Один элемент**: цикл не выполняется, ответ `nums[0]`.
- **Два элемента** `[2, 1]`: `mid = 0`, `2 > 1` → `lo = 1`, ответ `1`.
- **Минимум в самом конце** (`[2, 3, 4, 5, 1]`): серия сдвигов `lo` до последнего индекса.
- **Отрицательные числа**: сравнения работают для любых значений.

## Сложность

- **Время `O(log n)`**: каждая итерация сокращает отрезок примерно вдвое.
- **Память `O(1)`**: два индекса и середина.

## Типичные ошибки

1. **`hi = mid - 1`** во второй ветке → теряется минимум, если он в `mid`.
2. **Сравнение с `nums[lo]`** → неоднозначность на неповёрнутом массиве, неверный ответ.
3. **`while (lo <= hi)` вместе с `hi = mid`** → бесконечный цикл при `lo === hi`.
4. **Вернуть `lo` вместо `nums[lo]`** → задача просит значение, а не индекс.
5. **Применять без изменений к массиву с дубликатами** (задача II): при `nums[mid] === nums[hi]` направление неизвестно, нужно `hi--`, и худший случай становится `O(n)`.

## Как узнать такую задачу

- «Отсортированный и прокрученный массив», «найти точку сдвига», «найти минимум/максимум» за `O(log n)`.
- Массив из двух отсортированных кусков, где один кусок целиком больше другого.
- Найденный индекс минимума — это величина сдвига; с ним Search in Rotated Sorted Array сводится к обычному бинарному поиску.
