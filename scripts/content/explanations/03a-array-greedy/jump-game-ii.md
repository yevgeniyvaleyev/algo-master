## Задача простыми словами

Стоим на индексе `0` массива `nums`; из позиции `i` можно прыгнуть вперёд на любое расстояние от `0` до `nums[i]`. Гарантируется, что до последнего индекса добраться можно. Нужно вернуть **минимальное число прыжков**.

Пример: `nums = [2, 3, 1, 1, 4]`. Путь `0 → 1 → 4` — два прыжка, быстрее нельзя (за один прыжок дотягиваемся только до индекса `2`). Ответ `2`.

## Наивный подход

Динамическое программирование: `dp[i]` — минимум прыжков до индекса `i`. Из каждого `i` обновляем все точки, куда можно прыгнуть:

```ts naive
const dp = new Array(nums.length).fill(Infinity);
dp[0] = 0;
for (let i = 0; i < nums.length; i++) {
  for (let j = i + 1; j <= i + nums[i] && j < nums.length; j++) {
    dp[j] = Math.min(dp[j], dp[i] + 1);
  }
}
return dp[nums.length - 1];
```

Это `O(n · max(nums))`, до `O(n²)`, и `O(n)` памяти. Лишняя работа: мы честно вычисляем ответ для **каждого** индекса и многократно перезаписываем одни и те же ячейки. Но значения `dp` устроены очень просто — они **неубывают** слева направо и идут «ступеньками»: несколько индексов с `dp = 1`, потом несколько с `dp = 2` и т. д. Хватит знать, где кончается каждая ступенька.

## Ключевое наблюдение

Посмотрим на задачу как на поиск кратчайшего пути в графе (индексы — вершины, прыжки — рёбра). Кратчайший путь ищет BFS, который обходит граф **уровнями**: уровень `j` — вершины, достижимые ровно за `j` прыжков.

Здесь уровни — это **непрерывные отрезки** массива (как в Jump Game: если достижим индекс, достижимы и все левее). Уровень `0` — `[0, 0]`. Уровень `j + 1` начинается сразу после конца уровня `j` и кончается на максимуме `i + nums[i]` по всем `i` из уровня `j`. Поэтому очередь не нужна: достаточно идти слева направо и помнить два числа — конец текущего уровня и самую дальнюю точку следующего.

## Техники

### BFS по уровням без очереди (неявный граф)

**Что это.** BFS находит кратчайшие пути в невзвешенном графе, обрабатывая вершины слоями по расстоянию. Обычно слой хранится в очереди, но если слои — это непрерывные отрезки массива, вместо очереди хватает двух границ.

**Типичный шаблон.**

```ts naive
let level = 0, end = 0, next = 0;
for (let i = 0; i < n - 1; i++) {
  next = Math.max(next, reach(i)); // расширяем следующий слой
  if (i === end) { level++; end = next; } // текущий слой исчерпан
}
```

**Как применяется здесь.** `jumps` — номер слоя, `currentEnd` — правая граница текущего слоя, `farthest` — правая граница следующего.

### Жадный выбор

Мы не решаем, с **какой** точки слоя прыгать. Достаточно знать, что из слоя можно дотянуться до `farthest`, — и считать, что прыжок сделан из лучшей точки. Это жадность по дальности, как и в Jump Game. Подробнее о жадных алгоритмах — во вкладке «Теория».

## Разбор кода

```ts
function jump(nums: number[]): number {
  let jumps = 0;
  let currentEnd = 0; // правая граница зоны, достижимой за jumps прыжков
  let farthest = 0; // самый дальний индекс, достижимый за jumps + 1 прыжков
```

Начальное состояние: сделано `0` прыжков, достижим только индекс `0` (текущий уровень — `[0, 0]`), следующий уровень ещё не известен.

```ts
  // Последний индекс не перебираем: прыгать из него уже не нужно
  for (let i = 0; i < nums.length - 1; i++) {
```

Идём по всем индексам, кроме последнего. Почему без последнего: проверка `i === currentEnd` на последнем индексе засчитала бы прыжок **из** финиша, который не нужен. Например, для `[0]` (уже на месте) цикл не выполняется вовсе, и ответ — `0`.

```ts
    // Из любой точки текущего «уровня» пробуем прыгнуть как можно дальше
    farthest = Math.max(farthest, i + nums[i]);
```

Каждая точка `i`, которую мы проходим, принадлежит текущему уровню. Из неё можно дотянуться до `i + nums[i]` — обновляем границу следующего уровня.

```ts
    // Дошли до конца текущего уровня — нужен ещё один прыжок
    if (i === currentEnd) {
      jumps++;
      currentEnd = farthest;
      // Новый уровень уже накрывает последний индекс
      if (currentEnd >= nums.length - 1) break;
    }
  }
```

Когда `i` дошёл до правой границы текущего уровня, все его точки просмотрены, и `farthest` — окончательная граница следующего. «Совершаем» прыжок: увеличиваем счётчик и переходим на новый уровень (`currentEnd = farthest`). Если новый уровень уже накрывает финиш, дальше считать незачем — `break`.

Гарантия достижимости важна: благодаря ей `farthest` всегда строго больше `currentEnd` в момент перехода, и цикл не застревает.

```ts
  return jumps;
}
```

Номер уровня, содержащего последний индекс, — это и есть минимальное число прыжков.

## Трассировка

`nums = [2, 3, 1, 1, 4]`, цикл по `i = 0..3`:

1. `i = 0`: `farthest = max(0, 0 + 2) = 2`. `i === currentEnd (0)` → `jumps = 1`, `currentEnd = 2`. `2 >= 4`? Нет.
2. `i = 1`: `farthest = max(2, 1 + 3) = 4`. `1 === 2`? Нет.
3. `i = 2`: `farthest = max(4, 2 + 1) = 4`. `2 === 2` → `jumps = 2`, `currentEnd = 4`. `4 >= 4` → `break`.

Ответ `2`. Уровни: `[0]`, `[1, 2]`, `[3, 4]`.

`nums = [1, 2, 1, 1, 1]`:

```
i=0: farthest=1; i==currentEnd(0) → jumps=1, currentEnd=1
i=1: farthest=3; i==currentEnd(1) → jumps=2, currentEnd=3
i=2: farthest=max(3, 3)=3
i=3: farthest=max(3, 4)=4; i==currentEnd(3) → jumps=3, currentEnd=4 → break
```

Ответ `3`: `0 → 1 → 3 → 4`.

## Почему это работает

Утверждение: после того как обработан конец уровня с номером `j - 1`, отрезок `(конец уровня j-1, currentEnd]` — это в точности индексы, минимальное число прыжков до которых равно `j`.

- Любая точка, достижимая за `j` прыжков, достижима одним прыжком из точки уровня `≤ j - 1`, а значит лежит не дальше максимума `i + nums[i]` по этим точкам — это и есть `farthest` в момент перехода.
- Любая точка до `farthest` достижима за `j` прыжков: есть точка `i` из предыдущих уровней с `i + nums[i] >= farthest`, а прыжок можно укоротить.

Поэтому `jumps` в момент, когда `currentEnd` впервые накрывает последний индекс, — номер его уровня, то есть минимальное число прыжков. Меньше быть не может: за `jumps - 1` прыжков дальше предыдущей границы не добраться.

## Пограничные случаи

- **Один элемент**: цикл пуст, ответ `0`.
- **Первый прыжок сразу накрывает финиш** (`[5, 1, 1]`): на `i = 0` `jumps = 1`, `currentEnd = 5 >= 2` → `break`.
- **Нули внутри** (`[2, 3, 0, 1, 4]`): ноль просто не расширяет `farthest`, но через него перепрыгивают из соседних точек уровня. Ответ `2`.
- **Все единицы** (`[1, 1, 1, 1]`): каждый уровень из одной точки, ответ `n - 1 = 3`.
- **Недостижимый финиш** по условию не встречается; иначе `farthest` перестал бы расти, и код вернул бы неверное число.

## Сложность

- **Время `O(n)`**: один проход, на каждом шаге `O(1)` работы.
- **Память `O(1)`**: три переменные.

## Типичные ошибки

1. **Цикл до `nums.length` вместо `nums.length - 1`** → на `[0]` получится `1` вместо `0`: проверка `i === currentEnd` сработает на финише.
2. **Всегда прыгать на максимальную длину** — на `[2, 3, 1, 1, 4]` прыжок `0 → 2` даёт путь `0 → 2 → 3 → 4` из трёх прыжков вместо двух.
3. **Увеличивать `jumps` при каждом обновлении `farthest`** — прыжок засчитывается только на границе уровня.
4. **Обновлять `currentEnd` сразу на `i + nums[i]`** вместо `farthest` — граница уровня должна быть максимумом по **всему** уровню.
5. **Путать с Jump Game I**: там вопрос «можно ли», здесь «за сколько», и нужна вторая граница.

## Как узнать такую задачу

- «Минимальное число шагов/прыжков», а из позиции можно продвинуться **на любое расстояние до** `x` — BFS, где уровни — отрезки; хватает двух указателей-границ.
- Достижимость гарантирована, и нужен `O(n)` вместо очевидного `O(n²)` ДП.
- Родственные: Jump Game, Video Stitching, Minimum Number of Taps to Open to Water a Garden, Minimum Number of Refueling Stops.
