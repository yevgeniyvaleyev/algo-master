## Задача простыми словами

Стоим на индексе `0` массива `nums`. Из позиции `i` можно прыгнуть вперёд на любое расстояние от `0` до `nums[i]`. Нужно ответить: можно ли добраться до **последнего** индекса?

Пример: `nums = [2, 3, 1, 1, 4]` — да: `0 → 1 → 4`. А `nums = [3, 2, 1, 0, 4]` — нет: любой путь упирается в индекс `3`, где `nums[3] = 0`.

## Наивный подход

Помечать достижимые индексы: из каждого достижимого `i` отмечаем все `i + 1 .. i + nums[i]`.

```ts naive
const reachable = new Array(nums.length).fill(false);
reachable[0] = true;
for (let i = 0; i < nums.length; i++) {
  if (!reachable[i]) continue;
  for (let j = i + 1; j <= i + nums[i] && j < nums.length; j++) {
    reachable[j] = true;
  }
}
return reachable[nums.length - 1];
```

Это `O(n · max(nums))`, в худшем случае `O(n²)`, плюс `O(n)` памяти. Лишняя работа: одни и те же индексы помечаются снова и снова — из `i` и из `i + 1` мы отмечаем почти тот же отрезок. А сам массив `reachable` всегда выглядит как `true, true, ..., true, false, ..., false` — хранить его поэлементно незачем.

## Ключевое наблюдение

Множество достижимых индексов — это всегда **отрезок от `0`** до некоторой границы `farthest`. Если можно добраться до `j`, то можно и до любого `i < j`: на пути к `j` мы прыгали «через» `i`, а прыжок разрешено укоротить.

Значит, вся информация сжимается в **одно число** — `farthest`. Идём слева направо: пока `i <= farthest`, индекс достижим, и из него граница расширяется до `i + nums[i]`. Если `i` оказался правее границы — дальше пути нет.

## Техники

### Жадный алгоритм: поддержка максимальной дальности

**Что это.** Жадный алгоритм на каждом шаге делает локально лучший выбор, не пересматривая его. Здесь «выбор» — расширять границу досягаемости до максимума из того, что даёт каждая достижимая точка. Мы не решаем, **куда** именно прыгать, — достаточно знать, **докуда** можно дотянуться.

**Типичный шаблон.** Один проход слева направо с переменной «текущий максимум охвата». Встречается в задачах о покрытии отрезками, прыжках, интервалах:

```ts naive
let reach = 0;
for (let i = 0; i < n; i++) {
  if (i > reach) return false; // дыра в покрытии
  reach = Math.max(reach, i + len[i]);
}
```

**Как применяется здесь.** `farthest` — правая граница отрезка достижимых индексов. Подробнее о жадных алгоритмах — во вкладке «Теория».

### Ранний выход

Как только граница накрыла последний индекс, ответ известен — дальше проверять нечего. Аналогично, как только найдена «дыра», ответ `false`.

## Разбор кода

```ts
function canJump(nums: number[]): boolean {
  // Самый дальний индекс, до которого точно можно добраться
  let farthest = 0;
```

Изначально достижим только стартовый индекс `0`, поэтому граница — `0`.

```ts
  for (let i = 0; i < nums.length; i++) {
    // Индекс i недостижим — значит, и все дальше тоже
    if (i > farthest) return false;
```

Проверяем, лежит ли `i` внутри достижимого отрезка `[0, farthest]`. Если нет — ни одна из уже просмотренных позиций не дотягивается до `i`, а позиции правее `i` сами недостижимы и помочь не могут. Застряли.

```ts
    // Из i можно допрыгнуть до i + nums[i] — расширяем зону досягаемости
    farthest = Math.max(farthest, i + nums[i]);
```

Индекс `i` достижим, значит из него можно прыгнуть на любое место до `i + nums[i]`. Расширяем границу, если это дальше текущей. `Math.max` нужен, потому что маленький `nums[i]` не должен «сжимать» уже достигнутую границу.

```ts
    // Последний индекс уже в зоне досягаемости
    if (farthest >= nums.length - 1) return true;
  }
```

Граница дошла до последнего индекса или перешагнула его — ответ `true`. Перешагнуть не страшно: прыжок можно укоротить.

```ts
  return true;
}
```

Эта строка фактически недостижима при непустом массиве: на последнем индексе либо сработает `return false` (он вне границы), либо `farthest >= n - 1` даст `return true`. Она нужна, чтобы TypeScript видел возврат на всех путях.

## Трассировка

`nums = [2, 3, 1, 1, 4]`, `n - 1 = 4`:

1. `i = 0`: `0 > 0`? Нет. `farthest = max(0, 0 + 2) = 2`. `2 >= 4`? Нет.
2. `i = 1`: `1 > 2`? Нет. `farthest = max(2, 1 + 3) = 4`. `4 >= 4`? Да → `true`.

`nums = [3, 2, 1, 0, 4]`:

1. `i = 0`: `farthest = max(0, 3) = 3`. `3 >= 4`? Нет.
2. `i = 1`: `farthest = max(3, 1 + 2) = 3`.
3. `i = 2`: `farthest = max(3, 2 + 1) = 3`.
4. `i = 3`: `farthest = max(3, 3 + 0) = 3`.
5. `i = 4`: `4 > 3`? Да → `false`.

Все позиции `0..3` «упираются» в индекс `3`, и ноль на нём не даёт пройти дальше.

## Почему это работает

Инвариант: перед обработкой индекса `i` переменная `farthest` равна максимуму `j + nums[j]` по всем `j < i` (и не меньше `0`), а все индексы `0..farthest` достижимы.

- Если `i <= farthest`, то `i` достижим (по инварианту), и из него можно попасть в любую точку до `i + nums[i]`. Обновление сохраняет инвариант.
- Если `i > farthest`, то ни один индекс `j < i` не дотягивается до `i` и дальше. Любой путь к последнему индексу должен когда-то впервые оказаться на позиции `>= i`, а сделать этот шаг можно только с позиции `< i` — но оттуда так далеко не допрыгнуть. Значит, последний индекс недостижим.

Оба ответа поэтому верны.

## Пограничные случаи

- **Один элемент** (`[0]`): на `i = 0` граница `0 >= 0` → `true`. Мы уже на месте.
- **Ноль в начале** (`[0, 1]`): `farthest = 0`, на `i = 1` срабатывает `1 > 0` → `false`.
- **Ноль, который можно перепрыгнуть** (`[2, 0, 0]`): с индекса `0` граница сразу `2` → `true`.
- **Огромные значения** (до `10⁵`): `i + nums[i]` не переполняется в JS.
- **Последний элемент равен `0`**: неважно — прыгать из него не нужно.

## Сложность

- **Время `O(n)`**: один проход, на каждом индексе `O(1)` работы.
- **Память `O(1)`**: одна переменная `farthest`.

## Типичные ошибки

1. **Обновлять `farthest` без проверки `i > farthest`** → граница «расширяется» из недостижимых позиций, и на `[3, 2, 1, 0, 4]` получится `true`.
2. **Присваивать `farthest = i + nums[i]` без `Math.max`** → маленькое значение затирает уже достигнутую границу.
3. **Всегда прыгать на максимум `nums[i]`** — жадность «по прыжку» неверна: на `[2, 3, 0, 1, 4]` прыжок на 2 ведёт на индекс `2` с `nums[2] = 0` и застревает, хотя путь `0 → 1 → 4` существует. Жадность нужна по **границе**, а не по одиночному прыжку.
4. **Сравнивать с `nums.length` вместо `nums.length - 1`** — граница может равняться последнему индексу, этого достаточно.
5. **DFS/BFS по всем прыжкам без отметок** — экспоненциальное время.

## Как узнать такую задачу

- «Из позиции можно продвинуться **на любое расстояние до** `x`», «достижимо ли конечное состояние» — достижимые позиции образуют отрезок, достаточно хранить его границу.
- Вопрос «да/нет» о покрытии отрезка интервалами `[i, i + nums[i]]`.
- Родственные: Jump Game II (минимум прыжков, тот же приём с «уровнями»), Video Stitching, Minimum Number of Taps to Open to Water a Garden.
