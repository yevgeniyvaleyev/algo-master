## Задача простыми словами

По кругу стоят `n` заправок. На заправке `i` можно залить `gas[i]` топлива, а дорога от неё до следующей стоит `cost[i]`. Стартуем с пустым баком (бак бесконечный). Нужно найти заправку, с которой можно объехать весь круг, или вернуть `-1`. Если ответ есть, он единственный.

Пример: `gas = [1, 2, 3, 4, 5]`, `cost = [3, 4, 5, 1, 2]`. Со старта `3`: бак `4 → 8 → 7 → 6 → 5`, и последнего участка (стоимость `5`) хватает ровно. Ответ `3`.

## Наивный подход

Попробовать каждую заправку как старт и честно проехать круг:

```ts naive
for (let start = 0; start < n; start++) {
  let tank = 0;
  let ok = true;
  for (let step = 0; step < n; step++) {
    const i = (start + step) % n;
    tank += gas[i] - cost[i];
    if (tank < 0) { ok = false; break; }
  }
  if (ok) return start;
}
return -1;
```

Это `O(n²)`: при `n = 10⁵` — до 10 миллиардов шагов. Лишняя работа: стартовав с `start` и провалившись на участке `i`, мы затем пробуем `start + 1`, `start + 2`, … — и снова проезжаем **те же участки**, хотя можно доказать, что все эти старты обречены провалиться не позже `i`.

## Ключевое наблюдение

Обозначим `diff[i] = gas[i] - cost[i]` — как меняется бак на участке `i → i + 1`.

**Факт 1.** Если `Σ diff < 0`, топлива на круг не хватит ни с какого старта — ответ `-1`.

**Факт 2.** Пусть стартовали с `start` и бак впервые ушёл в минус после участка `i`. Тогда ни одна заправка из `[start, i]` не годится как старт. На каждую промежуточную заправку `j` мы приезжали с баком `≥ 0`. Стартовав прямо с `j` с пустым баком, мы будем иметь на каждом следующем участке **не больше** топлива, чем раньше, — и тоже провалимся на участке `i` или раньше. Значит, следующий кандидат — сразу `i + 1`.

**Факт 3.** Если `Σ diff >= 0`, то последний кандидат `start` — ответ.

Получается один проход: кандидат «перепрыгивает» через провальные участки, и каждый участок обрабатывается один раз.

## Техники

### Жадный проход с перезапуском кандидата

**Что это.** Жадный алгоритм принимает локальное решение и не пересматривает его. Здесь решение — «отбросить весь отрезок `[start, i]` целиком», как только бак ушёл в минус. Корректность держится на доказательстве, что ни одна точка внутри отрезка не может быть ответом (Факт 2).

**Типичный шаблон.** Накопитель суммы, который **сбрасывается**, когда становится «плохим», вместе с переносом начала отрезка. Тот же скелет у алгоритма Кадане (максимальная сумма подмассива):

```ts naive
let cur = 0, start = 0;
for (let i = 0; i < n; i++) {
  cur += a[i];
  if (cur < 0) { cur = 0; start = i + 1; }
}
```

**Как применяется здесь.** `tank` — накопленный баланс от кандидата `start`; при `tank < 0` кандидат переносится на `i + 1`. Подробнее о жадных алгоритмах — во вкладке «Теория».

### Глобальная проверка суммой

Существование ответа проверяется отдельно и просто — общим балансом `total`. Это разделяет задачу на «есть ли ответ» и «где он», и второе решает жадность.

## Разбор кода

```ts
function canCompleteCircuit(gas: number[], cost: number[]): number {
  let total = 0; // общий баланс топлива за весь круг
  let tank = 0; // топливо в баке с момента текущего кандидата start
  let start = 0; // кандидат на стартовую заправку
```

Три величины: `total` — сумма всех `diff` (для Факта 1), `tank` — сколько топлива было бы в баке, если бы мы стартовали с `start`, `start` — текущий кандидат. Начинаем с кандидата `0`.

```ts
  for (let i = 0; i < gas.length; i++) {
    const diff = gas[i] - cost[i];
    total += diff;
    tank += diff;
```

На заправке `i` заливаем `gas[i]` и тратим `cost[i]` на дорогу к `i + 1`. Изменение добавляем и в общий баланс, и в бак текущего кандидата.

```ts
    // Не доехали от start до i + 1. Ни одна заправка из [start, i]
    // не подходит как старт — следующий кандидат i + 1
    if (tank < 0) {
      start = i + 1;
      tank = 0;
    }
  }
```

Бак ушёл в минус — значит, от `start` не доехать до `i + 1`. По Факту 2 отбрасываем весь отрезок `[start, i]`, новый кандидат — `i + 1`, и он стартует с пустым баком.

Заметьте: проход идёт только до конца массива, без «второго круга». Хвост `[0, start)` проверяется не симуляцией, а через `total`.

```ts
  // Если топлива суммарно меньше, чем расход, круг невозможен.
  // Иначе последний кандидат гарантированно подходит
  return total >= 0 ? start : -1;
}
```

Факт 1 и Факт 3 в одной строке. Если последний сброс случился на последней заправке, то `start = n` — но в этом случае `total` обязательно отрицательный (см. ниже), и вернётся `-1`.

## Трассировка

`gas = [1, 2, 3, 4, 5]`, `cost = [3, 4, 5, 1, 2]`, `diff = [-2, -2, -2, 3, 3]`:

1. `i = 0`: `total = -2`, `tank = -2 < 0` → `start = 1`, `tank = 0`.
2. `i = 1`: `total = -4`, `tank = -2 < 0` → `start = 2`, `tank = 0`.
3. `i = 2`: `total = -6`, `tank = -2 < 0` → `start = 3`, `tank = 0`.
4. `i = 3`: `total = -3`, `tank = 3`.
5. `i = 4`: `total = 0`, `tank = 6`.

`total = 0 >= 0` → ответ `3`.

`gas = [2, 3, 4]`, `cost = [3, 4, 3]`, `diff = [-1, -1, 1]`:

1. `i = 0`: `total = -1`, `tank = -1` → `start = 1`, `tank = 0`.
2. `i = 1`: `total = -2`, `tank = -1` → `start = 2`, `tank = 0`.
3. `i = 2`: `total = -1`, `tank = 1`.

`total = -1 < 0` → ответ `-1`.

## Почему это работает

**Факт 2** подробнее. Пусть от `start` бак неотрицателен на всех участках до `i - 1`, а после `i` впервые отрицателен. Для любого `j` из `(start, i]` сумма `diff[start..j-1] >= 0` (мы доехали до `j`). Тогда `diff[j..i] = diff[start..i] - diff[start..j-1] < 0`: со старта `j` бак тоже уйдёт в минус не позже участка `i`.

**Факт 3.** Пусть итоговый кандидат — `start`, а `T = diff[start..n-1] >= 0` (на этом хвосте сброса не было, и все его частичные суммы неотрицательны). Отрезок `[0, start)` разбит сбросами на блоки, у каждого сумма отрицательна, а частичные суммы внутри блока неотрицательны до последнего элемента. Значит, для любой точки `j` в `[0, start)` сумма `diff[0..j-1]` не меньше суммы всех блоков, то есть не меньше `total - T`. Проехав хвост, мы имеем `T` топлива, и в точке `j` второго отрезка в баке `T + diff[0..j-1] >= T + (total - T) = total >= 0`. Бак нигде не уходит в минус — круг проходится.

Отсюда же: если `start` стал `n`, то весь массив разбит на блоки с отрицательной суммой, `total < 0`, и вернётся `-1`.

## Пограничные случаи

- **Одна заправка**: `gas[0] >= cost[0]` → `0`, иначе `-1`.
- **`total = 0`**: топлива ровно хватает, ответ существует (бак в конце круга пуст).
- **Сброс на последней заправке**: `start = n`, но тогда `total < 0` и ответ `-1`.
- **Все `diff = 0`**: сбросов нет, ответ `0`.
- **Нулевые значения `gas` и `cost`**: допустимы, арифметика обычная.

## Сложность

- **Время `O(n)`**: один проход, на каждом шаге `O(1)`.
- **Память `O(1)`**: три переменные.

## Типичные ошибки

1. **Сбрасывать кандидата на `start + 1`**, а не на `i + 1` — это снова `O(n²)` и теряет смысл Факта 2.
2. **Забыть обнулить `tank`** при смене кандидата — новый старт начинается с пустым баком.
3. **Не считать `total`** и возвращать `start` всегда — на втором примере получится `2` вместо `-1`.
4. **Проверять `tank <= 0`** вместо `< 0`: приехать с пустым баком можно, это не провал. На `gas = [1, 1]`, `cost = [1, 1]` такой код сбросит кандидата дважды и вернёт несуществующий индекс `2` вместо `0`.
5. **Симулировать второй круг** «на всякий случай» — не нужно, хвост покрывается `total`.

## Как узнать такую задачу

- Кольцевой маршрут/массив и «баланс», который не должен уходить в минус, — ищите стартовую точку одним проходом со сбросом.
- Условие «ответ, если существует, единственный» и `n` до `10⁵` — намёк на `O(n)`.
- Общий скелет — «копим, сбрасываем при плохом значении», как в Maximum Subarray (Кадане). Родственные: Maximum Sum Circular Subarray, Minimum Number of Refueling Stops.
