## Задача простыми словами

Дан массив `citations`: `citations[i]` — сколько раз процитирована `i`-я статья. Нужно найти **h-индекс** — наибольшее `h`, при котором есть хотя бы `h` статей, у каждой из которых не меньше `h` цитирований.

Пример: `citations = [3, 0, 6, 1, 5]`. Статей с `≥ 3` цитированиями три (`3, 6, 5`) — значит `h = 3` подходит. Для `h = 4` нужны четыре статьи с `≥ 4`, а их только две (`6, 5`). Ответ `3`.

## Наивный подход

Перебрать все возможные `h` и для каждого посчитать подходящие статьи:

```ts naive
const n = citations.length;
for (let h = n; h >= 0; h--) {
  let papers = 0;
  for (const c of citations) if (c >= h) papers++;
  if (papers >= h) return h;
}
return 0;
```

Это `O(n²)`. Лишняя работа: для каждого `h` мы **заново** просматриваем все статьи, хотя вопрос «сколько статей с `≥ h` цитированиями» легко ответить сразу для всех `h`, если статьи упорядочены по числу цитирований.

## Ключевое наблюдение

Отсортируем статьи **по убыванию** цитирований. Тогда первые `i + 1` статей (индексы `0..i`) — самые цитируемые, и у каждой из них не меньше `sorted[i]` цитирований (`sorted[i]` — наименьшее среди них).

Значит, `h = i + 1` достижим ровно тогда, когда `sorted[i] >= i + 1`: у нас есть `i + 1` статей, и самая слабая из них процитирована хотя бы `i + 1` раз.

Идём по `i` слева направо: пока условие выполняется, ответ растёт на единицу. Как только оно нарушилось, дальше смотреть бессмысленно — цитирования только убывают, а требуемый порог `i + 1` только растёт.

## Техники

### Сортировка как подготовка данных

**Что это.** Многие задачи о «хотя бы `X` элементов со свойством `≥ Y`» становятся простыми, если элементы упорядочить: тогда «лучшие `k` элементов» — это просто первые `k` позиций, а их «худший» — элемент на позиции `k - 1`.

**Типичный шаблон.**

```ts naive
const sorted = [...arr].sort((a, b) => b - a); // по убыванию
for (let i = 0; i < sorted.length; i++) {
  // первые i + 1 элементов — лучшие, sorted[i] — худший из них
}
```

Важно передать компаратор `(a, b) => b - a`: без него `sort` сравнивает числа **как строки** (`[10, 9].sort()` → `[10, 9]`, но `[5, 10].sort()` → `[10, 5]`). Подробнее о работе с массивами — во вкладке «Теория».

**Как применяется здесь.** После сортировки проверка «подходит ли `h = i + 1`» — одно сравнение `sorted[i] >= i + 1`.

### Ранняя остановка по монотонности

Последовательность `sorted[i]` не возрастает, а `i + 1` строго растёт. Поэтому условие `sorted[i] >= i + 1` выполняется на **префиксе** индексов, а потом ломается навсегда. Значит, на первом нарушении можно делать `break` — дальше подходящих `h` нет.

## Разбор кода

```ts
function hIndex(citations: number[]): number {
  // Сортируем по убыванию: самые цитируемые статьи — в начале
  const sorted = [...citations].sort((a, b) => b - a);
```

Копируем массив через `[...citations]`, чтобы не менять входные данные, и сортируем по убыванию числовым компаратором. Для `[3, 0, 6, 1, 5]` получаем `[6, 5, 3, 1, 0]`.

```ts
  let h = 0;
  for (let i = 0; i < sorted.length; i++) {
    // i + 1 статей (с 0-й по i-ю) имеют не меньше sorted[i] цитирований.
    // Если sorted[i] >= i + 1, то h = i + 1 достижим
    if (sorted[i] >= i + 1) {
      h = i + 1;
```

`h` начинается с `0` — этот ответ подходит всегда. На шаге `i` проверяем кандидата `i + 1`: в префиксе ровно `i + 1` статей, наименьшая из них — `sorted[i]`. Если её цитирований хватает, `h = i + 1` достижим, запоминаем.

```ts
    } else {
      // Дальше цитирований только меньше, а нужно больше — останавливаемся
      break;
    }
  }
```

Первое нарушение — конец поиска: для всех следующих `i` значение `sorted[i]` не больше текущего, а порог `i + 1` больше, так что условие больше не выполнится.

```ts
  return h;
}
```

`h` — последний достижимый кандидат, то есть максимальный.

## Трассировка

`citations = [3, 0, 6, 1, 5]` → `sorted = [6, 5, 3, 1, 0]`.

```
i  sorted[i]  i + 1  sorted[i] >= i + 1   h
0  6          1      да                   1
1  5          2      да                   2
2  3          3      да                   3
3  1          4      нет → break          3
```

Ответ `3`.

`citations = [1, 3, 1]` → `sorted = [3, 1, 1]`: `i = 0`: `3 >= 1` → `h = 1`; `i = 1`: `1 >= 2` — нет, `break`. Ответ `1`.

`citations = [4, 4, 4, 4]` → условие выполняется на всех четырёх шагах, цикл заканчивается сам, ответ `4 = n`.

## Почему это работает

После сортировки по убыванию для любого `k` лучшие `k` статей — это `sorted[0..k-1]`, и у каждой из них не меньше `sorted[k - 1]` цитирований. Если `h = k` вообще достижим (есть `k` статей с `≥ k`), то и лучшие `k` статей годятся, то есть `sorted[k - 1] >= k`. Обратно, если `sorted[k - 1] >= k`, эти `k` статей и есть свидетельство. Значит, `h = k` достижим ⇔ `sorted[k - 1] >= k`.

Левая часть не возрастает по `k`, правая растёт, поэтому достижимые `k` образуют отрезок `1..H`. Цикл проходит этот отрезок до первого нарушения и возвращает его правый конец `H` — максимальный h-индекс. Если даже `k = 1` недостижим, `h` остаётся `0`.

## Пограничные случаи

- **Все нули** (`[0, 0, 0]`): уже на `i = 0` условие `0 >= 1` ложно, ответ `0`.
- **Одна статья** (`[0]` → `0`, `[100]` → `1`): одна проверка `sorted[0] >= 1`.
- **Все цитирования огромные** (`[1000, 1000, 1000]`): условие выполняется до конца массива, ответ `n`.
- **Повторяющиеся значения** (`[4, 4, 4, 4]`): сортировка их не различает, всё работает.
- **Ровно на границе** (`[1, 1]`): `i = 0` — `1 >= 1` да; `i = 1` — `1 >= 2` нет → `1`.

## Сложность

- **Время `O(n log n)`**: сортировка; сам цикл — `O(n)`.
- **Память `O(n)`**: отсортированная копия (если сортировать вход на месте — `O(1)` дополнительно, не считая памяти самой сортировки).

**Follow-up на собеседовании: `O(n)` без сортировки — корзины.** Ответ не больше `n`, поэтому значения `> n` можно обрезать до `n` и разложить статьи по корзинам `0..n`, а потом идти по `h` сверху вниз, накапливая число статей с `≥ h`:

```ts naive
const buckets = new Array<number>(n + 1).fill(0);
for (const c of citations) buckets[Math.min(c, n)]++;
let papers = 0;
for (let h = n; h >= 0; h--) {
  papers += buckets[h];
  if (papers >= h) return h;
}
```

## Типичные ошибки

1. **`sort()` без компаратора** → числа сортируются как строки (`[10, 9, 100]` → `[10, 100, 9]`), ответ получается неверным.
2. **Ошибка на единицу**: `sorted[i] >= i` вместо `sorted[i] >= i + 1` — тогда, например, `[0]` даст `h = 1`.
3. **Сортировать по возрастанию** и применять ту же формулу — логика ломается; для возрастающего порядка условие другое: `sorted[i] >= n - i`.
4. **Перепутать определение**: «ровно `h` статей» вместо «хотя бы `h`», или «больше `h` цитирований» вместо «не меньше».
5. **Забыть про случай, когда условие выполняется до конца** — ответ тогда `n`, и он должен вернуться после цикла, а не только из `break`.

## Как узнать такую задачу

- Условие вида «хотя бы `X` элементов со значением `≥ X`» — отсортируйте по убыванию и сравнивайте `sorted[i]` с `i + 1`.
- Монотонное условие по ответу → ранняя остановка или бинарный поиск по ответу.
- Значения — небольшие неотрицательные целые, а ответ лежит в `[0, n]` → можно ускорить до `O(n)` сортировкой подсчётом.
- Родственные: H-Index II (массив уже отсортирован — бинарный поиск), Top K Frequent Elements (корзины по частоте), Sort Colors.
