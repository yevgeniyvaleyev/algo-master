## Задача простыми словами

Дан массив `citations`: `citations[i]` — сколько раз процитирована `i`-я статья. Нужно найти **h-индекс** — наибольшее `h`, при котором есть хотя бы `h` статей, у каждой из которых не меньше `h` цитирований.

Пример: `citations = [3, 0, 6, 1, 5]`. Статей с `≥ 3` цитированиями три (`3, 6, 5`) — значит `h = 3` подходит. Для `h = 4` нужны четыре статьи с `≥ 4`, а их только две (`6, 5`). Ответ `3`.

## Наивный подход

Перебрать все возможные `h` и для каждого посчитать подходящие статьи:

```ts naive
const n = citations.length;
for (let h = n; h >= 0; h--) {
  let papers = 0;
  for (const c of citations) if (c >= h) papers++;
  if (papers >= h) return h;
}
return 0;
```

Это `O(n²)`. Лишняя работа: для каждого `h` мы **заново** пересчитываем все статьи, хотя множество статей с `≥ h` цитированиями при уменьшении `h` только **пополняется**. Достаточно знать, сколько статей имеют ровно `h` цитирований, и накапливать.

Другой вариант — отсортировать по убыванию и найти, где `citations[i]` становится `<= i`. Это `O(n log n)` — уже хорошо, но сортировка делает больше, чем нужно.

## Ключевое наблюдение

1. **Ответ не больше `n`.** Статей всего `n`, значит больше `n` статей с чем бы то ни было не набрать. Поэтому статья со `100` цитированиями при `n = 5` ничем не лучше статьи с `5` — все значения выше `n` можно «обрезать» до `n`.
2. После обрезки значения лежат в диапазоне `0..n`, и их можно разложить по **корзинам** — сортировка подсчётом за `O(n)`.
3. Идём по `h` от `n` вниз и копим `papers` — число статей с `≥ h` цитированиями: это сумма корзин `h..n`. Первый `h`, при котором `papers >= h`, — максимальный.

## Техники

### Сортировка подсчётом (корзины)

**Что это.** Если значения — целые числа из небольшого диапазона `[0, m]`, их не нужно сравнивать между собой: заводим массив счётчиков длины `m + 1` и для каждого значения увеличиваем `count[value]`. Это `O(n + m)` вместо `O(n log n)`.

**Типичный шаблон.** Подсчитать частоты → пройти по корзинам в нужном порядке, накапливая сумму («сколько элементов не меньше / не больше x»). Работает, когда диапазон значений сравним с `n` или его можно к этому свести.

**Как применяется здесь.** Диапазон `0..1000` и так небольшой, но приём «обрезать до `n`» делает его ровно `0..n` — массив корзин не больше входа. Подробнее о работе с массивами — во вкладке «Теория».

### Суффиксные суммы

Число статей с `≥ h` цитированиями — это сумма `buckets[h] + buckets[h + 1] + ... + buckets[n]`. Считая `h` по убыванию, мы получаем каждую такую сумму из предыдущей добавлением одного слагаемого — `O(1)` на шаг.

## Разбор кода

```ts
function hIndex(citations: number[]): number {
  const n = citations.length;

  // h не может быть больше n, поэтому все значения > n считаем как n.
  // buckets[c] — сколько статей имеют c цитирований (c от 0 до n)
  const buckets = new Array<number>(n + 1).fill(0);
```

Корзины для значений `0..n` — всего `n + 1` штука, все пустые.

```ts
  for (const c of citations) {
    buckets[Math.min(c, n)]++;
  }
```

Раскладываем статьи по корзинам. `Math.min(c, n)` — та самая обрезка: всё, что больше `n`, попадает в корзину `n`. Это не искажает ответ, потому что любое `h <= n`, и для него «`≥ h` цитирований» одинаково выполняется и для `c = n`, и для `c = 100`.

```ts
  // Идём от больших h к меньшим и считаем статьи с >= h цитированиями
  let papers = 0;
  for (let h = n; h >= 0; h--) {
    papers += buckets[h];
```

Перебираем кандидатов на ответ от самого большого. Добавляя `buckets[h]`, получаем `papers` = число статей с `≥ h` цитированиями (статьи из корзин `h + 1..n` уже учтены на предыдущих шагах).

```ts
    // Нашлось хотя бы h статей с >= h цитированиями — это максимальный h
    if (papers >= h) return h;
  }
```

Первое `h`, удовлетворяющее определению, — максимальное, потому что мы идём сверху вниз. Возвращаем сразу.

```ts
  return 0;
}
```

На `h = 0` условие `papers >= 0` выполняется всегда, поэтому цикл обязательно вернёт значение. Эта строка — для TypeScript.

## Трассировка

`citations = [3, 0, 6, 1, 5]`, `n = 5`.

Раскладка по корзинам (`6` обрезается до `5`):

```
c=3 → buckets[3]   c=0 → buckets[0]   c=6 → buckets[5]
c=1 → buckets[1]   c=5 → buckets[5]
buckets = [1, 1, 0, 1, 0, 2]   (индексы 0..5)
```

Проход сверху вниз:

1. `h = 5`: `papers = 0 + 2 = 2`. `2 >= 5`? Нет.
2. `h = 4`: `papers = 2 + 0 = 2`. `2 >= 4`? Нет.
3. `h = 3`: `papers = 2 + 1 = 3`. `3 >= 3`? Да → ответ `3`.

`citations = [1, 3, 1]`, `n = 3`: `buckets = [0, 2, 0, 1]`. `h = 3`: `papers = 1`; `h = 2`: `papers = 1`; `h = 1`: `papers = 3 >= 1` → ответ `1`.

## Почему это работает

После шага с номером `h` переменная `papers` равна числу статей с обрезанным значением `≥ h`. Для `h <= n` это то же самое, что число статей с исходным значением `≥ h`: обрезка меняет только значения `> n`, а они и до, и после обрезки `≥ h`.

Функция «число статей с `≥ h` цитированиями» не возрастает с ростом `h`, а правая часть `h` растёт. Поэтому множество подходящих `h` — это отрезок `[0, H]`, и первый подходящий `h` при движении сверху вниз — ровно `H`, максимальный. Значения `h > n` проверять не нужно: для них потребовалось бы больше `n` статей.

## Пограничные случаи

- **Все нули** (`[0, 0]`): `buckets = [2, 0, 0]`, ни `h = 2`, ни `h = 1` не подходят, на `h = 0` ответ `0`.
- **Одна статья** (`[0]` → `0`, `[100]` → `1`): обрезка `100 → 1`, `papers = 1 >= 1`.
- **Все цитирования огромные** (`[1000, 1000, 1000]`): всё в корзине `3`, ответ `3 = n`.
- **Повторяющиеся значения**: корзины считают кратность, ничего особого не нужно.
- **Ровно на границе** (`[1, 1]`): `h = 2` — `papers = 0`; `h = 1` — `papers = 2 >= 1` → `1`.

## Сложность

- **Время `O(n)`**: проход по статьям для раскладки и проход по `n + 1` корзинам.
- **Память `O(n)`**: массив корзин длины `n + 1`.

Вариант с сортировкой — `O(n log n)` времени и `O(1)` дополнительной памяти (если сортировать на месте).

## Типичные ошибки

1. **Не обрезать до `n`** и обращаться к `buckets[c]` при `c > n` — получится `NaN` (`undefined + 1`) или выход за размер массива.
2. **Перепутать определение**: «ровно `h` статей» вместо «хотя бы `h`», или «больше `h` цитирований» вместо «не меньше».
3. **Идти по `h` снизу вверх** и возвращать первый подходящий — это всегда `0`. Снизу вверх нужно искать **последний** подходящий.
4. **В варианте с сортировкой** сравнивать `citations[i] >= i` вместо `citations[i] >= i + 1` (или `> i`) — ошибка на единицу.
5. **Двоичный поиск по `h` с подсчётом за `O(n)`** — работает (`O(n log n)`), но сложнее и медленнее корзин.

## Как узнать такую задачу

- Ответ — число в диапазоне `[0, n]`, а условие формулируется как «хотя бы `X` элементов со значением `≥ X`» — значения выше `n` можно обрезать, затем корзины.
- Значения — небольшие неотрицательные целые → сортировка подсчётом вместо обычной.
- Монотонное условие по `h` → можно и бинарный поиск по ответу.
- Родственные: H-Index II (массив уже отсортирован — бинарный поиск), Top K Frequent Elements (корзины по частоте), Sort Colors.
