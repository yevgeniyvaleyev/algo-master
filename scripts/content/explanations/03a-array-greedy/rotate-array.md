## Задача простыми словами

Дан массив `nums` и число `k`. Нужно **на месте** циклически сдвинуть массив вправо на `k` шагов: элементы, «выпадающие» справа, появляются слева. Функция ничего не возвращает — меняется сам `nums`.

Пример: `nums = [1, 2, 3, 4, 5, 6, 7]`, `k = 3`. Последние три элемента `5, 6, 7` переезжают в начало: `[5, 6, 7, 1, 2, 3, 4]`.

## Наивный подход

Буквально сделать `k` сдвигов на одну позицию:

```ts naive
for (let step = 0; step < k; step++) {
  const last = nums[nums.length - 1];
  for (let i = nums.length - 1; i > 0; i--) nums[i] = nums[i - 1];
  nums[0] = last;
}
```

Это `O(n · k)`: при `n = k = 10⁵` — 10 миллиардов присваиваний. Лишняя работа очевидна: каждый элемент проходит путь в `k` позиций **по одному шагу**, хотя его конечное место известно сразу — `(i + k) % n`.

Можно поставить каждый элемент сразу на место через вспомогательный массив (`res[(i + k) % n] = nums[i]`) — это `O(n)` по времени, но `O(n)` по памяти. Задача же просит `O(1)` памяти.

## Ключевое наблюдение

Разобьём массив на две части: `A` — первые `n - k` элементов, `B` — последние `k`. Поворот превращает `A B` в `B A`. Блоки меняются местами, а порядок **внутри** каждого блока сохраняется.

Разворот всего массива тоже меняет блоки местами, но вдобавок переворачивает каждый из них: `A B` → `rev(B) rev(A)`. Значит, достаточно после этого развернуть каждый блок ещё раз — и получим `B A`. Три разворота, каждый делается на месте двумя указателями.

## Техники

### Разворот отрезка двумя указателями

**Что это.** Два указателя стоят на концах отрезка и идут навстречу, меняя элементы местами, пока не встретятся. Каждый элемент переставляется ровно один раз, дополнительной памяти не нужно.

**Типичный шаблон.**

```ts naive
while (left < right) {
  swap(left, right);
  left++;
  right--;
}
```

Это базовый кирпич для многих задач: развернуть строку, развернуть слова в предложении, проверить палиндром. Подробнее о работе с массивами — во вкладке «Теория».

**Как применяется здесь.** Разворот вызывается три раза на разных отрезках.

### Перестановка двух блоков через развороты

Общий приём: чтобы поменять местами два соседних блока на месте, разверните всё, затем каждый блок по отдельности (или наоборот: сначала блоки, потом всё). Так же решаются «циклический сдвиг строки» и «развернуть порядок слов».

### Нормализация `k %= n`

Поворот на `n` шагов возвращает массив в исходное состояние, поэтому важен только остаток. Без этого при `k > n` индексы выйдут за границы массива.

## Разбор кода

```ts
/**
 Do not return anything, modify nums in-place instead.
 */
function rotate(nums: number[], k: number): void {
  const n = nums.length;
  // Поворот на n шагов возвращает массив в исходное состояние
  k %= n;
  if (k === 0) return;
```

Комментарий-шапка — из шаблона LeetCode: функция меняет массив и ничего не возвращает. Затем нормализуем `k`: при `n = 7`, `k = 10` реальный сдвиг — `3`. Если остаток `0`, массив не меняется, и мы выходим сразу (это заодно спасает от вызова `reverse(0, -1)`, который, впрочем, ничего бы не сделал).

```ts
  // Разворот отрезка nums[left..right] на месте
  const reverse = (left: number, right: number): void => {
    while (left < right) {
      [nums[left], nums[right]] = [nums[right], nums[left]];
      left++;
      right--;
    }
  };
```

Вспомогательная функция разворачивает `nums[left..right]` включительно. Обмен через деструктуризацию `[a, b] = [b, a]` — короткий способ поменять значения без временной переменной. Цикл идёт, пока `left < right`: когда указатели встретились (нечётная длина) или разошлись (чётная), отрезок развёрнут. Стрелочная функция замыкает `nums`, поэтому массив не надо передавать параметром.

```ts
  // 1) Разворачиваем весь массив: последние k элементов оказываются в начале (задом наперёд)
  reverse(0, n - 1);
```

Шаг 1: `A B` → `rev(B) rev(A)`. Блоки уже стоят на своих местах, но перевёрнуты.

```ts
  // 2) Восстанавливаем порядок первых k элементов
  reverse(0, k - 1);
  // 3) Восстанавливаем порядок остальных n - k элементов
  reverse(k, n - 1);
}
```

Шаг 2: первые `k` ячеек — это `rev(B)`, разворачиваем обратно в `B`. Шаг 3: оставшиеся `n - k` ячеек — это `rev(A)`, получаем `A`. Итог: `B A`.

## Трассировка

`nums = [1, 2, 3, 4, 5, 6, 7]`, `k = 3`, `n = 7`. `k %= 7` → `3`. `A = [1, 2, 3, 4]`, `B = [5, 6, 7]`.

```
старт:           [1, 2, 3, 4, 5, 6, 7]
reverse(0, 6):   [7, 6, 5, 4, 3, 2, 1]    rev(B) | rev(A)
reverse(0, 2):   [5, 6, 7, 4, 3, 2, 1]    B      | rev(A)
reverse(3, 6):   [5, 6, 7, 1, 2, 3, 4]    B      | A
```

Внутри `reverse(3, 6)`: меняем `nums[3]` и `nums[6]` (`4` ↔ `1`), затем `nums[4]` и `nums[5]` (`3` ↔ `2`), указатели `5` и `4` разошлись — стоп.

Пример с `k > n`: `nums = [-1, -100, 3, 99]`, `k = 6`. `6 % 4 = 2`.

```
reverse(0, 3):   [99, 3, -100, -1]
reverse(0, 1):   [3, 99, -100, -1]
reverse(2, 3):   [3, 99, -1, -100]
```

Совпадает с поворотом на 2: `[3, 99, -1, -100]`.

## Почему это работает

Элемент с индексом `i` должен попасть на позицию `(i + k) % n`.

- Если `i` из `B` (`i >= n - k`): после полного разворота он на позиции `n - 1 - i`, это внутри `[0, k - 1]`. Разворот этого отрезка переводит позицию `p` в `k - 1 - p`: `k - 1 - (n - 1 - i) = i + k - n = (i + k) % n`.
- Если `i` из `A` (`i < n - k`): после полного разворота он на `n - 1 - i`, это внутри `[k, n - 1]`. Разворот этого отрезка переводит `p` в `k + n - 1 - p`: `k + n - 1 - (n - 1 - i) = i + k`, и это меньше `n`, то есть `(i + k) % n`.

Каждый элемент попал на своё место — поворот выполнен.

## Пограничные случаи

- **`k = 0` или `k` кратно `n`**: после `k %= n` получаем `0` и выходим, массив не меняется.
- **`k > n`**: нормализация обязательна, иначе `reverse(0, k - 1)` полезет за пределы массива.
- **`n = 1`**: `k % 1 = 0`, выход сразу.
- **`k = n - 1`**: блок `A` из одного элемента, `reverse(k, n - 1)` ничего не делает — так и должно быть.
- **Большие и отрицательные значения**: числа только переставляются, арифметики над ними нет.

## Сложность

- **Время `O(n)`**: три разворота суммарно обходят `n + k + (n - k) = 2n` позиций, каждая перестановка — `O(1)`.
- **Память `O(1)`**: две переменные-указателя внутри `reverse`, массив меняется на месте.

## Типичные ошибки

1. **Забыть `k %= n`** → при `k > n` разворот отрезка `[0, k - 1]` пишет в несуществующие индексы и портит массив.
2. **Перепутать направление**: для поворота **вправо** сначала разворачивают всё, потом `[0, k - 1]` и `[k, n - 1]`. Разворот `[0, n - k - 1]` и `[n - k, n - 1]` после полного даёт поворот **влево**.
3. **Присвоить новый массив** (`nums = [...]`) — снаружи функции ничего не изменится, нужен именно мутирующий код.
4. **Ошибка на единицу в границах**: `reverse(0, k)` вместо `reverse(0, k - 1)` захватывает лишний элемент.
5. **Наивные `k` сдвигов по одному** — проходят на маленьких тестах и падают по времени на больших.

## Как узнать такую задачу

- «Циклический сдвиг», «поворот», «переставить два блока местами» при требовании **`O(1)` памяти** — приём трёх разворотов.
- Встречается в задачах Reverse Words in a String (развернуть всё, затем каждое слово), Rotate String, а также при повороте матрицы (транспонирование + разворот строк).
- Альтернатива для той же задачи — циклические замены по `gcd(n, k)` циклам; она тоже `O(1)` по памяти, но код сложнее.
