## Задача простыми словами

Дан массив `nums` и число `k`. Нужно **на месте** циклически сдвинуть массив вправо на `k` шагов: элементы, «выпадающие» справа, появляются слева. Функция ничего не возвращает — меняется сам `nums`.

Пример: `nums = [1, 2, 3, 4, 5, 6, 7]`, `k = 3`. Последние три элемента `5, 6, 7` переезжают в начало: `[5, 6, 7, 1, 2, 3, 4]`.

## Наивный подход

Буквально сделать `k` сдвигов на одну позицию:

```ts naive
for (let step = 0; step < k; step++) {
  const last = nums[nums.length - 1];
  for (let i = nums.length - 1; i > 0; i--) nums[i] = nums[i - 1];
  nums[0] = last;
}
```

Это `O(n · k)`: при `n = k = 10⁵` — 10 миллиардов присваиваний. Лишняя работа очевидна: каждый элемент проходит путь в `k` позиций **по одному шагу**, хотя его конечное место можно вычислить сразу.

## Ключевое наблюдение

После поворота вправо на `k` элемент с индексом `i` оказывается на позиции `i + k`, а если она вылезает за конец массива — «заворачивается» в начало. Это ровно остаток от деления: **новая позиция = `(i + k) % n`**.

Раз конечное место каждого элемента известно заранее, его можно поставить туда одним присваиванием. Мешает только то, что запись в `nums` затрёт ещё не перенесённые элементы. Поэтому раскладываем элементы во **вспомогательный массив** `res`, а потом копируем его обратно в `nums`.

## Техники

### Циклический индекс через остаток `%`

**Что это.** Чтобы индекс «ходил по кругу» по массиву длины `n`, берут остаток от деления на `n`: `(i + shift) % n`. При `i + shift < n` значение не меняется, а при `i + shift >= n` из него вычитается `n` — индекс возвращается в начало.

**Типичный шаблон.**

```ts naive
const next = (i + shift) % n; // сдвиг вправо по кругу
```

Тот же приём используется в кольцевом буфере, в задачах про круговой маршрут (Gas Station), при обходе «следующего элемента» в кольцевом массиве. Подробнее о работе с массивами — во вкладке «Теория».

**Как применяется здесь.** `res[(i + k) % n] = nums[i]` — каждый элемент сразу встаёт на итоговое место.

### Вспомогательный массив и копирование обратно

Когда элементы переставляются по формуле, запись прямо в исходный массив затирает данные, которые ещё нужны. Простой выход — писать результат в отдельный массив, а затем переписать его в исходный. Копировать нужно **поэлементно**: присваивание `nums = res` изменило бы только локальную переменную, а массив снаружи функции остался бы прежним.

### Нормализация `k %= n`

Поворот на `n` шагов возвращает массив в исходное состояние, поэтому важен только остаток. В этом решении формула `(i + k) % n` и так корректна при любом `k`, но нормализация делает намерение явным и держит числа маленькими.

## Разбор кода

```ts
/**
 Do not return anything, modify nums in-place instead.
 */
function rotate(nums: number[], k: number): void {
  const n = nums.length;
  // Поворот на n шагов возвращает массив в исходное состояние
  k %= n;
```

Комментарий-шапка — из шаблона LeetCode: функция меняет массив и ничего не возвращает. Затем нормализуем `k`: при `n = 7`, `k = 10` реальный сдвиг — `3`. Если `k` стал `0`, дальнейший код просто скопирует элементы на те же места — отдельная проверка не нужна.

```ts
  // Каждый элемент nums[i] после поворота стоит на позиции (i + k) % n
  const res = new Array<number>(n);
  for (let i = 0; i < n; i++) {
    res[(i + k) % n] = nums[i];
  }
```

Создаём массив той же длины и раскладываем в него элементы по итоговым позициям. Формула `(i + k) % n` для `i < n - k` даёт просто `i + k` (сдвиг вправо), а для последних `k` элементов — `i + k - n`, то есть начало массива. Исходный `nums` при этом не меняется, поэтому ничего не затирается.

```ts
  // Копируем результат обратно: менять нужно именно nums
  for (let i = 0; i < n; i++) {
    nums[i] = res[i];
  }
}
```

Переписываем `res` в `nums` поэлементно — так изменения видны вызывающему коду. Здесь подошёл бы и короткий вариант `nums.splice(0, n, ...res)`, но явный цикл понятнее и не упирается в лимит аргументов при больших `n`.

## Трассировка

`nums = [1, 2, 3, 4, 5, 6, 7]`, `k = 3`, `n = 7`. `k %= 7` → `3`.

```
i  nums[i]  (i + 3) % 7   res после шага
0  1        3             [_, _, _, 1, _, _, _]
1  2        4             [_, _, _, 1, 2, _, _]
2  3        5             [_, _, _, 1, 2, 3, _]
3  4        6             [_, _, _, 1, 2, 3, 4]
4  5        0             [5, _, _, 1, 2, 3, 4]
5  6        1             [5, 6, _, 1, 2, 3, 4]
6  7        2             [5, 6, 7, 1, 2, 3, 4]
```

Копируем обратно: `nums = [5, 6, 7, 1, 2, 3, 4]`.

Пример с `k > n`: `nums = [-1, -100, 3, 99]`, `k = 6`. `6 % 4 = 2`.

```
i  nums[i]  (i + 2) % 4
0  -1       2
1  -100     3
2  3        0
3  99       1
res = [3, 99, -1, -100]
```

Совпадает с поворотом на 2.

## Почему это работает

Поворот вправо на `k` по определению ставит элемент с индексом `i` на позицию `(i + k) % n`. Отображение `i → (i + k) % n` — **биекция** на `[0, n - 1]`: разные `i` дают разные позиции (сдвиг по кругу обратим сдвигом на `n - k`). Значит, первый цикл заполняет **каждую** ячейку `res` ровно один раз, и `res` — в точности повёрнутый массив. Поскольку читаем мы только из `nums`, а пишем только в `res`, никакие данные не теряются. Второй цикл переносит результат в `nums` без изменений.

## Пограничные случаи

- **`k = 0` или `k` кратно `n`**: после `k %= n` получаем `0`, каждый элемент копируется на своё же место — массив не меняется.
- **`k > n`**: нормализация (или сама формула с `%`) сводит всё к остатку.
- **`n = 1`**: `k % 1 = 0`, единственный элемент остаётся на месте.
- **`k = n - 1`**: первый элемент уезжает в конец, остальные сдвигаются влево на одну позицию — формула обрабатывает это без особых веток.
- **Большие и отрицательные значения**: числа только переставляются, арифметики над ними нет.

## Сложность

- **Время `O(n)`**: два прохода по массиву, каждый шаг — `O(1)`.
- **Память `O(n)`**: вспомогательный массив `res`.

**Follow-up на собеседовании: `O(1)` памяти — три разворота.** Разбейте массив на `A` (первые `n - k`) и `B` (последние `k`). Нужно `A B` → `B A`. Разворот всего массива даёт `rev(B) rev(A)`, затем разворачиваем первые `k` элементов и остальные `n - k`:

```ts naive
const reverse = (l: number, r: number) => {
  while (l < r) {
    [nums[l], nums[r]] = [nums[r], nums[l]];
    l++;
    r--;
  }
};
reverse(0, n - 1); // [7,6,5,4,3,2,1]
reverse(0, k - 1); // [5,6,7,4,3,2,1]
reverse(k, n - 1); // [5,6,7,1,2,3,4]
```

Время то же `O(n)`, памяти `O(1)`. Есть и третий способ — циклические замены по `gcd(n, k)` циклам, тоже `O(1)`, но код сложнее.

## Типичные ошибки

1. **`nums = res`** вместо поэлементного копирования → снаружи функции массив не изменится, тест упадёт.
2. **Писать сразу в `nums[(i + k) % n]`** без вспомогательного массива → значение на целевой позиции затирается до того, как его перенесли.
3. **Перепутать направление**: `(i - k + n) % n` — это поворот **влево**. Для поворота вправо элемент уезжает на `i + k`.
4. **Забыть `%`** и писать `res[i + k]` → последние `k` элементов попадут за пределы массива, а начало останется пустым.
5. **Наивные `k` сдвигов по одному** — проходят на маленьких тестах и падают по времени на больших.

## Как узнать такую задачу

- «Циклический сдвиг», «поворот», «по кругу» — думайте об индексе `(i + k) % n`.
- Если известна итоговая позиция каждого элемента, а писать на место нельзя, — вспомогательный массив и копирование.
- Если интервьюер просит **`O(1)` памяти** — приём трёх разворотов (так же решаются Reverse Words in a String и Rotate String; поворот матрицы — транспонирование + разворот строк).
