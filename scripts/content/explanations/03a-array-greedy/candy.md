## Задача простыми словами

В ряд стоят дети, у каждого рейтинг `ratings[i]`. Нужно раздать конфеты так, чтобы каждый получил **хотя бы одну**, а ребёнок с рейтингом **выше соседа** получил больше конфет, чем этот сосед. Вернуть **минимальное** общее число конфет.

Пример: `ratings = [1, 0, 2]`. Раздаём `[2, 1, 2]`: средний ребёнок ниже обоих соседей — ему `1`, крайние выше него — им по `2`. Итого `5`.

## Наивный подход

Всем дать по одной, а потом «чинить» нарушения, пока они есть:

```ts naive
const candies = new Array(n).fill(1);
let changed = true;
while (changed) {
  changed = false;
  for (let i = 0; i < n; i++) {
    if (i > 0 && ratings[i] > ratings[i - 1] && candies[i] <= candies[i - 1]) {
      candies[i] = candies[i - 1] + 1; changed = true;
    }
    if (i < n - 1 && ratings[i] > ratings[i + 1] && candies[i] <= candies[i + 1]) {
      candies[i] = candies[i + 1] + 1; changed = true;
    }
  }
}
```

Это верно, но на убывающем массиве `[5, 4, 3, 2, 1]` каждый проход слева направо продвигает «волну» исправлений только на одну позицию: всего до `n` проходов, `O(n²)`. Лишняя работа: мы смешиваем ограничения от **левого** и **правого** соседа и ходим в направлении, против которого распространяется одно из них.

## Ключевое наблюдение

Условие распадается на два **независимых** набора ограничений:

- **левые**: если `ratings[i] > ratings[i - 1]`, то `candies[i] > candies[i - 1]`;
- **правые**: если `ratings[i] > ratings[i + 1]`, то `candies[i] > candies[i + 1]`.

Левые ограничения «текут» слева направо — их можно выполнить одним проходом слева направо. Правые текут справа налево — одним обратным проходом. Чтобы второй проход не сломал первый, берём **максимум** из двух требований. В итоге каждый ребёнок получает `max(длина возрастающей серии слева, длина возрастающей серии справа)` — и это минимально возможное.

## Техники

### Два прохода (слева направо и справа налево)

**Что это.** Когда значение в позиции зависит и от левой, и от правой части массива, часто удобно посчитать вклад каждой стороны отдельным проходом, а затем объединить (максимумом, суммой, произведением).

**Типичный шаблон.**

```ts naive
for (let i = 1; i < n; i++) left[i] = f(left[i - 1], a[i]);
for (let i = n - 2; i >= 0; i--) right[i] = g(right[i + 1], a[i]);
// ответ строится из left[i] и right[i]
```

**Как применяется здесь.** Первый проход пишет требования левых соседей прямо в `candies`, второй — сразу объединяет их с правыми через `Math.max`, без отдельного массива `right`.

### Жадность: минимальное значение, удовлетворяющее ограничениям

Каждому ребёнку даём **наименьшее** число конфет, которое требуют ограничения: `1`, если ограничений нет, иначе «на одну больше соседа». Брать больше никогда не нужно — это только увеличит сумму и не поможет соседям. Подробнее о жадных алгоритмах — во вкладке «Теория».

## Разбор кода

```ts
function candy(ratings: number[]): number {
  const n = ratings.length;
  // Каждому минимум по одной конфете
  const candies = new Array<number>(n).fill(1);
```

Базовое правило: каждому хотя бы одну. Это нижняя граница для всех.

```ts
  // Проход слева направо: учитываем только левого соседа
  for (let i = 1; i < n; i++) {
    if (ratings[i] > ratings[i - 1]) {
      candies[i] = candies[i - 1] + 1;
    }
  }
```

Если ребёнок выше левого соседа, ему нужно на одну конфету больше, чем у соседа. Значение `candies[i - 1]` к этому моменту уже окончательно для левых ограничений, поэтому присваивание сразу верное. При равных или меньших рейтингах левое ограничение отсутствует, остаётся `1`. После прохода `candies[i]` — длина возрастающей серии, заканчивающейся в `i`.

```ts
  // Проход справа налево: учитываем правого соседа,
  // не ломая уже выполненное условие для левого (берём максимум)
  for (let i = n - 2; i >= 0; i--) {
    if (ratings[i] > ratings[i + 1]) {
      candies[i] = Math.max(candies[i], candies[i + 1] + 1);
    }
  }
```

Теперь идём справа налево. Если ребёнок выше правого соседа, ему нужно хотя бы `candies[i + 1] + 1`. Но у него уже есть требование от левого соседа — поэтому берём `Math.max`: значение может только **вырасти**, и левое ограничение не сломается. `candies[i + 1]` к этому моменту уже финальное (правее мы всё обработали).

```ts
  // Суммируем итоговое распределение
  let total = 0;
  for (const c of candies) total += c;
  return total;
}
```

Ответ — сумма конфет.

## Трассировка

`ratings = [1, 3, 4, 5, 2]`:

```
старт:             candies = [1, 1, 1, 1, 1]
слева направо:
  i=1: 3>1 → 2     candies = [1, 2, 1, 1, 1]
  i=2: 4>3 → 3     candies = [1, 2, 3, 1, 1]
  i=3: 5>4 → 4     candies = [1, 2, 3, 4, 1]
  i=4: 2>5? нет
справа налево:
  i=3: 5>2 → max(4, 1+1) = 4
  i=2: 4>5? нет
  i=1: 3>4? нет
  i=0: 1>3? нет
итог:              candies = [1, 2, 3, 4, 1], сумма 11
```

На `i = 3` видно, зачем `Math.max`: без него вершина получила бы `2`, и сломалось бы условие относительно левого соседа (`4 > 3` по рейтингу, а конфет `2 < 3`).

`ratings = [5, 4, 3]` — здесь работает второй проход:

```
слева направо:  ничего не растёт      [1, 1, 1]
справа налево:  i=1: 4>3 → max(1, 2)  [1, 2, 1]
                i=0: 5>4 → max(1, 3)  [3, 2, 1]
сумма 6
```

`ratings = [1, 2, 2]`: первый проход даёт `[1, 2, 1]` (у третьего рейтинг **равен** соседу, ограничения нет), второй ничего не меняет. Сумма `4`.

## Почему это работает

Обозначим `L[i]` — длину строго возрастающей серии рейтингов, заканчивающейся в `i` (слева), `R[i]` — длину строго убывающей серии, начинающейся в `i` (справа). После первого прохода `candies[i] = L[i]`, после второго `candies[i] = max(L[i], R[i])` (по индукции справа налево).

- **Нижняя граница.** Любая допустимая раздача даёт ребёнку `i` хотя бы `L[i]` конфет: вдоль возрастающей серии слева каждое следующее значение строго больше, начиная с `≥ 1`. Аналогично хотя бы `R[i]`. Значит, хотя бы `max(L[i], R[i])`.
- **Допустимость.** Пусть `ratings[i] > ratings[i - 1]`. Тогда `L[i] = L[i - 1] + 1`, а `R[i - 1] = 1`: справа от `i - 1` рейтинг растёт, убывающей серии нет. Значит, у `i - 1` ровно `max(L[i - 1], 1) = L[i - 1]` конфет, а у `i` — не меньше `L[i] = L[i - 1] + 1`. Левое условие выполнено; правое — симметрично.

Каждый ребёнок получает ровно нижнюю границу, и все условия выполнены — сумма минимальна.

## Пограничные случаи

- **Один ребёнок**: оба цикла пусты, ответ `1`.
- **Равные рейтинги** (`[2, 2, 2]`): ограничений нет, все по `1`, сумма `3`.
- **Строго возрастающие** (`[1, 2, 3]`): `[1, 2, 3]`, сумма `6`.
- **Строго убывающие** (`[3, 2, 1]`): всё делает второй проход, `[3, 2, 1]`.
- **«Долина» и «гора»**: на вершине `Math.max` выбирает более длинный склон.

## Сложность

- **Время `O(n)`**: три линейных прохода (два по ограничениям и один на сумму).
- **Память `O(n)`**: массив `candies`. Существует вариант за `O(1)` памяти — подсчёт длин склонов с арифметическими прогрессиями, но он заметно сложнее.

## Типичные ошибки

1. **Присваивать во втором проходе без `Math.max`** → затирается левое требование, на `[1, 3, 4, 5, 2]` вершина получит `2`.
2. **Требовать больше конфет при равных рейтингах** — по условию равные соседи ни на что не влияют (`[1, 2, 2]` → `4`, а не `6`).
3. **Один проход в одну сторону** — правые ограничения на убывающих участках не выполняются.
4. **Сравнивать во втором проходе с уже изменённым левым соседом** вместо правого — направление прохода и сосед должны совпадать.
5. **Наивные повторные проходы до стабилизации** — `O(n²)` на длинных убывающих участках.

## Как узнать такую задачу

- Ограничения между **соседями** в обе стороны, и нужно минимальное распределение — два прохода с объединением через `max`.
- Значение в позиции определяется «тем, что слева» и «тем, что справа» — шаблон «префикс + суффикс».
- Родственные: Trapping Rain Water (максимумы слева и справа), Product of Array Except Self (произведения слева и справа), Shortest Distance to a Character.
