## Задача простыми словами

Дан массив `prices`: `prices[i]` — цена акции в день `i`. Можно совершать **сколько угодно** сделок, но держать не больше одной акции одновременно; продать и снова купить можно в тот же день. Нужно вернуть максимальную суммарную прибыль.

Пример: `prices = [7, 1, 5, 3, 6, 4]`. Покупаем за `1`, продаём за `5` (`+4`), покупаем за `3`, продаём за `6` (`+3`). Ответ `7`.

## Наивный подход

Перебрать все стратегии: в каждый день либо ничего не делаем, либо (если акции нет) покупаем, либо (если есть) продаём.

```ts naive
function best(day: number, holding: boolean): number {
  if (day === prices.length) return 0;
  let res = best(day + 1, holding); // ничего не делаем
  if (holding) res = Math.max(res, prices[day] + best(day + 1, false)); // продаём
  else res = Math.max(res, -prices[day] + best(day + 1, true)); // покупаем
  return res;
}
```

Без запоминания это `O(2ⁿ)`: на каждом дне два варианта. С мемоизацией по `(day, holding)` получится `O(n)` — это уже нормальное ДП. Но и в нём есть лишнее: мы рассматриваем «держать акцию сквозь падение цены», хотя такое решение никогда не выгодно, если можно продать раньше и откупить дешевле.

## Ключевое наблюдение

Прибыль любой сделки «купить в день `a`, продать в день `b`» раскладывается на сумму **дневных изменений** цены:

```
prices[b] - prices[a] = (prices[a+1] - prices[a]) + ... + (prices[b] - prices[b-1])
```

Значит, любая стратегия — это выбор набора дней, в которые мы держим акцию, а её прибыль — сумма дневных изменений за эти дни. Чтобы сумма была максимальной, нужно взять **все положительные** изменения и не брать ни одного отрицательного. Ограничений на число сделок нет, поэтому такой выбор всегда реализуем: «купили вчера, продали сегодня» на каждом росте.

## Техники

### Жадный алгоритм

**Что это.** Жадный алгоритм на каждом шаге делает локально лучший выбор и никогда его не пересматривает. Он корректен, только если можно доказать, что локально лучшие шаги складываются в глобальный оптимум — обычно через разложение ответа на независимые части или через аргумент «обмена».

**Типичный шаблон.** Один проход по данным с аккумулятором; на каждом элементе решение принимается по простому локальному правилу.

**Как применяется здесь.** Ответ раскладывается на независимые дневные приросты, и каждый можно взять или не взять отдельно. Локальное правило: «прирост положительный — берём». Подробнее о жадных алгоритмах — во вкладке «Теория».

### Разложение на разности соседних элементов

Сумму на отрезке можно переписать как сумму разностей соседних элементов (телескопическая сумма). Этот приём превращает задачу о выборе пар «купить–продать» в задачу о выборе отдельных элементов массива разностей — гораздо более простую.

## Разбор кода

```ts
function maxProfit(prices: number[]): number {
  let profit = 0;
```

Накопитель прибыли. Начинаем с `0`: ничего не покупать — всегда допустимая стратегия, поэтому ответ не может быть отрицательным.

```ts
  for (let i = 1; i < prices.length; i++) {
    // Цена выросла за день — забираем этот рост:
    // «купили вчера, продали сегодня»
    if (prices[i] > prices[i - 1]) {
      profit += prices[i] - prices[i - 1];
    }
  }
```

Перебираем пары соседних дней, начиная с `i = 1`, чтобы `prices[i - 1]` существовал. Если цена выросла — добавляем рост к прибыли. Если упала или не изменилась — пропускаем: в этот день мы «не держим» акцию.

Несколько подряд идущих ростов складываются в одну длинную сделку: `1 → 2 → 3` даёт `+1 +1 = 2`, ровно как «купить за 1, продать за 3». Код не различает, одна это сделка или несколько, — прибыль одинакова.

```ts
  return profit;
}
```

Возвращаем сумму всех положительных приростов.

## Трассировка

`prices = [7, 1, 5, 3, 6, 4]`:

1. `i = 1`: `1 > 7`? Нет. `profit = 0`.
2. `i = 2`: `5 > 1`? Да, `+4`. `profit = 4`.
3. `i = 3`: `3 > 5`? Нет. `profit = 4`.
4. `i = 4`: `6 > 3`? Да, `+3`. `profit = 7`.
5. `i = 5`: `4 > 6`? Нет. `profit = 7`.

Ответ `7`.

`prices = [1, 2, 3, 4, 5]`: приросты `+1, +1, +1, +1`, сумма `4` — то же, что одна сделка `1 → 5`.

`prices = [7, 6, 4, 3, 1]`: все изменения отрицательные, `profit` остаётся `0`.

## Почему это работает

Пусть `d[i] = prices[i] - prices[i - 1]` для `i >= 1`. Любая допустимая стратегия держит акцию в некотором наборе переходов «день `i - 1` → день `i`», и её прибыль равна `Σ d[i]` по этим переходам (телескопическая сумма внутри каждой сделки).

- **Верхняя граница**: для любого набора `Σ d[i] <= Σ max(d[i], 0)`, потому что каждое слагаемое не больше своего положительного варианта.
- **Достижимость**: набор «все `i` с `d[i] > 0`» реализуется стратегией «купить в `i - 1`, продать в `i`» для каждого такого `i` (покупка и продажа в один день разрешены, и в каждый момент держим не больше одной акции).

Значит, `Σ max(d[i], 0)` — точный максимум, и код считает именно его.

## Пограничные случаи

- **Один день**: цикл не выполняется, ответ `0`.
- **Монотонно падающие цены**: ни одного роста, ответ `0`.
- **Монотонно растущие**: сумма всех приростов равна `prices[n - 1] - prices[0]`.
- **Равные цены подряд**: прирост `0`, условие `>` его пропускает (добавлять ноль и так бессмысленно).
- **Цены `0`**: допустимы, арифметика не ломается.

## Сложность

- **Время `O(n)`**: один проход по массиву, тело цикла — `O(1)`.
- **Память `O(1)`**: одна переменная `profit`.

## Типичные ошибки

1. **Решать как Stock I** (одна сделка, `max - min`): на `[7, 1, 5, 3, 6, 4]` получится `5` вместо `7`.
2. **Искать «локальные минимумы и максимумы»** вручную — можно, но легко ошибиться на плато и краях; сумма положительных разностей проще и эквивалентна.
3. **Начинать цикл с `i = 0`** → `prices[-1]` равно `undefined`, сравнение даёт `false`, но это ошибка по смыслу и источник багов в других языках.
4. **Добавлять `prices[i] - prices[i - 1]` без проверки знака** → получится `prices[n-1] - prices[0]`, что может быть отрицательным.
5. **Переносить решение на варианты с комиссией или «кулдауном»** — там жадность ломается, нужно ДП с состояниями `hold`/`cash`.

## Как узнать такую задачу

- **Неограниченное** число сделок/операций, и прибыль операции раскладывается на сумму соседних разностей — берите все положительные разности.
- Если сделок ограниченное число (Stock III, IV), есть комиссия или кулдаун — это ДП по состояниям, а не жадность.
- Родственные: Best Time to Buy and Sell Stock (одна сделка), Stock with Transaction Fee, Stock with Cooldown.
