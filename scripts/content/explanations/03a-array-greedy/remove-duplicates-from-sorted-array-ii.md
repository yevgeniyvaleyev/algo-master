## Задача простыми словами

Дан массив `nums`, отсортированный по неубыванию. Нужно **на месте** оставить каждое значение не более **двух** раз, сохранив порядок, и вернуть `k` — сколько элементов осталось. Важны только первые `k` ячеек, что лежит дальше — неважно. Дополнительный массив заводить нельзя.

Пример: `nums = [1, 1, 1, 2, 2, 3]`. Третья единица лишняя, остальное оставляем: первые пять ячеек становятся `[1, 1, 2, 2, 3]`, ответ `k = 5`.

## Наивный подход

Самое прямолинейное — идти по массиву и, встретив третью подряд копию, **удалять** её сдвигом хвоста влево:

```ts naive
let i = 2;
let n = nums.length;
while (i < n) {
  if (nums[i] === nums[i - 1] && nums[i] === nums[i - 2]) {
    for (let j = i; j < n - 1; j++) nums[j] = nums[j + 1];
    n--; // массив «укоротился», i не двигаем
  } else {
    i++;
  }
}
return n;
```

Это верно, но каждое удаление стоит `O(n)` сдвигов, а удалений может быть почти `n` (например, `[5, 5, 5, ..., 5]`). Итого `O(n²)`. Лишняя работа в том, что один и тот же хвост массива **перемещается много раз**: каждый элемент сдвигается на одну позицию столько раз, сколько лишних копий стоит перед ним. А ведь его итоговое место можно вычислить сразу.

## Ключевое наблюдение

Не надо удалять — надо **переписывать**. Заведём «указатель записи» `k`: всё, что левее него, — уже готовый ответ. Читаем элементы по одному и копируем в `nums[k]` только те, что нужно оставить. Каждый элемент перемещается не больше одного раза.

Остаётся понять, когда элемент оставлять. Массив отсортирован, значит одинаковые значения стоят подряд — и в готовой части тоже. Если `nums[i]` равен `nums[k - 2]`, то готовая часть уже заканчивается двумя такими же значениями (`nums[k - 2]` и `nums[k - 1]` — между ними ничего другого быть не может). Третья копия не нужна. Одно сравнение — и решение принято.

## Техники

### Два указателя в одном направлении (чтение / запись)

**Что это.** Два индекса движутся по массиву слева направо с разной скоростью: «читатель» `i` проходит каждый элемент, «писатель» `k` сдвигается только тогда, когда элемент попадает в результат. Всегда `k <= i`, поэтому запись не портит ещё не прочитанные элементы.

**Типичный шаблон.** Фильтрация массива на месте: удалить значение (Remove Element), убрать дубликаты, сдвинуть нули в конец (Move Zeroes). Общая схема:

```ts naive
let k = 0;
for (let i = 0; i < nums.length; i++) {
  if (нужноОставить(nums[i])) nums[k++] = nums[i];
}
return k;
```

**Как применяется здесь.** Условие «нужно оставить» — `nums[i] !== nums[k - 2]`, а стартуем с `k = 2`, потому что первые два элемента оставляются всегда. Подробнее о двух указателях — во вкладке «Теория».

### Опора на сортировку

Сортировка превращает вопрос «сколько раз это значение уже встречалось в результате?» в локальную проверку: все копии стоят подряд, поэтому достаточно посмотреть на ячейку на две позиции назад в **готовой** части. Без сортировки понадобился бы словарь счётчиков.

## Разбор кода

```ts
function removeDuplicates(nums: number[]): number {
  // Первые два элемента можно оставить всегда
  if (nums.length <= 2) return nums.length;
```

Массив из одного или двух элементов не может содержать «третью копию», поэтому он уже является ответом. Эта проверка также гарантирует, что дальше индексы `k - 2` и `i = 2` корректны.

```ts
  // k — сколько элементов уже записано в «чистую» часть nums[0..k-1]
  let k = 2;
```

Готовая часть изначально — первые два элемента: какими бы они ни были, их можно оставить (даже если они равны — это ровно две копии). `k` одновременно и длина готовой части, и индекс, куда пойдёт следующий оставленный элемент.

```ts
  for (let i = 2; i < nums.length; i++) {
    // Массив отсортирован: если nums[i] совпадает с nums[k - 2],
    // то в чистой части уже есть две такие копии — третью не берём
    if (nums[i] !== nums[k - 2]) {
      nums[k] = nums[i];
      k++;
    }
  }
```

Читатель `i` идёт с третьего элемента. Сравниваем с `nums[k - 2]` — предпоследним элементом **готовой** части. Если значения различаются, значит в готовой части этого значения не больше одной копии, и `nums[i]` можно дописать: кладём его в `nums[k]` и расширяем готовую часть. Если совпадают — просто идём дальше, `k` стоит на месте, и следующая подходящая запись затрёт эту позицию.

Почему не `nums[i - 2]`? Потому что ячейки левее `i` могли быть уже перезаписаны, и там лежит не исходный массив. Решение принимается по результату, а не по входу.

```ts
  return k;
}
```

`k` — длина готовой части, это и есть ответ.

## Трассировка

`nums = [1, 1, 1, 2, 2, 3]`, старт `k = 2`:

1. `i = 2`: `nums[2] = 1`, `nums[k - 2] = nums[0] = 1` — равны, пропускаем. `k = 2`.
2. `i = 3`: `nums[3] = 2`, `nums[0] = 1` — различаются. `nums[2] = 2`, `k = 3`. Массив `[1, 1, 2, 2, 2, 3]`.
3. `i = 4`: `nums[4] = 2`, `nums[1] = 1` — различаются. `nums[3] = 2`, `k = 4`. Массив `[1, 1, 2, 2, 2, 3]`.
4. `i = 5`: `nums[5] = 3`, `nums[2] = 2` — различаются. `nums[4] = 3`, `k = 5`. Массив `[1, 1, 2, 2, 3, 3]`.

Ответ `k = 5`, первые пять ячеек — `[1, 1, 2, 2, 3]`.

Обратите внимание на шаг 3: сравнение идёт с `nums[1]`, а не с `nums[2]`. Если бы мы смотрели на `nums[i - 2] = nums[2]`, там уже лежала бы перезаписанная двойка, и вторую двойку мы бы ошибочно выбросили.

## Почему это работает

Инвариант: перед каждой итерацией `nums[0..k-1]` — правильный ответ для префикса `nums[0..i-1]` исходного массива (каждое значение не более двух раз, порядок сохранён), и `k <= i`.

- В начале `k = i = 2`, и первые два элемента — правильный ответ для себя.
- Готовая часть отсортирована, поэтому копии значения `x` в ней стоят в самом конце, если `x` — максимальное на данный момент. А `nums[i]` не меньше всего, что было раньше. Значит, в готовой части уже две копии `nums[i]` **тогда и только тогда**, когда `nums[k - 2] === nums[i]`.
- Запись в `nums[k]` безопасна: `k <= i`, поэтому мы пишем либо в уже прочитанную ячейку, либо в саму `nums[i]`.

После последней итерации инвариант даёт ответ для всего массива.

## Пограничные случаи

- **Длина 1 или 2**: сразу возвращаем длину.
- **Все элементы одинаковые** (`[7, 7, 7, 7]`): остаются две семёрки, `k = 2`.
- **Нет дубликатов** (`[1, 2, 3]`): каждый элемент переписывается сам в себя, `k = n`.
- **Отрицательные числа**: сравнение на равенство не зависит от знака.
- **Длинная серия в конце** (`[1, 2, 2, 2, 2]`): лишние двойки пропускаются, `k = 3`.

## Сложность

- **Время `O(n)`**: один проход, на каждом шаге одно сравнение и не более одной записи.
- **Память `O(1)`**: только два индекса, массив меняется на месте.

## Типичные ошибки

1. **Сравнивать с `nums[i - 2]` вместо `nums[k - 2]`.** На `[1, 1, 1, 2, 2, 3]` вторая двойка теряется, получится `k = 4` вместо `5`.
2. **Сравнивать с `nums[k - 1]`** — так получится задача «каждое значение по одному разу», вторая копия будет выброшена.
3. **Забыть проверку длины** и начать с `k = 2` на массиве из одного элемента — вернётся `2` вместо `1`.
4. **Удалять через `splice`** — работает, но это `O(n)` на каждое удаление и `O(n²)` в сумме.
5. **Возвращать `k + 1` или `k - 1`**: `k` уже равен длине готовой части, а не индексу последнего элемента.

## Как узнать такую задачу

- «Удалите **на месте**», «верните новую длину», «что после первых `k` элементов — неважно» — это шаблон «читатель/писатель».
- Массив **отсортирован** и есть ограничение на число повторов — сравниваем с элементом на `m` позиций назад в готовой части (`nums[k - m]`).
- Родственные задачи: Remove Duplicates from Sorted Array (`m = 1`), Remove Element, Move Zeroes, Sort Colors.
