## Задача простыми словами

Дан корень `root` двоичного дерева. Нужно вернуть его **максимальную глубину** — число узлов на самом длинном пути от корня вниз до какого-нибудь листа. Пустое дерево имеет глубину `0`.

Пример: `root = [3, 9, 20, null, null, 15, 7]`.

```
    3
   / \
  9   20
     /  \
    15   7
```

Самый длинный путь — `3 → 20 → 15` (или `3 → 20 → 7`), в нём три узла. Ответ `3`.

## Наивный подход

Можно рассуждать «в лоб»: перечислить все пути от корня до листьев, посчитать длину каждого и взять максимум. Например, собирать текущий путь в массив и в каждом листе записывать его длину:

```ts naive
let best = 0;
const walk = (node: TreeNode | null, path: number[]) => {
  if (node === null) return;
  const next = [...path, node.val];
  if (node.left === null && node.right === null) best = Math.max(best, next.length);
  walk(node.left, next);
  walk(node.right, next);
};
walk(root, []);
```

Ответ правильный, но на каждом узле копируется весь путь — до `O(n²)` времени и памяти на вырожденном дереве-«палке». Лишняя работа в том, что мы **храним сам путь**, хотя нужна только его длина, и каждый узел снова и снова переписывает общие префиксы путей.

## Ключевое наблюдение

Глубина дерева выражается через глубины его поддеревьев:

- глубина пустого дерева — `0`;
- глубина непустого — `1` (сам корень) `+ max(глубина левого, глубина правого)`.

Это рекурсивное определение и есть решение: каждая подзадача — меньшее поддерево, а ответ «собирается» на обратном пути рекурсии из двух чисел. Никаких путей хранить не надо.

## Техники

### Рекурсивный DFS «снизу вверх» (post-order)

**Что это.** Обход в глубину, где узел обрабатывается **после** своих детей: сначала рекурсивно получаем ответы для левого и правого поддеревьев, затем комбинируем их в ответ для текущего узла. Такой порядок называют post-order.

**Типичный шаблон:**

```ts naive
function solve(node: TreeNode | null): Result {
  if (node === null) return БАЗА;
  const l = solve(node.left);
  const r = solve(node.right);
  return объединить(node, l, r);
}
```

**Когда применять.** Когда ответ для дерева однозначно выражается через ответы для поддеревьев: высота, число узлов, сумма, сбалансированность (Balanced Binary Tree), диаметр, максимальная сумма пути.

**Как применяется здесь.** База — `0` для `null`, объединение — `1 + Math.max(l, r)`. Подробнее об обходах дерева в глубину — во вкладке «Теория».

### Альтернатива: BFS по уровням

Можно обходить дерево уровнями (очередь или массив текущего уровня) и считать, сколько уровней прошли, — это и есть глубина. Такой вариант не использует стек вызовов и полезен, если дерево может быть очень глубоким. В нашем решении используется рекурсия — она короче.

## Разбор кода

```ts
function maxDepth(root: TreeNode | null): number {
  // Пустое дерево имеет глубину 0
  if (root === null) {
    return 0;
  }
```

База рекурсии. Она срабатывает не только для пустого входа, но и каждый раз, когда рекурсия спускается в отсутствующего ребёнка. Благодаря этому листу не нужна отдельная ветка: у листа оба ребёнка `null`, оба вызова вернут `0`, и глубина листа получится `1 + max(0, 0) = 1`.

```ts
  // Глубина дерева = 1 (сам узел) + глубина более глубокого поддерева
  return 1 + Math.max(maxDepth(root.left), maxDepth(root.right));
}
```

Два рекурсивных вызова вычисляют глубины поддеревьев, `Math.max` выбирает более глубокое (самый длинный путь идёт через него), `1` добавляет сам текущий узел. Значение возвращается вызвавшему — родителю, который сделает то же самое уровнем выше.

Обратите внимание: рекурсия честно посещает **оба** поддерева, ни одно нельзя пропустить — заранее неизвестно, какое из них глубже.

## Трассировка

Дерево `[3, 9, 20, null, null, 15, 7]`. Вызовы в порядке завершения (post-order):

```
maxDepth(9):  дети null, null → 1 + max(0, 0) = 1
maxDepth(15): дети null, null → 1 + max(0, 0) = 1
maxDepth(7):  дети null, null → 1 + max(0, 0) = 1
maxDepth(20): 1 + max(1, 1) = 2
maxDepth(3):  1 + max(1, 2) = 3
```

Ответ `3`. Видно, что ответ поднимается снизу вверх: корень узнаёт результат только после того, как оба поддерева полностью обработаны.

Вырожденное дерево `[1, null, 2]`:

```
1
 \
  2
```

`maxDepth(2) = 1 + max(0, 0) = 1`, `maxDepth(1) = 1 + max(0, 1) = 2`. Ответ `2`.

## Почему это работает

По индукции по числу узлов. Для пустого дерева глубина `0` — это база. Пусть для поддеревьев с меньшим числом узлов функция возвращает верную глубину. Любой путь от корня до листа начинается с корня и дальше целиком лежит либо в левом, либо в правом поддереве. Значит, самый длинный такой путь — это корень плюс самый длинный путь в одном из поддеревьев, то есть `1 + max(depth(left), depth(right))`. Поддеревья меньше исходного, так что для них функция верна по предположению.

## Пограничные случаи

- **Пустое дерево** (`root = null`): сразу `0`.
- **Один узел**: `1 + max(0, 0) = 1`.
- **Дерево-«палка»** (каждый узел имеет одного ребёнка): глубина равна `n`, рекурсия уходит на `n` уровней. При `n = 10⁴` это близко к пределу стека JavaScript; если дерево может быть глубже, лучше BFS или DFS с явным стеком.
- **Отрицательные значения**: не влияют, значения узлов вообще не используются.

## Сложность

- **Время `O(n)`**: функция вызывается один раз для каждого узла и по разу для каждого `null`-ребёнка (их `n + 1`), каждый вызов — `O(1)` работы помимо рекурсии.
- **Память `O(h)`**, где `h` — высота дерева: столько кадров одновременно лежит в стеке вызовов. Для сбалансированного дерева это `O(log n)`, для вырожденного — `O(n)`.

## Типичные ошибки

1. **База `return 1` для листа без базы для `null`** → падение на `root.left.left`, когда ребёнка нет, или неверный ответ для пустого дерева.
2. **Считать рёбра вместо узлов** → ответ на 1 меньше; в этой задаче глубина — число **узлов** на пути.
3. **`Math.min` вместо `Math.max`** — это другая задача (Minimum Depth), и там к тому же нужна особая обработка узлов с одним ребёнком.
4. **Глобальный счётчик, который увеличивают при спуске и забывают уменьшать** при возврате → глубина растёт с каждым посещённым узлом.

## Как узнать такую задачу

- Нужна характеристика дерева, которая **складывается из характеристик поддеревьев**: высота, размер, сумма, «сбалансировано ли».
- Формулировка «самый длинный путь от корня до листа».
- Если нужны данные по уровням (ширина, средние, последний узел уровня) — скорее BFS.
- Похожие задачи: Minimum Depth of Binary Tree, Balanced Binary Tree, Diameter of Binary Tree, Count Complete Tree Nodes, Binary Tree Maximum Path Sum.
