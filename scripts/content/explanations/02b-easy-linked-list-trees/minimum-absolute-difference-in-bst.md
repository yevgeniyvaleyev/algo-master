## Задача простыми словами

Дан корень **двоичного дерева поиска** (BST). Нужно найти минимальную абсолютную разность между значениями **любых двух разных узлов**. Узлов не меньше двух, значения неотрицательны.

Пример: `root = [1, 0, 48, null, null, 12, 49]`.

```
     1
    / \
   0   48
      /  \
     12   49
```

Пары с минимальной разностью — `(0, 1)` и `(48, 49)`, разность `1`. Ответ `1`.

## Наивный подход

Собрать все значения и сравнить каждую пару:

```ts naive
const vals: number[] = [];
const collect = (n: TreeNode | null) => {
  if (n === null) return;
  vals.push(n.val);
  collect(n.left);
  collect(n.right);
};
collect(root);
let best = Infinity;
for (let i = 0; i < vals.length; i++)
  for (let j = i + 1; j < vals.length; j++)
    best = Math.min(best, Math.abs(vals[i] - vals[j]));
```

Это `O(n²)` — при `n = 10⁴` около 50 миллионов сравнений. Лишняя работа сразу в двух местах: сравниваются пары, которые **заведомо не могут** дать минимум, и полностью игнорируется свойство BST — дерево уже упорядочено, а мы обращаемся с ним как с произвольной кучей чисел.

## Ключевое наблюдение

Два факта, которые вместе дают линейное решение:

1. **В отсортированной последовательности минимальная разность достигается на соседях.** Если `a ≤ b ≤ c`, то `c - a = (c - b) + (b - a)` не меньше каждой из «соседних» разностей. Значит, достаточно проверить `n - 1` соседних пар.
2. **In-order обход BST выдаёт значения в возрастающем порядке.** Сортировать ничего не нужно — порядок даёт сам обход.

Итого: идём in-order, помним предыдущее значение `prev` и в каждом узле сравниваем его с `prev`.

## Техники

### In-order обход BST

**Что это.** Порядок обхода «левое поддерево → узел → правое поддерево». В двоичном дереве поиска все значения левого поддерева меньше узла, а правого — больше, поэтому in-order перечисляет значения **по возрастанию**.

**Типичный шаблон с «предыдущим» узлом:**

```ts naive
let prev = null;
const inorder = (node) => {
  if (node === null) return;
  inorder(node.left);
  // обработать пару (prev, node)
  prev = node;
  inorder(node.right);
};
```

**Когда применять.** Всё, где BST нужно рассмотреть как отсортированный массив: проверка корректности BST (каждое значение больше `prev`), `k`-й наименьший элемент, поиск двух переставленных узлов (Recover BST), итератор BST.

**Как применяется здесь.** Обрабатываемая пара — `(prev, node.val)`, обработка — обновление минимума разности. Подробнее о двоичных деревьях поиска — во вкладке «Теория».

### Соседние элементы отсортированной последовательности

Общий приём: многие вопросы о парах (минимальная разница, ближайший элемент, пересечения интервалов) в отсортированных данных сводятся к **соседним** элементам. Так `O(n²)` пар превращается в `O(n)`.

## Разбор кода

```ts
function getMinimumDifference(root: TreeNode | null): number {
  let best = Infinity;
  // Значение предыдущего узла в порядке in-order (то есть по возрастанию)
  let prev: number | null = null;
```

`best` — текущий минимум; `Infinity` гарантирует, что первая же найденная разность его заменит. `prev` — значение узла, посещённого непосредственно перед текущим в in-order. Изначально `null`: у самого маленького элемента предшественника нет. Тип `number | null`, а не `0` по умолчанию, — потому что `0` может быть реальным значением узла.

```ts
  const inorder = (node: TreeNode | null): void => {
    if (node === null) {
      return;
    }

    // Сначала все меньшие значения
    inorder(node.left);
```

Рекурсивная функция-замыкание: она видит и меняет `best` и `prev` из внешней функции, поэтому их не надо передавать параметрами. Пустой узел — ничего не делаем. Затем полностью обходим левое поддерево — все значения, меньшие `node.val`. После этого `prev` хранит **наибольшее** из них — непосредственного предшественника `node.val`.

```ts
    // node.val и prev — соседи в отсортированном порядке
    if (prev !== null) {
      best = Math.min(best, node.val - prev);
    }
    prev = node.val;
```

Обработка узла. Если предшественник есть, разность `node.val - prev` — разность соседей в отсортированной последовательности; она неотрицательна, поэтому `Math.abs` не нужен. Проверка именно `prev !== null`, а не `if (prev)`: значение `0` ложно в JS, и узел со значением `0` иначе считался бы «отсутствующим». Затем текущий узел становится предшественником для следующего.

```ts
    // Затем все большие значения
    inorder(node.right);
  };

  inorder(root);
  return best;
}
```

Обходим правое поддерево — значения больше `node.val`; первый из них сравнится с `node.val`. Внешняя функция запускает обход с корня и возвращает найденный минимум. Так как узлов минимум два, хотя бы одна пара будет сравнена, и `best` не останется `Infinity`.

## Трассировка

Возьмём BST, где лучшая пара — узлы на разных уровнях:

```
        27
       /  \
     10    34
    /  \     \
   4    25    50
```

In-order: `4, 10, 25, 27, 34, 50`.

```
узел 4:  prev = null → сравнения нет;           prev = 4
узел 10: 10 - 4 = 6    → best = 6;               prev = 10
узел 25: 25 - 10 = 15  → best = 6;               prev = 25
узел 27: 27 - 25 = 2   → best = 2;               prev = 27
узел 34: 34 - 27 = 7   → best = 2;               prev = 34
узел 50: 50 - 34 = 16  → best = 2;               prev = 50
ответ: 2
```

Пара `(25, 27)` — внук и корень, в дереве они не соседи, но в отсортированном порядке стоят рядом. Именно поэтому сравнивать узел только с его детьми недостаточно.

Пример из условия `[1, 0, 48, null, null, 12, 49]`: in-order `0, 1, 12, 48, 49`, разности `1, 11, 36, 1`, ответ `1`.

## Почему это работает

1. **Порядок.** In-order обход BST перечисляет значения в возрастающем порядке (по индукции: всё левое поддерево меньше узла, всё правое — больше). Значит, в момент обработки узла `prev` — его непосредственный предшественник в отсортированной последовательности.
2. **Достаточность соседей.** Для любой пары `x_i < x_j` в отсортированной последовательности `x_j - x_i` равно сумме соседних разностей между ними, каждая из которых неотрицательна, — поэтому не меньше любой из них. Минимум по всем парам равен минимуму по соседним.
3. Код проверяет **все** соседние пары ровно по одному разу — значит, находит этот минимум.

## Пограничные случаи

- **Два узла**: одна пара, ответ — их разность.
- **Узел со значением `0`**: проверка `prev !== null` не путает его с отсутствием предшественника.
- **Лучшая пара не связана ребром** (`25` и `27` выше): находится благодаря сквозной переменной `prev`.
- **Вырожденное дерево-«палка»**: рекурсия глубиной до `10⁴` — на грани стека JavaScript; при угрозе переполнения in-order делается явным стеком.
- **Повторяющиеся значения**: в BST по этой задаче их нет, но если бы были, ответ корректно стал бы `0`.

## Сложность

- **Время `O(n)`**: in-order посещает каждый узел один раз, работа в узле — `O(1)`.
- **Память `O(h)`**: стек рекурсии высотой дерева — `O(log n)` для сбалансированного, `O(n)` для вырожденного. Массив значений не строится, хватает одной переменной `prev`.

## Типичные ошибки

1. **Сравнивать узел только с детьми** → пропускаются пары вроде «корень и самый правый узел левого поддерева».
2. **`if (prev)` вместо `prev !== null`** → значение `0` воспринимается как «нет предшественника», пара с нулём теряется.
3. **Инициализировать `prev = 0`** → для наименьшего узла появляется фиктивная разность `node.val - 0`, которая может оказаться ложным минимумом.
4. **Передавать `prev` параметром рекурсии** вместо общей переменной → после возврата из левого поддерева обновлённое значение теряется.
5. **Pre-order или post-order вместо in-order** → значения идут не по возрастанию, соседние в обходе не соседи по величине.

## Как узнать такую задачу

- Дано **BST**, а вопрос звучит так, будто дан **отсортированный массив**: минимальная разность, `k`-й элемент, проверка порядка, два ошибочных узла.
- Нужен минимум или максимум по **парам**, а данные можно упорядочить — проверьте, не хватит ли соседних пар.
- Похожие задачи: Minimum Distance Between BST Nodes (та же задача), Kth Smallest Element in a BST, Validate Binary Search Tree, Recover Binary Search Tree, Binary Search Tree Iterator.
