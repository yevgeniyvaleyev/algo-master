## Задача простыми словами

Дан массив `nums`, отсортированный по строгому возрастанию. Нужно построить из него **сбалансированное по высоте** двоичное дерево поиска: у каждого узла высоты левого и правого поддеревьев отличаются не больше чем на 1. Подходит любое такое дерево.

Пример: `nums = [-10, -3, 0, 5, 9]`. Один из правильных ответов:

```
        0
       / \
    -10   5
       \   \
       -3   9
```

В сериализации LeetCode это `[0, -10, 5, null, -3, null, 9]`. Ответ из условия `[0, -3, 9, -10, null, 5]` тоже верен — вариантов несколько.

## Наивный подход

Самое прямолинейное — вставлять элементы в BST по очереди, как в обычное дерево поиска:

```ts naive
let root: TreeNode | null = null;
for (const x of nums) root = insert(root, x);
```

Поскольку массив отсортирован, каждый новый элемент больше всех предыдущих и уходит вправо — получается «палка» высоты `n`. Это корректное BST, но **не сбалансированное**, а построение стоит `O(n²)`. Можно было бы потом балансировать дерево поворотами (как AVL), но это сложная машинерия для простой задачи.

Где ошибка? Мы выбираем корень случайно (первый элемент), хотя сбалансированность целиком зависит от того, **какое значение окажется в корне**.

## Ключевое наблюдение

In-order обход любого BST, построенного из `nums`, должен давать сам `nums`. Если взять корнем **средний** элемент, то слева от него в массиве — ровно меньшие значения (левое поддерево), справа — большие (правое поддерево), и обе половины отличаются по размеру не больше чем на 1. Дальше то же самое рекурсивно для каждой половины. Так дерево получается сбалансированным само собой, без каких-либо поворотов.

## Техники

### Разделяй и властвуй

**Что это.** Задача делится на независимые подзадачи того же вида меньшего размера, они решаются рекурсивно, а результаты объединяются. Три части: **разделить**, **решить** подзадачи, **объединить**.

**Типичный шаблон на отрезке массива:**

```ts naive
function solve(l: number, r: number) {
  if (l > r) return БАЗА;
  const mid = Math.floor((l + r) / 2);
  const left = solve(l, mid - 1);
  const right = solve(mid + 1, r);
  return объединить(mid, left, right);
}
```

**Когда применять.** Когда ответ для отрезка выражается через ответы для его половин: сортировка слиянием, быстрая сортировка, построение дерева отрезков, Sort List, Construct Binary Tree from Preorder and Inorder Traversal.

**Как применяется здесь.** Разделение — по середине отрезка; подзадачи — построить деревья из левой и правой половин; объединение — подвесить их к узлу с `nums[mid]`. Подробнее — во вкладке «Теория».

### Свойство BST и in-order

В BST всё левое поддерево меньше узла, всё правое — больше. Поэтому отсортированный массив — это in-order обход искомого дерева, и любой элемент массива, выбранный корнем, автоматически «правильно» делит остальные на левых и правых. Нам остаётся только выбрать **середину** — ради баланса.

### Индексы вместо копий

Подзадачи задаются границами `l` и `r`, а не `nums.slice(...)`. Копирование половин на каждом уровне стоило бы `O(n log n)` времени и памяти; индексы — `O(1)`.

## Трассировка

`nums = [-10, -3, 0, 5, 9]` (индексы `0..4`):

```
build(0, 4): mid = 2 → узел 0
  build(0, 1): mid = 0 → узел -10
    build(0, -1) → null          (левый ребёнок -10)
    build(1, 1): mid = 1 → узел -3
      build(1, 0) → null
      build(2, 1) → null
    → -10.right = -3
  build(3, 4): mid = 3 → узел 5
    build(3, 2) → null           (левый ребёнок 5)
    build(4, 4): mid = 4 → узел 9
      build(4, 3) → null
      build(5, 4) → null
    → 5.right = 9
→ корень 0: left = -10, right = 5
```

Итог — дерево из раздела «Задача простыми словами», `[0, -10, 5, null, -3, null, 9]`. Отрезки длины 2 (`[0, 1]` и `[3, 4]`) берут левую середину, поэтому второй элемент уходит вправо. Если бы бралась правая середина (`Math.ceil`), получился бы ответ из условия `[0, -3, 9, -10, null, 5]`.

Для `nums = [1, 3]`: `build(0, 1)`, `mid = 0`, корень `1`, правый ребёнок `3` — `[1, null, 3]`; это тоже допустимый ответ.

## Почему это работает

**Это BST.** По индукции: узел получает `nums[mid]`, левое поддерево строится только из `nums[l..mid-1]` — все они меньше `nums[mid]` (массив строго возрастает), правое — из `nums[mid+1..r]`, все больше. Поддеревья по предположению индукции — корректные BST.

**Это сбалансировано.** Отрезок длины `k` делится на половины размеров `⌊(k-1)/2⌋` и `⌈(k-1)/2⌉`, отличающиеся не больше чем на 1. Высота дерева, построенного таким способом из `k` элементов, равна `⌊log₂ k⌋ + 1` — функция, не убывающая по `k` и меняющаяся не больше чем на 1 при увеличении `k` на 1. Значит, высоты левого и правого поддеревьев отличаются не больше чем на 1, и так в каждом узле.

## Пограничные случаи

- **Один элемент**: `mid = 0`, узел без детей.
- **Два элемента**: левая середина — корень, второй элемент — правый ребёнок; высоты поддеревьев `0` и `1`, баланс соблюдён.
- **Чётная длина**: выбор левой или правой середины даёт разные, но одинаково правильные деревья.
- **Отрицательные числа**: на построение не влияют, важен только порядок.
- **Пустой массив**: по ограничениям не встречается, но `build(0, -1)` вернул бы `null`.

## Сложность

- **Время `O(n)`**: каждый вызов с непустым отрезком создаёт ровно один узел, всего `n` таких вызовов плюс `n + 1` вызов с пустыми отрезками; работа в вызове — `O(1)`.
- **Память `O(log n)`** на стек рекурсии: каждый уровень делит отрезок пополам, так что глубина — `⌊log₂ n⌋ + 1`. Само дерево занимает `O(n)`, но это ответ, а не вспомогательная память.

## Типичные ошибки

1. **Вставлять элементы по порядку** в BST → дерево-«палка», не сбалансировано.
2. **Включать `mid` в одну из половин** (`build(l, mid)`) → элемент дублируется, а на отрезке из одного элемента рекурсия зацикливается.
3. **Копировать половины через `slice`** → лишние `O(n log n)` времени и памяти.
4. **Неверное условие базы** (`l >= r`) → теряются отрезки из одного элемента, листья не создаются.
5. **Считать, что ответ единственный**, и подгонять код под пример из условия — любой сбалансированный BST засчитывается.

## Как узнать такую задачу

- Из **отсортированных** данных нужно построить **сбалансированное** дерево.
- Свойство «высоты отличаются не больше чем на 1» достигается делением ровно пополам.
- Ответ для отрезка строится из ответов для двух половин — разделяй и властвуй.
- Похожие задачи: Convert Sorted List to Binary Search Tree, Construct Binary Tree from Preorder and Inorder Traversal, Balance a Binary Search Tree, Sort List.
