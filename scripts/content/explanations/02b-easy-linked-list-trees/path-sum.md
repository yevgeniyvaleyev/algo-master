## Задача простыми словами

Дан корень `root` двоичного дерева и число `targetSum`. Нужно ответить, есть ли путь **от корня до листа** (узла без детей), сумма значений на котором равна `targetSum`.

Пример: `targetSum = 22`.

```
          5
         / \
        4   8
       /   / \
      11  13  4
     /  \      \
    7    2      1
```

Путь `5 → 4 → 11 → 2` даёт `22` — ответ `true`. Для дерева `[1, 2, 3]` и `targetSum = 5` пути `1 → 2` (сумма `3`) и `1 → 3` (сумма `4`) не подходят — ответ `false`.

## Наивный подход

Можно собрать **все** пути от корня до листьев, посчитать сумму каждого и проверить, есть ли среди них `targetSum`:

```ts naive
const sums: number[] = [];
const walk = (node: TreeNode | null, path: number[]) => {
  if (node === null) return;
  const next = [...path, node.val];
  if (node.left === null && node.right === null) {
    sums.push(next.reduce((a, b) => a + b, 0));
  }
  walk(node.left, next);
  walk(node.right, next);
};
walk(root, []);
return sums.includes(targetSum);
```

Это верно, но расточительно: на каждом узле копируется путь, в каждом листе сумма пересчитывается с нуля — до `O(n²)` на вырожденном дереве. Кроме того, обходятся все пути, даже если подходящий найден в самом начале. Лишнее — **хранение пути и повторное суммирование общих префиксов**.

## Ключевое наблюдение

Сумма пути складывается по мере спуска, и нам важен только **остаток**: сколько ещё нужно набрать ниже текущего узла. Если при входе в узел вычесть его значение из `targetSum`, вопрос для поддерева становится той же задачей с меньшим числом: «есть ли путь от этого узла до листа с суммой `rest`?». Состояние — одно число, передаваемое вниз через параметр рекурсии.

## Техники

### DFS сверху вниз с передачей состояния через параметр

**Что это.** Обход в глубину, где информация течёт **от корня к листьям**: каждый вызов получает от родителя накопленное состояние (здесь — остаток суммы) и передаёт обновлённое детям. Это противоположность подходу «снизу вверх», где ответ собирается из ответов детей.

**Типичный шаблон:**

```ts naive
function dfs(node: TreeNode | null, state: S): boolean {
  if (node === null) return false;
  const next = обновить(state, node);
  if (лист(node)) return проверить(next);
  return dfs(node.left, next) || dfs(node.right, next);
}
```

**Когда применять.** Задачи про пути от корня: Path Sum, Path Sum II (собрать сами пути), Sum Root to Leaf Numbers (состояние — число, составленное из цифр), проверка BST с границами `(min, max)`.

**Как применяется здесь.** Состояние — `rest = targetSum - root.val`, проверка в листе — `rest === 0`. Подробнее об обходе дерева в глубину — во вкладке «Теория».

### Ранний выход через `||`

`||` не вычисляет правую часть, если левая уже `true`. Как только подходящий путь найден в левом поддереве, правое не обходится вовсе, и `true` сразу поднимается к корню.

## Разбор кода

```ts
function hasPathSum(root: TreeNode | null, targetSum: number): boolean {
  // В пустом дереве путей нет
  if (root === null) {
    return false;
  }
```

Пустое дерево не содержит ни одного пути от корня до листа, поэтому даже при `targetSum = 0` ответ `false`. Эта же ветка срабатывает, когда рекурсия спускается в отсутствующего ребёнка: «через пустоту» пути нет.

```ts
  // Сколько ещё нужно набрать ниже текущего узла
  const rest = targetSum - root.val;
```

Текущий узел входит в любой путь через него, поэтому сразу «оплачиваем» его значение. Дальше задача для детей — набрать `rest`. Новая переменная, а не изменение `targetSum` на месте, — так понятнее, и значение родителя не портится (хотя для чисел это и так копия).

```ts
  // Лист: путь закончился, проверяем, набрали ли ровно targetSum
  if (root.left === null && root.right === null) {
    return rest === 0;
  }
```

Путь обязан заканчиваться **в листе**, поэтому проверять сумму можно только здесь. Если `rest === 0`, сумма пути от корня до этого листа равна исходному `targetSum`.

```ts
  // Иначе ищем подходящий путь в любом из поддеревьев
  return hasPathSum(root.left, rest) || hasPathSum(root.right, rest);
}
```

Узел не лист — путь продолжается в левое или правое поддерево. Если у узла только один ребёнок, вызов для отсутствующего вернёт `false` по первой базе и не создаст ложного «пути, оканчивающегося в середине дерева».

## Трассировка

Дерево из примера, `targetSum = 22`:

```
hasPathSum(5, 22):  rest = 17, не лист
  hasPathSum(4, 17):  rest = 13, не лист
    hasPathSum(11, 13): rest = 2, не лист
      hasPathSum(7, 2):  rest = -5, лист → false
      hasPathSum(2, 2):  rest = 0,  лист → true
    → true
  → true
→ true (правое поддерево 8 не обходится)
```

Дерево `[1, 2, 3]`, `targetSum = 5`:

```
hasPathSum(1, 5): rest = 4, не лист
  hasPathSum(2, 4): rest = 2, лист → false
  hasPathSum(3, 4): rest = 1, лист → false
→ false
```

## Почему это работает

Утверждение для любого вызова: `hasPathSum(node, s)` возвращает `true` тогда и только тогда, когда в поддереве `node` есть путь от `node` до листа с суммой `s`. Доказательство по индукции по размеру поддерева:

- `node === null` — путей нет, `false` верно.
- `node` — лист: единственный путь — сам узел, его сумма `node.val`; проверка `s - node.val === 0` эквивалентна `node.val === s`.
- Иначе любой путь от `node` до листа — это `node` плюс путь от одного из детей до листа с суммой `s - node.val`. По предположению индукции вызовы для детей отвечают именно на этот вопрос, а `||` объединяет варианты.

Для корня это и есть условие задачи.

## Пограничные случаи

- **Пустое дерево**, `targetSum = 0`: ответ `false` — путей нет вообще.
- **Узел с одним ребёнком**: для `[1, 2]` и `targetSum = 1` корень не лист, поэтому `rest = 0` у корня не засчитывается; ответ `false` — верно.
- **Отрицательные значения**: сумма может уменьшаться при спуске, поэтому обрывать поиск при «переборе» (`rest < 0`) нельзя.
- **Один узел**: ответ `root.val === targetSum`.
- **Несколько подходящих путей**: возвращаемся на первом найденном.

## Сложность

- **Время `O(n)`**: в худшем случае (подходящего пути нет) каждый узел посещается один раз, работа в узле — `O(1)`.
- **Память `O(h)`**: глубина стека рекурсии равна высоте дерева — `O(log n)` для сбалансированного, до `O(n)` (5000) для вырожденного.

## Типичные ошибки

1. **Проверять сумму при `root === null`** (`return targetSum === 0`) → путь, «обрывающийся» у узла с одним ребёнком, ложно засчитывается: `[1, 2]`, `targetSum = 1` даст `true`.
2. **Обрывать поиск при `rest < 0`** → неверно при отрицательных значениях узлов.
3. **Возвращать `true` для пустого дерева при `targetSum = 0`** → по условию путей в пустом дереве нет.
4. **Глобальная сумма без отката** при возврате из рекурсии → сумма «накапливает» значения из соседних ветвей. Передача через параметр избавляет от этого автоматически.

## Как узнать такую задачу

- Речь о путях **от корня до листа** (root-to-leaf) и некотором их свойстве: сумма, число, последовательность.
- Состояние пути — одно значение, которое легко обновить при шаге вниз — передавайте его параметром.
- Если путь может начинаться и заканчиваться где угодно — это уже другая техника (префиксные суммы на дереве, Path Sum III).
- Похожие задачи: Path Sum II, Path Sum III, Sum Root to Leaf Numbers, Binary Tree Paths, Validate Binary Search Tree.
