## Задача простыми словами

Даны корни двух двоичных деревьев `p` и `q`. Нужно проверить, одинаковы ли они: совпадает ли **форма** (где есть дети, а где нет) и **значения** в соответствующих узлах.

Пример: `p = [1, 2]`, `q = [1, null, 2]`.

```
  p:   1          q:   1
      /                 \
     2                   2
```

Значения одни и те же, но у `p` двойка — левый ребёнок, а у `q` — правый. Форма разная, ответ `false`. Для `p = [1, 2, 3]` и `q = [1, 2, 3]` ответ `true`.

## Наивный подход

Первая мысль — обойти оба дерева, выписать значения в массивы и сравнить массивы:

```ts naive
const collect = (n: TreeNode | null, out: number[]) => {
  if (n === null) return;
  out.push(n.val);
  collect(n.left, out);
  collect(n.right, out);
};
```

Но это **неверно**: для примера выше оба дерева дают pre-order `[1, 2]`, хотя они разные. Обход теряет информацию о структуре. Исправить можно, записывая и пустые места (`null`) в сериализацию, — тогда сравнение станет корректным, но мы тратим `O(n)` памяти на две строки и всегда обходим **оба дерева целиком**, даже если они различаются уже в корне.

## Ключевое наблюдение

Деревья одинаковы тогда и только тогда, когда:

1. оба пусты, или
2. оба непусты, у корней одинаковые значения, **и** левые поддеревья одинаковы, **и** правые поддеревья одинаковы.

Это рекурсивное определение напрямую превращается в код: спускаемся по двум деревьям **синхронно**, сравнивая узлы в одинаковых позициях, и останавливаемся на первом же расхождении.

## Техники

### Одновременный DFS по двум деревьям

**Что это.** Рекурсия принимает не один узел, а **пару** узлов, стоящих в одинаковых позициях двух деревьев, и рекурсивно вызывает себя для пар их детей. Это обычный обход в глубину, только «в две руки».

**Типичный шаблон:**

```ts naive
function cmp(a: TreeNode | null, b: TreeNode | null): boolean {
  if (a === null && b === null) return true;
  if (a === null || b === null) return false;
  return проверка(a, b) && cmp(пара 1) && cmp(пара 2);
}
```

**Когда применять.** Сравнение двух деревьев или частей одного дерева: Same Tree (пары `left–left`, `right–right`), Symmetric Tree (пары «крест-накрест»), Subtree of Another Tree, слияние двух деревьев (Merge Two Binary Trees).

**Как применяется здесь.** Пары детей — `(p.left, q.left)` и `(p.right, q.right)`. Подробнее об обходе дерева в глубину — во вкладке «Теория».

### Короткое замыкание `&&`

Оператор `&&` не вычисляет правую часть, если левая уже `false`. Поэтому при несовпадении значений рекурсия в детей не запускается, а при расхождении в левом поддереве правое даже не просматривается. Это бесплатный ранний выход.

## Разбор кода

```ts
function isSameTree(p: TreeNode | null, q: TreeNode | null): boolean {
  // Оба поддерева пустые — совпадают
  if (p === null && q === null) {
    return true;
  }
```

Первая база: в этой позиции у обоих деревьев ничего нет — здесь они совпадают. Сюда рекурсия приходит, например, под каждым листом.

```ts
  // Пусто только одно — структура разная
  if (p === null || q === null) {
    return false;
  }
```

Вторая база. Случай «оба `null`» уже отсечён выше, поэтому если сейчас хотя бы один `null` — то ровно один. В одном дереве узел есть, в другом нет — формы различаются. Порядок двух проверок важен: если поменять их местами, «оба `null`» попадёт во вторую ветку и вернёт `false`.

После этих двух проверок TypeScript знает, что и `p`, и `q` не `null`, и разрешает обращаться к `.val`, `.left`, `.right`.

```ts
  // Оба узла есть: значения должны совпасть,
  // а левые и правые поддеревья — быть одинаковыми попарно
  return p.val === q.val && isSameTree(p.left, q.left) && isSameTree(p.right, q.right);
}
```

Три условия через `&&`: значения корней равны, левые поддеревья одинаковы, правые одинаковы. Вычисление идёт слева направо и обрывается на первом `false`: сравнение значений самое дешёвое и стоит первым.

## Трассировка

`p = [1, 2]`, `q = [1, null, 2]`:

```
isSameTree(p1, q1): оба есть, 1 === 1 → проверяем левых
  isSameTree(p2, null): пусто только одно → false
→ && обрывается, правые не сравниваются
ответ: false
```

`p = [1, 2, 3]`, `q = [1, 2, 3]`:

```
isSameTree(1, 1): 1 === 1
  isSameTree(2, 2): 2 === 2
    isSameTree(null, null) → true   (левые дети двоек)
    isSameTree(null, null) → true   (правые дети двоек)
  → true
  isSameTree(3, 3): 3 === 3
    isSameTree(null, null) → true
    isSameTree(null, null) → true
  → true
ответ: true
```

`p = [1, 2, 1]`, `q = [1, 1, 2]`: корни равны, затем `isSameTree(2, 1)` — значения различаются, `false`, и правая пара уже не проверяется.

## Почему это работает

По индукции по суммарному числу узлов в `p` и `q`. Базовые случаи (хотя бы одно дерево пусто) разобраны явно и верно: два пустых дерева одинаковы, пустое и непустое — нет. Если оба непусты, деревья одинаковы ровно тогда, когда совпадают корни и попарно одинаковы поддеревья, — это определение «одинаковости». Поддеревья меньше исходных, поэтому для них функция верна по предположению индукции. Короткое замыкание не меняет результат: если одно из условий `false`, конъюнкция `false` при любых остальных.

## Пограничные случаи

- **Оба дерева пусты**: первая проверка → `true`.
- **Одно пусто, другое нет**: вторая проверка → `false`.
- **Одинаковые значения, разная форма** (`[1, 2]` и `[1, null, 2]`): ловится второй базой на уровне детей.
- **Одинаковая форма, разные значения**: ловится сравнением `p.val === q.val`.
- **Деревья разного размера**: рекурсия остановится на первом месте, где одно дерево кончилось, а другое нет.

## Сложность

- **Время `O(min(n, m))`**, где `n` и `m` — размеры деревьев: каждая пара узлов сравнивается не более одного раза, а спуск прекращается, как только одно из деревьев кончается в какой-то позиции. В худшем случае (деревья одинаковы) — `O(n)`.
- **Память `O(h)`**: столько кадров одновременно лежит в стеке рекурсии, где `h` — глубина, до которой деревья совпадают по форме (не больше высоты меньшего дерева). Для сбалансированных деревьев это `O(log n)`, для вырожденных — до `O(n)`.

## Типичные ошибки

1. **Сравнивать только обходы** (pre-order, in-order) без пустых мест → разные деревья признаются одинаковыми.
2. **Перепутать порядок баз** → два пустых поддерева считаются разными.
3. **Обращаться к `p.val` до проверок на `null`** → `TypeError`, как только одно из деревьев кончится раньше другого.
4. **Сравнивать узлы по ссылке** (`p === q`) вместо значений → два разных, но одинаковых по содержимому дерева признаются разными.
5. **Сравнивать пары «крест-накрест»** `(p.left, q.right)` — это уже проверка зеркальности, другая задача.

## Как узнать такую задачу

- Нужно **сравнить два дерева** (или два поддерева одного дерева) по структуре и значениям.
- Определение свойства рекурсивно: «корни совпадают и поддеревья удовлетворяют тому же».
- Нужно идти по двум структурам **синхронно** — передавайте в рекурсию пару узлов.
- Похожие задачи: Symmetric Tree, Subtree of Another Tree, Merge Two Binary Trees, Flip Equivalent Binary Trees, Leaf-Similar Trees.
