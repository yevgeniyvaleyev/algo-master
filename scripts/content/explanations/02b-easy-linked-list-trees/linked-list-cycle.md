## Задача простыми словами

Дан `head` — голова односвязного списка. Нужно ответить, есть ли в списке **цикл**: можно ли, двигаясь по `next`, снова попасть в уже пройденный узел. Номер узла `pos`, куда «замыкается» хвост, в функцию не передаётся — он нужен только для описания тестов.

Пример: `head = [3, 2, 0, -4]`, `pos = 1`. Хвост `-4` указывает обратно на узел `2`:

```
3 → 2 → 0 → -4
    ↑        │
    └────────┘
```

Ответ `true`. Для `[1]` с `pos = -1` (хвост указывает на `null`) ответ `false`.

## Наивный подход

Самое очевидное — запоминать уже посещённые узлы и проверять, не пришли ли мы в один из них повторно:

```ts naive
const seen = new Set<ListNode>();
let node = head;
while (node !== null) {
  if (seen.has(node)) return true;
  seen.add(node);
  node = node.next;
}
return false;
```

Это `O(n)` по времени — уже хорошо, но и `O(n)` по памяти: в множество попадает каждый узел. Follow-up задачи прямо просит `O(1)` памяти. Где здесь лишнее? Мы храним **всю историю** пути, хотя нам нужно лишь узнать факт «путь где-то зациклился», а не место, где это произошло.

Ещё одна ловушка наивного мышления — «идти, пока не встретим `null`, и считать шаги; если шагов больше 10⁴ — цикл». Это опирается на ограничение из условия и ломается при другом размере данных, так что это не решение, а хак.

## Ключевое наблюдение

Если в списке есть цикл, то любой указатель, идущий по `next`, рано или поздно **попадает в цикл и больше из него не выходит**. Запустим два указателя с разной скоростью: медленный `slow` (1 шаг) и быстрый `fast` (2 шага).

- Нет цикла — `fast` первым упрётся в `null`.
- Есть цикл — оба окажутся внутри него, и на каждом шаге `fast` сокращает отставание от `slow` **ровно на 1** узел. Расстояние уменьшается на единицу и не может «перепрыгнуть» через ноль — значит, они обязательно встретятся.

Для этого хватает двух переменных — `O(1)` памяти.

## Техники

### Быстрый и медленный указатели (алгоритм Флойда, «черепаха и заяц»)

**Что это.** Два указателя движутся по одной и той же последовательности с разной скоростью, обычно 1 и 2. Последовательность может быть списком, а может быть неявной: `x → f(x)`.

**Типичный шаблон:**

```ts naive
let slow = start, fast = start;
while (fast !== null && fast.next !== null) {
  slow = slow.next;
  fast = fast.next.next;
  if (slow === fast) { /* цикл найден */ }
}
```

**Когда применять.**

- Обнаружить цикл в списке или в функциональной последовательности (Happy Number, Find the Duplicate Number).
- Найти середину списка: когда `fast` дошёл до конца, `slow` стоит на середине.
- Найти **начало** цикла (Linked List Cycle II): после встречи переставить один указатель в голову и двигать оба по одному шагу.

**Как применяется здесь.** Ровно по шаблону: встреча указателей означает цикл, выход `fast` на `null` — его отсутствие. Подробнее о связных списках и приёмах работы с ними — во вкладке «Теория».

### Сравнение по ссылке

Мы сравниваем **узлы** (`slow === fast`), а не их значения. Значения в списке могут повторяться (`[1, 1, 1]` без цикла), и сравнение `slow.val === fast.val` дало бы ложное срабатывание. `===` для объектов в JS сравнивает именно ссылки — то, что нужно.

## Разбор кода

```ts
function hasCycle(head: ListNode | null): boolean {
  // Черепаха шагает на 1 узел, заяц — на 2
  let slow = head;
  let fast = head;
```

Оба указателя стартуют с головы. Стартовать из одной точки удобно: проверка на встречу делается **после** шагов, поэтому равенство в начальный момент не вызывает ложного `true`. Если `head === null`, то оба указателя — `null`, и цикл ниже не выполнится ни разу.

```ts
  // Если цикла нет, заяц рано или поздно упрётся в null
  while (fast !== null && fast.next !== null) {
    slow = slow!.next;
    fast = fast.next.next;
```

Условие цикла проверяет, что `fast` может безопасно сделать **два** шага: сам `fast` не `null` (иначе нельзя прочитать `fast.next`) и `fast.next` не `null` (иначе нельзя прочитать `fast.next.next`). Порядок важен: `&&` вычисляется слева направо и не тронет `fast.next`, если `fast` уже `null`.

`slow!` — подсказка TypeScript: компилятор не знает, что `slow` не может быть `null`, пока `fast` жив, но это так — `slow` всегда идёт **позади** `fast` по тому же пути. Затем каждый делает свой шаг: черепаха — на 1, заяц — на 2.

```ts
    // Заяц догнал черепаху «по кругу» — значит, цикл есть
    if (slow === fast) {
      return true;
    }
  }
```

В линейном списке `fast` всегда строго впереди `slow` и встретиться они не могут. Совпасть они способны только если `fast` «обошёл круг» и оказался в том же узле — это и есть доказательство цикла.

```ts
  // Дошли до конца списка — цикла нет
  return false;
}
```

Цикл `while` закончился, потому что `fast` или `fast.next` оказался `null` — у списка есть конец, а значит, цикла нет.

## Трассировка

`head = [3, 2, 0, -4]`, `pos = 1`. Обозначим узлы `A(3) → B(2) → C(0) → D(-4) → B`.

```
старт:  slow = A, fast = A
шаг 1:  fast=A, fast.next=B — можно идти
        slow = B, fast = C        B ≠ C
шаг 2:  fast=C, fast.next=D — можно идти
        slow = C, fast = D.next = B   C ≠ B
шаг 3:  fast=B, fast.next=C — можно идти
        slow = D, fast = C.next = D   D === D → true
```

Цикл `B → C → D → B` длины 3. После шага 1 оба уже внутри цикла, `fast` отстаёт от `slow` на 2 узла по кругу (от `C` до `B`: `C → D → B`). Каждый шаг сокращает отставание на 1: после шага 2 — 1, после шага 3 — 0. Встреча.

Без цикла, `head = [1, 2]`, узлы `A(1) → B(2) → null`:

```
старт:  slow = A, fast = A
шаг 1:  fast=A, fast.next=B — можно идти
        slow = B, fast = B.next = null   B ≠ null
проверка: fast === null — выходим, return false
```

## Почему это работает

**Нет цикла.** `fast` движется только вперёд по конечному списку и на каждом шаге проходит 2 узла, значит, за `≤ n/2` итераций условие `while` станет ложным. Встречи до этого не будет: `fast` всегда строго дальше `slow` от головы. Ответ `false` верен.

**Есть цикл длины `L`.** Через не более чем `n` шагов `slow` входит в цикл; `fast` к этому моменту уже там. Пусть `d` — на сколько узлов `fast` отстаёт от `slow`, если идти по кругу (`0 ≤ d < L`). За одну итерацию `slow` уходит на 1, `fast` — на 2, и отставание меняется на `d - 1`. Значит, через `d` итераций оно станет `0` — указатели в одном узле. Перепрыгнуть нельзя именно потому, что разница скоростей равна 1. При этом `fast` никогда не встретит `null`, так что цикл `while` не завершится раньше встречи.

## Пограничные случаи

- **Пустой список** (`head = null`): `fast === null`, цикл не выполняется, ответ `false`.
- **Один узел без цикла**: `fast.next === null`, сразу `false`.
- **Один узел, указывающий сам на себя** (`[1]`, `pos = 0`): шаг 1 даёт `slow = A`, `fast = A.next.next = A` — встреча, `true`.
- **Два узла с циклом на голову** (`[1, 2]`, `pos = 0`): `slow = B`, `fast = A`; затем `slow = A`, `fast = A` — `true`.
- **Повторяющиеся значения**: не мешают, потому что сравниваются ссылки.

## Сложность

- **Время `O(n)`**: до входа `slow` в цикл проходит не больше `n` шагов, после входа встреча происходит не позже чем через `L ≤ n` шагов. Каждая итерация — `O(1)`.
- **Память `O(1)`**: только две переменные-указателя, никаких структур данных.

## Типичные ошибки

1. **Проверить только `fast.next !== null`** без `fast !== null` → `TypeError` при чтении `.next` у `null` на списке чётной длины.
2. **Сравнивать перед шагом** (`if (slow === fast)` в начале тела) при старте из одной точки → сразу ложный `true`.
3. **Сравнивать значения** `slow.val === fast.val` вместо узлов → ложные срабатывания на повторяющихся значениях.
4. **Заяц шагает на 3 и больше**: в общем случае встреча тоже произойдёт, но доказательство сложнее и проверки на `null` громоздче; скорость 2 — простой и надёжный выбор.
5. **Портить список** (например, ставить метку в `val` или перенаправлять `next`) — это «работает», но изменяет входные данные, что обычно запрещено.

## Как узнать такую задачу

- Структура, где из каждого элемента есть **ровно один переход** «дальше» (`next`, `f(x)`, `nums[i]` как индекс), и вопрос — зациклится ли движение.
- Требование **`O(1)` памяти** там, где очевидное решение использует `Set` посещённых.
- Нужна середина списка, `k`-й с конца элемент или точка входа в цикл — тоже двухуказательные приёмы.
- Похожие задачи: Linked List Cycle II, Happy Number, Find the Duplicate Number, Middle of the Linked List, Palindrome Linked List.
