## Задача простыми словами

Дан корень `root` двоичного дерева. Нужно **зеркально отразить** дерево (поменять местами левое и правое во всех узлах) и вернуть его корень.

Пример: `root = [4, 2, 7, 1, 3, 6, 9]`.

```
до:        4                после:      4
         /   \                        /   \
        2     7                      7     2
       / \   / \                    / \   / \
      1   3 6   9                  9   6 3   1
```

Ответ `[4, 7, 2, 9, 6, 3, 1]`. Дерево как будто посмотрели в зеркало, поставленное вертикально.

## Наивный подход

Частая первая попытка — поменять местами детей **только у корня**:

```ts naive
const tmp = root.left;
root.left = root.right;
root.right = tmp;
```

Получится `[4, 7, 2, 6, 9, 1, 3]` — поддеревья переставлены, но внутри каждого порядок остался прежним (`6` всё ещё слева от `9`). Отражение — свойство **всего** дерева, а не одного уровня.

Другой «лобовой» путь — выписать уровни дерева в массивы, развернуть каждый уровень и построить дерево заново. Это работает, но требует `O(n)` памяти на копию, создаёт новые узлы и сложно восстанавливает связи при пропусках (`null`). Лишняя работа — пересборка структуры, которую можно изменить на месте.

## Ключевое наблюдение

Зеркальное отражение дерева = отразить левое поддерево, отразить правое поддерево и **поменять их местами** у корня. Это рекурсивное определение: каждый узел делает одно и то же локальное действие — обмен своих детей, — а рекурсия гарантирует, что это произойдёт в **каждом** узле. Новых узлов не нужно, меняются только ссылки.

## Техники

### Рекурсивный DFS с изменением дерева на месте

**Что это.** Обход в глубину, при котором в каждом узле выполняется локальная операция над его ссылками. Здесь операция — обмен `left` и `right`. Порядок post-order (сначала дети, потом узел): рекурсивно обрабатываем оба поддерева, затем меняем их местами.

**Типичный шаблон:**

```ts naive
function transform(node: TreeNode | null): TreeNode | null {
  if (node === null) return null;
  const l = transform(node.left);
  const r = transform(node.right);
  // пересобрать node из l и r
  return node;
}
```

**Когда применять.** Когда дерево нужно преобразовать структурно: отразить, обрезать (Trim a BST), удалить листья с условием, «выпрямить» в список (Flatten Binary Tree to Linked List). Функция возвращает новый корень поддерева, и родитель просто присваивает его.

**Как применяется здесь.** Для отражения порядок не принципиален: можно менять детей до рекурсии (pre-order) или после (post-order), и даже обходить BFS-ом — важно лишь, чтобы обмен случился в каждом узле ровно один раз. Подробнее об обходах дерева — во вкладке «Теория».

## Разбор кода

```ts
function invertTree(root: TreeNode | null): TreeNode | null {
  // Пустое дерево отражать нечего
  if (root === null) {
    return null;
  }
```

База рекурсии: отражение пустого дерева — пустое дерево. Она же срабатывает, когда рекурсия спускается в отсутствующего ребёнка листа.

```ts
  // Сначала отражаем оба поддерева...
  const left = invertTree(root.left);
  const right = invertTree(root.right);
```

Рекурсивно отражаем поддеревья и **сохраняем** их корни в локальные переменные. Корни поддеревьев при отражении не меняются (меняются только их внутренние связи), так что `left` — это тот же узел, что и `root.left`, просто уже отражённый изнутри. Сохранение в переменные важно для следующего шага: оно делает обмен безопасным без отдельной временной переменной.

```ts
  // ...затем меняем их местами
  root.left = right;
  root.right = left;

  return root;
}
```

Обмен: бывшее правое поддерево становится левым, бывшее левое — правым. Если бы мы написали `root.left = invertTree(root.right); root.right = invertTree(root.left);`, то во втором присваивании `root.left` уже был бы перезаписан — оба ребёнка указали бы на одно поддерево. Локальные `left` и `right` от этого защищают.

Возвращаем `root`, чтобы родитель (или вызывающий код) получил корень отражённого поддерева.

## Трассировка

`root = [4, 2, 7, 1, 3, 6, 9]`. Вызовы в порядке завершения:

```
invertTree(1): left=null, right=null → обмен ничего не меняет → 1
invertTree(3): аналогично → 3
invertTree(2): left=1, right=3 → 2.left=3, 2.right=1
invertTree(6): → 6
invertTree(9): → 9
invertTree(7): left=6, right=9 → 7.left=9, 7.right=6
invertTree(4): left=2 (уже 3,1), right=7 (уже 9,6)
               → 4.left=7, 4.right=2
```

Итоговое дерево:

```
        4
      /   \
     7     2
    / \   / \
   9   6 3   1
```

Обход по уровням — `[4, 7, 2, 9, 6, 3, 1]`, как в ответе.

## Почему это работает

По индукции по высоте. Пустое дерево — уже своё отражение. Пусть для поддеревьев меньшей высоты функция возвращает их корректно отражённые версии. Зеркальное отражение дерева с корнем `r` по определению имеет тот же корень, слева — отражение **правого** поддерева, справа — отражение **левого**. Именно это и строит код: `root.left = right` (отражённое правое), `root.right = left` (отражённое левое). Каждый узел обрабатывается ровно одним вызовом, поэтому обмен в нём происходит ровно один раз — двойной обмен вернул бы всё на место.

## Пограничные случаи

- **Пустое дерево**: возвращается `null`.
- **Один узел**: оба ребёнка `null`, обмен `null` на `null` ничего не меняет.
- **Узел с одним ребёнком**: ребёнок переезжает на другую сторону — `[2, 1]` становится `[2, null, 1]`.
- **Вырожденное дерево-«палка»**: рекурсия глубиной `n`; при ограничении в 100 узлов это не проблема.
- **Повторяющиеся значения**: не важны, работаем только со ссылками.

## Сложность

- **Время `O(n)`**: каждый узел обрабатывается одним вызовом, внутри — `O(1)` работы (два присваивания).
- **Память `O(h)`**: глубина стека рекурсии равна высоте дерева — `O(log n)` для сбалансированного, `O(n)` для вырожденного. Дополнительных структур нет, дерево меняется на месте.

## Типичные ошибки

1. **Обмен только у корня** → поддеревья внутри не отражены.
2. **Перезапись без временной переменной**: `root.left = invertTree(root.right); root.right = invertTree(root.left);` → оба ребёнка указывают на одно поддерево.
3. **Обмен и в pre-order, и в post-order одновременно** (или двойной вызов для узла) → обмен дважды, дерево возвращается к исходному виду.
4. **Создавать новые узлы** вместо изменения ссылок — лишняя память, а если смешать старые и новые узлы, легко получить общие поддеревья.
5. **Забыть `return root`** → вызывающий код получает `undefined`.

## Как узнать такую задачу

- Нужно **преобразовать структуру** дерева (отразить, переставить, обрезать), а не просто посчитать что-то.
- Операция локальна для каждого узла и одинакова для всех — классический рекурсивный обход с действием в узле.
- Слова «mirror», «invert», «flip».
- Похожие задачи: Symmetric Tree (проверка зеркальности без изменения), Flip Equivalent Binary Trees, Flatten Binary Tree to Linked List, Trim a Binary Search Tree.
