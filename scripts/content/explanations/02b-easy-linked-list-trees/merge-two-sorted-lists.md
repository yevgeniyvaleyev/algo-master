## Задача простыми словами

Даны головы двух **отсортированных** по неубыванию связных списков `list1` и `list2`. Нужно слить их в один отсортированный список, **переиспользуя существующие узлы** (а не создавая новые), и вернуть его голову.

Пример: `list1 = [1, 2, 4]`, `list2 = [1, 3, 4]` → `[1, 1, 2, 3, 4, 4]`. Если оба списка пусты — ответ пустой; если пуст один — ответ равен другому.

## Наивный подход

Лобовой вариант — выписать все значения в массив, отсортировать его и построить новый список:

```ts naive
const values: number[] = [];
for (let n = list1; n !== null; n = n.next) values.push(n.val);
for (let n = list2; n !== null; n = n.next) values.push(n.val);
values.sort((a, b) => a - b);
const dummy = new ListNode(0);
let tail = dummy;
for (const v of values) { tail.next = new ListNode(v); tail = tail.next; }
return dummy.next;
```

Это `O((n + m) log(n + m))` времени и `O(n + m)` памяти, и к тому же создаёт новые узлы, хотя условие просит «сшить» исходные. Главная потеря — **мы выбрасываем информацию**: оба списка уже отсортированы, а сортировка начинает с нуля, как будто порядка нет.

## Ключевое наблюдение

Наименьший ещё не взятый элемент всегда находится в **голове одного из двух списков** — внутри каждого списка дальше идут только не меньшие значения. Значит, достаточно на каждом шаге сравнить две головы, забрать меньшую и сдвинуться. Один проход, без сортировки и без новых узлов — это шаг слияния (merge) из сортировки слиянием.

## Техники

### Слияние двух отсортированных последовательностей

**Что это.** Два указателя, по одному на каждую последовательность. На каждом шаге выбираем меньший из двух текущих элементов, кладём его в результат и сдвигаем соответствующий указатель. Когда одна последовательность кончилась, остаток второй дописывается целиком.

**Когда применять.** Объединение отсортированных массивов или списков (Merge Sorted Array), сортировка слиянием, слияние `k` списков (там головы держат в куче), пересечение и объединение отсортированных множеств.

**Как применяется здесь.** Указателями служат сами переменные `list1` и `list2`: «сдвинуть указатель» — значит сделать `list1 = list1.next`. Подробнее о связных списках — во вкладке «Теория».

### Фиктивная голова (dummy node)

**Что это.** Вспомогательный узел перед началом результата. Пока результат пуст, «последним узлом» служит `dummy`, поэтому код добавления всегда одинаковый: `tail.next = узел; tail = tail.next`. В конце настоящая голова — `dummy.next`.

**Зачем.** Без заглушки пришлось бы отдельно решать, какой узел станет головой (меньший из двух первых), и отдельно обрабатывать пустые списки. Заглушка убирает эти ветки — частый источник ошибок в задачах на списки (удаление узлов, разбиение списка, сложение чисел в списках).

## Разбор кода

```ts
function mergeTwoLists(list1: ListNode | null, list2: ListNode | null): ListNode | null {
  // Фиктивная голова: не нужно отдельно решать, кто станет первым узлом
  const dummy = new ListNode(0);
  // tail — последний узел уже собранного результата
  let tail = dummy;
```

`dummy` — единственный новый узел во всём решении; его значение `0` ни на что не влияет, потому что сам он в ответ не попадает. `tail` всегда указывает на последний узел собранной части — туда пришиваем следующий.

```ts
  // Пока в обоих списках есть узлы, пришиваем меньший
  while (list1 !== null && list2 !== null) {
    if (list1.val <= list2.val) {
      tail.next = list1;
      list1 = list1.next;
    } else {
      tail.next = list2;
      list2 = list2.next;
    }
    tail = tail.next;
  }
```

Пока сравнивать есть что, сравниваем головы. Меньшую пришиваем к хвосту результата (`tail.next = ...`) и сразу сдвигаем этот список на следующий узел. Важно сдвинуть **до** того, как мы когда-нибудь перезапишем `next` пришитого узла: здесь `list1 = list1.next` читает старый `next`, а меняется он только на следующей итерации через `tail.next = ...`.

`<=` (а не `<`) означает, что при равенстве берём узел из `list1` — слияние **устойчиво**: равные элементы сохраняют порядок «сначала из первого списка». Для чисел это не важно, но для записей с ключами — существенно.

`tail = tail.next` — хвост переезжает на только что пришитый узел.

```ts
  // Один из списков закончился — остаток другого уже отсортирован,
  // подвешиваем его целиком
  tail.next = list1 !== null ? list1 : list2;

  return dummy.next;
}
```

После цикла пуст хотя бы один список. Остаток другого уже отсортирован и все его значения не меньше последнего пришитого, поэтому его не нужно перебирать — достаточно одной ссылки. Если пусты оба, `tail.next = null` — тоже корректно. Возвращаем `dummy.next` — первый настоящий узел (или `null`, если оба списка были пусты).

## Трассировка

`list1 = [1, 2, 4]`, `list2 = [1, 3, 4]`. Обозначим узлы первого списка `a1, a2, a4`, второго — `b1, b3, b4`.

```
итерация 1: 1 <= 1 → берём a1, list1 = a2   результат: 1a
итерация 2: 2 vs 1 → берём b1, list2 = b3   результат: 1a 1b
итерация 3: 2 vs 3 → берём a2, list1 = a4   результат: 1a 1b 2
итерация 4: 4 vs 3 → берём b3, list2 = b4   результат: 1a 1b 2 3
итерация 5: 4 <= 4 → берём a4, list1 = null результат: 1a 1b 2 3 4a
выход: list1 === null → tail.next = list2 = b4
итог: 1a → 1b → 2 → 3 → 4a → 4b
```

При равенстве (итерации 1 и 5) первым идёт узел из `list1` — так работает `<=`.

Пример с пустым списком, `list1 = []`, `list2 = [0]`: цикл не выполняется ни разу, `tail = dummy`, `tail.next = list2`, ответ `[0]`.

## Почему это работает

**Инвариант:** перед каждой итерацией цепочка `dummy.next … tail` содержит уже взятые узлы в отсортированном порядке, и каждый из них не больше любого узла, оставшегося в `list1` и `list2`.

- В начале цепочка пуста — инвариант верен.
- На шаге берём минимум из двух голов. Так как каждый список отсортирован, голова — минимум своего остатка, а значит, взятый узел — минимум **всех** оставшихся. Он не меньше уже взятых (по инварианту) и не больше оставшихся — инвариант сохраняется.
- После цикла один список пуст, остаток другого отсортирован и по инварианту не меньше всех взятых — подвешивание сохраняет сортировку.

Каждый узел пришивается ровно один раз, поэтому в ответе все `n + m` узлов.

## Пограничные случаи

- **Оба списка пусты**: цикл не выполняется, `tail.next = null`, ответ `dummy.next = null`.
- **Один список пуст**: ответ — второй список целиком, без перебора.
- **Все элементы одного списка меньше всех элементов другого**: цикл забирает весь первый список, второй подвешивается одной ссылкой.
- **Равные значения**: обрабатываются ветвью `<=`, порядок устойчивый.
- **Отрицательные значения**: на сравнение не влияют.

## Сложность

- **Время `O(n + m)`**: каждая итерация цикла пришивает один узел, итераций не больше `n + m`; подвешивание остатка — `O(1)`.
- **Память `O(1)`**: создаётся только `dummy`, все остальные узлы переиспользуются. Рекурсивный вариант слияния проще на вид, но тратит `O(n + m)` памяти на стек вызовов.

## Типичные ошибки

1. **Забыть `tail = tail.next`** → все узлы пришиваются к `dummy`, в ответе остаётся один последний.
2. **Вернуть `dummy` вместо `dummy.next`** → в начале ответа лишний узел `0`.
3. **Дописывать остаток в цикле по одному узлу** — не ошибка, но лишний код; достаточно одной ссылки.
4. **Создавать новые узлы** (`new ListNode(list1.val)`) — условие просит сшивать существующие, и это лишняя память.
5. **Без заглушки** забыть случай пустых списков или выбор головы → `null`-разыменование.

## Как узнать такую задачу

- Даны **две или несколько уже отсортированных** последовательностей, и нужно получить общую отсортированную.
- Слова «merge», «splice together», «in-place» про списки.
- Нужно строить новый список и не хочется отдельно разбирать «первый узел» — сигнал к фиктивной голове.
- Похожие задачи: Merge Sorted Array, Merge k Sorted Lists, Sort List (сортировка слиянием на списке), Add Two Numbers, Partition List.
