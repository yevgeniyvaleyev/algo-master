## Задача простыми словами

Дан корень `root` двоичного дерева. Для каждого **уровня** (всех узлов на одинаковом расстоянии от корня) нужно посчитать среднее значение и вернуть массив средних сверху вниз.

Пример: `root = [3, 9, 20, null, null, 15, 7]`.

```
    3          уровень 0: 3           → 3
   / \
  9   20       уровень 1: 9, 20       → 14.5
     /  \
    15   7     уровень 2: 15, 7       → 11
```

Ответ `[3, 14.5, 11]`.

## Наивный подход

Можно для каждого уровня `d` отдельно обойти дерево и собрать узлы на глубине `d`:

```ts naive
const result: number[] = [];
for (let d = 0; d < maxDepth(root); d++) {
  let sum = 0, count = 0;
  const walk = (n: TreeNode | null, depth: number) => {
    if (n === null || depth > d) return;
    if (depth === d) { sum += n.val; count++; return; }
    walk(n.left, depth + 1);
    walk(n.right, depth + 1);
  };
  walk(root, 0);
  result.push(sum / count);
}
```

Это `O(n · h)`: на каждый уровень заново проходим все верхние уровни. Для вырожденного дерева — `O(n²)`. Лишняя работа — **повторные спуски** к уровню, хотя уровни естественно идут один за другим и каждый полностью определяет следующий (это дети его узлов).

## Ключевое наблюдение

Следующий уровень — это ровно все дети узлов текущего уровня, перечисленные слева направо. Значит, можно идти **уровень за уровнем**: имея массив узлов текущего уровня, за один проход по нему посчитать сумму и собрать массив следующего уровня. Каждый узел обрабатывается один раз, а граница уровня и число узлов на нём известны бесплатно — это длина массива.

## Техники

### Обход в ширину (BFS) по уровням

**Что это.** BFS посещает узлы в порядке удаления от корня: сначала уровень 0, затем все узлы уровня 1, затем уровня 2 и т. д. Классически его пишут с очередью; в варианте «по уровням» нужно ещё знать, где кончается один уровень и начинается другой.

**Два типичных способа отделить уровни:**

1. Очередь и фиксированный размер: перед обработкой уровня запомнить `size = queue.length` и извлечь ровно `size` узлов.
2. Два массива: `level` (текущий) и `next` (следующий); после прохода по `level` выполнить `level = next`.

**Когда применять.** Любой ответ, сформулированный «по уровням»: Level Order Traversal, Right Side View, Zigzag Level Order, максимум на каждом уровне, минимальная глубина (BFS остановится на первом листе).

**Как применяется здесь.** Используется второй способ — два массива. Он не требует `shift()` (который у массивов JS работает за `O(n)`) и сразу даёт размер уровня. Подробнее об обходе в ширину — во вкладке «Теория».

## Разбор кода

```ts
function averageOfLevels(root: TreeNode | null): number[] {
  const result: number[] = [];
  if (root === null) {
    return result;
  }
```

`result` — массив средних по уровням. Пустое дерево не имеет уровней — возвращаем пустой массив (по ограничениям узлов хотя бы один, но тип допускает `null`).

```ts
  // Текущий уровень дерева
  let level: TreeNode[] = [root];
```

Уровень 0 состоит из одного корня. `let`, потому что в конце каждой итерации переменная будет указывать на следующий уровень.

```ts
  while (level.length > 0) {
    // Узлы следующего уровня соберём по ходу обхода текущего
    const next: TreeNode[] = [];
    let sum = 0;
```

Цикл идёт, пока уровень непуст. Для каждого уровня заводим свежие `next` и `sum` — они относятся только к нему.

```ts
    for (const node of level) {
      sum += node.val;
      if (node.left !== null) next.push(node.left);
      if (node.right !== null) next.push(node.right);
    }
```

Один проход по уровню делает две вещи сразу: накапливает сумму значений и собирает детей в `next`. Порядок «сначала левый, потом правый» сохраняет порядок слева направо (для среднего он не важен, но шаблон остаётся универсальным). `null`-детей не добавляем, чтобы в массиве уровня были только реальные узлы и `level.length` равнялся их числу.

```ts
    // Уровень пройден целиком — записываем его среднее
    result.push(sum / level.length);
    level = next;
  }

  return result;
}
```

Среднее — сумма, делённая на число узлов уровня; деление в JS вещественное, поэтому `29 / 2 = 14.5` без дополнительных приведений. Затем переходим к следующему уровню. Когда у последнего уровня нет детей, `next` пуст, и цикл заканчивается.

## Трассировка

`root = [3, 9, 20, null, null, 15, 7]`:

```
level = [3]
  sum = 3; дети 3: 9, 20 → next = [9, 20]
  result = [3]
level = [9, 20]
  9: sum = 9, детей нет
  20: sum = 29, дети 15, 7 → next = [15, 7]
  result = [3, 14.5]
level = [15, 7]
  sum = 22, детей нет → next = []
  result = [3, 14.5, 11]
level = [] → выход
```

Ответ `[3, 14.5, 11]`.

## Почему это работает

**Инвариант:** в начале `k`-й итерации `level` содержит ровно все узлы на глубине `k`.

- Для `k = 0` это `[root]` — верно.
- Пусть верно для `k`. Каждый узел глубины `k + 1` — ребёнок ровно одного узла глубины `k`, и наоборот, каждый ребёнок узла глубины `k` имеет глубину `k + 1`. Цикл `for` добавляет в `next` всех (непустых) детей узлов `level`, ни одного не пропуская и не повторяя. Значит, `next` — ровно уровень `k + 1`.

Раз `level` — полный уровень, `sum / level.length` — его точное среднее. Цикл заканчивается после последнего непустого уровня, так что в `result` по одному среднему на каждый уровень, сверху вниз.

## Пограничные случаи

- **Один узел**: ответ `[root.val]`.
- **Пустое дерево**: `[]`.
- **Большие значения** (до `2^31 - 1`) и до `10⁴` узлов на уровне: сумма уровня до ~`2 · 10¹³`, что меньше `2^53` — `number` в JS хранит такие целые точно, переполнения нет (в Java/C++ понадобился бы `long`).
- **Отрицательные значения**: среднее может быть отрицательным, это нормально.
- **Вырожденное дерево**: каждый уровень из одного узла, ответ — сами значения сверху вниз.

## Сложность

- **Время `O(n)`**: каждый узел попадает в `level` ровно один раз и обрабатывается за `O(1)`.
- **Память `O(w)`**, где `w` — максимальная ширина уровня: одновременно живут `level` и `next`, то есть два соседних уровня. Для полного дерева нижний уровень содержит около `n / 2` узлов, так что в худшем случае это `O(n)`. Плюс сам ответ — `O(h)` чисел.

## Типичные ошибки

1. **Классическая очередь без разделения уровней** → узлы разных уровней смешиваются в одной сумме.
2. **Делить на число всех узлов** или на ширину «полного» уровня (`2^k`) вместо фактического `level.length`.
3. **Класть `null`-детей в массив уровня** → `level.length` завышен, и при чтении `node.val` получаем `TypeError`.
4. **`queue.shift()` в цикле** — работает, но каждый `shift` у массива JS стоит `O(n)`, и на больших деревьях обход становится квадратичным.
5. **Целочисленное деление** (`Math.floor(sum / count)`) по привычке из других языков — ответ должен быть вещественным.

## Как узнать такую задачу

- Ответ — **массив по уровням**: средние, максимумы, суммы, крайние узлы, сами уровни.
- Слова «level», «level by level», «each depth».
- Нужно знать, где кончается один уровень, — массив уровня или фиксированный размер очереди.
- Похожие задачи: Binary Tree Level Order Traversal, Binary Tree Right Side View, Binary Tree Zigzag Level Order Traversal, Find Largest Value in Each Tree Row, Minimum Depth of Binary Tree.
