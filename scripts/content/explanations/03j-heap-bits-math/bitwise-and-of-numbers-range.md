## Задача простыми словами

Даны два числа `left ≤ right` (от `0` до `2³¹ - 1`). Нужно вернуть побитовое И (`&`) **всех** чисел отрезка `[left, right]` включительно.

Пример: `left = 5`, `right = 7`. `5 & 6 & 7` = `101 & 110 & 111` = `100` = `4`. А для `left = 1`, `right = 2147483647` ответ `0`.

## Наивный подход

Просто пройти по всем числам:

```ts naive
let result = left;
for (let x = left + 1; x <= right; x++) result &= x;
return result;
```

Отрезок может содержать до `2³¹` чисел — около двух миллиардов итераций, слишком медленно. Можно добавить ранний выход «если `result === 0`, стоп», но и это не спасает в худшем случае. Лишняя работа: мы честно обрабатываем каждое число, хотя результат И зависит только от **структуры битов** концов отрезка — какие старшие биты общие у `left` и `right`.

## Ключевое наблюдение

Запишем `left` и `right` в двоичном виде и найдём их **общий префикс** — старшие биты, которые совпадают.

```
left  = 26 = 1 1 0 1 0
right = 30 = 1 1 1 1 0
             └─┘ общий префикс «11»
                 ↑ первый различающийся бит: у left 0, у right 1
```

- Биты **префикса** одинаковы у всех чисел между `left` и `right` (числа между ними отличаются только младшими битами), поэтому в И они сохраняются.
- В первом различающемся бите у `left` стоит `0`, у `right` — `1`. Значит, отрезок содержит число `префикс 0 111…1` и следующее за ним `префикс 1 000…0`. Их И обнуляет этот бит **и все младшие**.

Ответ — общий префикс, дополненный нулями: `11000 = 24`. Чтобы найти префикс, сдвигаем оба числа вправо, пока они не станут равны, и считаем сдвиги.

## Техники

### Битовые сдвиги

**Что это.** `x >> 1` отбрасывает младший бит (для неотрицательных — целочисленное деление на 2), `x << s` дописывает `s` нулей справа (умножение на `2^s`). Пара «сдвинуть вправо, потом обратно влево» обнуляет младшие биты числа.

**Типичный шаблон** — общий старший префикс двух чисел:

```ts naive
let shift = 0;
while (a !== b) { a >>= 1; b >>= 1; shift++; }
const prefix = a << shift;
```

**Как применяется здесь.** Сдвигаем `left` и `right` до совпадения; совпавшее значение и есть префикс. В JS сдвиги работают с 32-битными знаковыми целыми, но по условию числа не больше `2³¹ - 1`, так что знаковый бит не задействован. Подробнее о битовых операциях — во вкладке «Теория».

### Свойство И на отрезке

И нескольких чисел имеет единицу в бите, только если **у всех** чисел там единица. На отрезке подряд идущих чисел младшие биты «пробегают» и нули, и единицы, поэтому сохраниться могут только старшие биты, которые ни разу не меняются на всём отрезке, — а это ровно общий префикс концов.

## Разбор кода

```ts
function rangeBitwiseAnd(left: number, right: number): number {
  // Ответ — общий двоичный префикс left и right, дополненный нулями.
  // Сдвигаем оба числа вправо, пока они не совпадут
  let shift = 0;
```

`shift` — сколько младших битов мы отбросили. Именно столько нулей потом вернём справа.

```ts
  while (left < right) {
    left >>= 1;
    right >>= 1;
    shift++;
  }
```

Пока числа различаются, отбрасываем у обоих младший бит. Условие `left < right` эквивалентно `left !== right`: сдвиг вправо сохраняет порядок (`a ≤ b ⇒ a >> 1 ≤ b >> 1`), поэтому `left` никогда не обгонит `right`. Когда они совпали — у нас в руках общий префикс, «прижатый» к правому краю. Цикл выполнится не больше 31 раза: после 31 сдвига оба числа станут `0`.

```ts
  // Возвращаем общий префикс на место; младшие shift битов — нули
  return left << shift;
}
```

Сдвигаем префикс обратно: старшие биты встают на свои позиции, а `shift` младших заполняются нулями. Переполнения нет — результат не больше исходного `left`, а значит, меньше `2³¹`.

## Трассировка

`left = 26` (`11010`), `right = 30` (`11110`):

```
старт:     left = 11010 (26), right = 11110 (30), shift = 0
итерация 1: left =  1101 (13), right =  1111 (15), shift = 1
итерация 2: left =   110 (6),  right =   111 (7),  shift = 2
итерация 3: left =    11 (3),  right =    11 (3),  shift = 3
left === right → выход
ответ: 3 << 3 = 11000 = 24
```

Проверка: `26 & 27 = 11010 & 11011 = 11010`, `& 28 (11100) = 11000`, `& 29 (11101) = 11000`, `& 30 (11110) = 11000 = 24`. Верно.

Пример из условия `left = 5`, `right = 7`: `(5, 7) → (2, 3) → (1, 1)`, `shift = 2`, ответ `1 << 2 = 4`.

## Почему это работает

Пусть общий префикс `left` и `right` имеет длину `p` битов (с учётом ведущих нулей до 31-го бита), а в позиции `d` они впервые различаются: у `left` там `0`, у `right` — `1` (иначе было бы `left > right`).

1. **Биты префикса сохраняются.** Любое `x` из `[left, right]` имеет тот же префикс: если бы `x` отличалось в одном из этих битов, оно было бы меньше `left` или больше `right`. Значит, у всех чисел эти биты одинаковы, и И их не меняет.
2. **Бит `d` и младшие обнуляются.** Число `m = префикс 1 000…0` (бит `d` равен 1, младшие — 0) не больше `right`, а `m - 1 = префикс 0 111…1` не меньше `left`. Оба лежат в отрезке. В `m` все младшие биты — нули, а в `m - 1` бит `d` — ноль. Значит, в И все биты от `d` и ниже — нули.

Цикл сдвигов находит ровно этот префикс: числа перестают различаться в тот момент, когда отброшены бит `d` и все младшие, — это `shift = d + 1`.

## Пограничные случаи

- **`left === right`**: цикл не выполняется, ответ — само число.
- **`left = 0`**: цикл идёт, пока `right` не станет `0`; ответ `0 << shift = 0`.
- **Отрезок пересекает степень двойки** (`left = 7`, `right = 8`): префикс пустой, ответ `0`.
- **`right = 2³¹ - 1`**: сдвиги работают корректно, это максимальное положительное int32.
- **`left = 1`, `right = 2³¹ - 1`**: 31 итерация, ответ `0`.

## Сложность

- **Время `O(log right)`**: каждая итерация отбрасывает один бит; итераций не больше 31.
- **Память `O(1)`**: одна переменная `shift`.

## Типичные ошибки

1. **Перебор всех чисел** → до `2³¹` итераций, превышение времени.
2. **Возвращать `left` после цикла без обратного сдвига** → вместо префикса на месте получаем префикс, сдвинутый в младшие биты.
3. **Возвращать `left & right`** → `26 & 30 = 11010 = 26`, а правильно `24`: И только концов не учитывает числа внутри отрезка.
4. **Сдвиг `>>>` или `<<` на значениях больше `2³¹ - 1`** в других вариантах задачи → переполнение int32 в JS; здесь ограничения его исключают.
5. **Считать, что достаточно найти старший бит `right`** → важен первый **различающийся** бит, а не первый единичный.

## Как узнать такую задачу

- Побитовая операция (`&`, `|`) над **всем отрезком** подряд идущих чисел, а длина отрезка огромна.
- Ответ зависит только от концов отрезка — ищите **общий двоичный префикс** или старший различающийся бит.
- Альтернатива того же семейства — приём Кернигана `right &= right - 1` (сбрасывает младшую единицу, пока `right > left`). Похожие задачи: Number of 1 Bits, Counting Bits, Reverse Bits, Minimum Flips to Make a OR b Equal to c.
