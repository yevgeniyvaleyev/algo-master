## Задача простыми словами

Дан массив **различных** точек на плоскости с целыми координатами (до 300 точек, координаты от `-10⁴` до `10⁴`). Нужно вернуть **наибольшее число точек, лежащих на одной прямой**.

Пример: `[[1, 1], [2, 2], [3, 3]]` → `3`, все точки на прямой `y = x`. Через любые две точки прямая проходит всегда, поэтому ответ не меньше `min(n, 2)`.

## Наивный подход

Перебрать все пары точек (каждая пара задаёт прямую) и для каждой пары посчитать, сколько остальных точек на ней лежит. Проверка «точка `k` на прямой через `i` и `j`» без деления — через векторное произведение:

```ts naive
let best = Math.min(n, 2);
for (let i = 0; i < n; i++)
  for (let j = i + 1; j < n; j++) {
    let cnt = 2;
    for (let k = j + 1; k < n; k++) {
      const [dx1, dy1] = [xj - xi, yj - yi];
      const [dx2, dy2] = [xk - xi, yk - yi];
      if (dx1 * dy2 - dy1 * dx2 === 0) cnt++;
    }
    best = Math.max(best, cnt);
  }
```

Это `O(n³)`: при `n = 300` около 4.5 миллиона проверок — проходит, но лишняя работа налицо. Для фиксированной точки `i` мы проверяем одну и ту же прямую многократно: если на ней лежат `j₁, j₂, j₃`, то пары `(i, j₁)`, `(i, j₂)`, `(i, j₃)` каждая заново пересчитывает одни и те же точки.

## Ключевое наблюдение

Прямая однозначно задаётся **точкой и наклоном**. Зафиксируем точку `i`. Для каждой другой точки `j` вычислим наклон отрезка `i → j`. Все точки с **одинаковым наклоном** лежат на одной прямой через `i` — это одна и та же прямая. Значит, для точки `i` достаточно **сгруппировать** остальные точки по наклону в хеш-таблице: самая большая группа плюс сама `i` — лучшая прямая через `i`.

Так за `O(n)` для каждого `i` мы находим лучшую прямую через него, а всего — `O(n²)`.

Остаётся вопрос, как хранить наклон. Число `dy / dx` в double ненадёжно: разные дроби могут округлиться одинаково, вертикаль даёт `±Infinity`, а горизонталь — `0` или `-0`. Поэтому наклон хранится как **несократимая дробь** с нормализованным знаком.

## Техники

### Группировка через хеш-таблицу

**Что это.** Чтобы найти самую большую группу «эквивалентных» объектов, каждому объекту ставят в соответствие **канонический ключ** (одинаковый у эквивалентных и разный у неэквивалентных) и считают частоты ключей в `Map`. Самая большая частота — ответ.

**Типичный шаблон:**

```ts naive
const groups = new Map<string, number>();
for (const item of items) {
  const key = canonical(item);
  groups.set(key, (groups.get(key) ?? 0) + 1);
}
```

**Как применяется здесь.** Объекты — точки `j`, эквивалентность — «на одной прямой с `i`», ключ — сокращённый наклон `"dy/dx"`. Подробнее о хеш-таблицах и математических приёмах — во вкладке «Теория».

### Наклон как несократимая дробь (НОД)

Дробь `dy / dx` приводится к каноническому виду:

1. делим числитель и знаменатель на `gcd(|dx|, |dy|)` — так `2/4` и `1/2` дают одно и то же;
2. нормализуем знак: `dx > 0`, а при `dx = 0` (вертикаль) — `dy > 0`. Так `(-1)/(-2)` и `1/2` совпадают.

После этого у каждой прямой ровно один ключ. Горизонталь всегда превращается в `0/1`, вертикаль — в `1/0`.

### Алгоритм Евклида

`gcd(a, b) = gcd(b, a mod b)`, `gcd(a, 0) = a`. Работает за `O(log min(a, b))` шагов. Удобное свойство: `gcd(0, b) = b`, так что горизонтальные и вертикальные отрезки обрабатываются без особых случаев.

## Разбор кода

```ts
function maxPoints(points: number[][]): number {
  const n = points.length;
  // Через одну или две точки всегда проходит прямая
  if (n <= 2) return n;
```

Одна точка — ответ `1`, две — `2`. Дальше считаем, что точек хотя бы три.

```ts
  // НОД по алгоритму Евклида
  const gcd = (a: number, b: number): number => (b === 0 ? a : gcd(b, a % b));
```

Рекурсивный НОД. Аргументы — неотрицательные целые до `2 · 10⁴`, глубина рекурсии — десятки уровней. Поскольку точки различны, `dx` и `dy` не равны нулю одновременно, и `gcd` всегда положителен — деления на ноль не будет.

```ts
  let best = 0;
  for (let i = 0; i < n; i++) {
    // Для точки i: наклон -> сколько других точек лежат на прямой с этим наклоном через i
    const slopes = new Map<string, number>();
    let localBest = 0;
```

Для каждой опорной точки `i` заводим **свою** таблицу наклонов: одинаковый наклон через разные опорные точки — это параллельные, а не одна и та же прямая, поэтому таблицы не смешиваются. `localBest` — размер самой большой группы для этой `i`.

```ts
    for (let j = i + 1; j < n; j++) {
      let dx = points[j][0] - points[i][0];
      let dy = points[j][1] - points[i][1];
```

Перебираем только `j > i`. Этого достаточно: любая прямая с несколькими точками будет полностью посчитана, когда `i` — **первая** (с наименьшим индексом) из её точек; все остальные её точки имеют индекс больше. Вектор `(dx, dy)` — направление от `i` к `j`.

```ts
      // Сокращаем дробь dy/dx, чтобы одинаковые наклоны дали одинаковый ключ
      // (числа не делим — у double нет точного сравнения дробей)
      const g = gcd(Math.abs(dx), Math.abs(dy));
      dx /= g;
      dy /= g;
```

Делим на НОД модулей — получаем несократимую пару. Деление здесь точное (`g` делит оба числа), так что `dx` и `dy` остаются целыми. Для горизонтали `dy = 0`, `g = |dx|`, пара становится `(±1, 0)`; для вертикали — `(0, ±1)`.

```ts
      // Нормализуем знак: dx > 0, а для вертикали (dx = 0) берём dy > 0
      if (dx < 0 || (dx === 0 && dy < 0)) {
        dx = -dx;
        dy = -dy;
      }
```

Направления `(dx, dy)` и `(-dx, -dy)` задают одну прямую, но без нормализации дали бы разные ключи: точка левее `i` и точка правее `i` на одной прямой не попали бы в одну группу. Правило «`dx` положителен, а при `dx = 0` положителен `dy`» выбирает одного представителя из пары.

```ts
      const key = `${dy}/${dx}`;
      const count = (slopes.get(key) ?? 0) + 1;
      slopes.set(key, count);
      localBest = Math.max(localBest, count);
    }
```

Ключ — строка вида `"1/2"`: у `Map` с массивами в качестве ключей сравнение шло бы по ссылке, а строки сравниваются по значению. Тонкость: при `dy = 0` и `dx < 0` после смены знака `dy` становится `-0`, но шаблонная строка превращает `-0` в `"0"`, так что ключ горизонтали всегда `"0/1"`. Затем увеличиваем счётчик группы и обновляем максимум.

```ts
    // +1 — сама точка i
    best = Math.max(best, localBest + 1);
  }

  return best;
}
```

Группа содержит только точки `j`, поэтому добавляем саму `i`. Для последней точки внутренний цикл пуст, `localBest + 1 = 1` — на ответ это не влияет, ведь `n ≥ 3`.

## Трассировка

Точки: `A(0, 0)`, `B(2, 1)`, `C(-2, -1)`, `D(1, 3)`, `E(4, 2)`. Ожидаемый ответ `4` — прямая `y = x/2` через `A, B, C, E`.

```
i = 0 (A):
  j = B: dx=2,  dy=1,  g=1 → (2, 1)            ключ "1/2" → 1
  j = C: dx=-2, dy=-1, g=1 → знак → (2, 1)     ключ "1/2" → 2
  j = D: dx=1,  dy=3,  g=1                     ключ "3/1" → 1
  j = E: dx=4,  dy=2,  g=2 → (2, 1)            ключ "1/2" → 3
  localBest = 3 → best = 4
i = 1 (B):
  j = C: dx=-4, dy=-2, g=2 → (-2,-1) → (2, 1)  ключ "1/2" → 1
  j = D: dx=-1, dy=2,  g=1 → знак → (1, -2)    ключ "-2/1" → 1
  j = E: dx=2,  dy=1,  g=1                     ключ "1/2" → 2
  localBest = 2 → 3, best = 4
i = 2 (C):
  j = D: dx=3, dy=4 → "4/3" → 1
  j = E: dx=6, dy=3, g=3 → "1/2" → 1
  localBest = 1 → 2
i = 3 (D):
  j = E: dx=3, dy=-1 → "-1/3" → 1 → 2
i = 4 (E): нет j → 1
ответ 4
```

Без нормализации знака точка `C` (левее `A`) получила бы ключ `"-1/-2"` и не попала бы в группу `"1/2"` — ответ оказался бы `3`. Без сокращения `E` получила бы `"2/4"` — тоже мимо.

## Почему это работает

**Ключи корректны.** Две точки `j`, `k` лежат на одной прямой с `i` тогда и только тогда, когда векторы `i → j` и `i → k` коллинеарны, то есть пропорциональны. Пропорциональные целые векторы после деления на НОД и нормализации знака дают **одну и ту же** несократимую пару, а непропорциональные — разные. Значит, группы в `slopes` — это ровно прямые через `i`.

**Ни одна прямая не упущена.** Пусть лучшая прямая содержит точки с индексами `p₁ < p₂ < … < p_m`. На итерации `i = p₁` все `p₂, …, p_m` имеют индекс больше `i`, у них один ключ, и группа имеет размер не меньше `m - 1`. Тогда `best ≥ m`. С другой стороны, каждая группа + `i` — это реальные точки на одной прямой, так что `best` не превышает истинного ответа.

## Пограничные случаи

- **Одна или две точки**: ранний возврат `n`.
- **Вертикальная прямая** (`dx = 0`): `g = |dy|`, ключ `"1/0"` после нормализации.
- **Горизонтальная прямая** (`dy = 0`): ключ `"0/1"`; `-0` превращается в строку `"0"`.
- **Точки по разные стороны от `i`**: нормализация знака сводит их к одному ключу.
- **Все точки на одной прямой**: на `i = 0` все `n - 1` точек в одной группе, ответ `n`.
- **Дубликаты точек**: по условию их нет; иначе `gcd(0, 0) = 0` дал бы деление на ноль, и дубликаты пришлось бы считать отдельно.

## Сложность

- **Время `O(n² · log C)`**: пар `(i, j)` — `n(n - 1)/2`, на каждую — НОД за `O(log C)`, где `C` — диапазон координат, и операции с `Map` за амортизированное `O(1)` (ключ — короткая строка). При `n = 300` это около 45 000 пар.
- **Память `O(n)`**: таблица `slopes` для одной точки `i` содержит не больше `n - 1` ключей и пересоздаётся на каждой итерации.

## Типичные ошибки

1. **Ключ — `dy / dx` как число double** → коллизии из-за округления, `Infinity` и `-Infinity` для вертикали в разных направлениях, `0` и `-0`.
2. **Нет нормализации знака** → точки по разные стороны от `i` попадают в разные группы.
3. **Не сокращать дробь** → `"2/4"` и `"1/2"` считаются разными наклонами.
4. **Одна общая `Map` на все `i`** → параллельные прямые сливаются в одну группу.
5. **Забыть `+1` за саму точку `i`** → ответ на единицу меньше.

## Как узнать такую задачу

- Геометрия на **целочисленной** решётке: «сколько точек на одной прямой», «одинаковое направление», «коллинеарность».
- Нужно сгруппировать объекты по отношению, которое выражается **дробью** — значит, ключ строится через НОД и нормализацию знака, а не через деление.
- Шаблон «зафиксировать один объект + хеш-таблица по отношению к остальным» даёт `O(n²)` вместо `O(n³)`. Похожие задачи: Number of Boomerangs (группировка по расстоянию), Line Reflection, Valid Boomerang, Check If It Is a Straight Line.
