## Задача простыми словами

Дано целое `n` (от `0` до `10⁴`). Нужно вернуть, сколько **нулей стоит в конце** десятичной записи `n!` = `1 · 2 · 3 · … · n`. Дополнительный вопрос — решить за логарифмическое время.

Пример: `5! = 120` — один ноль в конце, ответ `1`. `3! = 6` — ответ `0`. `0! = 1` — ответ `0`.

## Наивный подход

**Посчитать факториал и считать нули.** Уже `25!` ≈ `1.55 · 10²⁵` не помещается в точную арифметику `number` (точность double — около 15–16 значащих цифр), а `10⁴!` содержит больше 35 000 цифр. Через `BigInt` это технически возможно, но умножение длинных чисел делает решение очень медленным.

**Посчитать множители 5 у каждого числа.** Ноль в конце даёт множитель `10 = 2 · 5`, так что можно разложить каждое число от `1` до `n`:

```ts naive
let count = 0;
for (let i = 5; i <= n; i += 5) {
  let x = i;
  while (x % 5 === 0) {
    count++;
    x /= 5;
  }
}
return count;
```

Это уже верно, но `O(n)` (точнее, `O(n/5 · log₅ n)`). Лишняя работа: мы по отдельности проверяем каждое кратное пяти, хотя **сколько** чисел делится на 5, на 25, на 125 — можно сказать сразу одним делением.

## Ключевое наблюдение

1. Каждый конечный ноль — это множитель `10 = 2 · 5` в разложении `n!` на простые. Двоек (от чётных чисел) в `n!` всегда больше, чем пятёрок, поэтому **нулей ровно столько, сколько пятёрок**.
2. Пятёрки считаем «слоями» (**формула Лежандра**):
   - каждое кратное 5 даёт хотя бы одну пятёрку — их `⌊n / 5⌋`;
   - каждое кратное 25 даёт **ещё одну** — `⌊n / 25⌋`;
   - кратное 125 — ещё одну, и так далее.

   Итого `⌊n/5⌋ + ⌊n/25⌋ + ⌊n/125⌋ + …`

3. Вместо роста делителя `5, 25, 125, …` можно каждый раз делить само `n` на 5: `⌊⌊n/5⌋/5⌋ = ⌊n/25⌋`. Так сумма считается за `log₅ n` шагов.

## Техники

### Формула Лежандра (кратность простого в факториале)

**Что это.** Показатель степени простого `p` в разложении `n!` равен `⌊n/p⌋ + ⌊n/p²⌋ + ⌊n/p³⌋ + …`. Каждое слагаемое считает числа, которые вносят «ещё одну» копию `p`: число, делящееся на `p³`, учтено в трёх слоях — ровно столько пятёрок оно и содержит.

**Типичное применение.** Конечные нули факториала (в десятичной или другой системе), делимость `n!` на заданное число, биномиальные коэффициенты по модулю простого.

**Как применяется здесь.** `p = 5`, потому что пятёрки — дефицитный множитель для десятки. Подробнее о математических приёмах — во вкладке «Теория».

### Целочисленное деление в JS

В JavaScript `/` даёт дробь, поэтому для `⌊n / 5⌋` нужен `Math.floor`. Для неотрицательных `n` это то же самое, что `Math.trunc`. Тождество `⌊⌊n/a⌋/b⌋ = ⌊n/(a·b)⌋` для натуральных `a`, `b` позволяет делить по шагам без потери точности.

## Разбор кода

```ts
function trailingZeroes(n: number): number {
  // Каждый ноль в конце — это множитель 10 = 2 * 5.
  // Двоек среди множителей n! всегда больше, чем пятёрок,
  // поэтому ответ — количество пятёрок в разложении n!
  let count = 0;
```

`count` — накопленное число пятёрок, оно же ответ. Комментарий фиксирует главный переход: задача о цифрах сводится к задаче о простых множителях.

```ts
  while (n > 0) {
    // n / 5 — сколько чисел до n делятся на 5,
    // на следующем шаге — на 25, затем на 125 и т. д.
    n = Math.floor(n / 5);
    count += n;
  }
```

На первой итерации `n` становится `⌊n₀ / 5⌋` — это число кратных 5 среди `1..n₀`, и мы прибавляем его. На второй — `⌊⌊n₀/5⌋/5⌋ = ⌊n₀/25⌋`, число кратных 25. И так далее: на `t`-й итерации прибавляется `⌊n₀/5ᵗ⌋`. Цикл заканчивается, когда `5ᵗ > n₀` и слагаемое стало нулём. Изменять параметр `n` здесь безопасно — исходное значение после цикла не нужно.

Почему делим `n`, а не умножаем делитель? Вариант `for (let d = 5; d <= n; d *= 5) count += Math.floor(n / d)` тоже верен, но в языках с `int` делитель `d` может переполниться при больших `n`. Деление самого `n` от этой проблемы свободно.

```ts
  return count;
}
```

Сумма всех слоёв — общее число пятёрок, то есть число конечных нулей.

## Трассировка

`n = 30`:

```
старт:       n = 30, count = 0
итерация 1:  n = ⌊30/5⌋ = 6,  count = 6   (5, 10, 15, 20, 25, 30)
итерация 2:  n = ⌊6/5⌋  = 1,  count = 7   (25 — вторая пятёрка)
итерация 3:  n = ⌊1/5⌋  = 0,  count = 7
n = 0 → выход, ответ 7
```

Проверка: `30! = 265252859812191058636308480000000` — семь нулей в конце.

`n = 125`: `25 → 5 → 1 → 0`, `count = 25 + 5 + 1 = 31`. Число `125 = 5³` учтено во всех трёх слоях — три пятёрки.

`n = 4`: первая же итерация даёт `n = 0`, `count = 0`.

## Почему это работает

**Нули = пятёрки.** Число оканчивается на `z` нулей ровно тогда, когда делится на `10^z = 2^z · 5^z`, но не на `10^(z+1)`. Значит, `z = min(e₂, e₅)`, где `e₂`, `e₅` — показатели 2 и 5 в разложении `n!`. Кратных 2 среди `1..n` не меньше, чем кратных 5 (а кратных 4 — не меньше, чем кратных 25, и т. д.), поэтому `e₂ ≥ e₅` и `z = e₅`.

**Подсчёт пятёрок.** Число `m ≤ n` с ровно `j` пятёрками в разложении (`5ʲ | m`, `5ʲ⁺¹ ∤ m`) делится на `5, 25, …, 5ʲ` и учитывается ровно в `j` слоях суммы `⌊n/5⌋ + ⌊n/25⌋ + …`. Сумма по всем `m` даёт `e₅`.

**Цикл.** Индукцией по номеру итерации: после `t` итераций `n = ⌊n₀/5ᵗ⌋` (по тождеству вложенного деления), а `count = ⌊n₀/5⌋ + … + ⌊n₀/5ᵗ⌋`.

## Пограничные случаи

- **`n = 0`**: цикл не выполняется, ответ `0` (`0! = 1`).
- **`n < 5`**: первая итерация даёт `0`, ответ `0`.
- **Степени пятёрки** (`25`, `125`, `625`): каждая даёт несколько пятёрок, формула учитывает их слоями.
- **`n = 10⁴`**: `2000 + 400 + 80 + 16 + 3 = 2499`, всего 6 итераций (последняя с `n = 0` не меняет `count`).

## Сложность

- **Время `O(log₅ n)`**: каждая итерация делит `n` на 5; при `n = 10⁴` — 6 итераций. Это и есть «логарифмическое» решение из follow-up.
- **Память `O(1)`**: одна переменная `count`.

## Типичные ошибки

1. **Вычислять `n!` в `number`** → потеря точности уже на `25!` и неверный подсчёт нулей.
2. **Считать только `⌊n / 5⌋`** → для `n = 25` получится `5` вместо `6`: число `25` даёт две пятёрки.
3. **Считать двойки или `min` двоек и пятёрок** — лишняя работа; двоек всегда больше.
4. **Обычное деление `/` без `Math.floor`** → `n` становится дробным, цикл крутится до исчезающе малых значений и `count` дробный.
5. **Считать нули по числам, кратным 10** (`⌊n / 10⌋`) → `5! = 120` даёт `0` вместо `1`: пара `2 · 5` возникает из разных множителей.

## Как узнать такую задачу

- Вопрос о **конечных нулях**, делимости или степени простого в **факториале** или произведении диапазона.
- Огромные числа, которые нельзя вычислить напрямую, но ответ зависит только от простых множителей.
- Сигнал к формуле Лежандра: «сколько раз `p` входит в `n!`». Похожие задачи: Preimage Size of Factorial Zeroes Function (бинарный поиск по этой же функции), Count Primes, Ugly Number.
