## Задача простыми словами

Нужно реализовать `pow(x, n)` — возведение вещественного числа `x` в **целую** степень `n`, которая может быть отрицательной и очень большой по модулю (от `-2³¹` до `2³¹ - 1`). Результат принимается с точностью `10⁻⁵`.

Пример: `x = 2`, `n = 10` → `1024`. `x = 2`, `n = -2` → `2⁻² = 1/4 = 0.25`. `x = 2.1`, `n = 3` → `9.261`.

## Наивный подход

Умножить `x` на себя `|n|` раз, а для отрицательной степени взять обратную величину:

```ts naive
let result = 1;
for (let i = 0; i < Math.abs(n); i++) result *= x;
return n < 0 ? 1 / result : result;
```

При `|n|` до `2³¹` — это два миллиарда умножений, превышение времени. Лишняя работа видна на примере `x¹⁶`: мы считаем `x·x·x·…·x` шестнадцать раз, хотя `x¹⁶ = ((x²)²)²)²` — всего **четыре** умножения. Наивный цикл не переиспользует уже вычисленные степени.

## Ключевое наблюдение

Степени можно удваивать возведением в квадрат: `x → x² → x⁴ → x⁸ → …` — каждое значение получается одним умножением из предыдущего. А любое `n` раскладывается в сумму степеней двойки по своей **двоичной записи**:

```
n = 13 = 1101₂ = 8 + 4 + 1
x¹³ = x⁸ · x⁴ · x¹
```

Значит, достаточно пройти по битам `n` от младшего к старшему, держа текущую «квадратную» степень `x^(2^t)`, и домножать результат на неё там, где бит равен 1. Битов в `n` около 31, поэтому умножений — около 62 вместо двух миллиардов.

Отрицательную степень сводим к положительной: `x⁻ⁿ = (1/x)ⁿ`.

## Техники

### Быстрое (бинарное) возведение в степень

**Что это.** Алгоритм вычисления `aⁿ` за `O(log n)` умножений. Работает для любой ассоциативной операции: чисел, чисел по модулю, матриц (например, для `n`-го числа Фибоначчи), композиции перестановок.

**Две формы.**

Рекурсивная — через половинную степень:

```ts naive
function pow(x: number, n: number): number {
  if (n === 0) return 1;
  const half = pow(x, Math.floor(n / 2));
  return n % 2 === 0 ? half * half : half * half * x;
}
```

Итеративная — по битам показателя (её использует решение): `x` возводится в квадрат на каждом шаге, а результат домножается, когда младший бит `n` равен 1.

**Как применяется здесь.** Итеративный вариант с памятью `O(1)`. Подробнее о математических приёмах — во вкладке «Теория».

### Работа с битами без побитовых операторов

Обычно бит проверяют как `n & 1`, а сдвигают как `n >>= 1`. Но в JavaScript побитовые операторы приводят число к **32-битному знаковому** целому. После `n = -n` для `n = -2³¹` получится `2³¹` — а это уже за пределами int32: `2³¹ >> 1` даёт `-2³⁰`, и цикл сломается. Поэтому решение использует арифметические аналоги: `n % 2` вместо `n & 1` и `Math.floor(n / 2)` вместо `n >> 1`. Числа в JS — double, и `2³¹` в них представлено точно.

## Разбор кода

```ts
function myPow(x: number, n: number): number {
  // Отрицательная степень: x^-n = (1/x)^n.
  // В JS -(-2^31) не переполняется (это double), в отличие от int в Java/C++
  if (n < 0) {
    x = 1 / x;
    n = -n;
  }
```

Переходим к положительной степени: `x⁻ⁿ = (1/x)ⁿ`. В Java/C++ `-n` для `n = -2³¹` переполнил бы `int` (там нет `+2³¹`), и пришлось бы переходить к `long`. В JS `n` — double, `-(-2147483648) = 2147483648` вычисляется точно. Деление `1 / x` безопасно: по условию либо `x ≠ 0`, либо `n > 0`.

```ts
  let result = 1;
  // Быстрое возведение в степень: идём по битам n от младшего к старшему,
  // x последовательно принимает значения x, x^2, x^4, x^8, ...
  while (n > 0) {
```

`result` начинается с `1` — нейтрального элемента умножения; при `n = 0` цикл не выполнится, и вернётся `x⁰ = 1`. Условие `n > 0` — пока в показателе остались непросмотренные биты.

```ts
    // Бит n равен 1 — соответствующая степень x входит в произведение
    if (n % 2 === 1) result *= x;
    x *= x;
```

Если младший бит текущего `n` равен 1, текущая степень `x^(2^t)` входит в разложение — домножаем результат. Затем возводим `x` в квадрат: теперь это `x^(2^(t+1))` для следующего бита. Проверка `n % 2 === 1` корректна, потому что `n` здесь всегда неотрицательное целое.

```ts
    // Не используем >> : для n = 2^31 побитовый сдвиг переполнил бы int32
    n = Math.floor(n / 2);
  }

  return result;
}
```

Отбрасываем младший бит — целочисленное деление на 2. Когда все биты обработаны, `n` становится `0`, и в `result` собрано произведение нужных степеней.

## Трассировка

`x = 2`, `n = 10` (`1010₂`):

```
старт:   result = 1,    x = 2,     n = 10
шаг 1:   10 % 2 = 0 → result = 1;        x = 4;      n = 5
шаг 2:   5 % 2 = 1  → result = 1·4 = 4;  x = 16;     n = 2
шаг 3:   2 % 2 = 0  → result = 4;        x = 256;    n = 1
шаг 4:   1 % 2 = 1  → result = 4·256 = 1024; x = 65536; n = 0
n = 0 → ответ 1024
```

Действительно, `10 = 8 + 2`, и `2¹⁰ = 2⁸ · 2² = 256 · 4`. На последнем шаге `x` возводится в квадрат «впустую» — это значение уже не используется.

Отрицательная степень, `x = 2`, `n = -2`: сначала `x = 0.5`, `n = 2`.

```
шаг 1:   2 % 2 = 0 → result = 1;     x = 0.25;   n = 1
шаг 2:   1 % 2 = 1 → result = 0.25;  x = 0.0625; n = 0
ответ 0.25
```

## Почему это работает

**Инвариант цикла:** `result · xⁿ` (с текущими значениями переменных) всегда равно искомому `x₀^n₀` (после перехода к положительной степени).

- В начале `result = 1`, `x = x₀`, `n = n₀` — верно.
- Шаг при чётном `n = 2m`: `xⁿ = (x²)ᵐ`. Мы делаем `x = x²`, `n = m` — произведение не меняется.
- Шаг при нечётном `n = 2m + 1`: `xⁿ = x · (x²)ᵐ`. Мы делаем `result = result · x`, `x = x²`, `n = m` — произведение снова не меняется.
- В конце `n = 0`, `x⁰ = 1`, значит `result = x₀^n₀`.

Цикл конечен: `n` уменьшается вдвое на каждом шаге.

## Пограничные случаи

- **`n = 0`**: цикл не выполняется, ответ `1` (даже для `x = 0`, но условие этот случай исключает).
- **`n = -2³¹`**: `-n = 2³¹` точно представимо в double, а `Math.floor(n / 2)` не переполняется, в отличие от `>>`.
- **`x = 1` или `x = -1` при огромном `n`**: около 31 шага, результат `1` или `±1` в зависимости от чётности.
- **`|x| < 1` и огромный `n`** (или `|x| > 1` и огромный отрицательный): результат уходит к `0` (возможен денормализованный ноль), что укладывается в точность `10⁻⁵`.
- **Отрицательное `x`**: знак правильно определяется чётностью — множители `x` перемножаются как есть.

## Сложность

- **Время `O(log |n|)`**: на каждой итерации `n` делится на 2; при `|n| ≤ 2³¹` — не больше 32 итераций и около 64 умножений.
- **Память `O(1)`**: несколько переменных, без рекурсии (рекурсивная версия заняла бы `O(log n)` стека).

## Типичные ошибки

1. **`n & 1` и `n >>= 1`** в JS → для `n = 2³¹` (после смены знака у `-2³¹`) приведение к int32 даёт `-2³¹`, после первого сдвига `n = -2³⁰`, цикл обрывается и возвращается `1`.
2. **В Java/C++ `n = -n` в `int`** → переполнение для `-2³¹`; нужно `long`.
3. **Рекурсия с двумя вызовами** `pow(x, n/2) * pow(x, n/2)` → снова `O(n)` вызовов: половинную степень нужно вычислить один раз и сохранить.
4. **Начинать `result` с `x`** вместо `1` → лишний множитель, ответ в `x` раз больше.
5. **Наивный цикл на `|n|` умножений** → превышение времени при `|n|` порядка миллиардов.

## Как узнать такую задачу

- Нужно вычислить **большую степень** чего-то (числа, числа по модулю, матрицы), и показатель слишком велик для линейного цикла.
- Операция **ассоциативна** — значит, применим бинарный подъём: `aⁿ` через `a^(n/2)`.
- Похожие задачи: Super Pow (степень по модулю с огромным показателем), Fibonacci через матрицу в степени, Count Good Numbers, Sqrt(x) (тоже про логарифмическое число шагов).
