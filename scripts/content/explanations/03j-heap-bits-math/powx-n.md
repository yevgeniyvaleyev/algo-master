## Задача простыми словами

Нужно реализовать `pow(x, n)` — возведение вещественного числа `x` в **целую** степень `n`, которая может быть отрицательной и очень большой по модулю (от `-2³¹` до `2³¹ - 1`). Результат принимается с точностью `10⁻⁵`.

Пример: `x = 2`, `n = 10` → `1024`. `x = 2`, `n = -2` → `2⁻² = 1/4 = 0.25`. `x = 2.1`, `n = 3` → `9.261`.

## Наивный подход

Умножить `x` на себя `|n|` раз, а для отрицательной степени взять обратную величину:

```ts naive
let result = 1;
for (let i = 0; i < Math.abs(n); i++) result *= x;
return n < 0 ? 1 / result : result;
```

При `|n|` до `2³¹` — это два миллиарда умножений, превышение времени. Лишняя работа видна на примере `x¹⁶`: мы считаем `x·x·x·…·x` шестнадцать раз, хотя `x¹⁶ = (x⁸)²`, `x⁸ = (x⁴)²`, `x⁴ = (x²)²` — всего **четыре** умножения. Наивный цикл не переиспользует уже вычисленные степени.

## Ключевое наблюдение

Если знать `x` в половинной степени, полную можно получить **одним-двумя умножениями**:

```
n чётное:   xⁿ = (x^(n/2))²            x¹⁰ = (x⁵)²
n нечётное: xⁿ = (x^⌊n/2⌋)² · x        x⁵  = (x²)² · x
```

А `x^(n/2)` считается тем же способом — через `x^(n/4)`, и так далее, пока степень не станет `0` (`x⁰ = 1`). Степень на каждом шаге уменьшается вдвое, поэтому шагов около `log₂ |n|` — для `2³¹` всего 32 вместо двух миллиардов.

Отрицательную степень сводим к положительной: `x⁻ⁿ = 1 / xⁿ`.

## Техники

### Быстрое (бинарное) возведение в степень

**Что это.** Алгоритм вычисления `aⁿ` за `O(log n)` умножений. Работает для любой ассоциативной операции: чисел, чисел по модулю, матриц (например, для `n`-го числа Фибоначчи), композиции перестановок.

**Шаблон (рекурсивный).**

1. База: `n = 0` → вернуть `1`.
2. Один раз вычислить `half = pow(x, ⌊n/2⌋)`.
3. Вернуть `half · half`, а при нечётном `n` — ещё `· x`.

Ключевое слово — **один раз**: `half` сохраняется в переменную и используется дважды. Это и есть «разделяй и властвуй», где обе половины одинаковы, поэтому вторую считать не нужно.

**Как применяется здесь.** Решение — ровно этот шаблон плюс одна строка для отрицательного `n`. Подробнее о математических приёмах — во вкладке «Теория».

### Арифметика вместо побитовых операторов

Обычно чётность проверяют как `n & 1`, а делят пополам как `n >> 1`. Но в JavaScript побитовые операторы приводят число к **32-битному знаковому** целому. После смены знака у `n = -2³¹` получится `2³¹` — а это уже за пределами int32: `2³¹ >> 1` даёт `-2³⁰`, и рекурсия пойдёт по отрицательной ветке. Поэтому решение использует арифметические аналоги: `n % 2` вместо `n & 1` и `Math.floor(n / 2)` вместо `n >> 1`. Числа в JS — double, и `2³¹` в них представлено точно.

## Разбор кода

```ts
function myPow(x: number, n: number): number {
  // Отрицательная степень: x^-n = 1 / x^n.
  // В JS -(-2^31) не переполняется (это double), в отличие от int в Java/C++
  if (n < 0) return 1 / myPow(x, -n);
```

Переходим к положительной степени: `x⁻ⁿ = 1 / xⁿ`. Это происходит только один раз, на самом верхнем вызове: дальше `n` всегда неотрицательное. В Java/C++ `-n` для `n = -2³¹` переполнил бы `int` (там нет `+2³¹`), и пришлось бы переходить к `long`. В JS `n` — double, `-(-2147483648) = 2147483648` вычисляется точно.

```ts
  // База рекурсии: любое число в нулевой степени — 1
  if (n === 0) return 1;
```

Сюда сводится любая цепочка вызовов: степень делится пополам, пока не станет `0`. Значение `1` — нейтральный элемент умножения, поэтому `half * half` на следующем уровне вверх даст правильный результат.

```ts
  // Считаем x^(n/2) один раз и возводим в квадрат.
  // Не используем >> : для n = 2^31 побитовый сдвиг переполнил бы int32
  const half = myPow(x, Math.floor(n / 2));
```

Один рекурсивный вызов с вдвое меньшей степенью. `Math.floor` округляет вниз: для `n = 5` получаем `2`, для `n = 1` — `0`. Результат сохраняется в `half`, чтобы не вызывать функцию второй раз.

```ts
  // Чётная степень: x^n = (x^(n/2))^2, нечётная — ещё раз умножаем на x
  return n % 2 === 0 ? half * half : half * half * x;
}
```

При чётном `n` два раза по `⌊n/2⌋` дают ровно `n`. При нечётном — `2·⌊n/2⌋ = n - 1`, поэтому не хватает одного множителя `x`. Проверка `n % 2 === 0` корректна, потому что `n` здесь неотрицательное целое.

## Трассировка

`x = 2`, `n = 10`. Спускаемся, деля степень пополам:

```
myPow(2, 10) → half = myPow(2, 5)
myPow(2, 5)  → half = myPow(2, 2)
myPow(2, 2)  → half = myPow(2, 1)
myPow(2, 1)  → half = myPow(2, 0)
myPow(2, 0)  = 1                          (база)
```

Поднимаемся обратно:

```
myPow(2, 1):  1 нечётное → 1 · 1 · 2   = 2
myPow(2, 2):  2 чётное   → 2 · 2       = 4
myPow(2, 5):  5 нечётное → 4 · 4 · 2   = 32
myPow(2, 10): 10 чётное  → 32 · 32     = 1024
```

Пять вызовов вместо десяти умножений — а для `n = 2³¹` будет 33 вызова вместо двух миллиардов.

Отрицательная степень, `x = 2`, `n = -2`: `n < 0` → `1 / myPow(2, 2) = 1 / 4 = 0.25`.

## Почему это работает

Докажем индукцией по `n ≥ 0`, что `myPow(x, n) = xⁿ`:

- **База.** `n = 0`: функция возвращает `1 = x⁰`.
- **Шаг.** Пусть `n > 0` и для всех меньших степеней утверждение верно. `m = ⌊n/2⌋ < n`, поэтому `half = xᵐ`. Если `n = 2m`, то `half · half = x²ᵐ = xⁿ`. Если `n = 2m + 1`, то `half · half · x = x²ᵐ⁺¹ = xⁿ`.

Для `n < 0` функция возвращает `1 / x⁻ⁿ = xⁿ`, используя уже доказанный случай положительной степени. Рекурсия конечна: степень уменьшается вдвое на каждом вызове и доходит до `0`.

## Пограничные случаи

- **`n = 0`**: сразу база, ответ `1` (даже для `x = 0`, но условие этот случай исключает).
- **`n = -2³¹`**: `-n = 2³¹` точно представимо в double, а `Math.floor(n / 2)` не переполняется, в отличие от `>>`.
- **`x = 1` или `x = -1` при огромном `n`**: 33 вызова, результат `1` или `±1` в зависимости от чётности.
- **`|x| > 1` и огромный отрицательный `n`** (`x = 2`, `n = -2³¹`): `myPow(2, 2³¹)` переполняется до `Infinity`, а `1 / Infinity = 0` — укладывается в точность `10⁻⁵`. Аналогично `|x| < 1` и огромный `n` уходит к `0`.
- **Дробное основание с отрицательной степенью** (`x = 0.5`, `n = -3`): `1 / 0.125 = 8`.
- **Отрицательное `x`**: знак правильно определяется чётностью — множители `x` перемножаются как есть.

## Сложность

- **Время `O(log |n|)`**: каждый вызов вдвое уменьшает степень; при `|n| ≤ 2³¹` — не больше 33 вызовов и около 64 умножений.
- **Память `O(log |n|)`**: глубина стека рекурсии, не больше 33 кадров.

**Follow-up на собеседовании:** «а без рекурсии, за `O(1)` памяти?» — итеративный вариант идёт по битам `n` от младшего к старшему: `x` на каждом шаге возводится в квадрат (`x, x², x⁴, x⁸, …`), а результат домножается, когда текущий бит равен 1 (`13 = 1101₂`, `x¹³ = x⁸ · x⁴ · x¹`):

```ts naive
if (n < 0) {
  x = 1 / x;
  n = -n;
}
let result = 1;
while (n > 0) {
  if (n % 2 === 1) result *= x;
  x *= x;
  n = Math.floor(n / 2);
}
return result;
```

## Типичные ошибки

1. **Рекурсия с двумя вызовами** `myPow(x, n/2) * myPow(x, n/2)` → дерево вызовов удваивается на каждом уровне, снова `O(n)`: половинную степень нужно вычислить один раз и сохранить в `half`.
2. **`n & 1` и `n >> 1`** в JS → для `n = 2³¹` (после смены знака у `-2³¹`) приведение к int32 даёт `-2³⁰`, рекурсия уходит в отрицательную ветку и считает неверный ответ.
3. **В Java/C++ `-n` в `int`** → переполнение для `-2³¹`; нужно `long`.
4. **`n / 2` без `Math.floor`** → в JS это дробное число (`5 / 2 = 2.5`), степень уходит в дроби `1.25, 0.625, …`, до `0` она дойдёт только через сотни вызовов, а `n % 2` для дробей не равно ни `0`, ни `1` как надо — ответ неверный.
5. **Наивный цикл на `|n|` умножений** → превышение времени при `|n|` порядка миллиардов.

## Как узнать такую задачу

- Нужно вычислить **большую степень** чего-то (числа, числа по модулю, матрицы), и показатель слишком велик для линейного цикла.
- Операция **ассоциативна** — значит, применим бинарный подъём: `aⁿ` через `a^(n/2)`.
- Похожие задачи: Super Pow (степень по модулю с огромным показателем), Fibonacci через матрицу в степени, Count Good Numbers, Sqrt(x) (тоже про логарифмическое число шагов).
