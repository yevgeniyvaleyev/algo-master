## Задача простыми словами

Даны два массива `nums1` и `nums2`, оба **отсортированы по неубыванию**, и число `k`. Пара — это один элемент из `nums1` и один из `nums2`. Нужно вернуть `k` пар с **наименьшими суммами**.

Пример: `nums1 = [1, 7, 11]`, `nums2 = [2, 4, 6]`, `k = 3`. Все суммы по возрастанию: `1+2=3`, `1+4=5`, `1+6=7`, `7+2=9`, … Ответ — `[[1, 2], [1, 4], [1, 6]]`. При равных суммах допустим любой порядок пар.

## Наивный подход

Перебрать все пары, отсортировать по сумме и взять первые `k`:

```ts naive
const all: number[][] = [];
for (const a of nums1) for (const b of nums2) all.push([a, b]);
all.sort((p, q) => p[0] + p[1] - (q[0] + q[1]));
return all.slice(0, k);
```

Пар `n1 · n2` — при длинах до `10⁵` это до `10¹⁰`, не влезет ни по времени, ни по памяти. Лишняя работа очевидна: `k ≤ 10⁴`, а мы строим и сортируем **все** пары. К тому же мы игнорируем то, что массивы уже отсортированы, — а это бесплатная информация о порядке.

## Ключевое наблюдение

Разложим все пары в таблицу: строка `i` — это `nums1[i]` в паре с `nums2[0], nums2[1], nums2[2], …`

```
            nums2:  2    4    6
nums1 = 1  строка 0: 3 →  5 →  7
nums1 = 7  строка 1: 9 → 11 → 13
nums1 = 11 строка 2: 13 → 15 → 17
```

Так как `nums2` отсортирован, **каждая строка отсортирована по сумме** слева направо. Задача превращается в «слить несколько отсортированных списков и взять первые `k` элементов» — классическое слияние `k` списков через min-кучу. В куче лежит по одному «текущему» кандидату от каждой строки; минимум всей таблицы среди ещё не взятых — всегда один из этих кандидатов.

Ещё одно сокращение: строк больше `k` рассматривать не нужно. `nums1` тоже отсортирован, поэтому первая пара строки `i ≥ k` не меньше первых пар строк `0..k-1`, а их уже `k` штук.

## Техники

### Слияние k отсортированных списков через min-кучу

**Что это.** Есть несколько отсортированных последовательностей, нужно выдавать их элементы в общем порядке. Держим min-кучу из «голов» всех последовательностей. Извлекаем минимум — это следующий элемент общего порядка — и кладём в кучу следующий элемент **той же** последовательности.

```ts naive
for (const list of lists) heap.push({ value: list[0], list, pos: 0 });
while (heap.size() > 0) {
  const { value, list, pos } = heap.pop();
  output(value);
  if (pos + 1 < list.length) heap.push({ value: list[pos + 1], list, pos: pos + 1 });
}
```

**Типичное применение.** Merge k Sorted Lists, k-й наименьший элемент в отсортированной матрице, «умные» последовательности (Ugly Number II). Особенно полезно, когда последовательности **неявные** — их элементы вычисляются по индексам, а не хранятся.

**Как применяется здесь.** Списки — это строки таблицы пар; элемент строки задаётся парой индексов `(i, j)` и вычисляется на лету. Подробнее о кучах — во вкладке «Теория».

### Куча кортежей с компаратором

В куче лежат кортежи `[сумма, i, j]`: сумма — для сравнения, индексы — чтобы восстановить пару и найти следующего кандидата. Своя куча `Heap<T>` принимает компаратор, поэтому достаточно `(a, b) => a[0] < b[0]`.

## Разбор кода

```ts
// В TypeScript нет встроенной кучи — пишем свою.
// Двоичная куча хранится в массиве: дети узла i — 2i + 1 и 2i + 2, родитель — (i - 1) >> 1.
class Heap<T> {
  private data: T[] = [];

  // less(a, b) === true, если a должен стоять ближе к вершине, чем b.
  // (a, b) => a < b — min-куча, (a, b) => a > b — max-куча
  constructor(private less: (a: T, b: T) => boolean) {}

  size(): number {
    return this.data.length;
  }

  // Вершина кучи (минимум или максимум) за O(1)
  peek(): T | undefined {
    return this.data[0];
  }
```

Обобщённая двоичная куча: элементы любого типа `T`, порядок задаёт компаратор `less(a, b)` («`a` выше `b`»). Вершина — `data[0]`.

```ts
  // Добавление за O(log n): кладём в конец и «поднимаем» вверх
  push(value: T): void {
    const a = this.data;
    a.push(value);
    let i = a.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      // Родитель уже «лучше» — порядок кучи восстановлен
      if (!this.less(a[i], a[parent])) break;
      [a[i], a[parent]] = [a[parent], a[i]];
      i = parent;
    }
  }
```

Вставка: кладём в конец массива и поднимаем, пока элемент «лучше» родителя (`(i - 1) >> 1`). Высота дерева — `O(log n)`.

```ts
  // Извлечение вершины за O(log n): на её место ставим последний элемент и «топим» его вниз
  pop(): T | undefined {
    const a = this.data;
    const top = a[0];
    const last = a.pop();
    if (a.length > 0 && last !== undefined) {
      a[0] = last;
      let i = 0;
      while (true) {
        const l = 2 * i + 1;
        const r = l + 1;
        // Выбираем «лучшего» из узла и двух его детей
        let best = i;
        if (l < a.length && this.less(a[l], a[best])) best = l;
        if (r < a.length && this.less(a[r], a[best])) best = r;
        if (best === i) break;
        [a[i], a[best]] = [a[best], a[i]];
        i = best;
      }
    }
    return top;
  }
}
```

Извлечение: возвращаем вершину, на её место ставим последний элемент и опускаем его, меняя с лучшим из детей, пока порядок не восстановится. Если элемент был единственным, после `a.pop()` массив пуст и погружение не нужно.

```ts
function kSmallestPairs(nums1: number[], nums2: number[], k: number): number[][] {
  // В куче — кандидаты [сумма, i, j]; меньшая сумма ближе к вершине
  const heap = new Heap<[number, number, number]>((a, b) => a[0] < b[0]);
```

Min-куча по сумме. Хранить сумму в кортеже выгодно: не нужно пересчитывать её при каждом сравнении.

```ts
  // Для каждого i (не больше k штук) самая маленькая пара — (nums1[i], nums2[0])
  for (let i = 0; i < Math.min(k, nums1.length); i++) {
    heap.push([nums1[i] + nums2[0], i, 0]);
  }
```

Кладём в кучу «голову» каждой строки — пару с `nums2[0]`. Строк берём `min(k, n1)`: если `nums1` длиннее `k`, лишние строки в ответ не попадут (их первые пары не меньше первых пар строк `0..k-1`). Так куча никогда не превышает `k` элементов.

```ts
  const result: number[][] = [];
  while (result.length < k && heap.size() > 0) {
    // Достаём пару с минимальной суммой среди всех кандидатов
    const [, i, j] = heap.pop()!;
    result.push([nums1[i], nums2[j]]);
```

`k` раз извлекаем минимальную сумму. Деструктуризация `[, i, j]` пропускает первый элемент (сумму) — она уже не нужна, нам нужны индексы, по которым восстанавливаем пару. Условие `heap.size() > 0` — страховка: по ограничениям `k ≤ n1 · n2`, и куча раньше не опустеет.

```ts
    // Следующий кандидат в «строке» i — тот же nums1[i] со следующим nums2[j + 1]
    if (j + 1 < nums2.length) {
      heap.push([nums1[i] + nums2[j + 1], i, j + 1]);
    }
  }

  return result;
}
```

Взяв пару `(i, j)`, продвигаем строку `i`: её новый кандидат — `(i, j + 1)`, если строка не закончилась. Каждая пара попадает в кучу не больше одного раза: в строку `i` мы заходим только из `(i, j)` в `(i, j + 1)`, поэтому дубликатов нет и множество посещённых не нужно.

## Трассировка

`nums1 = [1, 7, 11]`, `nums2 = [2, 4, 6]`, `k = 5`. Кучу показываем как множество кандидатов `сумма(i,j)`.

Инициализация (`min(5, 3) = 3` строки): `{3(0,0), 9(1,0), 13(2,0)}`.

1. Достаём `3(0,0)` → ответ `[1, 2]`. Кладём `5(0,1)`. Куча `{5(0,1), 9(1,0), 13(2,0)}`.
2. Достаём `5(0,1)` → `[1, 4]`. Кладём `7(0,2)`. Куча `{7(0,2), 9(1,0), 13(2,0)}`.
3. Достаём `7(0,2)` → `[1, 6]`. `j + 1 = 3` — строка 0 закончилась, ничего не кладём. Куча `{9(1,0), 13(2,0)}`.
4. Достаём `9(1,0)` → `[7, 2]`. Кладём `11(1,1)`. Куча `{11(1,1), 13(2,0)}`.
5. Достаём `11(1,1)` → `[7, 4]`. Кладём `13(1,2)`. `result.length = 5` — стоп.

Ответ: `[[1, 2], [1, 4], [1, 6], [7, 2], [7, 4]]` — совпадает с началом полного списка из условия. Из девяти пар в кучу попало только семь, а при больших массивах разница — миллиарды пар против `O(k)`.

## Почему это работает

**Инвариант:** для каждой строки `i < min(k, n1)`, которая ещё не исчерпана, в куче лежит ровно один её кандидат — **самая левая ещё не взятая** пара `(i, j)`.

Любая не взятая пара `(i, j')` находится в строке правее кандидата `(i, j)` своей строки, а строка отсортирована, поэтому `сумма(i, j) ≤ сумма(i, j')`. Значит, минимальная сумма среди всех не взятых пар — это минимум среди кандидатов, то есть вершина кучи. Каждое извлечение выдаёт следующую пару в порядке возрастания сумм, а после него `push` кандидата `(i, j + 1)` восстанавливает инвариант.

Строки `i ≥ k` пропущены корректно: каждая их пара не меньше `сумма(i', 0)` для любого `i' < k` (так как `nums1` отсортирован), а таких пар уже `k`.

## Пограничные случаи

- **`k = n1 · n2`**: выдаются все пары; строки исчерпываются, куча пустеет ровно к концу.
- **`nums1` длиннее `k`**: в кучу попадают только первые `k` строк.
- **Повторы** (`[1, 1, 2]` и `[1, 2, 3]`): одинаковые значения в разных строках — разные пары, обе попадают в ответ (`[[1, 1], [1, 1]]` при `k = 2`).
- **Отрицательные числа**: суммы сравниваются как обычные числа; `±10⁹ + ±10⁹` точно представимы в double.
- **Равные суммы**: порядок между ними зависит от кучи, но это допустимо.

## Сложность

- **Время `O(k log k)`**: инициализация — до `k` вставок; затем `k` извлечений и до `k` вставок. Куча никогда не больше `k` элементов (каждое извлечение — максимум одна вставка), поэтому каждая операция `O(log k)`.
- **Память `O(k)`**: куча и массив ответа по `k` элементов.

## Типичные ошибки

1. **Класть в кучу все строки**, а не `min(k, n1)` → при `n1 = 10⁵` и маленьком `k` куча раздувается до `O(n1)`, время `O(n1 log n1)`.
2. **Начинать с одной пары `(0, 0)` и двигаться в двух направлениях** `(i + 1, j)` и `(i, j + 1)` без `Set` посещённых → одна пара добавляется дважды и попадает в ответ два раза.
3. **Хранить в куче только сумму** без индексов → нельзя ни восстановить пару, ни найти следующего кандидата.
4. **Забыть проверку `j + 1 < nums2.length`** → в кучу попадёт сумма с `undefined`, то есть `NaN`, и порядок кучи сломается.
5. **Генерировать все пары «с отсечением по сумме»** — без кучи всё равно приходится смотреть на `O(n1 · n2)` пар.

## Как узнать такую задачу

- Нужно `k` наименьших (наибольших) элементов из **неявного множества** комбинаций, которое слишком велико, чтобы его построить.
- Исходные данные **отсортированы**, и из этого следует, что множество раскладывается на несколько отсортированных «строк».
- Сигнал к шаблону «слияние `k` списков через кучу»: «следующий» кандидат легко вычислить по текущему. Похожие задачи: Merge k Sorted Lists, Kth Smallest Element in a Sorted Matrix, Find K-th Smallest Pair Distance, Ugly Number II.
