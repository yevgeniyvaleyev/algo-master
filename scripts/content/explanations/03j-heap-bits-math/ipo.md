## Задача простыми словами

Есть `n` проектов. Проект `i` требует стартового капитала `capital[i]` (деньги не тратятся, это лишь порог входа) и приносит чистую прибыль `profits[i]`. Начальный капитал — `w`. Можно выполнить **не больше `k`** разных проектов по одному, и прибыль каждого сразу добавляется к капиталу. Нужно вернуть **максимально возможный итоговый капитал**.

Пример: `k = 2`, `w = 0`, `profits = [1, 2, 3]`, `capital = [0, 1, 1]`. С нулём доступен только проект 0 → капитал `1`. Теперь доступны проекты 1 и 2; берём более прибыльный (2) → `1 + 3 = 4`.

## Наивный подход

Перебрать все упорядоченные наборы из не более чем `k` проектов, проверяя по пути, что каждый проект доступен при текущем капитале, — это экспонента, бессмысленно при `n = 10⁵`.

Более разумный «наивный» вариант — уже жадный, но без структуры данных: `k` раз пробегать весь массив проектов и выбирать самый прибыльный среди доступных и ещё не выполненных.

```ts naive
const done = new Array(n).fill(false);
for (let round = 0; round < k; round++) {
  let pick = -1;
  for (let i = 0; i < n; i++) {
    if (!done[i] && capital[i] <= w && (pick < 0 || profits[i] > profits[pick])) pick = i;
  }
  if (pick < 0) break;
  done[pick] = true;
  w += profits[pick];
}
```

Это `O(k · n)` — до `10¹⁰` операций. Лишняя работа: в каждом раунде мы **заново проверяем все проекты**, хотя набор доступных меняется предсказуемо — он только **растёт** (капитал не уменьшается), а из него каждый раз уходит один максимум.

## Ключевое наблюдение

1. Прибыль неотрицательна, поэтому капитал **никогда не падает**: проект, ставший доступным, остаётся доступным навсегда.
2. Значит, проекты открываются в порядке возрастания `capital`. Если отсортировать их по `capital`, новые доступные проекты — это всегда **следующий отрезок** отсортированного списка; достаточно одного указателя, который движется только вперёд.
3. Среди доступных нужно раз за разом брать **максимум прибыли** и удалять его — это работа для **max-кучи**.

Жадный выбор «самый прибыльный из доступных» оптимален: больше денег сейчас никогда не сужает выбор потом.

## Техники

### Жадный алгоритм с обменным аргументом

**Что это.** Жадность — на каждом шаге делать локально лучший выбор и никогда его не пересматривать. Она верна не всегда, поэтому её нужно обосновывать. Стандартный способ — **обменный аргумент**: берём любое оптимальное решение и показываем, что замена его выбора на жадный не ухудшает результат.

**Как применяется здесь.** Пусть на некотором шаге оптимальное решение берёт проект `p`, а самый прибыльный доступный — `q` (`profits[q] ≥ profits[p]`). Заменим `p` на `q` (а если `q` взят позже — поменяем их местами). Капитал после этого шага не меньше, чем был, а значит, все дальнейшие проекты по-прежнему доступны, и итог не уменьшается.

### Сортировка + указатель «открытых» элементов

Когда элементы становятся доступными по монотонно растущему порогу, их сортируют по порогу один раз и двигают указатель `next`: всё левее `next` уже «открыто». Каждый элемент проходит через указатель ровно один раз — суммарно `O(n)` на все раунды.

### Max-куча

Куча отдаёт максимум за `O(1)` и удаляет его за `O(log n)`, а новые элементы добавляются тоже за `O(log n)`. Здесь в кучу попадают только прибыли открытых проектов. В TypeScript своей кучи нет, решение использует собственный класс `Heap<T>` с компаратором `(a, b) => a > b`. Подробнее о куче — во вкладке «Теория».

## Разбор кода

```ts
// В TypeScript нет встроенной кучи — пишем свою.
// Двоичная куча хранится в массиве: дети узла i — 2i + 1 и 2i + 2, родитель — (i - 1) >> 1.
class Heap<T> {
  private data: T[] = [];

  // less(a, b) === true, если a должен стоять ближе к вершине, чем b.
  // (a, b) => a < b — min-куча, (a, b) => a > b — max-куча
  constructor(private less: (a: T, b: T) => boolean) {}

  size(): number {
    return this.data.length;
  }

  // Вершина кучи (минимум или максимум) за O(1)
  peek(): T | undefined {
    return this.data[0];
  }
```

Универсальная двоичная куча. Порядок задаётся компаратором `less(a, b)` — «`a` должен быть ближе к вершине». Дерево хранится в массиве `data`, вершина — `data[0]`.

```ts
  // Добавление за O(log n): кладём в конец и «поднимаем» вверх
  push(value: T): void {
    const a = this.data;
    a.push(value);
    let i = a.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      // Родитель уже «лучше» — порядок кучи восстановлен
      if (!this.less(a[i], a[parent])) break;
      [a[i], a[parent]] = [a[parent], a[i]];
      i = parent;
    }
  }
```

Вставка: элемент кладём в конец и поднимаем, пока он «лучше» родителя. Нарушение порядка возможно только на пути «новый лист → корень», поэтому хватает `O(log n)` обменов.

```ts
  // Извлечение вершины за O(log n): на её место ставим последний элемент и «топим» его вниз
  pop(): T | undefined {
    const a = this.data;
    const top = a[0];
    const last = a.pop();
    if (a.length > 0 && last !== undefined) {
      a[0] = last;
      let i = 0;
      while (true) {
        const l = 2 * i + 1;
        const r = l + 1;
        // Выбираем «лучшего» из узла и двух его детей
        let best = i;
        if (l < a.length && this.less(a[l], a[best])) best = l;
        if (r < a.length && this.less(a[r], a[best])) best = r;
        if (best === i) break;
        [a[i], a[best]] = [a[best], a[i]];
        i = best;
      }
    }
    return top;
  }
}
```

Извлечение: запоминаем вершину, ставим на её место последний элемент и опускаем его, каждый раз меняя с **лучшим** из детей, пока он не станет не хуже обоих. Для кучи из одного элемента `a.length` после `pop()` равен нулю, и погружение пропускается.

```ts
function findMaximizedCapital(k: number, w: number, profits: number[], capital: number[]): number {
  const n = profits.length;

  // Индексы проектов по возрастанию требуемого капитала
  const order = Array.from({ length: n }, (_, i) => i).sort((a, b) => capital[a] - capital[b]);
```

Сортируем не сами проекты, а их **индексы** — так `profits[i]` и `capital[i]` остаются связанными, и не нужно создавать массив пар. `Array.from({ length: n }, (_, i) => i)` — это `[0, 1, …, n - 1]`. Компаратор `capital[a] - capital[b]` упорядочивает по возрастанию порога (числа до `10⁹`, разность не переполняется — это обычные double).

```ts
  // Max-куча прибылей проектов, которые уже по карману
  const available = new Heap<number>((a, b) => a > b);
  let next = 0; // первый ещё не открытый проект в order
```

В куче храним только прибыли: для выбора больше ничего не нужно. `next` делит `order` на «уже в куче» (левее) и «ещё недоступны» (правее).

```ts
  for (let round = 0; round < k; round++) {
    // Капитал вырос — открываем все проекты, которые теперь доступны
    while (next < n && capital[order[next]] <= w) {
      available.push(profits[order[next]]);
      next++;
    }
```

До `k` раундов. В начале раунда переносим в кучу все проекты, чей порог теперь не больше `w`. Так как `order` отсортирован, как только встретился проект дороже `w`, все следующие тоже дороже — цикл останавливается. Указатель никогда не возвращается назад, поэтому за всё время работы этот `while` сделает не больше `n` итераций.

```ts
    // Делать нечего: ни один проект не доступен
    if (available.size() === 0) break;
```

Если куча пуста, доступных проектов нет и не появится: капитал больше не вырастет. Выходим досрочно — это же обрабатывает случай `k > n` (проекты закончились).

```ts
    // Жадно берём самый прибыльный из доступных
    w += available.pop()!;
  }

  return w;
}
```

Извлекаем максимум прибыли и добавляем к капиталу. Проект удалён из кучи, поэтому повторно выбран не будет. Непроданные проекты остаются в куче и могут быть выбраны позже.

## Трассировка

`k = 3`, `w = 0`, `profits = [1, 2, 3, 5]`, `capital = [0, 1, 1, 4]`.

`order = [0, 1, 2, 3]` (пороги `0, 1, 1, 4` уже по возрастанию), `next = 0`.

1. `round = 0`, `w = 0`. Открываем: проект 0 (`0 ≤ 0`) → куча `{1}`; проект 1 (`1 ≤ 0`) — нет, стоп, `next = 1`. Берём `1` → `w = 1`.
2. `round = 1`, `w = 1`. Открываем проект 1 (`1 ≤ 1`) → `{2}`, проект 2 (`1 ≤ 1`) → `{3, 2}`; проект 3 (`4 ≤ 1`) — нет, `next = 3`. Берём `3` → `w = 4`.
3. `round = 2`, `w = 4`. Открываем проект 3 (`4 ≤ 4`) → `{5, 2}`, `next = 4`. Берём `5` → `w = 9`.

Цикл завершён (`k = 3`). Ответ `9`. Проект с прибылью `2` так и остался в куче — он хуже остальных и не понадобился. Заметьте: если бы во втором раунде мы взяли `2` вместо `3`, капитал был бы `3`, и проект 3 с прибылью `5` не открылся бы — итог `1 + 2 + 3 = 6`.

## Почему это работает

**Корректность кучи.** Инвариант перед выбором в каждом раунде: куча содержит ровно прибыли проектов, которые доступны при текущем `w` и ещё не выполнены. Новые проекты добавляются по указателю сразу, как только `w` до них дорастает; выполненные удаляются через `pop`. Поскольку `w` не уменьшается, ни один проект из кучи не становится недоступным.

**Оптимальность жадности** (обменный аргумент). Пусть оптимальная последовательность совпадает с жадной в первых `t` шагах, а на шаге `t + 1` берёт `p` вместо самого прибыльного доступного `q`. Если `q` встречается в ней позже — поменяем `p` и `q` местами; иначе заменим `p` на `q`. Капитал после шага `t + 1` не уменьшится (`profits[q] ≥ profits[p]`), а на всех последующих шагах он не меньше, чем был, — значит, все последующие проекты по-прежнему доступны и итог не хуже. Повторяя рассуждение, превращаем оптимальное решение в жадное без потерь.

## Пограничные случаи

- **Ни один проект не доступен изначально** (все `capital[i] > w`): в первом раунде куча пуста → `break`, ответ `w`.
- **`k > n`**: после `n` раундов куча пустеет, срабатывает `break`.
- **Нулевая прибыль**: проект выполняется, капитал не меняется — вреда нет, а ограничение «не больше `k`» это допускает.
- **Одинаковые пороги**: внутренний `while` открывает их все за один раз.
- **Огромный `w`** (больше всех порогов): в первом раунде открываются все проекты, дальше — просто `k` извлечений максимума.

## Сложность

- **Время `O(n log n + k log n)`**: сортировка индексов — `O(n log n)`; каждый проект ровно один раз попадает в кучу (`O(log n)`), и не больше `k` извлечений по `O(log n)`.
- **Память `O(n)`**: массив `order` и куча, в которой может оказаться до `n` прибылей.

## Типичные ошибки

1. **Брать самый дешёвый проект или проект с лучшим отношением прибыль/порог** — жадность по неверному критерию. Порог не тратится, важна только прибыль.
2. **Сбрасывать указатель `next` в каждом раунде** → `O(k · n)` и повторное добавление проектов в кучу.
3. **Не выходить при пустой куче** → `available.pop()` вернёт `undefined`, и `w += undefined` даст `NaN`.
4. **Сортировать `profits` и `capital` по отдельности** → связь «проект — его прибыль» теряется; нужна сортировка индексов или пар.
5. **Min-куча вместо max-кучи** — компаратор `a < b` превратит алгоритм в «бери худший проект».

## Как узнать такую задачу

- Есть ресурс, который **только растёт**, и элементы, которые **открываются** при достижении порога.
- Нужно ограниченное число раз (`k`) выбрать лучший из доступных сейчас вариантов.
- Типичная пара: **сортировка по порогу + указатель** для открытия и **куча по ценности** для выбора. Похожие задачи: Course Schedule III, Maximum Number of Events That Can Be Attended, Minimum Number of Refueling Stops.
