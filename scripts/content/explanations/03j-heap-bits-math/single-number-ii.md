## Задача простыми словами

Дан массив `nums`, в котором каждое число встречается **ровно три раза**, кроме одного — оно встречается **один раз**. Нужно найти это одиночное число. Ограничения жёсткие: время `O(n)` и **константная** дополнительная память.

Пример: `nums = [2, 2, 3, 2]` → `3`. Для `[0, 1, 0, 1, 0, 1, 99]` → `99`. Числа могут быть отрицательными, вплоть до `-2³¹`.

## Наивный подход

Посчитать частоты в `Map` и вернуть число с частотой 1:

```ts naive
const freq = new Map<number, number>();
for (const x of nums) freq.set(x, (freq.get(x) ?? 0) + 1);
for (const [x, c] of freq) if (c === 1) return x;
```

Время `O(n)`, но память `O(n)` — условие нарушено. Сортировка с поиском «одиночки» по тройкам даёт `O(1)` памяти, но `O(n log n)` времени.

Приём из Single Number (там все числа по два раза) — XOR всего массива — здесь не работает: `a ^ a ^ a = a`, тройки не уничтожаются. Лишнее в наивных решениях одно и то же: мы помним **каждое число целиком**, хотя на деле достаточно гораздо меньшей информации.

## Ключевое наблюдение

Посмотрим на **один бит**, например младший. Посчитаем, у скольких чисел массива он равен 1. Каждое «тройное» число добавляет к счётчику `0` или `3`, а одиночное — `0` или `1`. Значит, **счётчик по модулю 3 равен этому биту одиночного числа**.

Так можно собрать ответ бит за битом: 32 счётчика по модулю 3 — это `O(1)` памяти. Остаётся хранить их компактно. Счётчику по модулю 3 нужно три состояния (`0, 1, 2`), то есть два бита. Возьмём две 32-битные маски:

- `ones` — биты, чей счётчик сейчас равен 1;
- `twos` — биты, чей счётчик сейчас равен 2.

Тогда все 32 счётчика обновляются **одновременно** парой битовых операций на каждое число. В конце в `ones` стоят ровно те биты, что встретились `3k + 1` раз, — биты ответа.

## Техники

### Побитовый подсчёт

**Что это.** Если операция над числами «разваливается» на независимые биты, задачу можно решать для каждого бита отдельно. Классический пример — «элемент, повторённый не `k` раз»: сумма бита по всем числам по модулю `k` даёт бит ответа.

```ts naive
let result = 0;
for (let bit = 0; bit < 32; bit++) {
  let sum = 0;
  for (const x of nums) sum += (x >> bit) & 1;
  if (sum % 3 === 1) result |= 1 << bit;
}
```

Это тоже `O(32 · n)` и `O(1)` памяти — понятная альтернатива. Решение делает то же самое, но за один проход и параллельно по всем битам.

### Конечный автомат на битовых масках

Для каждого бита пара `(twos, ones)` — это состояние счётчика по модулю 3:

```
состояние   twos ones   смысл
  0          0    0     бит встретился 0 раз (mod 3)
  1          0    1     1 раз
  2          1    0     2 раза
вход 1:  00 → 01 → 10 → 00
вход 0:  состояние не меняется
```

Переходы записываются формулами, которые применяются ко всем 32 битам сразу: XOR «переключает» бит при входе 1, а `& ~маска` запрещает биту быть одновременно в обеих масках. Подробнее о битовых операциях — во вкладке «Теория».

### 32-битная арифметика JS

Операторы `^`, `&`, `~` в JavaScript приводят операнды к **32-битным знаковым целым**. Знаковый бит (31-й) обрабатывается так же, как остальные, поэтому `ones` в конце — это сразу правильное знаковое число, включая отрицательные.

## Разбор кода

```ts
function singleNumber(nums: number[]): number {
  // Для каждого бита считаем, сколько раз он встретился, по модулю 3.
  // Счётчик 0..2 кодируется двумя масками:
  //   ones — биты, встреченные 1 раз (mod 3)
  //   twos — биты, встреченные 2 раза (mod 3)
  let ones = 0;
  let twos = 0;
```

Изначально все счётчики в состоянии `0`: обе маски нулевые. Это и есть вся дополнительная память — два числа.

```ts
  for (const num of nums) {
    // Бит попадает в ones, если его ещё нет в twos (переход 0 -> 1 или 1 -> 0 через XOR)
    ones = (ones ^ num) & ~twos;
```

Разберём для одного бита, где в `num` стоит 1:

- состояние `0` (`twos = 0`, `ones = 0`): `ones ^ 1 = 1`, `& ~0` — остаётся `1`. Переход в состояние `1`;
- состояние `1` (`ones = 1`): `1 ^ 1 = 0` — бит уходит из `ones`;
- состояние `2` (`twos = 1`): `& ~1` обнуляет — в `ones` бит не появляется.

Если в `num` бит равен 0, `ones ^ 0 = ones`, а `& ~twos` ничего не меняет, потому что бит не бывает одновременно в обеих масках.

```ts
    // Бит попадает в twos, если он только что ушёл из ones (переход 1 -> 2),
    // а третье появление обнуляет его в обеих масках (2 -> 0)
    twos = (twos ^ num) & ~ones;
  }
```

Здесь используется **уже обновлённое** `ones`. Снова для бита, где в `num` стоит 1:

- было состояние `0`: новый `ones = 1`, поэтому `& ~ones` гасит бит — `twos = 0`. Итог `01`;
- было состояние `1`: новый `ones = 0`, `twos ^ 1 = 1` — бит переходит в `twos`. Итог `10`;
- было состояние `2`: новый `ones = 0`, `twos ^ 1 = 1 ^ 1 = 0` — бит сбрасывается. Итог `00`.

Цикл `0 → 1 → 2 → 0` замкнулся: третье появление обнуляет счётчик. Порядок двух строк важен — формула для `twos` рассчитана на новое `ones`.

```ts
  // Биты, встретившиеся 3k + 1 раз, — это биты единственного числа.
  // Битовые операции в JS работают с 32-битными знаковыми числами,
  // поэтому отрицательные значения восстанавливаются автоматически
  return ones;
}
```

У «тройных» чисел каждый бит встречается кратно трём — их вклад обнуляется. У одиночного числа каждый единичный бит встречается `3k + 1` раз и оказывается в состоянии `1`, то есть в `ones`. А `twos` в конце равна нулю: состояния `2` (`3k + 2`) не бывает.

## Трассировка

`nums = [2, 2, 3, 2]`. В двоичном виде `2 = 10`, `3 = 11`. Показываем два младших бита масок.

```
старт:       ones = 00, twos = 00
num = 2 (10): ones = (00 ^ 10) & ~00 = 10
              twos = (00 ^ 10) & ~10 = 00
num = 2 (10): ones = (10 ^ 10) & ~00 = 00
              twos = (00 ^ 10) & ~00 = 10
num = 3 (11): ones = (00 ^ 11) & ~10 = 01
              twos = (10 ^ 11) & ~01 = 01 & 10 = 00
num = 2 (10): ones = (01 ^ 10) & ~00 = 11
              twos = (00 ^ 10) & ~11 = 00
```

Ответ `ones = 11₂ = 3`. По битам: бит 1 встретился 4 раза (`4 mod 3 = 1`) — в ответе; бит 0 встретился 1 раз — тоже в ответе. На третьем шаге бит 1 получил третье появление и был сброшен в обеих масках.

Отрицательный пример: `nums = [-2, -2, 1, -2]`. `-2` в 32 битах — `111…110`. Каждый бит `-2` встречается трижды и обнуляется, а бит 0 (от единицы) — один раз. Ответ `ones = 1`. Если бы одиночным было `-2`, в `ones` оказались бы все биты `111…110`, включая знаковый, и JS прочитал бы это как `-2`.

## Почему это работает

**Инвариант:** после обработки любого префикса для каждого бита `b` пара (`twos[b]`, `ones[b]`) кодирует число `c_b mod 3`, где `c_b` — сколько чисел префикса имеют единицу в бите `b`: `00` — 0, `01` — 1, `10` — 2.

Проверка переходов выше (для входного бита 1 — сдвиг `0 → 1 → 2 → 0`, для входного бита 0 — без изменений) — это ровно шаг индукции. Биты независимы, потому что `^`, `&`, `~` работают поразрядно.

После всего массива `c_b = 3·(количество «тройных» чисел с битом b) + (бит b одиночного)`, значит `c_b mod 3` — это бит одиночного числа, и он хранится в `ones`.

## Пограничные случаи

- **Массив из одного элемента**: `ones = num`, ответ — сам элемент.
- **Одиночное число `0`**: все биты кратны трём, `ones = 0` — верно.
- **Отрицательные числа и `-2³¹`**: 32-битные операции обрабатывают знаковый бит как обычный; результат — корректное знаковое int32.
- **Одиночное число в любом месте массива**: порядок не важен, счётчики коммутативны.
- **`2³¹ - 1`**: помещается в int32 без искажений.

## Сложность

- **Время `O(n)`**: один проход, на каждый элемент — четыре битовые операции.
- **Память `O(1)`**: две переменные `ones` и `twos`, независимо от размера массива.

## Типичные ошибки

1. **XOR всего массива** по аналогии с Single Number → тройки не исчезают, `a ^ a ^ a = a`.
2. **Поменять порядок строк** (сначала `twos`, потом `ones`) с теми же формулами → маски меняются ролями: ответ окажется в `twos`, а `return ones` вернёт `0`.
3. **Использовать старое `ones` в формуле для `twos`** (сохранить в временную переменную «до») → переход `0 → 1` ошибочно поставит бит и в `twos`.
4. **В побитовом варианте собирать ответ через сложение `2 ** bit`** → для 31-го бита получится `+2³¹` вместо отрицательного числа; нужно `|= 1 << bit`.
5. **Беззнаковый сдвиг `>>>` при восстановлении результата** → отрицательный ответ превратится в большое положительное.

## Как узнать такую задачу

- Каждый элемент повторяется **`k` раз**, кроме одного, и требуется `O(1)` памяти — сигнал к подсчёту битов по модулю `k`.
- Слова «linear runtime, constant extra space» рядом с повторениями — почти всегда битовые трюки.
- Если `k = 2`, хватает XOR; при `k = 3` и больше — счётчики по модулю (автомат на масках или побитовые суммы). Похожие задачи: Single Number, Single Number III (два одиночных: XOR + разделение по младшему биту), Missing Number.
