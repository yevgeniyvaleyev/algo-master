## Задача простыми словами

Дан массив `nums`, в котором каждое число встречается **ровно три раза**, кроме одного — оно встречается **один раз**. Нужно найти это одиночное число. Ограничения жёсткие: время `O(n)` и **константная** дополнительная память.

Пример: `nums = [2, 2, 3, 2]` → `3`. Для `[0, 1, 0, 1, 0, 1, 99]` → `99`. Числа могут быть отрицательными, вплоть до `-2³¹`.

## Наивный подход

Посчитать частоты в `Map` и вернуть число с частотой 1:

```ts naive
const freq = new Map<number, number>();
for (const x of nums) freq.set(x, (freq.get(x) ?? 0) + 1);
for (const [x, c] of freq) if (c === 1) return x;
```

Время `O(n)`, но память `O(n)` — условие нарушено. Сортировка с поиском «одиночки» по тройкам даёт `O(1)` памяти, но `O(n log n)` времени.

Приём из Single Number (там все числа по два раза) — XOR всего массива — здесь не работает: `a ^ a ^ a = a`, тройки не уничтожаются. Лишнее в наивных решениях одно и то же: мы помним **каждое число целиком**, хотя на деле достаточно гораздо меньшей информации — 32 маленьких счётчиков.

## Ключевое наблюдение

Посмотрим на **один бит**, например младший. Посчитаем, у скольких чисел массива он равен 1. Каждое «тройное» число добавляет к счётчику `0` или `3`, а одиночное — `0` или `1`. Значит, **счётчик по модулю 3 равен этому биту одиночного числа**.

Битов в числе всего 32. Повторим подсчёт для каждого бита — и соберём ответ бит за битом. Это 32 прохода по массиву, то есть `O(32 · n) = O(n)` времени, и пара переменных памяти.

## Техники

### Побитовый подсчёт

**Что это.** Если свойство «разваливается» на независимые биты, задачу можно решать для каждого бита отдельно, а потом склеить ответ. Классический пример — «элемент, повторённый не `k` раз»: сумма бита по всем числам по модулю `k` даёт бит ответа.

**Шаблон.**

1. Внешний цикл по битам `b = 0..31`.
2. Внутренний цикл по числам: `count += (num >> b) & 1` — достаём бит `b`.
3. По `count` решаем, стоит ли бит `b` в ответе, и ставим его: `res |= 1 << b`.

**Как применяется здесь.** Бит ставится, когда `count % 3 !== 0`. Подробнее о битовых операциях — во вкладке «Теория».

### Извлечение и установка бита

- `(num >> b) & 1` — сдвигаем нужный бит в младшую позицию и отрезаем всё остальное. Получается `0` или `1`.
- `res |= 1 << b` — `1 << b` это число, у которого единица только в бите `b`; OR ставит этот бит в `res`, не трогая остальные.

### 32-битная арифметика JS

Операторы `>>`, `&`, `|`, `<<` в JavaScript приводят операнды к **32-битным знаковым целым** (дополнительный код). Поэтому знаковый 31-й бит обрабатывается как остальные: `-4 >> 31` даёт `-1`, а `-1 & 1 = 1`. И наоборот, `1 << 31 = -2147483648`, так что `res` сразу получается корректным отрицательным числом.

## Разбор кода

```ts
function singleNumber(nums: number[]): number {
  let res = 0;
```

`res` — ответ, который мы будем собирать по одному биту. Изначально все биты нулевые.

```ts
  // Рассматриваем каждый из 32 битов по отдельности
  for (let b = 0; b < 32; b++) {
    // Сколько чисел имеют единицу в бите b
    let count = 0;
    for (const num of nums) {
      count += (num >> b) & 1;
    }
```

Для бита `b` проходим весь массив и считаем, у скольких чисел он равен 1. Выражение `(num >> b) & 1` всегда `0` или `1`, даже для отрицательных `num`: знаковый сдвиг заполняет старшие разряды единицами, но `& 1` оставляет только младший.

```ts
    // Тройки дают вклад, кратный 3; остаток — это бит единственного числа
    if (count % 3 !== 0) res |= 1 << b;
  }
```

`count = 3·(сколько «тройных» чисел имеют этот бит) + (бит одиночного)`. Поэтому `count % 3` равен `0` или `1`, и единица означает, что бит `b` у ответа стоит. Проверка `!== 0` надёжнее, чем `=== 1`, если условие когда-нибудь поменяется на «одиночное встречается дважды».

```ts
  // res — 32-битное знаковое число: бит 31 сам делает его отрицательным
  return res;
}
```

Если у ответа стоит 31-й бит, `res |= 1 << 31` превращает `res` в отрицательное int32 — именно то, что нужно. Никаких дополнительных преобразований.

## Трассировка

`nums = [2, 2, 3, 2]`. В двоичном виде `2 = 10`, `3 = 11`.

```
b = 0: биты 0,0,1,0  → count = 1, 1 % 3 = 1 → res |= 1  → res = 01
b = 1: биты 1,1,1,1  → count = 4, 4 % 3 = 1 → res |= 2  → res = 11
b = 2..31: у всех 0  → count = 0             → без изменений
```

Ответ `res = 11₂ = 3`.

Отрицательный пример: `nums = [-2, -2, 1, -2]`. `-2` в 32 битах — `111…110`, `1` — `000…001`.

```
b = 0:     -2 даёт 0 (трижды), 1 даёт 1 → count = 1 → res = 1
b = 1..31: -2 даёт 1 (трижды), 1 даёт 0 → count = 3 → 3 % 3 = 0
```

Ответ `1`. Если бы одиночным было `-2`, то на `b = 31` счётчик дал бы остаток 1, `res |= 1 << 31` поставил бы знаковый бит, и `res` стал бы `-2`.

## Почему это работает

Зафиксируем бит `b`. Пусть `t_b` — сколько различных «тройных» чисел имеют единицу в бите `b`, а `s_b` — бит `b` одиночного числа. Каждое тройное число встречается ровно три раза, поэтому

`count = 3 · t_b + s_b`, и `count mod 3 = s_b`, так как `s_b ∈ {0, 1}`.

Значит, после обработки бита `b` в `res` стоит ровно бит `s_b`. Биты независимы (`>>`, `&`, `|` поразрядны), и мы перебрали все 32 — следовательно, `res` совпадает с одиночным числом во всех разрядах, включая знаковый.

## Пограничные случаи

- **Массив из одного элемента**: каждый `count` — это просто бит числа, ответ — сам элемент.
- **Одиночное число `0`**: все счётчики кратны трём, `res = 0` — верно.
- **Отрицательные числа и `-2³¹`**: `(num >> 31) & 1 = 1` для отрицательных, `1 << 31` ставит знаковый бит — результат корректное int32.
- **`2³¹ - 1`**: 31 младший бит единичные, знаковый ноль — помещается без искажений.
- **Одиночное число в любом месте массива**: порядок не важен, сумма коммутативна.

## Сложность

- **Время `O(32 · n) = O(n)`**: 32 прохода по массиву, на каждый элемент — сдвиг, AND и сложение.
- **Память `O(1)`**: `res`, `count` и счётчик цикла, независимо от размера массива.

**Follow-up на собеседовании:** «а за один проход?» Те же 32 счётчика по модулю 3 можно хранить в двух масках — `ones` (счётчик равен 1) и `twos` (равен 2) — и обновлять все биты сразу:

```ts naive
let ones = 0;
let twos = 0;
for (const num of nums) {
  ones = (ones ^ num) & ~twos;
  twos = (twos ^ num) & ~ones;
}
return ones;
```

Для каждого бита пара `(twos, ones)` проходит `00 → 01 → 10 → 00`, и после прохода в `ones` остаются биты одиночного числа. Асимптотика та же, константа в 32 раза меньше, но формулы трудно вывести на ходу — достаточно знать, что такой приём существует.

## Типичные ошибки

1. **XOR всего массива** по аналогии с Single Number → тройки не исчезают, `a ^ a ^ a = a`.
2. **Собирать ответ через сложение `2 ** b`** → для 31-го бита получится `+2³¹` вместо отрицательного числа; нужно `res |= 1 << b`.
3. **Беззнаковый сдвиг `>>>` при возврате** (`return res >>> 0`) → отрицательный ответ превратится в большое положительное.
4. **Перебирать только 31 бит** (`b < 31`) → теряется знаковый бит, отрицательные ответы ломаются.
5. **Объявить `count` вне цикла по битам** → счётчик не обнуляется между битами, остатки смешиваются.

## Как узнать такую задачу

- Каждый элемент повторяется **`k` раз**, кроме одного, и требуется `O(1)` памяти — сигнал к подсчёту битов по модулю `k`.
- Слова «linear runtime, constant extra space» рядом с повторениями — почти всегда битовые трюки.
- Если `k = 2`, хватает XOR; при `k = 3` и больше — побитовые суммы по модулю `k` (или автомат на масках). Похожие задачи: Single Number, Single Number III (два одиночных: XOR + разделение по младшему биту), Missing Number.
