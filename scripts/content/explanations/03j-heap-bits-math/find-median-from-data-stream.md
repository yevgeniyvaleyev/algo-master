## Задача простыми словами

Нужно спроектировать класс `MedianFinder` для **потока чисел**: метод `addNum(num)` добавляет очередное число, а `findMedian()` в любой момент возвращает медиану всех добавленных чисел. Медиана — средний элемент в отсортированном порядке, а при чётном количестве — среднее двух средних.

Пример: `addNum(1)`, `addNum(2)` → `findMedian()` = `(1 + 2) / 2 = 1.5`; затем `addNum(3)` → `findMedian()` = `2`. Вызовов — до `5 · 10⁴`, и они перемешаны произвольно.

## Наивный подход

Хранить все числа в массиве и при каждом запросе медианы сортировать: `O(n log n)` на `findMedian`. Чуть лучше — держать массив **всегда отсортированным**, вставляя число на место бинарным поиском:

```ts naive
addNum(num: number): void {
  let lo = 0, hi = this.arr.length;
  while (lo < hi) {
    const mid = (lo + hi) >> 1;
    if (this.arr[mid] < num) lo = mid + 1;
    else hi = mid;
  }
  this.arr.splice(lo, 0, num); // сдвиг хвоста — O(n)
}
```

Поиск места — `O(log n)`, но `splice` сдвигает все элементы правее — `O(n)` на вставку, `O(n²)` на весь поток. Лишняя работа в том, что мы поддерживаем **полный порядок** всех чисел, хотя медиане нужно знать только то, что происходит **на границе** между меньшей и большей половинами.

## Ключевое наблюдение

Разделим числа на две половины:

- `low` — меньшая половина; из неё нужен только **максимум**;
- `high` — большая половина; из неё нужен только **минимум**.

Если половины равны по размеру (или `low` больше на один) и каждый элемент `low` не больше каждого элемента `high`, медиана определяется только вершинами: `max(low)` при нечётном количестве или среднее `max(low)` и `min(high)` при чётном.

Структура, которая быстро даёт максимум и принимает новые элементы, — **max-куча**; минимум — **min-куча**. Внутренний порядок половин нам не важен, и кучи именно его и не поддерживают — отсюда выигрыш.

```
low (max-куча)          high (min-куча)
  [1, 2, 3, 5]  |  [7, 8, 9]
            ↑ вершина   ↑ вершина
медиана (7 чисел) = вершина low = 5
```

## Техники

### Две кучи (two heaps)

**Что это.** Приём для задач, где нужно поддерживать **границу**, делящую множество на две части: медиану, `k`-й элемент при фиксированной доле, баланс «меньших» и «больших». Одна max-куча хранит левую часть, одна min-куча — правую; граница видна по их вершинам за `O(1)`.

**Типичный шаблон добавления** — «пропустить через другую кучу», чтобы элемент гарантированно оказался на правильной стороне, а затем выровнять размеры:

```ts naive
left.push(x);
right.push(left.pop());          // наибольший из левых уходит вправо
if (right.size() > left.size())  // выравниваем размеры
  left.push(right.pop());
```

**Как применяется здесь.** `low` — max-куча, `high` — min-куча, на обеих — общий класс `Heap<T>` с разными компараторами. Подробнее о кучах — во вкладке «Теория».

### Проектирование класса с инвариантом

В задачах на дизайн удобно сначала сформулировать **инвариант** — условие, которое верно между любыми вызовами методов, — и затем писать каждый метод так, чтобы он его сохранял. Тогда «запросы» (`findMedian`) становятся тривиальными, а вся сложность уходит в «обновления» (`addNum`).

## Разбор кода

```ts
// В TypeScript нет встроенной кучи — пишем свою.
// Двоичная куча хранится в массиве: дети узла i — 2i + 1 и 2i + 2, родитель — (i - 1) >> 1.
class Heap<T> {
  private data: T[] = [];

  // less(a, b) === true, если a должен стоять ближе к вершине, чем b.
  // (a, b) => a < b — min-куча, (a, b) => a > b — max-куча
  constructor(private less: (a: T, b: T) => boolean) {}

  size(): number {
    return this.data.length;
  }

  // Вершина кучи (минимум или максимум) за O(1)
  peek(): T | undefined {
    return this.data[0];
  }
```

Обобщённая двоичная куча в массиве. Компаратор `less(a, b)` решает, кто ближе к вершине, поэтому один класс обслуживает и `low`, и `high`. Вершина — `data[0]`.

```ts
  // Добавление за O(log n): кладём в конец и «поднимаем» вверх
  push(value: T): void {
    const a = this.data;
    a.push(value);
    let i = a.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      // Родитель уже «лучше» — порядок кучи восстановлен
      if (!this.less(a[i], a[parent])) break;
      [a[i], a[parent]] = [a[parent], a[i]];
      i = parent;
    }
  }
```

Вставка: элемент встаёт в конец и поднимается, пока он «лучше» родителя. Порядок может нарушиться только на этом пути, поэтому `O(log n)`.

```ts
  // Извлечение вершины за O(log n): на её место ставим последний элемент и «топим» его вниз
  pop(): T | undefined {
    const a = this.data;
    const top = a[0];
    const last = a.pop();
    if (a.length > 0 && last !== undefined) {
      a[0] = last;
      let i = 0;
      while (true) {
        const l = 2 * i + 1;
        const r = l + 1;
        // Выбираем «лучшего» из узла и двух его детей
        let best = i;
        if (l < a.length && this.less(a[l], a[best])) best = l;
        if (r < a.length && this.less(a[r], a[best])) best = r;
        if (best === i) break;
        [a[i], a[best]] = [a[best], a[i]];
        i = best;
      }
    }
    return top;
  }
}
```

Извлечение: запоминаем вершину, на её место ставим последний элемент и опускаем, меняя с лучшим из детей. Если в куче был один элемент, `a.pop()` уже его снял, и погружение не нужно.

```ts
class MedianFinder {
  // Меньшая половина чисел — max-куча: на вершине самое большое из маленьких
  private low = new Heap<number>((a, b) => a > b);
  // Большая половина чисел — min-куча: на вершине самое маленькое из больших
  private high = new Heap<number>((a, b) => a < b);
```

Две кучи: компаратор `a > b` делает `low` max-кучей, `a < b` делает `high` min-кучей. Конструктор не нужен — поля инициализируются прямо в объявлении.

```ts
  // Инвариант: low.size() === high.size() или low.size() === high.size() + 1,
  // и каждый элемент low не больше любого элемента high
```

Два условия, которые верны после любого вызова:

1. **Баланс размеров**: `low` равна `high` или больше на один. Так при нечётном количестве медиана — вершина `low`.
2. **Порядок половин**: `max(low) ≤ min(high)`.

```ts
  addNum(num: number): void {
    // Сначала кладём в нижнюю половину,
    // а её максимум перекидываем наверх — так порядок половин сохраняется
    this.low.push(num);
    this.high.push(this.low.pop()!);
```

Куда положить `num`, заранее неизвестно — он может быть меньше вершины `low`, больше вершины `high` или между ними. Приём «пропустить через `low`» снимает вопрос: после `push` из `low` извлекается её максимум — это либо сам `num`, либо прежний максимум `low`, если `num` был меньше. В любом случае в `high` уходит число, которое не меньше всех оставшихся в `low`, а прежние элементы `high` и так были не меньше всех в `low`. Порядок половин сохранён при любом `num`. `!` убирает `undefined` из типа — после `push` куча не пуста.

```ts
    // Возвращаем баланс размеров: нижняя половина не меньше верхней
    if (this.high.size() > this.low.size()) {
      this.low.push(this.high.pop()!);
    }
  }
```

После переброса `high` выросла на один, `low` — не изменилась. Если `high` стала больше `low`, возвращаем её минимум вниз. Минимум `high` не меньше всего в `low`, поэтому порядок половин снова сохраняется. Итог — баланс `|low| = |high|` или `|low| = |high| + 1`.

```ts
  findMedian(): number {
    // Нечётное количество — медиана на вершине нижней половины
    if (this.low.size() > this.high.size()) return this.low.peek()!;
    // Чётное — среднее двух «средних» вершин
    return (this.low.peek()! + this.high.peek()!) / 2;
  }
}
```

Благодаря инварианту запрос — `O(1)`. Если `low` больше на один, общее количество нечётно, и средний элемент — максимум меньшей половины. Иначе два средних — вершины обеих куч.

## Трассировка

Добавляем `1, 2, 3, -1`. Кучи показаны как множества, вершина — первой.

1. `addNum(1)`: `low.push(1)` → `low {1}`. Переброс: `high {1}`, `low {}`. `|high| = 1 > |low| = 0` → обратно: `low {1}`, `high {}`.
2. `addNum(2)`: `low {2, 1}`. Переброс максимума `2`: `low {1}`, `high {2}`. Размеры 1 и 1 — баланс в порядке.
   `findMedian()`: размеры равны → `(1 + 2) / 2 = 1.5`.
3. `addNum(3)`: `low {3, 1}`. Переброс `3`: `low {1}`, `high {2, 3}`. `|high| = 2 > 1` → `high.pop() = 2` вниз: `low {2, 1}`, `high {3}`.
   `findMedian()`: `|low| = 2 > |high| = 1` → `2`.
4. `addNum(-1)`: `low {2, 1, -1}`. Переброс `2`: `low {1, -1}`, `high {2, 3}`. Размеры 2 и 2.
   `findMedian()` → `(1 + 2) / 2 = 1.5`. Проверка: отсортировано `[-1, 1, 2, 3]`, средние `1` и `2`. Верно.

Обратите внимание на шаг 4: `-1` — самое маленькое число, но через `high` ушёл не он, а прежний максимум `low` (`2`). Именно так приём «пропустить через `low`» сохраняет порядок половин.

## Почему это работает

Докажем, что `addNum` сохраняет оба условия инварианта.

**Порядок.** До вызова `max(low) ≤ min(high)`. После `low.push(num)` и `x = low.pop()` число `x` — максимум из `low ∪ {num}`, значит `x ≥` всех оставшихся в `low`. Кладём `x` в `high`: все элементы `high` (старые и `x`) не меньше всех элементов `low` — для старых это следует из старого инварианта и того, что `low` лишь потеряла свой максимум, а для `x` — из его выбора. При обратном переносе `y = min(high)` уходит в `low`: `y ≥ всех в low`, и `y ≤` всех оставшихся в `high`. Порядок сохранён.

**Баланс.** Было `|low| = |high|` → после переброса `|high| = |low| + 1` → обратный перенос → `|low| = |high| + 1`. Было `|low| = |high| + 1` → после переброса размеры равны, переноса нет.

**Медиана.** Пусть всего `n` чисел. При нечётном `n` в `low` ровно `(n + 1) / 2` наименьших, и её максимум — средний элемент. При чётном в каждой половине по `n / 2`, а два средних — `max(low)` и `min(high)`.

## Пограничные случаи

- **Первое число**: проходит путь `low → high → low`, в итоге `low = {num}`, `high` пуста; `findMedian` вернёт его (ветка «нечётное»).
- **Одинаковые числа**: условия с `≤` допускают равенство; дубликаты могут оказаться в обеих половинах.
- **Монотонный поток** (`1, 2, 3, …` или наоборот): кучи остаются сбалансированными благодаря выравниванию размеров.
- **Отрицательные числа**: сравнения работают для любых знаков.
- **Дробная медиана**: `/ 2` в JS — деление с дробью, `1.5` получается без приведения типов.

## Сложность

- **`addNum` — `O(log n)`**: не больше трёх операций с кучами (`push`, `pop`/`push`, ещё `pop`/`push`), каждая по высоте кучи.
- **`findMedian` — `O(1)`**: два сравнения размеров и `peek`.
- **Память `O(n)`**: каждое добавленное число лежит ровно в одной из куч.

## Типичные ошибки

1. **Класть `num` сразу в одну из куч по размеру**, без сравнения с вершинами → большое число попадает в `low`, и порядок половин нарушается.
2. **Перепутать типы куч** (min-куча для меньшей половины) → вершины показывают не середину, а края.
3. **Балансировать без порядка**: переносить элементы ради размеров, но не через вершины → нарушается `max(low) ≤ min(high)`.
4. **Целочисленное деление** в других языках (`(a + b) / 2` у `int`) → потеря `.5`; в JS это не проблема, но при переносе на Java/C++ важно.
5. **Позволить `high` быть больше `low`** и при этом брать медиану из `low` при нечётном `n` → ответ из неправильной половины.

## Как узнать такую задачу

- Поток данных и запросы **медианы** или **процентиля** между добавлениями.
- Нужна **граница** между «меньшими» и «большими» элементами, а полный порядок не требуется.
- Сигнал к «двум кучам»: «поддерживать середину», «сбалансировать две группы». Похожие задачи: Sliding Window Median (две кучи + ленивое удаление), IPO (две структуры: по порогу и по ценности). Если значения лежат в малом диапазоне (follow-up про `[0, 100]`), вместо куч хватает массива счётчиков.
