## Задача простыми словами

Дан массив целых чисел `nums` и число `k`. Нужно вернуть **`k`-й по величине** элемент — тот, что стоял бы на позиции `k - 1`, если отсортировать массив по убыванию. Повторы считаются: это `k`-й элемент в отсортированном порядке, а не `k`-е **различное** значение.

Пример: `nums = [3, 2, 1, 5, 6, 4]`, `k = 2`. По убыванию: `6, 5, 4, 3, 2, 1` — второй элемент `5`. А для `[3, 2, 3, 1, 2, 4, 5, 5, 6]`, `k = 4` порядок `6, 5, 5, 4, …` даёт `4`: обе пятёрки занимают свои места.

## Наивный подход

Отсортировать по убыванию и взять элемент с индексом `k - 1`:

```ts naive
return nums.sort((a, b) => b - a)[k - 1];
```

Это `O(n log n)` и одна строка — на собеседовании вполне приемлемый старт. Но условие прямо спрашивает «можно ли без сортировки?». Лишняя работа сортировки в том, что она **упорядочивает все `n` элементов**, включая сотни тысяч маленьких чисел, которые к ответу не имеют никакого отношения. Нам важен только «топ-`k`», причём даже внутри топа порядок не нужен — нужен лишь его **самый слабый** участник.

## Ключевое наблюдение

`k`-й по величине элемент — это **минимум среди `k` наибольших**. Значит, достаточно, проходя по массиву, поддерживать множество из `k` самых больших чисел, встреченных к этому моменту, и уметь быстро:

1. добавить новое число;
2. выкинуть самое маленькое, если чисел стало `k + 1`.

Обе операции — ровно то, что умеет **min-куча**: вставка и извлечение минимума за `O(log k)`, просмотр минимума за `O(1)`. В конце вершина кучи и есть ответ.

## Техники

### Двоичная куча (приоритетная очередь)

**Что это.** Куча — почти полное двоичное дерево, где каждый узел «не хуже» своих детей (в min-куче — не больше). Отсюда вершина — минимум всей кучи. Полной сортировки нет, только частичный порядок «родитель ≤ дети», и поэтому операции дешёвые:

- `peek` — посмотреть вершину, `O(1)`;
- `push` — положить в конец и «всплыть» вверх, `O(log n)`;
- `pop` — снять вершину, поставить на её место последний элемент и «утопить» его вниз, `O(log n)`.

Дерево хранится прямо в массиве без указателей: у узла `i` дети `2i + 1` и `2i + 2`, родитель `(i - 1) >> 1`.

```
индексы:        0
              /   \
             1     2
            / \   /
           3   4 5
массив: [a0, a1, a2, a3, a4, a5]
```

В TypeScript/JavaScript встроенной кучи нет, поэтому решение пишет свой небольшой класс `Heap<T>` с компаратором `less`. Подробнее о куче — во вкладке «Теория».

### Топ-k через кучу размера k

**Типичный шаблон.** Чтобы найти `k` наибольших, держат **min**-кучу размера `k`; чтобы найти `k` наименьших — **max**-кучу размера `k`. Кажется парадоксальным, но логика простая: куча должна быстро отдавать того, кого **выкидываем**, а выкидываем мы самого слабого кандидата.

```ts naive
for (const x of stream) {
  heap.push(x);
  if (heap.size() > k) heap.pop(); // выкинуть худшего
}
// heap.peek() — граница топа
```

**Как применяется здесь.** Куча с компаратором `(a, b) => a < b` (min-куча); после обработки всех чисел в ней ровно `k` наибольших, а на вершине — `k`-е по величине.

## Разбор кода

```ts
// В TypeScript нет встроенной кучи — пишем свою.
// Двоичная куча хранится в массиве: дети узла i — 2i + 1 и 2i + 2, родитель — (i - 1) >> 1.
class Heap<T> {
  private data: T[] = [];

  // less(a, b) === true, если a должен стоять ближе к вершине, чем b.
  // (a, b) => a < b — min-куча, (a, b) => a > b — max-куча
  constructor(private less: (a: T, b: T) => boolean) {}
```

Класс обобщённый: тип элементов `T` и правило порядка передаются снаружи. `less(a, b)` отвечает на вопрос «должен ли `a` стоять выше `b`». Одна и та же реализация даёт и min-кучу, и max-кучу, и кучу кортежей — меняется только компаратор. `private less` в параметрах конструктора — сокращение TypeScript: параметр сразу становится полем класса.

```ts
  size(): number {
    return this.data.length;
  }

  // Вершина кучи (минимум или максимум) за O(1)
  peek(): T | undefined {
    return this.data[0];
  }
```

Размер — длина массива. Вершина дерева всегда лежит в `data[0]`; для пустой кучи вернётся `undefined`.

```ts
  // Добавление за O(log n): кладём в конец и «поднимаем» вверх
  push(value: T): void {
    const a = this.data;
    a.push(value);
    let i = a.length - 1;
    while (i > 0) {
      const parent = (i - 1) >> 1;
      // Родитель уже «лучше» — порядок кучи восстановлен
      if (!this.less(a[i], a[parent])) break;
      [a[i], a[parent]] = [a[parent], a[i]];
      i = parent;
    }
  }
```

**Всплытие (sift up).** Новый элемент кладём в конец массива — дерево остаётся почти полным, но порядок «родитель лучше ребёнка» может нарушиться только на пути от нового листа к корню. Поэтому сравниваем элемент с родителем и, если он «лучше» (`less(a[i], a[parent])`), меняем их местами и поднимаемся дальше. Как только родитель не хуже — остальное дерево уже в порядке, выходим. Путь до корня — высота дерева, `O(log n)`.

```ts
  // Извлечение вершины за O(log n): на её место ставим последний элемент и «топим» его вниз
  pop(): T | undefined {
    const a = this.data;
    const top = a[0];
    const last = a.pop();
    if (a.length > 0 && last !== undefined) {
      a[0] = last;
```

Запоминаем вершину — её и вернём. Убрать корень напрямую нельзя (в дереве образуется дыра), поэтому снимаем **последний** элемент массива и ставим его на место корня. Проверка `a.length > 0` нужна для кучи из одного элемента: тогда `a.pop()` уже снял единственный элемент, и ставить его обратно не надо.

```ts
      let i = 0;
      while (true) {
        const l = 2 * i + 1;
        const r = l + 1;
        // Выбираем «лучшего» из узла и двух его детей
        let best = i;
        if (l < a.length && this.less(a[l], a[best])) best = l;
        if (r < a.length && this.less(a[r], a[best])) best = r;
        if (best === i) break;
        [a[i], a[best]] = [a[best], a[i]];
        i = best;
      }
    }
    return top;
  }
}
```

**Погружение (sift down).** Новый корень, скорее всего, «хуже» своих детей. Среди узла и двух детей выбираем лучшего (`best`). Если лучший — сам узел, порядок восстановлен. Иначе меняем узел с **лучшим** ребёнком (именно с лучшим: тогда новый родитель не хуже второго ребёнка) и спускаемся. Проверки `l < a.length`, `r < a.length` защищают от выхода за конец массива у узлов с одним ребёнком или без детей.

```ts
function findKthLargest(nums: number[], k: number): number {
  // Min-куча, в которой держим k наибольших из просмотренных чисел
  const heap = new Heap<number>((a, b) => a < b);
```

Компаратор `a < b` — меньшее число ближе к вершине, то есть min-куча.

```ts
  for (const num of nums) {
    heap.push(num);
    // Лишний элемент — самый маленький из k + 1, он точно не k-й наибольший
    if (heap.size() > k) heap.pop();
  }
```

Каждое число сначала кладём в кучу, а если там стало `k + 1` элементов — извлекаем минимум. Извлекаемое число меньше (или равно) `k` других, поэтому ни при каком продолжении оно не может оказаться `k`-м наибольшим. Порядок «сначала `push`, потом `pop`» важен: новое число тоже участвует в отборе, и если оно самое маленькое, оно же и вылетит.

```ts
  // На вершине — минимальный из k наибольших, то есть k-й наибольший
  return heap.peek()!;
}
```

После прохода в куче ровно `k` наибольших чисел массива. Наименьшее из них — `k`-е по величине. `!` говорит компилятору, что `undefined` здесь невозможен: `k >= 1`, так что куча не пуста.

## Трассировка

`nums = [3, 2, 1, 5, 6, 4]`, `k = 2`. Показываем массив `data` кучи после каждого шага.

1. `push 3` → `[3]`. Размер 1 ≤ 2.
2. `push 2` → `[3, 2]`; `2 < 3`, всплывает → `[2, 3]`. Размер 2.
3. `push 1` → `[2, 3, 1]`; `1 < 2`, всплывает → `[1, 3, 2]`. Размер 3 > 2 → `pop`: вершина `1`, последний `2` встаёт в корень → `[2, 3]`, ребёнок `3` не меньше — стоп. Куча `[2, 3]`.
4. `push 5` → `[2, 3, 5]`; `5 < 2` нет. `pop`: уходит `2`, `5` в корень → `[5, 3]`; `3 < 5`, меняем → `[3, 5]`.
5. `push 6` → `[3, 5, 6]`. `pop`: уходит `3`, `6` в корень → `[6, 5]` → `[5, 6]`.
6. `push 4` → `[5, 6, 4]`; `4 < 5`, всплывает → `[4, 6, 5]`. `pop`: уходит `4`, `5` в корень → `[5, 6]`; `6 < 5` нет — стоп.

`peek()` → `5`. В куче остались `5` и `6` — два наибольших числа, ответ верный.

## Почему это работает

**Инвариант:** после обработки первых `t` чисел куча содержит `min(t, k)` наибольших из них (с учётом повторов).

- Пока `t ≤ k`, мы ничего не выбрасываем — куча содержит все числа, а это и есть их топ.
- Пусть инвариант верен для `t`, и куча — это `k` наибольших из первых `t`. Добавляем `x`: топ-`k` первых `t + 1` чисел — это `k` наибольших из `k + 1` кандидатов (старый топ плюс `x`); любое число вне старого топа не больше каждого из `k` чисел топа и не может попасть в новый. Убрав минимум из `k + 1` кандидатов, получаем ровно новый топ.

В конце куча — `k` наибольших чисел массива, а её минимум по определению `k`-й по величине. Повторы не мешают: равные числа просто лежат в куче как отдельные элементы.

## Пограничные случаи

- **`k = 1`**: куча из одного элемента — текущий максимум; `pop` из кучи размера 2 оставляет большее.
- **`k = n`**: ничего не выбрасывается, ответ — минимум массива.
- **Повторы** (`[3, 2, 3, 1, 2, 4, 5, 5, 6]`, `k = 4`): две пятёрки занимают два места в куче, ответ `4`.
- **Отрицательные числа**: сравнение `a < b` работает для любых знаков.
- **Один элемент**: `k = 1`, ответ — сам элемент.

## Сложность

- **Время `O(n log k)`**: `n` вставок и до `n` извлечений, каждая операция идёт по высоте кучи из не более чем `k + 1` элементов, то есть `O(log k)`. При малом `k` это заметно лучше сортировки.
- **Память `O(k)`**: в куче одновременно не больше `k + 1` чисел.

Для сравнения: quickselect даёт `O(n)` в среднем (но `O(n²)` в худшем), а подсчёт частот по диапазону значений `[-10⁴, 10⁴]` — `O(n + 2·10⁴)`.

## Типичные ошибки

1. **Max-куча вместо min-кучи** с той же схемой «push, затем pop при переполнении» → выкидываются самые большие числа, и в конце остаются `k` наименьших.
2. **Max-куча на весь массив и `k` извлечений** — работает, но с этим классом это `O(n log n)` времени и `O(n)` памяти; не ошибка, но не то, что ждут при «без сортировки».
3. **Проверять `size() >= k`** вместо `> k` → в куче остаётся `k - 1` элемент, ответ сдвигается на одну позицию.
4. **Убирать дубликаты** (`new Set(nums)`) → задача про `k`-е в отсортированном порядке, а не `k`-е различное.
5. **В `pop` менять узел с любым ребёнком**, а не с лучшим → свойство кучи нарушается, и вершина перестаёт быть минимумом.

## Как узнать такую задачу

- Нужно **`k`-е по величине**, «топ-`k`», «`k` ближайших», «`k` самых частых» — а полный порядок не требуется.
- Ограничение «без сортировки» или поток данных, который нельзя сохранить целиком: куча размера `k` работает онлайн, по одному элементу.
- Правило выбора кучи: для `k` **наибольших** — min-куча (выкидываем минимум), для `k` **наименьших** — max-куча. Похожие задачи: Top K Frequent Elements, K Closest Points to Origin, Kth Largest Element in a Stream.
