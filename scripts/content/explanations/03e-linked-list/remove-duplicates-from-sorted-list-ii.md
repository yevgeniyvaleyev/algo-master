## Задача простыми словами

Дан **отсортированный** связный список. Нужно удалить **все** узлы, значения которых встречаются больше одного раза, — не оставляя ни одной копии, — и вернуть то, что осталось (тоже отсортированным).

Пример: `head = [1, 2, 3, 3, 4, 4, 5]`. Значения `3` и `4` повторяются — они исчезают полностью. Ответ `[1, 2, 5]`. Если `head = [1, 1, 1, 2, 3]`, ответ `[2, 3]` — удаляется даже голова.

## Наивный подход

Можно посчитать частоты значений в `Map`, а потом вторым проходом собрать список только из узлов с частотой `1`:

```ts naive
const cnt = new Map<number, number>();
for (let c = head; c !== null; c = c.next) cnt.set(c.val, (cnt.get(c.val) ?? 0) + 1);
const dummy = new ListNode(0);
let tail = dummy;
for (let c = head; c !== null; c = c.next) {
  if (cnt.get(c.val) === 1) { tail.next = c; tail = c; }
}
tail.next = null;
return dummy.next;
```

Работает за `O(n)`, но тратит `O(n)` памяти на таблицу и **не использует сортировку**. А в отсортированном списке одинаковые значения стоят **подряд** — чтобы понять, что значение повторяется, достаточно сравнить узел с соседом.

## Ключевое наблюдение

Из-за сортировки дубликаты образуют **непрерывные блоки**. Узел уникален тогда и только тогда, когда его значение отличается от значения следующего узла и он не является продолжением блока. Значит, идём по списку; если `curr.val === curr.next.val` — начался блок, пропускаем его целиком и подвешиваем то, что после блока, к последнему надёжному узлу `prev`. Иначе узел уникален, `prev` переезжает на него.

Отличие от более простой версии задачи (Remove Duplicates I, где оставляют одну копию): там можно стоять на первом узле блока, здесь первый узел блока тоже удаляется — поэтому нужен указатель на узел **перед** блоком.

## Техники

### Фиктивная голова (dummy)

**Что это.** Узел-заглушка перед головой, `new ListNode(0, head)`. У каждого реального узла появляется предшественник.

**Как применяется здесь.** Голова сама может быть дубликатом (`[1, 1, 2]`), и тогда новой головой станет узел, который заранее неизвестен. С заглушкой «удаление блока в начале» — это просто `dummy.next = ...`, а ответ всегда `dummy.next`. Подробнее о заглушках — во вкладке «Теория».

### Указатель «последний надёжный узел» (prev) + сканер (curr)

**Что это.** Два указателя: `prev` — конец уже построенного ответа, `curr` — текущий проверяемый узел. Это вариант двух указателей «читающий / пишущий», только на списке: `curr` читает, а `prev.next = ...` «пишет».

**Типичный шаблон фильтрации списка:**

```ts naive
let prev = dummy, curr = head;
while (curr !== null) {
  if (удалить(curr)) prev.next = curr.next;   // prev стоит
  else prev = curr;                            // prev шагает
  curr = curr.next;
}
```

**Как применяется здесь.** Удаляется не один узел, а целый блок, поэтому вместо `curr.next` подвешиваем первый узел **после** блока.

### Пропуск блока одинаковых значений

Внутренний цикл `while (curr !== null && curr.val === dup)` — стандартный способ проскочить «серию» в отсортированных данных. Каждый узел посещается им ровно один раз, так что вложенный цикл не делает решение квадратичным.

## Разбор кода

```ts
function deleteDuplicates(head: ListNode | null): ListNode | null {
  // Заглушка: голова тоже может оказаться дубликатом и быть удалена
  const dummy = new ListNode(0, head);
  // prev — последний узел, который точно остаётся в ответе
  let prev: ListNode = dummy;
  let curr = head;
```

Заглушка смотрит на голову. `prev` стартует с заглушки — в ответе пока ничего нет. `curr` — первый проверяемый узел.

```ts
  while (curr !== null) {
    if (curr.next !== null && curr.next.val === curr.val) {
```

Проверяем, не начинается ли с `curr` блок дубликатов: есть следующий узел, и его значение такое же. Проверка `curr.next !== null` защищает от обращения к `null.val` на последнем узле. Важно: `curr` в этой точке всегда **первый** узел своего значения — либо это начало списка, либо предыдущий узел имел другое значение (иначе мы бы его пропустили вместе с блоком).

```ts
      // Начался блок одинаковых значений — пропускаем его целиком
      const dup = curr.val;
      while (curr !== null && curr.val === dup) curr = curr.next;
```

Запоминаем значение блока и двигаем `curr`, пока значения равны `dup`. После цикла `curr` — первый узел с другим значением или `null`, если блок шёл до конца.

```ts
      // Отрезаем весь блок; prev не двигаем — следующий узел тоже может быть дубликатом
      prev.next = curr;
```

Подвешиваем узел после блока к `prev` — весь блок выпадает из цепочки. `prev` **не двигаем**: мы ещё не знаем, уникален ли новый `curr`. Например, в `[1, 1, 2, 2, 3]` после блока единиц сразу начинается блок двоек, и `prev` (заглушка) должен остаться на месте, чтобы вырезать и его.

```ts
    } else {
      // Значение уникально — оставляем узел
      prev = curr;
      curr = curr.next;
    }
  }
```

Если следующий узел другой (или его нет), `curr` уникален — он точно остаётся. `prev` переезжает на него, `curr` идёт дальше. Связь `prev.next` уже указывает на `curr`, переписывать её не нужно.

```ts
  return dummy.next;
}
```

Ответ — всё после заглушки. Если удалены все узлы, `dummy.next === null`.

## Трассировка

`head = [1, 2, 3, 3, 4, 4, 5]`:

1. `prev = dummy`, `curr = 1`. `1.next = 2`, значения разные → `prev = 1`, `curr = 2`.
2. `curr = 2`, `2.next = 3` — разные → `prev = 2`, `curr = 3`.
3. `curr = 3`, `3.next = 3` — блок. `dup = 3`, пропуск: `curr` → второе `3` → `4`. `2.next = 4`. `prev = 2`.
4. `curr = 4`, `4.next = 4` — блок. `dup = 4`, пропуск до `5`. `2.next = 5`. `prev = 2`.
5. `curr = 5`, `5.next = null` → уникален. `prev = 5`, `curr = null`. Выход.

```
dummy -> 1 -> 2 -> 5
```

Ответ `[1, 2, 5]`. Обратите внимание на шаг 4: `prev` остался `2` после шага 3, и это позволило вырезать второй блок подряд.

Удаление головы, `head = [1, 1, 1, 2, 3]`:

1. `curr = 1`, `1.next.val = 1` — блок, пропуск трёх единиц, `curr = 2`. `dummy.next = 2`.
2. `curr = 2` уникален → `prev = 2`. `curr = 3` уникален → `prev = 3`. Выход.

Ответ `[2, 3]`.

## Почему это работает

Инвариант: цепочка от `dummy` до `prev` — это ровно уникальные узлы среди уже просмотренных, в исходном порядке, и `prev.next === curr`; `curr` — первый узел своего значения среди непросмотренных.

- Если у `curr` есть сосед с тем же значением, значение повторяется — весь блок удаляется, `prev.next` переставляется на первый узел следующего значения. Инвариант сохранён.
- Иначе, поскольку список отсортирован и `curr` — первый узел своего значения, других узлов с этим значением нет вообще. Узел уникален и законно добавляется к ответу.

Порядок сохраняется, потому что мы только вырезаем узлы, но не переставляем их.

## Пограничные случаи

- **Пустой список**: цикл не выполняется, ответ `null`.
- **Дубликаты в начале** (`[1, 1, 2]`): удаляется голова, работает через заглушку.
- **Дубликаты в конце** (`[1, 2, 2]`): пропуск блока доводит `curr` до `null`, `prev.next = null` обрезает хвост.
- **Всё — дубликаты** (`[1, 1]`): ответ пустой.
- **Блоки подряд** (`[1, 1, 2, 2]`): `prev` не двигается между блоками.
- **Нет дубликатов**: список возвращается без изменений.

## Сложность

- **Время `O(n)`**: каждый узел посещается `curr` ровно один раз — либо в ветке «уникален», либо внутренним циклом пропуска. Вложенный цикл не даёт `O(n²)`, потому что `curr` двигается только вперёд.
- **Память `O(1)`**: два указателя, переменная `dup` и заглушка.

## Типичные ошибки

1. **Оставлять одну копию** (как в Remove Duplicates I) → в ответе останутся `3` и `4`.
2. **Сдвигать `prev` после удаления блока** → следующий блок подряд не удалится целиком.
3. **Без заглушки** → удаление дубликатов в голове требует отдельного цикла.
4. **Сравнивать с `prev.val`** вместо соседа `curr.next` → первый узел блока не распознаётся как дубликат.
5. **Забыть `curr.next !== null`** → ошибка на последнем узле.

## Как узнать такую задачу

- Список (или массив) **отсортирован**, и нужно что-то сделать с повторяющимися значениями — дубликаты идут подряд, хватает сравнения с соседом.
- Нужно удалить **все** вхождения повторяющихся значений — нужен указатель на узел **перед** блоком.
- Удаление может затронуть голову — сигнал к заглушке. Родственные задачи: Remove Duplicates from Sorted List (оставить одну копию), Remove Linked List Elements, Remove Duplicates from Sorted Array.
