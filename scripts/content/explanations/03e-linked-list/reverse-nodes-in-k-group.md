## Задача простыми словами

Дан связный список и число `k`. Нужно разбить список на группы по `k` узлов подряд и **развернуть каждую группу**. Если в конце осталось меньше `k` узлов, они остаются в исходном порядке. Значения менять нельзя — только связи.

Пример: `head = [1, 2, 3, 4, 5]`, `k = 2`. Группы `[1, 2]`, `[3, 4]` и неполный остаток `[5]`. Ответ `[2, 1, 4, 3, 5]`. При `k = 3` получится `[3, 2, 1, 4, 5]`.

## Наивный подход

Можно сложить узлы в массив, развернуть в нём каждый отрезок длины `k` и заново перевесить `next` по массиву:

```ts naive
const nodes: ListNode[] = [];
for (let c = head; c !== null; c = c.next) nodes.push(c);
for (let s = 0; s + k <= nodes.length; s += k) {
  // развернуть nodes[s .. s + k - 1]
}
for (let i = 0; i < nodes.length; i++) nodes[i].next = nodes[i + 1] ?? null;
return nodes[0];
```

Время `O(n)`, память `O(n)`. Работает, но массив нужен лишь для того, чтобы знать, где кончается группа и что идёт после неё, — а это можно узнать прямо в списке, пройдя `k` шагов.

## Ключевое наблюдение

Задача **самоподобна**: после разворота первой группы остаток списка — это та же задача меньшего размера. Поэтому функция `reverseKGroup(head, k)` может:

1. убедиться, что впереди есть `k` узлов (иначе вернуть `head` как есть);
2. развернуть первые `k` узлов обычным разворотом;
3. пришить к хвосту группы результат `reverseKGroup(остаток, k)`.

```
[1 -> 2] -> [3 -> 4] -> 5
 2 -> 1 -> reverseKGroup([3, 4, 5])
```

После разворота бывший первый узел группы (`head`) стал её хвостом, а бывший `k`-й (`prev`) — началом. Ни заглушки, ни указателя «перед группой» не нужно: каждый вызов работает со своей группой с самого начала.

## Техники

### Разворот связного списка тремя указателями

**Что это.** Базовая операция: идём по узлам, держа `prev`, `curr` и `next`, и каждый `curr.next` перенаправляем на `prev`.

```ts naive
let prev = null, curr = head;
while (curr !== null) {
  const next = curr.next;
  curr.next = prev;
  prev = curr;
  curr = next;
}
// prev — новая голова
```

**Как применяется здесь.** Делаем не «до `null`», а ровно `k` шагов. После цикла `prev` — новое начало группы, `curr` — начало следующей.

### Рекурсия «реши первый кусок, остальное — тем же вызовом»

**Что это.** Приём для списков и строк: обработать префикс фиксированного размера, а для остатка вызвать саму функцию; результат вызова пришить к обработанному префиксу.

**Как применяется здесь.** База рекурсии — «узлов меньше `k`»: такой остаток возвращается без изменений. Это сразу покрывает и пустой остаток (`null`). Подробнее о приёмах работы со связными списками — во вкладке «Теория».

## Разбор кода

```ts
function reverseKGroup(head: ListNode | null, k: number): ListNode | null {
  // Проверяем, что впереди есть хотя бы k узлов; если нет — остаток не трогаем
  let check: ListNode | null = head;
  for (let i = 0; i < k; i++) {
    if (check === null) return head;
    check = check.next;
  }
```

Проходим `k` шагов отдельным указателем `check`, ничего не меняя. Если на каком-то шаге узлы кончились — группа неполная, возвращаем `head`: по условию такой хвост остаётся как есть. Это же база рекурсии: при `head = null` выходим на первой же итерации.

```ts
  // Обычный разворот первых k узлов
  let prev: ListNode | null = null;
  let curr: ListNode | null = head;
  for (let i = 0; i < k; i++) {
    const next: ListNode | null = curr!.next;
    curr!.next = prev;
    prev = curr;
    curr = next;
  }
```

Стандартный разворот ровно `k` узлов. `curr!` безопасен: проверка выше гарантирует, что `k` узлов есть. После цикла `prev` — бывший `k`-й узел (новое начало группы), `curr` — первый узел следующей группы (или `null`), а `head.next === null` — бывший первый узел временно «оторван».

```ts
  // head (бывший первый) стал хвостом группы: пришиваем к нему
  // рекурсивно обработанный остаток, который начинается с curr
  head!.next = reverseKGroup(curr, k);
```

Рекурсивный вызов обрабатывает весь остаток и возвращает его новую голову — её и пришиваем к хвосту группы. `head!` — `head` здесь точно не `null`, иначе мы вышли бы на проверке.

```ts
  // prev — бывший k-й узел, теперь начало группы
  return prev;
}
```

Возвращаем начало развёрнутой группы — это голова всего результата для этого вызова.

## Трассировка

`head = [1, 2, 3, 4, 5]`, `k = 2`.

**Вызов f(1).** Проверка: `1`, `2` — есть 2 узла. Разворот: `1.next = null`, `2.next = 1`, `prev = 2`, `curr = 3`. Вызываем `f(3)`.

**Вызов f(3).** Проверка: `3`, `4` — есть. Разворот: `3.next = null`, `4.next = 3`, `prev = 4`, `curr = 5`. Вызываем `f(5)`.

**Вызов f(5).** Проверка: `i = 0` — `5`, `check = null`; `i = 1` — `check === null` → возвращаем `5` без изменений.

Возврат в `f(3)`: `3.next = 5`, возвращаем `4` → `4 -> 3 -> 5`.

Возврат в `f(1)`: `1.next = 4`, возвращаем `2`:

```
2 -> 1 -> 4 -> 3 -> 5
```

Ответ `[2, 1, 4, 3, 5]`. Глубина рекурсии — 3 вызова (две полные группы и остаток).

## Почему это работает

Докажем по индукции по длине списка, что `reverseKGroup(head, k)` возвращает правильно преобразованный список. Если узлов меньше `k`, функция возвращает их без изменений — это и требуется. Иначе первые `k` узлов разворачиваются: `prev` указывает на бывший `k`-й, цепочка идёт назад до бывшего первого `head`. Остаток, начинающийся с `curr`, короче исходного списка, и по предположению индукции рекурсивный вызов вернёт его правильно преобразованным. Пришив его к `head`, получаем «развёрнутая первая группа + правильный остаток» — ровно ответ. Каждый вызов продвигается на `k ≥ 1` узлов, поэтому рекурсия конечна.

## Пограничные случаи

- **`k = 1`**: каждая «группа» из одного узла, разворот ничего не меняет — список возвращается как есть.
- **`k = n`**: весь список разворачивается одной группой, рекурсивный вызов получает `null`.
- **`n` кратно `k`**: последний вызов получает `null` и сразу его возвращает.
- **Остаток меньше `k`**: проверка ничего не меняет в связях, остаток возвращается нетронутым.

## Сложность

- **Время `O(n)`**: каждый узел проходится дважды — при проверке и при развороте (плюс последняя неполная проверка, не длиннее `k`).
- **Память `O(n / k)`**: по одному кадру стека на группу. При `n ≤ 5000` это не больше 5000 кадров — безопасно.
- **Follow-up на собеседовании** — `O(1)` памяти: итеративный вариант с заглушкой `dummy` и указателем `groupPrev` на узел перед текущей группой. Найти `k`-й узел, развернуть группу, пришить `groupPrev.next` к новому началу и сдвинуть `groupPrev` на хвост группы. Та же логика, только стыки пришиваются вручную вместо рекурсии.

## Типичные ошибки

1. **Разворачивать, не проверив, что в группе `k` узлов** → неполный остаток тоже развернётся.
2. **Проверять тем же указателем, что и разворачивать**, или менять связи во время проверки → неполный хвост испорчен.
3. **Вернуть `head` вместо `prev`** → вернётся бывший первый узел, который теперь хвост группы.
4. **Передать в рекурсию `head.next`** вместо `curr` → после разворота `head.next` уже `null`.
5. **Разворачивать до `null`**, а не `k` шагов → развернётся весь список.

## Как узнать такую задачу

- Нужно преобразовать список **кусками фиксированного размера** (развернуть, переставить пары).
- Неполный кусок в конце обрабатывается особо — это база рекурсии.
- Задача «обработай первый кусок и сделай то же с остатком» — сигнал к рекурсии; при требовании `O(1)` памяти — к итеративному варианту с якорем `groupPrev`. Родственные задачи: Swap Nodes in Pairs (это `k = 2`), Reverse Linked List II, Reverse Linked List.
