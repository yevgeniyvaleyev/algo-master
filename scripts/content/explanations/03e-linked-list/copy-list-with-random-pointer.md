## Задача простыми словами

Дан связный список, у каждого узла которого кроме `next` есть ещё указатель `random` — он может смотреть на **любой** узел этого же списка или быть `null`. Нужно сделать **глубокую копию**: создать новые узлы с теми же значениями и с такими же связями, причём ни один указатель копии не должен вести в исходный список.

Пример: список `7 → 13 → 11`, где у `13` поле `random` указывает на `7`, а у `11` — на себя. В копии `13'` должен указывать на `7'`, а `11'` — на `11'`, а не на старые узлы.

## Наивный подход

Скопировать цепочку `next` легко. Трудность в `random`: когда мы создаём копию узла `B`, его `random` может указывать на узел, копии которого ещё нет, а если есть — непонятно, как её найти. Стандартное решение — хеш-таблица «оригинал → копия»:

```ts naive
const map = new Map<_Node, _Node>();
for (let c = head; c !== null; c = c.next) map.set(c, new _Node(c.val));
for (let c = head; c !== null; c = c.next) {
  map.get(c)!.next = c.next ? map.get(c.next)! : null;
  map.get(c)!.random = c.random ? map.get(c.random)! : null;
}
return map.get(head)!;
```

Это правильно и работает за `O(n)`, но требует `O(n)` **дополнительной памяти** на таблицу. Таблица нужна только чтобы ответить на вопрос «где копия узла `X`?». Ещё хуже — совсем без таблицы: для каждого `random` искать его позицию в исходном списке и потом идти на столько же шагов в копии, это `O(n²)`.

## Ключевое наблюдение

Ответ на вопрос «где копия `X`?» можно хранить **прямо в структуре списка**. Если вставить копию каждого узла сразу после оригинала (`A → A' → B → B' → …`), то копия любого узла `X` — это просто `X.next`. Тогда копия `X.random` — это `X.random.next`, и таблица не нужна. В конце списки «расплетаются» обратно.

## Техники

### Переплетение (interleaving) списков

**Что это.** Приём, когда вспомогательная информация временно кладётся в саму структуру данных вместо отдельной памяти. Здесь соответствие «оригинал → копия» кодируется позицией: копия стоит сразу за оригиналом.

**Типичный шаблон:** три прохода — (1) вставить копии, (2) заполнить поля, зависящие от соответствия, (3) разделить списки и восстановить исходный.

**Как применяется здесь.** Шаг 2 использует правило `copy(X) = X.next`, шаг 3 возвращает исходному списку прежний вид — это важно, по условию вход менять нельзя (его проверяют после вызова).

### Перевешивание указателей в связном списке

Вставка узла после `cur` — `copy.next = cur.next; cur.next = copy`, удаление «через один» — `cur.next = cur.next.next`. Обе операции `O(1)`, если есть ссылка на соседний узел. Подробнее о базовых приёмах со списками — во вкладке «Теория».

### Альтернатива: хеш-таблица

Вариант с `Map` из наивного подхода — тоже хороший ответ на собеседовании, его проще написать без ошибок. Переплетение — это оптимизация памяти до `O(1)`.

## Разбор кода

```ts
function copyRandomList(head: _Node | null): _Node | null {
  if (head === null) return null;
```

Пустой список копируется в пустой. Дальше можно считать, что `head` существует — это нужно в шаге 3, где берётся `head.next`.

```ts
  // Шаг 1. Вставляем копию сразу после каждого узла:
  // A -> B -> C  превращается в  A -> A' -> B -> B' -> C -> C'
  let cur: _Node | null = head;
  while (cur !== null) {
    const copy: _Node = new _Node(cur.val, cur.next);
    cur.next = copy;
    cur = copy.next;
  }
```

Для каждого оригинала создаём копию с тем же значением, и её `next` сразу указывает на следующий **оригинал** (`cur.next`). Затем оригинал указывает на копию. Переходим к `copy.next` — следующему оригиналу (через `cur.next` попали бы на только что созданную копию и зациклились бы на копировании копий).

```
до:    A -> B -> C -> null
после: A -> A' -> B -> B' -> C -> C' -> null
```

Поля `random` у копий пока пустые.

```ts
  // Шаг 2. Проставляем random у копий.
  // Копия узла X всегда лежит в X.next, поэтому копия X.random — это X.random.next
  cur = head;
  while (cur !== null) {
    const copy: _Node = cur.next!;
    copy.random = cur.random !== null ? cur.random.next : null;
    cur = copy.next;
  }
```

Снова идём по оригиналам (шагом через один). У оригинала `cur` копия — `cur.next`. Если `cur.random` указывает на узел `R`, то копия должна указывать на копию `R`, а она лежит в `R.next`. Если `random` пустой — у копии тоже `null`. Этот шаг нельзя слить с шагом 1: при вставке копии `B'` копия `R` могла ещё не существовать (если `R` правее).

```ts
  // Шаг 3. Расплетаем списки обратно: исходный восстанавливаем, копию собираем отдельно
  const newHead: _Node = head.next!;
  cur = head;
  while (cur !== null) {
    const copy: _Node = cur.next!;
    cur.next = copy.next; // возвращаем исходную связь
    copy.next = copy.next !== null ? copy.next.next : null; // копия -> следующая копия
    cur = cur.next;
  }
```

Голова копии — `head.next`; запоминаем её до того, как связи поменяются. Затем для каждой пары `cur, copy`:

- `cur.next = copy.next` — оригинал снова указывает на следующий оригинал;
- `copy.next = copy.next.next` — копия перепрыгивает через следующий оригинал на следующую копию; у последней копии `copy.next === null`, и она остаётся концом списка.

Порядок важен: сначала читаем `copy.next` для оригинала, потом меняем `copy.next`. `cur = cur.next` переходит уже по восстановленной связи к следующему оригиналу.

```ts
  return newHead;
}
```

Возвращаем голову независимой копии. Исходный список к этому моменту полностью восстановлен.

## Трассировка

Список `A(7) → B(13) → C(11)`, `A.random = null`, `B.random = A`, `C.random = C`.

Шаг 1 (вставка копий):

```
A -> A' -> B -> B' -> C -> C' -> null
```

Шаг 2 (random):

1. `cur = A`, `copy = A'`: `A.random = null` → `A'.random = null`.
2. `cur = B`, `copy = B'`: `B.random = A` → `B'.random = A.next = A'`.
3. `cur = C`, `copy = C'`: `C.random = C` → `C'.random = C.next = C'`.

Шаг 3 (расплетание), `newHead = A'`:

1. `cur = A`, `copy = A'`: `A.next = B`; `A'.next = B.next = B'`. `cur = B`.
2. `cur = B`, `copy = B'`: `B.next = C`; `B'.next = C.next = C'`. `cur = C`.
3. `cur = C`, `copy = C'`: `C.next = null`; `C'.next === null` → остаётся `null`. `cur = null`.

```
оригинал: A -> B -> C -> null      (random: B -> A, C -> C)
копия:    A' -> B' -> C' -> null   (random: B' -> A', C' -> C')
```

## Почему это работает

После шага 1 выполняется инвариант: для каждого оригинала `X` верно `X.next = copy(X)`, а `copy(X).next` — следующий оригинал. Шаг 2 не меняет `next`, поэтому инвариант держится всё время шага, и формула `copy(X.random) = X.random.next` верна для каждого узла — включая случаи, когда `random` указывает назад, вперёд или на себя. Шаг 3 читает связь «оригинал → следующий оригинал» из `copy.next` и восстанавливает её, а копиям отдаёт связи «копия → следующая копия». Поле `random` в шаге 3 не трогается, и все `random` копий указывают на копии — значит, копия полностью независима.

## Пограничные случаи

- **Пустой список**: сразу `null`.
- **Один узел с `random` на себя**: `A'.random = A.next = A'` — корректно.
- **Все `random` равны `null`**: шаг 2 просто проставляет `null`.
- **Одинаковые значения в разных узлах**: алгоритм опирается на ссылки, а не на значения, поэтому дубликаты не мешают (а вот таблица «значение → копия» сломалась бы).
- **Исходный список должен остаться прежним**: шаг 3 восстанавливает его полностью.

## Сложность

- **Время `O(n)`**: три прохода, каждый — `O(n)` с операциями `O(1)` на узел.
- **Память `O(1)` дополнительно**: только несколько указателей. Сами `n` копий — это ответ, их не считают. Решение с `Map` тратило бы ещё `O(n)`.

## Типичные ошибки

1. **Проставлять `random` в первом же проходе** → копия цели может ещё не существовать.
2. **`copy.random = cur.random`** → копия указывает в исходный список, глубокой копии нет.
3. **Забыть восстановить исходный список** → проверяющий код видит испорченный вход.
4. **В шаге 1 перейти по `cur.next`** вместо `copy.next` → бесконечное копирование копий.
5. **Не проверить `copy.next !== null`** в шаге 3 → обращение к `null.next` на последней копии.

## Как узнать такую задачу

- Нужно **клонировать** структуру, в которой есть «произвольные» ссылки помимо основной цепочки (`random`, соседи в графе).
- Ключевой вопрос «где копия этого узла?» — классически решается таблицей «оригинал → копия» (как в Clone Graph).
- Если просят `O(1)` дополнительной памяти, а структуру можно временно менять, — ищите способ закодировать соответствие в самих узлах (переплетение, как здесь). Родственные задачи: Clone Graph, Clone Binary Tree With Random Pointer.
