## Задача простыми словами

Дан связный список, у каждого узла которого кроме `next` есть ещё указатель `random` — он может смотреть на **любой** узел этого же списка или быть `null`. Нужно сделать **глубокую копию**: создать новые узлы с теми же значениями и с такими же связями, причём ни один указатель копии не должен вести в исходный список.

Пример: список `7 → 13 → 11`, где у `13` поле `random` указывает на `7`, а у `11` — на себя. В копии `13'` должен указывать на `7'`, а `11'` — на `11'`, а не на старые узлы.

## Наивный подход

Скопировать цепочку `next` легко — один проход. Трудность в `random`: когда мы создаём копию узла `B`, его `random` может указывать на узел, копии которого ещё нет, а если копия есть — непонятно, как её найти. Без вспомогательной структуры приходится для каждого `random` искать его **позицию** в исходном списке и потом идти на столько же шагов в копии:

```ts naive
// для каждого X: найти индекс X.random в оригинале (O(n)) ...
let idx = 0;
for (let c = head; c !== x.random; c = c.next) idx++;
// ... и дойти до узла с тем же индексом в копии (ещё O(n))
let target = copyHead;
for (let i = 0; i < idx; i++) target = target.next;
xCopy.random = target;
```

Итого `O(n²)`. Вся работа уходит на один вопрос: «где копия узла `X`?». Если отвечать на него за `O(1)`, задача становится линейной.

## Ключевое наблюдение

Заведём таблицу `Map` «оригинал → копия». Тогда список можно воспринимать как **граф**, у каждой вершины которого два ребра — `next` и `random`, и копировать его так же, как любой граф (Clone Graph): функция `cloneNode(node)` возвращает копию узла; если копия уже есть в таблице — отдаёт готовую, иначе создаёт новую, **сразу** записывает в таблицу и рекурсивно копирует оба соседа. Порядок, в котором `random` указывают вперёд, назад или на себя, перестаёт иметь значение.

## Техники

### Хеш-таблица «оригинал → копия»

**Что это.** `Map`, где ключ — ссылка на исходный узел, значение — его копия. Ключами служат сами объекты, а не значения `val`, поэтому одинаковые значения в разных узлах не путаются.

**Как применяется здесь.** Таблица выполняет две роли: отвечает на вопрос «где копия `X`?» и служит множеством посещённых узлов, чтобы ничего не копировать дважды.

### Рекурсивный обход графа (DFS) с запоминанием

**Что это.** Функция, которая обрабатывает вершину и вызывает себя для соседей, а посещённые вершины отмечает, чтобы не зациклиться.

**Типичный шаблон** клонирования графа:

```ts naive
function clone(node) {
  if (node === null) return null;
  if (seen.has(node)) return seen.get(node);
  const copy = new Node(node.val);
  seen.set(node, copy); // отметить ДО рекурсии
  for (const nb of node.neighbors) copy.neighbors.push(clone(nb));
  return copy;
}
```

**Как применяется здесь.** «Соседей» ровно два — `next` и `random`. Подробнее о приёмах со связными списками — во вкладке «Теория».

## Трассировка

Список `A(7) → B(13) → C(11)`, `A.random = null`, `B.random = A`, `C.random = C`.

1. `cloneNode(A)`: в таблице нет → `A' = 7`, `visited = {A: A'}`. Вызываем `cloneNode(B)`.
2. `cloneNode(B)`: нет → `B' = 13`, `visited = {A, B}`. Вызываем `cloneNode(C)`.
3. `cloneNode(C)`: нет → `C' = 11`, `visited = {A, B, C}`. `cloneNode(null)` → `C'.next = null`. `cloneNode(C)` — уже есть → `C'.random = C'`. Возвращаем `C'`.
4. Назад в `B`: `B'.next = C'`. `cloneNode(A)` — уже есть → `B'.random = A'`. Возвращаем `B'`.
5. Назад в `A`: `A'.next = B'`. `cloneNode(null)` → `A'.random = null`. Возвращаем `A'`.

```
копия: A'(7) -> B'(13) -> C'(11) -> null
random: B' -> A', C' -> C'
```

Глубина рекурсии здесь 3 — по одному кадру на узел цепочки `next`.

## Почему это работает

Инвариант: если узел `X` есть в `visited`, то `visited.get(X)` — **единственная** копия `X`, и после завершения всех вызовов у неё будут проставлены обе связи. Каждый узел попадает в таблицу при первом же вызове `cloneNode` для него — до рекурсии, поэтому второй копии не появится. Каждая связь копии получается как `cloneNode(связь оригинала)`, то есть ведёт на копию соответствующего узла (или `null`), и никогда — в исходный список. Каждый узел создаётся один раз и обрабатывает две связи, значит, рекурсия конечна.

## Пограничные случаи

- **Пустой список**: `cloneNode(null)` сразу возвращает `null`.
- **Один узел с `random` на себя**: при копировании `random` узел уже в таблице → `A'.random = A'`.
- **Все `random` равны `null`**: обычное копирование цепочки.
- **`random` указывает вперёд**: к этому моменту рекурсия по `next` уже скопировала весь хвост, копия найдётся в таблице.
- **Одинаковые значения в разных узлах**: ключ таблицы — ссылка, а не `val`, дубликаты не мешают.

## Сложность

- **Время `O(n)`**: каждый узел создаётся один раз, каждый вызов делает `O(1)` работы плюс два вызова, из которых все, кроме первых `n`, сразу возвращаются из таблицы.
- **Память `O(n)`**: таблица на `n` записей и стек рекурсии. Глубина стека — до `n`, так как рекурсия идёт по цепочке `next`; при `n ≤ 1000` это безопасно. Сами `n` копий — это ответ.
- **Follow-up на собеседовании**: «а без таблицы?». Можно вставить копию сразу за оригиналом (`A → A' → B → B' → …`): тогда копия `X` — это `X.next`, копия `X.random` — `X.random.next`, а в конце списки расплетаются обратно. Это `O(1)` дополнительной памяти, но три аккуратных прохода.

## Типичные ошибки

1. **Записывать в таблицу после рекурсии** → `random` на себя или назад создаёт дубль копии или бесконечную рекурсию.
2. **`newNode.random = node.random`** → копия указывает в исходный список, глубокой копии нет.
3. **Ключ таблицы — `val`** вместо самого узла → разные узлы с одинаковым значением склеиваются.
4. **Создавать новую таблицу в каждом вызове** → ничего не запоминается.
5. **Рекурсия на очень длинных списках** → при `n` порядка сотен тысяч стек переполнится; тогда нужен итеративный вариант с двумя проходами по таблице. Здесь `n ≤ 1000`.

## Как узнать такую задачу

- Нужно **клонировать** структуру, в которой есть «произвольные» ссылки помимо основной цепочки (`random`, соседи в графе).
- Ключевой вопрос «где копия этого узла?» — классически решается таблицей «оригинал → копия» и обходом с запоминанием.
- Если просят `O(1)` дополнительной памяти, а структуру можно временно менять, — вспоминайте переплетение копий с оригиналами. Родственные задачи: Clone Graph, Clone Binary Tree With Random Pointer.
