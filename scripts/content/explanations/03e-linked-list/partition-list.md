## Задача простыми словами

Дан связный список и число `x`. Нужно переставить узлы так, чтобы все узлы со значением **меньше `x`** шли раньше всех узлов со значением **больше или равным `x`**. Внутри каждой из двух частей исходный относительный порядок должен сохраниться.

Пример: `head = [1, 4, 3, 2, 5, 2]`, `x = 3`. Меньше трёх: `1, 2, 2` (в исходном порядке), остальные: `4, 3, 5`. Ответ `[1, 2, 2, 4, 3, 5]`.

## Наивный подход

Выписать значения в два массива и пересоздать список:

```ts naive
const small: number[] = [], big: number[] = [];
for (let c = head; c !== null; c = c.next) (c.val < x ? small : big).push(c.val);
const dummy = new ListNode(0);
let tail = dummy;
for (const v of [...small, ...big]) { tail.next = new ListNode(v); tail = tail.next; }
return dummy.next;
```

Это `O(n)` по времени, но `O(n)` дополнительной памяти и создание новых узлов — хотя все нужные узлы уже есть, их надо лишь **перецепить**. Ещё один соблазн — «как в быстрой сортировке» менять местами элементы, но обмен нарушает требование стабильности (сохранения порядка).

## Ключевое наблюдение

Ответ — это **конкатенация двух подпоследовательностей** исходного списка: сначала узлы `< x`, потом узлы `>= x`, каждая в исходном порядке. Такие подпоследовательности можно собирать прямо из существующих узлов: идём по списку и пристраиваем каждый узел в хвост одного из двух списков. Потом пришиваем второй список к концу первого. Перецепка узла — `O(1)`, новых узлов не нужно.

## Техники

### Разделение на два списка с заглушками

**Что это.** Приём «разложить по корзинам»: заводим несколько списков-результатов, у каждого — заглушка (`dummy`) и указатель на хвост. Каждый узел входа пристраиваем к хвосту нужного списка. В конце склеиваем.

**Типичный шаблон:**

```ts naive
const aDummy = new ListNode(0), bDummy = new ListNode(0);
let a = aDummy, b = bDummy;
for (let n = head; n !== null; n = n.next) {
  if (условие(n)) { a.next = n; a = n; } else { b.next = n; b = n; }
}
b.next = null;
a.next = bDummy.next;
```

**Когда применять.** Нужно стабильно разделить список по признаку: чётные/нечётные позиции (Odd Even Linked List), меньше/больше опорного, разделить на `k` частей. Заглушки избавляют от проверок «список ещё пуст?».

**Как применяется здесь.** Две корзины: `less` (значения `< x`) и `ge` (значения `>= x`). Подробнее о заглушках и перевешивании указателей — во вкладке «Теория».

### Стабильность

Порядок внутри корзин сохраняется автоматически: узлы пристраиваются **в хвост** в том порядке, в котором встречаются. Это отличает приём от разбиения Хоара/Ломуто в quicksort, где элементы меняются местами и порядок теряется.

## Разбор кода

```ts
function partition(head: ListNode | null, x: number): ListNode | null {
  // Две заглушки: для узлов < x и для узлов >= x
  const lessDummy = new ListNode(0);
  const geDummy = new ListNode(0);
  let less = lessDummy;
  let ge = geDummy;
```

Две заглушки — начала двух будущих списков, и два указателя на их текущие хвосты. Пока списки пусты, хвост — сама заглушка.

```ts
  // Раскладываем узлы по двум спискам, сохраняя порядок
  for (let node = head; node !== null; node = node.next) {
    if (node.val < x) {
      less.next = node;
      less = node;
    } else {
      ge.next = node;
      ge = node;
    }
  }
```

Проходим исходный список. Каждый узел цепляем к хвосту своего списка и делаем его новым хвостом. Заметьте: поле `node.next` мы **не меняем** — шаг цикла `node = node.next` читает исходную связь, и она ещё цела. Меняется только `next` у предыдущего хвоста, а он уже пройден. Поэтому обход не сбивается.

Побочный эффект: у последних узлов корзин `next` по-прежнему указывает куда-то в исходный список.

```ts
  // Обрываем хвост второго списка — иначе может остаться ссылка
  // на узел из первого списка и получится цикл
  ge.next = null;
```

Хвост второй корзины станет концом ответа, поэтому его `next` обязательно обнуляем. Если последний узел второй корзины в исходном списке указывал на узел первой корзины, без этой строки получился бы цикл (см. трассировку). Хвост первой корзины обнулять не нужно — следующая строка всё равно его перезапишет.

```ts
  // Склеиваем: сначала меньшие, затем большие или равные
  less.next = geDummy.next;

  return lessDummy.next;
}
```

Пришиваем начало второго списка (узел после его заглушки) к хвосту первого. Если вторая корзина пуста, `geDummy.next === null`, и первый список правильно заканчивается. Ответ — узел после первой заглушки; если первая корзина пуста, `less === lessDummy`, и `lessDummy.next` сразу указывает на начало второй.

## Трассировка

`head = [1, 4, 3, 2, 5, 2]`, `x = 3`. Обозначим вторую двойку как `2'`.

1. `1 < 3` → в `less`: `L: 1`.
2. `4 >= 3` → в `ge`: `G: 4`.
3. `3 >= 3` → `G: 4 → 3`.
4. `2 < 3` → `L: 1 → 2`.
5. `5 >= 3` → `G: 4 → 3 → 5`.
6. `2' < 3` → `L: 1 → 2 → 2'`.

После цикла хвосты: `less = 2'`, `ge = 5`. Но `5.next` всё ещё указывает на `2'` (исходная связь!):

```
L: lessDummy -> 1 -> 2 -> 2' -> null
G: geDummy -> 4 -> 3 -> 5 -> 2'       (хвостовая ссылка из исходного списка)
```

Без `ge.next = null` после склейки получилось бы `1 → 2 → 2' → 4 → 3 → 5 → 2' → 4 → …` — цикл. Обнуляем: `5.next = null`. Склеиваем: `2'.next = 4`.

```
lessDummy -> 1 -> 2 -> 2' -> 4 -> 3 -> 5 -> null
```

Ответ `[1, 2, 2, 4, 3, 5]`.

## Почему это работает

Инвариант цикла: после обработки первых `t` узлов цепочка от `lessDummy.next` до `less` — это все узлы `< x` среди них в исходном порядке, а от `geDummy.next` до `ge` — все узлы `>= x` в исходном порядке. Каждый узел попадает ровно в одну корзину. После цикла все узлы распределены; обнуление `ge.next` делает второй список конечным, а `less.next = geDummy.next` ставит его целиком после первого. Получаем требуемый порядок: все `< x`, затем все `>= x`, стабильно. Узлов не прибавилось и не потерялось — мы только перецепили существующие.

## Пограничные случаи

- **Пустой список**: цикл не выполняется, `ge.next = null` меняет заглушку, ответ `lessDummy.next = geDummy.next = null`.
- **Все узлы `< x`**: вторая корзина пуста, `less.next = null` — список заканчивается правильно.
- **Все узлы `>= x`**: первая корзина пуста, ответ — второй список.
- **Значения, равные `x`**: идут во вторую корзину (`>= x`), как требует условие.
- **Цикл через хвост**: предотвращён `ge.next = null`.

## Сложность

- **Время `O(n)`**: один проход, на каждый узел — сравнение и два присваивания.
- **Память `O(1)`**: две заглушки и два указателя; существующие узлы переиспользуются.

## Типичные ошибки

1. **Забыть `ge.next = null`** → цикл в ответе (тест падает по таймауту или по памяти).
2. **Обнулить `less.next`, а не `ge.next`** → хвост второго списка всё ещё может ссылаться на узел первого.
3. **Обмен значениями «как в quicksort»** → нарушается порядок внутри частей.
4. **Менять `node.next` внутри цикла до перехода** (например, `node.next = null` сразу) → обход обрывается.
5. **Сравнение `<=` вместо `<`** → узлы, равные `x`, попадают не в ту часть.

## Как узнать такую задачу

- Нужно разделить список (или массив) по признаку **с сохранением порядка** внутри частей.
- Ответ — «сначала одни, потом другие» — это склейка двух подпоследовательностей.
- Требуется `O(1)` памяти для списка — перецепляем узлы в корзины с заглушками. Родственные задачи: Odd Even Linked List, Split Linked List in Parts, Sort Colors (для массива, но без стабильности), Merge Two Sorted Lists (обратная операция — сборка из двух списков).
