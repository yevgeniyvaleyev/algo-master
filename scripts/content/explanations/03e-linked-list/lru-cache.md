## Задача простыми словами

Нужно реализовать класс кэша фиксированной ёмкости `capacity` с политикой **LRU** (Least Recently Used — «дольше всех не использовавшийся»):

- `get(key)` — вернуть значение по ключу или `-1`, если ключа нет;
- `put(key, value)` — записать значение (новое или обновить); если ключей стало больше `capacity`, выбросить тот, к которому **дольше всего не обращались**.

Обе операции должны работать за `O(1)` в среднем. «Обращение» — это и `get`, и `put`.

Пример при `capacity = 2`: `put(1,1)`, `put(2,2)`, `get(1)` → `1` (теперь `1` свежее, чем `2`), `put(3,3)` → вытесняется `2`, `get(2)` → `-1`.

## Наивный подход

Хранить ключи в `Map` и для каждого — «время последнего обращения»; при переполнении искать ключ с минимальным временем:

```ts naive
const data = new Map<number, { value: number; time: number }>();
let clock = 0;
// get/put: обновить data.get(key).time = clock++
// переполнение: перебрать все записи и удалить запись с минимальным time
```

`get` и обновление — `O(1)`, но вытеснение — `O(capacity)`: поиск минимума линейным перебором. Другой вариант — держать ключи в массиве по порядку свежести: тогда «освежить» ключ — это удалить его из середины массива, тоже `O(capacity)`. Лишняя работа в обоих случаях — **поиск** или **сдвиг** при каждом обращении. Нужна структура, где элемент можно вынуть из любого места и вставить в начало за `O(1)`, и при этом найти его по ключу за `O(1)`.

## Ключевое наблюдение

Две структуры дополняют друг друга:

- **двусвязный список** хранит порядок свежести: в начале — самый свежий, в конце — самый старый. Вынуть узел, зная ссылку на него, и вставить в начало — `O(1)`, потому что у узла есть и `prev`, и `next`;
- **хеш-таблица** `ключ → узел` даёт эту ссылку за `O(1)`.

```
map: { 1 -> •, 3 -> • }
head <-> [3:3] <-> [1:1] <-> tail
        свежий     старый
```

Каждое обращение: найти узел через `map`, вынуть его из списка, вставить в начало. Вытеснение: взять узел перед `tail`, вынуть его и удалить ключ из `map`.

## Техники

### Хеш-таблица + двусвязный список

**Что это.** Классическая составная структура: таблица обеспечивает доступ по ключу, список — порядок. Узлы списка лежат в таблице как значения, поэтому любой элемент списка находится за `O(1)`, а перестановка в списке не требует поиска.

**Когда применять.** Нужен порядок (по времени, по частоте) **и** доступ по ключу, и элементы часто перемещаются в начало/конец. Так устроены LRU-кэши в реальных системах, `LinkedHashMap` в Java, `OrderedDict` в Python.

**Как применяется здесь.** `map: Map<number, DListNode>`, список с двумя заглушками `head` и `tail`. В узле хранится и ключ — чтобы при вытеснении, зная только узел, удалить запись из `map`. Подробнее о связных списках — во вкладке «Теория».

### Две заглушки (sentinels)

**Что это.** Фиктивные узлы в начале и в конце двусвязного списка. Реальные элементы всегда лежат **между** ними, поэтому у каждого реального узла есть и `prev`, и `next`.

**Как применяется здесь.** `remove` и `addToFront` не проверяют `null` и не обрабатывают «пустой список» или «удаляем первый/последний». Самый свежий элемент — `head.next`, самый старый — `tail.prev`.

### Замечание об альтернативе

В JavaScript `Map` сохраняет порядок вставки, поэтому LRU можно написать через одну `Map` (удалить и вставить ключ заново = «освежить»; первый ключ `map.keys().next()` — самый старый). Это короче, но опирается на особенность языка; решение со списком показывает саму идею и переносится на любой язык.

## Разбор кода

```ts
// Узел двусвязного списка: хранит и ключ, чтобы при вытеснении удалить его из Map
class DListNode {
  key: number;
  value: number;
  prev: DListNode | null = null;
  next: DListNode | null = null;

  constructor(key: number, value: number) {
    this.key = key;
    this.value = value;
  }
}
```

Узел двусвязного списка. `value` — сохранённое значение, `prev`/`next` — соседи. Поле `key` нужно ровно в одном месте — при вытеснении: мы берём узел `tail.prev` и должны удалить его ключ из `map`, а узнать ключ по узлу больше неоткуда.

```ts
class LRUCache {
  private capacity: number;
  // ключ -> узел списка: доступ к узлу за O(1)
  private map = new Map<number, DListNode>();
  // Заглушки: head.next — самый свежий элемент, tail.prev — самый старый
  private head = new DListNode(0, 0);
  private tail = new DListNode(0, 0);
```

Состояние кэша: ёмкость, таблица и две заглушки. Значения `0, 0` у заглушек ни на что не влияют — заглушки никогда не попадают в `map`.

```ts
  constructor(capacity: number) {
    this.capacity = capacity;
    this.head.next = this.tail;
    this.tail.prev = this.head;
  }
```

Пустой кэш: заглушки указывают друг на друга.

```
head <-> tail
```

```ts
  get(key: number): number {
    const node = this.map.get(key);
    if (node === undefined) return -1;
    // Обращение делает элемент самым свежим — переносим в начало
    this.remove(node);
    this.addToFront(node);
    return node.value;
  }
```

Ищем узел по ключу. Нет — `-1`, и порядок не меняется. Есть — это обращение, элемент становится самым свежим: вынимаем узел с текущего места и вставляем сразу после `head`. Узел тот же самый, поэтому запись в `map` обновлять не нужно.

```ts
  put(key: number, value: number): void {
    const node = this.map.get(key);
    if (node !== undefined) {
      // Ключ уже есть: обновляем значение и освежаем
      node.value = value;
      this.remove(node);
      this.addToFront(node);
      return;
    }
```

Первый случай `put` — ключ уже есть. Размер кэша не меняется, поэтому вытеснение не нужно: обновляем значение в узле и переносим узел в начало, как в `get`.

```ts
    const fresh = new DListNode(key, value);
    this.map.set(key, fresh);
    this.addToFront(fresh);
```

Второй случай — новый ключ. Создаём узел, кладём в таблицу и в начало списка.

```ts
    // Переполнение — вытесняем самый старый элемент (перед хвостовой заглушкой)
    if (this.map.size > this.capacity) {
      const lru = this.tail.prev!;
      this.remove(lru);
      this.map.delete(lru.key);
    }
  }
```

Если элементов стало больше `capacity` (а превысить можно только на 1), вытесняем самый старый — узел перед `tail`. Удаляем его и из списка, и из таблицы — для этого и нужен `lru.key`. Только что добавленный узел вытеснен быть не может: он в начале, а `capacity >= 1`, значит, перед `tail` стоит другой узел.

Порядок «сначала добавить, потом вытеснить» удобен: `map.size` сразу показывает, есть ли переполнение. Можно и наоборот (проверить `size === capacity` до добавления) — результат тот же.

```ts
  // Вынуть узел из списка за O(1): соседи знают друг о друге благодаря prev/next
  private remove(node: DListNode): void {
    node.prev!.next = node.next;
    node.next!.prev = node.prev;
  }
```

Соседи узла начинают указывать друг на друга в обход него:

```
до:    A <-> node <-> B
после: A <-> B
```

Благодаря заглушкам у реального узла оба соседа существуют, отсюда `!` без проверок. Поля самого `node` не обнуляются — их сразу перезапишет `addToFront` или узел станет мусором.

```ts
  // Вставить узел сразу после головной заглушки
  private addToFront(node: DListNode): void {
    node.prev = this.head;
    node.next = this.head.next;
    this.head.next!.prev = node;
    this.head.next = node;
  }
}
```

Вставка между `head` и текущим первым элементом `F` (или `tail`, если список пуст):

1. `node.prev = head`, `node.next = F` — узел знает соседей;
2. `F.prev = node` — правый сосед знает узел;
3. `head.next = node` — левый сосед знает узел.

Шаг 3 должен идти **после** шага 2: пока мы не перезаписали `head.next`, через него доступен `F`. Если поменять их местами, `head.next.prev = node` запишет `node.prev = node`.

## Трассировка

`capacity = 2`. Состояние списка — слева самый свежий.

1. `put(1, 1)`: новый ключ. `H ⇄ 1 ⇄ T`, размер 1.
2. `put(2, 2)`: новый ключ. `H ⇄ 2 ⇄ 1 ⇄ T`, размер 2.
3. `get(1)`: найден, переносим в начало. `H ⇄ 1 ⇄ 2 ⇄ T`. Возврат `1`.
4. `put(3, 3)`: новый. `H ⇄ 3 ⇄ 1 ⇄ 2 ⇄ T`, размер 3 > 2 → вытесняем `T.prev = 2`. `H ⇄ 3 ⇄ 1 ⇄ T`, в `map` ключи `{1, 3}`.
5. `get(2)`: нет в `map` → `-1`.
6. `put(4, 4)`: новый. `H ⇄ 4 ⇄ 3 ⇄ 1 ⇄ T`, размер 3 → вытесняем `1`. `H ⇄ 4 ⇄ 3 ⇄ T`.
7. `get(1)`: `-1`.
8. `get(3)`: найден → `H ⇄ 3 ⇄ 4 ⇄ T`. Возврат `3`.
9. `get(4)`: найден → `H ⇄ 4 ⇄ 3 ⇄ T`. Возврат `4`.

Итог вызовов: `[null, null, 1, null, -1, null, -1, 3, 4]`. Шаг 3 показывает суть LRU: без `get(1)` на шаге 4 вытеснился бы `1`, а не `2`.

Обновление существующего ключа: при `H ⇄ 4 ⇄ 3 ⇄ T` вызов `put(3, 30)` меняет значение и переносит узел: `H ⇄ 3 ⇄ 4 ⇄ T`, размер не растёт, никто не вытесняется.

## Почему это работает

Инварианты после каждой операции:

1. `map` и список содержат **одни и те же** ключи: каждый `put` нового ключа добавляет в оба места, каждое вытеснение удаляет из обоих; `get` и обновление только переставляют узел.
2. Узлы в списке упорядочены по времени последнего обращения: от самого свежего (`head.next`) к самому старому (`tail.prev`). Любое обращение переносит узел в начало — он становится самым свежим, относительный порядок остальных не меняется.
3. Размер не превышает `capacity`: он растёт максимум на 1 за `put` и сразу возвращается вытеснением.

Из инварианта 2 следует, что `tail.prev` — действительно дольше всех не использованный ключ, то есть вытесняется правильный элемент.

## Пограничные случаи

- **`capacity = 1`**: каждый новый ключ вытесняет предыдущий; только что вставленный узел не вытесняется, потому что перед `tail` стоит старый.
- **`put` существующего ключа**: обновление без вытеснения, даже если кэш полон.
- **`get` отсутствующего ключа**: `-1`, порядок не меняется.
- **Пустой кэш**: `head.next === tail`, `get` любого ключа возвращает `-1`.
- **Повторный `get` самого свежего**: вынимаем и вставляем на то же место — корректно.

## Сложность

- **Время `O(1)`** на `get` и `put`: операции `Map` (`get`, `set`, `delete`) — амортизированное `O(1)`; `remove` и `addToFront` — фиксированное число присваиваний.
- **Память `O(capacity)`**: не больше `capacity` узлов в списке и записей в таблице (плюс две заглушки).

## Типичные ошибки

1. **Односвязный список** → чтобы вынуть узел, нужен предшественник, его поиск — `O(n)`.
2. **Не хранить `key` в узле** → при вытеснении нельзя удалить запись из `map`, и таблица «течёт».
3. **Не освежать элемент при `get`** или при обновлении в `put` → вытесняется не тот ключ.
4. **Вытеснять при обновлении существующего ключа** → размер не рос, а элемент потерян.
5. **Неправильный порядок присваиваний в `addToFront`** → узел указывает сам на себя, список рвётся.

## Как узнать такую задачу

- Нужно спроектировать структуру с операциями за **`O(1)`**, где важен **порядок** элементов (по времени обращения) и **доступ по ключу**.
- Ключевые слова: «кэш», «вытеснить наименее недавно использованный», «ограниченная ёмкость».
- «Переместить в начало / удалить из середины за `O(1)`» → двусвязный список; «найти за `O(1)`» → хеш-таблица; вместе — их комбинация. Родственные задачи: LFU Cache (добавляются частоты и несколько списков), Design Browser History, All O'one Data Structure, Insert Delete GetRandom O(1).
