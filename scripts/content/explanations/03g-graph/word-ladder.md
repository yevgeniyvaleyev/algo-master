## Задача простыми словами

Даны слова `beginWord`, `endWord` и словарь `wordList`. За шаг можно поменять **одну букву** слова, и получившееся слово должно быть в словаре. Нужно вернуть **число слов** в самой короткой цепочке от `beginWord` до `endWord` (включая оба конца) или `0`, если цепочки нет.

Пример: `"hit" → "cog"`, словарь `["hot","dot","dog","lot","log","cog"]`. Самая короткая цепочка `hit → hot → dot → dog → cog` — 5 слов, ответ `5`.

## Наивный подход

Явно построить граф: сравнить каждую пару слов словаря и соединить ребром отличающиеся одной буквой, а потом искать путь:

```ts naive
for (let i = 0; i < words.length; i++)
  for (let j = i + 1; j < words.length; j++)
    if (diffByOne(words[i], words[j])) addEdge(i, j);
```

Построение — `O(N² · L)`: при `N = 5000` и `L = 10` это 125 миллионов сравнений символов, ещё до поиска пути. Если же вместо BFS искать путь перебором (DFS), то число простых путей вообще экспоненциально.

Лишняя работа — сравнение **всех пар** слов, хотя у каждого слова соседей обычно единицы.

## Ключевое наблюдение

Две идеи:

1. Это **кратчайший путь в невзвешенном графе** (каждая замена буквы — одно ребро) → **BFS**. Ответ — число рёбер + 1.
2. Соседей не нужно искать среди всех слов — их можно **сгенерировать**: для каждой позиции подставить 26 букв и проверить кандидата по `Set`. Это `26 · L` кандидатов на слово вместо `N` сравнений, и при `N = 5000` выигрыш огромный.

## Техники

### Поиск в ширину (BFS) по слоям

**Что это.** BFS обходит граф «волнами»: сначала старт, потом все вершины на расстоянии 1, потом 2 и т. д. Вершина впервые встречается на минимальном расстоянии. Подробнее про обход в ширину — во вкладке «Теория».

**Типичный шаблон.** Держим текущий слой и счётчик; из слоя строим следующий из непосещённых соседей; нашли цель — счётчик и есть ответ.

**Как применяется здесь.** Счётчик — `length`, число слов в цепочке. Слой — слова, до которых цепочка имеет длину `length`.

### Генерация соседей вместо явного графа

Когда вершины — строки, а ребро — «отличие в одном символе», соседей перебирают по схеме «позиция × буква алфавита» и фильтруют по `Set`. Выгодно, когда `26 · L` много меньше `N`. Альтернатива — шаблоны с подстановкой (`"h*t"`) и `Map<шаблон, слова>`.

### `Set` непосещённых: удаление вместо `visited`

`unvisited` — и словарь, и пометка посещённых: слово удаляется в момент постановки в очередь. Проверка кандидата одна: `unvisited.has(candidate)`.

## Разбор кода

```ts
function ladderLength(beginWord: string, endWord: string, wordList: string[]): number {
  // Ещё не посещённые слова словаря; удаление из множества = пометка visited
  const unvisited = new Set(wordList);
  if (!unvisited.has(endWord)) return 0;
```

Множество словаря для проверки за `O(1)`. Если `endWord` нет в словаре, последний шаг цепочки невозможен — сразу `0`.

```ts
  const a = 'a'.charCodeAt(0);
  let layer = [beginWord];
  let length = 1; // число слов в последовательности, включая beginWord
```

`a` — код буквы `'a'`, чтобы получать буквы `a…z` как `String.fromCharCode(a + c)`. Стартовый слой — одно слово, и цепочка из него одного имеет длину `1`.

```ts
  while (layer.length) {
    length++;
    const next: string[] = [];
```

Каждая итерация — переход к следующему слою. `length++` в начале: всё, что сгенерируем из текущего слоя, будет `length`-м словом цепочки.

```ts
    for (const word of layer) {
      // Перебираем все слова, отличающиеся от word одной буквой
      for (let i = 0; i < word.length; i++) {
        const prefix = word.slice(0, i);
        const suffix = word.slice(i + 1);
```

Для каждой позиции `i` один раз вычисляем префикс и суффикс — они не зависят от подставляемой буквы, так что выносим их из внутреннего цикла.

```ts
        for (let c = 0; c < 26; c++) {
          const candidate = prefix + String.fromCharCode(a + c) + suffix;
          if (!unvisited.has(candidate)) continue; // нет в словаре или уже были
```

Перебираем все 26 букв. Кандидат с той же буквой — это само `word`, отдельно его не исключаем. Любое слово из слоя уже удалено из `unvisited`, так что `has` его отсеет. Единственное исключение — `beginWord`, который **есть** в словаре: он не удалялся, поэтому на первом шаге сгенерирует сам себя и попадёт в следующий слой. Это лишняя вершина, но не ошибка: у неё те же соседи, что у `beginWord`, и они к тому моменту уже помечены — короче ответ не станет.

```ts
          if (candidate === endWord) return length;
          unvisited.delete(candidate);
          next.push(candidate);
        }
      }
    }
    layer = next;
  }
```

Нашли `endWord` — возвращаем длину сразу, при генерации. Иначе помечаем слово посещённым (удаляем) и ставим в следующий слой. После обработки слоя переключаемся на `next`.

```ts
  // endWord недостижимо
  return 0;
}
```

Слои кончились, `endWord` не встретилось — цепочки нет, по условию возвращаем `0`.

## Трассировка

`beginWord = "hit"`, `endWord = "cog"`, `wordList = ["hot","dot","dog","lot","log","cog"]`.

`unvisited = {hot, dot, dog, lot, log, cog}`.

1. `length = 2`, слой `[hit]`.
   - `i = 0` (`?it`): ни одного слова из словаря.
   - `i = 1` (`h?t`): `hot` — есть, не цель → удаляем, `next = [hot]`.
   - `i = 2` (`hi?`): ничего.
2. `length = 3`, слой `[hot]`.
   - `i = 0` (`?ot`): `dot` → `next = [dot]`; `lot` → `next = [dot, lot]`. `hot` уже удалён.
   - `i = 1` (`h?t`): `hit` нет в словаре.
   - `i = 2` (`ho?`): ничего.
3. `length = 4`, слой `[dot, lot]`.
   - `dot`: `?ot` — `hot`, `lot` уже удалены; `d?t` — ничего; `do?` — `dog` → `next = [dog]`.
   - `lot`: `?ot` — ничего нового; `l?t` — ничего; `lo?` — `log` → `next = [dog, log]`.
4. `length = 5`, слой `[dog, log]`.
   - `dog`, `i = 0` (`?og`): буква `c` → `cog` — есть и равно `endWord` → возвращаем `5`.

Ответ `5`: `hit → hot → dot → dog → cog`.

## Почему это работает

- **Слои = расстояния.** Инвариант: на итерации со значением `length` слой содержит слова, для которых кратчайшая цепочка от `beginWord` состоит ровно из `length - 1` слов. Сгенерированные из них непосещённые слова — из `length` слов. Слово, достижимое короче, уже удалено из `unvisited` и в слой не попадёт.
- **Минимальность.** `endWord` возвращается при первом появлении, а BFS открывает вершины в порядке неубывания расстояния.
- **Полнота генерации.** Любой сосед слова отличается в одной позиции и буквой из `a…z` — перебор `позиция × буква` находит его, `Set` проверяет, что он в словаре.
- **Завершение.** Каждое слово словаря удаляется из `unvisited` не более одного раза, поэтому суммарно в слоях не больше `N` слов.

## Пограничные случаи

- **`endWord` нет в словаре** → `0` сразу.
- **`beginWord` в словаре** — допустимо, см. разбор: лишняя вершина в первом слое, ответ не меняется.
- **`beginWord` и `endWord` отличаются одной буквой** → ответ `2` уже на первой итерации.
- **Цели не достичь** (словарь распадается на компоненты) → слои иссякают, `0`.
- **Слова длины 1** (`"a" → "c"`, словарь `["a","b","c"]`) — работают так же, ответ `2`.

## Сложность

- **Время `O(N · L² · 26)`**: в слои попадает не больше `N + 1` слов; для каждого — `L · 26` кандидатов; построение строки и её хеширование в `Set` — `O(L)`.
- **Память `O(N · L)`**: множество словаря и слои (каждое слово — строка длины `L`).

При `N = 5000`, `L = 10` это около 13 миллионов символьных операций — заметно лучше, чем `O(N² · L)` попарных сравнений.

## Типичные ошибки

1. **Возвращать число рёбер (преобразований), а не слов** — ответ на `1` меньше нужного.
2. **Помечать слово посещённым при извлечении, а не при добавлении** — одно слово попадает в слой многократно, на больших словарях это превышение лимита времени.
3. **Сравнивать каждое слово слоя со всем словарём** — `O(N² · L)`, медленно при `N = 5000`.
4. **DFS вместо BFS** — первая найденная цепочка не обязана быть кратчайшей.
5. **Забыть проверку `endWord` в словаре** — ответ всё равно `0`, но после полного обхода; хуже, если код «пропускает» цель без проверки по словарю.

## Как узнать такую задачу

- Слово/строка/состояние меняется **по одному элементу за шаг**, промежуточные состояния ограничены словарём, нужно **минимальное** число шагов → BFS по неявному графу.
- Большой словарь, но маленький алфавит и короткие слова → генерировать соседей, а не сравнивать пары.
- Оптимизация для крупных входов — **двунаправленный BFS** (расширять меньший фронт с обеих сторон).
- Родственные задачи: Minimum Genetic Mutation (то же на алфавите `ACGT`), Word Ladder II (восстановить все кратчайшие пути), Open the Lock.
