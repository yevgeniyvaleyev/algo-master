## Задача простыми словами

Есть `numCourses` курсов и зависимости `prerequisites`: пара `[a, b]` значит «перед `a` нужно пройти `b`». Нужно вернуть **порядок** прохождения всех курсов, в котором каждая зависимость соблюдена. Подходит любой такой порядок. Если пройти всё нельзя (есть цикл) — вернуть пустой массив.

Пример: `numCourses = 4`, `[[1,0],[2,0],[3,1],[3,2]]`. Курс `0` — первым, `1` и `2` — после него, `3` — после `1` и `2`. Ответы `[0,1,2,3]` и `[0,2,1,3]` оба верны.

## Наивный подход

«Симуляция по проходам»: многократно перебирать все курсы и добавлять в ответ те, у которых все зависимости уже в ответе:

```ts naive
const order: number[] = [];
const done = new Set<number>();
let progress = true;
while (progress) {
  progress = false;
  for (let c = 0; c < numCourses; c++) {
    if (!done.has(c) && зависимости c все в done) {
      done.add(c); order.push(c); progress = true;
    }
  }
}
return order.length === numCourses ? order : [];
```

Порядок получается верный, но каждый проход заново перепроверяет **все** курсы и все их зависимости. Проходов в худшем случае `V`, итого `O(V · (V + E))`. Лишняя работа: у большинства курсов между проходами ничего не меняется.

## Ключевое наблюдение

Для каждого курса достаточно хранить **счётчик невыполненных зависимостей** — полустепень захода `indegree`. Когда курс пройден, меняются счётчики только у **его прямых потомков** — на единицу. Курс становится доступным ровно в момент, когда его счётчик обнулился.

Значит, достаточно держать очередь «доступных» курсов: доставать курс, дописывать в ответ, уменьшать счётчики потомков и добавлять обнулившиеся в очередь. Каждое ребро обрабатывается один раз — `O(V + E)`.

## Техники

### Топологическая сортировка: алгоритм Кана

**Что это.** Топологический порядок — расстановка вершин ориентированного графа так, что каждое ребро ведёт слева направо. Алгоритм Кана строит его «снаружи внутрь»: всегда берёт вершину без входящих рёбер и мысленно удаляет её из графа. Подробнее — во вкладке «Теория».

**Типичный шаблон:**

```ts naive
посчитать indegree всех вершин;
очередь ← все вершины с indegree 0;
пока очередь не пуста:
  v ← из очереди; добавить v в ответ;
  для каждого ребра v → u: indegree[u]--; если 0 — u в очередь;
если в ответе все вершины — порядок найден, иначе есть цикл.
```

**Как применяется здесь.** Вершины — курсы, ребро `b → a` — «`b` перед `a`». Выход алгоритма — ответ задачи, а неполный выход — признак цикла.

### Очередь на массиве с указателем головы

`Array.prototype.shift()` в JavaScript сдвигает весь массив — `O(n)` на операцию. Вместо него читаем элементы по индексу `head`, а сам массив только растёт. Бонус: в конце массив содержит **все** извлечённые вершины в порядке извлечения — это и есть ответ, отдельный массив не нужен.

## Разбор кода

```ts
function findOrder(numCourses: number, prerequisites: number[][]): number[] {
  // Ребро b -> a; indegree[a] — сколько курсов нужно пройти до a
  const graph: number[][] = Array.from({ length: numCourses }, () => []);
  const indegree = new Array<number>(numCourses).fill(0);
  for (const [a, b] of prerequisites) {
    graph[b].push(a);
    indegree[a]++;
  }
```

Строим список смежности и одновременно считаем полустепени захода. Для пары `[a, b]`: ребро `b → a` и у `a` на одну зависимость больше. Здесь направление **важно**: ответ должен начинаться с `b`, поэтому рёбра идут от зависимости к зависимому курсу.

```ts
  // Начинаем с курсов без зависимостей
  const queue: number[] = [];
  for (let c = 0; c < numCourses; c++) {
    if (indegree[c] === 0) queue.push(c);
  }
```

Курсы с `indegree === 0` можно проходить сразу — они стартовые. Если таких нет, граф целиком «зациклен» — очередь пуста, и ответ будет `[]`.

```ts
  // queue одновременно и очередь, и ответ: курсы в ней лежат в порядке прохождения.
  // head — указатель на начало очереди (без дорогого shift)
  for (let head = 0; head < queue.length; head++) {
    const course = queue[head];
```

Цикл по очереди. Условие `head < queue.length` перечитывается на каждой итерации, поэтому курсы, добавленные внутри цикла, тоже будут обработаны. `queue[head]` — «извлечение» из очереди без сдвига.

```ts
    for (const next of graph[course]) {
      // Курс course пройден — у next стало на одну зависимость меньше
      indegree[next]--;
      if (indegree[next] === 0) queue.push(next);
    }
  }
```

«Удаляем» курс из графа: каждому зависимому курсу уменьшаем счётчик. Курс попадает в очередь **ровно один раз** — в момент, когда счётчик стал `0`; дальше он уменьшаться не будет, потому что все его входящие рёбра уже сняты.

```ts
  // Если какие-то курсы так и не освободились — они в цикле
  return queue.length === numCourses ? queue : [];
}
```

Если в очередь попали все курсы — она и есть топологический порядок. Если нет — оставшиеся курсы лежат на цикле (или зависят от цикла): их счётчики никогда не обнулятся. Тогда пустой массив.

## Трассировка

`numCourses = 4`, `prerequisites = [[1,0],[2,0],[3,1],[3,2]]`.

```
graph:    0 → [1, 2], 1 → [3], 2 → [3], 3 → []
indegree: [0, 1, 1, 2]
queue:    [0]
```

1. `head = 0`, курс `0`. `next = 1`: `indegree[1] = 0` → в очередь. `next = 2`: `indegree[2] = 0` → в очередь. `queue = [0, 1, 2]`.
2. `head = 1`, курс `1`. `next = 3`: `indegree[3] = 1` — ещё ждёт `2`.
3. `head = 2`, курс `2`. `next = 3`: `indegree[3] = 0` → в очередь. `queue = [0, 1, 2, 3]`.
4. `head = 3`, курс `3`: потомков нет.
5. `head = 4 = queue.length` — выход. `4 === numCourses` → ответ `[0, 1, 2, 3]`.

Пример с циклом: `numCourses = 3`, `prerequisites = [[1,0],[2,1],[1,2]]`.

```
graph:    0 → [1], 1 → [2], 2 → [1]
indegree: [0, 2, 1]
queue:    [0]
```

1. Курс `0`: `indegree[1] = 1` — не ноль (ждёт ещё `2`).
2. Очередь кончилась. `queue = [0]`, длина `1 ≠ 3` → ответ `[]`. Курсы `1` и `2` ждут друг друга.

## Почему это работает

- **Порядок корректен.** Курс `a` попадает в очередь только когда `indegree[a] = 0`, то есть когда **все** курсы `b` с ребром `b → a` уже извлечены и стоят в очереди левее. Значит, каждое ребро идёт слева направо.
- **Если цикла нет — попадут все.** В любом непустом ациклическом графе есть вершина без входящих рёбер. Пока не все вершины извлечены, среди оставшихся (их подграф тоже ацикличен) есть вершина, у которой все входящие рёбра уже сняты, — она в очереди. Алгоритм не остановится раньше времени.
- **Если цикл есть — не попадут вершины цикла.** У первой вершины цикла, которая могла бы попасть в очередь, остаётся входящее ребро от предшественника по циклу, который ещё не извлечён. Счётчик не обнулится — длина ответа меньше `numCourses`.

## Пограничные случаи

- **Нет зависимостей**: все курсы сразу в очереди, ответ `[0, 1, …, n-1]`.
- **Один курс** → `[0]`.
- **Цикл в части графа**: курсы вне цикла в очередь попадут, но длина всё равно меньше `numCourses` → `[]`.
- **Курс, зависящий от курса из цикла**, тоже никогда не освободится — и правильно, его нельзя пройти.
- **Несколько верных порядков**: алгоритм вернёт один из них, задача принимает любой.

## Сложность

- **Время `O(V + E)`**: подсчёт `indegree` — `O(E)`, начальное заполнение очереди — `O(V)`, каждая вершина извлекается один раз, каждое ребро уменьшает счётчик один раз.
- **Память `O(V + E)`**: список смежности, массив `indegree` и очередь (она же ответ).

## Типичные ошибки

1. **Перепутать направление рёбер** (`graph[a].push(b)` и `indegree[b]++`) — получится обратный порядок: зависимые курсы раньше своих зависимостей.
2. **`queue.shift()` в цикле** — работает, но превращает `O(V)` извлечений в `O(V²)` на больших входах.
3. **Возвращать `queue` без проверки длины** — при цикле вернётся неполный порядок вместо `[]`.
4. **Добавлять в очередь при каждом уменьшении счётчика**, а не при обнулении — курсы появляются в ответе раньше своих зависимостей и по нескольку раз.
5. **Путать с DFS-версией**: в DFS вершину добавляют после всех потомков (post-order), и список нужно **развернуть** — у Кана разворот не нужен.

## Как узнать такую задачу

- Нужен **порядок** выполнения задач с зависимостями «X до Y» (курсы, сборка, установка пакетов, вычисление формул в ячейках).
- Нужно вернуть «любой корректный порядок» или пустой ответ, если его нет → топологическая сортировка с проверкой на цикл.
- Нужен порядок «по уровням» или минимальное число семестров → Кан по слоям (Parallel Courses).
- Родственные задачи: Course Schedule (только проверка), Alien Dictionary, Sequence Reconstruction, Minimum Height Trees (снятие листьев — тот же приём).
