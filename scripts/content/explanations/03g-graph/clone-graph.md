## Задача простыми словами

Дана ссылка на узел связного неориентированного графа. У каждого узла есть `val` и массив соседей `neighbors`. Нужно построить **глубокую копию** графа: новые объекты-узлы с теми же значениями и той же структурой рёбер, причём ни одна ссылка в копии не должна указывать на узел оригинала.

Пример: граф-квадрат `1 — 2 — 3 — 4 — 1`.

```
1 --- 2
|     |
4 --- 3
```

Ответ — новый узел `1'`, у которого соседи `2'` и `4'`, у `2'` — соседи `1'` и `3'` и так далее.

## Наивный подход

Первое, что приходит в голову, — рекурсивно копировать «узел и его соседей»:

```ts naive
function copy(node: _Node): _Node {
  const c = new _Node(node.val);
  for (const nb of node.neighbors) c.neighbors.push(copy(nb));
  return c;
}
```

Для дерева это сработало бы. Но граф неориентированный: у `1` сосед `2`, а у `2` сосед `1`. Вызов `copy(1)` вызовет `copy(2)`, тот — снова `copy(1)`, и так до переполнения стека. Даже без циклов (например, «ромб») один и тот же узел скопировался бы несколько раз, и структура копии разошлась бы с оригиналом: у узла, достижимого двумя путями, оказалось бы две разные копии.

Проблема: мы не помним, какие узлы уже скопированы, и не можем найти их копии.

## Ключевое наблюдение

Нужна таблица **«оригинал → копия»**. Она решает обе проблемы сразу:

- это множество посещённых узлов — повторно узел не копируется, и циклы не зацикливают обход;
- это способ получить **ту самую** копию соседа, чтобы связать с ней рёбра.

Ключевой момент — регистрировать копию в таблице **до** обхода соседей. Тогда, вернувшись по циклу в узел, который ещё «в процессе», мы найдём его копию и не начнём копировать заново.

## Техники

### Обход графа в глубину (DFS)

**Что это.** DFS идёт из узла в непосещённого соседа, оттуда дальше, а упёршись — возвращается. Он посещает все узлы, достижимые из стартового, ровно по одному разу при условии, что посещённые помечаются.

**Типичный шаблон.** `dfs(v)`: если `v` посещён — выход; пометить; для каждого соседа — `dfs(сосед)`. Подробнее про обход в глубину — во вкладке «Теория».

**Как применяется здесь.** `dfs(orig)` возвращает копию узла: «посещён» означает «копия уже есть в `Map`». Поскольку граф связный, обход из переданного узла дойдёт до всех узлов.

### Хеш-таблица «оригинал → копия»

`Map` в JavaScript умеет использовать **объекты** как ключи (по ссылке). Это классический приём глубокого копирования структур с общими ссылками и циклами: так работают, например, `structuredClone` и копирование списка со случайными указателями (Copy List with Random Pointer).

### Регистрация до рекурсии

Общее правило для обходов с циклами: пометка «посещено» ставится **до** рекурсивного спуска. Здесь пометка — это запись `copies.set(orig, copy)`, и она обязана стоять до цикла по соседям.

## Разбор кода

```ts
function cloneGraph(node: _Node | null): _Node | null {
  if (node === null) return null;
```

Пустой граф (ноль узлов) приходит как `null` — тогда и копия `null`.

```ts
  // оригинал -> его копия; заодно служит множеством посещённых узлов
  const copies = new Map<_Node, _Node>();
```

Ключ — ссылка на узел оригинала, значение — ссылка на его копию. Отдельного `Set` для посещённых не нужно.

```ts
  const dfs = (orig: _Node): _Node => {
    // Узел уже скопирован (мы пришли по циклу) — возвращаем готовую копию
    const existing = copies.get(orig);
    if (existing) return existing;
```

Если копия есть — просто возвращаем её. Это и обрыв рекурсии на цикле, и способ связать ребро с уже существующей копией. Проверка `if (existing)` здесь корректна: значение — объект, а объект всегда истинен (в отличие от индекса `0` в Two Sum).

```ts
    // Создаём копию и регистрируем её ДО обхода соседей,
    // иначе на цикле рекурсия будет бесконечной
    const copy = new _Node(orig.val);
    copies.set(orig, copy);
```

Создаём новый узел с тем же `val` и пустым списком соседей (конструктор подставит `[]`). Сразу записываем в `copies`: если кто-то из потомков по циклу вернётся в `orig`, он получит эту копию, даже если её `neighbors` ещё не заполнены.

```ts
    // Соседи копии — копии соседей оригинала
    for (const nb of orig.neighbors) {
      copy.neighbors.push(dfs(nb));
    }
    return copy;
  };
```

Для каждого соседа оригинала получаем его копию (новую или уже существующую) и дописываем в `copy.neighbors`. Порядок соседей сохраняется. Обратите внимание: в копию попадают **только** результаты `dfs`, то есть копии, — ни одной ссылки на оригинал.

```ts
  return dfs(node);
}
```

Запускаем обход с переданного узла и возвращаем его копию — это и есть «вход» в клонированный граф.

## Трассировка

Граф-квадрат, `adjList = [[2,4],[1,3],[2,4],[1,3]]`. Запись `n'` — копия узла `n`.

1. `dfs(1)`: копии нет → создаём `1'`, `copies = {1}`. Соседи `1`: `[2, 4]`.
2. `dfs(2)`: создаём `2'`, `copies = {1, 2}`. Соседи `2`: `[1, 3]`.
3. `dfs(1)` → копия уже есть → `1'`. `2'.neighbors = [1']`.
4. `dfs(3)`: создаём `3'`, `copies = {1, 2, 3}`. Соседи `3`: `[2, 4]`.
5. `dfs(2)` → `2'` уже есть (хотя он ещё «в процессе»). `3'.neighbors = [2']`.
6. `dfs(4)`: создаём `4'`, `copies = {1, 2, 3, 4}`. Соседи `4`: `[1, 3]`.
7. `dfs(1)` → `1'`; `dfs(3)` → `3'`. `4'.neighbors = [1', 3']`, возвращаем `4'`.
8. Назад в `3'`: `3'.neighbors = [2', 4']`, возвращаем `3'`.
9. Назад в `2'`: `2'.neighbors = [1', 3']`, возвращаем `2'`.
10. Назад в `1'`: `1'.neighbors = [2']`. Следующий сосед `4` → `dfs(4)` возвращает готовый `4'`. `1'.neighbors = [2', 4']`.

Итог: `[[2,4],[1,3],[2,4],[1,3]]` — та же структура, все узлы новые. Каждый узел создан ровно один раз, хотя на узлы `1`, `2`, `3` мы приходили повторно.

## Почему это работает

Инвариант: для каждого узла оригинала в `copies` хранится **не больше одной** копии, и она создаётся при первом заходе в узел.

- **Каждый узел скопирован.** Граф связный, DFS из `node` доходит до всех узлов.
- **Каждый узел скопирован ровно один раз.** Перед созданием копии проверяется `copies`, а запись делается сразу после создания.
- **Рёбра верные.** Для каждого `orig` цикл проходит все его рёбра `orig — nb` и добавляет в `copy.neighbors` единственную копию `nb`. Значит, у копии ровно те же соседи (в копиях), в том же порядке.
- **Обход завершается.** Цикл по соседям выполняется только при первом заходе в узел, поэтому каждое ребро просматривается конечное число раз.

## Пограничные случаи

- **Пустой граф** (`node === null`) → `null`.
- **Один узел без соседей** (`[[]]`) → копия `1'` с пустым `neighbors`.
- **Два узла** (`[[2],[1]]`) — самый короткий «цикл» туда-обратно; обрабатывается через `copies`.
- **Глубина рекурсии**: не больше 100 узлов по условию, стек вызовов не переполнится. Для огромных графов лучше BFS с очередью.

## Сложность

- **Время `O(V + E)`**: каждый узел создаётся один раз; каждое неориентированное ребро просматривается дважды (из обоих концов), каждый просмотр — `O(1)` операций с `Map`.
- **Память `O(V)`** дополнительной: `copies` хранит `V` пар, глубина рекурсии до `V`. Саму копию графа (`O(V + E)`) обычно не считают — это ответ.

## Типичные ошибки

1. **Записать копию в `Map` после обхода соседей** → бесконечная рекурсия на первом же цикле.
2. **Положить в `copy.neighbors` оригинальных соседей** (`copy.neighbors = orig.neighbors`) — это поверхностная копия, граф «склеен» с оригиналом.
3. **Создавать новую копию при каждом заходе** без проверки `copies` — у одного узла появляется несколько копий, структура ломается.
4. **Использовать `val` как ключ, не убедившись в уникальности** — здесь `val` уникальны, но в общем случае ключом должна быть ссылка на узел.
5. **Забыть случай `null`** — падение на `node.val`.

## Как узнать такую задачу

- «Глубокая копия», «клон» структуры, где на объект могут ссылаться **несколько** других объектов или есть **циклы**.
- Нужно сопоставить старые объекты с новыми — сигнал к `Map<старый, новый>` плюс обход (DFS или BFS).
- Родственные задачи: Copy List with Random Pointer, Clone Binary Tree With Random Pointer, Clone N-ary Tree; сериализация графа.
