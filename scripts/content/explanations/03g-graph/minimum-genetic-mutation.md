## Задача простыми словами

Ген — строка из 8 букв `A`, `C`, `G`, `T`. Мутация — замена одной буквы. Допустимы только гены из банка `bank` (стартовый ген допустим всегда). Нужно найти **минимальное число мутаций**, превращающих `startGene` в `endGene` так, чтобы каждый промежуточный ген был допустимым, или `-1`.

Пример: `start = "AACCGGTT"`, `end = "AAACGGTA"`, `bank = ["AACCGGTA", "AACCGCTA", "AAACGGTA"]`. Путь `AACCGGTT → AACCGGTA → AAACGGTA` — две мутации, ответ `2`.

## Наивный подход

Перебрать все цепочки мутаций рекурсией с возвратом (DFS), запоминая лучший результат:

```ts naive
function dfs(gene: string, steps: number, used: Set<string>): void {
  if (gene === endGene) { best = Math.min(best, steps); return; }
  for (const g of bank) {
    if (!used.has(g) && отличается ровно одной буквой(gene, g)) {
      used.add(g); dfs(g, steps + 1, used); used.delete(g);
    }
  }
}
```

Это перебор **всех простых путей** в графе — их число растёт факториально от размера банка. Лишняя работа в том, что DFS не знает, нашёл ли он **кратчайший** путь, и вынужден проверить все, снова и снова заходя в одни и те же гены по разным маршрутам.

## Ключевое наблюдение

Гены — вершины графа, рёбра соединяют гены, отличающиеся **одной** буквой. Каждая мутация — одно ребро, все рёбра «стоят» одинаково. Минимальное число мутаций — длина кратчайшего пути в **невзвешенном** графе, а его даёт **BFS**: он обходит гены слоями по числу мутаций и каждый ген посещает один раз.

Соседей при этом не нужно строить заранее: у гена всего `8 · 3 = 24` возможные одиночные мутации, их можно сгенерировать и проверить по `Set` банка.

## Техники

### Поиск в ширину (BFS) по слоям

**Что это.** BFS расширяет «фронт» от старта по одному ребру за шаг. Вершина, впервые встреченная на шаге `k`, находится на расстоянии ровно `k`. Подробнее про обход в ширину — во вкладке «Теория».

**Типичный шаблон.** Текущий слой → для каждой вершины перебрать непосещённых соседей → они образуют следующий слой; счётчик слоёв — расстояние.

**Как применяется здесь.** Слой номер `steps` — гены, достижимые ровно за `steps` мутаций.

### Неявный граф и генерация соседей

Вместо списка смежности перебираем все строки, отличающиеся от текущей одной буквой (позиция × новая буква), и оставляем только допустимые. Это выгодно, когда алфавит и длина малы, а проверка «есть ли вершина» — `O(1)` через `Set`.

### `Set` непосещённых: удаление вместо `visited`

Один `Set` выполняет две роли: «ген допустим» и «ген ещё не посещён». Удаляя ген при добавлении в очередь, мы и помечаем его, и гарантируем, что он не попадёт в очередь второй раз.

## Разбор кода

```ts
function minMutation(startGene: string, endGene: string, bank: string[]): number {
  if (startGene === endGene) return 0;
```

Если ген уже целевой — мутаций не нужно. Без этой проверки BFS не нашёл бы ответ `0`: целевой ген распознаётся только при генерации соседей, то есть минимум на шаге `1`.

```ts
  // Непосещённые допустимые гены; удаление из множества = пометка visited
  const unvisited = new Set(bank);
  if (!unvisited.has(endGene)) return -1; // цель недопустима — не дойдём никогда
```

Строим множество допустимых генов. Если цели нет в банке, последняя мутация никогда не будет разрешена — сразу `-1`. Стартовый ген в множество специально не добавляем: в него возвращаться незачем.

```ts
  const letters = ['A', 'C', 'G', 'T'];
  let layer = [startGene];
  let steps = 0;
```

Алфавит мутаций, стартовый слой из одного гена и счётчик сделанных мутаций.

```ts
  // BFS: слой = все гены, достижимые ровно за steps мутаций
  while (layer.length) {
    steps++;
    const next: string[] = [];
```

`steps++` в начале итерации: все гены, которые мы сейчас сгенерируем из текущего слоя, находятся на расстоянии `steps`.

```ts
    for (const gene of layer) {
      // Перебираем все одиночные мутации: позиция × новая буква
      for (let i = 0; i < gene.length; i++) {
        for (const ch of letters) {
          if (ch === gene[i]) continue;
          const mutated = gene.slice(0, i) + ch + gene.slice(i + 1);
```

Для каждого гена слоя — 8 позиций × 3 другие буквы. Замену на ту же букву пропускаем (`continue`) — это не мутация. Строки в JavaScript неизменяемы, поэтому новую собираем из префикса, новой буквы и суффикса.

```ts
          if (!unvisited.has(mutated)) continue; // недопустим или уже посещён
          if (mutated === endGene) return steps;
          unvisited.delete(mutated);
          next.push(mutated);
        }
      }
    }
    layer = next;
  }
```

Нет в множестве — либо ген недопустим, либо уже посещён; пропускаем. Совпал с целью — возвращаем `steps` сразу, **при генерации**, не дожидаясь следующего слоя. Иначе удаляем из множества (пометка «посещён») и кладём в следующий слой.

```ts
  return -1;
}
```

Слои иссякли, а цель не встретилась — она недостижима из старта.

## Трассировка

`start = "AACCGGTT"`, `end = "AAACGGTA"`, `bank = ["AACCGGTA", "AACCGCTA", "AAACGGTA"]`.

`unvisited = {AACCGGTA, AACCGCTA, AAACGGTA}`, цель там есть.

1. `steps = 1`, слой `[AACCGGTT]`. Из 24 мутаций в множестве только `AACCGGTA` (позиция 7: `T → A`). `AACCGCTA` и `AAACGGTA` отличаются от старта двумя буквами — их сейчас не сгенерировать. Это не цель → удаляем, `next = [AACCGGTA]`.
2. `steps = 2`, слой `[AACCGGTA]`. Позиции `0` и `1` — ничего. Позиция `2` (`C`): буква `A` → `AAACGGTA` — есть в множестве и совпадает с целью → возвращаем `2`.

До мутации `AACCGCTA` (позиция 5) дело не дошло — ответ найден раньше.

Пример «нет пути»: `start = "AAAAAAAA"`, `end = "CCCCCCCC"`, `bank = ["CCCCCCCC"]`. Цель есть в банке, но на шаге `1` ни одна мутация старта не попадает в множество → `next = []`, цикл заканчивается, ответ `-1`.

## Почему это работает

- **Слои = расстояния.** Перед итерацией со значением `steps` (после инкремента) слой содержит гены на расстоянии ровно `steps - 1`; сгенерированные из них непосещённые гены — на расстоянии `steps`. Ген, достижимый быстрее, уже удалён из множества и повторно не попадёт.
- **Ответ минимален.** Цель возвращается при первом появлении, а BFS находит вершины в порядке неубывания расстояния.
- **Генерация полна.** Любое ребро графа — замена одной буквы на одну из трёх других; перебор `позиция × буква` находит все такие строки, а `Set` оставляет только допустимые.
- **Завершение.** Каждый ген банка удаляется из множества один раз, значит, в слои попадает не больше `B` генов.

## Пограничные случаи

- **`startGene === endGene`** → `0` (отдельная проверка).
- **Пустой банк** или цели нет в банке → `-1`.
- **Стартовый ген есть в банке**: не мешает — назад в него не вернёмся, а если и сгенерируем, это будет лишь ещё одна вершина, не влияющая на кратчайший путь до цели.
- **Цель в банке, но изолирована** → слои иссякнут, `-1`.

## Сложность

- **Время `O(B · L · 4 · L)`**, где `B` — размер банка, `L = 8`: в слои попадает не больше `B + 1` генов, для каждого — `L · 4` итераций, каждая строит строку и хеширует её за `O(L)`. При `B ≤ 10` это сотни операций.
- **Память `O(B · L)`**: множество генов и слои, каждый ген — строка длины `L`.

## Типичные ошибки

1. **DFS вместо BFS** — первый найденный путь не обязательно кратчайший.
2. **Не проверять, что `endGene` в банке** — без этой проверки результат всё равно будет `-1`, но с полным обходом; хуже, если по ошибке разрешить недопустимую цель.
3. **Помечать посещённым при извлечении, а не при добавлении** — один ген попадает в слой несколько раз.
4. **Забыть случай `startGene === endGene`** — получим `-1` или `2` вместо `0`.
5. **Генерировать мутацию «в ту же букву»** без `continue` — ген получает себя же в соседи (безвредно здесь, но лишняя работа и источник ошибок).

## Как узнать такую задачу

- Строка/состояние меняется **по одному символу за шаг**, промежуточные состояния ограничены словарём, и нужно **минимальное** число шагов.
- Граф не дан явно, но соседей легко сгенерировать (мало позиций × маленький алфавит) → BFS по неявному графу.
- Родственные задачи: Word Ladder (то же самое, алфавит 26 букв), Open the Lock (поворот одного колёсика), Sliding Puzzle.
