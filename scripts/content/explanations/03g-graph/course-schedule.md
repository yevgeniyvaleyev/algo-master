## Задача простыми словами

Есть `numCourses` курсов с номерами `0 … numCourses - 1` и список зависимостей `prerequisites`: пара `[a, b]` значит «перед курсом `a` нужно пройти курс `b`». Нужно ответить, можно ли пройти **все** курсы.

Пример: `numCourses = 2`, `[[1, 0]]` — сначала `0`, потом `1`, ответ `true`. А `[[1, 0], [0, 1]]` — курсы ждут друг друга, ответ `false`.

## Наивный подход

Можно «симулировать семестры»: на каждом шаге искать курс, у которого все зависимости уже пройдены, и отмечать его пройденным; если за проход ничего нового не нашли — остановиться:

```ts naive
const done = new Set<number>();
let progress = true;
while (progress) {
  progress = false;
  for (let c = 0; c < numCourses; c++) {
    if (!done.has(c) && все зависимости c в done) { done.add(c); progress = true; }
  }
}
return done.size === numCourses;
```

Это работает, но каждый проход перебирает все курсы и все их зависимости — `O(V + E)` на проход, а проходов может быть `V` (цепочка `0 → 1 → … → V-1`, перечисленная в неудачном порядке). Итого `O(V · (V + E))`. Лишняя работа — мы снова и снова перепроверяем курсы, зависимости которых не изменились.

## Ключевое наблюдение

Нарисуем ориентированный граф: ребро `b → a` для каждой пары `[a, b]` («`b` перед `a`»). Тогда:

- если в графе есть **цикл** `x → y → … → x`, курсы цикла ждут друг друга бесконечно — пройти всё нельзя;
- если цикла нет, существует **топологический порядок**, и все курсы проходятся по нему.

Значит, задача — **найти цикл в ориентированном графе**. Это делается одним DFS за `O(V + E)`, если различать три состояния вершины.

## Техники

### Топологическая сортировка и ациклические графы

**Что это.** Топологический порядок — расстановка вершин ориентированного графа в ряд так, что каждое ребро идёт слева направо. Он существует **тогда и только тогда**, когда в графе нет циклов (граф — DAG). Подробнее — во вкладке «Теория».

**Когда применять.** Задачи про зависимости, порядок сборки, расписание: «X нужно сделать до Y».

**Как применяется здесь.** Сам порядок не нужен — нужно только проверить, что он существует, то есть что циклов нет.

### Поиск цикла DFS с тремя цветами

**Что это.** Каждой вершине присваиваем состояние:

- `0` (белый) — ещё не посещали;
- `1` (серый) — вершина в **текущем** пути рекурсии, её потомки ещё обрабатываются;
- `2` (чёрный) — вершина и всё достижимое из неё проверено, циклов нет.

Если DFS по ребру приходит в **серую** вершину — это обратное ребро, найден цикл. Чёрную вершину повторно не обходим — это делает алгоритм линейным.

**Почему не хватает двух состояний.** В ориентированном графе повторный заход в вершину не всегда цикл. «Ромб» `0 → 1 → 3`, `0 → 2 → 3`: вершину `3` посетим дважды, но цикла нет. Флаг `visited` не отличит такой случай от настоящего цикла; серый/чёрный — отличает.

## Разбор кода

```ts
function canFinish(numCourses: number, prerequisites: number[][]): boolean {
  // Ребро b -> a: курс b нужно пройти перед курсом a
  const graph: number[][] = Array.from({ length: numCourses }, () => []);
  for (const [a, b] of prerequisites) graph[b].push(a);
```

Строим список смежности. `Array.from({ length }, () => [])` создаёт **отдельный** пустой массив для каждой вершины (в отличие от `new Array(n).fill([])`, где все ячейки ссылались бы на один массив). Для пары `[a, b]` добавляем ребро `b → a`.

Направление на самом деле не критично для **проверки** цикла: цикл есть в графе тогда и только тогда, когда он есть в графе с развёрнутыми рёбрами. Но «`b` перед `a`» читается естественно и пригодится, если понадобится сам порядок.

```ts
  // 0 — не посещён, 1 — в текущем пути DFS, 2 — полностью обработан
  const state = new Array<number>(numCourses).fill(0);
```

Все вершины изначально белые.

```ts
  // Возвращает true, если из course нельзя попасть в цикл
  const dfs = (course: number): boolean => {
    if (state[course] === 1) return false; // вернулись в вершину текущего пути — цикл
    if (state[course] === 2) return true; // уже проверена ранее, циклов через неё нет
```

Два выхода в начале — суть алгоритма. Серая вершина — мы пришли в неё из её же потомка, значит, есть цикл. Чёрная — уже доказано, что из неё цикл недостижим; повторная проверка не нужна.

```ts
    state[course] = 1;
    for (const next of graph[course]) {
      if (!dfs(next)) return false;
    }
    state[course] = 2; // все потомки проверены — выходим из пути
    return true;
  };
```

Входим в вершину — красим в серый. Рекурсивно проверяем каждого потомка; как только где-то найден цикл — сразу пробрасываем `false` наверх, дальше искать незачем. Если все потомки чистые — вершина чёрная: она покидает текущий путь, и в будущем заход в неё будет мгновенным.

```ts
  // Граф может быть несвязным — запускаем DFS из каждой вершины
  for (let c = 0; c < numCourses; c++) {
    if (!dfs(c)) return false;
  }
  return true;
}
```

Цикл может быть в части графа, недостижимой из курса `0`, поэтому запускаем DFS из каждой вершины. Для уже чёрных вершин вызов завершается сразу — это не добавляет лишней работы. Если ни один запуск не нашёл цикл — `true`.

## Трассировка

Пример «ромб»: `numCourses = 4`, `prerequisites = [[1,0],[2,0],[3,1],[3,2]]`.

```
graph: 0 → [1, 2], 1 → [3], 2 → [3], 3 → []
```

1. `dfs(0)`: `state[0] = 1`. Потомок `1`.
2. `dfs(1)`: `state[1] = 1`. Потомок `3`.
3. `dfs(3)`: `state[3] = 1`, потомков нет, `state[3] = 2`, `true`.
4. Назад в `1`: `state[1] = 2`, `true`. Назад в `0`, следующий потомок `2`.
5. `dfs(2)`: `state[2] = 1`. Потомок `3` — **чёрный** → сразу `true`. `state[2] = 2`.
6. `state[0] = 2`. Внешний цикл: `dfs(1)`, `dfs(2)`, `dfs(3)` — все чёрные, мгновенно `true`.

Ответ `true`. Вершину `3` встретили дважды, но во второй раз она чёрная — цикла нет.

Пример с циклом: `numCourses = 3`, `prerequisites = [[1,0],[2,1],[0,2]]`.

```
graph: 0 → [1], 1 → [2], 2 → [0]
```

1. `dfs(0)`: `state[0] = 1` → `dfs(1)`: `state[1] = 1` → `dfs(2)`: `state[2] = 1` → `dfs(0)`.
2. `state[0] === 1` — серая, вернулись в текущий путь → `false`.
3. `false` пробрасывается через `2`, `1`, `0` и внешний цикл. Ответ `false`.

## Почему это работает

- **Если найдена серая вершина — цикл есть.** Серые вершины в каждый момент образуют путь рекурсии `v₀ → v₁ → … → vₖ`. Ребро из `vₖ` в серую `vᵢ` замыкает этот путь в цикл `vᵢ → … → vₖ → vᵢ`.
- **Если цикл есть — он будет найден.** Пусть `u` — первая вершина цикла, в которую зашёл DFS. В этот момент остальные вершины цикла белые, и все они достижимы из `u`, поэтому будут посещены, пока `u` серая. Предшественник `u` по циклу рано или поздно попытается пройти по ребру в `u` — и застанет её серой.
- **Чёрная вершина безопасна.** Её покрасили в чёрный, только когда все пути из неё проверены и цикла не нашли. Новых рёбер не появляется, так что вывод остаётся верным.

## Пограничные случаи

- **Нет зависимостей**: все вершины проверяются мгновенно, ответ `true`.
- **Цикл из двух курсов** (`[[1,0],[0,1]]`) — обычный цикл длины 2.
- **Самозависимость** `[a, a]` (теоретически): ребро `a → a`, вход в серую `a` → `false`.
- **Несвязный граф**: цикл в «дальней» компоненте найдёт внешний цикл по всем вершинам.
- **Глубокая цепочка** из 2000 курсов: глубина рекурсии до 2000 — для JavaScript безопасно. Для гораздо больших графов лучше алгоритм Кана без рекурсии.

## Сложность

- **Время `O(V + E)`**: каждая вершина красится в серый и чёрный ровно один раз, её список рёбер просматривается один раз (при последующих заходах вершина уже чёрная и выход мгновенный).
- **Память `O(V + E)`**: список смежности `O(V + E)`, массив `state` `O(V)`, стек рекурсии до `O(V)`.

## Типичные ошибки

1. **Один флаг `visited` вместо трёх состояний** — «ромб» ложно считается циклом (или, если не возвращать `false`, циклы не находятся).
2. **Забыть покрасить вершину в чёрный** (`state = 2`) — повторный заход в неё из другой ветки будет выглядеть как цикл.
3. **Сбрасывать вершину в `0` вместо `2`** при выходе — корректно, но экспоненциально медленно на графах с большим числом путей.
4. **Запускать DFS только из вершины `0`** — цикл в другой компоненте пропускается.
5. **`new Array(n).fill([])`** — все вершины делят один массив соседей.

## Как узнать такую задачу

- Есть **зависимости** «X до Y» (курсы, задачи сборки, порядок установки пакетов) и вопрос «можно ли всё выполнить» → проверка ориентированного графа на цикл.
- Нужен и сам порядок → топологическая сортировка (Course Schedule II).
- Родственные задачи: Course Schedule II, Find Eventual Safe States (тот же DFS с тремя цветами), Alien Dictionary, Parallel Courses, Minimum Height Trees.
