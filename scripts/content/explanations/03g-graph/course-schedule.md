## Задача простыми словами

Есть `numCourses` курсов с номерами `0 … numCourses - 1` и список зависимостей `prerequisites`: пара `[a, b]` значит «перед курсом `a` нужно пройти курс `b`». Нужно ответить, можно ли пройти **все** курсы.

Пример: `numCourses = 2`, `[[1, 0]]` — сначала `0`, потом `1`, ответ `true`. А `[[1, 0], [0, 1]]` — курсы ждут друг друга, ответ `false`.

## Наивный подход

Можно «симулировать семестры»: на каждом шаге искать курс, у которого все зависимости уже пройдены, и отмечать его пройденным; если за проход ничего нового не нашли — остановиться:

```ts naive
const done = new Set<number>();
let progress = true;
while (progress) {
  progress = false;
  for (let c = 0; c < numCourses; c++) {
    if (!done.has(c) && все зависимости c в done) { done.add(c); progress = true; }
  }
}
return done.size === numCourses;
```

Это работает, но каждый проход перебирает все курсы и все их зависимости — `O(V + E)` на проход, а проходов может быть `V` (цепочка `0 → 1 → … → V-1`, перечисленная в неудачном порядке). Итого `O(V · (V + E))`. Лишняя работа — мы снова и снова перепроверяем курсы, зависимости которых не изменились.

## Ключевое наблюдение

Нарисуем ориентированный граф: ребро `b → a` для каждой пары `[a, b]` («`b` перед `a`»). Тогда:

- если в графе есть **цикл** `x → y → … → x`, курсы цикла ждут друг друга бесконечно — пройти всё нельзя;
- если цикла нет, существует **топологический порядок**, и все курсы проходятся по нему.

Наивная симуляция «семестров» правильна по смыслу, но медленна, потому что каждый раз заново проверяет все зависимости. Достаточно для каждого курса хранить **счётчик невыполненных зависимостей** `indegree`. Когда курс пройден, мы уменьшаем счётчик только у его прямых последователей — и сразу видим, кто освободился. Освободившиеся курсы складываем в очередь. Это алгоритм Кана: если в итоге обработаны все `numCourses` курсов — цикла нет.

## Техники

### Топологическая сортировка и ациклические графы

**Что это.** Топологический порядок — расстановка вершин ориентированного графа в ряд так, что каждое ребро идёт слева направо. Он существует **тогда и только тогда**, когда в графе нет циклов (граф — DAG). Подробнее — во вкладке «Теория».

**Когда применять.** Задачи про зависимости, порядок сборки, расписание: «X нужно сделать до Y».

**Как применяется здесь.** Сам порядок не нужен — нужно только проверить, что он существует, то есть что алгоритм смог обработать все вершины.

### Алгоритм Кана (BFS по полустепеням захода)

**Что это.** `indegree[v]` — число рёбер, входящих в `v` (сколько зависимостей у курса). Вершины с `indegree = 0` можно брать сразу. Взяв вершину, «удаляем» её исходящие рёбра: уменьшаем `indegree` у соседей. Обнулившиеся соседи становятся доступными и попадают в очередь.

**Шаблон:**

```ts naive
const queue = вершины с indegree 0;
while (queue не пуста) {
  const v = queue.shift();
  for (const u of graph[v]) if (--indegree[u] === 0) queue.push(u);
}
```

**Как применяется здесь.** Считаем, сколько вершин прошло через очередь (`processed`). Вершины цикла никогда не обнулятся, поэтому `processed < numCourses` ⇔ есть цикл.

### Очередь на массиве с указателем `head`

`Array.prototype.shift` в JavaScript сдвигает весь массив — `O(n)` на операцию. Вместо этого читаем элементы по индексу `head` и только дописываем в конец через `push`. Очередь никогда не уменьшается физически, но каждый элемент читается ровно один раз.

## Разбор кода

```ts
function canFinish(numCourses: number, prerequisites: number[][]): boolean {
  // Ребро b -> a; indegree[a] — сколько курсов нужно пройти до a
  const graph: number[][] = Array.from({ length: numCourses }, () => []);
  const indegree = new Array<number>(numCourses).fill(0);
  for (const [a, b] of prerequisites) {
    graph[b].push(a);
    indegree[a]++;
  }
```

Строим список смежности и одновременно считаем зависимости. `Array.from({ length }, () => [])` создаёт **отдельный** пустой массив для каждой вершины (в отличие от `new Array(n).fill([])`, где все ячейки ссылались бы на один массив). Пара `[a, b]` даёт ребро `b → a` и ещё одну зависимость у `a`.

```ts
  // Начинаем с курсов без зависимостей
  const queue: number[] = [];
  for (let c = 0; c < numCourses; c++) {
    if (indegree[c] === 0) queue.push(c);
  }
```

Стартовая «волна» — все курсы, которые можно проходить прямо сейчас. Если таких нет вовсе, очередь пуста, `processed` останется `0` — и при `numCourses ≥ 1` ответ `false` (в графе без истоков обязательно есть цикл).

```ts
  // head — указатель на начало очереди (без дорогого shift)
  let processed = 0;
  for (let head = 0; head < queue.length; head++) {
    const course = queue[head];
    processed++;
```

Цикл идёт, пока указатель не догнал конец очереди. Условие `head < queue.length` перепроверяется на каждой итерации, поэтому курсы, дописанные во время обхода, тоже будут обработаны. Каждый извлечённый курс считается пройденным.

```ts
    for (const next of graph[course]) {
      // Курс course пройден — у next стало на одну зависимость меньше
      indegree[next]--;
      if (indegree[next] === 0) queue.push(next);
    }
  }
```

«Снимаем» рёбра курса. Ровно в момент, когда у `next` не осталось зависимостей, он попадает в очередь — один раз, потому что счётчик проходит через `0` только однажды.

```ts
  // Если какие-то курсы так и не освободились — они в цикле
  return processed === numCourses;
}
```

Все курсы прошли через очередь — порядок существует. Иначе оставшиеся курсы застряли с `indegree > 0`.

## Трассировка

Пример «ромб»: `numCourses = 4`, `prerequisites = [[1,0],[2,0],[3,1],[3,2]]`.

```
graph:    0 → [1, 2], 1 → [3], 2 → [3], 3 → []
indegree: [0, 1, 1, 2]
```

| head | course | действия                         | indegree     | queue        | processed |
| ---- | ------ | -------------------------------- | ------------ | ------------ | --------- |
| —    | —      | старт: истоки                    | [0, 1, 1, 2] | [0]          | 0         |
| 0    | 0      | `1`: 1→0 (push), `2`: 1→0 (push) | [0, 0, 0, 2] | [0, 1, 2]    | 1         |
| 1    | 1      | `3`: 2→1                         | [0, 0, 0, 1] | [0, 1, 2]    | 2         |
| 2    | 2      | `3`: 1→0 (push)                  | [0, 0, 0, 0] | [0, 1, 2, 3] | 3         |
| 3    | 3      | соседей нет                      | [0, 0, 0, 0] | [0, 1, 2, 3] | 4         |

`processed = 4 = numCourses` → `true`. Курс `3` попал в очередь только после обоих своих предшественников.

Пример с циклом: `numCourses = 3`, `prerequisites = [[1,0],[2,1],[0,2]]`.

```
graph:    0 → [1], 1 → [2], 2 → [0]
indegree: [1, 1, 1]
```

Ни у одного курса `indegree` не равен `0` — очередь пуста, цикл обработки не выполняется ни разу. `processed = 0 ≠ 3` → `false`.

## Почему это работает

- **Корректность порядка.** Курс попадает в очередь только когда все его зависимости уже обработаны (`indegree` стал `0`). Значит, порядок, в котором курсы проходят через очередь, — топологический.
- **Если цикла нет, обработаются все.** В любом непустом DAG есть вершина без входящих рёбер. Пока есть необработанные вершины, среди них (в подграфе необработанных) найдётся такая — её счётчик уже обнулился, и она в очереди. Значит, алгоритм не остановится раньше времени.
- **Если цикл есть, обработаются не все.** У первой вершины цикла, которая могла бы попасть в очередь, есть зависимость — её предшественник по циклу, ещё не обработанный. Противоречие: ни одна вершина цикла не обнулится, `processed < numCourses`.

## Пограничные случаи

- **Нет зависимостей** (`[]`): все курсы сразу в очереди, `processed = numCourses`, ответ `true`.
- **Цикл из двух курсов** (`[[1,0],[0,1]]`): оба с `indegree = 1`, очередь пуста — `false`.
- **Самозависимость** `[a, a]`: ребро `a → a` даёт `indegree[a] = 1`, который никогда не обнулится — `false`.
- **Несвязный граф**: курсы без связей — истоки и сразу в очереди; цикл в любой компоненте оставит её вершины необработанными.
- **Глубокая цепочка** из 2000 курсов: рекурсии нет, переполнения стека не бывает.

## Сложность

- **Время `O(V + E)`**: построение графа — `O(E)`, поиск истоков — `O(V)`, каждая вершина извлекается из очереди один раз, каждое ребро уменьшает счётчик один раз.
- **Память `O(V + E)`**: список смежности `O(V + E)`, массивы `indegree` и `queue` — `O(V)`.

## Типичные ошибки

1. **Перепутать направление ребра** — `graph[a].push(b)` и `indegree[b]++`. Для проверки цикла это не ломает ответ (цикл при развороте рёбер сохраняется), но в Course Schedule II порядок выйдет перевёрнутым. Лучше сразу привыкнуть к `b → a`.
2. **`queue.shift()` в цикле** — работает, но каждый `shift` — `O(n)`, в худшем случае `O(V²)`.
3. **Сравнивать `queue.length` с `numCourses` до обработки** — длина растёт по ходу, проверять нужно в конце.
4. **Класть курс в очередь при каждом уменьшении** вместо проверки `=== 0` — курсы попадут в очередь несколько раз, счётчик `processed` станет неверным.
5. **`new Array(n).fill([])`** — все вершины делят один массив соседей.

## Как узнать такую задачу

- Есть **зависимости** «X до Y» (курсы, задачи сборки, порядок установки пакетов) и вопрос «можно ли всё выполнить» → проверка ориентированного графа на цикл, алгоритм Кана.
- Нужен и сам порядок → тот же код, но вернуть `queue` (Course Schedule II).
- **Альтернатива на собеседовании:** DFS с тремя цветами — `0` не посещён, `1` в текущем пути, `2` проверен. Заход в «серую» вершину означает цикл:

```ts naive
const dfs = (v: number): boolean => {
  if (state[v] === 1) return false; // цикл
  if (state[v] === 2) return true;
  state[v] = 1;
  for (const u of graph[v]) if (!dfs(u)) return false;
  state[v] = 2;
  return true;
};
```

- Родственные задачи: Course Schedule II, Find Eventual Safe States, Alien Dictionary, Parallel Courses, Minimum Height Trees.
