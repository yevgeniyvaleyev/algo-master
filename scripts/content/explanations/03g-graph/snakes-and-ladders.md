## Задача простыми словами

Дана доска `n × n` для игры «Змеи и лестницы». Клетки пронумерованы от `1` до `n²` «змейкой»: от левого нижнего угла, и в каждой следующей строке направление меняется. За ход бросаем кубик (1–6) и сдвигаемся вперёд; если попали на начало змеи или лестницы (`board[r][c] !== -1`) — обязательно переходим в её конец. Нужно найти **минимальное число бросков**, чтобы дойти до клетки `n²`, или `-1`.

Пример: `board = [[-1,-1],[-1,3]]`. Нумерация:

```
4 3
1 2
```

На клетке `2` лестница в `3`. Из `1` за один бросок можно выбросить `3` и попасть сразу в `4` — ответ `1`.

## Наивный подход

Перебрать все последовательности бросков рекурсией: «из клетки `curr` попробовать все 6 исходов и взять минимум»:

```ts naive
function minMoves(curr: number): number {
  if (curr === target) return 0;
  let best = Infinity;
  for (let step = 1; step <= 6; step++) {
    best = Math.min(best, 1 + minMoves(перейти(curr + step)));
  }
  return best;
}
```

Это экспоненциально (`6^глубина`), а главное — **змеи создают циклы**: из клетки `17` можно спуститься на `13`, оттуда снова дойти до `17`… Рекурсия зациклится. Даже с мемоизацией ДП не работает напрямую: значение клетки зависит от клеток, которые зависят от неё же.

Лишняя работа — одни и те же клетки рассматриваются на огромном количестве путей.

## Ключевое наблюдение

Доска — это **невзвешенный ориентированный граф**: вершины — клетки `1 … n²`, из клетки `curr` есть рёбра в `curr + 1 … curr + 6` (с учётом змей и лестниц). Каждый бросок — одно ребро, у всех рёбер «цена» `1`.

Минимальное число бросков — это **кратчайший путь** в невзвешенном графе. Его находит **BFS**: он обходит клетки слоями — сначала все, достижимые за 0 бросков, потом за 1, за 2 и так далее. Каждая клетка посещается один раз, и циклы не страшны.

## Техники

### Поиск в ширину (BFS) по слоям

**Что это.** BFS начинает со стартовой вершины и расширяет «фронт» по одному ребру за шаг. Вершина впервые попадает во фронт на шаге `k` — значит, кратчайшее расстояние до неё ровно `k`. Подробнее про обход в ширину — во вкладке «Теория».

**Типичный шаблон по слоям:**

```ts naive
layer = [start]; dist = 0;
while (layer не пуст) {
  next = [];
  для каждой v в layer: если v — цель, вернуть dist;
    для каждого непосещённого соседа u: пометить, next.push(u);
  layer = next; dist++;
}
```

**Как применяется здесь.** Слой = клетки, где можно оказаться ровно после `moves` бросков. Соседи клетки — результаты шести исходов кубика.

### Неявный граф

Рёбра не хранятся: соседей вычисляем на лету (`curr + step`, затем змея/лестница). Граф маленький (до 400 клеток), но хранить его незачем.

### Перевод номера клетки в координаты

Самая «грязная» часть задачи — нумерация бустрофедоном снизу вверх. Её стоит вынести в отдельную функцию (`cellValue`) и проверить на паре клеток, прежде чем писать BFS.

## Разбор кода

```ts
function snakesAndLadders(board: number[][]): number {
  const n = board.length;
  const target = n * n;
```

`target` — номер последней клетки, куда нужно дойти.

```ts
  // Номер клетки (1..n²) -> значение board в этой клетке
  const cellValue = (label: number): number => {
    const rowFromBottom = Math.floor((label - 1) / n);
    const row = n - 1 - rowFromBottom;
    let col = (label - 1) % n;
```

Переходим к нумерации с нуля: `label - 1`. Целая часть от деления на `n` — номер строки **снизу** (`rowFromBottom`), а в массиве строки нумеруются сверху, поэтому `row = n - 1 - rowFromBottom`. Остаток — позиция внутри строки, если идти слева направо.

```ts
    // В нечётных (считая снизу с нуля) строках нумерация идёт справа налево
    if (rowFromBottom % 2 === 1) col = n - 1 - col;
    return board[row][col];
  };
```

Нижняя строка (`rowFromBottom = 0`) идёт слева направо, следующая — справа налево, и так далее. Для «обратных» строк отражаем столбец. Функция возвращает значение клетки: `-1` или номер конца змеи/лестницы.

Проверка на доске `6 × 6` из примера 1: клетка `14` → `rowFromBottom = 2`, `row = 3`, `col = 1` (строка прямая) → `board[3][1] = 35` — лестница `14 → 35`, как в пояснении. Клетка `7` → `rowFromBottom = 1`, `col = 0` отражается в `5` — правый край второй снизу строки, всё верно.

```ts
  // BFS по номерам клеток: слой = число сделанных бросков
  const visited = new Array<boolean>(target + 1).fill(false);
  visited[1] = true;
  let layer = [1];
  let moves = 0;
```

`visited` индексируется номерами клеток (`0`-й элемент не используется). Стартуем с клетки `1`, сделано `0` бросков.

```ts
  while (layer.length) {
    const next: number[] = [];
    for (const curr of layer) {
      if (curr === target) return moves;
```

Обрабатываем текущий слой целиком. Если в слое есть финиш — до него ровно `moves` бросков, и меньше быть не может: на предыдущих слоях его не было.

```ts
      // Перебираем все 6 исходов броска
      for (let step = 1; step <= 6 && curr + step <= target; step++) {
        let dest = curr + step;
        const jump = cellValue(dest);
        // Змея или лестница переносит нас сразу (только один раз за ход)
        if (jump !== -1) dest = jump;
```

Шесть исходов, но не дальше `target` — по условию нельзя «перелететь» финиш. Если на клетке `curr + step` есть змея или лестница — переносимся в её конец **один раз**: даже если конец — начало другой лестницы, дальше не идём (поэтому `if`, а не `while`).

```ts
        if (!visited[dest]) {
          visited[dest] = true;
          next.push(dest);
        }
      }
    }
    layer = next;
    moves++;
  }
```

Отмечаем **итоговую** клетку `dest` — ту, где мы реально оказались после перехода. Помечаем при добавлении, чтобы клетка не попала в следующий слой дважды. После обработки слоя переходим к следующему и увеличиваем счётчик бросков.

```ts
  // Последняя клетка недостижима
  return -1;
}
```

Если очередной слой оказался пустым, а финиш так и не встретился — все достижимые клетки исчерпаны, ответ `-1`.

## Трассировка

`board = [[-1,-1],[-1,3]]`, `n = 2`, `target = 4`.

Значения `cellValue`:

```
1: rowFromBottom 0, row 1, col 0       → board[1][0] = -1
2: rowFromBottom 0, row 1, col 1       → board[1][1] = 3  (лестница)
3: rowFromBottom 1, row 0, col 0 → 1   → board[0][1] = -1
4: rowFromBottom 1, row 0, col 1 → 0   → board[0][0] = -1
```

BFS:

1. `layer = [1]`, `moves = 0`. `curr = 1 ≠ 4`.
   - `step = 1`: `dest = 2`, лестница → `dest = 3`. Новая → `next = [3]`.
   - `step = 2`: `dest = 3`, уже посещена.
   - `step = 3`: `dest = 4`, новая → `next = [3, 4]`.
   - `step = 4`: `1 + 4 > 4`, цикл заканчивается.
2. `layer = [3, 4]`, `moves = 1`. `curr = 3`: `step = 1` → `4`, уже посещена. `curr = 4 === target` → возвращаем `1`.

Ответ `1`. Обратите внимание: клетка `2` ни разу не стала «стоянкой» — с неё нас всегда уносит лестница.

## Почему это работает

- **Слои = расстояния.** Инвариант: перед `k`-й итерацией `layer` содержит ровно те клетки, где можно оказаться за `k` бросков и нельзя быстрее. Для `k = 0` это `[1]`. Клетки следующего слоя — непосещённые результаты одного броска из текущего; если бы клетка была достижима быстрее, она уже была бы помечена.
- **Первое появление финиша — минимум.** Финиш возвращается на слое `moves`, а на всех предыдущих слоях его не было.
- **Пометка итоговой клетки корректна.** Состояние игры — только номер клетки, где мы стоим; как мы туда пришли (пешком или по лестнице), на будущее не влияет. Поэтому повторное посещение клетки не может дать более короткий путь.
- **Завершение.** Каждая клетка попадает в слой не больше одного раза, всего клеток `n²`.

## Пограничные случаи

- **Финиш недостижим** (например, шесть клеток подряд — змеи назад): слои иссякают → `-1`.
- **Лестница прямо на финиш**: `dest = target` попадает в слой и вернётся на следующей итерации.
- **Конец лестницы — начало другой**: второй переход не делаем (`if`, а не `while`).
- **Змея назад в уже посещённую клетку**: `visited` отсекает, цикла нет.
- **Близко к финишу**: условие `curr + step <= target` не даёт выйти за доску.

## Сложность

- **Время `O(n²)`**: каждая из `n²` клеток попадает в слой не больше одного раза, для неё — до 6 переходов, `cellValue` — `O(1)`.
- **Память `O(n²)`**: массив `visited` на `n² + 1` элементов и слои (суммарно не больше `n²` клеток).

## Типичные ошибки

1. **Неверный перевод номера в координаты** — забыть, что строки считаются снизу, или отражать столбец не в тех строках.
2. **Применять змеи/лестницы цепочкой** (`while`) — по условию только один переход за ход.
3. **Помечать посещённой клетку `curr + step` вместо `dest`** — тогда клетка после лестницы может быть пропущена или посещена дважды.
4. **DFS или ДП вместо BFS** — змеи создают циклы, а DFS не гарантирует кратчайший путь.
5. **Разрешать «перелёт»** за `n²` или обрезать ход до `n²` — нужно просто не рассматривать такие исходы.

## Как узнать такую задачу

- «Минимальное число ходов/шагов/бросков», каждый ход стоит одинаково → кратчайший путь в невзвешенном графе → BFS.
- Состояние полностью описывается небольшим набором значений (здесь — номер клетки), а переходы между состояниями легко перечислить.
- Родственные задачи: Open the Lock, Jump Game III, Minimum Knight Moves, Word Ladder, Shortest Path in Binary Matrix.
