## Задача простыми словами

Даны уравнения вида `a / b = k` (`equations` и `values`) и запросы `c / d = ?` (`queries`). Для каждого запроса нужно вычислить значение, пользуясь уравнениями, или вернуть `-1`, если его нельзя вывести.

Пример: `a / b = 2`, `b / c = 3`. Тогда `a / c = 2 · 3 = 6`, `b / a = 1 / 2 = 0.5`, `a / a = 1`, а `a / e` и `x / x` — `-1`: переменных `e` и `x` в уравнениях нет.

## Наивный подход

Можно пытаться «выводить» новые уравнения, пока они появляются: из `a / b` и `b / c` получить `a / c`, добавить его к известным, снова перебрать все пары уравнений и так далее до насыщения:

```ts naive
let changed = true;
while (changed) {
  changed = false;
  for (const [x, y] of known)
    for (const [y2, z] of known)
      if (y === y2 && !known.has(x, z)) { known.add(x, z, k1 * k2); changed = true; }
}
```

Это транзитивное замыкание: известных отношений может стать `O(V²)`, а каждый проход перебирает пары отношений — `O(V⁴)` на проход. Лишняя работа в том, что мы вычисляем **все** возможные отношения, хотя спрашивают лишь несколько конкретных.

## Ключевое наблюдение

Уравнения — это **взвешенный граф**. Переменные — вершины, уравнение `a / b = k` даёт ребро `a → b` с весом `k` и обратное ребро `b → a` с весом `1 / k`.

Если есть путь `a → b → c`, то `a / c = (a / b) · (b / c)` — **произведение весов вдоль пути**. Значит, ответ на запрос `c / d` — произведение весов на любом пути от `c` до `d`. Противоречий в данных нет, поэтому все пути дают одно и то же число. Нет пути — ответа нет.

Каждый запрос — один обход графа, только для нужной пары.

## Техники

### Обход графа в глубину (DFS) с накоплением значения

**Что это.** DFS идёт из вершины в непосещённого соседа, пока не найдёт цель или не упрётся в тупик, затем откатывается. Помимо поиска пути, по ходу можно **нести значение** — здесь произведение весов от старта до текущей вершины.

**Типичный шаблон.** `dfs(cur, target, acc)`: если `cur === target` — вернуть `acc`; иначе для каждого соседа `dfs(next, target, f(acc, w))`. Подробнее про обход в глубину — во вкладке «Теория».

**Как применяется здесь.** `acc` — это `product`, а `f(acc, w) = acc · w`. Найденный путь сразу даёт ответ.

### Граф из отношений (список смежности в `Map`)

Вершины — строки, поэтому список смежности хранится в `Map<string, [string, number][]>`, а не в массиве по индексам. Каждое отношение порождает **два** ребра — прямое и обратное.

### Сигнальное значение `-1`

Все веса положительны (`0 < values[i] <= 20`), значит любое произведение тоже положительно. Поэтому `-1` можно безопасно использовать как «пути нет» — с настоящим ответом оно не спутается.

## Разбор кода

```ts
function calcEquation(equations: string[][], values: number[], queries: string[][]): number[] {
  // Взвешенный граф: ребро a -> b с весом k означает a / b = k
  const graph = new Map<string, [string, number][]>();
  const addEdge = (from: string, to: string, w: number): void => {
    if (!graph.has(from)) graph.set(from, []);
    graph.get(from)!.push([to, w]);
  };
```

`graph` — список смежности: для каждой переменной массив пар `[сосед, вес]`. `addEdge` лениво создаёт список для новой вершины и дописывает ребро. `!` после `get` безопасен — строкой выше список гарантированно создан.

```ts
  equations.forEach(([a, b], i) => {
    addEdge(a, b, values[i]); // a / b = k
    addEdge(b, a, 1 / values[i]); // b / a = 1 / k
  });
```

Каждое уравнение превращаем в два ребра. Обратное ребро критично: без него запрос `b / a` был бы неразрешим. Побочный эффект: каждая переменная из уравнений попадает в `graph` и имеет хотя бы одно ребро.

```ts
  // DFS: ищем путь от cur до target, перемножая веса рёбер по пути
  const dfs = (cur: string, target: string, product: number, visited: Set<string>): number => {
    if (cur === target) return product;
    visited.add(cur);
```

`product` — значение `start / cur`, накопленное по пути. Дошли до цели — это и есть ответ `start / target`. Иначе помечаем `cur` посещённой, чтобы не ходить по кругу (граф содержит циклы хотя бы из пар прямое–обратное ребро).

```ts
    for (const [next, w] of graph.get(cur)!) {
      if (visited.has(next)) continue;
      const res = dfs(next, target, product * w, visited);
      if (res !== -1) return res;
    }
    return -1; // из этой вершины цель недостижима
  };
```

Перебираем рёбра. Для непосещённого соседа спускаемся с `product * w`, потому что `start / next = (start / cur) · (cur / next)`. Первый же успешный результат возвращаем наверх — искать другие пути незачем, они дают то же число. Если ни один сосед не привёл к цели — `-1`.

Обратите внимание: `visited` **не** очищается при откате. Это верно: граф по сути неориентированный (рёбра парные), и если из посещённой вершины цель достижима, то DFS найдёт её через эту вершину при первом же заходе. Повторно заходить незачем.

```ts
  return queries.map(([c, d]) => {
    // Неизвестная переменная — ответа нет (даже для x / x)
    if (!graph.has(c) || !graph.has(d)) return -1;
    return dfs(c, d, 1, new Set<string>());
  });
}
```

Для каждого запроса: если хотя бы одной переменной нет в графе — `-1`. Проверка стоит **до** DFS, потому что иначе `x / x` вернул бы `1` (сработало бы `cur === target`), а по условию неизвестная переменная даёт `-1`. Для известных переменных запускаем DFS с `product = 1` и свежим `visited`. Случай `a / a` для известной `a` даёт `1` сразу.

## Трассировка

`equations = [["a","b"],["b","c"]]`, `values = [2, 3]`.

Граф после построения:

```
a: [(b, 2)]
b: [(a, 0.5), (c, 3)]
c: [(b, 0.333…)]
```

Запросы:

1. `a / c`: обе есть. `dfs(a, c, 1)`: `a ≠ c`, `visited = {a}`. Ребро `(b, 2)` → `dfs(b, c, 2)`: `visited = {a, b}`. Ребро `(a, 0.5)` — `a` посещена, пропуск. Ребро `(c, 3)` → `dfs(c, c, 6)` → `6`. Ответ `6`.
2. `b / a`: `dfs(b, a, 1)`: `visited = {b}`, ребро `(a, 0.5)` → `dfs(a, a, 0.5)` → `0.5`.
3. `a / e`: `e` нет в `graph` → `-1`.
4. `a / a`: обе есть, `dfs(a, a, 1)` → сразу `1`.
5. `x / x`: `x` нет в `graph` → `-1`.

Результат: `[6, 0.5, -1, 1, -1]`.

Пример с разными компонентами: уравнения `a / b = 2`, `c / d = 3`, запрос `a / d`. DFS из `a` посетит `a` и `b`, у `b` единственный сосед `a` уже посещён → `-1` на всех уровнях. Ответ `-1`.

## Почему это работает

- **Корректность значения.** Инвариант DFS: `product === start / cur`. Для старта это `1 = start / start`. При переходе по ребру `cur → next` с весом `w = cur / next` получаем `(start / cur) · (cur / next) = start / next`. Значит, в момент `cur === target` возвращается ровно `start / target`.
- **Независимость от пути.** Данные непротиворечивы, поэтому все пути между двумя вершинами дают одно произведение — можно брать первый найденный.
- **Полнота.** Если `c / d` выводимо из уравнений, то `c` и `d` в одной компоненте связности, и DFS из `c` обходит всю компоненту. Если в разных — значение действительно не определено: никакая цепочка уравнений не связывает эти переменные.

## Пограничные случаи

- **Неизвестная переменная**, включая `x / x` → `-1` (проверка до DFS).
- **Известная переменная, деленная на себя** → `1`.
- **Переменные в разных компонентах** → `-1`.
- **Обратный запрос** `b / a` при уравнении `a / b` → обратное ребро `1 / k`.
- **Дробные веса**: результат может отличаться от «красивого» в последних знаках (`1 / 3 · 3`), LeetCode сравнивает с допуском.

## Сложность

- **Время `O(Q · (V + E))`**: на каждый из `Q` запросов — один DFS, который посещает каждую вершину и ребро компоненты не больше раза. Построение графа — `O(E)`. При ограничениях (до 20 уравнений и запросов) это мгновенно.
- **Память `O(V + E)`**: список смежности, `visited` и глубина рекурсии до `V`.

## Типичные ошибки

1. **Не добавлять обратное ребро** `b → a` с весом `1 / k` — половина запросов становится неразрешимой.
2. **Возвращать `1` для `x / x`**, когда `x` неизвестна — по условию нужно `-1`.
3. **Складывать веса вместо умножения** — путь соответствует **произведению** отношений.
4. **Не помечать посещённые** — бесконечная рекурсия на паре `a → b → a`.
5. **Возвращать `-1` вместо того, чтобы продолжить перебор**, если первый сосед не привёл к цели: `if (res !== -1) return res` обязателен, иначе остальные рёбра не проверяются.

## Как узнать такую задачу

- Даны **отношения между парами** объектов (отношения, курсы валют, коэффициенты пересчёта), а спрашивают про **пары, не заданные напрямую**.
- Отношение транзитивно и «перемножается» по цепочке → взвешенный граф, ответ — путь между вершинами.
- Много запросов к статичным отношениям → альтернатива: взвешенный Union-Find (хранит `x / root(x)`). Родственные задачи: конвертация единиц и валют, проверка противоречий в системе уравнений, Satisfiability of Equality Equations.
