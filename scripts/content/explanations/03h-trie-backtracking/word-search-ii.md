## Задача простыми словами

Дана доска букв `board` размером `m × n` и список слов `words`. Нужно вернуть **все слова из списка**, которые можно прочитать на доске: буквы слова идут по соседним клеткам (вверх, вниз, влево, вправо), и одну клетку в одном слове использовать дважды нельзя.

Пример: доска

```
o a a n
e t a e
i h k r
i f l v
```

и `words = ["oath", "pea", "eat", "rain"]`. На доске есть `"oath"` (`o → a → t → h`) и `"eat"` (`e → a → t`), ответ `["eat", "oath"]` (порядок не важен).

## Наивный подход

Есть готовое решение для **одного** слова — Word Search: DFS из каждой клетки с откатом. Можно просто запустить его для каждого слова:

```ts naive
const result: string[] = [];
for (const w of words) {
  if (exist(board, w)) result.push(w);
}
```

Один вызов `exist` стоит до `O(m · n · 3^L)`. Слов до `3 · 10⁴`, значит, суммарно `3 · 10⁴ · 144 · 3^9` — миллиарды шагов.

Где лишняя работа? Слова `"oath"`, `"oat"`, `"oak"` начинаются одинаково, и для каждого мы заново обходим доску и заново находим одни и те же пути `o → a`. Кроме того, каждый поиск отдельного слова ничего не знает о других: путь, который не годится для `"oath"`, мог бы подойти для `"oak"`, но мы его уже бросили.

## Ключевое наблюдение

Перевернём задачу: вместо «для каждого слова обойти доску» сделаем **один** обход доски, который ищет **все слова сразу**. Для этого слова кладём в **префиксное дерево** и при DFS по доске параллельно спускаемся по trie:

- переходим в соседнюю клетку, только если в текущем узле trie есть ребро с её буквой;
- как только текущий путь на доске перестал быть префиксом **хоть какого-то** слова, ветка обрывается;
- попали в узел, где кончается слово, — нашли слово.

Общие префиксы слов проверяются один раз, а тупиковые пути отсекаются сразу после первой «чужой» буквы.

## Техники

### Префиксное дерево (trie) как фильтр путей

**Что это.** Дерево, где каждый узел — префикс, а ребро — буква. Все слова с общим началом идут по одному пути от корня.

**Как применяется здесь.** Trie строится из `words` и служит «картой допустимых продолжений»: узел trie, в котором мы находимся, точно говорит, какие буквы можно взять следующими. Вместо флага `isEnd` в конечном узле хранится **само слово** — тогда не нужно собирать путь в строку, найденное слово сразу кладётся в ответ. Подробнее — во вкладке «Теория».

### Перебор с возвратом (backtracking) на сетке

**Что это.** Рекурсивный DFS, который строит путь по шагам и при возврате **отменяет** свои изменения. На сетке типичный приём — временно пометить клетку как занятую, обойти соседей и вернуть исходное значение.

**Типичный шаблон:**

```ts naive
dfs(клетка):
  если клетка не подходит — return
  пометить клетку
  dfs(каждый сосед)
  снять пометку
```

**Как применяется здесь.** Клетку на время пути заменяем на `'#'`. Такой символ не встречается в словах, поэтому повторно наступить на неё нельзя: у узла trie нет ребра `'#'`. После обхода соседей букву возвращаем — клетка может понадобиться другому пути.

### Обрезка trie (удаление найденных веток)

Когда слово найдено, оно больше не нужно. Если после этого узел остался без детей и без слова, его можно удалить из родителя — в эту ветку больше незачем заходить. Чем больше слов найдено, тем меньше дерево и тем быстрее идёт остальной поиск. На тестах вида «доска из одних `a` и слова `aaaa…`» это решает разницу между таймаутом и проходом.

## Разбор кода

```ts
// Узел trie: в конечном узле храним само слово (вместо флага isEnd)
class TrieNode {
  children = new Map<string, TrieNode>();
  word: string | null = null;
}
```

Узел: рёбра по буквам и поле `word`. Если в узле кончается слово словаря, `word` хранит его целиком, иначе `null`.

```ts
function findWords(board: string[][], words: string[]): string[] {
  // 1. Строим trie из всех слов словаря
  const root = new TrieNode();
  for (const w of words) {
    let node = root;
    for (const ch of w) {
      if (!node.children.has(ch)) node.children.set(ch, new TrieNode());
      node = node.children.get(ch)!;
    }
    node.word = w;
  }
```

Стандартная вставка каждого слова: спуск по буквам с созданием недостающих узлов; в последнем узле запоминаем слово.

```ts
  const m = board.length;
  const n = board[0].length;
  const result: string[] = [];
```

Размеры доски для проверки границ и массив ответа.

```ts
  // 2. DFS по доске, параллельно спускаясь по trie
  const dfs = (r: number, c: number, parent: TrieNode): void => {
    const ch = board[r][c];
    const node = parent.children.get(ch);
    // Нет такого продолжения ни у одного слова — обрываем ветку
    if (!node) return;
```

`dfs(r, c, parent)` пытается продлить путь клеткой `(r, c)`, если текущий префикс соответствует узлу `parent`. Берём букву клетки и ищем ребро с ней. Нет ребра — ни одно слово не продолжается такой буквой, дальше идти бессмысленно. Эта же проверка отсекает уже занятые клетки: их буква сейчас `'#'`, а такого ребра в trie нет.

Узел `parent` передаётся (а не текущий узел) потому, что в конце нам понадобится удалить ребро `ch` именно у родителя.

```ts
    if (node.word !== null) {
      result.push(node.word);
      // Обнуляем, чтобы не добавить то же слово повторно
      node.word = null;
    }
```

Дошли до конца какого-то слова — добавляем его в ответ. Одно и то же слово может читаться на доске несколькими путями; обнуление `word` гарантирует, что в ответ оно попадёт один раз. Обратите внимание: после находки мы **не выходим** — из этого узла могут продолжаться более длинные слова (`"ab"` → `"abd"`).

```ts
    // Помечаем клетку как занятую на время текущего пути
    board[r][c] = '#';
    if (r > 0) dfs(r - 1, c, node);
    if (r < m - 1) dfs(r + 1, c, node);
    if (c > 0) dfs(r, c - 1, node);
    if (c < n - 1) dfs(r, c + 1, node);
```

Помечаем клетку, чтобы текущий путь не вернулся в неё. Затем пробуем четырёх соседей (вверх, вниз, влево, вправо), проверяя границы **до** вызова — так `dfs` никогда не получает координаты вне доски. Соседям передаём текущий `node`: для них он — родитель.

```ts
    // Возвращаем букву — откат (backtracking)
    board[r][c] = ch;
```

Откат: возвращаем букву. Другие пути (из других стартовых клеток или по другим веткам) могут проходить через эту клетку.

```ts
    // Оптимизация: опустевшую ветку удаляем, чтобы больше в неё не заходить
    if (node.children.size === 0 && node.word === null) {
      parent.children.delete(ch);
    }
  };
```

Если у узла не осталось ни детей, ни ненайденного слова, вся ветка исчерпана — удаляем ребро из родителя. После удаления последнего ребёнка родитель на своём уровне тоже может опустеть и будет удалён при возврате выше: дерево «сворачивается» снизу вверх.

```ts
  // 3. Запускаем поиск из каждой клетки
  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      dfs(r, c, root);
    }
  }

  return result;
}
```

Слово может начинаться в любой клетке, поэтому стартуем из каждой, с корнем trie в роли родителя. Если корень опустел (все слова найдены), каждый следующий запуск завершается на первой же проверке.

## Трассировка

Доска и слова:

```
a b        words = ["ab", "abd", "ba"]
c d
```

Trie: `root → a → b("ab") → d("abd")` и `root → b → a("ba")`.

1. Старт `(0,0)`, `ch = 'a'`, узел `a`, слова нет. Помечаем `(0,0)`. Соседи: вниз `(1,0)` — буква `c`, у `a` нет ребра `c` → возврат. Вправо `(0,1)`.
2. `(0,1)`, `ch = 'b'`, узел `b` со словом `"ab"` → `result = ["ab"]`, `word = null`. Помечаем. Вниз `(1,1)`.
3. `(1,1)`, `ch = 'd'`, узел `d` со словом `"abd"` → `result = ["ab", "abd"]`. Помечаем. Вверх `(0,1)` — там `'#'`, ребра нет. Влево `(1,0)` — `c`, ребра нет. Возвращаем `d`. У узла `d` нет детей и слова → удаляем ребро `d` у узла `b`.
4. Назад в `(0,1)`: влево `(0,0)` — `'#'`, нет ребра. Возвращаем `b`. Узел `b` опустел → удаляем у `a`.
5. Назад в `(0,0)`: возвращаем `a`. Узел `a` опустел → удаляем у корня. Теперь в trie осталась только ветка `b → a`.
6. Старт `(0,1)`, `ch = 'b'`, узел `b` (от корня). Помечаем. Вниз `(1,1)` — `d`, нет ребра. Влево `(0,0)`, `ch = 'a'`, узел со словом `"ba"` → `result = ["ab", "abd", "ba"]`. Его соседи `(1,0)` и `(0,1)` не подходят. Ветка `a` пуста → удаляем; затем пуста `b` → удаляем у корня.
7. Старты `(1,0)` и `(1,1)`: у пустого корня нет рёбер `c` и `d` → мгновенный возврат.

Ответ `["ab", "abd", "ba"]`.

## Почему это работает

Инвариант вызова `dfs(r, c, parent)`: текущий путь по доске (без клетки `(r, c)`) — это строка узла `parent`, и все клетки пути помечены `'#'`. Тогда:

- если ребра по `board[r][c]` нет, путь с этой клеткой не является префиксом ни одного слова — отсечение не теряет ответов;
- если ребро есть, строка узла `node` совпадает с путём, и если в нём хранится слово — это слово действительно читается на доске;
- пометки гарантируют, что путь не использует клетку дважды, а откат восстанавливает доску для остальных путей.

DFS из каждой клетки перебирает все простые пути, совпадающие с префиксами слов, значит, каждое слово, которое есть на доске, будет найдено. Удаление веток безопасно: удаляется только узел без детей и без ненайденного слова — через него нельзя найти ничего нового.

## Пограничные случаи

- **Слово читается несколькими путями**: попадёт в ответ один раз благодаря `node.word = null`.
- **Одно слово — префикс другого** (`"ab"` и `"abd"`): после находки `"ab"` поиск продолжается вглубь.
- **Нужно пройти по клетке дважды** (`"abcb"` на доске `ab/cd`): вторая `b` уже помечена `'#'` → слово не найдено.
- **Доска `1 × 1`**: все проверки границ ложны, находится только однобуквенное слово.
- **Ни одного слова нет на доске**: пустой массив.

## Сложность

- **Время `O(m · n · 4 · 3^(L−1))`** в худшем случае, где `L ≤ 10` — максимальная длина слова: из каждой клетки первый шаг в 4 стороны, дальше максимум в 3 (назад нельзя — клетка помечена), глубина ограничена длиной слова, потому что trie глубже не пускает. Плюс `O(S)` на построение trie, `S` — суммарная длина слов. На практике обрезка trie и отсечение по префиксам делают поиск гораздо быстрее.
- **Память `O(S)`** на trie плюс `O(L)` на стек рекурсии. Отдельный массив `visited` не нужен — пометки ставятся прямо на доске.

## Типичные ошибки

1. **Выходить из `dfs` после находки слова** → не находятся более длинные слова с тем же префиксом.
2. **Не обнулять `node.word`** → дубликаты в ответе, если слово читается двумя путями.
3. **Забыть вернуть букву после рекурсии** → доска «портится», следующие старты не находят слова.
4. **Удалять узел, у которого ещё есть дети** или ещё ненайденное слово → теряются ответы.
5. **Запускать Word Search отдельно для каждого слова** → таймаут на `3 · 10⁴` слов.

## Как узнать такую задачу

- Нужно найти **много слов/шаблонов** в одном источнике (доска, текст), и слова имеют общие префиксы.
- Наивно — «для каждого слова отдельный поиск», а ограничение на число слов большое.
- Сигнал: DFS/backtracking, который строит строку по символу, + словарь → спускаться по trie вместе с DFS. Похожие задачи: Word Search (одно слово), Implement Trie, Concatenated Words, Boggle.
