## Задача простыми словами

Дан массив **различных** положительных чисел `candidates` и число `target`. Нужно вернуть все **уникальные комбинации** чисел из `candidates`, дающие в сумме `target`. Одно и то же число можно брать **сколько угодно раз**. Комбинации, отличающиеся только порядком (`[2,2,3]` и `[3,2,2]`), считаются одинаковыми.

Пример: `candidates = [2, 3, 6, 7]`, `target = 7`. Ответ — `[[2,2,3], [7]]`: `2 + 2 + 3 = 7` и `7 = 7`.

## Наивный подход

Естественная рекурсия: «чтобы набрать `remain`, возьми любое число и набери остаток»:

```ts naive
function go(remain: number, path: number[]) {
  if (remain === 0) { result.push([...path]); return; }
  for (const c of candidates) {
    if (c <= remain) go(remain - c, [...path, c]);
  }
}
```

Она находит правильные суммы, но каждую комбинацию — **во всех порядках**: `[2,2,3]`, `[2,3,2]`, `[3,2,2]`. Для комбинации из `k` чисел это до `k!` копий, которые потом надо как-то удалять (сортировать каждую и класть в `Set` строк). Лишняя работа: дерево перебора разрастается за счёт веток, которые отличаются только порядком одних и тех же чисел.

Вторая потеря — цикл всегда проверяет **все** кандидаты, хотя если `c > remain`, то и следующие (более крупные) числа не помогут — но в несортированном массиве этого не узнать.

## Ключевое наблюдение

Чтобы каждая комбинация строилась **один раз**, договоримся брать числа в **неубывающем порядке индексов**: после `candidates[i]` можно взять только `candidates[j]` с `j >= i`. Именно `>=`, а не `>`: то же самое число можно брать повторно. Тогда `[2,2,3]` строится единственным способом, а `[3,2,2]` не появится никогда.

А если отсортировать кандидатов по возрастанию, то при первом `sorted[i] > remain` можно выйти из цикла целиком: все дальнейшие числа ещё больше.

## Техники

### Перебор с возвратом (backtracking) с повторным использованием

**Что это.** Backtracking строит решение по шагам (выбор → рекурсия → откат). В задачах на **комбинации** добавляют параметр `start`, чтобы элементы в пути шли в фиксированном порядке и не возникало перестановок одного набора.

**Три варианта шаблона:**

- сочетания без повторов (Combinations) — рекурсия с `i + 1`;
- с неограниченным повтором (эта задача) — рекурсия с `i`;
- перестановки (Permutations) — цикл с `0` и массив `used`.

**Как применяется здесь.** `backtrack(start, remain)`: перебираем следующее число с индекса `start`, рекурсия с тем же `i`. Подробнее — во вкладке «Теория».

### Отсечение по остатку на отсортированном массиве

Отсечение — отказ от веток, где решения точно нет. Отсортировав кандидатов, превращаем проверку `sorted[i] > remain` в `break`: одной проверкой отбрасываем весь хвост массива. Плюс остаток `remain` никогда не становится отрицательным — отрицательные ветки даже не создаются.

## Разбор кода

```ts
function combinationSum(candidates: number[], target: number): number[][] {
  // Сортировка позволяет прервать цикл, как только число стало больше остатка
  const sorted = [...candidates].sort((a, b) => a - b);
```

Сортируем **копию**, чтобы не менять входной массив. Компаратор `(a, b) => a - b` обязателен: без него `sort` сравнивает числа как строки, и `10` окажется раньше `2`.

```ts
  const result: number[][] = [];
  const path: number[] = [];
```

Ответ и текущая комбинация.

```ts
  // start — с какого кандидата можно продолжать (чтобы не было перестановок одной комбинации)
  // remain — сколько ещё осталось набрать
  const backtrack = (start: number, remain: number): void => {
    if (remain === 0) {
      // Сумма набрана точно — сохраняем копию
      result.push([...path]);
      return;
    }
```

Вместо суммы пути храним **остаток** `remain = target - сумма(path)`: так проверка «набрали?» — сравнение с нулём, а отсечение — сравнение с очередным числом. Остаток ноль — нашли комбинацию, сохраняем копию пути.

```ts
    for (let i = start; i < sorted.length; i++) {
      // Дальше числа только больше — ни одно уже не поместится
      if (sorted[i] > remain) break;
```

Перебираем следующее число, начиная с `start`. Если текущее число больше остатка, то и все следующие больше (массив отсортирован) — `break`, а не `continue`.

```ts
      path.push(sorted[i]);
      // Передаём i, а не i + 1: то же число можно взять ещё раз
      backtrack(i, remain - sorted[i]);
      path.pop(); // откат
    }
  };
```

Выбор → рекурсия → откат. Ключевая деталь — первый аргумент `i`: в следующем шаге снова доступно то же самое число (повтор разрешён), но **не** более ранние (это и убирает перестановки).

```ts
  backtrack(0, target);
  return result;
}
```

Старт: все кандидаты доступны, нужно набрать `target`.

## Трассировка

`candidates = [2, 3, 6, 7]`, `target = 7` (после сортировки тот же порядок):

```
bt(0, 7)
  2 → [2]        bt(0, 5)
    2 → [2,2]      bt(0, 3)
      2 → [2,2,2]    bt(0, 1): 2 > 1 → break
      3 → [2,2,3]    bt(1, 0): remain=0 → сохранить [2,2,3]
      6 > 3 → break
    3 → [2,3]      bt(1, 2): 3 > 2 → break
    6 > 5 → break
  3 → [3]        bt(1, 4)
    3 → [3,3]      bt(1, 1): 3 > 1 → break
    6 > 4 → break
  6 → [6]        bt(2, 1): 6 > 1 → break
  7 → [7]        bt(3, 0): сохранить [7]
```

Ответ `[[2,2,3], [7]]`. Обратите внимание: из ветки `[3]` рекурсия стартует с `start = 1`, поэтому `[3,2,2]` даже не рассматривается — двойка там уже недоступна.

## Почему это работает

Инвариант: при входе в `backtrack(start, remain)` путь `path` — неубывающая по индексам последовательность кандидатов с суммой `target - remain`, и все её индексы `<= start`.

- **Каждая комбинация найдётся.** Отсортируем её числа по возрастанию: `c₁ ≤ c₂ ≤ … ≤ c_k`. На каждом шаге нужный индекс не меньше текущего `start` (числа не убывают), а `cⱼ ≤ remain` (остальные слагаемые положительны), поэтому `break` до него не сработает.
- **Ровно один раз.** Путь всегда неубывающий, а у мультимножества только один неубывающий порядок.
- **Только верные.** Сохраняем лишь при `remain === 0`, то есть сумма пути равна `target`.
- **Завершение.** Все кандидаты `≥ 2` (по условию `≥ 1` в общем случае), так что `remain` строго уменьшается, глубина конечна.

## Пограничные случаи

- **`target` меньше всех кандидатов** (`[3]`, `target = 2`): первый же `break`, ответ `[]`.
- **`target` равен кандидату**: одноэлементная комбинация `[target]`.
- **Только одно число, многократно** (`[2]`, `target = 8`): `[[2,2,2,2]]`.
- **Неотсортированный вход** (`[7, 3, 2]`): работает благодаря сортировке копии; без неё `break` был бы ошибкой.

## Сложность

- **Время** экспоненциально: оценка `O(N^(T/M + 1))`, где `N` — число кандидатов, `T` — `target`, `M` — минимальный кандидат. Глубина дерева не больше `T/M` (каждый шаг уменьшает остаток хотя бы на `M`), ветвление не больше `N`. Плюс `O(T/M)` на копирование каждого найденного решения. На практике отсечения делают перебор гораздо меньше.
- **Память `O(T/M)`** дополнительно: максимальная глубина рекурсии и длина пути. Ответ — выходные данные.

## Типичные ошибки

1. **Рекурсия с `i + 1`** → число нельзя взять повторно, `[2,2,3]` не найдётся.
2. **Цикл с `0` вместо `start`** → дубликаты в разном порядке (`[2,2,3]`, `[2,3,2]`, `[3,2,2]`).
3. **`break` без сортировки** → пропуск решений с более мелкими числами, стоящими дальше в массиве.
4. **`sort()` без компаратора** → строковая сортировка (`[10, 2, 3]`), отсечение ломается.
5. **`result.push(path)` без копии** → все ответы — один массив.

## Как узнать такую задачу

- Нужно **перечислить все наборы** элементов с заданной суммой, и элементы **можно повторять**.
- «Уникальные комбинации», «порядок не важен» → параметр `start`.
- Если просят только **количество** или **минимум** — это уже ДП (Coin Change, Coin Change II, Combination Sum IV), а не перебор. Похожие задачи на перебор: Combination Sum II (без повторов, с дубликатами во входе), Combination Sum III, Subsets.
