## Задача простыми словами

На доске `n × n` нужно расставить `n` ферзей так, чтобы никакие два не били друг друга: не стояли в одной строке, одном столбце или на одной диагонали. Вернуть нужно **количество** различных расстановок (сами доски не нужны). `1 ≤ n ≤ 9`.

Пример: `n = 4` — ответ `2`:

```
. Q . .      . . Q .
. . . Q      Q . . .
Q . . .      . . . Q
. . Q .      . Q . .
```

## Наивный подход

Перебрать все способы поставить `n` ферзей на `n²` клеток и проверить каждую расстановку:

```ts naive
// все наборы из n клеток среди n² — C(n², n) вариантов
for (const cells of combinations(n * n, n)) {
  if (noTwoAttack(cells)) count++;
}
```

При `n = 8` это `C(64, 8) ≈ 4.4 · 10⁹` расстановок, каждая проверяется за `O(n²)`. Лишняя работа огромная: мы строим расстановки, где два ферзя стоят **в одной строке** (заведомо плохо), и замечаем конфликт только когда все `n` ферзей уже поставлены.

Даже если ставить по одному ферзю в строку (`n^n` вариантов: `8^8 ≈ 1.7 · 10⁷`), без проверки по ходу мы продолжаем достраивать доски, которые сломались уже на втором ферзе.

## Ключевое наблюдение

Два наблюдения убирают почти весь перебор:

1. **В каждой строке ровно один ферзь** (два в одной строке бьют друг друга, а ферзей `n` на `n` строк). Значит, идём по строкам сверху вниз и выбираем только **столбец**.
2. **Проверять конфликт сразу**, при постановке, а не в конце. Если клетка бьётся уже стоящим ферзём — в эту ветку не заходим вовсе.

Чтобы проверка была за `O(1)`, заметим: ферзь занимает столбец и две диагонали, а каждую диагональ можно пронумеровать одним числом:

- на диагонали «\» постоянна **разность** `row - col`;
- на диагонали «/» постоянна **сумма** `row + col`.

```
row - col (n = 4)        row + col
  0 -1 -2 -3             0 1 2 3
  1  0 -1 -2             1 2 3 4
  2  1  0 -1             2 3 4 5
  3  2  1  0             3 4 5 6
```

Три множества — занятые столбцы, «\»-диагонали и «/»-диагонали — отвечают на вопрос «свободна ли клетка?» тремя вызовами `has`.

## Техники

### Перебор с возвратом (backtracking) с отсечением

**Что это.** Рекурсивное построение решения по шагам с откатом. Сила метода — в **отсечениях**: проверяя ограничения на каждом шаге, мы отбрасываем целые поддеревья недопустимых вариантов.

**Типичный шаблон для задач на расстановку** («проверить — поставить — углубиться — убрать»):

```ts naive
backtrack(row):
  if (row === n) { count++; return; }
  for (col of столбцы)
    if (клетка свободна) { поставить; backtrack(row + 1); убрать; }
```

**Как применяется здесь.** Шаг — строка, вариант — столбец. Ограничения проверяются до постановки ферзя. Подробнее — во вкладке «Теория».

### Нумерация диагоналей и множества занятости

Приём для любых задач на сетке, где важны диагонали: диагональ «\» задаётся `row - col` (от `-(n-1)` до `n-1`), «/» — `row + col` (от `0` до `2n - 2`). Всего по `2n - 1` диагоналей каждого вида. В `Set` можно класть и отрицательные числа, поэтому никаких сдвигов индексов не нужно — ключ диагонали записывается ровно как в определении.

## Разбор кода

```ts
function totalNQueens(n: number): number {
  // Занятые столбцы и диагонали.
  // На «\»-диагонали постоянна разность row - col, на «/»-диагонали — сумма row + col.
  const cols = new Set<number>();
  const diag = new Set<number>();
  const anti = new Set<number>();
  let count = 0;
```

Три множества занятости: `cols` — номера столбцов, `diag` — разности `row - col`, `anti` — суммы `row + col` для уже стоящих ферзей. Строки отдельно не храним: в каждой строке ставим ровно одного ферзя по построению. `count` — счётчик найденных расстановок.

```ts
  // Ставим ровно одного ферзя в каждую строку, сверху вниз
  const backtrack = (row: number): void => {
    // Все n ферзей расставлены без конфликтов
    if (row === n) {
      count++;
      return;
    }
```

`backtrack(row)` расставляет ферзей в строках `row..n-1`, когда строки выше уже заполнены корректно. Если `row === n`, все `n` ферзей стоят без конфликтов — это одна полная расстановка.

```ts
    for (let col = 0; col < n; col++) {
      // Клетка бьётся уже стоящим ферзём — пропускаем
      if (cols.has(col) || diag.has(row - col) || anti.has(row + col)) continue;
```

Пробуем каждый столбец текущей строки. Через клетку `(row, col)` проходят столбец `col` и диагонали `row - col` и `row + col`. Если хотя бы одна из трёх линий занята — клетка под боем, пропускаем.

```ts
      // Выбор: ставим ферзя
      cols.add(col);
      diag.add(row - col);
      anti.add(row + col);

      backtrack(row + 1);

      // Откат: убираем ферзя
      cols.delete(col);
      diag.delete(row - col);
      anti.delete(row + col);
    }
  };
```

Ставим ферзя — добавляем три его линии. Рекурсивно заполняем следующие строки. После возврата удаляем ровно эти три значения: следующий столбец этой строки пробуется на доске без этого ферзя. Удалять безопасно — эти линии были свободны до постановки, значит, их занял только этот ферзь. Блоки `add` и `delete` зеркальны — их легко запомнить парой.

```ts
  backtrack(0);
  return count;
}
```

Начинаем с верхней строки на пустой доске.

## Трассировка

`n = 4`. Для каждой клетки `d = row - col`, `a = row + col`.

1. `row 0, col 0`: свободно, ставим (`cols = {0}`, `diag = {0}`, `anti = {0}`).
2. `row 1`: `col 0` — столбец занят; `col 1` — `d = 0` занята; `col 2` — `d = -1`, `a = 3` свободны → ставим.
3. `row 2`: `col 0` — столбец; `col 1` — `a = 3` занята; `col 2` — столбец; `col 3` — `d = -1` занята. Тупик, откат (удаляем `2`, `-1`, `3`).
4. `row 1, col 3`: `d = -2`, `a = 4` → ставим. `row 2`: `col 1` (`d = 1`, `a = 3`) свободна → ставим. `row 3`: `col 0`, `col 1`, `col 3` — столбцы заняты; `col 2` — `d = 1` занята. Тупик. `row 2`: `col 2` — `d = 0` занята, `col 3` — столбец. Тупик.
5. Ферзь в `(0, 0)` решений не даёт, откат — множества снова пусты. `row 0, col 1`: `d = -1`, `a = 1`.
6. `row 1`: `col 0` — `a = 1` занята; `col 1` — столбец; `col 2` — `d = -1` занята; `col 3` — `d = -2`, `a = 4` → ставим.
7. `row 2, col 0`: `d = 2`, `a = 2` свободны → ставим.
8. `row 3`: `col 2` — `d = 1`, `a = 5`, столбец 2 свободны → ставим, `backtrack(4)`: `count = 1`. Расстановка `(0,1), (1,3), (2,0), (3,2)`.
9. Дальнейший перебор находит зеркальную расстановку `(0,2), (1,0), (2,3), (3,1)` → `count = 2`; старт с `col 3` решений не даёт.

Ответ `2`.

## Почему это работает

Инвариант: при входе в `backtrack(row)` в строках `0..row-1` стоит ровно по одному ферзю, никакие два не бьют друг друга, и множества `cols`, `diag`, `anti` содержат ровно линии этих ферзей.

- Новый ферзь ставится только в клетку, не лежащую ни на одной отмеченной линии, — значит, он не бьёт ни одного уже стоящего; строка у него новая. Инвариант сохраняется.
- Откат удаляет ровно три значения, добавленные этим ферзём, — инвариант восстанавливается для следующей итерации.
- Любая корректная расстановка имеет по одному ферзю в строке; перебор по строкам рассматривает её столбцы по очереди, и ни на одном шаге её клетка не окажется под боем. Значит, каждая корректная расстановка посчитается ровно один раз.

## Пограничные случаи

- **`n = 1`**: один ферзь на одной клетке — ответ `1`.
- **`n = 2` и `n = 3`**: решений нет, ответ `0` — все ветки обрываются отсечением.
- **`n = 9`** (максимум): ответ `352`, перебор укладывается в доли секунды благодаря отсечениям.
- **Отрицательные разности** `row - col` (например, `-3` для клетки `(0, 3)`): `Set` хранит их как обычные ключи, сдвиг не нужен.

## Сложность

- **Время `O(n!)`** (грубая верхняя оценка): в первой строке до `n` вариантов, во второй не больше `n - 1` свободных столбцов, и так далее. На каждый узел — цикл на `n` столбцов с проверкой за `O(1)`. Диагональные отсечения уменьшают реальное число узлов на порядки.
- **Память `O(n)`**: в каждом множестве не больше `n` значений (по одному на ферзя), глубина рекурсии `n`. Доску не храним вообще.

**Follow-up на собеседовании — ускорение констант.** Вместо `Set` можно взять массивы `boolean[]` (для «\» — с индексом `row - col + n - 1`, чтобы он был `>= 0`) или **битовые маски**: `free = ~(cols | diag | anti) & ((1 << n) - 1)`, младший свободный бит — `free & -free`, а диагонали сдвигаются на каждой строке (`(diag | bit) << 1`, `(anti | bit) >> 1`). Асимптотика та же, но работа идёт с одним числом вместо хеш-таблицы.

## Типичные ошибки

1. **Проверять конфликт перебором всех поставленных ферзей** → `O(n)` на проверку вместо `O(1)`; работает, но медленнее.
2. **Не удалить из всех трёх множеств при откате** (например, забыть `anti.delete`) → линия остаётся «занятой», ответ занижен.
3. **Перепутать, где разность, а где сумма**, или положить одно и то же значение в `diag` и `anti` → пропущенные конфликты. В варианте с массивами — ещё и забытый сдвиг `n - 1`: `diag[-2]` всегда `undefined`.
4. **Не делать откат совсем** (нет блока `delete`) → после первой ветки линии считаются занятыми навсегда, ответ занижен.
5. **Перебирать клетки, а не строки** → одна и та же расстановка считается многократно (в разном порядке постановки).

## Как узнать такую задачу

- Расстановка объектов на доске/сетке с **ограничениями «не бьют друг друга»**, нужно количество или все варианты.
- Есть естественное правило «ровно один объект на строку/позицию» — это превращает перебор клеток в перебор столбцов (по сути, перестановок).
- Маленькое `n` (`≤ 9–12`) — ожидается backtracking с отсечениями. Похожие задачи: N-Queens (вывести доски), Sudoku Solver, Permutations, расстановка ладей/слонов.
