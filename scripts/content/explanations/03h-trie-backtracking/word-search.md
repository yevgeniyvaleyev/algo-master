## Задача простыми словами

Дана доска букв `board` размером `m × n` и слово `word`. Нужно ответить, можно ли прочитать слово на доске: буквы идут по **соседним** клеткам (вверх, вниз, влево, вправо), и одну клетку в одном слове использовать дважды нельзя.

Пример: доска

```
A B C E
S F C S
A D E E
```

Слово `"ABCCED"` есть (`A → B → C ↓ C ↓ E ← D`), слово `"SEE"` есть, а `"ABCB"` — нет: вторую `B` пришлось бы взять из той же клетки.

## Наивный подход

Можно перечислить **все** простые пути на доске длины `L` и сравнить каждый со словом. Путей экспоненциально много: из каждой клетки до `4 · 3^(L−1)`, и почти все они не имеют отношения к слову — уже вторая буква не совпадает, а мы продолжаем строить путь до длины `L`.

Другая ошибка — жадный обход: «иди в первого соседа с нужной буквой». Он не работает, потому что первый подходящий сосед может завести в тупик, а правильный путь идёт через другого — нужно уметь **вернуться** и попробовать иначе.

## Ключевое наблюдение

Строим путь **буква за буквой** и обрываем его, как только очередная клетка не совпала с нужной буквой слова. Тогда исследуются только пути, совпадающие с **префиксом** слова, — обычно их очень мало.

Чтобы не наступить на клетку дважды, на время пути помечаем её прямо на доске, а при возврате восстанавливаем — это и есть перебор с возвратом.

Плюс дешёвые предварительные проверки (за `O(m·n + L)`) отсекают самые тяжёлые случаи ещё до поиска: слово длиннее доски; какой-то буквы в слове больше, чем на доске; выгоднее искать слово с более редкого конца.

## Техники

### Перебор с возвратом (backtracking) на сетке

**Что это.** Рекурсивный DFS, который продлевает текущий путь и при возврате **отменяет** свои изменения. На сетке шаблон такой: проверить клетку → пометить → обойти соседей → снять пометку.

**Типичный шаблон:**

```ts naive
dfs(r, c, i):
  if (вне доски или буква не совпала) return false
  if (это последняя буква) return true
  пометить (r, c)
  found = dfs(соседи, i + 1)
  снять пометку
  return found
```

**Как применяется здесь.** `dfs(r, c, i)` отвечает: можно ли составить остаток слова, начиная с буквы `i` в клетке `(r, c)`. Подробнее — во вкладке «Теория».

### Пометка на месте вместо `visited`

Вместо отдельной матрицы `visited` клетку временно заменяем на `'#'`. Этот символ не встречается в слове, поэтому проверка «буква совпала» автоматически отсекает и уже занятые клетки. Восстанавливать букву обязательно — клетка может понадобиться другому пути.

### Предварительные отсечения

Отсечение — отказ от поиска, который заведомо не даст ответа. Подсчёт букв (`Map` «буква → количество») решает тяжёлый тест «доска из одних `A`, слово `AAAA…B`»: без него перебор исследует миллионы путей из `A`, а проверка счётчиков сразу видит, что `B` на доске нет. Разворот слова уменьшает число стартовых клеток: если первая буква встречается часто, а последняя редко, выгоднее начинать с последней — слово и его разворот читаются на доске по одним и тем же клеткам.

## Разбор кода

```ts
function exist(board: string[][], word: string): boolean {
  const m = board.length;
  const n = board[0].length;

  // Отсечение 1: в слове больше букв, чем клеток на доске
  if (word.length > m * n) return false;
```

Клетки нельзя использовать повторно, поэтому слово длиннее `m · n` не поместится в принципе.

```ts
  // Отсечение 2: какой-то буквы в слове больше, чем на доске
  const available = new Map<string, number>();
  for (const row of board) {
    for (const ch of row) available.set(ch, (available.get(ch) ?? 0) + 1);
  }
```

Считаем, сколько раз каждая буква встречается на доске. `?? 0` подставляет ноль для буквы, которой ещё нет в `Map`.

```ts
  const needed = new Map<string, number>();
  for (const ch of word) {
    needed.set(ch, (needed.get(ch) ?? 0) + 1);
    if (needed.get(ch)! > (available.get(ch) ?? 0)) return false;
  }
```

Считаем буквы слова и сразу сравниваем: как только какой-то буквы нужно больше, чем есть на доске, слова точно нет. Проверка по ходу подсчёта выходит при первом же дефиците.

```ts
  // Отсечение 3: начинаем с более редкого конца слова — меньше стартовых веток
  let target = word;
  if ((available.get(word[0]) ?? 0) > (available.get(word[word.length - 1]) ?? 0)) {
    target = [...word].reverse().join('');
  }
```

Если первая буква встречается на доске чаще последней, ищем развёрнутое слово. Путь для слова, пройденный в обратную сторону, — путь для его разворота, так что ответ не меняется, а число успешных стартов (и ветвей у корня) уменьшается.

```ts
  // dfs(r, c, i): можно ли составить target[i..], начиная с клетки (r, c)
  const dfs = (r: number, c: number, i: number): boolean => {
    if (r < 0 || r >= m || c < 0 || c >= n || board[r][c] !== target[i]) return false;
    // Совпала последняя буква — слово найдено
    if (i === target.length - 1) return true;
```

Первая строка — все причины неудачи сразу: вышли за доску, или буква клетки не та (включая `'#'` — клетка уже в пути). Проверка границ идёт **раньше** обращения к `board[r][c]`, иначе `board[-1]` дал бы `undefined` и ошибку. Если совпала последняя буква — слово составлено, дальше идти не нужно.

```ts
    // Помечаем клетку, чтобы не использовать её повторно в этом пути
    const saved = board[r][c];
    board[r][c] = '#';
```

Запоминаем букву и ставим метку: пока мы в этом пути, клетка занята.

```ts
    const found =
      dfs(r + 1, c, i + 1) || dfs(r - 1, c, i + 1) || dfs(r, c + 1, i + 1) || dfs(r, c - 1, i + 1);
```

Пробуем продолжить слово в каждом из четырёх соседей (вниз, вверх, вправо, влево). `||` вычисляется лениво: как только один сосед вернул `true`, остальные не вызываются. Границы проверяет сам `dfs`, поэтому соседей можно передавать без условий.

```ts
    // Откат: возвращаем букву
    board[r][c] = saved;
    return found;
  };
```

Восстанавливаем букву **до** возврата — независимо от результата. Даже если слово найдено, доска остаётся в исходном виде (вызывающий код её не испортит).

```ts
  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      if (dfs(r, c, 0)) return true;
    }
  }
  return false;
}
```

Слово может начинаться в любой клетке — пробуем все. Первый успех — `true`; если ни один старт не сработал — `false`.

## Трассировка

Доска из примера, `word = "ABCCED"`:

```
     0 1 2 3
0:   A B C E
1:   S F C S
2:   A D E E
```

1. Отсечения: `6 ≤ 12`; буквы `A:1, B:1, C:2, E:1, D:1` есть в достаточном количестве (`A:2, B:1, C:2, D:1, E:3`).
2. Первая буква `A` встречается 2 раза, последняя `D` — 1 раз → `target = "DECCBA"`.
3. Старты `(0,0)…(2,0)` — буква не `D`, сразу `false`. Старт `(2,1)` = `D`, `i = 0`, помечаем.
4. Соседи `D`: вниз — вне доски; вверх `(1,1)` = `F` ≠ `E`; вправо `(2,2)` = `E` ✓ (`i = 1`), помечаем.
5. Соседи `(2,2)`: вниз — вне; вверх `(1,2)` = `C` ✓ (`i = 2`), помечаем.
6. Соседи `(1,2)`: вниз `(2,2)` = `'#'` ✗; вверх `(0,2)` = `C` ✓ (`i = 3`), помечаем.
7. Соседи `(0,2)`: вниз `(1,2)` = `'#'`; вверх — вне; вправо `(0,3)` = `E` ≠ `B`; влево `(0,1)` = `B` ✓ (`i = 4`), помечаем.
8. Соседи `(0,1)`: вниз `(1,1)` = `F` ≠ `A`; вверх — вне; вправо `(0,2)` = `'#'`; влево `(0,0)` = `A` ✓, `i = 5` — последняя буква → `true`.
9. `true` поднимается по цепочке; каждый уровень по пути восстанавливает свою букву. Ответ `true`.

Для `word = "ABCB"` поиск даже не начнётся: в слове две `B`, на доске одна → `false` на отсечении 2.

## Почему это работает

Инвариант вызова `dfs(r, c, i)`: буквы `target[0..i-1]` уже составлены простым путём, клетки которого помечены `'#'`, а `(r, c)` — соседняя с концом пути клетка (или старт при `i = 0`).

- Если `dfs` вернул `true`, путь существует: каждая клетка пути совпала со своей буквой, соседство обеспечено вызовами, повторов нет благодаря меткам.
- Если путь для слова существует, перебор его найдёт: он пробует каждую стартовую клетку и из каждой клетки — всех соседей, а метки запрещают только клетки, уже занятые **текущим** путём.
- Откат гарантирует, что после возврата доска точно такая же, как до вызова, поэтому соседние ветки не влияют друг на друга.

Отсечения корректны: они отвечают `false` только когда слово заведомо не помещается, а разворот сохраняет ответ.

## Пограничные случаи

- **Однобуквенное слово**: `dfs` вернёт `true` в первой же клетке с этой буквой (`i === 0 === length − 1`).
- **Доска `1 × 1`**: все соседи — вне доски.
- **Нужно вернуться в клетку** (`"ABCB"`, или `"ABA"` на доске `A B`): метка `'#'` (или подсчёт букв) не даёт этого сделать.
- **Слово длиннее доски**: отсечение 1.
- **Палиндром** или равные частоты концов: разворота нет (условие строгое `>`), ищем как есть.

## Сложность

- **Время `O(m · n · 3^L)`** в худшем случае: стартов `m · n`, из каждой клетки на первом шаге до 4 направлений, дальше до 3 (в предыдущую клетку не вернуться — она помечена), глубина не больше `L`. Предварительные проверки — `O(m · n + L)`, на асимптотику не влияют, но на практике отсекают худшие тесты.
- **Память `O(L)`**: глубина рекурсии не больше длины слова; доска помечается на месте, плюс `Map` на не более чем 52 буквы (`O(1)`) и строка `target` за `O(L)`.

## Типичные ошибки

1. **Не восстанавливать букву** после рекурсии → следующие старты видят «дыры» в доске и не находят слово.
2. **Проверять `board[r][c]` до проверки границ** → обращение к `board[-1][c]` и `TypeError`.
3. **Общая матрица `visited` без снятия пометок** → клетка, занятая в неудачной ветке, недоступна и для удачной.
4. **Возвращать `true` при `i === word.length`** без проверки границ/буквы — возможно, но легко ошибиться на единицу; здесь проверка последней буквы явная.
5. **Восстанавливать букву только при неудаче** (ранний `return true` до отката) → после ответа доска испорчена.

## Как узнать такую задачу

- Найти **путь по соседним клеткам** сетки, совпадающий с заданной последовательностью, без повторного использования клеток.
- Нужно «да/нет» существования, но путей экспоненциально много → DFS с откатом и ранним выходом.
- Если слов **много** — тот же DFS, но с trie: Word Search II. Похожие задачи: Number of Islands (обход без отката), Path with Maximum Gold, Unique Paths III.
