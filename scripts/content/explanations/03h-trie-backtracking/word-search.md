## Задача простыми словами

Дана доска букв `board` размером `m × n` и слово `word`. Нужно ответить, можно ли прочитать слово на доске: буквы идут по **соседним** клеткам (вверх, вниз, влево, вправо), и одну клетку в одном слове использовать дважды нельзя.

Пример: доска

```
A B C E
S F C S
A D E E
```

Слово `"ABCCED"` есть (`A → B → C ↓ C ↓ E ← D`), слово `"SEE"` есть, а `"ABCB"` — нет: вторую `B` пришлось бы взять из той же клетки.

## Наивный подход

Можно перечислить **все** простые пути на доске длины `L` и сравнить каждый со словом. Путей экспоненциально много: из каждой клетки до `4 · 3^(L−1)`, и почти все они не имеют отношения к слову — уже вторая буква не совпадает, а мы продолжаем строить путь до длины `L`.

Другая ошибка — жадный обход: «иди в первого соседа с нужной буквой». Он не работает, потому что первый подходящий сосед может завести в тупик, а правильный путь идёт через другого — нужно уметь **вернуться** и попробовать иначе.

## Ключевое наблюдение

Строим путь **буква за буквой** и обрываем его, как только очередная клетка не совпала с нужной буквой слова. Тогда исследуются только пути, совпадающие с **префиксом** слова, — обычно их очень мало.

Чтобы не наступить на клетку дважды, на время пути помечаем её прямо на доске, а при возврате восстанавливаем — это и есть перебор с возвратом.

## Техники

### Перебор с возвратом (backtracking) на сетке

**Что это.** Рекурсивный DFS, который продлевает текущий путь и при возврате **отменяет** свои изменения. На сетке шаблон такой: проверить клетку → пометить → обойти соседей → снять пометку.

**Типичный шаблон:**

```ts naive
dfs(r, c, i):
  if (вне доски или буква не совпала) return false
  if (это последняя буква) return true
  пометить (r, c)
  found = dfs(соседи, i + 1)
  снять пометку
  return found
```

**Как применяется здесь.** `dfs(r, c, i)` отвечает: можно ли составить остаток слова, начиная с буквы `i` в клетке `(r, c)`. Подробнее — во вкладке «Теория».

### Пометка на месте вместо `visited`

Вместо отдельной матрицы `visited` клетку временно заменяем на `'#'`. Этот символ не встречается в слове, поэтому проверка «буква совпала» автоматически отсекает и уже занятые клетки. Восстанавливать букву обязательно — клетка может понадобиться другому пути.

## Разбор кода

```ts
function exist(board: string[][], word: string): boolean {
  const m = board.length;
  const n = board[0].length;
```

Размеры доски — понадобятся для проверки границ.

```ts
  // dfs(r, c, i): можно ли составить word[i..], начиная с клетки (r, c)
  const dfs = (r: number, c: number, i: number): boolean => {
    // Вышли за доску, клетка занята ('#') или буква не та
    if (r < 0 || r >= m || c < 0 || c >= n || board[r][c] !== word[i]) return false;
    // Совпала последняя буква — слово найдено
    if (i === word.length - 1) return true;
```

Первая строка — все причины неудачи сразу: вышли за доску, или буква клетки не та (включая `'#'` — клетка уже в пути). Проверка границ идёт **раньше** обращения к `board[r][c]`, иначе `board[-1]` дал бы `undefined` и ошибку. Если совпала последняя буква — слово составлено, дальше идти не нужно.

```ts
    // Выбор: помечаем клетку, чтобы не использовать её повторно в этом пути
    const saved = board[r][c];
    board[r][c] = '#';
```

Запоминаем букву и ставим метку: пока мы в этом пути, клетка занята.

```ts
    // Пробуем 4 направления
    const found = dfs(r + 1, c, i + 1) || dfs(r - 1, c, i + 1) || dfs(r, c + 1, i + 1) || dfs(r, c - 1, i + 1);
```

Пробуем продолжить слово в каждом из четырёх соседей (вниз, вверх, вправо, влево). `||` вычисляется лениво: как только один сосед вернул `true`, остальные не вызываются. Границы проверяет сам `dfs`, поэтому соседей можно передавать без условий.

```ts
    // Откат: возвращаем букву
    board[r][c] = saved;
    return found;
  };
```

Восстанавливаем букву **до** возврата — независимо от результата. Даже если слово найдено, доска остаётся в исходном виде.

```ts
  // Пробуем начать слово в каждой клетке
  for (let r = 0; r < m; r++) {
    for (let c = 0; c < n; c++) {
      if (dfs(r, c, 0)) return true;
    }
  }
  return false;
}
```

Слово может начинаться в любой клетке — пробуем все. Первый успех — `true`; если ни один старт не сработал — `false`. Клетки с другой буквой отсекаются первой же проверкой в `dfs`.

## Трассировка

Доска из примера, `word = "ABCCED"`, порядок соседей — вниз, вверх, вправо, влево:

```
     0 1 2 3
0:   A B C E
1:   S F C S
2:   A D E E
```

1. Старт `(0,0)` = `A` ✓ (`i = 0`), помечаем `'#'`.
2. Соседи `(0,0)`: вниз `(1,0)` = `S` ≠ `B`; вверх — вне доски; вправо `(0,1)` = `B` ✓ (`i = 1`), помечаем.
3. Соседи `(0,1)`: вниз `(1,1)` = `F` ≠ `C`; вверх — вне; вправо `(0,2)` = `C` ✓ (`i = 2`), помечаем.
4. Соседи `(0,2)`: вниз `(1,2)` = `C` ✓ (`i = 3`), помечаем.
5. Соседи `(1,2)`: вниз `(2,2)` = `E` ✓ (`i = 4`), помечаем.
6. Соседи `(2,2)`: вниз — вне; вверх `(1,2)` = `'#'` ✗; вправо `(2,3)` = `E` ≠ `D`; влево `(2,1)` = `D` ✓, `i = 5` — последняя буква → `true`.
7. `true` поднимается по цепочке; каждый уровень восстанавливает свою букву. Ответ `true`.

Для `word = "ABCB"`: путь `A(0,0) → B(0,1) → C(0,2)`, дальше нужна `B`: вниз `C`, вверх — вне, вправо `E`, влево `(0,1)` = `'#'` — метка не даёт взять ту же `B` второй раз. Остальные ветки и старты тоже обрываются → `false`.

## Почему это работает

Инвариант вызова `dfs(r, c, i)`: буквы `word[0..i-1]` уже составлены простым путём, клетки которого помечены `'#'`, а `(r, c)` — соседняя с концом пути клетка (или старт при `i = 0`).

- Если `dfs` вернул `true`, путь существует: каждая клетка пути совпала со своей буквой, соседство обеспечено вызовами, повторов нет благодаря меткам.
- Если путь для слова существует, перебор его найдёт: он пробует каждую стартовую клетку и из каждой клетки — всех соседей, а метки запрещают только клетки, уже занятые **текущим** путём.
- Откат гарантирует, что после возврата доска точно такая же, как до вызова, поэтому соседние ветки и старты не влияют друг на друга.

## Пограничные случаи

- **Однобуквенное слово**: `dfs` вернёт `true` в первой же клетке с этой буквой (`i === 0 === length − 1`).
- **Доска `1 × 1`**: все соседи — вне доски; `"a"` на доске `[["a"]]` — `true`, `"aa"` — `false` (вторую `a` взять негде, клетка помечена).
- **Нужно вернуться в клетку** (`"ABCB"`, или `"ABA"` на доске `A B`): метка `'#'` не даёт этого сделать.
- **Слово длиннее доски**: поиск честно переберёт пути и вернёт `false` — отдельная проверка не нужна для корректности.
- **Регистр букв**: `'a'` и `'A'` разные, сравнение строгое.

## Сложность

- **Время `O(m · n · 3^L)`** в худшем случае: стартов `m · n`, из каждой клетки на первом шаге до 4 направлений, дальше до 3 (в предыдущую клетку не вернуться — она помечена), глубина не больше `L`. На практике ветки обрываются на первой несовпавшей букве.
- **Память `O(L)`**: глубина рекурсии не больше длины слова; доска помечается на месте.

**Follow-up на собеседовании — необязательные ускорения** (в условии прямо спрашивают про отсечения). Перед поиском за `O(m · n + L)`:

- слово длиннее `m · n` клеток — сразу `false`;
- **подсчёт букв**: если какой-то буквы в слове больше, чем на доске, слова нет — это мгновенно решает тяжёлый тест «доска из одних `A`, слово `AAAA…B`»;
- **разворот слова**: если первая буква встречается на доске чаще последней, ищем слово задом наперёд — меньше стартовых веток, а ответ тот же.

Асимптотика худшего случая не меняется, но самые медленные тесты отсекаются ещё до DFS.

## Типичные ошибки

1. **Не восстанавливать букву** после рекурсии → следующие старты видят «дыры» в доске и не находят слово.
2. **Проверять `board[r][c]` до проверки границ** → обращение к `board[-1][c]` и `TypeError`.
3. **Общая матрица `visited` без снятия пометок** → клетка, занятая в неудачной ветке, недоступна и для удачной.
4. **Возвращать `true` при `i === word.length`** без проверки границ/буквы — возможно, но легко ошибиться на единицу; здесь проверка последней буквы явная.
5. **Восстанавливать букву только при неудаче** (ранний `return true` до отката) → после ответа доска испорчена.

## Как узнать такую задачу

- Найти **путь по соседним клеткам** сетки, совпадающий с заданной последовательностью, без повторного использования клеток.
- Нужно «да/нет» существования, но путей экспоненциально много → DFS с откатом и ранним выходом.
- Если слов **много** — тот же DFS, но с trie: Word Search II. Похожие задачи: Number of Islands (обход без отката), Path with Maximum Gold, Unique Paths III.
