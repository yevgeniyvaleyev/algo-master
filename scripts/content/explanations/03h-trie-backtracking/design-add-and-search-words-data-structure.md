## Задача простыми словами

Нужен класс `WordDictionary` с двумя методами: `addWord(word)` добавляет слово, а `search(word)` проверяет, есть ли в словаре слово, **совпадающее с шаблоном**. В шаблоне кроме букв может стоять точка `.` — она совпадает с **любой одной** буквой. Точек в запросе не больше двух.

Пример: добавили `"bad"`, `"dad"`, `"mad"`. Тогда `search("pad")` → `false`, `search("bad")` → `true`, `search(".ad")` → `true` (подходят все три), `search("b..")` → `true` (подходит `"bad"`).

## Наивный подход

Хранить слова в массиве и на каждый запрос сравнивать шаблон с каждым словом посимвольно:

```ts naive
search(pattern: string): boolean {
  for (const w of this.words) {
    if (w.length !== pattern.length) continue;
    let ok = true;
    for (let i = 0; i < w.length && ok; i++) {
      if (pattern[i] !== '.' && pattern[i] !== w[i]) ok = false;
    }
    if (ok) return true;
  }
  return false;
}
```

Это `O(N · L)` на запрос, где `N` — число слов. При `10⁴` вызовов и тысячах слов — десятки миллионов сравнений.

Лишняя работа: слова `"bad"`, `"bag"`, `"ban"` все начинаются на `"ba"`, и если шаблон начинается с `"c"`, мы всё равно отдельно проверяем каждое из них. Мы не умеем отбросить **сразу целую группу** слов с неподходящим началом. А `Set` здесь не помогает: точку в хеш не подставишь — пришлось бы перебрать все 26 букв на каждое место точки и сделать `26²` поисков по `Set`, каждый с построением строки.

## Ключевое наблюдение

Если хранить слова в **префиксном дереве**, то шаблон без точек проверяется обычным спуском: одна буква — одно ребро. Неподходящие группы слов отсекаются автоматически — в ветку с другой буквой мы просто не заходим.

Точка означает «любое ребро», поэтому в этом месте путь **ветвится**: пробуем всех детей текущего узла и рекурсивно проверяем остаток шаблона из каждого. Достаточно, чтобы совпала хоть одна ветка. Поскольку точек не больше двух, ветвление ограничено: максимум `26 · 26` путей, и почти все они быстро обрываются.

## Техники

### Префиксное дерево (trie)

**Что это.** Дерево, где каждый узел — префикс, ребро — одна буква, а флаг `isEnd` отмечает конец вставленного слова. Все слова с общим началом проходят по одному пути, поэтому проверка «подходит ли начало» делается один раз для всей группы.

**Как применяется здесь.** `addWord` — ровно стандартная вставка из задачи Implement Trie. Поиск — спуск, но с ветвлением на точках. Подробнее о trie — во вкладке «Теория».

### DFS по дереву с ветвлением (поиск по шаблону)

**Что это.** Рекурсивная функция вида `dfs(узел, позиция в шаблоне)` отвечает на вопрос «можно ли сопоставить остаток шаблона, начиная с этого узла». Каждый вызов обрабатывает один символ шаблона и переходит к следующему.

**Типичный шаблон:**

```ts naive
dfs(node, i):
  if (шаблон кончился) return node — конец слова?
  if (символ — подстановочный) return любой ребёнок даёт dfs(child, i + 1)
  return есть ребёнок по символу и dfs(ребёнок, i + 1)
```

**Как применяется здесь.** Буква даёт ровно один переход, точка — перебор всех детей. Возвращаем `true`, как только нашли первое совпадение: искать остальные не нужно.

### Ленивое вычисление (ранний выход)

`return true` внутри цикла по детям и `&&` в строке для обычной буквы останавливают поиск при первом успехе или первой неудаче. Это не меняет асимптотику худшего случая, но на практике отсекает большую часть дерева.

## Разбор кода

```ts
// Узел trie: переходы по буквам и признак конца слова
class TrieNode {
  children = new Map<string, TrieNode>();
  isEnd = false;
}
```

Обычный узел trie: `children` — рёбра «буква → узел», `isEnd` — заканчивается ли здесь добавленное слово.

```ts
class WordDictionary {
  private root = new TrieNode();

  addWord(word: string): void {
    // Обычная вставка в trie
    let node = this.root;
    for (const ch of word) {
      if (!node.children.has(ch)) {
        node.children.set(ch, new TrieNode());
      }
      node = node.children.get(ch)!;
    }
    node.isEnd = true;
  }
```

Корень — пустой префикс. Вставка спускается по буквам слова, создавая недостающие узлы, и в последнем узле ставит `isEnd = true`. Точек во вставляемых словах не бывает — только в запросах.

```ts
  search(word: string): boolean {
    // dfs(node, i): можно ли сопоставить суффикс word[i..], начиная с узла node
    const dfs = (node: TrieNode, i: number): boolean => {
      // Шаблон закончился — совпадение, только если здесь кончается слово
      if (i === word.length) return node.isEnd;
```

`dfs` объявлена стрелочной функцией внутри `search`, поэтому видит `word` через замыкание и не нужно передавать шаблон в каждый вызов.

Базовый случай: все символы шаблона сопоставлены. Это ещё не победа — нужно, чтобы в этом узле **кончалось слово**. Иначе шаблон `"ba"` «нашёлся» бы по слову `"bad"`, а `".."` — по любому слову длиннее двух букв.

```ts
      const ch = word[i];
      if (ch === '.') {
        // Точка совпадает с любой буквой — пробуем всех детей
        for (const child of node.children.values()) {
          if (dfs(child, i + 1)) return true;
        }
        return false;
      }
```

Точка — место ветвления. Перебираем всех детей узла (каждый соответствует какой-то букве, которая могла стоять на месте точки) и проверяем остаток шаблона из каждого. Первый успех — сразу `true`. Если детей нет или ни одна ветка не подошла — `false`.

```ts
      // Обычная буква — единственный возможный переход
      const next = node.children.get(ch);
      return next !== undefined && dfs(next, i + 1);
    };
```

Для буквы переход однозначен. Если ребра нет — ни одно слово не продолжается так, ответ `false` (и `dfs` даже не вызывается благодаря `&&`). Иначе идём дальше с `i + 1`.

```ts
    return dfs(this.root, 0);
  }
}
```

Запуск: от корня, с первого символа шаблона.

## Трассировка

Словарь: `addWord("bad")`, `addWord("dad")`, `addWord("mad")`. Дерево:

```
        (root)
      /   |   \
     b    d    m
     |    |    |
     a    a    a
     |    |    |
     d*   d*   d*
```

1. `search("pad")`: `dfs(root, 0)`, `ch = 'p'`, у корня нет ребра `p` → `false`.
2. `search("bad")`: `b` → `a` → `d`, затем `dfs(d, 3)`: `i === 3`, `isEnd = true` → `true`.
3. `search(".ad")`: `dfs(root, 0)`, `ch = '.'`, перебираем детей в порядке вставки. Первый ребёнок `b`: `dfs(b, 1)` → `'a'` есть → `dfs(a, 2)` → `'d'` есть → `dfs(d, 3)` → `isEnd = true`. Возвращаем `true`, детей `d` и `m` даже не смотрим.
4. `search("b..")`: `'b'` → `dfs(b, 1)`, `ch = '.'`, единственный ребёнок `a` → `dfs(a, 2)`, `ch = '.'`, единственный ребёнок `d` → `dfs(d, 3)` → `isEnd = true` → `true`.
5. Для контраста `search("b.")`: `'b'` → `dfs(b, 1)`, точка, ребёнок `a` → `dfs(a, 2)`: `i === 2 === word.length`, `isEnd` у `a` равен `false` → `false`; других детей у `b` нет → `false`.

## Почему это работает

`dfs(node, i)` возвращает `true` тогда и только тогда, когда существует вставленное слово, у которого префикс — строка узла `node`, а остаток совпадает с `word[i..]` по правилам шаблона. Доказательство индукцией по длине остатка:

- остаток пуст — слово совпадает ровно тогда, когда строка узла сама является словом, то есть `isEnd`;
- первая буква остатка — конкретная `ch`: подходящее слово обязано продолжаться ребром `ch`, а дальше работает предположение индукции;
- первая буква — точка: подходящее слово продолжается **каким-то** ребром, и мы перебираем все рёбра.

Вызов от корня с `i = 0` отвечает ровно на вопрос задачи.

## Пограничные случаи

- **Шаблон короче слова** (`"ba"` при словаре `{"bad"}`): путь есть, но `isEnd = false` → `false`.
- **Шаблон длиннее любого слова**: на каком-то шаге у узла нет детей → `false`.
- **Шаблон из одних точек** (`".."`): ищется любое слово длины 2 — перебор всех путей длины 2. Точек не больше двух, поэтому в более длинных шаблонах всегда есть буквы, отсекающие ветки.
- **Точка в конце** (`"ba."`): последний перебор детей и проверка `isEnd` у каждого.
- **Поиск в пустом словаре**: у корня нет детей — `false` и для букв, и для точек.

## Сложность

- **`addWord`: `O(L)`** — один шаг на букву, операции `Map` за `O(1)`.
- **`search` без точек: `O(L)`** — обычный спуск.
- **`search` с `k` точками: `O(26^k · L)`** в худшем случае: каждая точка размножает путь максимум на 26 веток, а каждый путь идёт не глубже `L`. При `k ≤ 2` это не больше `676 · L`, и большинство веток обрываются рано.
- **Память `O(S)`** на trie (`S` — суммарная длина слов) плюс `O(L)` на стек рекурсии.

## Типичные ошибки

1. **Базовый случай `return true`** вместо `return node.isEnd` → шаблон-префикс совпадает со словом длиннее.
2. **Возвращать результат первой же ветки на точке** (`return dfs(child, i + 1)` внутри цикла) → проверяется только первый ребёнок.
3. **Перебирать 26 букв на точке и строить строки для `Set`** → работает, но медленно и громоздко.
4. **Хранить слова в `Set` и делать регулярное выражение на каждый запрос** → `O(N · L)` на запрос, таймаут на больших тестах.
5. **Забыть, что `'.'` бывает только в запросах**, и обрабатывать точки при вставке → лишний код и путаница.

## Как узнать такую задачу

- Словарь слов + запросы с **подстановочным символом** (`.`, `?`) на отдельные позиции.
- Много запросов по общему набору слов, и нужно отсекать группы слов по префиксу.
- Сигнал: «любая буква» в позиции → ветвление DFS по детям узла trie. Похожие задачи: Implement Trie, Word Search II, Replace Words, поиск с одной ошибкой (Implement Magic Dictionary).
