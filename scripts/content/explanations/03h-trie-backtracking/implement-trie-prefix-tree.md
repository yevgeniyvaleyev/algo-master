## Задача простыми словами

Нужно написать класс `Trie` с тремя методами: `insert(word)` добавляет слово, `search(word)` отвечает, было ли **ровно это слово** вставлено, а `startsWith(prefix)` — начинается ли с `prefix` **хотя бы одно** вставленное слово.

Пример: после `insert("apple")` вызов `search("apple")` вернёт `true`, `search("app")` — `false` (такого слова не вставляли), а `startsWith("app")` — `true` (есть `"apple"`). После `insert("app")` уже и `search("app")` вернёт `true`.

## Наивный подход

Самое простое — хранить все слова в массиве (или в `Set`):

```ts naive
class Trie {
  private words = new Set<string>();
  insert(word: string) { this.words.add(word); }
  search(word: string) { return this.words.has(word); }
  startsWith(prefix: string) {
    for (const w of this.words) if (w.startsWith(prefix)) return true;
    return false;
  }
}
```

`insert` и `search` здесь быстрые (`O(L)` на хеширование строки), а вот `startsWith` — `O(N · L)`: перебираем **все** слова и у каждого сравниваем начало. При `3 · 10⁴` операций и тысячах слов это уже миллионы сравнений.

Где лишняя работа? Слова `"apple"`, `"apply"`, `"app"` имеют общее начало `"app"`, но `Set` хранит их независимо, и проверка префикса заново сравнивает эти три буквы у каждого слова. Общие префиксы никак не переиспользуются.

## Ключевое наблюдение

Если хранить слова как **дерево**, где каждое ребро — одна буква, то все слова с общим началом проходят по **одному и тому же пути** от корня. Тогда:

- проверка префикса — это просто спуск по `L` рёбрам: путь существует → есть слово с таким началом;
- проверка слова — тот же спуск плюс вопрос «заканчивается ли здесь какое-то вставленное слово?».

Время каждой операции зависит только от длины запроса `L`, а не от числа слов в структуре.

## Техники

### Префиксное дерево (trie)

**Что это.** Trie — дерево, в котором каждый узел соответствует некоторому **префиксу**, а переход к ребёнку — добавлению одной буквы. Корень — пустой префикс. Слово — путь от корня; конец слова отмечается флагом в узле.

```
insert("app"), insert("apple"), insert("bat"):

        (root)
        /    \
       a      b
       |      |
       p      a
       |      |
       p*     t*
       |
       l
       |
       e*          * — isEnd = true
```

**Типичный шаблон.** Почти все операции над trie — это «спуск по символам строки»: начинаем с корня, на каждом шаге берём ребёнка по текущей букве. При вставке недостающих детей создаём, при поиске — останавливаемся, если ребёнка нет.

**Когда применять.** Запросы по **префиксам** (автодополнение, «есть ли слово с таким началом»), поиск множества слов одновременно (Word Search II), шаблоны с подстановочными символами (Add and Search Word). Подробнее — во вкладке «Теория».

### Общий вспомогательный метод (спуск `walk`)

`search` и `startsWith` отличаются только последней проверкой, поэтому сам спуск вынесен в приватный метод `walk`, который возвращает узел конца пути или `null`. Это убирает дублирование и делает разницу между двумя методами видимой в одной строке.

## Разбор кода

```ts
// Узел дерева: переходы по символам и признак конца слова
class TrieNode {
  children = new Map<string, TrieNode>();
  isEnd = false;
}
```

Узел хранит две вещи. `children` — словарь «буква → дочерний узел»: это рёбра дерева. `isEnd` — заканчивается ли в этом узле какое-то вставленное слово. Без этого флага нельзя отличить «вставлено `"app"`» от «вставлено `"apple"`, а `"app"` — лишь его начало».

```ts
class Trie {
  // Корень соответствует пустому префиксу
  private root = new TrieNode();
```

Корень не соответствует ни одной букве — это пустая строка, начало любого пути. Он создаётся один раз в конструкторе.

```ts
  insert(word: string): void {
    let node = this.root;
    for (const ch of word) {
      // Нет ребра по символу — создаём новый узел
      if (!node.children.has(ch)) {
        node.children.set(ch, new TrieNode());
      }
      node = node.children.get(ch)!;
    }
```

Вставка — спуск от корня по буквам слова. Если ребро по букве `ch` уже есть (это слово делит префикс с ранее вставленным), просто идём по нему. Если нет — создаём новый узел. После `if` ребёнок гарантированно существует, поэтому `!` (non-null assertion) безопасен.

```ts
    // Помечаем, что здесь заканчивается вставленное слово
    node.isEnd = true;
  }
```

После цикла `node` — узел последней буквы. Ставим флаг: здесь кончается слово. Повторная вставка того же слова ничего не создаёт и просто ещё раз ставит `true`.

```ts
  search(word: string): boolean {
    // Слово есть, только если путь существует И в конце стоит пометка
    const node = this.walk(word);
    return node !== null && node.isEnd;
  }
```

Слово найдено, только если выполнены **оба** условия: путь по всем буквам существует и в конечном узле стоит `isEnd`. Проверка `node !== null` идёт первой — иначе обращение к `isEnd` у `null` упало бы.

```ts
  startsWith(prefix: string): boolean {
    // Для префикса достаточно, чтобы путь существовал
    return this.walk(prefix) !== null;
  }
```

Для префикса достаточно существования пути. Почему этого хватает: узлы создаются только при вставке, поэтому каждый узел лежит на пути какого-то вставленного слова — значит, у префикса есть продолжение до реального слова.

```ts
  // Спускаемся по символам строки; null — если путь обрывается
  private walk(s: string): TrieNode | null {
    let node: TrieNode = this.root;
    for (const ch of s) {
      const next = node.children.get(ch);
      if (!next) return null;
      node = next;
    }
    return node;
  }
}
```

Общий спуск. На каждом шаге берём ребёнка по букве; если его нет — путь оборвался, такой строки (и даже префикса) в дереве нет, возвращаем `null`. Если все буквы пройдены — возвращаем узел, в котором остановились. В отличие от `insert`, здесь ничего не создаётся: поиск не должен менять структуру.

## Трассировка

Последовательность из условия:

1. `insert("apple")`: у корня нет `a` → создаём; дальше создаём `p`, `p`, `l`, `e`. В узле `e` ставим `isEnd = true`. Путь: `root → a → p → p → l → e*`.
2. `search("apple")`: `walk` проходит все 5 рёбер, возвращает узел `e`; `isEnd = true` → `true`.
3. `search("app")`: `walk` проходит `a → p → p`, возвращает второй `p`; у него `isEnd = false` → `false`.
4. `startsWith("app")`: `walk` вернул тот же узел `p` (не `null`) → `true`.
5. `insert("app")`: все три ребра уже есть, новых узлов не создаётся; во втором `p` ставим `isEnd = true`.
6. `search("app")`: тот же узел, теперь `isEnd = true` → `true`.

Дополнительно: `startsWith("b")` — у корня нет ребёнка `b`, `walk` сразу возвращает `null` → `false`.

## Почему это работает

Инвариант: узел, до которого можно дойти от корня по строке `s`, существует **тогда и только тогда**, когда `s` — префикс хотя бы одного вставленного слова. В одну сторону: `insert` создаёт узлы ровно для всех префиксов вставляемого слова. В другую: узлы больше нигде не создаются, а `walk` ничего не добавляет.

Второй инвариант: `isEnd` у узла строки `s` равен `true` тогда и только тогда, когда `s` вставлялось целиком — флаг ставится только в конце `insert` и никогда не сбрасывается. Из этих двух фактов следуют ответы `search` и `startsWith`.

## Пограничные случаи

- **Слово — префикс другого** (`"app"` и `"apple"`): общие узлы, различаются только флагом `isEnd`.
- **Повторная вставка** того же слова: дерево не меняется.
- **Поиск длиннее любого слова** (`search("apples")`): путь обрывается на `s`, `walk` вернёт `null`.
- **Префикс равен целому слову** (`startsWith("apple")`): путь есть → `true`.
- **Поиск в пустом дереве**: у корня нет детей → `null` на первой букве.

## Сложность

- **Время `O(L)`** на каждую операцию, где `L` — длина слова или префикса: один шаг на букву, а `get`/`has`/`set` у `Map` — `O(1)`. От количества вставленных слов время не зависит.
- **Память `O(S)`**, где `S` — суммарная длина вставленных слов: в худшем случае (слова без общих префиксов) — по узлу на каждую букву. Общие префиксы хранятся один раз, так что на практике меньше.

## Типичные ошибки

1. **`search` без проверки `isEnd`** → после `insert("apple")` слово `"app"` «находится», хотя его не вставляли.
2. **Обращение к `node.isEnd`, когда `node === null`** → `TypeError`; проверка на `null` должна идти первой.
3. **Создавать узлы во время поиска** (переиспользовать код `insert`) → `startsWith` начинает возвращать `true` для всего, что когда-то искали.
4. **Ставить `isEnd` на каждом узле пути** при вставке → любой префикс считается словом.
5. **Хранить в узле одну строку-суффикс** вместо детей по буквам → теряется главное свойство: общий префикс в одном месте.

## Как узнать такую задачу

- Много запросов вида «есть ли слово, **начинающееся** на …», автодополнение, словарь с поиском по префиксу.
- Нужно сопоставлять строки **посимвольно** со словарём: поиск многих слов сразу (Word Search II), шаблоны с `.` (Design Add and Search Words), замена слов их корнями (Replace Words), максимальный XOR (trie по битам).
- Ограничения «только строчные латинские буквы» часто намекают на trie с 26 детьми в узле.
