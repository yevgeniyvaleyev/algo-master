## Задача простыми словами

Дано число `n` — количество пар скобок. Нужно вернуть **все правильные скобочные последовательности** из `n` пар `()`. Правильная — значит, каждая открывающая скобка закрыта, и закрывающая никогда не идёт раньше своей открывающей.

Пример: `n = 3` — ответ из 5 строк: `["((()))", "(()())", "(())()", "()(())", "()()()"]`. А `"())(()"` неправильная: после `"())"` закрывающих больше, чем открывающих.

## Наивный подход

Сгенерировать **все** строки длины `2n` из символов `(` и `)` и оставить правильные:

```ts naive
const all: string[] = [];
const gen = (s: string) => {
  if (s.length === 2 * n) { if (isValid(s)) all.push(s); return; }
  gen(s + '(');
  gen(s + ')');
};

function isValid(s: string): boolean {
  let balance = 0;
  for (const ch of s) {
    balance += ch === '(' ? 1 : -1;
    if (balance < 0) return false;
  }
  return balance === 0;
}
```

Строк `2^(2n)`, каждая проверяется за `O(n)`. При `n = 8` это `65 536` строк, а правильных среди них всего `1 430`. Лишняя работа: строка, начавшаяся с `")"`, уже безнадёжна, но мы достраиваем её до конца — все `2^(2n-1)` её продолжений — и лишь потом выбрасываем.

## Ключевое наблюдение

Проверку `isValid` можно «размазать» по построению: следить за двумя счётчиками — сколько поставлено открывающих (`open`) и закрывающих (`close`) — и **никогда не делать недопустимый ход**:

- `(` можно поставить, пока `open < n` — иначе открывающих станет больше, чем пар;
- `)` можно поставить, только если `close < open` — есть незакрытая открывающая, баланс не уйдёт в минус.

Любой префикс, построенный по этим правилам, **дополняется** до правильной последовательности (дописать недостающие `(`, затем все `)`). Значит, тупиковых веток нет вовсе: каждый лист дерева — готовый ответ.

## Техники

### Перебор с возвратом (backtracking) с ограничениями

**Что это.** Backtracking строит решение по символу: выбор → рекурсия → откат. Ограничения проверяются **до** выбора, поэтому недопустимые ветки не создаются. Чем точнее условия, тем меньше работы; в идеале (как здесь) каждая ветка приводит к решению.

**Типичный шаблон с двумя вариантами на шаге:**

```ts naive
backtrack(состояние):
  if (готово) { сохранить; return; }
  if (можно вариант A) { сделать A; backtrack(новое состояние); отменить A; }
  if (можно вариант B) { сделать B; backtrack(новое состояние); отменить B; }
```

**Как применяется здесь.** Состояние — пара счётчиков `(open, close)` и путь `path`. Вариант A — `(`, вариант B — `)`. Подробнее — во вкладке «Теория».

### Баланс скобок

Классический инвариант для скобочных последовательностей: баланс `open - close` в любом префиксе неотрицателен, а в конце равен нулю. Это то же правило, что проверяет стек в задаче Valid Parentheses, но для одного вида скобок стек сводится к счётчику.

## Разбор кода

```ts
function generateParenthesis(n: number): string[] {
  const result: string[] = [];
  const path: string[] = [];
```

`result` копит ответ, `path` — текущая строящаяся последовательность в виде массива символов (`push`/`pop` дешевле, чем создание новых строк на каждом шаге).

```ts
  // open / close — сколько открывающих и закрывающих скобок уже поставлено
  const backtrack = (open: number, close: number): void => {
    // Поставили все 2n скобок — последовательность правильная по построению
    if (path.length === 2 * n) {
      result.push(path.join(''));
      return;
    }
```

Счётчики передаются параметрами: при возврате из рекурсии они «откатываются» сами, ведь у каждого вызова свои значения. Базовый случай: в пути `2n` символов. Проверять правильность не нужно — правила хода её гарантируют. `join('')` создаёт новую строку-снимок.

```ts
    // Открывающую можно ставить, пока не израсходовали все n
    if (open < n) {
      path.push('(');
      backtrack(open + 1, close);
      path.pop();
    }
```

Ветка «поставить `(`». Разрешена, пока открывающих меньше `n`. После рекурсии убираем символ — путь снова такой, каким был при входе.

```ts
    // Закрывающую — только если есть незакрытая открывающая
    if (close < open) {
      path.push(')');
      backtrack(open, close + 1);
      path.pop();
    }
  };
```

Ветка «поставить `)`». Разрешена, только если закрывающих меньше, чем открывающих, — тогда баланс после хода останется `≥ 0`. Обе ветки независимы: если разрешены обе, пробуем обе по очереди. Порядок (`(` раньше `)`) даёт ответ в лексикографическом порядке, так как код `(` меньше кода `)`.

```ts
  backtrack(0, 0);
  return result;
}
```

Старт: ни одной скобки не поставлено.

## Трассировка

`n = 2`:

```
bt(0,0) path=""
  '(' → bt(1,0) "("
    '(' → bt(2,0) "(("
      open<2? нет
      ')' → bt(2,1) "(()"
        open<2? нет
        ')' → bt(2,2) "(())" → длина 4, сохранить
    ')' → bt(1,1) "()"
      '(' → bt(2,1) "()("
        ')' → bt(2,2) "()()" → сохранить
      close<open? 1<1 нет
  close<open? 0<0 нет — ")" в начале не ставится
```

Ответ `["(())", "()()"]`. Каждый лист оказался решением — ни одной отброшенной ветки. Для `n = 3` то же дерево даст 5 строк, начиная с `"((()))"` и заканчивая `"()()()"`.

## Почему это работает

Инвариант на каждом вызове: `0 ≤ close ≤ open ≤ n` и `path` — строка из `open` открывающих и `close` закрывающих, у которой баланс любого префикса неотрицателен.

- **Только правильные.** Ход `(` сохраняет `open ≤ n`; ход `)` разрешён при `close < open`, поэтому баланс не уходит в минус. В листе длина `2n` при `open ≤ n` и `close ≤ open` возможна только при `open = close = n` — баланс ноль. Это и есть определение правильной последовательности.
- **Все правильные.** Возьмём любую правильную последовательность и будем строить её по символу. Её `(` встречается, когда открывающих меньше `n`, а `)` — когда баланс префикса положителен, то есть `close < open`. Значит, каждый её ход разрешён, и она будет построена.
- **Без повторов.** Разные ветки различаются символом на какой-то позиции.
- **Нет тупиков.** Если `path.length < 2n`, то либо `open < n`, либо `open = n > close` — хотя бы один ход всегда разрешён.

## Пограничные случаи

- **`n = 1`**: единственная строка `"()"`.
- **`n = 8`** (максимум): `1 430` строк — перебор по-прежнему быстрый.
- **`)` в начале строки**: запрещена условием `close < open` (`0 < 0` ложно).
- **Порядок проверок**: если бы проверка `close < open` стояла первой, ответ был бы тем же множеством, просто в другом порядке.

## Сложность

- **Время `O(4^n / √n)`**: число ответов — `n`-е число Каталана `C(n) ~ 4^n / (n^{3/2} √π)`. Тупиков нет, поэтому каждый узел лежит на пути к какому-то листу, и узлов не больше `(2n + 1) · C(n)`, а каждый лист собирается `join` за `O(n)`. Итого `O(n · C(n)) = O(4^n / √n)`.
- **Память `O(n)`** дополнительно: глубина рекурсии и длина `path` — `2n`. Ответ занимает `O(n · C(n))` — это выходные данные.

## Типичные ошибки

1. **Условие `close < n`** вместо `close < open` → появляются строки вроде `"())("` с отрицательным балансом.
2. **Условие `open <= n`** → `n + 1` открывающая, строки длиннее нужного или неверные.
3. **`else if` между ветками** → когда разрешены оба хода, пробуется только первый, часть ответов теряется.
4. **Забыть `path.pop()`** в одной из веток → путь «засоряется», строки неправильные.
5. **Генерировать все `2^(2n)` строк и фильтровать** → верно, но экспоненциально больше работы.

## Как узнать такую задачу

- Нужно перечислить **все** строки/структуры, удовлетворяющие правилу, которое можно проверять **по префиксу** (баланс, лимит количества).
- Ответ — числа Каталана (скобки, бинарные деревья, триангуляции): верный признак рекурсивного построения.
- Сигнал: ограничение можно проверить до хода → backtracking без тупиков. Похожие задачи: Valid Parentheses (проверка), Remove Invalid Parentheses, Letter Combinations of a Phone Number, Unique Binary Search Trees II.
