## Задача простыми словами

Даны числа `n` и `k`. Нужно вернуть **все сочетания** из `k` чисел, выбранных из диапазона `1..n`. Сочетание — это набор без учёта порядка: `[1, 2]` и `[2, 1]` — одно и то же, в ответе оно должно быть один раз.

Пример: `n = 4`, `k = 2`. Ответ — 6 пар: `[1,2], [1,3], [1,4], [2,3], [2,4], [3,4]`. Их число — биномиальный коэффициент `C(4, 2) = 6`.

## Наивный подход

Первая идея — перебрать все **подмножества** `1..n` (их `2^n`, например через битовые маски) и оставить те, в которых ровно `k` элементов:

```ts naive
for (let mask = 0; mask < 1 << n; mask++) {
  if (popcount(mask) !== k) continue;
  const comb: number[] = [];
  for (let i = 0; i < n; i++) if (mask & (1 << i)) comb.push(i + 1);
  result.push(comb);
}
```

Это `O(2^n · n)`. При `n = 20`, `k = 2` подмножеств миллион, а нужных — всего 190. Лишняя работа: мы **строим и отбрасываем** подмножества неподходящего размера.

Другая ошибка — перебирать «любое число на каждую позицию» (как в перестановках). Тогда каждое сочетание появится `k!` раз в разном порядке, и придётся удалять дубликаты.

## Ключевое наблюдение

Чтобы каждое сочетание получилось **ровно один раз**, договоримся строить его **по возрастанию**: после числа `x` разрешено брать только числа больше `x`. Тогда у каждого набора есть единственный способ построения — его отсортированный вид.

Значит, рекурсии достаточно знать одно число — `start`, наименьшее число, которое ещё можно взять. Всё остальное — стандартный шаблон «выбрать — углубиться — откатить».

## Техники

### Перебор с возвратом (backtracking) с растущим началом

**Что это.** Backtracking строит решение по шагам: выбор → рекурсия → откат. Для **сочетаний и подмножеств** к нему добавляют параметр `start` — наименьший индекс, с которого можно выбирать дальше. Так элементы в пути всегда идут по возрастанию, и порядок выбора не порождает дубликатов.

**Типичный шаблон:**

```ts naive
backtrack(start):
  if (путь полный) { сохранить копию; return; }
  for (x = start; x <= последний; x++) {
    path.push(x);      // выбор
    backtrack(x + 1);  // углубление
    path.pop();        // откат
  }
```

**Как применяется здесь.** `start` — наименьшее число, которое ещё можно взять; рекурсия вызывается с `x + 1`; путь полон, когда в нём `k` чисел. Тот же шаблон используется в Combination Sum и (с множествами занятости вместо `start`) в N-Queens. Подробнее — во вкладке «Теория».

## Разбор кода

```ts
function combine(n: number, k: number): number[][] {
  const result: number[][] = [];
  const path: number[] = [];
```

`result` — ответ, `path` — текущее строящееся сочетание. Один массив `path` на всю рекурсию, меняется на месте.

```ts
  // start — наименьшее число, которое ещё можно взять
  const backtrack = (start: number): void => {
    // Набрали k чисел — сохраняем копию пути
    if (path.length === k) {
      result.push([...path]);
      return;
    }
```

Базовый случай: в пути `k` чисел — сочетание готово. Кладём **копию** `[...path]`: сам `path` дальше продолжит меняться, и без копии все элементы ответа оказались бы одним и тем же (в конце пустым) массивом.

```ts
    for (let x = start; x <= n; x++) {
      path.push(x); // выбор: берём x
      backtrack(x + 1); // дальше только числа больше x — без повторов порядка
      path.pop(); // откат: убираем x
    }
  };
```

Перебираем следующее число от `start` до `n`. Взяли `x` — рекурсивно добираем остальные **только из чисел больше `x`** (передаём `x + 1`). После возврата убираем `x` и пробуем следующее. Три строки тела цикла — это и есть весь backtracking.

```ts
  backtrack(1);
  return result;
}
```

Начинаем с числа `1` и пустого пути.

## Трассировка

`n = 4`, `k = 2`:

```
backtrack(1): path=[], x ∈ [1..4]
  x=1 → path=[1]
    backtrack(2): x ∈ [2..4]
      x=2 → [1,2] → сохранить
      x=3 → [1,3] → сохранить
      x=4 → [1,4] → сохранить
  x=2 → path=[2]
    backtrack(3): x ∈ [3..4]
      [2,3], [2,4]
  x=3 → path=[3]
    backtrack(4): x ∈ [4..4]
      [3,4]
  x=4 → path=[4]
    backtrack(5): цикл от 5 до 4 не выполняется — пустая ветка
```

Итог: `[[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]]` — 6 сочетаний. Последняя ветка `path = [4]` ничего не даёт: после 4 чисел нет. Именно такие ветки убирает отсечение из раздела «Сложность».

## Почему это работает

Инвариант: при входе в `backtrack(start)` числа в `path` строго возрастают, и все они меньше `start`.

- **Каждое сочетание найдётся.** Возьмём сочетание и отсортируем: `a₁ < a₂ < … < a_k`. На первом уровне цикл дойдёт до `a₁`, на втором — до `a₂` (так как `a₂ > a₁`, оно не меньше `start = a₁ + 1`), и так далее до `a_k`, после чего длина пути равна `k`.
- **Ровно один раз.** Путь всегда возрастает, значит, каждое сочетание строится только в своём отсортированном порядке.
- **Ничего лишнего.** В ответ попадают только пути длины ровно `k` из различных чисел `1..n`.

## Пограничные случаи

- **`k = n`**: единственное сочетание `[1..n]`. Например, `n = 20`, `k = 20` — один ответ `[1..20]`, хотя без отсечения рекурсия обходит и пустые ветки.
- **`k = 1`**: `n` одноэлементных наборов.
- **`n = 1`, `k = 1`**: `[[1]]`.
- **Копия пути**: без `[...path]` ответ состоит из ссылок на один пустой массив.

## Сложность

- **Время `O(C(n, k) · k)`** на построение ответа: решений `C(n, k)`, каждое копируется за `O(k)`. Без отсечения рекурсия ещё заходит в тупиковые ветки (в худшем случае узлов порядка `2^n`), но при `n ≤ 20` это быстро.
- **Память `O(k)`** дополнительно: глубина рекурсии и длина пути не больше `k`. Ответ занимает `O(C(n, k) · k)` — это выходные данные.

**Follow-up на собеседовании — отсечение.** Если осталось добрать `need = k - path.length` чисел, то следующее число не может быть больше `n - need + 1` (после него должно остаться ещё `need - 1` чисел). Достаточно сменить границу цикла:

```ts naive
const need = k - path.length;
for (let x = start; x <= n - need + 1; x++) { ... }
```

Ответ не меняется, но каждая ветка теперь ведёт хотя бы к одному решению, и тупиковых вызовов (как `path = [4]` в трассировке) больше нет.

## Типичные ошибки

1. **`result.push(path)` без копии** → все элементы ответа — один и тот же массив.
2. **Рекурсия с `start` вместо `x + 1`** → одно число берётся повторно (`[1,1]`).
3. **Цикл от 1, а не от `start`** → дубликаты `[1,2]` и `[2,1]`.
4. **Забыть `path.pop()`** → путь растёт, ответ неверен.
5. **Ошибка на единицу в отсечении** (если добавлять его: `n - need` вместо `n - need + 1`) → теряются сочетания с последним числом (`[3,4]`).

## Как узнать такую задачу

- Нужно перечислить **наборы без учёта порядка** заданного размера — «выбрать `k` из `n`».
- Ответ — все варианты, а ограничения маленькие (`n ≤ 20`) → backtracking.
- Признак шаблона с `start`: «комбинации», «подмножества», «без повторов в разном порядке». Похожие задачи: Subsets, Combination Sum (с повтором элементов — рекурсия с `i`, а не `i + 1`), Combination Sum III, Permutations (там порядок важен — `used` вместо `start`).
