## Задача простыми словами

Дан непустой массив целых чисел `nums`. Каждое число встречается в нём **ровно два раза**, и только одно — **один раз**. Нужно найти это одиночное число. Ограничения жёсткие: время `O(n)` и **константная** дополнительная память.

Пример: `nums = [4, 1, 2, 1, 2]`. Единицы и двойки встречаются парами, `4` — одна. Ответ `4`.

## Наивный подход

Посчитать, сколько раз встречается каждое число, и вернуть то, что встретилось один раз:

```ts naive
const count = new Map<number, number>();
for (const x of nums) count.set(x, (count.get(x) ?? 0) + 1);
for (const [x, c] of count) if (c === 1) return x;
```

Или через `Set`: добавляем число, если его нет, и удаляем, если есть, — в конце в множестве останется одиночка. Оба варианта `O(n)` по времени, но **`O(n)` по памяти**: мы храним почти половину массива. Ещё вариант — отсортировать и искать элемент без пары рядом: памяти `O(1)`, но время `O(n log n)`.

Лишняя работа здесь — **хранение**: мы помним каждое число отдельно, хотя нас интересует только одно. Нужна операция, которая сама «сокращает» пары, не запоминая их.

## Ключевое наблюдение

У исключающего ИЛИ (XOR, оператор `^`) есть три свойства:

- `a ^ a = 0` — число, «сложенное» с собой, исчезает;
- `a ^ 0 = a` — ноль ничего не меняет;
- XOR **коммутативен и ассоциативен** — порядок и группировка не важны.

Значит, XOR всех элементов массива можно мысленно переставить так, чтобы пары стояли рядом:

```
4 ^ 1 ^ 2 ^ 1 ^ 2 = 4 ^ (1 ^ 1) ^ (2 ^ 2) = 4 ^ 0 ^ 0 = 4
```

Каждая пара обнулится, останется одиночный элемент. Достаточно одной переменной.

## Техники

### XOR как «сокращение пар»

**Что это.** XOR работает побитово: в результате бит равен `1`, если у операндов этот бит **разный**. Удобно думать о XOR как о сложении битов **по модулю 2**, без переносов. Отсюда и `a ^ a = 0`: каждый бит встречается чётное число раз и обнуляется.

Если XOR-ить много чисел, то в каждом разряде результата будет `1`, только если в этом разряде у **нечётного** количества чисел стоит `1`. Все числа, встречающиеся чётное число раз, на результат не влияют.

**Типичные применения:**

- найти элемент, встречающийся нечётное число раз (эта задача);
- найти пропущенное число в `0..n` (Missing Number): XOR всех индексов и всех значений;
- поменять местами две переменные без третьей (`a ^= b; b ^= a; a ^= b`);
- найти **два** одиночных числа (Single Number III): XOR всех даёт `a ^ b`, по любому установленному биту делим массив на две группы.

**Шаблон:**

```ts naive
let acc = 0;
for (const x of items) acc ^= x;
// acc — XOR всех элементов
```

**Как применяется здесь.** Просто XOR всего массива. Подробнее о битовых операциях — во вкладке «Теория».

## Разбор кода

```ts
function singleNumber(nums: number[]): number {
  // x ^ x = 0 и x ^ 0 = x, а порядок XOR не важен.
  // Поэтому все пары взаимно уничтожатся, останется одиночный элемент
  let result = 0;
```

Начинаем с `0` — нейтрального элемента XOR (`x ^ 0 = x`), как `0` для сложения или `1` для умножения. Если начать с `nums[0]`, придётся пропускать первый элемент в цикле — лишняя деталь, где легко ошибиться.

```ts
  for (const num of nums) {
    result ^= num;
  }
```

Один проход: накапливаем XOR всех чисел. В промежуточных состояниях `result` — это XOR «ещё не закрытых» чисел: если `1` встретилась один раз, она «висит» в `result`, а когда встретится вторая `1`, она её «закроет». Промежуточные значения могут выглядеть случайными (например, `7`, которого нет в массиве), — это нормально, смысл имеет только итог.

```ts
  return result;
}
```

После прохода все пары сократились, в `result` — одиночный элемент.

## Трассировка

`nums = [4, 1, 2, 1, 2]`, в двоичной записи (3 бита):

```
шаг  num      result до   result после
1    4 (100)  000         100 (4)
2    1 (001)  100         101 (5)
3    2 (010)  101         111 (7)
4    1 (001)  111         110 (6)
5    2 (010)  110         100 (4)
```

Ответ `4`. На шаге 4 вторая единица «выключила» младший бит, который включила первая; на шаге 5 вторая двойка выключила средний бит.

С отрицательным числом, `nums = [-3, 5, -3]`:

1. `result = 0 ^ -3 = -3`.
2. `result = -3 ^ 5`. В 32-битном дополнительном коде `-3 = …11111101`, `5 = …00000101`; XOR = `…11111000` = `-8`.
3. `result = -8 ^ -3`: `…11111000 ^ …11111101 = …00000101` = `5`.

Ответ `5` — отрицательные числа сокращаются так же, как положительные.

## Почему это работает

Рассмотрим любой бит `b`. Его значение в итоговом `result` равно чётности количества чисел, у которых бит `b` равен `1`. Каждое число из пары даёт в этот бит одинаковый вклад дважды — чётное количество, не влияет на чётность. Значит, бит `b` результата совпадает с битом `b` одиночного числа. Так для всех битов — `result` равен одиночному числу.

То же самое алгебраически: благодаря коммутативности и ассоциативности XOR всего массива равен `single ^ (a ^ a) ^ (b ^ b) ^ … = single ^ 0 ^ 0 ^ … = single`.

## Пограничные случаи

- **Один элемент** (`[1]`): `0 ^ 1 = 1`.
- **Одиночка — первый или последний**: порядок не важен, XOR коммутативен.
- **Отрицательные числа**: в JS `^` работает с 32-битным дополнительным кодом; числа по модулю до `3 · 10⁴` помещаются без потерь, и `x ^ x = 0` для любых знаков.
- **Одиночка равен `0`** (`[0, 7, 7]`): результат `0` — корректно, хотя `0` совпадает с начальным значением.

## Сложность

- **Время `O(n)`**: один проход, одна операция `^` на элемент.
- **Память `O(1)`**: единственная переменная `result`, независимо от размера массива.

## Типичные ошибки

1. **`Map`/`Set`** — верно, но нарушает требование `O(1)` памяти.
2. **Путать `^` со степенью**: в JS `^` — это XOR, а степень — `**`.
3. **Сумма вместо XOR**: `2 · sum(уникальных) − sum(всех)` даёт ответ, но требует `Set` (память `O(n)`) и в других языках может переполниться.
4. **Перенос решения на Single Number II** (каждое число встречается **трижды**): XOR там не работает, нужен подсчёт битов по модулю 3.
5. **Начать с `result = nums[0]` и цикл с `0`** → первый элемент XOR-ится дважды и пропадает.

## Как узнать такую задачу

- «Каждый элемент встречается **дважды** (чётное число раз), кроме одного» + требование **`O(1)` памяти** — почти наверняка XOR.
- «Найдите пропущенное/лишнее число», если есть «парный» набор для сравнения (индексы `0..n`, две почти одинаковые строки — Find the Difference).
- Родственные задачи: Missing Number, Single Number II и III, Find the Difference, Hamming Distance.
