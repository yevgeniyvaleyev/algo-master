## Задача простыми словами

Дано 32-битное число `n`. Нужно **перевернуть порядок его битов**: бит 0 (младший) становится битом 31 (старшим), бит 1 — битом 30, и так далее. Вернуть получившееся число. Важно: число всегда рассматривается как ровно **32 бита**, включая ведущие нули.

Пример (для наглядности возьмём маленькое число): `n = 13`, в 32 битах это `00…0001101` (28 нулей и `1101`). Перевёрнутое — `1011` и 28 нулей: `10110000…0`, то есть `2952790016`.

## Наивный подход

Перевести число в строку из 32 символов, развернуть строку и перевести обратно:

```ts naive
const s = (n >>> 0).toString(2).padStart(32, '0');
return parseInt(s.split('').reverse().join(''), 2);
```

Это работает, но создаёт строку, массив из 32 символов, ещё одну строку — много аллокаций ради операции, которая целиком помещается в один регистр процессора. А главное, такой код прячет то, что проверяет задача: умение **работать с битами напрямую** — сдвигами и масками. Ещё одна ловушка наивного подхода — забыть `padStart`: без него ведущие нули потеряются и результат будет неверным.

## Ключевое наблюдение

Переворот — это «переложить стопку»: снимаем биты с **младшего** конца `n` по одному и кладём их на **младший** конец `result`, каждый раз сдвигая `result` влево. Бит, положенный первым, за последующие сдвиги уедет дальше всех — в старший разряд. Так порядок и переворачивается.

Нужно сделать **ровно 32** шага: даже когда в `n` остались одни нули, они должны «проехать» в `result` и сдвинуть уже положенные биты на свои места.

## Техники

### Побитовый перенос через сдвиги и маски

**Что это.** Базовые операции работы с битами:

- `n & 1` — взять младший бит (маска `…0001`);
- `n >>> 1` — сдвинуть вправо, отбросив младший бит;
- `r << 1` — сдвинуть влево, освободив младший бит (в нём появится `0`);
- `r | bit` — записать `bit` в освободившийся младший разряд.

**Типичный шаблон** «прочитать биты одного числа и собрать другое»:

```ts naive
for (let i = 0; i < 32; i++) {
  const bit = n & 1;
  r = (r << 1) | bit;
  n >>>= 1;
}
```

Тот же каркас, только в десятичной системе (`% 10`, `/ 10`, `* 10 +`), — у разворота цифр числа (Reverse Integer, Palindrome Number). Подробнее о битовых операциях — во вкладке «Теория».

### 32-битная арифметика в JavaScript

В JS битовые операторы (`&`, `|`, `<<`, `>>`) сначала приводят операнды к **знаковому 32-битному** целому. Отсюда две особенности:

- если в бит 31 попала `1`, результат операции — **отрицательное** число;
- `>>` (арифметический сдвиг) копирует знаковый бит: у отрицательного числа слева «заезжают» единицы. `>>>` (логический сдвиг) всегда дописывает нули и возвращает беззнаковое число.

Приём `x >>> 0` не меняет ни одного бита, а лишь **читает те же 32 бита как беззнаковое** число от `0` до `2^32 - 1`.

```ts
  // Ровно 32 шага: переносим биты n в result в обратном порядке
  for (let i = 0; i < 32; i++) {
```

Цикл с фиксированным числом итераций. Именно `32`, а не `while (n > 0)`: если остановиться, когда `n` стал нулём, ведущие нули `n` не попадут в `result`, и уже собранные биты окажутся сдвинуты недостаточно далеко влево.

```ts
    // Сдвигаем result влево, освобождая младший бит,
    // и записываем туда текущий младший бит n
    result = (result << 1) | (n & 1);
```

Главная строка. `n & 1` — младший бит `n` (0 или 1). `result << 1` сдвигает всё, что уже собрано, на позицию влево; в младшем разряде появляется `0`, и `| (n & 1)` записывает туда текущий бит. Бит, записанный на шаге `i`, затем сдвинется ещё `31 - i` раз и окажется в разряде `31 - i` — ровно зеркальная позиция для бита `i` исходного числа.

```ts
    // Убираем обработанный бит из n.
    // >>> (а не >>) слева дописывает нули, даже если n «отрицательное»
    n >>>= 1;
  }
```

Сдвигаем `n` вправо, чтобы на следующем шаге в младшем разряде оказался следующий бит. Почему `>>>`: если на входе у `n` установлен бит 31 (например, `n = 4294967293` или после приведения — отрицательное число), обычный `>>` дописывал бы слева копии знакового бита — единицы, и `n` в итоге превратилось бы в `-1`, а не в `0`. С `>>>` слева заходят нули — ровно то, что нужно. (Строго говоря, при ровно 32 итерациях каждый исходный бит читается до того, как до младшего разряда доберутся «заехавшие» слева биты, так что здесь и `>>` дал бы верный ответ. Но `>>>` делает код корректным без этого тонкого рассуждения и не ломается, если кто-то перепишет цикл на `while (n !== 0)`.)

```ts
  // Битовые операции в JS дают знаковое 32-битное число:
  // если старший бит стал 1, result < 0. >>> 0 читает те же биты как беззнаковые
  return result >>> 0;
}
```

Если младший бит исходного `n` был `1`, после 32 сдвигов он стоит в бите 31 — и `result`, полученный через `<<` и `|`, будет **отрицательным**. Ожидаемый же ответ — беззнаковое число. `>>> 0` переинтерпретирует биты без изменений: `-1342177280` превратится в `2952790016`.

## Трассировка

`n = 13` (`…0000 1101`). Отслеживаем младшие биты:

```
шаг  n&1  result после шага (двоичная)   n после >>>= 1
1    1    1                              6   (110)
2    0    10                             3   (11)
3    1    101                            1   (1)
4    1    1011                           0
5    0    10110                          0
6    0    101100                         0
...  0    каждый шаг дописывает 0 справа  0
32   0    1011 и 28 нулей                0
```

После шага 4 в `n` остались только нули, но цикл продолжается: ещё 28 сдвигов уносят `1011` в старшие биты. На шаге 32 `result << 1` ставит единицу в бит 31, и в JS `result = -1342177280` (знаковое прочтение). `result >>> 0` → `11 · 2^28 = 2952790016`.

Проверка «по смыслу»: биты `n` в 32-битной записи — `0000…1101`, перевёрнутые — `1011…0000`. Сходится.

## Почему это работает

Инвариант: после шага `k` (то есть `k` итераций) младшие `k` битов `result` — это биты `0, 1, …, k-1` исходного числа **в обратном порядке** (бит 0 — самый старший из них), а `n` сдвинуто на `k` вправо, так что его младший бит — исходный бит `k`.

Шаг `k + 1` сдвигает `result` влево (сохраняя порядок уже положенных битов) и дописывает в младший разряд исходный бит `k` — инвариант сохраняется. После 32 шагов `result` содержит все 32 бита в обратном порядке: исходный бит `i` стоит в разряде `31 - i`. Финальный `>>> 0` не меняет битов, только представление.

## Пограничные случаи

- **`n = 0`**: все биты нули, ответ `0`.
- **Младший бит `n` равен `1`**: ответ ≥ `2^31`, без `>>> 0` вернулось бы отрицательное число.
- **Старший бит `n` равен `1`** (на вход пришло число ≥ `2^31` или отрицательное знаковое): благодаря `>>>` при сдвиге не появляются лишние единицы.
- **Палиндромные битовые строки** (например, все единицы): ответ равен самому числу (`4294967295`).

## Сложность

- **Время `O(1)`**: ровно 32 итерации независимо от `n`, каждая — несколько битовых операций.
- **Память `O(1)`**: две числовые переменные.

**Follow-up «функцию вызывают много раз»:** заранее переворачиваем все 256 возможных байтов в таблицу, затем делим число на 4 байта, переворачиваем каждый по таблице и ставим на зеркальную позицию. 4 обращения к таблице вместо 32 итераций.

## Типичные ошибки

1. **`while (n > 0)` вместо ровно 32 шагов** → ведущие нули теряются, результат сдвинут неправильно (для `13` получится `11`, а не `2952790016`).
2. **Вернуть `result` без `>>> 0`** → отрицательное число вместо беззнакового.
3. **`n >>= 1` вместо `n >>>= 1`** → для чисел с единицей в бите 31 слева заезжают единицы (в общем случае опасно, хоть при 32 итерациях здесь и не успевает навредить).
4. **Перепутать порядок** `(result << 1) | bit` и `result | (bit << 1)` → бит пишется не в тот разряд.
5. **Через строку без `padStart(32, '0')`** → ведущие нули исчезают, разворачивается слишком короткая строка.

## Как узнать такую задачу

- В условии явно **«биты», «32-битное беззнаковое», «двоичное представление»**.
- Нужно переставить/прочитать биты числа по одному → цикл «`& 1`, сдвиг, `|`».
- Если операция над числом выглядит как операция над массивом (развернуть, посчитать, проверить) — думайте о числе как о массиве из 32 битов. Родственные задачи: Number of 1 Bits, Reverse Integer, Counting Bits, Power of Two, Single Number.
