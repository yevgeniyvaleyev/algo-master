## Задача простыми словами

Дано положительное целое число `n`. Нужно посчитать, **сколько единиц в его двоичной записи** (это число называют весом Хэмминга).

Пример: `n = 11`, в двоичной записи `1011` — три единицы, ответ `3`. Для `n = 128` (`10000000`) ответ `1`.

## Наивный подход

Проверить все 32 бита по очереди:

```ts naive
let count = 0;
for (let i = 0; i < 32; i++) {
  count += (n >>> i) & 1;
}
return count;
```

Или через строку: `n.toString(2).split('1').length - 1`. Оба варианта верны и работают за `O(32)`. Где лишняя работа? Мы **проверяем каждый бит, включая нули**. Для `n = 128` (одна единица) делаем 32 шага, хотя интересен только один бит. Хочется тратить время пропорционально количеству **единиц**, а не разрядов.

## Ключевое наблюдение

Выражение `n & (n - 1)` **сбрасывает ровно одну, самую младшую единицу** `n`, не трогая остальные биты. Почему: вычитание единицы «занимает» из младшей единицы — она становится `0`, а все нули правее неё становятся `1`. Биты левее не меняются:

```
n           = 1011000
n - 1       = 1010111
n & (n - 1) = 1010000   ← младшая единица исчезла
```

Значит, достаточно применять `n &= n - 1`, пока `n` не обнулится, и считать шаги. Шагов будет ровно столько, сколько в `n` единиц. Этот приём называют **алгоритмом Кернигана**.

## Техники

### Трюк `n & (n - 1)` (алгоритм Кернигана)

**Что это.** Однострочная операция «удалить младший установленный бит». Это один из самых полезных битовых приёмов, у него несколько типичных применений:

- **подсчёт единиц** — цикл до нуля, как здесь;
- **проверка степени двойки** — у степени двойки ровно одна единица, поэтому `n > 0 && (n & (n - 1)) === 0`;
- **перебор установленных битов** (например, подмножеств в битовой маске) — каждый шаг даёт следующую единицу.

Родственный приём — `n & -n`: он **оставляет** только младшую единицу (используется в дереве Фенвика).

**Типичный шаблон:**

```ts naive
while (n !== 0) {
  // обработать младшую единицу (при необходимости: n & -n)
  n &= n - 1;
}
```

**Как применяется здесь.** Каждая итерация убирает одну единицу и увеличивает счётчик. Подробнее о битовых операциях — во вкладке «Теория».

### 32-битные операции в JavaScript

Оператор `&` в JS приводит операнды к знаковому 32-битному целому. Для `n` до `2^31 - 1` (как в условии) это безопасно. Если бы на вход пришло число с единицей в бите 31, после приведения оно стало бы отрицательным; `n & (n - 1)` всё равно корректно сбрасывал бы младшую единицу, но промежуточные значения были бы отрицательными. Поэтому условие цикла записано как `n !== 0`, а не `n > 0`.

## Разбор кода

```ts
function hammingWeight(n: number): number {
  let count = 0;
```

Счётчик единиц. Ничего, кроме него и самого `n`, нам не понадобится.

```ts
  // Каждая итерация «гасит» одну единицу, поэтому
  // цикл выполнится ровно столько раз, сколько единиц в n
  while (n !== 0) {
```

Цикл идёт, пока в `n` есть хотя бы одна единица (число без единиц — это `0`). Сравнение `!== 0`, а не `> 0`, защищает от случая, когда `n` в 32-битном представлении отрицательное: отрицательное число тоже содержит единицы, и цикл не должен останавливаться.

```ts
    // n - 1 превращает младшую единицу в 0, а нули правее неё — в единицы.
    // n & (n - 1) поэтому сбрасывает ровно младшую единицу:
    // 1011 & 1010 = 1010, 1010 & 1001 = 1000, 1000 & 0111 = 0000
    n &= n - 1;
    count++;
  }
```

Сердце алгоритма. После `n &= n - 1`:

- младшая единица и всё правее неё в `n` — это `1000…0`, а в `n - 1` — `0111…1`; побитовое И даёт `0000…0`;
- все биты левее младшей единицы в `n` и `n - 1` одинаковые, и `&` их сохраняет.

Итог: ровно одна единица исчезла, значит `count++` считает её.

```ts
  return count;
}
```

Когда `n` стало нулём, все единицы погашены, и `count` равен их исходному количеству.

## Трассировка

`n = 11` (`1011`):

1. `n = 1011`, `n - 1 = 1010`, `n & (n - 1) = 1010` (10). `count = 1`.
2. `n = 1010`, `n - 1 = 1001`, `n & (n - 1) = 1000` (8). `count = 2`.
3. `n = 1000`, `n - 1 = 0111`, `n & (n - 1) = 0000` (0). `count = 3`.
4. `n === 0` → выход, ответ `3`.

`n = 128` (`10000000`):

1. `n - 1 = 01111111`, `n & (n - 1) = 0`. `count = 1`.
2. `n === 0` → ответ `1`. Одна итерация вместо 32 у наивного подхода.

## Почему это работает

Пусть младшая единица `n` стоит в разряде `k`. Тогда `n = X·2^(k+1) + 2^k`, где `X` — старшие биты, а разряды `0..k-1` нулевые. Вычитаем единицу: `n - 1 = X·2^(k+1) + (2^k - 1)` — старшие биты те же, разряд `k` стал `0`, разряды `0..k-1` стали единицами. Побитовое И: старшие биты дают `X` (совпадают), разряд `k` даёт `1 & 0 = 0`, младшие — `0 & 1 = 0`. Получаем `X·2^(k+1)` — то же число без младшей единицы.

Значит, каждая итерация уменьшает количество единиц ровно на одну, а цикл останавливается, когда их ноль. Число итераций = исходное число единиц = `count`.

## Пограничные случаи

- **`n = 0`** (если бы разрешили): цикл не выполняется, ответ `0`.
- **Степень двойки** (`1`, `128`, `2^30`): одна итерация.
- **Все биты единицы** (`2^31 - 1`): 31 итерация — худший случай для данных ограничений.
- **Число с единицей в бите 31** (за пределами ограничений): работает благодаря условию `n !== 0`; промежуточные значения отрицательные, но биты сбрасываются правильно, 32 итерации для `0xFFFFFFFF`.

## Сложность

- **Время `O(k)`**, где `k` — количество единичных битов (не больше 32): каждая итерация убирает ровно одну единицу. В худшем случае это те же 32 шага, но для разреженных чисел — намного меньше.
- **Память `O(1)`**: одна переменная-счётчик.

**Follow-up «функцию вызывают много раз»:** заранее посчитать число единиц для всех 256 байтов (`table[i] = table[i >> 1] + (i & 1)`) и складывать значения таблицы для 4 байтов числа — 4 обращения вместо цикла.

## Типичные ошибки

1. **`n & (n + 1)` или `n | (n - 1)`** вместо `n & (n - 1)` — это другие операции: первая сбрасывает хвост из младших единиц, вторая заполняет единицами хвост младших нулей.
2. **Условие `n > 0`** → для «отрицательного» 32-битного значения цикл не выполнится ни разу и вернёт `0`.
3. **Сдвиг `n >> 1` в наивном варианте** для чисел с единицей в бите 31 → слева заезжают единицы, цикл «пока `n !== 0`» никогда не закончится. Нужен `>>>`.
4. **Деление `n / 2` вместо сдвига** → в JS получаются дроби, `n % 2` перестаёт быть битом.
5. **Считать через `toString(2)` для отрицательного числа** → получится строка с минусом (`"-101"`), а не дополнительный код.

## Как узнать такую задачу

- «Количество единичных битов», «вес Хэмминга», «сколько бит различается» (тогда сначала `a ^ b`, потом считаем единицы — это Hamming Distance).
- «Является ли число степенью двойки», «перебрать все установленные биты маски» — тот же трюк `n & (n - 1)`.
- Родственные задачи: Counting Bits (единицы для всех чисел `0..n` через ДП `bits[i] = bits[i & (i - 1)] + 1`), Power of Two, Hamming Distance, Reverse Bits.
