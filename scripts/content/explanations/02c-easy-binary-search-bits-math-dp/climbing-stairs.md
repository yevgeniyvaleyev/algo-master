## Задача простыми словами

Лестница из `n` ступенек. За один ход можно подняться на `1` или на `2` ступеньки. Нужно посчитать, **сколькими различными способами** можно дойти до верха. Способы различаются последовательностью шагов.

Пример: `n = 3`. Способы: `1+1+1`, `1+2`, `2+1` — ответ `3`. Для `n = 2`: `1+1` и `2` — ответ `2`.

## Наивный подход

Рекурсия по последнему шагу: на ступеньку `n` попадаем либо с `n − 1`, либо с `n − 2`:

```ts naive
function ways(n: number): number {
  if (n <= 1) return 1;
  return ways(n - 1) + ways(n - 2);
}
```

Это верно, но **экспоненциально** — примерно `O(1.6^n)`. При `n = 45` — больше миллиарда вызовов. Лишняя работа видна на дереве вызовов: `ways(5)` вызывает `ways(4)` и `ways(3)`, а `ways(4)` снова вызывает `ways(3)`. Одни и те же подзадачи (**перекрывающиеся подзадачи**) пересчитываются заново на каждом пути.

```
           ways(5)
          /       \
     ways(4)     ways(3)
     /    \       /    \
ways(3) ways(2) ways(2) ways(1)
  ...
```

## Ключевое наблюдение

Ответ для ступеньки `i` зависит только от ответов для `i − 1` и `i − 2`:

```
ways(i) = ways(i − 1) + ways(i − 2),   ways(0) = 1, ways(1) = 1
```

Это **числа Фибоначчи**: 1, 1, 2, 3, 5, 8, 13, … Если считать их снизу вверх, от `0` к `n`, каждое значение вычисляется **один раз** — `O(n)`. Более того, для следующего шага нужны только **два последних** значения, так что массив на `n` элементов не нужен — хватит двух переменных.

## Техники

### Динамическое программирование (снизу вверх)

**Что это.** ДП применимо, когда у задачи есть **оптимальная подструктура** (ответ собирается из ответов подзадач) и **перекрывающиеся подзадачи**. Каждую подзадачу решаем один раз и запоминаем.

**Четыре вопроса для формулировки:**

1. **Состояние**: `dp[i]` — число способов добраться до ступеньки `i`.
2. **База**: `dp[0] = 1` (один способ — «ничего не делать»), `dp[1] = 1` (один шаг на 1).
3. **Переход**: последний шаг был либо `1` (с `i − 1`), либо `2` (с `i − 2`). Эти множества способов **не пересекаются** — они отличаются последним шагом, — поэтому их размеры складываются: `dp[i] = dp[i − 1] + dp[i − 2]`.
4. **Порядок и ответ**: `i` по возрастанию, ответ — `dp[n]`.

**Типичный шаблон с массивом:**

```ts naive
const dp = new Array(n + 1).fill(0);
dp[0] = 1; dp[1] = 1;
for (let i = 2; i <= n; i++) dp[i] = dp[i - 1] + dp[i - 2];
return dp[n];
```

Подробнее о ДП — во вкладке «Теория».

### Сжатие памяти: «скользящее окно» из двух значений

Если переход смотрит только на фиксированное число предыдущих состояний (здесь — на два), весь массив хранить не нужно: держим последние значения в переменных и «сдвигаем» их на каждом шаге. Память падает с `O(n)` до `O(1)`. Тот же приём — в House Robber, Min Cost Climbing Stairs, Fibonacci Number, N-th Tribonacci.

## Разбор кода

```ts
function climbStairs(n: number): number {
  // dp[i] — число способов дойти до ступеньки i.
  // На ступеньку i попадаем либо с i - 1 (шаг 1), либо с i - 2 (шаг 2):
  // dp[i] = dp[i - 1] + dp[i - 2]. Хватит двух последних значений.
  let prev = 1; // dp[0]: один способ — стоять на месте
  let curr = 1; // dp[1]: один способ — шаг на 1
```

Вместо массива — две переменные. Перед началом цикла `prev = dp[0]`, `curr = dp[1]`. База `dp[0] = 1` может показаться странной («способ дойти до нулевой ступеньки?»), но она нужна для формулы: `dp[2] = dp[1] + dp[0] = 2` — способы `1+1` и `2`, где второй — это «прыжок на 2 с нулевой ступеньки». Если взять `dp[0] = 0`, получится неверное `dp[2] = 1`.

```ts
  for (let i = 2; i <= n; i++) {
    const next = prev + curr;
```

Считаем `dp[i] = dp[i − 2] + dp[i − 1]`. На входе в итерацию `i` выполняется `prev = dp[i − 2]` и `curr = dp[i − 1]`, поэтому `next = dp[i]`.

```ts
    // Сдвигаем «окно» из двух значений на одну ступеньку вверх
    prev = curr;
    curr = next;
  }
```

Сдвигаем окно: старое `curr` (`dp[i − 1]`) становится `prev`, новое значение `dp[i]` — `curr`. Порядок присваиваний важен: если сначала написать `curr = next`, то старое `curr` потеряется, и `prev` получит неверное значение. Именно поэтому нужна временная переменная `next`.

```ts
  return curr;
}
```

После итерации `i = n` в `curr` лежит `dp[n]`. Если `n = 1`, цикл не выполняется ни разу, и возвращается начальное `curr = dp[1] = 1` — отдельной проверки не нужно.

## Трассировка

`n = 5`. Начало: `prev = 1` (`dp[0]`), `curr = 1` (`dp[1]`).

```
i   next = prev + curr   prev после   curr после
2   1 + 1 = 2            1            2      (dp[2])
3   1 + 2 = 3            2            3      (dp[3])
4   2 + 3 = 5            3            5      (dp[4])
5   3 + 5 = 8            5            8      (dp[5])
```

Ответ `8`. Проверка перебором для `n = 4` (`dp[4] = 5`): `1+1+1+1`, `1+1+2`, `1+2+1`, `2+1+1`, `2+2` — действительно 5.

## Почему это работает

**Корректность формулы.** Любой способ добраться до ступеньки `i ≥ 2` заканчивается шагом `1` или шагом `2`. Способы с последним шагом `1` взаимно однозначно соответствуют способам добраться до `i − 1` (убираем последний шаг), с последним шагом `2` — способам добраться до `i − 2`. Пересечений нет, пропусков нет — значит, `dp[i] = dp[i − 1] + dp[i − 2]`.

**Корректность кода.** Инвариант: перед итерацией `i` верно `prev = dp[i − 2]`, `curr = dp[i − 1]`. Для `i = 2` это база. Итерация вычисляет `next = dp[i]` и сдвигает окно, так что перед итерацией `i + 1` `prev = dp[i − 1]`, `curr = dp[i]`. После последней итерации `curr = dp[n]`.

## Пограничные случаи

- **`n = 1`**: цикл не выполняется, ответ `1`.
- **`n = 2`**: одна итерация, ответ `2`.
- **`n = 45`** (максимум): ответ `1836311903` — помещается и в 32-битный `int`, и тем более в `Number` (точные целые до `2^53`). Для больших `n` понадобился бы `BigInt` или ответ по модулю.

## Сложность

- **Время `O(n)`**: цикл из `n − 1` итераций, каждая — сложение и два присваивания.
- **Память `O(1)`**: три числовые переменные вместо массива на `n + 1` элементов.

Существует и `O(log n)` решение — возведение матрицы `[[1, 1], [1, 0]]` в степень быстрым возведением, — но при `n ≤ 45` оно не нужно.

## Типичные ошибки

1. **Наивная рекурсия без мемоизации** → экспоненциальное время, тайм-аут уже при `n ≈ 40`.
2. **База `dp[0] = 0`** → `dp[2] = 1`, все ответы сдвигаются на одну позицию Фибоначчи.
3. **Неверный порядок сдвига** (`curr = next; prev = curr;`) → `prev` и `curr` становятся равны, последовательность ломается.
4. **Считать комбинации, а не последовательности**: `1+2` и `2+1` — **разные** способы. Если бы порядок не важен, это была бы другая задача (разбиение числа).
5. **Цикл до `i < n`** вместо `i <= n` → возвращается `dp[n − 1]`.

## Как узнать такую задачу

- «Сколькими способами» дойти/набрать/разбить, где каждый ход — один из **небольшого набора** вариантов (шаг 1 или 2, монета из набора, символ из алфавита).
- Ответ для `n` естественно выражается через ответы для `n − 1`, `n − 2`, … — смотрите на **последний ход**.
- Наивная рекурсия ветвится и повторяет подзадачи. Родственные задачи: Fibonacci Number, Min Cost Climbing Stairs, House Robber, Decode Ways, Coin Change II, Unique Paths.
