## Задача простыми словами

Дано неотрицательное целое `x`. Нужно вернуть **целую часть квадратного корня** — корень, округлённый вниз. Встроенные функции вроде `Math.sqrt` и `x ** 0.5` использовать нельзя.

Пример: `x = 4` → `2`. `x = 8` → `2`, потому что `√8 ≈ 2.83`, а дробную часть отбрасываем. Другими словами, ответ — **наибольшее целое `m`, для которого `m · m ≤ x`**.

## Наивный подход

Перебирать `m = 1, 2, 3, …`, пока квадрат не превысит `x`:

```ts naive
let m = 0;
while ((m + 1) * (m + 1) <= x) m++;
return m;
```

Это верно, но работает за `O(√x)`: при `x = 2^31 − 1` — около 46 000 итераций. Немного, но лишняя работа очевидна: мы проверяем **каждое** `m` подряд, хотя условие `m · m ≤ x` устроено монотонно — до ответа оно истинно, после — ложно. Проверив одно `m` в середине диапазона, можно сразу отбросить половину кандидатов.

## Ключевое наблюдение

Условие `m · m ≤ x` выглядит как `true true … true false false …` при росте `m`. Ответ — **последнее `true`**. Найти границу монотонного условия — классическая задача для **бинарного поиска по ответу**: ищем не элемент в массиве, а число в диапазоне возможных ответов.

Диапазон можно сразу сузить: при `x ≥ 2` корень не больше `x / 2` (для `x ≥ 4` это верно, потому что `(x/2)² = x²/4 ≥ x`, а для `x = 2, 3` ответ `1 = ⌊x/2⌋`). Это `O(log x)` шагов — около 30 для максимального `x`.

## Техники

### Бинарный поиск по ответу

**Что это.** Если нужно найти наибольшее (или наименьшее) значение, удовлетворяющее **монотонному** условию, бинарный поиск можно вести прямо по диапазону значений, без всякого массива. Нужно только уметь проверить кандидата.

**Типичный шаблон** «последнее подходящее значение» с запоминанием ответа:

```ts naive
let lo = MIN, hi = MAX, answer = MIN;
while (lo <= hi) {
  const mid = lo + Math.floor((hi - lo) / 2);
  if (подходит(mid)) { answer = mid; lo = mid + 1; } // ищем больше
  else hi = mid - 1;                                  // ищем меньше
}
return answer;
```

Когда использовать: «найти максимальное/минимальное `k`, такое что…» при монотонном условии — Koko Eating Bananas, Capacity To Ship Packages, Split Array Largest Sum, Valid Perfect Square.

**Как применяется здесь.** Кандидаты — `m` от `1` до `⌊x/2⌋`, условие — `m · m ≤ x`. Подробнее про варианты бинарного поиска — во вкладке «Теория».

### Проверка без переполнения

Вместо `mid * mid <= x` проверяется `mid <= Math.floor(x / mid)`. Для положительных целых это **эквивалентно**: `mid · mid ≤ x` ⇔ `mid ≤ x / mid` ⇔ `mid ≤ ⌊x / mid⌋` (последний переход верен, потому что `mid` — целое). В Java/C++ это спасает от переполнения `int`. В JS при данных ограничениях `mid * mid` тоже дал бы верный результат (большие квадраты теряют точность, но остаются заметно больше `x`), так что здесь это скорее переносимая привычка, которая к тому же держит все промежуточные значения в пределах `x`.

## Разбор кода

```ts
function mySqrt(x: number): number {
  // Для 0 и 1 корень равен самому числу
  if (x < 2) {
    return x;
  }
```

`√0 = 0`, `√1 = 1`. Эти случаи выносим отдельно: для них верхняя граница `⌊x/2⌋` равна `0`, отрезок `[1, 0]` пуст, и функция вернула бы начальное `answer = 1`. Для `x = 1` это случайно верно, а для `x = 0` — ошибка. Явная проверка снимает все вопросы.

```ts
  // Ищем наибольшее m, для которого m * m <= x.
  // При x >= 2 корень не больше x / 2
  let lo = 1;
  let hi = Math.floor(x / 2);
  let answer = 1;
```

Границы поиска — `[1, ⌊x/2⌋]`, обе включены. `answer = 1` — заведомо подходящее значение (`1 · 1 ≤ x` при `x ≥ 2`), оно станет ответом, если ничего больше не подойдёт (как для `x = 2, 3`).

```ts
  while (lo <= hi) {
    const mid = lo + Math.floor((hi - lo) / 2);
```

Ищем на закрытом отрезке `[lo, hi]`, поэтому условие `lo <= hi`: отрезок из одного элемента тоже нужно проверить. Середина через `lo + (hi − lo) / 2` — классическая защита от переполнения суммы `lo + hi`; `Math.floor` обязателен, иначе в JS `mid` будет дробным.

```ts
    // Сравниваем mid <= x / mid вместо mid * mid <= x:
    // так произведение не выходит за пределы точности/диапазона
    if (mid <= Math.floor(x / mid)) {
      // mid подходит — запоминаем и пробуем больше
      answer = mid;
      lo = mid + 1;
```

`mid` подходит (`mid² ≤ x`) — это кандидат в ответ. Запоминаем его, но ищем **больший**: все значения левее `mid` подходят тоже, но они меньше, так что отбрасываем их вместе с `mid` (`lo = mid + 1`). Если больших подходящих не найдётся, `answer` сохранит `mid`.

```ts
    } else {
      // mid слишком велик — ищем левее
      hi = mid - 1;
    }
  }
```

`mid² > x` — `mid` и всё правее него не подходят (квадраты только растут), отбрасываем их.

```ts
  return answer;
}
```

Цикл закончился, когда `lo > hi`: каждое значение диапазона либо проверено, либо отброшено как заведомо худшее. `answer` — наибольшее из подошедших.

## Трассировка

`x = 8`: `lo = 1`, `hi = 4`, `answer = 1`.

1. `mid = 1 + Math.floor(3 / 2) = 2`. `Math.floor(8 / 2) = 4`, `2 <= 4` → подходит: `answer = 2`, `lo = 3`.
2. `lo = 3`, `hi = 4`. `mid = 3 + Math.floor(1 / 2) = 3`. `Math.floor(8 / 3) = 2`, `3 <= 2`? Нет → `hi = 2`.
3. `lo = 3 > hi = 2` → выход. Ответ `2`.

`x = 16`: `lo = 1`, `hi = 8`, `answer = 1`.

1. `mid = 1 + 3 = 4`. `Math.floor(16 / 4) = 4`, `4 <= 4` → `answer = 4`, `lo = 5`.
2. `lo = 5`, `hi = 8`. `mid = 5 + 1 = 6`. `Math.floor(16 / 6) = 2`, `6 <= 2`? Нет → `hi = 5`.
3. `lo = 5`, `hi = 5`. `mid = 5`. `Math.floor(16 / 5) = 3`, `5 <= 3`? Нет → `hi = 4`.
4. `lo = 5 > hi = 4` → выход. Ответ `4`.

`x = 3`: `lo = 1`, `hi = 1`. `mid = 1`, `1 <= 3` → `answer = 1`, `lo = 2`. Выход, ответ `1`.

## Почему это работает

Пусть `r = ⌊√x⌋` — правильный ответ. Инвариант цикла:

- `answer` подходит (`answer² ≤ x`) и `answer ≤ r`;
- если `r > answer`, то `r` лежит в `[lo, hi]`.

В начале `answer = 1 ≤ r`, а `r ∈ [1, ⌊x/2⌋]` по оценке выше. Если `mid` подходит, то `mid ≤ r`; присваивая `answer = mid` и `lo = mid + 1`, мы не теряем `r` (он либо равен `mid` = `answer`, либо правее). Если `mid` не подходит, то `mid > r`, и `hi = mid − 1` тоже не теряет `r`. Отрезок каждый раз сужается, цикл конечен; когда он пуст, `r` не может быть больше `answer` — значит, `answer = r`.

## Пограничные случаи

- **`x = 0`, `x = 1`**: возвращаются сразу.
- **`x = 2`, `x = 3`**: `hi = 1`, одна итерация, ответ `1`.
- **Точный квадрат** (`16`, `2147395600 = 46340²`): условие с `<=` включает равенство, ответ точный.
- **Максимум `2^31 − 1`**: `hi ≈ 10⁹`, около 30 итераций; `Math.floor(x / mid)` не выходит за пределы `x`. Ответ `46340`.

## Сложность

- **Время `O(log x)`**: отрезок `[1, x/2]` вдвое сужается каждую итерацию — не больше ~31 шага.
- **Память `O(1)`**: несколько числовых переменных.

Альтернатива — **метод Ньютона**: `r = (r + x / r) / 2` сходится квадратично, за единицы итераций, но его сложнее доказать и аккуратно округлить. Бинарный поиск надёжнее на собеседовании.

## Типичные ошибки

1. **`while (lo < hi)` при закрытом отрезке** → последний кандидат не проверяется: для `x = 4` после шага с `mid = 1` останется `lo = hi = 2`, цикл выйдет, и ответ будет `1` вместо `2`.
2. **Возвращать `lo` или `mid` вместо запомненного `answer`** → после выхода `lo` указывает на первое **неподходящее** значение (на единицу больше ответа).
3. **`(lo + hi) / 2` без `Math.floor`** → дробный `mid` и бесконечный цикл или неверный ответ.
4. **Убрать проверку `x < 2`**, оставив `hi = ⌊x/2⌋` и `answer = 1` → для `x = 0` вернётся `1`.
5. **`Math.round`/дробная арифметика** вместо целочисленной проверки → ошибки на точных квадратах.

## Как узнать такую задачу

- Нужно найти **наибольшее/наименьшее целое**, удовлетворяющее условию, которое монотонно по этому числу.
- Прямая формула запрещена или неудобна, но **проверить кандидата легко**.
- Диапазон ответов огромный (до `10⁹`), а линейный перебор слишком долгий. Родственные задачи: Valid Perfect Square, Search Insert Position, Koko Eating Bananas, Capacity To Ship Packages Within D Days, Find Peak Element.
