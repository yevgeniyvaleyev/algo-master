## Задача простыми словами

Дано неотрицательное целое `x`. Нужно вернуть **целую часть квадратного корня** из `x`, то есть наибольшее целое `m`, для которого `m * m <= x`. Встроенные `Math.sqrt`, `**` и `pow` использовать нельзя.

Примеры: `x = 4` → `2`. `x = 8` → корень `2.828…`, округляем вниз → `2`.

## Наивный подход

Перебрать кандидатов по возрастанию, пока квадрат не превысит `x`:

```ts naive
let m = 0;
while ((m + 1) * (m + 1) <= x) {
  m++;
}
return m;
```

Это верно, но работает за `O(√x)`: для `x = 2^31 - 1` — около 46 тысяч итераций. Где лишняя работа? Мы проверяем **каждое** число подряд, хотя условие `m * m <= x` устроено очень просто: для маленьких `m` оно истинно, а начиная с какого-то места — ложно навсегда. Искать границу в такой последовательности линейно — расточительно.

## Ключевое наблюдение

Последовательность ответов на вопрос «`m * m <= x`?» для `m = 0, 1, 2, …` выглядит так:

```
true true true … true false false … false
```

Она **монотонна**. Нам нужно последнее `true`. Найти границу в монотонной последовательности — классическая работа для **бинарного поиска**: каждым сравнением отбрасываем половину кандидатов. Кандидаты лежат в диапазоне `[0, x]` (корень никогда не больше самого числа), так что поиск займёт около `log₂ x ≈ 31` шага.

## Техники

### Бинарный поиск по ответу

**Что это.** Бинарный поиск можно вести не только по массиву, но и по **диапазону возможных ответов**, если есть монотонная проверка «подходит ли кандидат». Берём середину диапазона, проверяем её и выкидываем половину, где ответа точно нет.

**Типичный шаблон «найти последний подходящий»:**

```ts naive
let lo = minAnswer;
let hi = maxAnswer;
let ans = minAnswer;
while (lo <= hi) {
  const mid = Math.floor((lo + hi) / 2);
  if (ok(mid)) {
    ans = mid; // mid подходит — запомнить
    lo = mid + 1; // и поискать больше
  } else {
    hi = mid - 1; // mid не подходит — искать меньше
  }
}
return ans;
```

Переменная `ans` хранит лучший найденный кандидат, поэтому не нужно думать, где окажутся `lo` и `hi` после цикла.

**Как применяется здесь.** `ok(mid)` — это `mid * mid <= x`, диапазон `[0, x]`. Подробнее о бинарном поиске — во вкладке «Теория».

## Разбор кода

```ts
function mySqrt(x: number): number {
  // Ищем наибольшее mid, для которого mid * mid <= x.
  // Ответ точно лежит в диапазоне [0, x]
  let lo = 0;
  let hi = x;
  let ans = 0;
```

Границы поиска: корень не меньше `0` и не больше `x` (для `x >= 1` это очевидно, а для `x = 0` ответ `0`). `ans = 0` — безопасное начальное значение: `0 * 0 <= x` для любого неотрицательного `x`.

```ts
  while (lo <= hi) {
    const mid = Math.floor((lo + hi) / 2);
```

Пока в диапазоне есть хотя бы один кандидат, берём середину. `Math.floor` нужен, потому что в JS деление даёт дробь. Переполнения `lo + hi` в JS нет: сумма не больше `2^32`, а `number` точно хранит целые до `2^53`.

```ts
    if (mid * mid <= x) {
      // mid подходит — запоминаем и пробуем больше
      ans = mid;
      lo = mid + 1;
```

Если квадрат `mid` не превышает `x`, `mid` — допустимый ответ. Запоминаем его, но ищем дальше правее: вдруг подойдёт число побольше. Все числа левее `mid` нас больше не интересуют — они заведомо меньше `ans`.

```ts
    } else {
      // mid слишком велик — ищем левее
      hi = mid - 1;
    }
  }
```

Если `mid * mid > x`, то и все числа правее `mid` тоже слишком велики (монотонность), — отбрасываем правую половину вместе с `mid`.

```ts
  return ans;
}
```

Когда `lo > hi`, кандидатов не осталось, а `ans` — наибольший подошедший `mid`.

## Трассировка

`x = 8`, ищем последнее `m` с `m * m <= 8`:

1. `lo = 0, hi = 8`, `mid = 4`, `16 > 8` → `hi = 3`.
2. `lo = 0, hi = 3`, `mid = 1`, `1 <= 8` → `ans = 1`, `lo = 2`.
3. `lo = 2, hi = 3`, `mid = 2`, `4 <= 8` → `ans = 2`, `lo = 3`.
4. `lo = 3, hi = 3`, `mid = 3`, `9 > 8` → `hi = 2`.
5. `lo = 3 > hi = 2` → выход, ответ `ans = 2`.

`x = 1`:

1. `lo = 0, hi = 1`, `mid = 0`, `0 <= 1` → `ans = 0`, `lo = 1`.
2. `lo = 1, hi = 1`, `mid = 1`, `1 <= 1` → `ans = 1`, `lo = 2`.
3. Выход, ответ `1`.

## Почему это работает

Инвариант цикла: **все числа левее `lo` подходят (их квадрат `<= x`), все числа правее `hi` не подходят, а `ans` — наибольшее подошедшее из уже проверенных**. Изначально это так: левее `0` и правее `x` чисел-кандидатов нет. Ветка `if` сдвигает `lo` за подошедший `mid` и обновляет `ans`; ветка `else` сдвигает `hi` перед неподошедшим `mid`. Благодаря монотонности условия обе ветки сохраняют инвариант.

Каждая итерация уменьшает диапазон `[lo, hi]` хотя бы на один элемент, поэтому цикл конечен. Когда он пуст, граница между «подходит» и «не подходит» проходит между `hi` и `lo`, а последний подошедший — это `hi = lo - 1`, он же `ans`.

## Пограничные случаи

- **`x = 0`**: `lo = hi = 0`, `mid = 0` подходит, ответ `0`.
- **`x = 1`**: ответ `1` (см. трассировку), отдельная проверка не нужна.
- **Полные квадраты** (`4`, `9`): `mid * mid === x` попадает в ветку `<=`, ответ точный.
- **`x = 2^31 - 1`**: ответ `46340`. Около границы `mid * mid` ≈ `2^31` вычисляется точно; при больших `mid` (порядка `10^9`) квадрат может округлиться, но он всё равно намного больше `x`, так что сравнение верное.

## Сложность

- **Время `O(log x)`**: диапазон `[0, x]` делится пополам на каждом шаге — не больше 32 итераций.
- **Память `O(1)`**: три переменные.

**Follow-up на собеседовании:** можно сузить диапазон до `[1, x / 2]` для `x >= 2` (это экономит одну итерацию), а в Java/C++ проверять `mid <= x / mid` или использовать `long`, чтобы `mid * mid` не переполнил `int`. Ещё быстрее — метод Ньютона `r = (r + x / r) / 2`, он сходится за несколько итераций.

## Типичные ошибки

1. **Цикл `while (lo < hi)` вместо `lo <= hi`** с этим шаблоном → последний кандидат не проверяется, для `x = 1` ответ `0`.
2. **`lo = mid` вместо `lo = mid + 1`** → при `lo + 1 === hi` середина равна `lo`, и цикл бесконечен.
3. **Забыть `Math.floor` при вычислении `mid`** → дробный `mid`, поиск идёт по нецелым числам.
4. **Возвращать `lo` или `mid` вместо `ans`** → после цикла `lo` указывает на первый **неподходящий** кандидат, ответ получается на единицу больше.
5. **В Java/C++ писать `mid * mid` в `int`** → переполнение при `mid > 46340`.

## Как узнать такую задачу

- Нужно найти **наибольшее (или наименьшее) значение**, удовлетворяющее условию, и это условие **монотонно** — бинарный поиск по ответу.
- Диапазон ответов огромный (до `2^31`), а проверка одного кандидата дешёвая.
- Родственные задачи: Valid Perfect Square, First Bad Version, Koko Eating Bananas, Capacity To Ship Packages, Search Insert Position.
