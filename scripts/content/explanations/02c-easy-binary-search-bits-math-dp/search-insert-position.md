## Задача простыми словами

Дан **отсортированный по возрастанию** массив различных чисел `nums` и число `target`. Если `target` есть в массиве — вернуть его индекс. Если нет — вернуть индекс, **куда его нужно вставить**, чтобы массив остался отсортированным. Время должно быть `O(log n)`.

Пример: `nums = [1, 3, 5, 6]`. Для `target = 5` ответ `2` (он там стоит), для `target = 2` ответ `1` (между `1` и `3`), для `target = 7` ответ `4` (в самый конец).

## Наивный подход

Пройти массив слева направо и вернуть первый индекс, где элемент не меньше `target`:

```ts naive
for (let i = 0; i < nums.length; i++) {
  if (nums[i] >= target) return i;
}
return nums.length;
```

Это верно, но `O(n)`. Лишняя работа: мы **никак не используем сортировку**. Сравнив `target` с элементом в середине, мы сразу узнаём, в какой половине ответ, — а линейный проход честно проверяет и ту половину, где ответа заведомо нет.

## Ключевое наблюдение

Оба случая («нашли» и «куда вставить») — это **одна и та же позиция**: первый индекс `i`, где `nums[i] >= target`.

- Если `target` есть в массиве, на этой позиции стоит он сам.
- Если нет — всё левее меньше `target`, всё начиная с неё больше, значит именно туда его и вставляют.
- Если `target` больше всех — такой позиции в массиве нет, ответ `nums.length`.

Условие `nums[i] >= target` на отсортированном массиве выглядит как `false false … false true … true`. Найти границу между `false` и `true` — классическая задача для бинарного поиска (её называют **lower bound**).

## Техники

### Бинарный поиск границы (lower bound)

**Что это.** Бинарный поиск ищет не обязательно конкретный элемент, а **границу монотонного условия**: место, где `false` сменяется на `true`. Каждое сравнение с серединой отбрасывает половину кандидатов, поэтому шагов `O(log n)`.

**Типичный шаблон** на полуинтервале `[lo, hi)`:

```ts naive
let lo = 0, hi = n;            // ответ где-то в [lo, hi]
while (lo < hi) {
  const mid = lo + ((hi - lo) >> 1);
  if (!условие(mid)) lo = mid + 1;  // граница правее mid
  else hi = mid;                    // mid подходит, граница не правее
}
return lo;                          // lo === hi — первая позиция с true
```

Когда использовать: «первый элемент `>= x`», «первый день, когда…», «минимальное значение, при котором…». Всё, где ответ — граница в отсортированной или монотонной последовательности.

**Как применяется здесь.** Условие — `nums[i] >= target`. Мы берём `hi = nums.length`, чтобы позиция «за концом массива» тоже была кандидатом. Подробнее про варианты бинарного поиска — во вкладке «Теория».

### Полуинтервал `[lo, hi)`

Важная деталь — **какие границы включены**. Здесь `lo` включена, `hi` — нет (точнее, `hi` — кандидат-ответ, но элемент `nums[hi]` мы не читаем). Отсюда три согласованных решения: цикл `while (lo < hi)`, сдвиг `hi = mid` (без `- 1`) и `lo = mid + 1`. Смешивать их с вариантом `[lo, hi]` нельзя — получится зацикливание или пропуск ответа.

## Разбор кода

```ts
function searchInsert(nums: number[], target: number): number {
  // Ищем первый индекс, где nums[i] >= target, на полуинтервале [lo, hi).
  // hi = nums.length: target может оказаться больше всех элементов
  let lo = 0;
  let hi = nums.length;
```

Кандидаты на ответ — все индексы от `0` до `nums.length` включительно (последний означает «вставить в конец»). Поэтому `hi` начинается с `nums.length`, а не с `nums.length - 1`: иначе для `target = 7` мы никогда не смогли бы вернуть `4`.

```ts
  while (lo < hi) {
    // Середина без риска переполнения
    const mid = lo + ((hi - lo) >> 1);
```

Цикл крутится, пока в диапазоне больше одного кандидата. Середина считается как `lo + (hi - lo) / 2` с целочисленным делением через `>> 1`. Запись `(lo + hi) >> 1` в Java/C++ могла бы переполнить `int`; в JS это привычка, а не необходимость, но она ничего не стоит. Поскольку `lo < hi`, всегда `mid < hi`, то есть `mid` — реальный индекс массива, и `nums[mid]` безопасно читать.

```ts
    if (nums[mid] < target) {
      // mid и всё левее него меньше target — ответ строго правее
      lo = mid + 1;
```

Если `nums[mid] < target`, то из-за сортировки и все элементы левее `mid` меньше `target`. Ни один из них, включая сам `mid`, не может быть ответом — сдвигаем `lo` за `mid`.

```ts
    } else {
      // nums[mid] >= target — mid подходит, но может быть и левее
      hi = mid;
    }
  }
```

Если `nums[mid] >= target`, то `mid` — **подходящий** индекс, но не обязательно первый. Поэтому `mid` не выбрасываем (`hi = mid`, а не `mid - 1`), а продолжаем искать левее. Диапазон всё равно сужается: `mid < hi`.

```ts
  // lo === hi — первая позиция, где элемент >= target
  // (это и индекс найденного элемента, и место вставки)
  return lo;
}
```

Цикл закончился, когда `lo === hi`: остался ровно один кандидат, он и есть граница. Отдельной проверки «нашли ли мы `target`» не нужно — оба ответа совпадают.

## Трассировка

`nums = [1, 3, 5, 6]`, `target = 2`:

1. `lo = 0`, `hi = 4`. `mid = 2`, `nums[2] = 5 >= 2` → `hi = 2`.
2. `lo = 0`, `hi = 2`. `mid = 1`, `nums[1] = 3 >= 2` → `hi = 1`.
3. `lo = 0`, `hi = 1`. `mid = 0`, `nums[0] = 1 < 2` → `lo = 1`.
4. `lo = hi = 1` → возвращаем `1`.

`target = 7` (вставка в конец):

1. `lo = 0`, `hi = 4`. `mid = 2`, `5 < 7` → `lo = 3`.
2. `lo = 3`, `hi = 4`. `mid = 3`, `6 < 7` → `lo = 4`.
3. `lo = hi = 4` → возвращаем `4`. Элемент `nums[4]` ни разу не читался.

`target = 5` (элемент найден):

1. `lo = 0`, `hi = 4`. `mid = 2`, `5 >= 5` → `hi = 2`.
2. `lo = 0`, `hi = 2`. `mid = 1`, `3 < 5` → `lo = 2`.
3. `lo = hi = 2` → возвращаем `2`.

## Почему это работает

Инвариант цикла: **все индексы левее `lo` дают `nums[i] < target`, а индекс `hi` либо равен `nums.length`, либо `nums[hi] >= target`**. Значит, ответ (первая позиция с `>= target`) всегда лежит в `[lo, hi]`.

- В начале `lo = 0` (левее ничего нет) и `hi = nums.length` — инвариант верен.
- Ветка `lo = mid + 1` выполняется, только если `nums[mid] < target`, — тогда и все `i <= mid` дают `< target`.
- Ветка `hi = mid` выполняется, только если `nums[mid] >= target`.

Каждая итерация строго уменьшает `hi - lo` (потому что `lo <= mid < hi`), поэтому цикл завершится. При `lo === hi` диапазон `[lo, hi]` содержит один индекс — это и есть ответ.

## Пограничные случаи

- **`target` меньше всех** (`[1, 3]`, `0`): `hi` сдвигается до `0`, ответ `0`.
- **`target` больше всех**: `lo` доходит до `nums.length` — вставка в конец.
- **Массив из одного элемента**: одна итерация, ответ `0` или `1`.
- **`target` равен первому или последнему элементу**: обычный случай, граница найдётся точно на нём.
- **Отрицательные числа**: сравнения работают с любыми знаками.

## Сложность

- **Время `O(log n)`**: каждая итерация уменьшает длину диапазона `hi - lo` примерно вдвое; при `n = 10⁴` это не больше 14 итераций.
- **Память `O(1)`**: три числовые переменные, массив не копируется.

## Типичные ошибки

1. **`hi = nums.length - 1`** при полуинтервальном шаблоне → невозможно вернуть `nums.length`, ломается вставка в конец.
2. **`hi = mid - 1` в ветке `>=`** → выбрасываем сам `mid`, хотя он может быть ответом.
3. **`while (lo <= hi)` вместе с `hi = mid`** → при `lo === hi` цикл не сдвигает границы и зацикливается.
4. **Искать `target` «классическим» бинарным поиском и возвращать `-1`**, а потом отдельно вычислять место вставки — лишний код и лишние ошибки; lower bound даёт оба ответа сразу.
5. **`(lo + hi) / 2` без округления** → в JS получится дробный индекс и `nums[1.5] === undefined`.

## Как узнать такую задачу

- Массив **отсортирован**, и требуется `O(log n)`.
- Нужен не сам элемент, а **позиция**: «куда вставить», «первый элемент не меньше», «сколько элементов меньше x».
- Ответ — граница монотонного условия `false … true`. Родственные задачи: First Bad Version, Find First and Last Position of Element in Sorted Array, Find Peak Element, Search in Rotated Sorted Array, а также поиск по ответу (Koko Eating Bananas, Sqrt(x)).
