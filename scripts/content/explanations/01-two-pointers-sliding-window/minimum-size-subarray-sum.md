## Задача простыми словами

Дан массив **положительных** чисел `nums` и число `target`. Нужно найти длину самого короткого **непрерывного** подмассива, сумма которого **не меньше** `target`. Если такого нет — вернуть `0`.

Пример: `target = 7`, `nums = [2, 3, 1, 2, 4, 3]`. Подмассив `[4, 3]` даёт сумму `7` и имеет длину `2`; короче не бывает (самый большой элемент `4 < 7`) — ответ `2`.

## Наивный подход

Перебрать все начала и для каждого наращивать конец, пока сумма не дойдёт до `target`:

```ts naive
let best = Infinity;
for (let i = 0; i < nums.length; i++) {
  let sum = 0;
  for (let j = i; j < nums.length; j++) {
    sum += nums[j];
    if (sum >= target) {
      best = Math.min(best, j - i + 1);
      break; // дальше от i подмассивы только длиннее
    }
  }
}
```

Это `O(n²)`. Лишняя работа: для начала `i + 1` мы **заново складываем** почти те же элементы, что уже сложили для `i`. Сумма `nums[i+1..j]` — это просто `sum - nums[i]`, её не нужно пересчитывать с нуля. Кроме того, если для `i` подходящий конец был `j`, то для `i + 1` он точно не левее `j` — значит, начинать поиск конца сначала бессмысленно.

## Ключевое наблюдение

Все числа положительные, поэтому:

- расширение окна вправо **увеличивает** сумму;
- сужение окна слева **уменьшает** сумму.

Это монотонность: если окно `[left, right]` уже набрало `target`, то для этого `right` лучшее начало — самое правое `left`, при котором сумма ещё `≥ target`. И когда `right` сдвигается дальше, лучшее `left` не может сдвинуться назад. Значит, обе границы движутся **только вперёд**, и хватает одного прохода.

## Техники

### Скользящее окно переменного размера

**Что это.** Отрезок `[left, right]` с поддерживаемым агрегатом (здесь — суммой). `right` добавляет элементы, `left` убирает. Каждый элемент входит в окно один раз и выходит один раз, поэтому общее время `O(n)`, даже несмотря на вложенный `while`.

**Типичный шаблон («самое короткое окно с условием»).**

```ts naive
for (let right = 0; right < n; right++) {
  добавить(a[right]);
  while (окно_удовлетворяет_условию()) {
    обновить_ответ(right - left + 1);
    убрать(a[left]);
    left++;
  }
}
```

Ответ обновляется **внутри** `while`: каждое хорошее окно — кандидат, а мы пытаемся сделать его короче.

**Когда применять.** Непрерывный подмассив; условие монотонно по включению (расширение не портит «достаточность», сужение не портит «допустимость»). Подробнее — во вкладке «Теория» (скользящее окно).

**Как применяется здесь.** Агрегат — сумма `sum`; условие — `sum >= target`.

### Почему важна положительность

Если бы в массиве были отрицательные числа, сужение окна могло бы **увеличить** сумму, и монотонность пропала бы. Тогда нужен другой подход — префиксные суммы с монотонной очередью или бинарным поиском.

## Разбор кода

```ts
function minSubArrayLen(target: number, nums: number[]): number {
  let left = 0;
  let sum = 0; // сумма текущего окна [left, right]
  let best = Infinity;
```

- `left` — левая граница окна.
- `sum` — сумма окна; храним её, чтобы не пересчитывать.
- `best` — минимальная длина; `Infinity` означает «подходящего окна пока нет».

```ts
  for (let right = 0; right < nums.length; right++) {
    // Расширяем окно вправо
    sum += nums[right];
```

Правая граница проходит массив один раз; каждый новый элемент добавляется в сумму окна за `O(1)`.

```ts
    // Пока окно «достаточно большое» — пробуем его сузить слева
    while (sum >= target) {
      best = Math.min(best, right - left + 1);
      sum -= nums[left];
      left++;
    }
  }
```

Пока окно набирает `target`, оно — кандидат: записываем его длину. Затем убираем левый элемент и проверяем, хватает ли суммы без него. Цикл останавливается на первом окне, которое уже **не** набирает `target`; самое короткое хорошее окно, заканчивающееся в `right`, к этому моменту уже учтено.

Почему `left` не обгонит `right`? Если в окне остался один элемент и `sum >= target`, то после его удаления `sum = 0 < target` (а `target ≥ 1` по условию) — цикл остановится с `left = right + 1`, то есть с пустым окном. На следующей итерации `right` снова его догонит.

```ts
  // Ни одно окно не набрало target
  return best === Infinity ? 0 : best;
}
```

Если `best` не изменился, даже весь массив не набрал `target` — по условию возвращаем `0`.

## Трассировка

`target = 7`, `nums = [2, 3, 1, 2, 4, 3]`:

```
r=0: sum=2                  окно [2]
r=1: sum=5                  окно [2,3]
r=2: sum=6                  окно [2,3,1]
r=3: sum=8 ≥ 7 → best=4 (l=0..3), убираем 2: sum=6, l=1
r=4: sum=10 ≥ 7 → best=4 (l=1..4), убираем 3: sum=7, l=2
     sum=7 ≥ 7  → best=3 (l=2..4), убираем 1: sum=6, l=3
r=5: sum=9 ≥ 7 → best=3 (l=3..5), убираем 2: sum=7, l=4
     sum=7 ≥ 7  → best=2 (l=4..5), убираем 4: sum=3, l=5
конец → 2
```

Заметьте: `left` прошёл путь `0 → 5`, `right` — `0 → 5`. Всего 6 добавлений и 5 удалений — линейно.

## Почему это работает

**Утверждение:** ни одно окно, которое могло бы быть ответом, не пропущено.

Рассмотрим любое окно `[i, j]` с суммой `≥ target`. Разберём, где был `left`, когда `right` стал равен `j`.

- **`left ≤ i`.** Пока `left ≤ i`, окно `[left, j]` содержит `[i, j]` и (числа положительные) тоже набирает `target`, поэтому `while` не остановится, не дойдя до `left = i`. В момент `left = i` длина `j − i + 1` будет записана в `best`.
- **`left > i`.** Значит, раньше, при каком-то `right = j' ≤ j`, цикл убрал элемент `i`, а перед этим записал длину окна `[i, j']`. Это окно не длиннее `[i, j]`, так что `best` уже не больше длины `[i, j]`.

В обоих случаях `best ≤ j − i + 1` для любого подходящего окна. А записываем мы только окна с `sum >= target`, то есть настоящие кандидаты. Значит, `best` — ровно минимальная длина.

Ключевое место — положительность чисел: именно она гарантирует, что окно, содержащее подходящее, тоже подходит, и `while` не остановится раньше времени.

## Пограничные случаи

- **Ни одно окно не набирает `target`** (`target = 11`, `nums = [1, 1, 1]`): `best` остаётся `Infinity`, ответ `0`.
- **Один элемент уже `≥ target`** (`target = 4`, `nums = [1, 4, 4]`): окно сожмётся до длины `1`, ответ `1`.
- **Нужен весь массив** (`target = 15`, `nums = [1, 2, 3, 4, 5]`): окно `[0..4]` даст `best = 5`.
- **Сумма ровно равна `target`**: условие `>=`, такое окно подходит.

## Сложность

- **Время `O(n)`**: `right` проходит массив один раз, `left` — тоже не больше `n` шагов за всё время. Вложенный `while` не делает решение квадратичным: суммарное число его итераций `≤ n`.
- **Память `O(1)`**: три числа — `left`, `sum`, `best`.

Есть и вариант за `O(n log n)`: префиксные суммы и бинарный поиск для каждого начала. Он полезен, если окно не применимо, но здесь скользящее окно проще и быстрее.

## Типичные ошибки

1. **`if` вместо `while`** → окно сужается только на один элемент за шаг, короткие окна теряются.
2. **Обновлять `best` после сужения** → записывается длина окна, которое уже может не набирать `target`.
3. **Вернуть `Infinity`** вместо `0`, когда подходящего окна нет.
4. **Строгое `sum > target`** → не находятся окна с суммой ровно `target`.
5. **Применять этот же код при отрицательных числах** → монотонность ломается, ответ неверный.

## Как узнать такую задачу

- **Непрерывный** подмассив, сумма/количество/произведение которого должно достичь порога, и нужна **минимальная длина**.
- Все числа **неотрицательные** (или положительные) — сигнал, что окно с суммой монотонно.
- `n` до `10⁵`, перебор `O(n²)` не проходит.
- Родственные задачи: Minimum Window Substring (то же «сужай, пока условие выполнено», но с частотами символов), Subarray Product Less Than K, Max Consecutive Ones III, Longest Substring Without Repeating Characters (окно на максимум).
