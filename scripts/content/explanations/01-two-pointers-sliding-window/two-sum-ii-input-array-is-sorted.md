## Задача простыми словами

Дан массив `numbers`, **отсортированный по неубыванию**, и число `target`. Нужно найти два разных элемента с суммой `target` и вернуть их позиции **с единицы** (`[index1, index2]`, `index1 < index2`). Решение ровно одно, а дополнительной памяти можно использовать только `O(1)`.

Пример: `numbers = [2, 7, 11, 15]`, `target = 9`. `2 + 7 = 9`, они на позициях `1` и `2` (с единицы) — ответ `[1, 2]`.

## Наивный подход

Перебрать все пары — `O(n²)`:

```ts naive
for (let i = 0; i < numbers.length; i++) {
  for (let j = i + 1; j < numbers.length; j++) {
    if (numbers[i] + numbers[j] === target) return [i + 1, j + 1];
  }
}
```

Можно, как в обычном Two Sum, сложить числа в `Map` — это `O(n)` времени, но `O(n)` памяти, а условие требует `O(1)`. Можно для каждого `i` искать партнёра бинарным поиском — `O(n log n)`.

Все эти варианты **игнорируют главное свойство входа — сортировку** (или используют его лишь частично). Перебор проверяет пары, про которые уже из одной проверенной суммы ясно, что они не подходят.

## Ключевое наблюдение

Возьмём самый маленький и самый большой элемент: `numbers[left] + numbers[right]`.

- Если сумма **меньше** `target`, то `numbers[left]` не подходит **ни с каким** партнёром: даже самый большой из оставшихся (`numbers[right]`) даёт недостаточно. Его можно выбросить — `left++`.
- Если сумма **больше**, то `numbers[right]` не подходит ни с кем: даже с самым маленьким перебор. Выбрасываем — `right--`.

Одна проверка исключает целую строку или столбец из «таблицы всех пар». За `n - 1` шагов пространство поиска исчерпывается.

## Техники

### Два указателя навстречу друг другу

**Что это.** Индексы `left` и `right` стартуют с концов массива и сходятся. На каждом шаге по результату сравнения двигается один из них. Суммарно они делают не больше `n` шагов.

**Типичный шаблон для пар в отсортированном массиве.**

```ts naive
while (left < right) {
  const sum = a[left] + a[right];
  if (sum === target) return ...;
  if (sum < target) left++;
  else right--;
}
```

**Когда применять.** Массив отсортирован (или его можно отсортировать без потери нужной информации), и нужна пара с условием на сумму/разность. Подробнее — во вкладке «Теория» (два указателя).

**Как применяется здесь.** Ровно по шаблону; единственная особенность — ответ в индексации с единицы.

### Отсечение по монотонности

Сортировка даёт монотонность: при сдвиге `left` вправо сумма не уменьшается, при сдвиге `right` влево — не увеличивается. Поэтому знак разности `sum - target` однозначно говорит, **в какую сторону** двигаться. Это та же идея, что и в бинарном поиске: одно сравнение отбрасывает часть кандидатов.

## Разбор кода

```ts
function twoSum(numbers: number[], target: number): number[] {
  let left = 0;
  let right = numbers.length - 1;
```

Указатели на самый маленький и самый большой элемент. Все пары `(i, j)` с `left ≤ i < j ≤ right` — ещё не исключённые кандидаты.

```ts
  while (left < right) {
    const sum = numbers[left] + numbers[right];
```

Пока в диапазоне есть хотя бы два элемента, считаем сумму крайних. Условие строгое: `left === right` означало бы сложить элемент сам с собой.

```ts
    if (sum === target) {
      // Индексация в ответе — с единицы
      return [left + 1, right + 1];
    }
```

Нашли пару. Так как `left < right`, порядок `index1 < index2` выполняется автоматически. `+ 1` переводит индексы JavaScript (с нуля) в формат ответа (с единицы).

```ts
    if (sum < target) {
      // Сумма мала — нужно число побольше, двигаем левый указатель вправо
      left++;
    } else {
      // Сумма велика — нужно число поменьше, двигаем правый указатель влево
      right--;
    }
  }
```

Решаем, какой элемент исключить. При малой сумме бесполезен `numbers[left]`: с любым `numbers[j] ≤ numbers[right]` сумма будет ещё меньше или такой же. При большой — бесполезен `numbers[right]` по симметричной причине.

```ts
  // По условию решение всегда существует
  return [];
}
```

До этой строки при корректном входе не дойдём; она нужна, чтобы TypeScript видел возврат на всех путях.

## Трассировка

`numbers = [1, 3, 4, 6, 9]`, `target = 13`:

```
left=0 right=4: 1 + 9 = 10 < 13 → left=1
left=1 right=4: 3 + 9 = 12 < 13 → left=2
left=2 right=4: 4 + 9 = 13 = target → вернуть [3, 5]
```

`numbers = [2, 7, 11, 15]`, `target = 9`:

```
left=0 right=3: 2 + 15 = 17 > 9 → right=2
left=0 right=2: 2 + 11 = 13 > 9 → right=1
left=0 right=1: 2 + 7 = 9 → вернуть [1, 2]
```

Во втором примере `15` и `11` отброшены, хотя с ними мы проверили лишь по одной паре: каждая такая проверка доказала, что этот элемент не подходит ни с кем.

## Почему это работает

**Инвариант:** если ответ — пара `(a, b)`, `a < b`, то всегда `left ≤ a` и `b ≤ right`, то есть ответ не выброшен.

Пусть инвариант верен и `sum ≠ target`.

- `sum < target` и мы двигаем `left`. Может ли `left` совпадать с `a`? Тогда `numbers[a] + numbers[right] < target = numbers[a] + numbers[b]`, значит `numbers[right] < numbers[b]`, но `b ≤ right` и массив отсортирован — противоречие. Значит `left < a`, и после `left++` всё ещё `left ≤ a`.
- `sum > target` — симметрично, `right > b`, и после `right--` инвариант сохраняется.

Диапазон каждый шаг сужается на 1, а ответ внутри него. Значит, рано или поздно `left = a` и `right = b` одновременно, и мы вернём верную пару.

## Пограничные случаи

- **Два элемента**: одна проверка, они и есть ответ.
- **Отрицательные числа** (`[-3, -1, 0, 2]`, `target = -4`): рассуждения о монотонности от знака не зависят.
- **Дубликаты** (`[1, 2, 2, 4]`, `target = 4`): `1 + 4 = 5 > 4` → `right = 2`; `1 + 2 = 3 < 4` → `left = 1`; `2 + 2 = 4` → `[2, 3]`. Указатели на разных позициях, поэтому одинаковые значения допустимы.
- **Ответ — крайние элементы**: найдётся на первом же шаге.

## Сложность

- **Время `O(n)`**: каждая итерация сдвигает ровно один указатель, расстояние между ними уменьшается на 1, итераций не больше `n - 1`.
- **Память `O(1)`**: две переменные-индекса и сумма. Это и требовалось условием.

## Типичные ошибки

1. **Забыть `+ 1`** → ответ в индексации с нуля.
2. **Условие `left <= right`** → элемент может сложиться сам с собой (`[3, ...]`, `target = 6`).
3. **Перепутать направления**: при малой сумме двигать `right` — так сумма станет ещё меньше.
4. **Решать через `Map`, как обычный Two Sum** — работает, но нарушает требование `O(1)` памяти и не использует сортировку.
5. **Двигать оба указателя сразу** при несовпадении — можно перескочить через ответ.

## Как узнать такую задачу

- Массив **отсортирован**, нужна **пара** с заданной суммой или разностью.
- Явное требование `O(1)` памяти при поиске пары — почти всегда два указателя.
- «Таблицу всех пар» можно отсекать строками и столбцами по одному сравнению.
- Родственные задачи: 3Sum и 4Sum (фиксируем элементы и запускаем этот же проход), Container With Most Water, Two Sum IV (BST), Sum of Square Numbers.
