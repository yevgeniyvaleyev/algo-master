## Задача простыми словами

Дан массив `height`: `height[i]` — высота вертикальной стенки в точке `i`. Нужно выбрать **две стенки**, которые вместе с осью образуют контейнер с наибольшим количеством воды, и вернуть это количество. Вода не может быть выше более низкой стенки, а ширина — это расстояние между индексами.

Площадь пары `(i, j)`: `min(height[i], height[j]) * (j - i)`.

Пример: `height = [1, 8, 6, 2, 5, 4, 8, 3, 7]`. Лучшая пара — стенки `8` (индекс `1`) и `7` (индекс `8`): `min(8, 7) * (8 - 1) = 49`.

## Наивный подход

Перебрать все пары стенок:

```ts naive
let best = 0;
for (let i = 0; i < height.length; i++) {
  for (let j = i + 1; j < height.length; j++) {
    best = Math.max(best, Math.min(height[i], height[j]) * (j - i));
  }
}
```

Это `O(n²)`: при `n = 10⁵` — около 5 миллиардов пар, слишком медленно. Лишняя работа в том, что мы проверяем пары, которые **заведомо не лучше** уже найденной. Например, если мы уже посчитали пару крайних стенок и одна из них низкая, то любая более узкая пара с этой низкой стенкой не может быть лучше — но перебор всё равно её проверит.

## Ключевое наблюдение

Начнём с самого широкого контейнера: `left = 0`, `right = n - 1`. Пусть `height[left] < height[right]`.

Рассмотрим все остальные пары с этой левой стенкой: `(left, j)` при `j < right`. У них:

- ширина **меньше** (`j - left < right - left`);
- высота **не больше** `height[left]` (минимум не может превысить левую стенку).

Значит, ни одна из них не лучше текущей пары. Левая стенка «исчерпана» — её можно выбросить: `left++`. Симметрично, если ниже правая стенка, выбрасываем её.

Каждый шаг исключает одну стенку, а с ней — все её оставшиеся пары. За `n - 1` шагов перебор сведён к линейному.

## Техники

### Два указателя навстречу друг другу

**Что это.** Указатели стартуют с концов и сходятся; на каждом шаге по правилу сдвигается один из них. Всего не больше `n` шагов.

**Типичный шаблон.**

```ts naive
while (left < right) {
  обновить_ответ(left, right);
  if (левый_элемент_исчерпан) left++;
  else right--;
}
```

**Когда применять.** Когда можно доказать, что один из крайних элементов уже не войдёт в лучший ответ, и его безопасно отбросить. Здесь сортировка не нужна — монотонность даёт сама ширина, которая только уменьшается. Подробнее — во вкладке «Теория» (два указателя).

**Как применяется здесь.** Всегда сдвигаем **более низкую** стенку.

### Жадное отсечение

Это жадный алгоритм с доказательством через «исключение кандидатов»: мы не пытаемся угадать ответ, а показываем, что выбрасываемая стенка не участвует ни в одной паре лучше уже учтённой. Такой приём встречается часто: «худший из крайних элементов больше не нужен».

## Разбор кода

```ts
function maxArea(height: number[]): number {
  let left = 0;
  let right = height.length - 1;
  let best = 0;
```

Начинаем с самой широкой пары — крайних стенок. `best` — лучшая найденная площадь.

```ts
  while (left < right) {
    // Уровень воды ограничен более низкой стенкой
    const h = Math.min(height[left], height[right]);
    best = Math.max(best, h * (right - left));
```

Пока указатели не встретились, считаем площадь текущей пары: высота — меньшая из двух стенок, ширина — `right - left`. Обновляем максимум. Это единственное место, где вычисляется ответ: каждую «выживающую» пару мы учитываем перед тем, как сдвинуться.

```ts
    // Двигаем более низкую стенку: с ней любой более узкий
    // контейнер точно не лучше текущего
    if (height[left] < height[right]) {
      left++;
    } else {
      right--;
    }
  }
```

Выбрасываем низкую стенку. При равных высотах срабатывает `else` и двигается `right` — это тоже корректно: когда стенки равны, **обе** уже исчерпаны (любая более узкая пара с любой из них не выше `h` и уже), так что можно двигать любую.

Почему нельзя двигать более высокую? Высокая стенка ещё может дать хороший контейнер с какой-то другой стенкой, а мы бы её выбросили, ничего про неё не доказав. Следующая же пара при этом не лучше текущей: ширина уменьшилась, а высота по-прежнему ограничена той же низкой стенкой.

```ts
  return best;
}
```

Когда указатели встретились, все стенки исключены, а лучшая площадь сохранена в `best`.

## Трассировка

`height = [1, 8, 6, 2, 5, 4, 8, 3, 7]`:

```
l=0 r=8: min(1,7)=1 × 8 = 8    best=8   1<7 → l=1
l=1 r=8: min(8,7)=7 × 7 = 49   best=49  8<7? нет → r=7
l=1 r=7: min(8,3)=3 × 6 = 18   best=49  → r=6
l=1 r=6: min(8,8)=8 × 5 = 40   best=49  равны → r=5
l=1 r=5: min(8,4)=4 × 4 = 16   best=49  → r=4
l=1 r=4: min(8,5)=5 × 3 = 15   best=49  → r=3
l=1 r=3: min(8,2)=2 × 2 = 4    best=49  → r=2
l=1 r=2: min(8,6)=6 × 1 = 6    best=49  → r=1
l=1 r=1: цикл окончен → 49
```

На первом шаге стенка высоты `1` выброшена сразу: с ней любой контейнер не выше `1`, а самый широкий из них (площадь `8`) мы уже посчитали.

## Почему это работает

**Инвариант:** любая пара `(i, j)`, где `i < left` или `j > right`, уже не лучше `best`.

- Вначале таких пар нет — инвариант верен.
- Пусть `height[left] ≤ height[right]`, и мы сдвигаем `left`. Новые «исключённые» пары — `(left, j)` для `left < j ≤ right` (пары с `j > right` исключены раньше). Для них `min(height[left], height[j]) ≤ height[left]` и `j - left ≤ right - left`, поэтому площадь `≤ height[left] * (right - left)` — а эта площадь уже учтена в `best`.
- Симметрично для `right`.

Когда `left = right`, исключены все пары, и `best` — максимум по всем.

## Пограничные случаи

- **Две стенки**: одна итерация, ответ — `min(a, b) * 1`.
- **Нулевые стенки** (`[0, 0]`, `[0, 5]`): площадь `0`, ответ `0`.
- **Все стенки одинаковые**: лучший ответ — крайние, он посчитан на первом же шаге.
- **Высокие стенки в середине** (`[1, 100, 100, 1]`): крайние единицы выбросятся, найдётся `100 * 1 = 100`, что больше `1 * 3 = 3`.
- **Равные высоты на концах**: двигается `right`, это корректно (см. разбор).

## Сложность

- **Время `O(n)`**: каждая итерация сдвигает ровно один указатель, расстояние между ними уменьшается на 1.
- **Память `O(1)`**: два индекса, высота и лучший ответ.

## Типичные ошибки

1. **Двигать более высокую стенку** → теряются оптимальные пары (на примере выше после первого шага ушли бы от `8` и не нашли `49`).
2. **Считать высоту как `max`** вместо `min` → вода «переливается» через низкую стенку.
3. **Путать с задачей Trapping Rain Water**: там вода между всеми стенками, здесь — только две стенки, а промежуточные не мешают.
4. **Обновлять `best` после сдвига указателя** → последняя пара теряется или считается пара с `left = right`.
5. **Сортировать массив** → теряются позиции, а ширина зависит именно от индексов.

## Как узнать такую задачу

- Выбрать **два элемента**, а ценность пары зависит от расстояния между ними и от меньшего (или большего) из значений.
- Перебор пар `O(n²)` слишком медленный, а `n` до `10⁵`.
- Можно доказать, что «худший» из крайних элементов больше не нужен.
- Родственные задачи: Two Sum II, 3Sum, Trapping Rain Water (тоже два указателя навстречу, но с другим правилом), Boats to Save People.
