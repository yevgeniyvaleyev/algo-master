## Задача простыми словами

Дан массив целых чисел `nums`. Нужно найти **все уникальные тройки** значений `[a, b, c]` из разных позиций, у которых `a + b + c = 0`. Тройки, состоящие из тех же чисел, считаются одинаковыми и в ответе должны встречаться один раз; порядок троек не важен.

Пример: `nums = [-1, 0, 1, 2, -1, -4]`. Подходят `[-1, 0, 1]` и `[-1, -1, 2]`. Тройка `[0, 1, -1]` (из другой `-1`) — та же самая `[-1, 0, 1]`, второй раз её выводить нельзя.

## Наивный подход

Три вложенных цикла и множество для удаления дубликатов:

```ts naive
const seen = new Set<string>();
for (let i = 0; i < n; i++)
  for (let j = i + 1; j < n; j++)
    for (let k = j + 1; k < n; k++)
      if (nums[i] + nums[j] + nums[k] === 0) {
        seen.add([nums[i], nums[j], nums[k]].sort((x, y) => x - y).join(','));
      }
```

Это `O(n³)`: при `n = 3000` — около 4,5 миллиарда троек. Вдобавок дубликаты убираются уже **после** того, как их нашли, — через строки-ключи. Лишняя работа двойная: внутренние два цикла решают задачу «найти пару с суммой `-nums[i]`», которую в отсортированном массиве можно решить за линейное время, а одинаковые тройки генерируются многократно.

## Ключевое наблюдение

1. **Отсортируем массив.** Зафиксировав первое число `nums[i]`, нужно найти справа от него пары с суммой `-nums[i]` — а это ровно задача Two Sum II, которая в отсортированном массиве решается двумя указателями за `O(n)`. Итог — `O(n²)`.
2. **Сортировка решает и проблему дубликатов.** Одинаковые значения стоят рядом, поэтому достаточно **не брать одно и то же значение дважды** в одной роли: ни как первое число, ни как второе при том же первом. Тогда каждая тройка значений порождается ровно один раз, и множество не нужно.

## Техники

### Сортировка + два указателя

**Что это.** Указатели `left` и `right` идут навстречу по отсортированному отрезку. Если сумма мала — `left++` (нужно больше), если велика — `right--` (нужно меньше). Каждый шаг исключает элемент, который не подходит ни с одним партнёром.

**Типичный шаблон k-Sum.** Для поиска `k` чисел с заданной суммой фиксируем первые `k − 2` числа циклами, а последние два ищем двумя указателями. 3Sum — `O(n²)`, 4Sum — `O(n³)`.

**Как применяется здесь.** Внешний цикл фиксирует `nums[i]`, внутренний `while` ищет все пары на отрезке `[i + 1, n − 1]`. Подробнее — во вкладке «Теория» (два указателя).

### Пропуск дубликатов в отсортированном массиве

**Что это.** Если `nums[k] === nums[k − 1]`, то элемент `k` в той же роли даст ровно те же результаты, что `k − 1`. Его пропускают. Приём типичен для задач «все уникальные комбинации»: 3Sum, 4Sum, Subsets II, Combination Sum II.

**Как применяется здесь.** Пропускаем повторы первого числа (`i`) и второго числа (`left`) после найденной тройки.

### Ранний выход

В отсортированном массиве, если наименьшее из трёх чисел уже положительно, сумма не может быть нулём — дальше искать нечего.

## Разбор кода

```ts
function threeSum(nums: number[]): number[][] {
  // Сортировка позволяет использовать два указателя и легко пропускать дубликаты
  nums.sort((a, b) => a - b);
  const result: number[][] = [];
```

Сортируем **с компаратором** `(a, b) => a - b`: без него `sort` сравнивает числа как строки, и `-1` окажется после `-4`, но `10` — перед `2`. Сортировка меняет входной массив на месте — для этой задачи это допустимо. `result` — список найденных троек.

```ts
  for (let i = 0; i < nums.length - 2; i++) {
    // Если наименьшее число > 0, сумма трёх уже не может быть нулём
    if (nums[i] > 0) break;
```

`i` — позиция первого (наименьшего) числа тройки. Справа нужно ещё хотя бы два элемента, отсюда `nums.length - 2`. Так как массив отсортирован, `nums[left]` и `nums[right]` не меньше `nums[i]`; если `nums[i] > 0`, все три положительны — выходим из цикла целиком (`break`, а не `continue`: дальше числа только больше).

```ts
    // Пропускаем одинаковые первые числа, чтобы не получить повторяющиеся тройки
    if (i > 0 && nums[i] === nums[i - 1]) continue;
```

Если первое число такое же, как на предыдущей итерации, все тройки с ним уже найдены: на предыдущем шаге поиск шёл по отрезку, который включает текущий. Проверка `i > 0` защищает от сравнения с `nums[-1]`.

```ts
    // Ищем пару с суммой -nums[i] справа от i (как в Two Sum II)
    let left = i + 1;
    let right = nums.length - 1;
```

Указатели на концы оставшегося отрезка. Берём только элементы правее `i` — пары с элементами левее уже рассмотрены, когда те были «первым числом».

```ts
    while (left < right) {
      const sum = nums[i] + nums[left] + nums[right];

      if (sum < 0) {
        left++;
      } else if (sum > 0) {
        right--;
```

Стандартный шаг двух указателей. Сумма мала — `nums[left]` слишком мал для любого партнёра на отрезке, выбрасываем его. Велика — выбрасываем `nums[right]`.

```ts
      } else {
        result.push([nums[i], nums[left], nums[right]]);
        left++;
        right--;
```

Нашли тройку — записываем. Поиск на этом **не заканчивается**: при том же `i` может быть несколько разных пар (например, для `-4` пары `[0, 4]` и `[1, 3]`). Сдвигаем оба указателя: при том же `nums[i]` нулевую сумму с `nums[left]` даёт только одно значение третьего числа, поэтому новый ответ возможен лишь при смене **обоих** значений — сдвиг сразу двух указателей просто экономит шаг.

```ts
        // Пропускаем дубликаты второго числа (третье подстроится само)
        while (left < right && nums[left] === nums[left - 1]) left++;
      }
    }
  }
```

Если новый `nums[left]` равен только что использованному, тройка повторилась бы. Пропускаем все такие значения. Про `right` отдельно заботиться не нужно: при новом, большем `nums[left]` и старом значении `nums[right]` сумма будет `> 0`, и обычная ветка `right--` сама уведёт `right` с повторов.

```ts
  return result;
}
```

Возвращаем все найденные тройки.

## Трассировка

`nums = [-1, 0, 1, 2, -1, -4]` → после сортировки `[-4, -1, -1, 0, 1, 2]` (индексы `0..5`):

```
i=0 (−4): l=1 r=5: −4−1+2=−3 <0 → l=2
          l=2 r=5: −4−1+2=−3 <0 → l=3
          l=3 r=5: −4+0+2=−2 <0 → l=4
          l=4 r=5: −4+1+2=−1 <0 → l=5, стоп
i=1 (−1): l=2 r=5: −1−1+2=0 → [−1,−1,2], l=3 r=4
          (nums[3]=0 ≠ nums[2]=−1, пропусков нет)
          l=3 r=4: −1+0+1=0 → [−1,0,1], l=4 r=3, стоп
i=2 (−1): nums[2] = nums[1] → пропуск
i=3 (0):  l=4 r=5: 0+1+2=3 >0 → r=4, стоп
цикл окончен (i < 4)
```

Ответ: `[[-1, -1, 2], [-1, 0, 1]]`. Вторая `-1` на позиции `2` не дала повторной тройки `[-1, 0, 1]` благодаря пропуску в начале итерации `i = 2`.

Все нули, `nums = [0, 0, 0, 0]`: при `i = 0` находим `[0, 0, 0]` (`l=1`, `r=3`), затем `l=2`, `r=2` — стоп. `i = 1` — дубликат, пропуск. Ответ `[[0, 0, 0]]`.

## Почему это работает

**Полнота.** Возьмём любую тройку значений `x ≤ y ≤ z` с суммой `0`. Пусть `i` — **первое** вхождение `x` в отсортированном массиве; эта итерация не пропускается. На отрезке `[i + 1, n − 1]` лежат все нужные `y` и `z`, а два указателя (как доказано для Two Sum II) не выбрасывают элемент, который ещё может составить пару с суммой `-x`. Значит, тройка будет найдена.

**Уникальность.** Для фиксированного значения `x` обрабатывается только одна итерация `i`. Внутри неё после каждой найденной пары `left` уходит со значения `y`, а `right` строго уменьшается — пара `(y, z)` с тем же `y` не повторится, а с тем же `y` и другим `z` сумма была бы не `0`. Значит, каждая тройка значений попадает в ответ один раз.

## Пограничные случаи

- **Меньше трёх элементов**: внешний цикл не выполнится, ответ `[]`.
- **Все положительные** (`[1, 2, 3]`): `break` на первой итерации.
- **Все нули** (`[0, 0, 0, 0]`): одна тройка `[0, 0, 0]`.
- **Много одинаковых пар** (`[-2, 0, 0, 2, 2]`): пропуск по `left` даёт `[-2, 0, 2]` один раз.
- **Несколько пар при одном `i`** (`[-4, 0, 1, 3, 4]`): найдутся и `[-4, 0, 4]`, и `[-4, 1, 3]`, потому что после находки поиск продолжается.

## Сложность

- **Время `O(n²)`**: сортировка `O(n log n)`; внешний цикл — `n` итераций, внутренний проход двух указателей — `O(n)` на итерацию (пропуски дубликатов входят в этот же проход).
- **Память `O(1)`** дополнительно, не считая ответа и памяти самой сортировки (в V8 — `O(log n)`…`O(n)` в зависимости от реализации).

## Типичные ошибки

1. **`sort()` без компаратора** → строковое сравнение: `[2, 10, -4, -1].sort()` даёт `[-1, -4, 10, 2]`.
2. **Остановиться после первой найденной пары** при данном `i` → теряются тройки вроде `[-4, 1, 3]`.
3. **Пропуск дубликатов `i` в виде `nums[i] === nums[i + 1]`** → пропускается первое вхождение, и теряются тройки с двумя одинаковыми числами (`[-1, -1, 2]`).
4. **Не пропускать дубликаты `left`** → в ответе повторы (`[-2, 0, 2]` дважды на `[-2, 0, 0, 2, 2]`).
5. **`continue` вместо `break` при `nums[i] > 0`** — ответ верный, но итерации впустую.

## Как узнать такую задачу

- Найти **все уникальные** наборы из 3 (или `k`) чисел с заданной суммой.
- Порядок элементов в ответе не важен, а важны значения — значит, массив можно сортировать.
- `n` порядка нескольких тысяч: `O(n²)` проходит, `O(n³)` — нет.
- Родственные задачи: Two Sum II (внутренний шаг), 3Sum Closest, 4Sum, 3Sum Smaller, Subsets II и Combination Sum II (тот же приём пропуска дубликатов).
