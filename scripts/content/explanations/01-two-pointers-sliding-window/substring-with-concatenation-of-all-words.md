## Задача простыми словами

Дана строка `s` и массив слов `words`, **все слова одной длины**. Нужно найти все позиции в `s`, с которых начинается подстрока, составленная из **всех** слов `words`, каждого ровно столько раз, сколько оно встречается в массиве, в любом порядке и без промежутков. Вернуть список начальных индексов.

Пример: `s = "barfoothefoobarman"`, `words = ["foo", "bar"]`. С позиции `0` идёт `"barfoo"`, с позиции `9` — `"foobar"`. Ответ `[0, 9]`.

## Наивный подход

Перебрать все начала `i` и для каждого нарезать подстроку длины `totalLen` на слова, сверяя частоты:

```ts naive
for (let i = 0; i + totalLen <= s.length; i++) {
  const seen = new Map<string, number>();
  let ok = true;
  for (let k = 0; k < wordCount; k++) {
    const w = s.slice(i + k * wordLen, i + (k + 1) * wordLen);
    seen.set(w, (seen.get(w) ?? 0) + 1);
    if ((seen.get(w) ?? 0) > (need.get(w) ?? 0)) { ok = false; break; }
  }
  if (ok) result.push(i);
}
```

Это `O(n · m · wordLen)`, где `m` — число слов. Лишняя работа: начала `i` и `i + wordLen` нарезают строку **на одни и те же слова**, просто окно смещено на одно слово. Мы заново считаем частоты `m − 1` слов, которые уже посчитали.

## Ключевое наблюдение

Все слова одной длины `wordLen`. Значит, если начать резать `s` с позиции `offset`, строка превращается в **последовательность слов**: `s[offset..offset+wordLen)`, следующее, и так далее. Любой ответ, начинающийся с позиции `i`, попадает ровно в одну такую нарезку — с `offset = i % wordLen`.

Внутри одной нарезки задача становится обычной задачей про **скользящее окно по словам**: найти окна из `wordCount` подряд идущих слов, у которых частоты совпадают с `words`. Окно двигается на одно слово за шаг, частоты обновляются за `O(1)` слов. Нарезок всего `wordLen` штук.

## Техники

### Скользящее окно с частотами

**Что это.** Окно `[left, right)` с картой частот элементов внутри. При расширении увеличиваем частоту нового элемента, при сужении — уменьшаем частоту уходящего. Окно «хорошее», если частоты совпадают с нужными.

**Типичный шаблон («окно-анаграмма»).** Добавить элемент справа; пока какой-то элемент встречается **чаще, чем нужно**, — убирать слева; если размер окна равен нужному, — записать ответ. Так решаются Find All Anagrams in a String и Permutation in String.

**Как применяется здесь.** Элементы окна — не символы, а слова длины `wordLen`; границы двигаются шагом `wordLen`. Подробнее — во вкладке «Теория» (скользящее окно).

### Несколько нарезок со сдвигом

Если элементы — блоки фиксированной длины, а начало блока может быть где угодно, запускают отдельное окно для каждого остатка `offset ∈ [0, wordLen)`. Каждая позиция строки — начало блока ровно в одной нарезке.

### Сброс окна на «чужом» элементе

Слово, которого нет в `words`, не может входить ни в одну конкатенацию. Любое окно, содержащее его, плохое, поэтому окно сразу начинается заново **после** него.

## Разбор кода

```ts
function findSubstring(s: string, words: string[]): number[] {
  const wordLen = words[0].length;
  const wordCount = words.length;
  const totalLen = wordLen * wordCount;
  const result: number[] = [];
  if (s.length < totalLen) return result;
```

Длина одного слова, число слов и общая длина искомой подстроки. Если `s` короче, ответов нет — выходим сразу.

```ts
  // Сколько раз каждое слово должно встретиться в окне
  const need = new Map<string, number>();
  for (const w of words) need.set(w, (need.get(w) ?? 0) + 1);
```

Карта требуемых частот. Слова в `words` могут повторяться (`["foo", "foo"]`), поэтому нужна именно частота, а не множество. `?? 0` подставляет ноль для слова, которого ещё нет в карте.

```ts
  // Режем s на слова с разными сдвигами: 0, 1, ..., wordLen - 1.
  // Для каждого сдвига запускаем отдельное скользящее окно по «словам»
  for (let offset = 0; offset < wordLen; offset++) {
    const window = new Map<string, number>(); // слова внутри окна
    let left = offset; // начало окна
    let count = 0; // сколько слов сейчас в окне
```

Для каждой нарезки — своё пустое окно: карта частот `window`, начало `left` и число слов `count`.

```ts
    for (let right = offset; right + wordLen <= s.length; right += wordLen) {
      const word = s.slice(right, right + wordLen);
```

`right` — начало очередного слова нарезки; шаг — `wordLen`. Условие гарантирует, что слово целиком помещается в строку.

```ts
      if (!need.has(word)) {
        // Чужое слово рвёт любую конкатенацию — начинаем окно заново после него
        window.clear();
        count = 0;
        left = right + wordLen;
        continue;
      }
```

Чужое слово — сбрасываем окно полностью и ставим `left` сразу за ним. Удалять слова по одному не нужно: ни одно окно, начинающееся до этого слова и заканчивающееся после, не подходит.

```ts
      window.set(word, (window.get(word) ?? 0) + 1);
      count++;
```

Слово нужное — добавляем его в окно.

```ts
      // Слово встретилось чаще, чем нужно — сужаем окно слева
      while (window.get(word)! > need.get(word)!) {
        const leftWord = s.slice(left, left + wordLen);
        window.set(leftWord, window.get(leftWord)! - 1);
        count--;
        left += wordLen;
      }
```

Если слова `word` в окне стало больше, чем требуется, ни одно окно, содержащее всё текущее, не подойдёт. Убираем слова слева по одному, пока лишний экземпляр `word` не уйдёт. Проверяем только `word`: до его добавления ни одно слово не превышало нормы, а добавили мы только его. `!` говорит TypeScript, что значение точно есть: `word` только что добавлено, а `leftWord` лежит в окне.

```ts
      // В окне ровно все слова — нашли ответ
      if (count === wordCount) {
        result.push(left);
        // Сдвигаем окно на одно слово, чтобы искать дальше
        const leftWord = s.slice(left, left + wordLen);
        window.set(leftWord, window.get(leftWord)! - 1);
        count--;
        left += wordLen;
      }
    }
  }
```

Если в окне `wordCount` слов и ни одно не превышает норму, то частоты совпадают с `need` **точно** (сумма частот равна сумме норм, а каждая не больше нормы). Записываем начало окна. Затем убираем самое левое слово, чтобы окно снова стало «неполным» и могло принять следующее слово: следующий ответ в этой нарезке начинается не раньше `left + wordLen`.

```ts
  return result;
}
```

Ответы из разных нарезок идут не по возрастанию, но порядок в задаче не важен.

## Трассировка

`s = "barfoothefoobarman"`, `words = ["foo", "bar"]`: `wordLen = 3`, `wordCount = 2`, `need = {foo: 1, bar: 1}`.

```
offset=0: слова bar(0) foo(3) the(6) foo(9) bar(12) man(15)
  right=0  "bar": window={bar:1} count=1
  right=3  "foo": window={bar:1,foo:1} count=2 → ответ 0
           убираем "bar": count=1, left=3
  right=6  "the": чужое → сброс, left=9
  right=9  "foo": window={foo:1} count=1
  right=12 "bar": window={foo:1,bar:1} count=2 → ответ 9
           убираем "foo": count=1, left=12
  right=15 "man": чужое → сброс, left=18
offset=1: arf(1) oot(4) hef(7) oob(10) arm(13) — все чужие
offset=2: rfo(2) oth(5) efo(8) oba(11) rma(14) — все чужие
ответ [0, 9]
```

Сужение из-за лишнего слова, `s = "foofoobar"`, `words = ["foo", "bar"]`:

```
offset=0:
  right=0 "foo": window={foo:1} count=1
  right=3 "foo": window={foo:2} count=2 — foo больше нормы
          убираем "foo" с left=0: window={foo:1} count=1 left=3
  right=6 "bar": window={foo:1,bar:1} count=2 → ответ 3
```

## Почему это работает

**Инвариант** (в пределах одной нарезки): после обработки слова на позиции `right` окно `[left, right + wordLen)` состоит только из нужных слов, ни одно не превышает норму, а все начала левее `left` уже обработаны: либо записаны как ответ, либо доказуемо не подходят.

- Сброс на чужом слове верен: окно, содержащее чужое слово, не может быть ответом.
- Сужение верно: окно, содержащее лишний экземпляр слова, не может быть ответом, а любое окно с началом между старым и новым `left` содержит этот лишний экземпляр.
- Ответ: окно из `wordCount` слов без превышений — это ровно перестановка `words`.

Любой ответ с началом `i` принадлежит нарезке `offset = i % wordLen` и состоит из нужных слов без превышений, поэтому `left` никогда не перепрыгнет через `i`, и когда `right` дойдёт до последнего слова ответа, окно будет начинаться ровно в `i`.

## Пограничные случаи

- **`s` короче `totalLen`**: ранний выход, `[]`.
- **Повторяющиеся слова** (`words = ["foo", "foo"]`): `need = {foo: 2}`, окно из двух `"foo"` подходит, из трёх — сужается.
- **Перекрывающиеся ответы** (`s = "foobarfoo"`, `words = ["foo", "bar"]`): найдутся `0` и `3` — после ответа окно сдвигается лишь на одно слово.
- **Ответ не кратен `wordLen` по позиции** (начало `1`, `wordLen = 3`): его найдёт нарезка `offset = 1`.
- **Одно слово в `words`**: окно размером в одно слово — по сути поиск всех вхождений.

## Сложность

- **Время `O(n · wordLen)`**: нарезок `wordLen`; в каждой примерно `n / wordLen` слов, каждое входит в окно один раз и выходит один раз, а `slice` и хеширование слова стоят `O(wordLen)`. Итого `wordLen · (n / wordLen) · wordLen = n · wordLen`.
- **Память `O(m · wordLen)`**: карты `need` и `window` хранят до `m` различных слов (`m` — длина `words`) — в комментарии к коду это записано как `O(m)` по числу записей.

## Типичные ошибки

1. **Двигать окно по одному символу** вместо одного слова → границы слов «плывут», частоты считаются неверно.
2. **Запустить только `offset = 0`** → теряются ответы, начинающиеся не с кратной `wordLen` позиции.
3. **Использовать `Set` вместо частот** → ломается на повторяющихся словах.
4. **После ответа сдвигать окно сразу на `totalLen`** (за найденную подстроку) → теряются перекрывающиеся ответы: в `"foobarfoo"` найдётся `0`, но не `3`.
5. **При чужом слове удалять слова по одному**, не сбрасывая окно, — работает, но лишние шаги и больше места для ошибки с `left`.

## Как узнать такую задачу

- Найти все подстроки, являющиеся **перестановкой** заданного набора (символов или слов) — «в любом порядке», «конкатенация», «анаграмма».
- Элементы набора — блоки **фиксированной длины**: сигнал к нарезкам по остатку.
- Родственные задачи: Find All Anagrams in a String и Permutation in String (то же окно, но по символам), Minimum Window Substring (окно с частотами на минимум), Longest Substring Without Repeating Characters.
