## Задача простыми словами

Дана строка `s` из любых печатаемых символов. Нужно проверить, является ли она палиндромом, если **выбросить всё, кроме букв и цифр**, и **не различать регистр**. Вернуть `true` или `false`.

Пример: `s = "A man, a plan, a canal: Panama"`. После очистки получается `"amanaplanacanalpanama"` — читается одинаково в обе стороны, ответ `true`. А `"race a car"` превращается в `"raceacar"` — не палиндром, ответ `false`.

## Наивный подход

Самое очевидное — буквально выполнить условие: построить очищенную строку и сравнить её с перевёрнутой.

```ts naive
const clean = s.toLowerCase().replace(/[^a-z0-9]/g, '');
return clean === clean.split('').reverse().join('');
```

Это короткий и правильный код за `O(n)` времени. Но он создаёт **три новые строки/массива** длины до `n`: очищенную строку, массив символов и перевёрнутую строку. Это `O(n)` дополнительной памяти, хотя исходная строка уже лежит в памяти целиком. Лишняя работа здесь — копирование: чтобы сравнить символы попарно, их вовсе не нужно никуда переписывать.

## Ключевое наблюдение

Палиндром означает: **первый значимый символ равен последнему, второй — предпоследнему** и так далее. Сравнивать можно прямо в исходной строке, если идти двумя индексами с двух концов навстречу друг другу и просто **перешагивать** через «мусорные» символы (пробелы, запятые, двоеточия).

Как только нашлась пара несовпадающих значимых символов — ответ `false`. Если указатели встретились без расхождений — `true`. Память — две переменные.

## Техники

### Два указателя навстречу друг другу

**Что это.** Два индекса: `left` начинает с начала, `right` — с конца. На каждом шаге сравниваем элементы под ними и сдвигаем один или оба указателя к центру. Цикл идёт, пока `left < right`. Каждый указатель проходит не больше `n` позиций, поэтому весь проход линейный.

**Типичный шаблон.**

```ts naive
let left = 0;
let right = n - 1;
while (left < right) {
  // сравнить a[left] и a[right], принять решение
  left++;
  right--;
}
```

**Когда применять.** Задача симметрична относительно концов (палиндромы, разворот массива), или массив отсортирован и нужно искать пару с условием на сумму. Подробнее — во вкладке «Теория» (два указателя).

**Как применяется здесь.** Указатели сравнивают «зеркальные» значимые символы. Дополнительно каждый указатель умеет пропускать незначимые символы.

### Фильтрация «на лету»

Вместо того чтобы сначала очистить строку, а потом работать с ней, мы проверяем каждый символ в момент, когда указатель на него встаёт. Это общий приём: если преобразование данных нужно только для чтения, его часто можно делать лениво, не материализуя результат.

## Разбор кода

```ts
function isPalindrome(s: string): boolean {
  // Проверка: символ — латинская буква или цифра
  const isAlnum = (c: string): boolean => /[a-z0-9]/i.test(c);
```

Вспомогательная функция: `true`, если символ — латинская буква (любого регистра, флаг `i`) или цифра. По условию строка состоит из печатаемых ASCII-символов, поэтому другие алфавиты учитывать не нужно.

```ts
  let left = 0;
  let right = s.length - 1;
```

Указатели на первый и последний символ строки.

```ts
  while (left < right) {
    // Пропускаем «мусор» слева и справа, не создавая новую строку
    if (!isAlnum(s[left])) {
      left++;
      continue;
    }
    if (!isAlnum(s[right])) {
      right--;
      continue;
    }
```

Пока указатели не встретились, проверяем, стоят ли они на значимых символах. Если слева «мусор» — сдвигаем `left` на одну позицию и **начинаем итерацию заново** (`continue`). Это важно: после сдвига указатели могли сойтись, и условие `left < right` нужно проверить снова, прежде чем читать символы. То же самое для `right`. В итоге до сравнения мы доходим, только когда оба указателя стоят на буквах или цифрах.

```ts
    // Сравниваем без учёта регистра
    if (s[left].toLowerCase() !== s[right].toLowerCase()) {
      return false;
    }
```

Оба символа значимые — сравниваем их, приведя к нижнему регистру (`'A'` и `'a'` должны считаться равными). Расхождение означает, что строка точно не палиндром: эти два символа должны были стоять зеркально.

```ts
    // Символы совпали — сдвигаем оба указателя к центру
    left++;
    right--;
  }
```

Пара совпала — она больше не нужна, переходим к следующей паре внутрь.

```ts
  // Указатели встретились, расхождений не было
  return true;
}
```

Цикл закончился, когда `left >= right`: все зеркальные пары проверены. Средний символ (при нечётной длине) не с чем сравнивать — он палиндрому не мешает.

## Трассировка

`s = "A,b a"` (позиции: `0:'A'`, `1:','`, `2:'b'`, `3:' '`, `4:'a'`):

1. `left = 0`, `right = 4`. Оба значимые. `'a' === 'a'` → `left = 1`, `right = 3`.
2. `left = 1`: `','` не значимый → `left = 2`, `continue`.
3. `left = 2`, `right = 3`. `'b'` значимый, `' '` — нет → `right = 2`, `continue`.
4. `left = 2`, `right = 2` — условие `left < right` ложно, цикл окончен. Ответ `true`.

Ловушка с цифрами, `s = "0P"`:

1. `left = 0` (`'0'`), `right = 1` (`'P'`). Оба значимые. `'0' !== 'p'` → `false`.

Если бы `isAlnum` проверяла только буквы, `'0'` был бы пропущен, и ответ оказался бы неверным `true`.

## Почему это работает

**Инвариант:** перед каждой итерацией все значимые символы левее `left` уже сопоставлены с зеркальными значимыми символами правее `right`, и все такие пары совпали.

- Пропуск незначимого символа не меняет очищенную строку, значит инвариант сохраняется.
- Когда оба указателя на значимых символах, это ровно `k`-й значимый символ с начала и `k`-й с конца (все предыдущие пары уже сняты). Палиндром требует их равенства — поэтому несовпадение даёт верный `false`.
- Когда указатели встретились или разошлись, непроверенных пар не осталось — ответ `true`.

## Пограничные случаи

- **Строка из одних «мусорных» символов** (`" "`, `".,"`): указатели сойдутся, пропуская символы, ответ `true` — пустая строка палиндром.
- **Один символ**: цикл не выполняется, `true`.
- **Цифры** (`"0P"`, `"1a1"`): цифры значимые и участвуют в сравнении.
- **Разный регистр** (`"Aa"`): `toLowerCase` делает их равными, `true`.
- **Мусор только с одной стороны** (`"a."`): `right` сдвигается до `left`, ответ `true`.

## Сложность

- **Время `O(n)`**: каждая итерация сдвигает хотя бы один указатель на 1, а суммарно они проходят не больше `n` позиций. Проверка регулярным выражением одного символа — `O(1)`.
- **Память `O(1)`**: только два индекса; новых строк не создаётся (`toLowerCase` от одного символа — константа).

## Типичные ошибки

1. **Забыть цифры** (`/[a-z]/i`) → `"0P"` даёт неверный `true`.
2. **Пропускать мусор вложенными `while` без проверки `left < right`** → указатель вылетает за пределы строки на входе вроде `".,"`.
3. **Сравнивать без приведения регистра** → `"Aa"` даёт `false`.
4. **Сдвигать только один указатель после совпадения** → лишние сравнения или бесконечный цикл.
5. **Условие `left <= right`** — не ошибка, но лишняя итерация: средний символ сравнивается сам с собой.

## Как узнать такую задачу

- Слова «палиндром», «читается одинаково в обе стороны», «симметрично».
- Нужно сравнивать элементы с двух концов: начало с концом, второй с предпоследним.
- Просят `O(1)` памяти или явно намекают, что копировать строку не нужно.
- Родственные задачи: Valid Palindrome II (можно удалить один символ), Reverse String, Two Sum II, Container With Most Water — везде два указателя идут навстречу.
