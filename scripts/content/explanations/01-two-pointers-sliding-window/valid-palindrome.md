## Задача простыми словами

Дана строка `s` из любых печатаемых символов. Нужно проверить, является ли она палиндромом, если **выбросить всё, кроме букв и цифр**, и **не различать регистр**. Вернуть `true` или `false`.

Пример: `s = "A man, a plan, a canal: Panama"`. После очистки получается `"amanaplanacanalpanama"` — читается одинаково в обе стороны, ответ `true`. А `"race a car"` превращается в `"raceacar"` — не палиндром, ответ `false`.

Задачу удобно разбить на две независимые части: **очистить** строку и **проверить**, что очищенная строка — палиндром.

## Наивный подход

Самое буквальное решение — очистить строку, перевернуть её и сравнить с исходной очищенной:

```ts naive
const clean = s.toLowerCase().replace(/[^a-z0-9]/g, '');
return clean === clean.split('').reverse().join('');
```

Это правильный код за `O(n)`, но он делает лишнюю работу. Он создаёт ещё **массив символов и перевёрнутую строку** — две копии длины `n`, — и всегда переворачивает строку **целиком**, даже если первая и последняя буквы различаются и ответ `false` был ясен с первого же сравнения. К тому же на собеседовании такой ответ обычно встречают вопросом «а без `reverse`?» — от вас ждут именно техники двух указателей.

## Ключевое наблюдение

Палиндром означает: **первый символ равен последнему, второй — предпоследнему** и так далее. Переворачивать строку не нужно: достаточно идти двумя индексами с двух концов навстречу друг другу и сравнивать «зеркальные» символы.

Если сначала один раз очистить строку, то в ней останутся только значимые символы в нижнем регистре, и сравнение становится совсем простым: `clean[left] !== clean[right]` → `false`. Указатели встретились без расхождений → `true`. Никаких пропусков и особых случаев внутри цикла.

## Техники

### Предобработка строки регулярным выражением

**Что это.** Прежде чем решать задачу, приводим данные к удобному виду. Здесь это одна строчка:

```ts naive
s.toLowerCase().replace(/[^a-z0-9]/g, '');
```

- `toLowerCase()` — `'A'` и `'a'` становятся одинаковыми;
- `/[^a-z0-9]/g` — класс «всё, что **не** латинская буква и **не** цифра» (`^` внутри скобок — отрицание), флаг `g` — заменить **все** вхождения, а не только первое;
- заменяем на пустую строку, то есть просто удаляем.

**Порядок важен**: сначала `toLowerCase`, потом `replace`. Иначе заглавные буквы не попадут в класс `a-z` и будут удалены.

### Два указателя навстречу друг другу

**Что это.** Два индекса: `left` начинает с начала, `right` — с конца. На каждом шаге сравниваем элементы под ними и сдвигаем указатели к центру. Цикл идёт, пока `left < right`. Вместе указатели проходят не больше `n` позиций, поэтому проход линейный.

**Типичный шаблон.**

```ts naive
let left = 0;
let right = n - 1;
while (left < right) {
  // сравнить a[left] и a[right], принять решение
  left++;
  right--;
}
```

**Когда применять.** Задача симметрична относительно концов (палиндромы, разворот массива), или массив отсортирован и нужно искать пару с условием на сумму. Подробнее — во вкладке «Теория» (два указателя).

**Как применяется здесь.** Указатели сравнивают зеркальные символы очищенной строки и останавливаются на первом расхождении.

## Разбор кода

```ts
function isPalindrome(s: string): boolean {
  // Очищаем строку: нижний регистр, оставляем только буквы и цифры
  const clean = s.toLowerCase().replace(/[^a-z0-9]/g, '');
```

Шаг подготовки. После него в `clean` только символы `a–z` и `0–9`. По условию строка состоит из печатаемых ASCII-символов, поэтому другие алфавиты учитывать не нужно. Например, `"A man, a plan"` превращается в `"amanaplan"`.

```ts
  let left = 0;
  let right = clean.length - 1;
```

Указатели на первый и последний символ **очищенной** строки. Если `clean` пустая, `right = -1`, и цикл ниже не выполнится ни разу.

```ts
  while (left < right) {
    // Символы на концах различаются — не палиндром
    if (clean[left] !== clean[right]) {
      return false;
    }
```

Пока указатели не встретились, сравниваем зеркальные символы. Регистр и «мусор» уже убраны, так что сравнение прямое. Расхождение означает, что строка точно не палиндром: эти два символа должны были совпасть. Выходим сразу, не проверяя остальное.

```ts
    // Совпали — сдвигаем оба указателя к центру
    left++;
    right--;
  }
```

Пара совпала — она больше не нужна, переходим к следующей паре внутрь. Сдвигаем **оба** указателя.

```ts
  // Указатели встретились, расхождений не было
  return true;
}
```

Цикл закончился, когда `left >= right`: все зеркальные пары проверены. Средний символ (при нечётной длине) не с чем сравнивать — он палиндрому не мешает.

## Трассировка

`s = "A,b a"`:

1. Очистка: `toLowerCase` → `"a,b a"`, `replace` убирает `','` и `' '` → `clean = "aba"`.
2. `left = 0`, `right = 2`: `'a' === 'a'` → `left = 1`, `right = 1`.
3. `left < right` ложно (`1 < 1`), цикл окончен. Ответ `true`.

`s = "race a car"`:

1. `clean = "raceacar"` (длина 8), `left = 0`, `right = 7`.
2. `'r' === 'r'` → `left = 1`, `right = 6`.
3. `'a' === 'a'` → `left = 2`, `right = 5`.
4. `'c' === 'c'` → `left = 3`, `right = 4`.
5. `'e' !== 'a'` → `return false`.

Ловушка с цифрами, `s = "0P"`:

1. `clean = "0p"`, `left = 0`, `right = 1`.
2. `'0' !== 'p'` → `false`.

Если бы регулярное выражение удаляло и цифры (`/[^a-z]/g`), то `clean = "p"` и ответ оказался бы неверным `true`.

## Почему это работает

Очистка ровно повторяет условие задачи: после неё `clean` — та самая строка, которая должна читаться одинаково в обе стороны.

**Инвариант цикла:** перед каждой итерацией все пары `clean[i]` и `clean[len - 1 - i]` для `i < left` уже проверены и совпали, а `right = len - 1 - left`.

- Если `clean[left] !== clean[right]`, строка не равна своему развороту — ответ `false` верен.
- Если совпали, сдвиг обоих указателей сохраняет инвариант.
- Когда `left >= right`, непроверенных пар не осталось — все зеркальные символы равны, ответ `true`.

## Пограничные случаи

- **Строка из одних «мусорных» символов** (`" "`, `".,"`): `clean = ""`, `right = -1`, цикл не выполняется, ответ `true` — пустая строка палиндром.
- **Один значимый символ**: цикл не выполняется, `true`.
- **Цифры** (`"0P"`, `"1a1"`): цифры значимые и участвуют в сравнении.
- **Разный регистр** (`"Aa"`): после `toLowerCase` это `"aa"`, `true`.
- **Подчёркивание** (`"ab_a"`): `_` не буква и не цифра, удаляется → `"aba"`, `true`. Осторожно с `\W`: этот класс считает `_` «словесным» символом и не удалит его.

## Сложность

- **Время `O(n)`**: `toLowerCase` и `replace` — по одному проходу, цикл двух указателей — не больше `n / 2` итераций.
- **Память `O(n)`**: очищенная копия строки `clean`.

**Follow-up на собеседовании:** «а за `O(1)` памяти?». Тогда строку не копируют, а указатели ходят по исходной `s` и сами перешагивают через незначимые символы:

```ts naive
if (!isAlnum(s[left])) { left++; continue; }
if (!isAlnum(s[right])) { right--; continue; }
if (s[left].toLowerCase() !== s[right].toLowerCase()) return false;
```

Логика та же, но появляются пропуски внутри цикла — поэтому основное решение сначала очищает строку, а этот вариант стоит знать как оптимизацию.

## Типичные ошибки

1. **Забыть цифры** (`/[^a-z]/g`) → `"0P"` даёт неверный `true`.
2. **`replace` до `toLowerCase`** → заглавные буквы удаляются как «мусор»: `"Ab"` превращается в `"b"`, и неверно получается `true`.
3. **Забыть флаг `g`** → удаляется только первый незначимый символ.
4. **Сдвигать только один указатель после совпадения** → лишние сравнения или бесконечный цикл.
5. **Условие `left <= right`** — не ошибка, но лишняя итерация: средний символ сравнивается сам с собой.

## Как узнать такую задачу

- Слова «палиндром», «читается одинаково в обе стороны», «симметрично».
- Нужно сравнивать элементы с двух концов: начало с концом, второй с предпоследним.
- Во входе есть «шум» (регистр, пробелы, знаки), который по условию надо игнорировать, — сначала нормализуйте данные, потом решайте чистую задачу.
- Родственные задачи: Valid Palindrome II (можно удалить один символ), Reverse String, Two Sum II, Container With Most Water — везде два указателя идут навстречу.
