## Задача простыми словами

Даны строки `s` и `t`. Нужно найти **самую короткую подстроку** `s`, которая содержит все символы `t` **с учётом повторов** (если в `t` две `a`, в подстроке их должно быть не меньше двух). Если такой нет — вернуть пустую строку `""`. Ответ гарантированно единственный.

Пример: `s = "ADOBECODEBANC"`, `t = "ABC"`. Подстрока `"BANC"` содержит `A`, `B` и `C`, и короче не найти — ответ `"BANC"`.

## Наивный подход

Перебрать все подстроки и для каждой проверить, покрывает ли она `t`:

```ts naive
let best = '';
for (let i = 0; i < s.length; i++) {
  const have = new Map<string, number>();
  for (let j = i; j < s.length; j++) {
    have.set(s[j], (have.get(s[j]) ?? 0) + 1);
    if (covers(have, need) && (best === '' || j - i + 1 < best.length)) {
      best = s.slice(i, j + 1);
      break; // от этого i дальше только длиннее
    }
  }
}
```

Даже с `break` это `O(n²)` пар `(i, j)`, а проверка `covers` стоит `O(k)` (`k` — число различных символов). Лишняя работа: для начала `i + 1` мы заново набираем частоты почти тех же символов, что уже посчитали для `i`, и каждый раз сверяем **все** символы `t`, хотя изменился только один.

## Ключевое наблюдение

Две идеи убирают лишнюю работу.

1. **Скользящее окно.** Покрытие `t` монотонно: если окно `[left, right]` покрывает `t`, то и любое более широкое тоже. Поэтому можно двигать `right` вперёд, пока окно не начнёт покрывать `t`, а затем двигать `left`, пока покрытие сохраняется. Обе границы идут только вперёд.
2. **Счётчик недостающих символов.** Вместо проверки всех символов `t` храним `missing` — сколько символов `t` (с повторами) окну ещё не хватает. Когда символ добавляется или убирается, `missing` меняется на `0` или `1`, а условие «окно покрывает `t`» — это просто `missing === 0`. Проверка за `O(1)`.

## Техники

### Скользящее окно на минимум

**Что это.** Окно переменного размера: `right` расширяет его, пока условие не выполнено; как только выполнено — `left` сужает, пока условие держится, обновляя ответ на каждом хорошем окне. Каждый символ входит в окно и выходит из него не больше одного раза.

**Типичный шаблон.**

```ts naive
for (let right = 0; right < n; right++) {
  добавить(s[right]);
  while (окно_хорошее()) {
    обновить_ответ(left, right);
    убрать(s[left]);
    left++;
  }
}
```

**Когда применять.** Нужен **кратчайший** непрерывный отрезок, удовлетворяющий условию, которое сохраняется при расширении. Подробнее — во вкладке «Теория» (скользящее окно).

**Как применяется здесь.** Условие — «окно содержит все символы `t` с кратностями».

### Одна карта «долга» вместо двух карт частот

Классическая реализация хранит две карты — частоты `t` и частоты окна — и счётчик «сколько символов уже удовлетворено». Здесь используется одна карта `need`: **сколько символов `c` окну ещё не хватает**. Значение может уйти в минус — это значит, что в окне **избыток** символа `c`. Такой избыточный символ можно убрать без потери покрытия.

Правила обновления `missing`:

- добавили `c`, и до этого `need[c] > 0` — символ был нужен, `missing--`;
- убрали `c`, и после этого `need[c] > 0` — символа снова не хватает, `missing++`.

## Разбор кода

```ts
function minWindow(s: string, t: string): string {
  if (t.length > s.length) return '';
```

Если `t` длиннее `s`, никакая подстрока `s` не вместит все символы `t`.

```ts
  // need[c] — сколько ещё символов c не хватает в окне (может уйти в минус — это избыток)
  const need = new Map<string, number>();
  for (const c of t) need.set(c, (need.get(c) ?? 0) + 1);
```

Изначально окно пустое, значит, не хватает всех символов `t` в полном количестве. Ключи `need` — ровно символы `t`; символы, которых в `t` нет, в карту не попадают и дальше игнорируются.

```ts
  let missing = t.length; // сколько символов t ещё не покрыто окном
  let left = 0;
  let bestStart = 0;
  let bestLen = Infinity;
```

- `missing` — суммарный «долг» по всем символам (только положительная часть).
- `left` — левая граница окна.
- `bestStart`, `bestLen` — лучшее найденное окно. Храним начало и длину, а не саму подстроку, чтобы не делать `slice` на каждом улучшении.

```ts
  for (let right = 0; right < s.length; right++) {
    const c = s[right];
    if (need.has(c)) {
      // Символ был нужен (а не лишний) — покрыли ещё один символ t
      if (need.get(c)! > 0) missing--;
      need.set(c, need.get(c)! - 1);
    }
```

Расширяем окно символом `c`. Если `c` не из `t`, ничего не меняется. Если из `t`: проверяем **до** уменьшения, был ли долг положительным. Если да — этот символ закрыл часть долга, `missing` уменьшается. Если долг уже был `≤ 0`, символ лишний: уменьшаем `need[c]` (избыток растёт), но `missing` не трогаем.

```ts
    // Окно покрывает весь t — сужаем слева, пока покрытие сохраняется
    while (missing === 0) {
      if (right - left + 1 < bestLen) {
        bestLen = right - left + 1;
        bestStart = left;
      }
```

`missing === 0` — окно покрывает `t`. Это кандидат: если он короче лучшего, запоминаем. Условие проверяется на каждом шаге сужения, поэтому будет записано самое короткое хорошее окно для данного `right`.

```ts
      const d = s[left];
      if (need.has(d)) {
        need.set(d, need.get(d)! + 1);
        // Убрали символ, без которого окно больше не покрывает t
        if (need.get(d)! > 0) missing++;
      }
      left++;
    }
  }
```

Убираем левый символ `d`. Если он из `t`, долг по нему растёт на 1. Если долг стал положительным — это был не избыточный, а необходимый экземпляр, и окно перестало покрывать `t`: `missing++`, цикл `while` закончится. Если долг остался `≤ 0` — убрали лишний экземпляр, окно по-прежнему хорошее, продолжаем сужать.

```ts
  return bestLen === Infinity ? '' : s.slice(bestStart, bestStart + bestLen);
}
```

Если хорошего окна не нашлось — пустая строка. Иначе вырезаем лучшее окно один раз.

## Трассировка

`s = "ADOBECODEBANC"` (индексы `0..12`), `t = "ABC"`. Старт: `need = {A:1, B:1, C:1}`, `missing = 3`.

```
r=0  'A': A 1→0, missing=2
r=1  'D', r=2 'O': не из t
r=3  'B': B 1→0, missing=1
r=4  'E': не из t
r=5  'C': C 1→0, missing=0
     окно [0..5] "ADOBEC" len=6 → best=6 (start 0)
     убираем 'A': A 0→1 > 0 → missing=1, left=1
r=6..8 'O','D','E': не из t
r=9  'B': B 0 не > 0 (лишний), B 0→−1
r=10 'A': A 1→0, missing=0
     [1..10] len=10 — не лучше; убираем 'D', left=2
     [2..10] len=9  — убираем 'O', left=3
     [3..10] len=8  — убираем 'B': B −1→0, не > 0, left=4
     [4..10] len=7  — убираем 'E', left=5
     [5..10] len=6  — не < 6; убираем 'C': C 0→1 → missing=1, left=6
r=11 'N': не из t
r=12 'C': C 1→0, missing=0
     [6..12] len=7 — убираем 'O', left=7
     [7..12] len=6 — убираем 'D', left=8
     [8..12] len=5 → best=5 (start 8); убираем 'E', left=9
     [9..12] len=4 → best=4 (start 9); убираем 'B': B 0→1 → missing=1, left=10
конец → s.slice(9, 13) = "BANC"
```

Обратите внимание на `r=9`: вторая `B` стала избыточной (`need[B] = −1`). Благодаря этому на `r=10` окно смогло выбросить первую `B` (позиция `3`) без потери покрытия.

## Почему это работает

**Инвариант карты:** для каждого символа `c` из `t` значение `need[c]` равно «сколько раз `c` встречается в `t`» минус «сколько раз `c` встречается в окне». А `missing` — сумма положительных частей `need[c]`, то есть сколько символов `t` окну не хватает. Оба правила обновления `missing` сохраняют это равенство: `missing` меняется ровно тогда, когда `need[c]` переходит через границу между `0` и `1`.

**Полнота поиска:** возьмём любое окно `[i, j]`, покрывающее `t`, и посмотрим на `left` в момент, когда `right = j`.

- Если `left ≤ i`, то каждое окно `[left, j]` содержит `[i, j]` и тоже покрывает `t`, поэтому `while` не остановится, пока `left` не дойдёт до `i`, и длина `j − i + 1` будет проверена.
- Если `left > i`, значит, символ `i` уже убран при каком-то `right = j' ≤ j`, а перед этим было проверено окно `[i, j']`, которое не длиннее `[i, j]`.

В обоих случаях `bestLen ≤ j − i + 1`. А записываются только окна с `missing === 0`, то есть настоящие покрытия. Значит, `bestLen` — ровно минимальная длина.

## Пограничные случаи

- **`t` длиннее `s`**: ранний выход, `""`.
- **Нет покрытия** (`s = "a"`, `t = "aa"` — отсеется сразу; `s = "ab"`, `t = "c"`): `missing` никогда не станет `0`, ответ `""`.
- **Повторы в `t`** (`t = "AAB"`): `need[A] = 2`, окно должно содержать две `A`.
- **`s === t`**: окно покроет `t` на последнем символе, ответ — вся строка.
- **Ответ — один символ** (`s = "a"`, `t = "a"`): `"a"`.
- **Регистр важен**: `'a'` и `'A'` — разные ключи `Map`.

## Сложность

- **Время `O(m + n)`** (`m = |s|`, `n = |t|`): построение `need` — `O(n)`; `right` проходит `s` один раз, `left` — тоже не больше `m` шагов суммарно; операции с `Map` — `O(1)`. Итоговый `slice` — `O(m)`.
- **Память `O(k)`**: карта `need` хранит только различные символы `t` (`k ≤ n`, и не больше размера алфавита).

## Типичные ошибки

1. **Уменьшать `missing` для каждого символа из `t`**, даже лишнего → `missing` уходит в минус и `missing === 0` не срабатывает.
2. **Проверять `need[c] > 0` после уменьшения**, а не до → необходимый экземпляр считается лишним.
3. **Игнорировать кратности** (хранить `Set` символов `t`) → `t = "AA"` покрывается одной `A`.
4. **Обновлять ответ после сужения**, а не перед ним → записывается окно, которое уже не покрывает `t`.
5. **Делать `slice` при каждом улучшении** — корректно, но лишние `O(m)` на каждый раз; лучше хранить начало и длину.

## Как узнать такую задачу

- «Минимальная подстрока / подмассив, **содержащая все** элементы набора» — классическое окно на минимум с частотами.
- Условие монотонно по расширению: если отрезок подходит, любой содержащий его тоже подходит.
- Нужно учитывать **кратности** — значит, карта частот и счётчик «сколько ещё не хватает».
- Родственные задачи: Minimum Size Subarray Sum (то же окно, агрегат — сумма), Substring with Concatenation of All Words и Find All Anagrams in a String (окно с частотами фиксированного размера), Longest Substring with At Most K Distinct Characters.
