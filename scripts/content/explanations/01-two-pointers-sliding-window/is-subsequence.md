## Задача простыми словами

Даны две строки `s` и `t`. Нужно проверить, можно ли получить `s` из `t`, **вычеркнув** некоторые символы и не меняя порядок оставшихся. То есть встречаются ли все символы `s` в `t` в том же порядке (не обязательно подряд).

Пример: `s = "abc"`, `t = "ahbgdc"`. Вычёркиваем `h`, `g`, `d` — остаётся `"abc"`, ответ `true`. А `s = "axc"` получить нельзя: буквы `x` в `t` нет, ответ `false`.

## Наивный подход

Можно рассуждать «в лоб»: перебрать все способы выбрать `|s|` позиций из `t` и проверить, даёт ли какой-то из них `s`. Число таких наборов — биномиальный коэффициент, это экспонента.

Чуть умнее — рекурсия «взять или пропустить символ `t[j]`»:

```ts naive
function check(i: number, j: number): boolean {
  if (i === s.length) return true;
  if (j === t.length) return false;
  if (s[i] === t[j] && check(i + 1, j + 1)) return true;
  return check(i, j + 1); // пропустить t[j]
}
```

Она перебирает и вариант «сопоставить», и вариант «пропустить», хотя второй после удачного совпадения **никогда не нужен**. Без мемоизации это экспоненциально, с мемоизацией — `O(|s| · |t|)` времени и памяти. Лишняя работа — в рассмотрении альтернатив, которые заведомо не лучше.

## Ключевое наблюдение

Если символ `s[i]` совпал с `t[j]`, его **выгодно сопоставить именно здесь**, с самым ранним возможным вхождением. Любое более позднее вхождение того же символа оставляет для остальной части `s` меньше (или столько же) символов `t`. Значит, выбор жадный и откатываться не нужно.

Отсюда алгоритм: один указатель `i` по `s`, другой `j` по `t`. `j` всегда идёт вперёд, `i` сдвигается только при совпадении. Если `i` дошёл до конца `s` — ответ `true`.

## Техники

### Два указателя по двум последовательностям

**Что это.** Каждой последовательности — свой индекс. Оба двигаются только вперёд, но с разной скоростью: один — на каждом шаге, другой — по условию. Это та же схема, что при слиянии двух отсортированных массивов в merge sort.

**Типичный шаблон.**

```ts naive
let i = 0;
for (let j = 0; j < b.length; j++) {
  if (подходит(a[i], b[j])) i++;
}
```

**Когда применять.** Нужно сопоставить элементы двух последовательностей с сохранением порядка: подпоследовательности, слияние, пересечение отсортированных массивов. Подробнее — во вкладке «Теория» (два указателя).

**Как применяется здесь.** `j` читает `t`, `i` отмечает, сколько символов `s` уже найдено.

### Жадный выбор

**Что это.** На каждом шаге принимается локально лучшее решение без возврата назад. Работает, когда можно доказать, что локально лучший выбор не ухудшает итог.

**Как применяется здесь.** Совпавший символ сразу «засчитываем». Почему это безопасно — в разделе «Почему это работает».

## Разбор кода

```ts
function isSubsequence(s: string, t: string): boolean {
  // i — сколько символов s уже нашли в t
  let i = 0;
```

`i` одновременно и индекс следующего искомого символа `s[i]`, и количество уже найденных символов. Пока ничего не найдено — `0`.

```ts
  // Идём по t один раз и «жадно» сопоставляем символы
  for (let j = 0; j < t.length && i < s.length; j++) {
```

`j` проходит `t` слева направо. Условие цикла двойное:

- `j < t.length` — `t` не закончилась;
- `i < s.length` — ещё есть что искать. Если вся `s` уже найдена, дальше читать `t` бессмысленно, и цикл останавливается досрочно. Заодно это защищает от обращения к `s[i]` за пределами строки.

```ts
    if (s[i] === t[j]) {
      // Нашли очередной символ s — ищем следующий
      i++;
    }
  }
```

Если текущий символ `t` — тот, который мы ищем, засчитываем его и переходим к следующему символу `s`. Если нет — просто идём дальше по `t` (символ `t[j]` вычёркивается). Никаких откатов: `j` увеличивается на каждой итерации.

```ts
  // Все символы s найдены по порядку
  return i === s.length;
}
```

Если `i` дошёл до длины `s`, все её символы найдены в `t` в правильном порядке. Иначе какой-то символ найти не удалось.

## Трассировка

`s = "abc"`, `t = "ahbgdc"`:

```
j=0 t[0]='a' ищем s[0]='a' → совпало, i=1
j=1 t[1]='h' ищем s[1]='b' → нет
j=2 t[2]='b' ищем s[1]='b' → совпало, i=2
j=3 t[3]='g' ищем s[2]='c' → нет
j=4 t[4]='d' ищем s[2]='c' → нет
j=5 t[5]='c' ищем s[2]='c' → совпало, i=3
цикл окончен (i = 3 = s.length) → true
```

`s = "axc"`, `t = "ahbgdc"`:

```
j=0 'a' = s[0] → i=1
j=1..5: ни один символ не равен s[1]='x'
цикл окончен (j = 6), i=1 ≠ 3 → false
```

Обратите внимание: `'c'` на позиции `5` не засчитывается, потому что мы ещё не нашли `'x'` — порядок сохраняется автоматически.

## Почему это работает

**Утверждение:** если `s` — подпоследовательность `t`, то существует вложение, где каждый символ `s[i]` сопоставлен с **самым ранним** подходящим символом `t` после предыдущего сопоставленного.

Доказательство обменом. Возьмём любое корректное вложение. Пусть `s[0]` в нём сопоставлен с `t[p]`, а самое раннее вхождение — `t[q]`, `q < p`. Перенесём `s[0]` на `t[q]`: порядок не нарушен, ведь `s[1]` сопоставлен с позицией больше `p > q`. Повторяя это для каждого следующего символа, получаем ровно то вложение, которое строит жадный алгоритм.

Значит, если жадный проход не нашёл `s` целиком, то никакого вложения нет, и ответ `false` верен. Если нашёл — он сам и есть вложение.

## Пограничные случаи

- **Пустая `s`**: цикл не выполнится ни разу (`i < s.length` ложно), `0 === 0` → `true`. Пустая строка — подпоследовательность любой.
- **Пустая `t` при непустой `s`**: цикл не выполнится, `false`.
- **`s` длиннее `t`**: найти все символы невозможно, ответ получится `false` естественным образом.
- **Повторяющиеся символы** (`s = "aa"`, `t = "ab"`): после первого `'a'` второго не найдётся — `false`.
- **`s === t`**: каждый символ совпадёт сразу, `true`.

## Сложность

- **Время `O(|t|)`**: `j` проходит `t` не больше одного раза, каждая итерация — одно сравнение. Досрочный выход может сократить проход.
- **Память `O(1)`**: два индекса.

**Вариант с множеством запросов.** Если для одной большой `t` нужно проверить миллионы разных `s`, выгодно один раз построить для каждого символа отсортированный список его позиций в `t`, а затем для каждого символа `s` искать следующую позицию бинарным поиском: `O(|s| · log |t|)` на запрос.

## Типичные ошибки

1. **Сдвигать `i` при каждой итерации** → получается проверка «`s` — префикс/подстрока», а не подпоследовательность.
2. **Не ограничивать цикл условием `i < s.length`** → лишняя работа и обращение к `s[i]` за концом строки (в JS это `undefined`, ошибки нет, но логика становится неочевидной).
3. **Путать подпоследовательность с подстрокой** и искать `t.includes(s)`.
4. **Проверять только наличие символов** (например, через `Set`), забыв про порядок: `s = "ba"`, `t = "ab"` должно дать `false`.

## Как узнать такую задачу

- Слова «подпоследовательность», «удалить некоторые символы, не меняя порядок».
- Две последовательности, и нужно проверить, «вкладывается» ли одна в другую.
- Родственные задачи: Merge Sorted Array (слияние двумя указателями), Longest Common Subsequence (там жадность не работает — нужна ДП, потому что выбирать надо в обеих строках), Number of Matching Subsequences (вариант с многими запросами и бинарным поиском).
