## Задача простыми словами

Есть текст записки `ransomNote` и текст журнала `magazine`. Можно ли **вырезать буквы из журнала** и сложить из них записку? Каждую букву журнала разрешено использовать только один раз. Вернуть `true` или `false`.

Пример: `ransomNote = "aa"`, `magazine = "aab"` — в журнале две `a`, их хватает, ответ `true`. А для `magazine = "ab"` вторую `a` взять негде — ответ `false`.

## Наивный подход

Первое, что приходит в голову, — для каждой буквы записки найти такую же в журнале и «вычеркнуть» её:

```ts naive
const letters = magazine.split('');
for (const ch of ransomNote) {
  const pos = letters.indexOf(ch);
  if (pos === -1) return false;
  letters.splice(pos, 1); // вычёркиваем использованную букву
}
return true;
```

Это верно, но каждый `indexOf` и `splice` — линейный проход по журналу. Итого `O(m · n)`: при длинах `10⁵` это до `10¹⁰` операций. Лишняя работа в том, что мы **ищем конкретную букву перебором**, хотя нам вообще не важно, где она стоит в журнале. Важно только, **сколько** таких букв там есть.

## Ключевое наблюдение

Порядок букв в обеих строках не имеет значения. Записку можно составить тогда и только тогда, когда для **каждой буквы** её количество в журнале не меньше, чем в записке.

Значит, достаточно один раз посчитать частоты букв журнала, а потом «тратить» их на записку. Как только какой-то счётчик ушёл в минус — буквы не хватило.

## Техники

### Подсчёт частот (частотная таблица)

**Что это.** Частотная таблица хранит «символ → сколько раз он встретился». Обычно это хеш-таблица `Map`, но когда алфавит маленький и известен заранее, удобнее и быстрее обычный массив, где индекс — код символа.

**Типичный шаблон.** Задачи вида «можно ли из одного набора получить другой», «являются ли строки перестановками друг друга», «хватает ли ресурсов» решаются так:

1. пройти по «запасу» и увеличить счётчики;
2. пройти по «потребностям» и уменьшить счётчики;
3. проверить, что ни один счётчик не стал отрицательным (или что все равны нулю — если наборы должны совпасть).

**Как применяется здесь.** Алфавит — 26 строчных латинских букв, поэтому таблица — массив `count` длины 26, а индекс буквы — `charCodeAt(i) - 97` (код `'a'` равен 97). Это по сути та же хеш-таблица, только с «идеальной» хеш-функцией. Подробнее о хеш-таблицах — во вкладке «Теория».

### Ранний выход (early exit)

Две отсечки экономят работу: если записка длиннее журнала, букв точно не хватит; а при проходе по записке мы возвращаем `false` сразу, как только счётчик ушёл в минус, не дочитывая строку.

## Разбор кода

```ts
function canConstruct(ransomNote: string, magazine: string): boolean {
  // Букв в записке больше, чем в журнале, — точно не хватит
  if (ransomNote.length > magazine.length) return false;
```

Дешёвая проверка за `O(1)`: каждая буква записки требует отдельную букву журнала, поэтому длинная записка из короткого журнала не складывается. На корректность ответа отсечка не влияет — основной алгоритм тоже вернул бы `false`, — она лишь избавляет от лишних проходов.

```ts
  // Сколько раз каждая из 26 букв есть в журнале
  const count = new Array<number>(26).fill(0);
  for (let i = 0; i < magazine.length; i++) {
    count[magazine.charCodeAt(i) - 97]++;
  }
```

Создаём 26 нулевых счётчиков: `count[0]` — для `a`, `count[1]` — для `b`, …, `count[25]` — для `z`. Затем один проход по журналу: `charCodeAt(i)` даёт код символа, вычитание 97 превращает его в номер буквы в алфавите. Используем `charCodeAt`, а не `magazine[i]`, чтобы сразу получить число и не создавать строки.

```ts
  // «Тратим» буквы на записку
  for (let i = 0; i < ransomNote.length; i++) {
    const idx = ransomNote.charCodeAt(i) - 97;
    count[idx]--;
    // Ушли в минус — этой буквы в журнале не хватает
    if (count[idx] < 0) return false;
  }
```

Теперь каждая буква записки «забирает» одну такую же букву из запаса. После уменьшения `count[idx]` показывает, сколько таких букв **ещё осталось** в журнале. Если значение стало `-1`, значит, мы потребовали больше, чем было, — ответ `false`. Проверяем сразу после каждого уменьшения, поэтому выходим на первой же нехватке.

```ts
  return true;
}
```

Прошли всю записку, и ни один счётчик не стал отрицательным — всех букв хватило.

## Трассировка

`ransomNote = "aa"`, `magazine = "aab"`:

```
длины: 2 <= 3 — отсечка не срабатывает
журнал: 'a' → count[a]=1, 'a' → count[a]=2, 'b' → count[b]=1
записка:
  i=0 'a': count[a]=2-1=1, не < 0
  i=1 'a': count[a]=1-1=0, не < 0
конец цикла → true
```

`ransomNote = "aa"`, `magazine = "ab"`:

```
длины: 2 <= 2 — отсечка не срабатывает
журнал: count[a]=1, count[b]=1
записка:
  i=0 'a': count[a]=0
  i=1 'a': count[a]=-1 < 0 → return false
```

`ransomNote = "a"`, `magazine = "b"`: в журнале `count[b] = 1`, а `count[a] = 0`; первая же `a` записки даёт `count[a] = -1` → `false`.

## Почему это работает

После первого цикла `count[x]` равно числу букв `x` в журнале. Во втором цикле поддерживается инвариант: `count[x]` = (число `x` в журнале) − (число `x` в уже просмотренной части записки).

- Если записку можно составить, то для каждой буквы её в записке не больше, чем в журнале, поэтому разность никогда не станет отрицательной — дойдём до `return true`.
- Если нельзя, то есть буква `x`, которой в записке больше, чем в журнале. В момент, когда в записке встретится «лишняя» `x`, разность станет `-1` — вернём `false`.

## Пограничные случаи

- **Записка длиннее журнала** — мгновенный `false` без подсчёта.
- **Одинаковые строки** — все счётчики после второго цикла равны нулю, ответ `true`.
- **Буква записки вообще отсутствует в журнале** — её счётчик `0`, после уменьшения `-1`, `false` на первом же вхождении.
- **Лишние буквы в журнале** не мешают: положительные остатки в `count` никак не проверяются.

## Сложность

- **Время `O(m + n)`**, где `m` — длина журнала, `n` — длина записки: по одному проходу на каждую строку, внутри — операции `O(1)`.
- **Память `O(1)`**: массив всегда из 26 чисел, независимо от длины строк.

## Типичные ошибки

1. **Проверять только наличие буквы** (`magazine.includes(ch)`) без учёта количества — `"aa"` и `"ab"` дадут ложный `true`.
2. **Считать частоты записки и журнала, но сравнивать на равенство** — здесь нужно «не меньше», лишние буквы в журнале допустимы (в отличие от задачи про анаграммы).
3. **Перепутать направления**: увеличивать счётчики по записке и уменьшать по журналу — тогда проверка «< 0» ловит не то.
4. **Забыть `- 97`** и писать `count[charCode]` — массив разрастается до индексов 97–122, а `fill(0)` их не заполнил: `undefined - 1 = NaN`, и сравнение `NaN < 0` всегда ложно.
5. **`indexOf` + `splice`** — корректно, но квадратично и не проходит по времени на больших входах.

## Как узнать такую задачу

- Порядок элементов **не важен**, важны только **количества** — сигнал к частотной таблице.
- Формулировки «можно ли составить / собрать из», «хватит ли», «каждый элемент можно использовать один раз».
- Маленький фиксированный алфавит (только строчные латинские буквы) — вместо `Map` подойдёт массив на 26 элементов.
- Родственные задачи: Valid Anagram (наборы должны совпасть), Group Anagrams, Find All Anagrams in a String, Minimum Window Substring (частоты внутри скользящего окна).
