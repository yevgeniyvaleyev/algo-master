## Задача простыми словами

Даны две строки `s` и `t` одинаковой длины. Они **изоморфны**, если символы `s` можно заменить по некоторому правилу так, чтобы получилась `t`: каждый символ всегда заменяется одним и тем же, а два разных символа не могут превратиться в один и тот же. Символ может перейти сам в себя.

Пример: `s = "egg"`, `t = "add"` — правило `e → a`, `g → d` подходит, ответ `true`. Для `s = "f11"`, `t = "b23"` символ `1` пришлось бы заменить и на `2`, и на `3` — ответ `false`.

## Наивный подход

Можно для каждой пары позиций `i < j` проверить, что «одинаковость» сохраняется: `s[i] === s[j]` тогда и только тогда, когда `t[i] === t[j]`:

```ts naive
for (let i = 0; i < s.length; i++) {
  for (let j = i + 1; j < s.length; j++) {
    if ((s[i] === s[j]) !== (t[i] === t[j])) return false;
  }
}
return true;
```

Это верное определение изоморфности, но `O(n²)`: при `n = 5 · 10⁴` — больше миллиарда сравнений. Лишняя работа: для каждой позиции мы **заново ищем все её «копии»** по строке, хотя достаточно помнить, во что уже превратился каждый символ.

## Ключевое наблюдение

Правило замены — это **отображение символов**, и его можно строить на лету, слева направо. Первое появление символа `a` в паре с `b` фиксирует правило `a → b`; все следующие появления `a` обязаны стоять в паре с тем же `b`.

Но одной таблицы `s → t` мало: она не заметит, что **два разных** символа `s` склеились в один символ `t` (`s = "ab"`, `t = "aa"`: `a → a`, `b → a` — таблица довольна). Поэтому храним ещё и обратное отображение `t → s`. Две таблицы вместе гарантируют **биекцию** — взаимно-однозначное соответствие.

## Техники

### Хеш-таблица как отображение «символ → символ»

**Что это.** `Map` хранит пары «ключ → значение» и за амортизированное `O(1)` отвечает на вопрос «есть ли ключ и что ему сопоставлено». Это естественный способ хранить построенную по ходу функцию: «во что я уже решил превращать этот символ».

**Типичный шаблон.** Когда нужно проверить, что две последовательности «устроены одинаково» (одинаковые элементы стоят на одних и тех же местах), идём по ним синхронно и строим отображение. При каждом повторном ключе сверяем сохранённое значение с текущим.

**Как применяется здесь.** `sToT` хранит, во что превращается символ `s`, `tToS` — из какого символа `s` получился символ `t`. Подробнее о хеш-таблицах — во вкладке «Теория».

### Проверка биекции двумя таблицами

Отображение `f` — биекция, если оно (1) **однозначно**: один вход → один выход, и (2) **инъективно**: разные входы → разные выходы. Таблица `sToT` следит за (1), таблица `tToS` — за (2). Тот же приём используется в Word Pattern, где вместо второй строки — слова.

## Разбор кода

```ts
function isIsomorphic(s: string, t: string): boolean {
  // Отображения в обе стороны: s -> t и t -> s
  const sToT = new Map<string, string>();
  const tToS = new Map<string, string>();
```

Две пустые таблицы. Длины строк по условию равны, поэтому отдельной проверки длины нет.

```ts
  for (let i = 0; i < s.length; i++) {
    const a = s[i];
    const b = t[i];

    const mappedA = sToT.get(a);
    const mappedB = tToS.get(b);
```

Идём по позициям синхронно: на шаге `i` символ `a` из `s` должен превратиться в символ `b` из `t`. Достаём уже известные правила: `mappedA` — во что раньше превращали `a`, `mappedB` — какой символ раньше превращали в `b`. Если правила ещё нет, `get` вернёт `undefined`.

```ts
    // Символ a уже отображается во что-то другое — противоречие
    if (mappedA !== undefined && mappedA !== b) return false;
    // В символ b уже отображается другой символ — нарушена взаимность
    if (mappedB !== undefined && mappedB !== a) return false;
```

Две проверки — две половины биекции. Первая ловит «`a` раньше становился другим символом» (как `1 → 2`, а теперь `1 → 3`). Вторая — «в `b` уже превращается другой символ» (как `a → a`, а теперь `b → a`). Сравниваем именно с `undefined`: так отличаем «правила нет» от «правило есть, но другое».

```ts
    // Запоминаем пару (повторная запись той же пары безвредна)
    sToT.set(a, b);
    tToS.set(b, a);
  }
```

Если противоречий нет, фиксируем пару в обе стороны. Если пара уже была, `set` перезапишет то же значение — ничего не изменится, поэтому отдельно проверять «новая ли это пара» не нужно.

```ts
  return true;
}
```

Все позиции согласованы — отображение является биекцией, строки изоморфны.

## Трассировка

`s = "paper"`, `t = "title"`:

1. `i = 0`: `a = 'p'`, `b = 't'`. Правил нет. Записываем `p → t`, `t → p`.
2. `i = 1`: `a = 'a'`, `b = 'i'`. Правил нет. Записываем `a → i`, `i → a`.
3. `i = 2`: `a = 'p'`, `b = 't'`. `mappedA = 't'` совпадает с `b`, `mappedB = 'p'` совпадает с `a`. Перезаписываем ту же пару.
4. `i = 3`: `a = 'e'`, `b = 'l'`. Правил нет. Записываем `e → l`, `l → e`.
5. `i = 4`: `a = 'r'`, `b = 'e'`. Правил нет (в `tToS` ключа `'e'` нет — там ключи из `t`). Записываем `r → e`, `e → r`.

Ответ `true`.

`s = "badc"`, `t = "baba"` — пример, где нужна вторая таблица:

1. `i = 0`: `'b'` и `'b'` — записываем `b → b`.
2. `i = 1`: `'a'` и `'a'` — записываем `a → a`.
3. `i = 2`: `a = 'd'`, `b = 'b'`. `mappedA = undefined` (символ `d` новый), но `mappedB = tToS.get('b') = 'b'`, а это не `'d'` → `false`.

С одной таблицей `sToT` мы бы записали `d → b` и не заметили, что и `b`, и `d` превращаются в `b`.

## Почему это работает

Инвариант после обработки позиций `0..i`: `sToT` и `tToS` — взаимно обратные отображения, построенные по этому префиксу, и префиксы `s[0..i]` и `t[0..i]` изоморфны.

- Если на шаге `i` обе проверки прошли, то пара `(a, b)` либо уже была, либо и `a`, и `b` новые. В обоих случаях после записи таблицы остаются взаимно обратными, инвариант сохраняется.
- Если проверка не прошла, то либо один символ `s` пришлось бы превратить в два разных, либо два разных символа `s` — в один. Ни одно правило замены не может это исправить, поэтому `false` корректен.

Дойдя до конца, имеем биекцию на всей строке — ответ `true`.

## Пограничные случаи

- **Строки из одного символа** — всегда изоморфны.
- **Символ переходит сам в себя** (`"ab"` и `"ab"`) — разрешено, таблицы просто хранят `a → a`, `b → b`.
- **Склейка двух символов** (`"ab"` и `"aa"`) — ловится только второй таблицей.
- **Любые ASCII-символы, включая цифры и пробелы** — `Map` работает с любыми строками-ключами.

## Сложность

- **Время `O(n)`**: один проход, на каждом шаге по два `get` и два `set`, каждый за амортизированное `O(1)`.
- **Память `O(k)`**, где `k` — размер алфавита: в каждой таблице не больше одного ключа на каждый различный символ, то есть не больше 128 для ASCII, независимо от длины строк.

## Типичные ошибки

1. **Только одна таблица `s → t`** — пропускает `"ab"` / `"aa"` и `"badc"` / `"baba"`.
2. **Проверять только `mappedA !== b`** без условия `!== undefined` — тогда первая же новая пара считается противоречием.
3. **Сравнивать количество различных символов** в строках — это необходимое, но не достаточное условие: у `"ab"`/`"ba"` и `"aab"`/`"abb"` оно одинаковое, но вторая пара не изоморфна.
4. **Сортировать или считать частоты** — изоморфность зависит от **порядка** символов, а не только от количеств.

## Как узнать такую задачу

- «Можно ли заменить одни символы другими», «следует ли строка шаблону», «одинаковая структура повторов» — это проверка биекции.
- Ключевые слова: «no two characters may map to the same character», «each … maps to exactly one».
- Решение: синхронный проход + две хеш-таблицы (или сравнение последовательностей «индекс первого вхождения»).
- Родственные задачи: Word Pattern, Find and Replace Pattern, Group Shifted Strings.
