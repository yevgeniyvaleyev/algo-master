## Задача простыми словами

Даны шаблон `pattern` из букв и строка `s` из слов, разделённых одиночными пробелами. Нужно проверить, что `s` **следует шаблону**: каждой букве соответствует ровно одно слово, каждому слову — ровно одна буква, и разные буквы не могут означать одно и то же слово.

Пример: `pattern = "abba"`, `s = "dog cat cat dog"` — `a = dog`, `b = cat`, ответ `true`. Для `s = "dog cat cat fish"` буква `a` должна была бы означать и `dog`, и `fish` — ответ `false`. Для `pattern = "aaaa"` и той же `"dog cat cat dog"` одна буква `a` означала бы разные слова — тоже `false`.

## Наивный подход

Прямо по определению: для каждой пары позиций `i < j` проверить, что буквы совпадают тогда и только тогда, когда совпадают слова:

```ts naive
const words = s.split(' ');
if (words.length !== pattern.length) return false;
for (let i = 0; i < words.length; i++) {
  for (let j = i + 1; j < words.length; j++) {
    if ((pattern[i] === pattern[j]) !== (words[i] === words[j])) return false;
  }
}
return true;
```

Это `O(n²)` сравнений, а каждое сравнение слов ещё и стоит до длины слова. Лишняя работа: для каждой позиции мы **заново ищем её «двойников»**, хотя достаточно один раз запомнить, какое слово уже закреплено за буквой и какая буква — за словом.

## Ключевое наблюдение

Это ровно задача Isomorphic Strings, только вторая «строка» состоит не из символов, а из **слов**. Соответствие «буква ↔ слово» строим на лету, слева направо: первая встреча фиксирует связь, все последующие обязаны с ней совпадать.

Чтобы соответствие было **взаимно-однозначным** (биекцией), нужны две таблицы:

- `буква → слово` ловит «буква `a` сначала `dog`, потом `fish`»;
- `слово → буква` ловит «буквы `a` и `b` обе означают `dog`».

## Техники

### Хеш-таблица как отображение

**Что это.** `Map` хранит пары «ключ → значение» и за амортизированное `O(1)` отвечает, есть ли ключ и что с ним связано. Ключом может быть любая строка — в том числе целое слово.

**Типичный шаблон.** Синхронный проход по двум последовательностям одинаковой длины; при первом появлении ключа записываем связь, при повторном — сверяем с записанной. Подробнее о хеш-таблицах — во вкладке «Теория».

**Как применяется здесь.** `charToWord` хранит закреплённое за буквой слово, `wordToChar` — закреплённую за словом букву.

### Проверка биекции двумя таблицами

Отображение — биекция, если оно однозначно (одна буква — одно слово) и инъективно (разные буквы — разные слова). Каждая из двух таблиц отвечает за одно из этих свойств. Без второй таблицы `pattern = "ab"`, `s = "dog dog"` прошло бы проверку.

### Предварительная проверка длин

Биекция между позициями возможна только при равном числе букв и слов. Эта проверка ещё и защищает от выхода за границы: без неё `words[i]` мог бы оказаться `undefined`.

## Разбор кода

```ts
function wordPattern(pattern: string, s: string): boolean {
  const words = s.split(' ');
```

Разбиваем строку на слова. По условию пробелы одиночные и нет пробелов по краям, поэтому `split(' ')` даёт ровно список слов без пустых строк.

```ts
  // Количество букв и слов должно совпадать
  if (words.length !== pattern.length) return false;
```

Если букв и слов разное количество, сопоставить их по позициям нельзя — сразу `false`. Например, `pattern = "aaa"` и `s = "dog dog"`.

```ts
  // Отображения в обе стороны: буква -> слово и слово -> буква
  const charToWord = new Map<string, string>();
  const wordToChar = new Map<string, string>();
```

Две пустые таблицы — прямое и обратное отображения.

```ts
  for (let i = 0; i < pattern.length; i++) {
    const c = pattern[i];
    const w = words[i];

    const mappedWord = charToWord.get(c);
    const mappedChar = wordToChar.get(w);
```

На шаге `i` буква `c` должна соответствовать слову `w`. Достаём уже известные связи: какое слово раньше было у буквы `c` и какая буква раньше была у слова `w`. Если связи нет — `undefined`.

```ts
    // Буква уже связана с другим словом
    if (mappedWord !== undefined && mappedWord !== w) return false;
    // Слово уже связано с другой буквой
    if (mappedChar !== undefined && mappedChar !== c) return false;
```

Две проверки — две половины биекции. Если связь есть и указывает не туда, шаблон нарушен. Проверка `!== undefined` отделяет «ещё не видели» от «видели, но с другим партнёром».

```ts
    charToWord.set(c, w);
    wordToChar.set(w, c);
  }
```

Противоречий нет — фиксируем пару в обе стороны. Повторная запись уже существующей пары ничего не меняет.

```ts
  return true;
}
```

Все позиции согласованы — строка следует шаблону.

## Трассировка

`pattern = "abba"`, `s = "dog cat cat dog"`:

```
words = ["dog", "cat", "cat", "dog"], длины 4 = 4
i=0: c='a', w="dog": связей нет → a→dog, dog→a
i=1: c='b', w="cat": связей нет → b→cat, cat→b
i=2: c='b', w="cat": mappedWord="cat" = w, mappedChar='b' = c → ок
i=3: c='a', w="dog": mappedWord="dog" = w, mappedChar='a' = c → ок
→ true
```

`pattern = "abba"`, `s = "dog dog dog dog"` — нужна обратная таблица:

```
i=0: c='a', w="dog": связей нет → a→dog, dog→a
i=1: c='b', w="dog": mappedWord=undefined (буква b новая),
     mappedChar='a' ≠ 'b' → false
```

`pattern = "abba"`, `s = "dog cat cat fish"`: на `i = 3` буква `a` уже связана с `"dog"`, а пришло `"fish"` → первая проверка даёт `false`.

## Почему это работает

Инвариант после обработки позиций `0..i`: `charToWord` и `wordToChar` взаимно обратны, и префикс шаблона соответствует префиксу слов биекцией.

- Если обе проверки прошли, то пара `(c, w)` либо уже была, либо и буква, и слово новые — после записи таблицы остаются взаимно обратными.
- Если проверка упала, то либо одна буква должна означать два слова, либо одно слово — две буквы. Биекция невозможна, `false` корректен.

Плюс предварительная проверка длин гарантирует, что каждой букве есть позиционная пара. Дойдя до конца, получаем биекцию на всём шаблоне.

## Пограничные случаи

- **Разное число букв и слов** — `false` до цикла.
- **Одна буква и одно слово** — всегда `true`.
- **Разные буквы, одинаковые слова** (`"ab"`, `"dog dog"`) — ловит `wordToChar`.
- **Одинаковые буквы, разные слова** (`"aa"`, `"dog cat"`) — ловит `charToWord`.
- **Слово, совпадающее с буквой** (`pattern = "a"`, `s = "a"`) — таблицы разные, ключи не путаются.

## Сложность

- **Время `O(n + m)`**, где `n` — длина `pattern`, `m` — длина `s`: `split` проходит по `s` один раз, цикл делает `n` итераций; хеширование слов суммарно стоит порядка их общей длины, то есть `O(m)`.
- **Память `O(n + m)`**: массив слов хранит копию текста `s`, а таблицы — не больше `n` пар.

## Типичные ошибки

1. **Только одна таблица** — пропускает случай «две буквы → одно слово».
2. **Забыть проверку длин** — если `pattern` длиннее, `words[i]` становится `undefined`; если слов больше, лишние слова просто не проверятся. В обоих случаях возможен ложный `true` (`pattern = "a"`, `s = "dog cat"`).
3. **Хранить в одной общей `Map` и буквы, и слова** — однобуквенное слово `"a"` и буква `'a'` столкнутся как одинаковые ключи.
4. **Проверка `if (mappedWord && mappedWord !== w)`** — для строк работает (слова непустые), но та же привычка с числами/индексами ломается на `0`; надёжнее сравнивать с `undefined`.

## Как узнать такую задачу

- «Следует шаблону», «full match», «bijection», «each letter maps to exactly one word and vice versa».
- Две последовательности одной длины, у которых нужно сравнить **структуру повторов**, а не сами значения.
- Решение: синхронный проход + две хеш-таблицы «туда» и «обратно».
- Родственные задачи: Isomorphic Strings (тот же приём для символов), Word Pattern II (шаблон без разделителей — уже перебор с возвратом), Find and Replace Pattern.
