## Задача простыми словами

Дан **отсортированный** массив `nums` без повторов. Нужно сжать его в список диапазонов из подряд идущих целых чисел: диапазон из нескольких чисел записывается как `"a->b"`, а одиночное число — как `"a"`. Диапазоны должны покрывать ровно числа массива и ничего лишнего.

Пример: `nums = [0, 1, 2, 4, 5, 7]` → `["0->2", "4->5", "7"]`. Числа `0, 1, 2` идут подряд, затем «дырка» (нет `3`), затем `4, 5`, ещё дырка (нет `6`), и одиночное `7`.

## Наивный подход

Можно рассуждать «по числам»: пройти по всем целым от минимума до максимума и смотреть, какие из них есть в массиве:

```ts naive
const set = new Set(nums);
const result: string[] = [];
for (let x = nums[0]; x <= nums[nums.length - 1]; x++) {
  if (set.has(x) && !set.has(x - 1)) {
    let y = x;
    while (set.has(y + 1)) y++;
    result.push(x === y ? `${x}` : `${x}->${y}`);
  }
}
```

Это работает для маленьких значений, но время зависит от **разброса значений**, а не от длины массива: для `[-2^31, 2^31 - 1]` цикл сделает четыре миллиарда шагов ради двух чисел. Лишняя работа — перебирать числа, которых в массиве нет, и игнорировать то, что массив уже **отсортирован**.

## Ключевое наблюдение

Раз массив отсортирован и без повторов, числа одного диапазона стоят в массиве **подряд**, и соседние отличаются ровно на `1`. Диапазон обрывается в точности там, где `nums[i + 1] !== nums[i] + 1` — в месте «разрыва», — или на последнем элементе.

Значит, достаточно одного прохода по индексам: помним, где начался текущий диапазон, и на каждом разрыве «закрываем» его и выводим.

## Техники

### Линейный проход с разбиением на группы (интервалы)

**Что это.** Многие задачи об интервалах сводятся к тому, чтобы пройти по отсортированным данным и разрезать их на **максимальные куски**, внутри которых выполняется условие (числа подряд, интервалы перекрываются, символы одинаковые). Для этого хранят начало текущего куска и закрывают кусок, когда условие нарушается.

**Типичный шаблон.**

1. `start` — начало текущей группы;
2. для каждого `i` проверяем, заканчивается ли группа на `i` (последний элемент или следующий «не продолжает» группу);
3. если заканчивается — выводим группу `[start, i]` и ставим `start = i + 1`.

**Как применяется здесь.** Условие «продолжения группы» — `nums[i + 1] === nums[i] + 1`. Каждая группа и есть диапазон из ответа. Подробнее об интервалах — во вкладке «Теория».

### Проверка «конец группы» вперёд, а не назад

Решение смотрит на **следующий** элемент: «заканчивается ли диапазон на `i`». Это позволяет выводить диапазон в момент его завершения и не обрабатывать последний диапазон отдельно после цикла — условие `i === nums.length - 1` закрывает его внутри цикла.

## Разбор кода

```ts
function summaryRanges(nums: number[]): string[] {
  const result: string[] = [];
  // Индекс начала текущего диапазона
  let start = 0;
```

`result` копит строки-диапазоны. `start` — индекс первого элемента текущего, ещё не закрытого диапазона. Первый диапазон начинается с позиции `0`.

```ts
  for (let i = 0; i < nums.length; i++) {
    // Диапазон заканчивается на i, если это последний элемент
    // или следующий элемент идёт не подряд
    const isEnd = i === nums.length - 1 || nums[i + 1] !== nums[i] + 1;
    if (!isEnd) continue;
```

Для каждой позиции решаем: закончился ли здесь диапазон? Две причины: элементов больше нет, или следующий элемент не равен текущему плюс один. Благодаря `||` второе условие не вычисляется на последнем элементе, так что `nums[i + 1]` за пределами массива не читается. Если диапазон продолжается — просто идём дальше: `start` не меняется, диапазон «растёт».

```ts
    // Один элемент — "a", несколько — "a->b"
    result.push(start === i ? `${nums[i]}` : `${nums[start]}->${nums[i]}`);
```

Диапазон `[start, i]` закрыт — выводим его. Если он из одного элемента (`start === i`), формат `"a"`, иначе `"a->b"` из первого и последнего значений. Шаблонные строки сами превращают числа (в том числе отрицательные) в текст.

```ts
    // Следующий диапазон начинается сразу после разрыва
    start = i + 1;
  }
```

Следующий диапазон начинается с элемента после разрыва. На последней итерации `start` станет равным `nums.length` — это безвредно, цикл уже завершается.

```ts
  return result;
}
```

Все диапазоны собраны по порядку. Для пустого массива цикл не выполнится ни разу, и вернётся пустой список.

## Трассировка

`nums = [0, 2, 3, 4, 6, 8, 9]`:

```
start=0
i=0 (0): след. 2 ≠ 1      → конец, start=0=i → "0",    start=1
i=1 (2): след. 3 = 3      → продолжаем
i=2 (3): след. 4 = 4      → продолжаем
i=3 (4): след. 6 ≠ 5      → конец, start=1≠3 → "2->4", start=4
i=4 (6): след. 8 ≠ 7      → конец, start=4=i → "6",    start=5
i=5 (8): след. 9 = 9      → продолжаем
i=6 (9): последний        → конец, start=5≠6 → "8->9", start=7
result = ["0", "2->4", "6", "8->9"]
```

`nums = [-1]`: `i = 0` — последний элемент, `start === i`, ответ `["-1"]`.

## Почему это работает

Инвариант: перед обработкой позиции `i` все элементы левее `start` уже покрыты выведенными диапазонами, а элементы `nums[start..i-1]` идут подряд с шагом `1` (это начало текущего диапазона).

- Если на `i` разрыва нет, `nums[i + 1] = nums[i] + 1`, диапазон корректно продолжается.
- Если разрыв есть, то `nums[start..i]` — подряд идущие числа, а `nums[i] + 1` в массиве **нет** (массив отсортирован и без повторов, значит следующее число больше `nums[i] + 1`). Поэтому диапазон `[nums[start], nums[i]]` нельзя расширить вправо; влево его нельзя расширить, потому что на `start - 1` тоже был разрыв. Значит, это максимальный диапазон, и он не содержит чисел вне массива.

Каждый элемент попадает ровно в один диапазон, диапазоны выводятся по возрастанию и максимальны — это и есть наименьший отсортированный список.

## Пограничные случаи

- **Пустой массив** — цикл не выполняется, ответ `[]`.
- **Один элемент** — сразу последний, ответ `["a"]`.
- **Все числа подряд** (`[1, 2, 3]`) — один диапазон `"1->3"`, выводится на последнем элементе.
- **Нет ни одной пары подряд** (`[1, 3, 5]`) — все диапазоны одиночные.
- **Отрицательные числа и границы `int`** — в JavaScript `nums[i] + 1` считается в `number` без переполнения, даже для `2^31 - 1`. В языках с 32-битным `int` безопаснее сравнивать разность в 64 битах.

## Сложность

- **Время `O(n)`**: один проход, на каждом шаге проверка за `O(1)` и, возможно, создание одной строки.
- **Память `O(1)`** дополнительно, не считая ответа: только переменные `start` и `i`.

## Типичные ошибки

1. **Забыть закрыть последний диапазон** — если проверять только `nums[i + 1] !== nums[i] + 1`, без условия «последний элемент», в JavaScript это случайно сработает (`undefined !== …`), но в других языках будет выход за границы массива; а вариант «закрываем диапазон, когда видим разрыв слева» требует дописать последний диапазон после цикла, и его часто забывают.
2. **Неверный формат одиночного числа** — `"7->7"` вместо `"7"`.
3. **Забыть обновить `start`** после вывода — все следующие диапазоны начнутся с самого первого элемента.
4. **Переполнение в языках с `int`** при `nums[i] + 1` для `2^31 - 1`.
5. **Сравнивать значения, а не индексы** при выборе формата (`nums[start] === nums[i]` вместо `start === i`) — здесь работает из-за уникальности, но ломается, если в похожей задаче допускаются повторы.

## Как узнать такую задачу

- Отсортированный массив и просьба «сжать», «сгруппировать подряд идущие», «вывести диапазоны» — один проход с `start` и закрытием группы на разрыве.
- Слова «range», «consecutive», «cover exactly» — признаки задач на интервалы.
- Родственные задачи: Missing Ranges (выводить дырки, а не диапазоны), Merge Intervals (группы перекрывающихся интервалов), Longest Consecutive Sequence (подряд идущие числа в **неотсортированном** массиве — там нужен `Set`), String Compression.
