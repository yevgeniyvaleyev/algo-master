## Задача простыми словами

Дана строка `s` только из скобок `()`, `[]` и `{}`. Нужно проверить, что скобки расставлены правильно: каждая открывающая закрывается скобкой **того же типа**, закрываются они **в правильном порядке** (вложенно), и у каждой закрывающей есть пара.

Пример: `"([])"` и `"()[]{}"` — правильные, ответ `true`. `"(]"` — тип не совпал, `"([)]"` — порядок нарушен, `"(("` — скобки не закрыты; во всех трёх случаях ответ `false`.

## Наивный подход

Можно многократно удалять из строки «пустые пары», пока это возможно:

```ts naive
let prev = '';
while (s !== prev) {
  prev = s;
  s = s.replace('()', '').replace('[]', '').replace('{}', '');
}
return s === '';
```

Корректно: правильная строка схлопывается до пустой. Но каждый проход строит новую строку за `O(n)`, а проходов может быть до `n / 2` (для `"((((…))))"` за проход исчезает одна пара) — итого `O(n²)`. Лишняя работа: мы **заново просматриваем всю строку**, хотя после удаления пары новая «пустая пара» может появиться только рядом с местом удаления.

Другая ошибочная идея — считать открытые скобки каждого типа счётчиками. Для `"([)]"` все счётчики корректны, но строка неправильная: счётчики не видят **порядка**.

## Ключевое наблюдение

Скобки вкладываются друг в друга, поэтому **последняя открытая скобка должна закрыться первой**. Когда встречаем закрывающую, она обязана соответствовать самой «свежей» ещё не закрытой открывающей.

«Последний пришёл — первый ушёл» — это ровно **стек**. Храним в нём открытые скобки; закрывающая сравнивается с вершиной и снимает её. Один проход, и каждая «пустая пара» схлопывается в момент появления.

## Техники

### Стек (LIFO)

**Что это.** Стек — структура, в которую кладут (`push`) и из которой достают (`pop`) элементы с одного конца: последний положенный достаётся первым. В JavaScript стек — это обычный массив с методами `push` и `pop`, обе операции за `O(1)`.

**Типичный шаблон.** Стек нужен, когда текущий элемент нужно сопоставить с **ближайшим незакрытым** предыдущим: скобки, теги HTML, вложенные вызовы, вычисление выражений, «отмена последнего действия». Открывающее событие — `push`, закрывающее — `pop` и проверка соответствия.

**Как применяется здесь.** В стеке лежат открывающие скобки, которые ещё ждут своей пары. Вершина — самая внутренняя из них. Подробнее о стеке — во вкладке «Теория».

### Таблица пар «закрывающая → открывающая»

Объект `pairs` одновременно решает две задачи: отличает закрывающую скобку от открывающей (есть ли ключ) и говорит, какая открывающая ей нужна. Это избавляет от цепочки `if`/`switch` на шесть символов.

### Ранний выход по чётности

В правильной строке скобки разбиваются на пары, значит её длина чётная. Нечётную длину можно отсечь сразу.

## Разбор кода

```ts
function isValid(s: string): boolean {
  // Нечётная длина — какая-то скобка точно останется без пары
  if (s.length % 2 === 1) return false;
```

Дешёвая отсечка за `O(1)`. На корректность она не влияет — без неё алгоритм тоже вернул бы `false`, — но экономит проход для половины «плохих» входов.

```ts
  // Закрывающая скобка -> парная открывающая
  const pairs: Record<string, string> = { ')': '(', ']': '[', '}': '{' };
  const stack: string[] = [];
```

Ключи `pairs` — только закрывающие скобки. Для открывающей `pairs[c]` вернёт `undefined` — так мы их и различаем. `stack` — пустой массив-стек открытых скобок.

```ts
  for (const c of s) {
    const open = pairs[c];
    if (open === undefined) {
      // Открывающая скобка — откладываем до её закрытия
      stack.push(c);
```

Идём по символам. Если `c` не ключ в `pairs`, это открывающая скобка: кладём её на вершину стека, она станет самой внутренней незакрытой скобкой.

```ts
    } else if (stack.pop() !== open) {
      // Закрывающая должна закрыть ПОСЛЕДНЮЮ открытую скобку того же типа.
      // Пустой стек (pop вернёт undefined) — тоже ошибка
      return false;
    }
  }
```

Иначе `c` — закрывающая, а `open` — нужная ей открывающая. Снимаем вершину стека и сравниваем. Одно условие ловит сразу три ошибки:

- **не тот тип** (`"(]"`: на вершине `(`, а нужна `[`);
- **не тот порядок** (`"([)]"`: на вершине `[`, а пришла `)`);
- **нечего закрывать** (`"())"`: стек пуст, `pop()` вернёт `undefined`, который не равен ни одной скобке).

Если совпало, `pop` уже снял пару со стека — она закрыта, идём дальше.

```ts
  // Все открытые скобки должны быть закрыты
  return stack.length === 0;
}
```

После прохода в стеке остались открывающие без пары (как в `"(("` или `"(()"`) — строка неправильная. Пустой стек — все скобки закрыты.

## Трассировка

`s = "{[]()}"` (длина 6, чётная):

```
'{' открывающая → stack = [{]
'[' открывающая → stack = [{, []
']' нужна '[', pop → '[' совпало → stack = [{]
'(' открывающая → stack = [{, (]
')' нужна '(', pop → '(' совпало → stack = [{]
'}' нужна '{', pop → '{' совпало → stack = []
стек пуст → true
```

`s = "([)]"` (длина 4):

```
'(' → stack = [(]
'[' → stack = [(, []
')' нужна '(', pop → '[' ≠ '(' → false
```

`s = "(("`: обе скобки уходят в стек, в конце `stack.length = 2` → `false`.

## Почему это работает

Инвариант: после обработки префикса стек содержит **в порядке открытия** все открывающие скобки префикса, которые ещё не закрыты, а все закрытые пары префикса соответствуют друг другу по типу и вложены правильно.

- Открывающая скобка становится самой внутренней незакрытой — `push` на вершину сохраняет инвариант.
- В правильной строке закрывающая обязана закрыть самую внутреннюю незакрытую, то есть вершину стека. Если вершина другого типа или стек пуст, никакое продолжение строку не исправит — `false` корректен. Если совпала, `pop` убирает закрытую скобку, инвариант сохраняется.

В конце строка правильная тогда и только тогда, когда незакрытых скобок не осталось, — это проверка `stack.length === 0`.

## Пограничные случаи

- **Нечётная длина** — `false` сразу.
- **Строка начинается с закрывающей** (`")("`) — `pop` пустого стека даёт `undefined`, `false`.
- **Только открывающие** (`"(("`, `"[{"`) — цикл пройдёт без ошибок, но стек непуст, `false`.
- **Последовательные пары** (`"()[]{}"`) — стек каждый раз опустошается, `true`.
- **Глубокая вложенность** (`"(((…)))"`) — стек растёт до `n / 2`, работает за линейное время.

## Сложность

- **Время `O(n)`**: каждый символ обрабатывается один раз, `push`, `pop` и обращение к `pairs` — `O(1)`.
- **Память `O(n)`**: в худшем случае (первая половина строки — открывающие) в стеке окажется `n / 2` элементов.

## Типичные ошибки

1. **Счётчики вместо стека** — пропускают неправильный порядок (`"([)]"`).
2. **Не проверить стек в конце** — `"(("` ошибочно считается правильной.
3. **Не обработать пустой стек при закрывающей** — в других языках `pop` пустого стека бросает исключение; здесь спасает то, что `undefined` не равен скобке.
4. **Перепутать направление таблицы** (`'(' → ')'`) и при этом искать в ней закрывающую — открывающие и закрывающие начинают путаться.
5. **Подстроечные замены `replace` в цикле** — корректно, но `O(n²)`.

## Как узнать такую задачу

- Есть «открывающие» и «закрывающие» события, которые должны **правильно вкладываться** — стек.
- Нужно сопоставить элемент с **ближайшим незакрытым** предыдущим.
- Ключевые слова: «valid», «balanced», «nested», «correct order».
- Родственные задачи: Generate Parentheses, Longest Valid Parentheses, Minimum Remove to Make Valid Parentheses, Simplify Path, Evaluate Reverse Polish Notation, Basic Calculator, Decode String.
