## Задача простыми словами

Берём положительное число `n` и заменяем его суммой квадратов его цифр. Повторяем. Если когда-нибудь получим `1` — число **счастливое**, вернуть `true`. Если процесс крутится бесконечно, так и не попав в `1`, — вернуть `false`.

Пример: `n = 19` → `1² + 9² = 82` → `8² + 2² = 68` → `6² + 8² = 100` → `1² + 0² + 0² = 1`. Дошли до `1`, ответ `true`. А `n = 2` уходит в цикл `4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4 → …`, ответ `false`.

## Наивный подход

Просто применять шаг, пока не получим `1`:

```ts naive
while (n !== 1) n = next(n);
return true;
```

Для счастливых чисел это работает, а для несчастливых **никогда не завершится**. Типичная «заплатка» — ограничить число шагов («если за 1000 шагов не дошли до 1, вернуть `false`»). Но это угадывание: непонятно, почему 1000 достаточно, и мы делаем сотни лишних шагов, хотя цикл обнаружился бы намного раньше. Проблема в том, что мы **не помним, где уже были**, и не можем отличить «ещё не дошли» от «ходим по кругу».

## Ключевое наблюдение

Последовательность не может расти бесконечно. Для числа из `d` цифр сумма квадратов цифр не больше `81 · d`. Любое число до `2^31 - 1` имеет не больше 10 цифр, поэтому после первого шага получаем не больше `810`, а дальше значения остаются не больше `243` (`2² + 9² + 9²` для `299`).

Значит, значений конечное число, и рано или поздно какое-то из них **повторится**. Как только значение повторилось, дальше последовательность идёт по тому же кругу. Исходов два:

- повторилась `1` (`next(1) = 1`) — число счастливое;
- повторилось другое число — цикл без единицы, число несчастливое.

Достаточно складывать встреченные числа в множество и остановиться при первом повторе.

## Техники

### Множество (Set) для обнаружения повтора

**Что это.** `Set` — хеш-множество: за амортизированное `O(1)` проверяет, есть ли элемент, и добавляет новый. Это хеш-таблица, у которой есть только ключи без значений. Подробнее о хеш-таблицах — во вкладке «Теория».

**Типичный шаблон «видели ли уже».** Идём по последовательности состояний; перед переходом проверяем, было ли текущее состояние; если было — мы в цикле. Подходит для любой детерминированной последовательности (каждое состояние однозначно задаёт следующее) с конечным числом состояний.

**Как применяется здесь.** Состояние — текущее число `n`. `seen` хранит все числа, через которые мы уже прошли.

### Последовательность как неявный связный список

Функция `next` задаёт «указатель» из каждого числа в следующее — получается связный список, которого нет в памяти, но по которому можно ходить. Поиск цикла в нём — классическая задача; альтернатива `Set` — алгоритм Флойда «черепаха и заяц» (`slow` делает один шаг, `fast` — два), который находит цикл за `O(1)` памяти.

### Извлечение цифр числа

Стандартный приём: `x % 10` — последняя цифра, `Math.floor(x / 10)` — число без последней цифры. Повторяем, пока число не станет нулём.

## Разбор кода

```ts
function isHappy(n: number): boolean {
  // Сумма квадратов цифр числа
  const next = (x: number): number => {
    let sum = 0;
    while (x > 0) {
      const d = x % 10;
      sum += d * d;
      x = Math.floor(x / 10);
    }
    return sum;
  };
```

Вспомогательная функция одного шага. Пока в числе остались цифры, отрезаем последнюю (`d = x % 10`), добавляем её квадрат к сумме и убираем её из числа. `Math.floor` нужен потому, что в JavaScript `/` — деление с дробной частью: `19 / 10 = 1.9`. Цикл делает столько итераций, сколько цифр в числе. Параметр `x` — локальная копия, внешний `n` не меняется.

```ts
  // Уже встреченные числа — чтобы заметить цикл
  const seen = new Set<number>();
```

Множество всех чисел, которые уже были текущим значением.

```ts
  while (n !== 1) {
    // Число повторилось — мы в цикле без единицы
    if (seen.has(n)) return false;
    seen.add(n);
    n = next(n);
  }
```

Пока не пришли в `1`: если текущее число уже встречалось, мы пошли по кругу, а раз мы до сих пор в цикле `while`, то `1` в этом круге нет — возвращаем `false`. Иначе запоминаем число и делаем шаг. Порядок «проверить → добавить → шагнуть» важен: если добавить до проверки, `has` всегда вернёт `true`.

```ts
  // Дошли до 1 — число счастливое
  return true;
}
```

Выход из цикла возможен только при `n === 1` — значит, число счастливое. Если `n = 1` с самого начала, цикл не выполнится ни разу.

## Трассировка

`n = 19`:

```
next(19): d=9 → sum=81, x=1; d=1 → sum=82, x=0 → 82

n=19:  не в seen → seen={19},             n=next(19)=1+81=82
n=82:  не в seen → seen={19,82},          n=64+4=68
n=68:  не в seen → seen={19,82,68},       n=36+64=100
n=100: не в seen → seen={19,82,68,100},   n=1+0+0=1
n=1:   цикл while завершается → true
```

`n = 2`:

```
n=2   → seen={2},                     n=4
n=4   → seen={2,4},                   n=16
n=16  → seen={2,4,16},                n=1+36=37
n=37  → seen={…,37},                  n=9+49=58
n=58  → seen={…,58},                  n=25+64=89
n=89  → seen={…,89},                  n=64+81=145
n=145 → seen={…,145},                 n=1+16+25=42
n=42  → seen={…,42},                  n=16+4=20
n=20  → seen={…,20},                  n=4+0=4
n=4:  seen.has(4) = true → false
```

Все несчастливые числа рано или поздно попадают именно в этот цикл `4 → 16 → 37 → 58 → 89 → 145 → 42 → 20 → 4`.

## Почему это работает

`next` детерминирована: из каждого числа ровно один переход. Значения ограничены (после первого шага — не больше `810`), поэтому за конечное число шагов какое-то значение повторится, и цикл `while` обязательно завершится.

- Если последовательность доходит до `1`, мы выходим из `while` до того, как что-то повторится (до `1` все числа различны, иначе мы бы уже крутились в цикле без `1`) — возвращаем `true`.
- Если `1` никогда не встречается, то первое повторившееся число обнаружит `seen.has(n)` — возвращаем `false`. Так как переходы детерминированы, после повтора последовательность бесконечно повторяет тот же круг, и `1` в нём действительно нет.

## Пограничные случаи

- **`n = 1`** — цикл не выполняется, сразу `true`.
- **Степени десяти** (`10`, `100`, `1000000`) — за один шаг получаем `1`.
- **Максимальное `n = 2^31 - 1`** — после первого шага число не больше `810`, переполнения нет.
- **Число `7`** — счастливое, хотя и однозначное: `7 → 49 → 97 → 130 → 10 → 1`.

## Сложность

- **Время `O(log n)`**: первый шаг стоит `O(log n)` (число цифр). Дальше все значения не больше `810`, поэтому до повтора или до `1` пройдёт ограниченное константой число шагов, каждый по `O(1)`.
- **Память `O(log n)`** по оценке из решения; фактически множество хранит ограниченное константой число значений (все, кроме первого, не больше `810`). Алгоритм Флойда снижает память до `O(1)`.

## Типичные ошибки

1. **Нет обнаружения цикла** — бесконечный цикл на несчастливых числах.
2. **Магический лимит шагов** вместо проверки повтора — работает «случайно» и без обоснования.
3. **`x / 10` без `Math.floor`** — в JavaScript получается дробь, цикл `while (x > 0)` идёт сотни итераций по всё меньшим дробям, и сумма считается неверно.
4. **`seen.add(n)` до `seen.has(n)`** — проверка всегда истинна, ответ всегда `false` (кроме `n = 1`).
5. **Проверять повтор только для `1`**, а не для всех чисел — снова зависание.

## Как узнать такую задачу

- Процесс «повторять преобразование, пока не…» с вопросом, **закончится ли** он, — это поиск цикла в последовательности состояний.
- Каждое состояние однозначно определяет следующее, а число состояний конечно — повтор неизбежен, его ловят `Set` или быстрым/медленным указателями.
- Родственные задачи: Linked List Cycle и Linked List Cycle II (Флойд), Find the Duplicate Number (массив как неявный список), Circular Array Loop.
