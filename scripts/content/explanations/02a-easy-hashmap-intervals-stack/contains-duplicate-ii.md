## Задача простыми словами

Дан массив `nums` и число `k`. Нужно узнать, есть ли **два одинаковых числа**, стоящих **не дальше `k` позиций** друг от друга, то есть индексы `i ≠ j` с `nums[i] === nums[j]` и `|i - j| <= k`.

Пример: `nums = [1, 0, 1, 1]`, `k = 1` — единицы на позициях `2` и `3` стоят рядом, ответ `true`. А для `nums = [1, 2, 3, 1, 2, 3]`, `k = 2` каждая пара одинаковых чисел разнесена на 3 позиции — ответ `false`.

## Наивный подход

Для каждого `i` проверить следующие `k` элементов:

```ts naive
for (let i = 0; i < nums.length; i++) {
  for (let j = i + 1; j <= i + k && j < nums.length; j++) {
    if (nums[i] === nums[j]) return true;
  }
}
return false;
```

Это `O(n · min(n, k))`: при `n = k = 10⁵` — около `5 · 10⁹` сравнений. Лишняя работа: окно соседних элементов для `i` и для `i + 1` почти одно и то же, но мы **каждый раз заново** просматриваем его в поисках конкретного значения. Поиск по значению хеш-таблица делает за `O(1)`.

## Ключевое наблюдение

Для текущего элемента `nums[i]` из всех более ранних одинаковых с ним элементов важен только **ближайший слева**. Если даже он дальше `k`, то все более ранние — тем более.

Значит, достаточно для каждого значения помнить **последний индекс**, где оно встречалось. Тогда проверка «есть ли одинаковый в пределах `k`» — это одна операция: `i - lastIndex(nums[i]) <= k`.

## Техники

### Хеш-таблица «значение → последний индекс»

**Что это.** `Map` хранит пары «ключ → значение» и за амортизированное `O(1)` отвечает, есть ли ключ и что с ним связано. Подробнее о хеш-таблицах — во вкладке «Теория».

**Типичный шаблон «просмотренные слева».** Идём по массиву один раз и для текущего элемента спрашиваем таблицу о ранее виденных элементах; потом добавляем в таблицу текущий. Так же устроены Two Sum (ищем партнёра по сумме) и задачи с префиксными суммами.

**Как применяется здесь.** Ключ — значение элемента, значение — индекс его **последнего** появления. При каждом новом появлении старый индекс перезаписывается, потому что новый ближе ко всем будущим элементам.

### Связь со скользящим окном

Условие `|i - j| <= k` означает, что пара должна поместиться в окно из `k + 1` подряд идущих элементов. Альтернативное решение явно держит такое окно в `Set` (добавляем справа, удаляем элемент `nums[i - k]` слева). Решение с `Map` делает то же неявно: «последний индекс» позволяет проверить, попадает ли предыдущее вхождение в окно, без удалений.

Пустая таблица: пока ничего не видели.

```ts
  for (let i = 0; i < nums.length; i++) {
    const prev = lastIndex.get(nums[i]);
```

Один проход слева направо. `prev` — индекс ближайшего слева такого же значения или `undefined`, если значение встречается впервые.

```ts
    // Такое же значение было не дальше k позиций назад
    if (prev !== undefined && i - prev <= k) return true;
```

Если такое значение уже было и расстояние до него не больше `k` — пара найдена. Модуль не нужен: `prev < i`, поэтому `i - prev` всегда положительно. Сравнение с `undefined` обязательно: `prev` может быть `0`, и проверка `if (prev && …)` потеряла бы элемент на нулевой позиции.

```ts
    // Обновляем на текущий индекс: он ближе к будущим элементам
    lastIndex.set(nums[i], i);
  }
```

Записываем текущий индекс, затирая старый. Даже если старое вхождение было в пределах `k` от каких-то будущих элементов, новое вхождение к ним ещё ближе, так что старый индекс больше никогда не понадобится.

```ts
  return false;
}
```

Прошли весь массив, подходящей пары не нашлось.

## Трассировка

`nums = [1, 0, 1, 1]`, `k = 1`:

```
i=0, nums=1: prev=undefined         → lastIndex={1:0}
i=1, nums=0: prev=undefined         → lastIndex={1:0, 0:1}
i=2, nums=1: prev=0, 2-0=2 > 1      → lastIndex={1:2, 0:1}
i=3, nums=1: prev=2, 3-2=1 <= 1     → return true
```

На шаге `i = 2` единица уже была, но слишком далеко; индекс обновился на `2`, и на следующем шаге пара нашлась.

`nums = [1, 2, 3, 1, 2, 3]`, `k = 2`:

```
i=0..2: значения 1,2,3 новые        → {1:0, 2:1, 3:2}
i=3, nums=1: prev=0, 3-0=3 > 2      → {1:3, 2:1, 3:2}
i=4, nums=2: prev=1, 4-1=3 > 2      → {1:3, 2:4, 3:2}
i=5, nums=3: prev=2, 5-2=3 > 2      → {1:3, 2:4, 3:5}
конец → false
```

## Почему это работает

Инвариант: перед обработкой позиции `i` в `lastIndex` для каждого значения `v` лежит наибольший индекс `j < i` с `nums[j] = v`.

Пусть ответ `true`, и подходящая пара — `j < i` с `i - j <= k`. Когда цикл дойдёт до `i` (если не вернул `true` раньше), `prev` — наибольший индекс `< i` с тем же значением, то есть `prev >= j`, и `i - prev <= i - j <= k`. Значит, мы вернём `true`.

Обратно, если мы вернули `true`, то `prev` — реальный индекс с тем же значением, `prev ≠ i` и расстояние не больше `k`. Ложных срабатываний нет.

## Пограничные случаи

- **`k = 0`** — индексы должны быть разными, а расстояние `>= 1 > 0`, поэтому всегда `false`; код это обеспечивает, так как `i - prev >= 1`.
- **Соседние одинаковые числа** при `k >= 1` — находятся на втором из них.
- **Одинаковые числа на позиции `0`** — проверка `prev !== undefined`, а не `if (prev)`.
- **Отрицательные и большие числа** (до `±10⁹`) — `Map` работает с любыми числовыми ключами.
- **`k` больше длины массива** — задача сводится к «есть ли вообще повтор», код работает без изменений.

## Сложность

- **Время `O(n)`**: один проход, на каждом шаге `get` и `set` за амортизированное `O(1)`.
- **Память `O(n)`**: в худшем случае (все значения различны) в таблице окажется `n` ключей. Вариант со скользящим окном на `Set` хранит не больше `k` элементов — `O(min(n, k))`.

## Типичные ошибки

1. **Хранить первый индекс, а не последний** (не обновлять при повторе) — для `[1, 0, 1, 1]`, `k = 1` расстояние всегда считается от позиции `0`, ответ ошибочно `false`.
2. **`if (prev && …)`** вместо `prev !== undefined` — теряется вхождение с индексом `0`.
3. **Путать `<` и `<=`** — по условию расстояние ровно `k` подходит.
4. **Обновлять индекс до проверки** — тогда `prev` всегда равен `i`, и при `k >= 0` ответ всегда `true`.
5. **Хранить все индексы каждого значения** — работает, но тратит лишнюю память: нужен только последний.

## Как узнать такую задачу

- «Есть ли одинаковые элементы **не дальше `k`**», «в пределах окна», «distinct indices with `abs(i - j) <= k`».
- Нужно сравнивать элемент с **ближайшим** предыдущим таким же — хеш-таблица «значение → последний индекс».
- Ограничение по расстоянию — сигнал к скользящему окну фиксированной ширины.
- Родственные задачи: Contains Duplicate (без ограничения расстояния), Contains Duplicate III (близкие **значения** в окне — бакеты или упорядоченное множество), Two Sum, Longest Substring Without Repeating Characters (тоже «последний индекс» символа).
