## Задача простыми словами

Даны две строки `s` и `t` из строчных латинских букв. Нужно проверить, является ли `t` **анаграммой** `s` — то есть состоит ли она из тех же букв в тех же количествах, только, возможно, в другом порядке.

Пример: `s = "anagram"`, `t = "nagaram"` — в обеих три `a` и по одной `n`, `g`, `r`, `m`, ответ `true`. `s = "rat"`, `t = "car"` — в `t` есть `c`, но нет `t`, ответ `false`.

## Наивный подход

Самое короткое решение — отсортировать обе строки и сравнить:

```ts naive
const sort = (x: string) => x.split('').sort().join('');
return sort(s) === sort(t);
```

Это верно: у анаграмм после сортировки получается одна и та же строка. Но сортировка стоит `O(n log n)` и создаёт массивы и строки. Лишняя работа: сортировка **упорядочивает** буквы, а нам порядок не нужен вовсе — нужно только знать, **сколько** раз встречается каждая буква. Ещё хуже вариант «для каждой буквы `s` найти и вычеркнуть такую же в `t`» — это `O(n²)`.

## Ключевое наблюдение

Две строки — анаграммы тогда и только тогда, когда у них **совпадают частоты** всех букв. Букв всего 26, поэтому частоты помещаются в массив из 26 чисел.

Можно даже не заводить два массива: на одной и той же позиции `i` прибавляем `1` за букву из `s` и вычитаем `1` за букву из `t`. В конце в массиве лежат **разности частот**, и строки — анаграммы, только если все разности нулевые.

## Техники

### Подсчёт частот (частотная таблица)

**Что это.** Частотная таблица — это «символ → сколько раз встретился». В общем случае это хеш-таблица `Map`, но при маленьком известном алфавите удобнее массив: индекс — номер символа, значение — счётчик. Такой массив — та же хеш-таблица с «идеальной» хеш-функцией без коллизий. Подробнее о хеш-таблицах — во вкладке «Теория».

**Типичный шаблон.** Задачи «совпадают ли наборы символов», «можно ли переставить», «хватает ли букв»: считаем частоты, затем сравниваем. Когда нужно **равенство** наборов, удобно хранить одну таблицу разностей: плюс за один набор, минус за другой, и в конце проверить, что всё обнулилось.

**Как применяется здесь.** `count[26]`, индекс буквы — `charCodeAt(i) - 97`. Оба прохода объединены в один цикл, потому что длины строк равны.

### Ранний выход по длине

Если длины разные, наборы букв не могут совпасть — проверяем это до подсчёта. Это ещё и делает корректным общий цикл: индексы `i` валидны для обеих строк.

## Разбор кода

```ts
function isAnagram(s: string, t: string): boolean {
  // Анаграммы обязаны иметь одинаковую длину
  if (s.length !== t.length) return false;
```

Разные длины — разное общее число букв, анаграммой это быть не может. Кроме того, ниже мы читаем `s[i]` и `t[i]` в одном цикле, и равенство длин гарантирует, что ни одна строка не закончится раньше.

```ts
  // Разница частот: +1 за букву в s, -1 за букву в t
  const count = new Array<number>(26).fill(0);
  for (let i = 0; i < s.length; i++) {
    count[s.charCodeAt(i) - 97]++;
    count[t.charCodeAt(i) - 97]--;
  }
```

Массив на 26 счётчиков, изначально нулевых. На каждом шаге буква из `s` увеличивает свой счётчик, буква из `t` — уменьшает свой. После цикла `count[x]` = (сколько `x` в `s`) − (сколько `x` в `t`). Важно, что одинаковые буквы на одной позиции просто взаимно гасятся: `+1` и `-1` в одну ячейку.

Внутри цикла счётчик может временно уйти в минус (буква в `t` встретилась раньше, чем в `s`) — это нормально, мы проверяем только итог.

```ts
  // Анаграмма — если все разницы нулевые
  return count.every((c) => c === 0);
}
```

`every` проверяет 26 значений и останавливается на первом ненулевом. Все нули — частоты совпали, строки анаграммы.

## Трассировка

`s = "rat"`, `t = "car"` (длины равны):

```
i=0: s 'r' → count[r]=+1;  t 'c' → count[c]=-1
i=1: s 'a' → count[a]=+1;  t 'a' → count[a]=0
i=2: s 't' → count[t]=+1;  t 'r' → count[r]=0
итог: count[c]=-1, count[t]=+1, остальные 0
every → находит count[c]=-1 → false
```

`s = "ab"`, `t = "ba"`:

```
i=0: s 'a' → count[a]=+1;  t 'b' → count[b]=-1
i=1: s 'b' → count[b]=0;   t 'a' → count[a]=0
итог: все нули → true
```

Во втором примере видно, что промежуточные значения (`count[b] = -1`) ни на что не влияют.

## Почему это работает

Каждая буква `s` добавляет ровно `+1` к своему счётчику, каждая буква `t` — ровно `-1`. Поэтому после цикла `count[x] = freqS(x) − freqT(x)` для любой буквы `x`, независимо от порядка, в котором шли буквы.

Строки — анаграммы ⇔ `freqS(x) = freqT(x)` для всех `x` ⇔ все `count[x] = 0`. Это и проверяет `every`.

## Пограничные случаи

- **Разные длины** — `false` до подсчёта.
- **Одинаковые строки** — на каждой позиции `+1` и `-1` в одну ячейку, все нули, `true`.
- **Строка из одной повторяющейся буквы** (`"aaa"` и `"aaa"`) — работает, счётчик колеблется и возвращается к 0.
- **Те же буквы, другие количества** (`"aab"` и `"abb"`) — `count[a] = 1`, `count[b] = -1`, `false`.
- **Unicode (follow-up)** — массив на 26 не подходит: нужен `Map<string, number>` и обход по кодовым точкам `for (const ch of s)`, иначе эмодзи разобьются на половинки суррогатных пар; при необходимости строки предварительно нормализуют через `normalize()`.

## Сложность

- **Время `O(n)`**: один проход по `n` позициям плюс `every` по 26 элементам, то есть `O(n + 26) = O(n)`.
- **Память `O(1)`**: массив всегда из 26 чисел, не зависит от длины строк.

## Типичные ошибки

1. **Сравнивать только множества букв** (`new Set(s)` против `new Set(t)`) — `"aab"` и `"abb"` дадут ложный `true`.
2. **Проверять `count[x] < 0` внутри цикла** — при объединённом проходе промежуточный минус нормален (`"ab"`/`"ba"`), такая проверка даст ложный `false`.
3. **Забыть проверку длин** — цикл идёт по длине `s`, поэтому хвост более длинной `t` просто не учтётся: `"a"` и `"ab"` дадут ложный `true`.
4. **Сортировка через `sort()` без `join`** — сравнение массивов через `===` сравнивает ссылки и всегда даёт `false`.

## Как узнать такую задачу

- «Анаграмма», «перестановка букв», «состоят из тех же символов» — порядок не важен, важны количества.
- Маленький фиксированный алфавит — массив счётчиков вместо `Map`.
- Нужно равенство наборов — одна таблица разностей «+1 / −1».
- Родственные задачи: Ransom Note (набор должен «покрывать», а не совпадать), Group Anagrams (частоты как ключ группы), Find All Anagrams in a String и Permutation in String (частоты в скользящем окне).
