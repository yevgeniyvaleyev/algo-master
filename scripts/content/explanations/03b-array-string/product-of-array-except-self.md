## Задача простыми словами

Дан массив целых чисел `nums`. Нужно вернуть массив `answer`, где `answer[i]` — произведение **всех элементов, кроме `nums[i]`**. Ограничения: время `O(n)` и **без деления**.

Пример: `nums = [1, 2, 3, 4]` → `answer = [24, 12, 8, 6]`. Например, `answer[1] = 1 · 3 · 4 = 12` — пропущена двойка.

## Наивный подход

Для каждой позиции честно перемножить все остальные элементы:

```ts naive
const answer: number[] = [];
for (let i = 0; i < n; i++) {
  let p = 1;
  for (let j = 0; j < n; j++) if (j !== i) p *= nums[j];
  answer.push(p);
}
```

Это `O(n²)`: при `n = 10⁵` — десять миллиардов умножений. Лишняя работа очевидна: для соседних `i` и `i + 1` произведения почти одинаковые — отличаются одним множителем, а мы каждый раз пересчитываем их с нуля.

Вторая «очевидная» идея — перемножить всё и делить: `answer[i] = total / nums[i]`. Она запрещена условием и к тому же ломается на нулях: при одном нуле `total = 0`, и для самого нуля нужно произведение остальных, которое из `0 / 0` не восстановить.

## Ключевое наблюдение

«Все, кроме `i`» — это **всё левее `i`** и **всё правее `i`**:

```
answer[i] = (nums[0] · … · nums[i-1]) · (nums[i+1] · … · nums[n-1])
             └─ префикс левее i ─┘       └─ суффикс правее i ─┘
```

Произведения префиксов накапливаются одним проходом слева направо: каждое следующее получается из предыдущего одним умножением. Суффиксы — так же, проходом справа налево. Остаётся перемножить их попарно. Деления нет, а на каждую позицию уходит `O(1)` работы.

Чтобы не заводить отдельные массивы префиксов и суффиксов, префиксы пишем **прямо в `answer`**, а суффикс держим в одной переменной во втором проходе.

## Техники

### Префиксные и суффиксные накопления

**Что это.** Префиксная «сумма» (или произведение, максимум, XOR — любая ассоциативная операция) — это значение операции на отрезке `[0, i)`. Её считают одним проходом: `prefix_{i+1} = prefix_i ⊕ nums[i]`. Симметрично считается суффикс на `(i, n-1]` проходом справа налево.

**Типичный шаблон.** Когда ответ для позиции `i` зависит от «всего слева» и «всего справа» от неё, считаем оба накопления и комбинируем:

```ts naive
// left[i] — операция над nums[0..i-1], right[i] — над nums[i+1..n-1]
for (let i = 0; i < n; i++) answer[i] = combine(left[i], right[i]);
```

Так решаются задачи «произведение кроме себя», «вода между столбиками» (максимумы слева и справа), «конфеты» (ограничения от соседей с двух сторон).

**Как применяется здесь.** Операция — умножение, «пустой» префикс равен `1` (нейтральный элемент умножения). Подробнее о приёмах работы с массивами — во вкладке «Теория».

### Переиспользование выходного массива

По условию follow-up выходной массив не считается дополнительной памятью. Поэтому `answer` служит одновременно хранилищем префиксов, а второй проход домножает их на суффиксы «на месте». Итог — `O(1)` дополнительной памяти.

## Разбор кода

```ts
function productExceptSelf(nums: number[]): number[] {
  const n = nums.length;
  const answer = new Array<number>(n);
```

Заводим выходной массив нужной длины. Пока он пустой — заполним его в первом проходе.

```ts
  // Проход слева направо: answer[i] = произведение всех элементов левее i
  let prefix = 1;
  for (let i = 0; i < n; i++) {
    answer[i] = prefix;
    prefix *= nums[i];
  }
```

`prefix` перед итерацией `i` равен `nums[0] · … · nums[i-1]` — произведению элементов **строго левее** `i`. Поэтому сначала записываем его в `answer[i]`, и только потом домножаем на `nums[i]`, готовя значение для следующей позиции. Порядок двух строк критичен: если поменять их местами, в `answer[i]` попадёт и сам `nums[i]`. Для `i = 0` левее ничего нет — записывается начальное `1`.

```ts
  // Проход справа налево: домножаем на произведение всех элементов правее i
  let suffix = 1;
  for (let i = n - 1; i >= 0; i--) {
    answer[i] *= suffix;
    suffix *= nums[i];
  }
```

Зеркальный проход. `suffix` перед итерацией `i` равен `nums[i+1] · … · nums[n-1]`. Домножаем на него уже лежащий в `answer[i]` префикс — получаем «левее × правее». Затем включаем `nums[i]` в суффикс для позиции `i - 1`. Снова: сначала используем, потом обновляем.

```ts
  return answer;
}
```

После двух проходов в каждой ячейке — произведение всех элементов, кроме своего.

## Трассировка

`nums = [1, 2, 3, 4]`.

Первый проход (префиксы):

```
i=0: answer[0]=1,  prefix=1·1=1
i=1: answer[1]=1,  prefix=1·2=2
i=2: answer[2]=2,  prefix=2·3=6
i=3: answer[3]=6,  prefix=6·4=24
answer = [1, 1, 2, 6]
```

Второй проход (суффиксы):

```
i=3: answer[3]=6·1=6,    suffix=1·4=4
i=2: answer[2]=2·4=8,    suffix=4·3=12
i=1: answer[1]=1·12=12,  suffix=12·2=24
i=0: answer[0]=1·24=24,  suffix=24·1=24
answer = [24, 12, 8, 6]
```

Пример с нулём, `nums = [-1, 1, 0, -3, 3]`. После первого прохода `answer = [1, -1, -1, 0, 0]`: всё, что правее нуля, получает префикс `0`. Во втором проходе суффиксы равны `1, 3, -9, 0, 0` (для `i = 4, 3, 2, 1, 0`). Итог `[0, 0, 9, 0, 0]`: ненулевое значение только у самого нуля — `(-1 · 1) · (-3 · 3) = 9`.

## Почему это работает

Инварианты циклов:

- в первом цикле перед итерацией `i` выполнено `prefix = nums[0] · … · nums[i-1]` (пустое произведение — `1`); значит, после него `answer[i]` равен произведению элементов левее `i`;
- во втором цикле перед итерацией `i` выполнено `suffix = nums[i+1] · … · nums[n-1]`; значит, после неё `answer[i]` = (левее) · (правее).

Оба инварианта верны в начале (пустые произведения) и сохраняются, потому что каждый шаг добавляет ровно один множитель **после** использования. Умножение коммутативно и ассоциативно, поэтому «левее · правее» — это ровно произведение всех, кроме `nums[i]`.

## Пограничные случаи

- **Один ноль**: все ответы `0`, кроме позиции нуля, — у неё произведение остальных.
- **Два и больше нулей**: каждое «все, кроме одного» содержит ноль — весь ответ из нулей. Код ничего особого не делает, это получается само.
- **Отрицательные числа**: знак учитывается обычным умножением.
- **`n = 2`**: `answer = [nums[1], nums[0]]` — префикс и суффикс по одному элементу.
- **`-0` в JavaScript**: при умножении отрицательного числа на ноль получается `-0` (в примере с нулём он действительно появляется). `-0 === 0` истинно, а при выводе он печатается как `0`, так что ответ корректен.

## Сложность

- **Время `O(n)`**: два прохода по массиву, на каждом шаге два умножения.
- **Память `O(1)` дополнительно**: только `prefix`, `suffix` и счётчик; выходной массив по условию не учитывается. Вариант с отдельными массивами `left` и `right` использовал бы `O(n)`.

## Типичные ошибки

1. **Обновить `prefix` до записи** (`prefix *= nums[i]; answer[i] = prefix`) → в ответ попадает сам `nums[i]`.
2. **Использовать деление** → запрещено условием и ломается на нулях (`0 / 0 = NaN`, деление на ноль даёт `Infinity`).
3. **Начинать накопление с `0`** вместо `1` → все произведения обнуляются.
4. **Во втором проходе присваивать** `answer[i] = suffix` вместо `*=` → префиксы теряются.
5. **Отдельно обрабатывать нули** через счётчики — работает, но лишний код и лишние ветки; префиксы/суффиксы справляются сами.

## Как узнать такую задачу

- Ответ для позиции `i` — это агрегат «всего, кроме `i`» или комбинация «всего слева» и «всего справа».
- Запрет на деление (или операция, у которой нет обратной, например `max`) — сигнал, что «посчитать всё и вычесть себя» не сработает, нужны префиксы и суффиксы.
- Требование `O(1)` памяти при `O(n)` времени — используйте выходной массив как буфер.
- Родственные задачи: Trapping Rain Water (максимумы слева/справа), Candy, Range Sum Query, Maximum Product Subarray.
