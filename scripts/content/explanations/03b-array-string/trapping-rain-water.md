## Задача простыми словами

Массив `height` — это рельеф из столбиков ширины `1`. Прошёл дождь: вода заполнила все ямы между столбиками. Нужно посчитать, **сколько единиц воды** задержалось.

Пример: `height = [4, 2, 0, 3, 2, 5]` → `9`.

```
5 |           █
4 | █ ~ ~ ~ ~ █
3 | █ ~ ~ █ ~ █
2 | █ █ ~ █ █ █
1 | █ █ ~ █ █ █
    4 2 0 3 2 5
```

`█` — столбик, `~` — вода.

Вода поднимается до уровня `4` (ниже из двух крайних стенок): над `2` — `2`, над `0` — `4`, над `3` — `1`, над `2` — `2`. Итого `9`.

## Наивный подход

Посмотрим на одну позицию `i`. Вода над ней удерживается **самой высокой стенкой слева** и **самой высокой стенкой справа**; уровень определяется меньшей из них. Отсюда формула:

```
water[i] = min(maxLeft[i], maxRight[i]) - height[i]
```

где `maxLeft[i]` — максимум на `[0, i]`, `maxRight[i]` — на `[i, n-1]` (сам столбик включаем, тогда разность никогда не отрицательна).

Лобовая реализация считает максимумы для каждой позиции заново:

```ts naive
let water = 0;
for (let i = 0; i < n; i++) {
  let maxL = 0, maxR = 0;
  for (let j = 0; j <= i; j++) maxL = Math.max(maxL, height[j]);
  for (let j = i; j < n; j++) maxR = Math.max(maxR, height[j]);
  water += Math.min(maxL, maxR) - height[i];
}
```

Это `O(n²)`. Лишняя работа: максимум слева для `i + 1` отличается от максимума для `i` одним элементом, а мы пересчитываем его заново. Если предподсчитать `maxLeft` и `maxRight` двумя проходами, получим `O(n)` времени, но `O(n)` памяти на два массива.

## Ключевое наблюдение

Для ответа в позиции `i` нужны не оба максимума, а только **меньший** из них. И его часто можно узнать, не зная другого точно.

Поставим указатели на края: `left = 0`, `right = n - 1`, и будем помнить `leftMax` (максимум на `[0, left]`) и `rightMax` (максимум на `[right, n-1]`). Пусть `height[left] < height[right]`. Тогда справа от `left` гарантированно есть стенка выше `height[left]` — сам `height[right]`. Более того, указатели всегда двигаются со стороны меньшего столбика, поэтому `leftMax` не превосходит максимума правой части. Значит, для позиции `left` меньший из двух максимумов — это `leftMax`, и вода над ней равна `leftMax - height[left]`. Её можно сразу прибавить и сдвинуть `left`.

Симметрично, если `height[right] <= height[left]`, уровень над `right` определяется `rightMax`.

Всегда обрабатываем **сторону с меньшей высотой** — её уровень воды уже известен. Один проход, `O(1)` памяти.

## Техники

### Два указателя навстречу друг другу

**Что это.** Два индекса стартуют с концов массива и сходятся. На каждом шаге по локальному сравнению решаем, какой указатель сдвинуть, и **окончательно обрабатываем** элемент под ним. Каждый элемент обрабатывается ровно один раз — `O(n)`.

**Типичный шаблон:**

```ts naive
let l = 0, r = n - 1;
while (l < r) {
  if (условиеДляЛевого) { обработать(l); l++; }
  else { обработать(r); r--; }
}
```

Ключ к корректности — доказать, что элемент под сдвигаемым указателем можно обработать, **не зная** того, что лежит между указателями.

**Как применяется здесь.** Сдвигаем указатель с меньшей высотой: для него известна «нижняя» из двух стенок. Подробнее о двух указателях — во вкладке «Теория».

### Бегущий максимум вместо массива максимумов

Вместо массивов `maxLeft[]` и `maxRight[]` храним по одной переменной: `leftMax` обновляется при каждом шаге `left`, `rightMax` — при каждом шаге `right`. Это тот же префиксный максимум, но «потребляемый» сразу, поэтому хранить всю историю не нужно.

## Разбор кода

```ts
function trap(height: number[]): number {
  let left = 0;
  let right = height.length - 1;
  let leftMax = 0; // самый высокий столбик на отрезке [0, left]
  let rightMax = 0; // самый высокий столбик на отрезке [right, n - 1]
  let water = 0;
```

Указатели на краях, бегущие максимумы равны `0` (высоты неотрицательны, так что `0` — корректный «нейтральный» максимум), счётчик воды.

```ts
  while (left < right) {
```

Работаем, пока указатели не встретились. Столбик, на котором они сойдутся, — глобальный максимум (к нему сходятся обе стороны), над ним воды нет, поэтому его можно не обрабатывать.

```ts
    if (height[left] < height[right]) {
      // Справа есть стенка выше height[left], значит уровень воды
      // над left определяется только leftMax
      leftMax = Math.max(leftMax, height[left]);
      water += leftMax - height[left];
      left++;
```

Левый столбик ниже правого — обрабатываем левую позицию. Сначала включаем текущий столбик в `leftMax`: если он сам выше всех слева, то `leftMax` станет равен ему и вода над ним — `0`. Иначе вода — разница между уровнем `leftMax` и дном. Позиция обработана окончательно, сдвигаем `left`.

```ts
    } else {
      // Симметрично: слева есть стенка не ниже height[right],
      // уровень над right определяется rightMax
      rightMax = Math.max(rightMax, height[right]);
      water += rightMax - height[right];
      right--;
    }
  }
```

Зеркальная ветка: правый столбик не выше левого, уровень над `right` задаёт `rightMax`. Равенство высот попадает сюда — это безопасно: слева стоит стенка не ниже, так что правый максимум по-прежнему «меньший».

```ts
  return water;
}
```

Каждая позиция, кроме точки встречи, обработана ровно один раз — сумма и есть ответ.

## Трассировка

`height = [0, 1, 0, 2, 1, 0, 1, 3, 2, 1, 2, 1]`, ответ `6`. Обозначения: `L`, `R` — указатели, `lM`, `rM` — максимумы.

1. `L=0, R=11`: `0 < 1` → `lM = 0`, вода `+0`, итого `0`. `L = 1`.
2. `L=1, R=11`: `1 < 1` нет → `rM = 1`, `+0`. `R = 10`.
3. `L=1, R=10`: `1 < 2` → `lM = 1`, `+0`. `L = 2`.
4. `L=2, R=10`: `0 < 2` → `lM = 1`, `+1`, итого `1`. `L = 3`.
5. `L=3, R=10`: `2 < 2` нет → `rM = 2`, `+0`. `R = 9`.
6. `L=3, R=9`: `2 < 1` нет → `rM = 2`, `+1`, итого `2`. `R = 8`.
7. `L=3, R=8`: `2 < 2` нет → `rM = 2`, `+0`. `R = 7`.
8. `L=3, R=7`: `2 < 3` → `lM = 2`, `+0`. `L = 4`.
9. `L=4, R=7`: `1 < 3` → `lM = 2`, `+1`, итого `3`. `L = 5`.
10. `L=5, R=7`: `0 < 3` → `lM = 2`, `+2`, итого `5`. `L = 6`.
11. `L=6, R=7`: `1 < 3` → `lM = 2`, `+1`, итого `6`. `L = 7`.

`L = R = 7` — указатели встретились на столбике высоты `3` (глобальный максимум). Ответ `6`.

## Почему это работает

Достаточно показать: когда мы обрабатываем `left` (ветка `height[left] < height[right]`), истинный правый максимум для `left` не меньше `leftMax`. Тогда `min(maxLeft, maxRight) = leftMax`, и прибавленная вода верна.

**Инвариант:** в каждый момент `leftMax <= max(height[left..right])` при обработке слева и симметрично справа. Почему: указатель сдвигается только со стороны **строго меньшего** (или равного) столбика. Значит, каждый столбик, вошедший в `leftMax`, в момент своей обработки был `<` некоторого столбика справа, который ещё не пройден. Поэтому где-то в `[left, n-1]` всегда есть стенка не ниже `leftMax`, а в текущей ветке справа есть и `height[right] > height[left]`. Итог — правая стенка для `left` никогда не ниже `leftMax`, и уровень воды над `left` равен именно `leftMax`.

Для правой ветки рассуждение зеркально. Каждая позиция обрабатывается один раз, точка встречи — максимум, воды над ней нет.

## Пограничные случаи

- **`n = 1` или `n = 2`**: ям нет; при `n = 1` цикл не выполняется, при `n = 2` вода над крайним столбиком всегда `0`.
- **Монотонный рельеф** (`[1, 2, 3]` или `[3, 2, 1]`): каждый новый столбик обновляет максимум, вода `0`.
- **Плато и равные высоты**: равенство уходит в `else`, это корректно.
- **Нули по краям** (`[0, 2, 0]`): вода не держится — у края нет стенки, и `leftMax` равен самому столбику.
- **Одна глубокая яма** (`[5, 0, 0, 5]`): `5 + 5 = 10`.

## Сложность

- **Время `O(n)`**: каждая итерация сдвигает один из указателей, всего не больше `n - 1` итераций по `O(1)`.
- **Память `O(1)`**: пять переменных. Вариант с массивами `maxLeft`/`maxRight` или монотонным стеком требует `O(n)`.

## Типичные ошибки

1. **Двигать указатель с большей высотой** → уровень над ним ещё неизвестен, ответ неверен.
2. **Считать воду до обновления максимума** (`water += leftMax - height[left]` перед `Math.max`) → для столбика выше `leftMax` получается отрицательная «вода».
3. **Брать `max` вместо `min` стенок** в формуле → вода «перетекает» через низкую стенку.
4. **Сравнивать `leftMax` и `rightMax`** вместо `height[left]` и `height[right]` — это тоже рабочий вариант, но смешивать два стиля в одном коде нельзя: условие и обновляемый максимум должны соответствовать друг другу.
5. **Пытаться считать воду «по ямам»** между локальными максимумами → сложно и ломается на вложенных ямах.

## Как узнать такую задачу

- Ответ для элемента зависит от **максимума (минимума) слева и справа** от него — сигнал к префиксным/суффиксным максимумам, а затем к оптимизации двумя указателями.
- Слова «вода», «рельеф», «столбики», «ёмкость между стенками».
- Требование `O(1)` памяти для задачи, которая естественно решается двумя вспомогательными массивами.
- Родственные задачи: Container With Most Water (тоже два указателя, «двигай меньшую стенку»), Trapping Rain Water II (2D, решается кучей), Largest Rectangle in Histogram (монотонный стек), Product of Array Except Self (префиксы и суффиксы).
