## Задача простыми словами

Нужно написать класс `RandomizedSet` — множество целых чисел с тремя операциями: `insert(val)` (добавить, если ещё нет; вернуть, удалось ли), `remove(val)` (удалить, если есть; вернуть, удалось ли) и `getRandom()` (вернуть случайный элемент, причём **каждый — с одинаковой вероятностью**). Все три операции должны работать за `O(1)` в среднем.

Пример: `insert(1)` → `true`, `remove(2)` → `false` (двойки нет), `insert(2)` → `true`, `getRandom()` → `1` или `2` с вероятностью `1/2`, `remove(1)` → `true`, `insert(2)` → `false` (уже есть), `getRandom()` → всегда `2`.

## Наивный подход

Первое, что приходит в голову, — взять готовую структуру. Но каждая из очевидных справляется только с частью требований.

**Только массив:**

```ts naive
insert(val) { if (this.arr.includes(val)) return false; this.arr.push(val); return true; }
remove(val) { const i = this.arr.indexOf(val); if (i < 0) return false; this.arr.splice(i, 1); return true; }
getRandom() { return this.arr[Math.floor(Math.random() * this.arr.length)]; }
```

`getRandom` идеален — случайный индекс за `O(1)`. Но `includes` и `indexOf` — линейный поиск `O(n)`, а `splice` из середины сдвигает весь хвост — ещё `O(n)`.

**Только `Set`:** `insert` и `remove` за `O(1)`, но у `Set` нет доступа «по номеру». Чтобы выбрать случайный элемент, придётся пройти итератором до `k`-го — `O(n)`.

Где лишняя работа? У массива — в **поиске значения** и в **сдвиге хвоста** при удалении. У `Set` — в **отсутствии индексов**. Каждая структура закрывает именно то, что не умеет другая.

## Ключевое наблюдение

Хранить значения **в двух структурах сразу**:

- массив `values` — плотный, без «дыр»; по нему `getRandom` берёт случайный индекс;
- хеш-таблица `indexOf` «значение → индекс в массиве» — по ней за `O(1)` узнаём, есть ли значение и **где именно** оно лежит.

Остаётся одна проблема — удаление из середины массива. Решение: **порядок элементов в множестве не важен**. Поэтому удаляемый элемент можно заменить последним элементом массива, а затем отрезать хвост через `pop()` — это `O(1)`, никакого сдвига. Нужно лишь не забыть обновить индекс переехавшего элемента в `indexOf`.

## Техники

### Хеш-таблица как индекс к массиву

**Что это.** Хеш-таблица (`Map`) хранит пары «ключ → значение» и за амортизированное `O(1)` отвечает на вопросы «есть ли ключ?» и «что по ключу?». Часто её используют не как самостоятельное хранилище, а как **индекс** к другой структуре: «где в массиве / списке лежит вот этот объект».

**Типичный шаблон.** Когда одна структура хороша для одного вида доступа (по позиции, по порядку), а нужен ещё доступ по значению — добавляют `Map` «значение → позиция». Так устроены LRU-кеш (`Map` + двусвязный список), индексированные кучи, эта задача. Цена — нужно **синхронно** обновлять обе структуры в каждой операции.

**Как применяется здесь.** `indexOf` отвечает на «есть ли `val`» (для `insert` и `remove`) и «на какой позиции `val`» (для `remove`). Подробнее о хеш-таблицах — во вкладке «Теория».

### Удаление обменом с последним (swap-and-pop)

**Что это.** Удалить элемент из середины массива за `O(1)` нельзя, если важен порядок. Но если порядок не важен, удаляемую ячейку можно **перезаписать последним элементом** и укоротить массив на один. Массив остаётся плотным, а `pop()` работает за `O(1)`.

**Когда применять.** Любой «мешок» элементов, где порядок не важен: множества, пулы объектов, списки активных сущностей в играх, очереди задач без приоритета.

**Как применяется здесь.** В `remove` последний элемент переезжает на место удаляемого, а его индекс в `indexOf` обновляется.

### Равновероятный случайный индекс

`Math.floor(Math.random() * n)` даёт целое число от `0` до `n - 1` с одинаковой вероятностью. Если в массиве ровно `n` различных значений и нет пустых ячеек, то каждое значение выпадает с вероятностью `1/n` — именно это требует условие.

## Разбор кода

```ts
class RandomizedSet {
  // Значения подряд в массиве — по нему выбираем случайный элемент за O(1)
  private values: number[] = [];
  // Значение -> его индекс в массиве values
  private indexOf = new Map<number, number>();

  constructor() {}
```

Два поля и их **инвариант**: `values` содержит все элементы множества без пропусков и повторов, а для каждого `v` из множества `values[indexOf.get(v)] === v`. Каждый метод обязан сохранять это условие. Конструктор пустой — поля инициализируются прямо в объявлении.

```ts
  insert(val: number): boolean {
    // Уже есть — ничего не делаем
    if (this.indexOf.has(val)) return false;
```

Проверка присутствия по хеш-таблице за `O(1)` — вместо `values.includes(val)` за `O(n)`. Если значение уже есть, множество не меняется, возвращаем `false`.

```ts
    // Дописываем в конец массива и запоминаем индекс
    this.indexOf.set(val, this.values.length);
    this.values.push(val);
    return true;
  }
```

Новый элемент окажется на позиции `values.length` (текущая длина — это индекс следующей свободной ячейки). Поэтому сначала записываем этот индекс в `indexOf`, затем `push`. Порядок двух строк здесь не принципиален, если индекс считать правильно: после `push` нужно было бы писать `values.length - 1`.

```ts
  remove(val: number): boolean {
    const idx = this.indexOf.get(val);
    if (idx === undefined) return false;
```

Достаём позицию удаляемого значения. Если его нет — `undefined`, возвращаем `false`. Сравниваем именно с `undefined`: индекс `0` — ложное значение, и проверка `if (!idx)` ошибочно сочла бы элемент на позиции `0` отсутствующим.

```ts
    // Удалять из середины массива дорого (O(n)), поэтому
    // переносим последний элемент на место удаляемого
    const last = this.values[this.values.length - 1];
    this.values[idx] = last;
    this.indexOf.set(last, idx);
```

Сердце решения. Берём последний элемент `last`, кладём его в ячейку `idx` (поверх `val`) и сообщаем хеш-таблице, что `last` теперь живёт на позиции `idx`. В этот момент `last` временно лежит в массиве дважды — в ячейке `idx` и в конце.

```ts
    // Теперь удаляемое значение «лишнее» только в конце — убираем за O(1)
    this.values.pop();
    this.indexOf.delete(val);
    return true;
  }
```

`pop()` убирает дубликат из конца массива, `delete` убирает запись о `val`. Инвариант восстановлен: массив плотный, все индексы верны.

Важный частный случай — **удаляется сам последний элемент** (`last === val`, `idx === length - 1`). Тогда `values[idx] = last` ничего не меняет, `indexOf.set(last, idx)` перезаписывает ту же запись, `pop()` убирает элемент, а `delete(val)` — запись о нём. Всё корректно именно потому, что `delete` идёт **после** `set`. Поменяй их местами — и для этого случая в `indexOf` осталась бы «призрачная» запись `val → idx`, указывающая за пределы массива.

```ts
  getRandom(): number {
    // Равновероятный индекс в [0, length)
    const i = Math.floor(Math.random() * this.values.length);
    return this.values[i];
  }
}
```

`Math.random()` даёт число из `[0, 1)`, умножение на длину — из `[0, length)`, `Math.floor` — целый индекс от `0` до `length - 1`. Массив плотный, значения уникальны — каждое выпадает с вероятностью `1 / length`. Условие гарантирует, что множество не пусто.

## Трассировка

Операции: `insert(1)`, `insert(2)`, `insert(3)`, `remove(1)`, `remove(2)`, `insert(3)`, `getRandom()`.

```
insert(1): нет в Map → indexOf{1:0}, values [1]           → true
insert(2): нет в Map → indexOf{1:0, 2:1}, values [1,2]    → true
insert(3): нет в Map → indexOf{1:0, 2:1, 3:2}, [1,2,3]    → true

remove(1): idx = 0, last = 3
  values[0] = 3        → values [3,2,3]
  indexOf.set(3, 0)    → indexOf{1:0, 2:1, 3:0}
  pop()                → values [3,2]
  delete(1)            → indexOf{2:1, 3:0}                → true

remove(2): idx = 1, last = 2   (удаляем последний!)
  values[1] = 2        → values [3,2]
  indexOf.set(2, 1)    → indexOf{2:1, 3:0}
  pop()                → values [3]
  delete(2)            → indexOf{3:0}                     → true

insert(3): 3 уже в Map                                     → false
getRandom(): length = 1, i = 0                             → 3
```

После каждой операции проверяйте инвариант: например, после `remove(1)` в `values` на позиции `0` лежит `3`, а `indexOf` говорит `3 → 0` — совпадает.

## Почему это работает

Держится всё на инварианте: **`values` — плотный массив всех элементов множества без повторов, и `indexOf` точно знает позицию каждого**.

- `insert` добавляет элемент в конец и записывает его позицию — инвариант сохраняется. Проверка `has` не даёт появиться дубликату.
- `remove` перемещает `last` в ячейку `idx` и обновляет его позицию; затем удаляет хвостовую копию и запись о `val`. Все остальные элементы не двигались, их индексы верны. Случай `last === val` разобран выше.
- `getRandom` полагается на плотность и уникальность: `n` ячеек — `n` разных значений, каждая ячейка выбирается с вероятностью `1/n`.

## Пограничные случаи

- **Удаление единственного/последнего элемента**: `last === val`, порядок «сначала `set`, потом `delete`» оставляет `indexOf` правильным.
- **Элемент на индексе `0`**: проверка `idx === undefined`, а не `!idx`.
- **Повторная вставка**: `has` возвращает `true` → `false`, состояние не меняется.
- **Удаление отсутствующего**: `get` даёт `undefined` → `false`.
- **Отрицательные и большие значения** (`-2^31 … 2^31 - 1`): ключи `Map` — любые числа, проблем нет.
- **Вставка после удаления**: элемент просто дописывается в конец, «дыр» в массиве не бывает.

## Сложность

- **Время `O(1)` в среднем на каждую операцию**: `Map.has/get/set/delete` — амортизированное `O(1)`, `push`/`pop` в конец массива — амортизированное `O(1)`, присваивание по индексу и `Math.random` — `O(1)`. Нигде нет циклов.
- **Память `O(n)`**: каждый элемент хранится один раз в массиве и один раз как ключ в `Map`.

## Типичные ошибки

1. **`splice(idx, 1)` вместо обмена с последним** → удаление становится `O(n)`.
2. **Забыть `indexOf.set(last, idx)`** → после переноса хеш-таблица указывает на старую позицию `last`, и следующее удаление `last` испортит массив.
3. **`delete(val)` до `set(last, idx)`** → при удалении последнего элемента в `Map` остаётся запись `val`, хотя значения уже нет.
4. **Помечать удалённые ячейки пустыми** (`undefined`) вместо сжатия → `getRandom` либо возвращает «пустоту», либо требует повторных попыток и теряет равновероятность.
5. **Использовать только `Set`** и выбирать случайный элемент перебором итератора → `getRandom` за `O(n)`.

## Как узнать такую задачу

- Задача на **проектирование структуры данных** с требованием `O(1)` на **несколько разных видов доступа**: по значению (поиск, удаление) и по позиции (случайный выбор, k-й элемент).
- Ни одна стандартная структура не подходит целиком → комбинируем две и поддерживаем их согласованность.
- Слова «порядок не важен» или «случайный элемент» — подсказка к трюку swap-and-pop.
- Родственные задачи: Insert Delete GetRandom O(1) — Duplicates allowed (там в `Map` хранится множество индексов), LRU Cache, LFU Cache, Random Pick with Blacklist.
