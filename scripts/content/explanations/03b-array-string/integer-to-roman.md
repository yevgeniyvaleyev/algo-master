## Задача простыми словами

Дано целое число `num` от `1` до `3999`. Нужно записать его **римскими цифрами** и вернуть строку.

Символы: `I = 1`, `V = 5`, `X = 10`, `L = 50`, `C = 100`, `D = 500`, `M = 1000`. Обычно символы пишутся от больших к меньшим и складываются, но для 4 и 9 в каждом разряде используется **вычитательная форма**: `IV = 4`, `IX = 9`, `XL = 40`, `XC = 90`, `CD = 400`, `CM = 900`. Один символ подряд можно повторить не больше трёх раз.

Пример: `1994` → `"MCMXCIV"` (`1000 + 900 + 90 + 4`). Ещё: `58` → `"LVIII"` (`50 + 5 + 1 + 1 + 1`).

## Наивный подход

Первое желание — перевести разряд за разрядом, разбирая случаи вручную:

```ts naive
function digit(d: number, one: string, five: string, ten: string): string {
  if (d === 9) return one + ten;
  if (d >= 5) return five + one.repeat(d - 5);
  if (d === 4) return one + five;
  return one.repeat(d);
}
// result = digit(тысячи, 'M', '', '') + digit(сотни, 'C', 'D', 'M') + ...
```

Это работает и даже быстро, но код состоит из веток с особыми случаями, в которых легко ошибиться (перепутать порядок `IV`/`VI`, забыть 9). Ещё наивнее — «жадно» брать только 7 базовых символов: тогда `4` превратится в `IIII`, а это запрещено правилами.

Проблема в том, что вычитательные формы мы воспринимаем как **исключения** из правила, и под каждое пишем свою ветку.

## Ключевое наблюдение

Если считать вычитательные формы **отдельными символами**, исключения исчезают. Получается 13 «атомов» по убыванию:

```
M=1000  CM=900  D=500  CD=400
C=100   XC=90   L=50   XL=40
X=10    IX=9    V=5    IV=4    I=1
```

Теперь правило одно: **пока число не меньше текущего атома — дописываем его и вычитаем**, затем переходим к следующему, меньшему. Для `4` атом `IV` встретится раньше `I`, поэтому `IIII` не появится; для `9` раньше `V` встретится `IX`. Вся логика римской записи «зашита» в таблицу, а код сводится к двум вложенным циклам.

## Техники

### Жадный алгоритм по убывающей таблице номиналов

**Что это.** Жадный алгоритм на каждом шаге делает **локально лучший** выбор (берёт самый крупный подходящий номинал) и никогда его не пересматривает. Он верен не всегда: для произвольных монет, например `[1, 3, 4]` и суммы `6`, жадность даёт `4 + 1 + 1` вместо `3 + 3`. Но для «канонических» систем — обычных денег, римских цифр — жадный выбор всегда даёт правильное (и единственное допустимое) представление.

**Типичный шаблон:**

```ts naive
for (const [value, symbol] of tableDescending) {
  while (rest >= value) { out += symbol; rest -= value; }
}
```

**Как применяется здесь.** Таблица из 13 атомов устроена так, что жадный выбор в каждом десятичном разряде даёт ровно каноническую запись. Подробнее о приёмах работы с числами — во вкладке «Теория».

### Табличное кодирование правил

Вместо ветвлений `if (d === 4) … else if (d === 9) …` правила вынесены в **данные** — два параллельных массива `values` и `symbols`. Код становится универсальным, а ошибку в таблице видно сразу. Этот приём полезен везде, где много однотипных особых случаев: конвертеры единиц, разбор форматов, перевод чисел в слова.

## Разбор кода

```ts
function intToRoman(num: number): string {
  // Все «атомы» римской записи по убыванию, включая вычитательные формы
  const values = [1000, 900, 500, 400, 100, 90, 50, 40, 10, 9, 5, 4, 1];
  const symbols = ['M', 'CM', 'D', 'CD', 'C', 'XC', 'L', 'XL', 'X', 'IX', 'V', 'IV', 'I'];
```

Два параллельных массива: `symbols[i]` записывает значение `values[i]`. Порядок строго по убыванию — на этом держится жадность. Вычитательные формы стоят между соседними базовыми символами (`900` между `1000` и `500` и т. д.).

```ts
  let result = '';
  for (let i = 0; i < values.length && num > 0; i++) {
```

Идём по атомам от крупного к мелкому. Условие `num > 0` позволяет выйти раньше, когда число уже полностью разложено, — например, для `1000` не нужно проверять оставшиеся 12 атомов. На корректность это не влияет: при `num = 0` внутренний цикл всё равно не выполнился бы.

```ts
    // Жадно берём самый большой атом, пока он помещается в остаток
    while (num >= values[i]) {
      result += symbols[i];
      num -= values[i];
    }
  }
```

Пока текущий атом помещается в остаток — дописываем его символ и вычитаем значение. Для «десятичных» атомов (`M`, `C`, `X`, `I`) цикл может выполниться до трёх раз (`MMM`, `CCC`…), для остальных — не больше одного раза: например, после `D` остаток меньше `500`, после `CM` — меньше `100`.

```ts
  return result;
}
```

Когда все атомы пройдены (или `num` стал нулём), `result` содержит ответ.

## Трассировка

`num = 1994`:

```
i=0  M  (1000): 1994 >= 1000 → "M",       num = 994
i=1  CM (900):  994 >= 900   → "MCM",     num = 94
i=2  D  (500):  94 < 500     — пропуск
i=3  CD (400):  пропуск
i=4  C  (100):  пропуск
i=5  XC (90):   94 >= 90     → "MCMXC",   num = 4
i=6  L  (50):   пропуск
i=7  XL (40):   пропуск
i=8  X  (10):   пропуск
i=9  IX (9):    пропуск
i=10 V  (5):    пропуск
i=11 IV (4):    4 >= 4       → "MCMXCIV", num = 0
i=12: условие num > 0 ложно — выход
```

Ответ `"MCMXCIV"`.

`num = 58`: `L` → `8`; атомы `XL`, `X`, `IX` пропускаются; `V` → `3`; `IV` пропускается; `I` трижды → `0`. Ответ `"LVIII"`.

`num = 3749`: `MMM` → `749`; `D` → `249`; `CC` → `49`; `XL` → `9`; `IX` → `0`. Ответ `"MMMDCCXLIX"`. Обратите внимание: `49` — это `XLIX`, а не `IL`: атома `IL` в таблице нет, и правильно — потому что запись идёт по десятичным разрядам.

## Почему это работает

Рассмотрим один десятичный разряд, например сотни (цифра `d`, значение `d · 100`). Атомы этого разряда — `CM`, `D`, `CD`, `C`; всё, что крупнее (`M`), уже снято на предыдущих шагах, поэтому остаток меньше `1000`. Перебором проверяется, что для любой цифры жадность даёт каноническую запись:

- `d = 9` → `CM`; `d = 5…8` → `D` + `C`×(`d − 5`); `d = 4` → `CD`; `d = 0…3` → `C`×`d`.

После атомов разряда остаток меньше `100`, и тот же разбор повторяется для десятков и единиц. Атомы разных разрядов не смешиваются: ни один атом не «перепрыгивает» через границу разряда (например, `XC = 90` берётся только когда в десятках `9`). Значит, результат — это записи разрядов, склеенные от старшего к младшему, ровно как требует условие.

## Пограничные случаи

- **`num = 1`** → `"I"`; **`num = 3999`** → `"MMMCMXCIX"` — максимальное значение по условию.
- **Нули в разрядах** (`1004`, `2020`): атомы этого разряда просто пропускаются, «нулевой» цифры в римской записи нет.
- **Цифры 4 и 9 в любом разряде**: обрабатываются атомами `IV`, `IX`, `XL`, `XC`, `CD`, `CM` без особых веток.
- **Максимальная длина ответа** — 15 символов (`3888` = `"MMMDCCCLXXXVIII"`).

## Сложность

- **Время `O(1)`**: внешний цикл — не больше 13 итераций, внутренний суммарно добавляет не больше 15 символов (длина результата ограничена, так как `num <= 3999`). В общем виде — `O(длина ответа)`.
- **Память `O(1)`**: две таблицы фиксированного размера и строка ответа ограниченной длины.

## Типичные ошибки

1. **Только 7 базовых символов в таблице** → получится `IIII` вместо `IV` и `VIIII` вместо `IX`.
2. **Таблица не по убыванию** → жадность выбирает не тот атом (например, если `V` стоит раньше `IX`, то `9` превратится в `VIV`).
3. **`if` вместо `while`** → `3` превратится в `I` вместо `III`, `2000` — в `M`.
4. **Рассогласованные массивы** `values` и `symbols` (пропущен или переставлен элемент) → неправильные символы; удобнее проверять, держа их рядом или в виде пар.
5. **Придумывать «короткие» формы** вроде `IL` для `49` или `IM` для `999` → они не входят в правила; запись строится по десятичным разрядам.

## Как узнать такую задачу

- Нужно **представить число** в системе с фиксированным набором номиналов: римские цифры, сдача монетами канонической системы, перевод секунд в «дни/часы/минуты», числа словами (Integer to English Words).
- Номиналы можно упорядочить так, что **жадный выбор крупнейшего** гарантированно корректен.
- Много особых случаев, которые выглядят как исключения, — попробуйте превратить их в **строки таблицы**.
- Обратная задача — Roman to Integer: там идут слева направо и вычитают символ, если следующий больше.
