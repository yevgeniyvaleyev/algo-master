## Задача простыми словами

Строку `s` записывают «зигзагом» в `numRows` строк: сначала сверху вниз по столбцу, затем по диагонали вверх, снова вниз и так далее. Потом получившуюся картинку читают **построчно** слева направо. Нужно вернуть результат такого чтения.

Пример: `s = "PAYPALISHIRING"`, `numRows = 3`:

```
P   A   H   N
A P L S I I G
Y   I   R
```

Читаем по строкам: `"PAHN" + "APLSIIG" + "YIR"` = `"PAHNAPLSIIGYIR"`.

## Наивный подход

Самое буквальное решение — нарисовать зигзаг в двумерной сетке и прочитать её:

```ts naive
const cols = s.length; // с запасом
const grid: string[][] = Array.from({ length: numRows }, () => new Array(cols).fill(''));
let r = 0, c = 0, down = true;
for (const ch of s) {
  grid[r][c] = ch;
  if (down) { if (r === numRows - 1) { down = false; r--; c++; } else r++; }
  else { if (r === 0) { down = true; r++; } else { r--; c++; } }
}
return grid.map((row) => row.join('')).join('');
```

Это работает, но сетка занимает `numRows × cols` ячеек — до `1000 × 1000` при длине строки `1000`, и почти все ячейки пустые. Лишняя работа — **хранить и обходить столбцы и пробелы**, хотя при построчном чтении позиция по горизонтали ничего не меняет: символы в каждой строке и так идут слева направо в порядке появления в `s`.

## Ключевое наблюдение

Для ответа важен только **номер строки** каждого символа. Номер строки «ходит» туда-обратно:

```
0, 1, 2, …, numRows-1, numRows-2, …, 1, 0, 1, 2, …
```

Поэтому достаточно завести `numRows` строк-накопителей, идти по `s` и дописывать каждый символ в строку с текущим номером. Направление меняется на верхней (`0`) и нижней (`numRows - 1`) строке. В конце склеиваем накопители по порядку. Каждый символ обрабатывается один раз, столбцы не нужны вовсе.

## Техники

### Симуляция с «отскоком» (направление ±1)

**Что это.** Многие задачи описывают процесс, который проще всего **промоделировать**, чем выводить формулу. Здесь процесс — движение «шарика» между двумя стенками: текущая позиция `row` и шаг `step`, равный `+1` или `-1`. Дошли до стенки — меняем знак шага.

**Типичный шаблон:**

```ts naive
let pos = 0, step = 1;
for (const item of items) {
  обработать(item, pos);
  if (pos === MIN) step = 1;
  else if (pos === MAX) step = -1;
  pos += step;
}
```

Такой же каркас встречается в обходе матрицы по диагоналям, анимации «пинг-понг», распределении элементов «змейкой» по корзинам.

**Как применяется здесь.** `row` — номер строки зигзага, `step` — направление; стенки — строки `0` и `numRows - 1`. Подробнее о приёмах работы с массивами и строками — во вкладке «Теория».

### Группировка по ключу в корзины

Вместо двумерной структуры используем массив «корзин» (`rows`), где ключ — номер строки. Порядок внутри корзины сохраняется сам, потому что символы добавляются в порядке обхода `s`. Склейка корзин по порядку ключей и даёт построчное чтение.

## Разбор кода

```ts
function convert(s: string, numRows: number): string {
  // Одна строка или строк не меньше, чем символов, — зигзага нет
  if (numRows === 1 || numRows >= s.length) return s;
```

Ранний выход. При `numRows === 1` развернуть направление невозможно: строка `0` одновременно верхняя и нижняя, и симуляция ниже ушла бы в `row = 1`, за пределы массива. При `numRows >= s.length` все символы ложатся в первый столбец, по одному в строку, и построчное чтение возвращает исходную строку. Второе условие — оптимизация, но первое — обязательно.

```ts
  // Для каждой строки зигзага копим её символы
  const rows: string[] = new Array(numRows).fill('');
  let row = 0;
  let step = 1; // +1 — идём вниз, -1 — вверх по диагонали
```

`numRows` пустых строк-накопителей. Стартуем с верхней строки и движемся вниз.

```ts
  for (const ch of s) {
    rows[row] += ch;
```

Каждый символ дописываем в накопитель текущей строки. Порядок символов внутри строки совпадает с порядком «слева направо» на картинке, потому что более правые символы зигзага встречаются в `s` позже.

```ts
    // На верхней и нижней строке меняем направление
    if (row === 0) step = 1;
    else if (row === numRows - 1) step = -1;

    row += step;
  }
```

Сначала решаем, куда двигаться **после** текущего символа: на верхней строке — вниз, на нижней — вверх, в середине — продолжаем в том же направлении. Затем делаем шаг. Проверка стоит после записи символа, поэтому символ на «стенке» записывается ровно один раз, а следующий уже идёт в обратную сторону.

```ts
  // Читаем построчно
  return rows.join('');
}
```

Склеиваем строки сверху вниз — это и есть построчное чтение зигзага.

## Трассировка

`s = "PAYPALISHIRING"`, `numRows = 3`. Для каждого символа — строка, куда он попал, и новое направление:

```
P → row 0, step=+1      A → row 1             Y → row 2, step=-1
P → row 1               A → row 0, step=+1    L → row 1
I → row 2, step=-1      S → row 1             H → row 0, step=+1
I → row 1               R → row 2, step=-1    I → row 1
N → row 0, step=+1      G → row 1
```

Накопители в конце:

```
rows[0] = "PAHN"
rows[1] = "APLSIIG"
rows[2] = "YIR"
```

Ответ: `"PAHNAPLSIIGYIR"` — совпадает с примером.

Для `numRows = 4` последовательность строк — `0,1,2,3,2,1,0,1,2,3,2,1,0,1`, накопители `"PIN"`, `"ALSIG"`, `"YAHR"`, `"PI"`, ответ `"PINALSIGYAHRPI"`.

## Почему это работает

Зигзаг — это ровно последовательность номеров строк `0, 1, …, numRows-1, numRows-2, …, 1, 0, …` с периодом `2 · (numRows - 1)`. Переменная `row` воспроизводит её точно: на стенках шаг разворачивается, между стенками сохраняется. Значит, каждый символ попадает в свою строку картинки.

Внутри одной строки картинки символы стоят слева направо в порядке их появления в `s` (зигзаг движется по столбцам только вправо). Код дописывает символы в накопитель в том же порядке. Поэтому `rows[r]` — это ровно `r`-я строка картинки без пробелов, а склейка по `r` — построчное чтение.

## Пограничные случаи

- **`numRows = 1`**: возвращаем `s`; без этой проверки `row` ушёл бы в `1` и дальше.
- **`numRows >= s.length`**: каждый символ в своей строке, ответ — `s`.
- **`numRows = 2`**: строки чередуются `0, 1, 0, 1…` — символы с чётных позиций, затем с нечётных (`"ABCD"` → `"ACBD"`).
- **Строка из одного символа**: срабатывает ранний выход.
- **Знаки препинания** (`,` и `.`): обрабатываются как обычные символы.

## Сложность

- **Время `O(n)`**: один проход по строке, на каждом шаге `O(1)` действий (дописывание символа в строку в современных движках JS амортизированно дешёвое), плюс финальная склейка за `O(n)`.
- **Память `O(n)`**: накопители суммарно содержат все `n` символов. Двумерная сетка из наивного варианта требовала бы `O(numRows · n)`.

Альтернатива без накопителей — формула по периоду `cycle = 2 · (numRows - 1)`: в строке `r` стоят символы с индексами `k · cycle + r` и, для средних строк, `k · cycle + cycle - r`. Асимптотика та же, но легче ошибиться в индексах.

## Типичные ошибки

1. **Нет проверки `numRows === 1`** → индекс `row` выходит за пределы массива, получаются `undefined` и мусор в ответе.
2. **Менять направление до записи символа** → символ на стенке записывается не в ту строку или строка «перескакивает».
3. **Строить двумерную сетку** → лишняя память и сложный код с расчётом столбцов.
4. **Путать период**: `2 · numRows` вместо `2 · (numRows - 1)` в формульном варианте — верхняя и нижняя строки посещаются один раз за период, а не два.
5. **`new Array(numRows)` без `fill('')`** → `undefined + 'P'` даёт строку `"undefinedP"`.

## Как узнать такую задачу

- Описан **процесс раскладки** символов или элементов по рядам, корзинам, столбцам, а спрашивается результат чтения в другом порядке.
- Позиция «ходит туда-обратно» между двумя границами — симуляция с шагом `±1`.
- Если важно только «в какую группу попал элемент», а не точные координаты, — группируем по ключу и не строим полную сетку.
- Родственные задачи: Spiral Matrix, Diagonal Traverse, Binary Tree Zigzag Level Order Traversal, Text Justification (тоже аккуратная симуляция правил).
