## Задача простыми словами

Дан массив `prices`, где `prices[i]` — цена акции в день `i`. Можно совершить **одну** сделку: купить в какой-то день и продать в **более поздний** день. Нужно вернуть максимальную прибыль; если заработать нельзя — `0`.

Пример: `prices = [7, 1, 5, 3, 6, 4]`. Купить за `1` (день 1), продать за `6` (день 4) — прибыль `5`. Продать за `7` нельзя: этот день раньше покупки.

## Наивный подход

Перебрать все пары «день покупки `i` < день продажи `j`»:

```ts naive
let best = 0;
for (let i = 0; i < prices.length; i++) {
  for (let j = i + 1; j < prices.length; j++) {
    best = Math.max(best, prices[j] - prices[i]);
  }
}
return best;
```

Это `O(n²)`: при `n = 10⁵` — около 5 миллиардов пар, слишком медленно. Лишняя работа: для каждого дня продажи `j` мы снова пробегаем все предыдущие дни, хотя из них нам нужен **один** — самый дешёвый. Минимум префикса пересчитывается заново на каждом `j`.

## Ключевое наблюдение

Если продаём в день `j`, то лучшая покупка — по **минимальной цене среди дней `0..j-1`**. Этот минимум можно поддерживать на ходу: при переходе к следующему дню он либо остаётся прежним, либо становится текущей ценой.

Значит, достаточно одного прохода слева направо с двумя переменными: «самая низкая цена до сих пор» и «лучшая прибыль до сих пор».

## Техники

### Бегущий минимум (префиксный минимум)

**Что это.** Вместо того чтобы для каждой позиции заново искать минимум (или максимум, сумму) всех предыдущих элементов, храним его в переменной и обновляем за `O(1)` при каждом шаге. Это «префиксная» агрегация в одну переменную.

**Типичный шаблон:**

```ts naive
let best = initial;
let agg = нейтральное;
for (const x of arr) {
  best = лучшее(best, ответ(x, agg));
  agg = обновить(agg, x);
}
```

Применяется, когда ответ для позиции `j` зависит от «лучшего элемента левее `j`»: максимальная разница `a[j] - a[i]` при `i < j`, максимальная пара с условием на порядок.

**Как применяется здесь.** `agg` — это `minPrice`, ответ для дня — `price - minPrice`. Подробнее о приёмах одного прохода — во вкладке «Теория».

### Связь с алгоритмом Кадане

Прибыль `prices[j] - prices[i]` равна сумме ежедневных изменений `prices[k] - prices[k - 1]` для `k` от `i + 1` до `j`. Поэтому задача — это максимальная сумма подотрезка массива разниц, классический Kadane. Решение через бегущий минимум — та же идея в более наглядной форме.

## Разбор кода

```ts
function maxProfit(prices: number[]): number {
  // Самая низкая цена среди уже прошедших дней — лучший день покупки
  let minPrice = Infinity;
  let best = 0;
```

`minPrice = Infinity` — «пока ни одного дня не видели»: первая же цена окажется меньше и станет минимумом. `best = 0` — вариант «вообще не торговать» всегда доступен, поэтому прибыль ниже нуля не нужна.

```ts
  for (const price of prices) {
    if (price < minPrice) {
      // Нашли более дешёвый день для покупки
      minPrice = price;
```

Если сегодняшняя цена ниже всех прошлых, она становится новым минимумом. Продавать в этот же день бессмысленно: прибыль относительно старого минимума была бы отрицательной, а относительно себя — нулевой.

```ts
    } else {
      // Пробуем продать сегодня, купив по минимальной цене в прошлом
      best = Math.max(best, price - minPrice);
    }
  }
```

Иначе пробуем продать сегодня: покупка была по `minPrice` в **одном из прошлых** дней (строго раньше, ведь сегодняшняя цена минимумом не стала). Если цена равна `minPrice`, прибыль `0` — `best` не изменится.

```ts
  // Если цены только падали, best так и останется 0
  return best;
}

// Время: O(n) — один проход
// Память: O(1)
```

Возвращаем лучшую найденную прибыль; при постоянно падающих ценах ни разу не сработает ветка `else` с положительной разницей, и ответ — `0`.

## Трассировка

`prices = [7, 1, 5, 3, 6, 4]`, старт `minPrice = ∞`, `best = 0`:

```
price=7: 7<∞  → minPrice=7               best=0
price=1: 1<7  → minPrice=1               best=0
price=5: 5≥1  → 5−1=4, best=max(0,4)     best=4
price=3: 3≥1  → 3−1=2, best=max(4,2)     best=4
price=6: 6≥1  → 6−1=5, best=max(4,5)     best=5
price=4: 4≥1  → 4−1=3, best=max(5,3)     best=5
```

Ответ `5`: купить за `1`, продать за `6`.

Падающие цены, `prices = [7, 6, 4, 3, 1]`: каждая цена меньше предыдущего минимума, срабатывает только первая ветка, `best` остаётся `0`.

## Почему это работает

Инвариант: перед обработкой дня `j` переменная `minPrice` равна минимуму `prices[0..j-1]`, а `best` — максимальной прибыли среди всех сделок с продажей в днях `0..j-1` (или `0`).

Для дня `j` лучшая сделка с продажей именно в этот день — `prices[j] - minPrice`. Если `prices[j] < minPrice`, такая сделка убыточна и `best` не улучшит, поэтому её можно не считать; зато минимум обновляется. Иначе сравниваем её с `best`. После обработки инвариант верен для `j + 1`. Так как каждая сделка «купить в `i`, продать в `j`» не лучше `prices[j] - min(prices[0..j-1])`, а этот вариант мы рассмотрели для каждого `j`, итоговый `best` — максимум.

## Пограничные случаи

- **Один день**: продать после покупки нельзя, ответ `0` (цена станет минимумом, `else` не выполнится).
- **Цены только падают**: ответ `0`.
- **Все цены одинаковые**: разница всегда `0`, ответ `0`.
- **Минимум в самом конце** (`[3, 8, 1]`): новый минимум `1` ни на что не влияет, ответ `5` уже найден раньше.
- **Лучшая сделка не включает глобальный минимум** (`[2, 9, 1, 3]`): ответ `7`, а не `2` — бегущий минимум учитывает только прошлое.

## Сложность

- **Время `O(n)`**: один проход, на каждом дне `O(1)` операций.
- **Память `O(1)`**: две переменные.

## Типичные ошибки

1. **Взять `max(prices) - min(prices)`** → игнорирует порядок дней: для `[7, 1]` получится `6`, хотя продать раньше покупки нельзя.
2. **Начинать `best` с `-Infinity`** → для падающих цен вернётся отрицательное число вместо `0`.
3. **Покупать строго в день глобального минимума** и искать максимум после него → для `[2, 9, 1, 3]` получится `2` вместо `7`. Лучшая покупка зависит от дня продажи.
4. **Хранить индекс минимума и пересчитывать минимум заново** → возвращение к `O(n²)`.

## Как узнать такую задачу

- Нужен максимум `a[j] - a[i]` при условии **`i < j`** — бегущий минимум слева.
- «Одна покупка и одна продажа», «лучший момент входа и выхода», «максимальный рост за период».
- Похожие задачи: Best Time to Buy and Sell Stock II (много сделок — жадно суммировать рост), Maximum Subarray (Кадане), Maximum Difference Between Increasing Elements.
