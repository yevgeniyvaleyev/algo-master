## Задача простыми словами

Дан массив `nums` длины `n`. Нужно вернуть **элемент большинства** — значение, которое встречается **строго больше `n / 2` раз**. Гарантируется, что такой элемент есть. Дополнительно просят решение за `O(n)` времени и `O(1)` памяти.

Пример: `nums = [2, 2, 1, 1, 1, 2, 2]`. Двоек четыре из семи (`4 > 3.5`), ответ `2`.

## Наивный подход

Самый прямой способ — посчитать частоты:

```ts naive
const freq = new Map<number, number>();
for (const x of nums) {
  const c = (freq.get(x) ?? 0) + 1;
  if (c > nums.length / 2) return x;
  freq.set(x, c);
}
```

Это `O(n)` по времени, но `O(n)` по памяти: в таблице может оказаться до `n / 2` разных значений. Есть и вариант с сортировкой — элемент большинства обязательно займёт середину, `nums[Math.floor(n / 2)]`, — но это `O(n log n)`.

Где лишняя работа? Мы храним точные частоты **всех** значений, хотя нас интересует только одно — то, которого больше половины. Про остальные значения достаточно знать лишь то, что они «мешают».

## Ключевое наблюдение

Если вычеркнуть из массива **пару разных элементов**, элемент большинства останется большинством в оставшейся части: из пары он теряет максимум один экземпляр, а длина уменьшается на два.

Значит, можно идти по массиву и «аннигилировать» разные элементы попарно, держа только **одного кандидата** и **счётчик его неуничтоженных копий**. Элементу большинства не хватит соперников, чтобы уничтожить все его копии, и в конце кандидатом останется именно он.

## Техники

### Голосование Бойера–Мура (Boyer–Moore majority vote)

**Что это.** Алгоритм поиска элемента большинства за один проход и `O(1)` памяти. Состояние — пара `(candidate, count)`:

1. если `count === 0`, текущий элемент становится кандидатом;
2. если элемент совпадает с кандидатом — `count++` (голос «за»);
3. иначе — `count--` (голос «против», пара взаимно уничтожилась).

**Когда применять.** Нужно найти значение, встречающееся больше `n / 2` раз (или, в обобщении, больше `n / k` раз — тогда держат `k - 1` кандидатов), и важна память. Если существование большинства **не** гарантировано, после прохода нужен второй проход: посчитать, сколько раз встречается `candidate`, и проверить, что больше `n / 2`.

**Как применяется здесь.** Ровно в базовой форме; второй проход не нужен, потому что большинство гарантировано условием.

### Проход с компактным состоянием

Это частный случай общего приёма из темы «Массивы и строки»: решить задачу за один проход, понимая, какое **минимальное состояние** достаточно держать. Здесь вместо таблицы частот хватает двух переменных. Подробнее — во вкладке «Теория».

## Разбор кода

```ts
function majorityElement(nums: number[]): number {
  // Текущий кандидат в большинство и его «перевес» голосов
  let candidate = nums[0];
  let count = 0;
```

`count` — на сколько голосов «за» кандидата больше, чем «против» в текущем отрезке. Начальное значение `candidate` на самом деле не важно: при `count = 0` первый же элемент станет кандидатом. `nums[0]` просто удобен для типа `number`.

```ts
  for (const x of nums) {
    if (count === 0) {
      // Перевеса нет — новый элемент становится кандидатом
      candidate = x;
    }
```

Если перевес исчерпан, все предыдущие элементы разбились на пары разных и «уничтожили» друг друга. Начинаем новый отрезок: текущий элемент — новый кандидат.

```ts
    // Голос «за» своего кандидата, «против» — за чужого
    count += x === candidate ? 1 : -1;
  }
```

Совпал с кандидатом — перевес растёт, иначе падает. Обратите внимание: если `x` только что стал кандидатом, сюда он придёт уже как «свой» и даст `count = 1`. Счётчик никогда не становится отрицательным: уменьшение возможно только при `count >= 1`.

```ts
  // По условию большинство существует, значит это кандидат
  return candidate;
}

// Время: O(n) — один проход
// Память: O(1) — алгоритм голосования Бойера–Мура
```

После прохода кандидат и есть элемент большинства (доказательство ниже).

## Трассировка

`nums = [2, 2, 1, 1, 1, 2, 2]`:

```
x=2: count=0 → candidate=2; 2=2 → count=1
x=2: 2=2 → count=2
x=1: 1≠2 → count=1
x=1: 1≠2 → count=0
x=1: count=0 → candidate=1; 1=1 → count=1
x=2: 2≠1 → count=0
x=2: count=0 → candidate=2; 2=2 → count=1
```

Ответ `2`. Видно, что кандидат по ходу менялся (в середине им была `1`), но к концу двоек оказалось достаточно, чтобы «победить».

Пример `nums = [3, 2, 3]`: `x = 3` → кандидат `3`, `count = 1`; `x = 2` → `count = 0`; `x = 3` → кандидат `3`, `count = 1`. Ответ `3`.

## Почему это работает

Разрежем массив на отрезки по моментам, когда `count` становится `0` перед новым элементом. Получатся несколько **закрытых** отрезков (в конце каждого `count = 0`) и один **последний** отрезок, где кандидат больше не менялся.

**Закрытые отрезки.** В каждом из них кандидат отрезка встречается ровно половину раз (столько же «за», сколько «против»). Значит, **любое** значение занимает в закрытом отрезке не больше половины.

**Последний отрезок.** Элемент большинства `M` встречается больше половины всего массива, а в закрытых отрезках — не больше их половины. Следовательно, в последнем отрезке `M` встречается **больше половины** его длины. Пусть кандидат последнего отрезка `c` отличен от `M`. Тогда каждое `M` — голос «против», и `count = #c − #остальных ≤ #c − #M`. Но `#c + #M ≤ длина`, а `#M > длина / 2`, значит `#c < #M` и `count < 0` — невозможно. Итак, `c = M`.

## Пограничные случаи

- **Один элемент**: он становится кандидатом, ответ — он.
- **Все элементы одинаковые**: `count` просто растёт до `n`.
- **Большинство в самом конце** (`[1, 2, 3, 3, 3]`): кандидат меняется несколько раз, но в итоге остаётся `3`.
- **Отрицательные числа и ноль**: сравниваются через `===`, знак не важен.
- **Если бы большинства не было** (`[1, 2, 3]`): алгоритм вернул бы какой-то элемент (здесь `3`), поэтому без гарантии нужен проверочный второй проход.

## Сложность

- **Время `O(n)`**: один проход, на каждом элементе `O(1)` действий.
- **Память `O(1)`**: две переменные, никаких таблиц.

## Типичные ошибки

1. **Сначала менять `count`, потом проверять `count === 0`** → новый кандидат не получает свой голос, и счётчик уходит в минус.
2. **Считать, что `count` в конце — это частота элемента** → нет, это только перевес в последнем отрезке.
3. **Применять без гарантии существования** большинства и без второго прохода → неверный ответ на массивах без большинства.
4. **Путать «больше `n / 2`» с «самым частым»**: для `[1, 1, 2, 2, 3]` голосование вернёт `3`, хотя самые частые — `1` и `2`.

## Как узнать такую задачу

- «Элемент встречается **больше `n / 2`** (или `n / 3`, `n / k`) раз» + требование `O(1)` памяти — голосование Бойера–Мура.
- Нужно найти «доминирующее» значение, а про остальные важно лишь то, что они ему мешают.
- Похожие задачи: Majority Element II (больше `n / 3`, два кандидата), Check If a Number Is Majority Element in a Sorted Array, «доминатор» массива.
