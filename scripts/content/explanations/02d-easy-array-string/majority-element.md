## Задача простыми словами

Дан массив `nums` длины `n`. Нужно вернуть **элемент большинства** — число, которое встречается **больше `n / 2` раз**. Гарантируется, что такой элемент есть.

Пример: `nums = [2, 2, 1, 1, 1, 2, 2]`, `n = 7`. Двойка встречается 4 раза, а `4 > 3.5` — ответ `2`.

## Наивный подход

Для каждого элемента посчитать, сколько раз он встречается во всём массиве:

```ts naive
for (const x of nums) {
  let count = 0;
  for (const y of nums) {
    if (y === x) count++;
  }
  if (count > nums.length / 2) return x;
}
```

Это `O(n²)`: при `n = 5 * 10^4` — больше миллиарда сравнений. Где лишняя работа? Для каждого элемента мы **заново пересчитываем** одно и то же: сколько раз встречается число. Одинаковые числа пересчитываются снова и снова. Если запоминать счётчики по ходу, хватит одного прохода.

## Ключевое наблюдение

Нам нужна просто **частота** каждого числа. Частоты удобно хранить в хеш-таблице «значение → сколько раз встретилось»: увеличить счётчик и прочитать его — `O(1)`.

Больше того, весь массив проходить не обязательно: как только счётчик какого-то числа стал больше `n / 2`, это и есть ответ. Другое число не может встретиться больше половины раз, если половину уже заняло это.

## Техники

### Подсчёт частот в хеш-таблице

**Что это.** `Map` хранит пары «ключ → значение» и за амортизированное `O(1)` умеет прочитать и записать значение по ключу. Для подсчёта частот ключ — элемент, значение — сколько раз он встретился.

**Типичный шаблон:**

```ts naive
const counts = new Map<number, number>();
for (const x of nums) {
  counts.set(x, (counts.get(x) ?? 0) + 1);
}
```

`counts.get(x) ?? 0` возвращает текущий счётчик или `0`, если число встречается впервые. Тот же шаблон работает в Valid Anagram, Ransom Note, Top K Frequent Elements и десятках других задач.

**Как применяется здесь.** Сразу после увеличения счётчика проверяем, не превысил ли он половину длины массива. Подробнее о хеш-таблицах — во вкладке «Теория».

## Разбор кода

```ts
function majorityElement(nums: number[]): number {
  // Значение -> сколько раз оно уже встретилось
  const counts = new Map<number, number>();
```

Таблица частот, изначально пустая — мы ещё ничего не видели.

```ts
  for (const x of nums) {
    const count = (counts.get(x) ?? 0) + 1;
    counts.set(x, count);
```

Идём по массиву один раз. Для текущего числа берём старый счётчик (или `0`, если числа ещё не было), прибавляем единицу и записываем обратно. Новое значение сохраняем в `count`, чтобы сразу его проверить и не читать таблицу второй раз.

```ts
    // Встретился больше n / 2 раз — это и есть элемент большинства
    if (count > nums.length / 2) {
      return x;
    }
  }
```

Сравнение с `nums.length / 2` без округления: при `n = 7` порог `3.5`, и подходит `count = 4`; при `n = 4` порог `2`, и нужен `count = 3`. Это ровно «больше `⌊n / 2⌋`». Как только счётчик перевалил за половину, возвращаем ответ, не дочитывая массив.

```ts
  // По условию большинство существует, сюда не дойдём
  return -1;
}
```

Если элемент большинства гарантирован, цикл всегда вернёт ответ раньше. Строка нужна только для TypeScript: функция обязана вернуть число на всех путях.

## Трассировка

`nums = [2, 2, 1, 1, 1, 2, 2]`, порог `7 / 2 = 3.5`:

1. `x = 2`: `count = 1`, `counts = {2: 1}`. `1 > 3.5`? Нет.
2. `x = 2`: `count = 2`, `counts = {2: 2}`. Нет.
3. `x = 1`: `count = 1`, `counts = {2: 2, 1: 1}`. Нет.
4. `x = 1`: `count = 2`, `counts = {2: 2, 1: 2}`. Нет.
5. `x = 1`: `count = 3`, `counts = {2: 2, 1: 3}`. `3 > 3.5`? Нет.
6. `x = 2`: `count = 3`, `counts = {2: 3, 1: 3}`. Нет.
7. `x = 2`: `count = 4`, `counts = {2: 4, 1: 3}`. `4 > 3.5` → возвращаем `2`.

`nums = [3, 2, 3]`, порог `1.5`: после `3` счётчик `1`, после `2` — `{3: 1, 2: 1}`, после второго `3` счётчик `2 > 1.5` → ответ `3`.

## Почему это работает

Таблица в каждый момент хранит **точные** частоты всех просмотренных элементов: каждый элемент увеличивает свой счётчик ровно один раз. Пусть `m` — элемент большинства, он встречается `c > n / 2` раз. Когда цикл дойдёт до его `c`-го вхождения, счётчик станет `c` и проверка сработает — значит, функция обязательно вернёт ответ.

Ложного срабатывания быть не может: если у какого-то числа счётчик превысил `n / 2`, оно встречается больше половины раз, а таких чисел не больше одного — два разных числа вместе заняли бы больше `n` позиций. Значит, вернётся именно `m`.

## Пограничные случаи

- **Один элемент** (`[1]`): порог `0.5`, счётчик `1` сразу превышает его.
- **Большинство в конце** (`[1, 2, 2]`): ответ находится на последнем элементе.
- **Отрицательные числа** (`[-1, 1, -1, 1, -1]`): `Map` работает с любыми числовыми ключами.
- **Чётная длина** (`[6, 5, 5, 5]`, порог `2`): нужно минимум 3 вхождения, сравнение `>` а не `>=`.

## Сложность

- **Время `O(n)`**: один проход, на каждом шаге `get` и `set` у `Map` за амортизированное `O(1)`.
- **Память `O(n)`**: в худшем случае в таблице окажется около `n / 2` разных чисел.

**Follow-up на собеседовании — `O(1)` памяти, голосование Бойера–Мура.** Храним кандидата и «перевес» его голосов: при нулевом перевесе текущий элемент становится кандидатом, совпадение даёт `+1`, иначе `-1`. Каждый `-1` — это взаимное уничтожение двух разных элементов, а большинство не может быть уничтожено полностью:

```ts naive
let candidate = nums[0];
let count = 0;
for (const x of nums) {
  if (count === 0) candidate = x;
  count += x === candidate ? 1 : -1;
}
return candidate;
```

Ещё один вариант — отсортировать и вернуть `nums[Math.floor(n / 2)]`: большинство обязательно занимает середину, но это `O(n log n)`.

## Типичные ошибки

1. **Сравнивать с `Math.floor(n / 2)` через `>=`** → при `n = 7` порог становится `3`, и если большинство не гарантировано, вернётся число, встречающееся ровно 3 раза из 7, — а это не большинство. Порог — строго `count > n / 2`.
2. **Забыть, что `n / 2` в JS дробное**, и пытаться сравнивать с ним через `===` → при нечётном `n` равенства не будет никогда.
3. **`counts.get(x) + 1` без `?? 0`** → для нового числа `undefined + 1 = NaN`, счётчик сломан.
4. **Сначала посчитать все частоты, потом искать максимум** — верно, но два прохода и лишний код; ранний выход проще.
5. **Использовать объект `{}` вместо `Map`** → ключи становятся строками; работает, но `Map` надёжнее и нагляднее.

## Как узнать такую задачу

- Нужно найти элемент по **частоте**: «встречается больше половины», «чаще всех», «ровно k раз» — таблица частот в `Map`.
- Есть follow-up «`O(1)` памяти» и гарантия большинства — голосование Бойера–Мура.
- Родственные задачи: Majority Element II (больше `n / 3`, два кандидата), Top K Frequent Elements, Valid Anagram, Single Number.
