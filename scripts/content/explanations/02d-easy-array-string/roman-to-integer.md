## Задача простыми словами

Дана строка `s` — корректное римское число от `1` до `3999`. Нужно вернуть его значение как обычное целое. Цифры: `I = 1`, `V = 5`, `X = 10`, `L = 50`, `C = 100`, `D = 500`, `M = 1000`. Обычно цифры пишутся от больших к меньшим и складываются, но есть шесть «вычитательных» пар: `IV = 4`, `IX = 9`, `XL = 40`, `XC = 90`, `CD = 400`, `CM = 900`.

Пример: `s = "LVIII"` → `50 + 5 + 1 + 1 + 1 = 58`. `s = "MCMXCIV"` → `1000 + 900 + 90 + 4 = 1994`.

## Наивный подход

Прямолинейный способ — закодировать все особые случаи: проверять, не начинается ли с текущей позиции одна из шести двухсимвольных пар, и если да — прибавлять её значение и прыгать на два символа:

```ts naive
const pairs: Record<string, number> = { IV: 4, IX: 9, XL: 40, XC: 90, CD: 400, CM: 900 };
let total = 0;
for (let i = 0; i < s.length; ) {
  const two = s.slice(i, i + 2);
  if (two in pairs) { total += pairs[two]; i += 2; }
  else { total += values[s[i]]; i += 1; }
}
```

По скорости это тоже `O(n)`, но решение хрупкое: две таблицы, срезы строк на каждом шаге, ручной сдвиг индекса на 1 или 2. Лишнее здесь — сама таблица из шести пар: все они подчиняются **одному правилу**, и перечислять их не нужно.

## Ключевое наблюдение

В корректной записи цифры идут по невозрастанию, и единственное исключение — **меньшая цифра перед большей**. Такая меньшая цифра всегда **вычитается**: `IV = −1 + 5`, `XC = −10 + 100`, `CM = −100 + 1000`.

Поэтому каждый символ можно обработать независимо, глядя только на **следующий**: если текущее значение меньше следующего — вычитаем, иначе прибавляем. Никаких пар и прыжков на два символа.

## Техники

### Таблица соответствий (lookup table)

**Что это.** Фиксированное отображение «символ → значение» в объекте или `Map`. Доступ за `O(1)`, а код не превращается в длинный `switch`.

**Когда применять.** Конвертации и разбор форматов: римские цифры, телефонная клавиатура (Letter Combinations), азбука Морзе, частоты символов алфавита.

**Как применяется здесь.** `values` переводит каждую римскую цифру в число. Подробнее о приёмах для строк — во вкладке «Теория».

### Взгляд на соседа (lookahead)

Решение для текущего элемента зависит от **следующего** элемента. Это частый приём однопроходного разбора: смотрим на `s[i + 1]`, но не потребляем его — он будет обработан на своей итерации. Важно аккуратно обработать конец строки, где соседа нет. Эквивалентный вариант — идти **с конца** и помнить предыдущее (правое) значение.

## Разбор кода

```ts
function romanToInt(s: string): number {
  // Значения римских цифр
  const values: Record<string, number> = {
    I: 1,
    V: 5,
    X: 10,
    L: 50,
    C: 100,
    D: 500,
    M: 1000,
  };
```

Таблица из семи цифр. Тип `Record<string, number>` позволяет индексировать её любым символом строки `s[i]` без лишних приведений типов.

```ts
  let total = 0;

  for (let i = 0; i < s.length; i++) {
    const cur = values[s[i]];
    // Для последнего символа «следующего» нет — считаем его нулём
    const next = i + 1 < s.length ? values[s[i + 1]] : 0;
```

`total` — накопленная сумма. На каждом шаге берём значение текущей цифры `cur` и значение следующей `next`. У последнего символа следующего нет — подставляем `0`: любая цифра больше нуля, поэтому последний символ всегда прибавляется. Без этой проверки `values[undefined]` дал бы `undefined`, а сравнение `cur < undefined` — `false`; работало бы случайно, но читалось бы плохо.

```ts
    if (cur < next) {
      // Меньшая цифра перед большей (IV, XC, CM...) — вычитаем
      total -= cur;
    } else {
      // Обычный случай — прибавляем
      total += cur;
    }
  }
```

Главное правило. Меньшая перед большей — вычитательная запись, `cur` уходит с минусом; большая цифра из пары будет прибавлена на следующей итерации. Равные соседи (`II`, `XX`) и убывание — обычное сложение, поэтому условие строгое: `<`, а не `<=`.

```ts
  return total;
}

// Время: O(n), где n — длина строки
// Память: O(1) — таблица из 7 символов
```

После прохода `total` — значение числа.

## Трассировка

`s = "MCMXCIV"`:

```
i=0 M: cur=1000, next=C=100   → 1000≥100 → +1000  total=1000
i=1 C: cur=100,  next=M=1000  → 100<1000 → −100   total=900
i=2 M: cur=1000, next=X=10    → +1000             total=1900
i=3 X: cur=10,   next=C=100   → −10               total=1890
i=4 C: cur=100,  next=I=1     → +100              total=1990
i=5 I: cur=1,    next=V=5     → −1                total=1989
i=6 V: cur=5,    next=0       → +5                total=1994
```

Ответ `1994`. Вычитательные пары `CM`, `XC`, `IV` разобрались сами: минус меньшей цифры плюс большая цифра.

`s = "LVIII"`: `L` (50 ≥ 5) `+50`, `V` (5 ≥ 1) `+5`, `I` (1 = 1) `+1`, `I` `+1`, последняя `I` (next = 0) `+1`. Итого `58`.

## Почему это работает

Римское число — это сумма «групп»: одиночных цифр и вычитательных пар. Одиночная цифра в корректной записи не меньше следующей за ней, поэтому код прибавляет её значение. В паре вида `ab` с `a < b` значение группы — `b − a`: код видит `a < b` и вычитает `a`, а затем на следующем шаге прибавляет `b` (за `b` в корректной записи идёт цифра не больше `b`, так что `b` прибавляется). Сумма вкладов по всем символам совпадает с суммой групп.

Корректность входа здесь важна: в римской записи не бывает, например, `IIV` или `IC`, поэтому правило «меньшая перед большей — минус» всегда даёт правильное значение.

## Пограничные случаи

- **Один символ** (`"M"`): `next = 0`, прибавляем `1000`.
- **Повторы** (`"III"`, `"MMM"`): равные соседи складываются, условие строгое.
- **Вычитательная пара в конце** (`"XIV"`): `I` вычитается, `V` прибавляется как последний символ.
- **Максимум** `"MMMCMXCIX" = 3999`: три вычитательные пары подряд обрабатываются тем же правилом.

## Сложность

- **Время `O(n)`**: каждый символ обрабатывается один раз, доступ к таблице — `O(1)`. Длина строки не больше 15.
- **Память `O(1)`**: таблица из семи записей и пара переменных.

## Типичные ошибки

1. **Условие `cur <= next`** → `II` превратится в `−1 + 1 = 0`.
2. **Не обработать последний символ** (цикл до `s.length - 1`) → последняя цифра теряется.
3. **Жёстко кодировать шесть пар** и сдвигать индекс на 2 → больше кода и легко ошибиться со сдвигом.
4. **Вычитать большую цифру** вместо меньшей (путаница направлений) → `IV` даёт `−4`.
5. **Сравнивать символы, а не значения** (`s[i] < s[i + 1]`) → сравниваются коды букв, а их порядок не совпадает с порядком значений: по алфавиту `'L' < 'X'`, хотя `50 > 10`, и `"LX"` даст `−50 + 10 = −40` вместо `60`.

## Как узнать такую задачу

- Разбор записи, где **значение символа зависит от соседа** (вычитательная нотация, особые сочетания) — смотрите на следующий элемент или идите с конца.
- Конвертация между системами записи — таблица соответствий.
- Похожие задачи: Integer to Roman (обратная — жадно по убыванию номиналов), Excel Sheet Column Number, String to Integer (atoi).
