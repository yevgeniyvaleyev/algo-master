## Задача простыми словами

Дан массив `nums`, отсортированный по неубыванию. Нужно на месте убрать повторы так, чтобы в начале массива каждое значение осталось **по одному разу** в исходном порядке, и вернуть `k` — число уникальных значений. Что лежит после первых `k` ячеек, неважно.

Пример: `nums = [1, 1, 2]`. Ответ `k = 2`, начало массива — `[1, 2, ...]`.

## Наивный подход

Выбрасывать дубликаты через `splice`, пока соседние элементы совпадают:

```ts naive
for (let i = 1; i < nums.length; ) {
  if (nums[i] === nums[i - 1]) nums.splice(i, 1);
  else i++;
}
return nums.length;
```

Каждый `splice` сдвигает весь хвост на одну позицию, поэтому при большом числе повторов это `O(n²)`. Лишняя работа: уникальный элемент из конца массива сдвигается влево столько раз, сколько дубликатов стоит перед ним, хотя его финальная позиция известна сразу.

Вариант через `new Set(nums)` даёт `O(n)` времени, но требует `O(n)` памяти и вообще не использует то, что массив отсортирован.

## Ключевое наблюдение

Массив отсортирован, поэтому **все копии одного значения стоят подряд**. Значит, элемент «новый» тогда и только тогда, когда он отличается от **последнего записанного уникального** значения. Не нужно помнить все встреченные значения — достаточно смотреть на одну ячейку.

Финальная позиция нового значения — число уникальных, найденных до него. Это ровно указатель записи `k`, как в «фильтрации на месте».

## Техники

### Быстрый и медленный указатели

**Что это.** Два индекса идут в одном направлении: `i` читает каждый элемент, `k` показывает, куда записать следующий элемент результата. В префиксе `nums[0..k-1]` всегда лежит готовый результат, а `k <= i` гарантирует, что запись не портит непрочитанные данные.

**Типичный шаблон:** фильтрация на месте — `if (оставить) nums[k++] = nums[i]`. Здесь условие «оставить» сравнивает текущий элемент с последним **записанным**.

**Как применяется здесь.** «Оставить» — значит `nums[i] !== nums[k - 1]`. Подробнее о вариантах двух указателей — во вкладке «Теория».

### Использование отсортированности

Сортировка превращает глобальный вопрос «встречалось ли это значение где-то раньше?» в локальный «отличается ли оно от предыдущего?». Это частый приём: в отсортированном массиве одинаковые элементы образуют **непрерывные группы**, и с группами можно работать одним проходом без хеш-таблицы.

## Разбор кода

```ts
function removeDuplicates(nums: number[]): number {
  // Первый элемент всегда уникален, поэтому писать начинаем с индекса 1
  let k = 1;
```

По условию массив непустой, а первый элемент не может быть дубликатом — до него ничего нет. Поэтому он уже «записан» на своё место, и уникальный префикс имеет длину `1`.

```ts
  for (let i = 1; i < nums.length; i++) {
    // Массив отсортирован: дубликаты стоят подряд, значит
    // новое значение — то, что отличается от последнего записанного
    if (nums[i] !== nums[k - 1]) {
      nums[k] = nums[i];
      k++;
    }
  }
```

Читаем со второго элемента. `nums[k - 1]` — последнее уникальное значение в готовом префиксе. Если `nums[i]` от него отличается, это начало новой группы: записываем его в `nums[k]` и расширяем префикс. Если совпадает — это очередная копия, пропускаем.

Почему сравнение именно с `nums[k - 1]`, а не с `nums[i - 1]`? Для этой задачи оба варианта дают верный ответ, но сравнение с последним записанным элементом — более общий приём: в Remove Duplicates II («не больше двух копий») достаточно заменить его на `nums[k - 2]`.

```ts
  // В nums[0..k-1] — все уникальные значения по возрастанию
  return k;
}

// Время: O(n) — один проход
// Память: O(1) — меняем массив на месте
```

`k` — длина уникального префикса, именно её и ждёт проверка.

## Трассировка

`nums = [0, 0, 1, 1, 1, 2, 2, 3, 3, 4]`, старт `k = 1`:

```
i=1: 0 vs nums[0]=0 → равны, пропуск
i=2: 1 vs nums[0]=0 → новое, nums[1]=1, k=2
i=3: 1 vs nums[1]=1 → пропуск
i=4: 1 vs nums[1]=1 → пропуск
i=5: 2 vs nums[1]=1 → новое, nums[2]=2, k=3
i=6: 2 vs nums[2]=2 → пропуск
i=7: 3 vs nums[2]=2 → новое, nums[3]=3, k=4
i=8: 3 vs nums[3]=3 → пропуск
i=9: 4 vs nums[3]=3 → новое, nums[4]=4, k=5
```

Ответ `k = 5`, массив `[0, 1, 2, 3, 4, 2, 2, 3, 3, 4]` — первые пять ячеек `[0, 1, 2, 3, 4]`, остальное — мусорный хвост.

Пример без повторов, `nums = [1, 2, 3]`: на каждом шаге `k === i`, элементы записываются сами в себя, ответ `3`.

## Почему это работает

Инвариант перед итерацией с индексом `i`: `nums[0..k-1]` — все различные значения из `nums[0..i-1]` по возрастанию, без повторов, и `k <= i`.

- В начале `k = i = 1`: префикс `[nums[0]]` — верно.
- Так как массив отсортирован, `nums[i] >= nums[i - 1]`, а последнее записанное `nums[k - 1]` — это максимум просмотренной части, то есть `nums[i - 1]`. Если `nums[i]` отличается, оно строго больше всех записанных — новое значение, и дописывание сохраняет и уникальность, и порядок. Если равно — это копия уже записанного значения.
- `k <= i`, поэтому `nums[k] = nums[i]` пишет в уже прочитанную ячейку.

После цикла `i = n`, и префикс длины `k` — ровно все уникальные значения.

## Пограничные случаи

- **Один элемент**: цикл не выполняется, ответ `1`.
- **Все элементы одинаковые** (`[7, 7, 7]`): ни одной записи, ответ `1`.
- **Нет повторов**: каждый элемент пишется сам в себя, ответ `n`.
- **Отрицательные числа**: сравнение `!==` работает для любых значений.
- **Пустой массив** по условию невозможен; если бы он был, код вернул бы `1` — понадобилась бы отдельная проверка.

## Сложность

- **Время `O(n)`**: один проход, на каждом шаге сравнение и не больше одной записи.
- **Память `O(1)`**: два индекса, массив меняется на месте.

## Типичные ошибки

1. **Начинать с `k = 0`** и сравнивать с `nums[k - 1]` → обращение к `nums[-1]`, первый элемент теряется или дублируется.
2. **`splice` в цикле** → `O(n²)` и риск пропустить элемент из-за сдвига индексов.
3. **Возвращать `nums.length`** вместо `k`.
4. **Использовать `Set`** — работает, но тратит `O(n)` памяти и игнорирует отсортированность (а в задаче требуется `O(1)`).
5. **Сравнивать с `nums[i + 1]`** и выходить за границу массива на последнем элементе.

## Как узнать такую задачу

- Массив **отсортирован**, нужно убрать или ограничить повторы **на месте** и вернуть новую длину — медленный указатель записи + сравнение с последним записанным.
- «Не больше `t` копий каждого значения» — то же самое, сравнение с `nums[k - t]`.
- Похожие задачи: Remove Duplicates from Sorted Array II, Remove Element, Move Zeroes, Remove Duplicates from Sorted List (тот же принцип для связного списка).
