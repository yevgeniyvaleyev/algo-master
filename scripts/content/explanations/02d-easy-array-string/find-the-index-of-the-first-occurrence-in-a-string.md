## Задача простыми словами

Даны две строки: `haystack` («стог сена») и `needle` («иголка»). Нужно вернуть индекс **первого вхождения** `needle` в `haystack` или `-1`, если вхождений нет. Это ровно то, что делает встроенный `haystack.indexOf(needle)`.

Пример: `haystack = "sadbutsad"`, `needle = "sad"`. Вхождения начинаются с позиций `0` и `6`, первое — `0`. Для `haystack = "leetcode"`, `needle = "leeto"` ответ `-1`.

## Наивный подход

Самый буквальный способ — для каждой позиции вырезать подстроку длины `needle` и сравнить её целиком:

```ts naive
for (let start = 0; start < haystack.length; start++) {
  if (haystack.slice(start, start + needle.length) === needle) return start;
}
return -1;
```

Он верен, но тратит силы впустую в двух местах:

- `slice` **всегда копирует** `m` символов, даже если уже первый символ не совпадает — то есть на каждой позиции мы платим `O(m)` и выделяем память под новую строку;
- цикл доходит до самого конца `haystack`, хотя начиная с позиции `n - m + 1` иголка туда **физически не помещается**.

## Ключевое наблюдение

Сравнивать можно **посимвольно на месте**, без копирования, и прекращать сравнение на **первом несовпадении**. На случайных строках несовпадение обычно находится на первом-втором символе, поэтому каждая позиция стоит почти `O(1)`.

А стартовые позиции достаточно перебирать, пока `start + m <= n` — дальше `needle` не поместится.

Именно так устроено решение: «наивный» поиск подстроки, но без лишней работы. Асимптотически быстрее — алгоритм KMP (см. ниже), однако при ограничениях задачи (длины до `10⁴`) простого варианта хватает.

## Техники

### Перебор позиций с ранним выходом (brute-force pattern matching)

**Что это.** Классический поиск подстроки: «прикладываем» шаблон к тексту в каждой допустимой позиции и сравниваем символ за символом, пока они совпадают. Внутренний цикл обрывается на первом расхождении.

**Типичный шаблон:**

```ts naive
for (let start = 0; start + m <= n; start++) {
  let j = 0;
  while (j < m && text[start + j] === pattern[j]) j++;
  if (j === m) return start;
}
```

Подходит, когда строки короткие или нужно простое и надёжное решение. Это также окно фиксированной ширины `m`, которое скользит по тексту на один символ.

**Как применяется здесь.** Ровно этот шаблон; ответ — первая позиция, где `j` дошёл до `m`. Подробнее о приёмах для строк — во вкладке «Теория».

### KMP — как избежать повторных сравнений (кратко)

В худшем случае простой перебор делает `O(n · m)` сравнений: например, `haystack = "aaaa…ab"`, `needle = "aa…ab"` — на каждой позиции совпадают почти все символы, а затем откат. Алгоритм Кнута–Морриса–Пратта заранее считает для `needle` префикс-функцию и при несовпадении **не возвращает** указатель в тексте назад — итого `O(n + m)`. В этой задаче он не обязателен, но хорошо знать, что он существует.

## Разбор кода

```ts
function strStr(haystack: string, needle: string): number {
  const n = haystack.length;
  const m = needle.length;
```

Сохраняем длины в короткие переменные — так условия цикла читаются как формулы из разбора.

```ts
  // Перебираем все стартовые позиции, где needle ещё помещается целиком
  for (let start = 0; start + m <= n; start++) {
    let j = 0;
```

Перебираем стартовые позиции. Условие `start + m <= n` означает, что отрезок `haystack[start..start+m-1]` целиком внутри строки; последняя проверяемая позиция — `n - m`. Если `needle` длиннее `haystack`, цикл не выполнится ни разу. `j` — сколько символов `needle` уже совпало в этой позиции.

```ts
    // Сравниваем посимвольно, пока символы совпадают
    while (j < m && haystack[start + j] === needle[j]) {
      j++;
    }
```

Сдвигаем `j`, пока символы совпадают. Цикл заканчивается либо при `j === m` (совпали все символы), либо на первом несовпадении. Порядок условий важен: сначала `j < m`, чтобы не сравнивать за концом `needle`. Выход за `haystack` невозможен: `start + j <= start + m - 1 <= n - 1`.

```ts
    // Дошли до конца needle — вхождение найдено
    if (j === m) {
      return start;
    }
  }
```

Если `j` дошёл до `m`, все символы совпали — это вхождение. Так как стартовые позиции перебираются по возрастанию, первое найденное вхождение и есть **первое** — сразу возвращаем.

```ts
  // Ни одна позиция не подошла
  return -1;
}

// Время: O((n - m + 1) · m) в худшем случае, на практике обычно близко к O(n)
// Память: O(1)
```

Перебрали все допустимые позиции, совпадения нет — `-1`.

## Трассировка

`haystack = "abcabd"`, `needle = "abd"`, `n = 6`, `m = 3`; допустимые `start` — от `0` до `3`:

```
start=0: a=a (j=1), b=b (j=2), c≠d → стоп, j=2 ≠ 3
start=1: b≠a → стоп, j=0
start=2: c≠a → стоп, j=0
start=3: a=a (j=1), b=b (j=2), d=d (j=3) → j=3 = m → return 3
```

Ответ `3`. На позициях `1` и `2` сравнение заняло один шаг — так обычно и бывает.

Нет вхождения, `haystack = "leetcode"`, `needle = "leeto"`, `n = 8`, `m = 5`; `start` от `0` до `3`:

```
start=0: l,e,e,t совпали (j=4), c≠o → стоп
start=1: e≠l → стоп
start=2: e≠l → стоп
start=3: t≠l → стоп
start=4: 4+5=9 > 8 → цикл окончен → return -1
```

## Почему это работает

Вхождение `needle` с позиции `start` — это ровно равенство `haystack[start + j] === needle[j]` для всех `j` от `0` до `m - 1`. Внутренний цикл доходит до `j === m` тогда и только тогда, когда все эти равенства выполнены: он останавливается на первом нарушенном. Внешний цикл проверяет **все** позиции, где вхождение в принципе возможно (`0..n-m`), по возрастанию, поэтому первая успешная позиция — наименьший индекс вхождения. Если ни одна не подошла, вхождений нет.

## Пограничные случаи

- **`needle` длиннее `haystack`**: `0 + m > n`, цикл не выполняется, ответ `-1`.
- **Строки равны**: одна позиция `start = 0`, совпадают все символы, ответ `0`.
- **Вхождение в самом конце** (`"hello"`, `"lo"`): последняя допустимая позиция `n - m = 3` проверяется, ответ `3`.
- **Несколько вхождений** (`"sadbutsad"`): возвращается первое, `0`.
- **Пустая `needle`** (по условию длины от 1): код вернул бы `0` — так же, как `indexOf`.

## Сложность

- **Время `O((n − m + 1) · m)`** в худшем случае: до `n − m + 1` стартовых позиций, на каждой до `m` сравнений. Худший случай — длинные совпадающие начала, как `"aaaa…ab"` и `"aa…ab"`. На обычных данных внутренний цикл обрывается почти сразу, и работа близка к `O(n)`.
- **Память `O(1)`**: несколько индексов, подстроки не создаются.

## Типичные ошибки

1. **Условие `start < n - m`** вместо `start + m <= n` (то есть `start <= n - m`) → пропускается вхождение в самом конце.
2. **Перебирать `start` до `n`** без учёта длины `needle` → лишние позиции и сравнения с `undefined`.
3. **Не сбрасывать `j`** на каждой новой позиции → сравнение продолжается с середины `needle`.
4. **Сдвигать `start` на `j` после частичного совпадения** («пропустить уже сравненное») → можно перепрыгнуть вхождение: для `"aaab"` и `"aab"` пропустится позиция `1`. Корректно так делает только KMP.
5. **`slice` на каждой позиции** → копирование `m` символов даже при несовпадении первого.

## Как узнать такую задачу

- «Найти подстроку / шаблон в тексте», «первое вхождение» — посимвольный перебор позиций; при больших длинах или многих запросах — KMP, Z-функция или Rabin–Karp (хеширование).
- Окно фиксированной ширины, которое сравнивается с эталоном, — тот же перебор, а при сравнении «по составу» — скользящее окно с частотами.
- Похожие задачи: Repeated Substring Pattern, Shortest Palindrome (KMP), Find All Anagrams in a String, Repeated String Match.
