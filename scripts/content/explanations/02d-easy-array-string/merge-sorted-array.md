## Задача простыми словами

Даны два массива, отсортированных по неубыванию: `nums1` с `m` полезными элементами и `nums2` с `n` элементами. Длина `nums1` равна `m + n`: в его хвосте лежат `n` нулей-заглушек. Нужно слить оба массива в один отсортированный **прямо внутри `nums1`** — функция ничего не возвращает.

Пример: `nums1 = [1, 2, 3, 0, 0, 0]`, `m = 3`, `nums2 = [2, 5, 6]`, `n = 3`. После вызова `nums1 = [1, 2, 2, 3, 5, 6]`.

## Наивный подход

Самое короткое решение — скопировать `nums2` в свободный хвост и отсортировать:

```ts naive
for (let j = 0; j < n; j++) nums1[m + j] = nums2[j];
nums1.sort((a, b) => a - b);
```

Это `O((m + n) log(m + n))`. Лишняя работа в том, что сортировка **не знает**, что обе половины уже упорядочены, и заново выясняет порядок, который нам дан бесплатно.

Второй очевидный вариант — классическое слияние из merge sort **с начала**: два указателя на начала массивов, меньший элемент пишем в результат. Но писать результат с начала `nums1` нельзя: первая же запись `nums2[0]` затрёт ещё не прочитанный `nums1[0]`. Приходится заводить копию `nums1` — это `O(m)` дополнительной памяти.

## Ключевое наблюдение

Свободное место в `nums1` находится **в конце**. Значит, и заполнять результат надо с конца: на позицию `m + n - 1` встаёт **наибольший** элемент из двух массивов, на позицию перед ней — следующий по величине, и так далее.

При записи с конца позиция записи `write` всегда правее непрочитанной части `nums1`, поэтому мы ничего полезного не затираем. Слияние получается за один проход и без дополнительной памяти.

## Техники

### Два указателя по двум массивам

**Что это.** По каждому из двух упорядоченных массивов движется свой указатель; на каждом шаге сравниваем элементы под указателями, берём «победителя» и сдвигаем только его указатель. Так работает шаг слияния в merge sort.

**Типичный шаблон.** Сливать отсортированные последовательности, искать пересечение или объединение двух отсортированных массивов, сравнивать два списка «в ногу». Каждый указатель только движется в одну сторону, поэтому суммарно шагов не больше `m + n`.

**Как применяется здесь.** Указатели `i` и `j` стоят на **последних** элементах `nums1` и `nums2`, и на каждом шаге выбирается **больший** из них. Подробнее о вариантах двух указателей — во вкладке «Теория».

### Заполнение с конца (запись в буфер на месте)

Если результат пишется в тот же массив, откуда ещё читаются данные, важно, чтобы запись не обгоняла чтение. Когда свободное место в конце, приём простой — третий указатель `write` идёт с конца навстречу данным. Тот же трюк встречается в задачах «заменить пробелы на `%20` на месте» и «квадраты отсортированного массива».

## Разбор кода

```ts
/**
 Do not return anything, modify nums1 in-place instead.
 */
function merge(nums1: number[], m: number, nums2: number[], n: number): void {
  // Три указателя: конец полезной части nums1, конец nums2 и позиция записи
  let i = m - 1;
  let j = n - 1;
  let write = m + n - 1;
```

Сигнатура из LeetCode: результат возвращается через изменение `nums1`. Три указателя:

- `i` — последний ещё не обработанный элемент полезной части `nums1` (если `m = 0`, сразу `-1`);
- `j` — последний не обработанный элемент `nums2`;
- `write` — ячейка, куда положим следующий по величине элемент; начинаем с самого конца `nums1`.

```ts
  // Идём с конца: самый большой элемент сразу встаёт на своё место,
  // поэтому мы никогда не затираем ещё не обработанные элементы nums1
  while (j >= 0) {
```

Условие цикла — «пока в `nums2` что-то осталось». Почему не `i >= 0 || j >= 0`? Если `nums2` закончился, оставшиеся элементы `nums1[0..i]` уже стоят на своих местах (они самые маленькие и уже отсортированы), переносить их некуда и незачем.

```ts
    if (i >= 0 && nums1[i] > nums2[j]) {
      // Элемент из nums1 больше — переносим его в конец
      nums1[write] = nums1[i];
      i--;
```

Если в `nums1` ещё есть элементы и его текущий элемент больше — он и есть наибольший из оставшихся. Переносим его в `write` и сдвигаем `i` влево. Проверка `i >= 0` стоит **первой**: когда `nums1` исчерпан, `nums1[-1]` даст `undefined`, и сравнение пройдёт неверно — короткое замыкание `&&` этого не допускает.

```ts
    } else {
      // Иначе берём элемент из nums2 (при равенстве тоже из nums2 — порядок не важен)
      nums1[write] = nums2[j];
      j--;
    }
    write--;
  }
```

Во всех остальных случаях (элементы `nums1` кончились, или `nums2[j]` не меньше) пишем элемент из `nums2`. При равенстве всё равно, какой брать: значения одинаковые. После любой записи позиция `write` сдвигается влево.

```ts
  // Если в nums1 остались элементы — они уже на своих местах, ничего делать не нужно
}

// Время: O(m + n) — каждый элемент рассматривается один раз
// Память: O(1) — сливаем прямо в nums1
```

После цикла ничего делать не нужно: если остался префикс `nums1[0..i]`, то `write === i` и все эти элементы уже стоят там, где должны.

## Трассировка

`nums1 = [1, 2, 3, 0, 0, 0]`, `m = 3`, `nums2 = [2, 5, 6]`, `n = 3`. Старт: `i = 2`, `j = 2`, `write = 5`.

1. `nums1[2] = 3 > nums2[2] = 6`? Нет → `nums1[5] = 6`, `j = 1`, `write = 4`. `nums1 = [1, 2, 3, 0, 0, 6]`.
2. `3 > nums2[1] = 5`? Нет → `nums1[4] = 5`, `j = 0`, `write = 3`. `nums1 = [1, 2, 3, 0, 5, 6]`.
3. `3 > nums2[0] = 2`? Да → `nums1[3] = 3`, `i = 1`, `write = 2`. `nums1 = [1, 2, 3, 3, 5, 6]`.
4. `nums1[1] = 2 > 2`? Нет (равенство) → `nums1[2] = 2`, `j = -1`, `write = 1`. `nums1 = [1, 2, 2, 3, 5, 6]`.
5. `j = -1` — цикл окончен. Элементы `nums1[0..1] = [1, 2]` уже на местах.

Ответ `[1, 2, 2, 3, 5, 6]`.

Пример, где `nums1` заканчивается раньше: `nums1 = [4, 5, 6, 0, 0]`, `m = 3`, `nums2 = [1, 2]`.

```
i=2 j=1 w=4: 6>2 → nums1[4]=6, i=1   [4,5,6,0,6]
i=1 j=1 w=3: 5>2 → nums1[3]=5, i=0   [4,5,6,5,6]
i=0 j=1 w=2: 4>2 → nums1[2]=4, i=-1  [4,5,4,5,6]
i=-1 j=1 w=1: i<0 → nums1[1]=2, j=0  [4,2,4,5,6]
i=-1 j=0 w=0: i<0 → nums1[0]=1, j=-1 [1,2,4,5,6]
```

Промежуточные «мусорные» значения вроде `[4, 5, 4, 5, 6]` безопасны: они лежат в уже прочитанных ячейках и затем перезаписываются.

## Почему это работает

**Ничего не затирается.** До шага осталось обработать `i + 1` элементов `nums1` и `j + 1` элементов `nums2`, а свободных ячеек справа от них ровно столько, сколько уже записано. Отсюда инвариант `write = i + j + 1`. Пока цикл идёт, `j >= 0`, значит `write >= i + 1 > i`: запись всегда правее последнего непрочитанного элемента `nums1`.

**Порядок верный.** Оба массива отсортированы, поэтому наибольший из **оставшихся** элементов — это `max(nums1[i], nums2[j])`. Мы кладём его в самую правую свободную ячейку, и справа от `write` всегда стоят наибольшие элементы в правильном порядке.

**Остаток на месте.** Когда `j` стал `-1`, по инварианту `write = i`, и в ячейках `0..i` лежат ровно оставшиеся элементы `nums1` — отсортированные и меньшие всего, что правее.

## Пограничные случаи

- **`n = 0`**: `j = -1`, цикл не выполняется, `nums1` не меняется.
- **`m = 0`**: `i = -1`, условие `i >= 0` всегда ложно, весь `nums2` копируется в `nums1`.
- **Все элементы `nums2` больше**: каждый шаг берёт из `nums2`, `nums1` не трогается.
- **Все элементы `nums2` меньше**: сначала переносятся все элементы `nums1` вправо, затем `nums2` заполняет начало.
- **Равные элементы и отрицательные числа**: сравнение `>` корректно для любых чисел, при равенстве берём из `nums2`.

## Сложность

- **Время `O(m + n)`**: каждая итерация записывает ровно один элемент и сдвигает `write`; итераций не больше `m + n`.
- **Память `O(1)`**: три целочисленных указателя, слияние идёт прямо в `nums1`.

## Типичные ошибки

1. **Сливать с начала** без копии `nums1` → затираются ещё не прочитанные элементы.
2. **Проверять `nums1[i] > nums2[j]` без `i >= 0`** → при `i = -1` сравнивается `undefined`, и логика ломается (особенно при `m = 0`).
3. **Цикл `while (i >= 0)`** вместо `while (j >= 0)` → оставшиеся элементы `nums2` не переносятся.
4. **Добавлять отдельный цикл для остатка `nums1`** — не ошибка, но лишний код: эти элементы уже на месте.
5. **Начинать `write` с `m + n`** → запись за пределы массива и сдвиг всего результата.

## Как узнать такую задачу

- Даны **два отсортированных** набора, и нужно их объединить, пересечь или сравнить — два указателя «в ногу», как в merge sort.
- Нужно писать результат **на месте**, а свободное место есть **в конце** массива — заполняйте с конца, от наибольших элементов.
- Похожие задачи: Merge Two Sorted Lists, Squares of a Sorted Array, Intersection of Two Arrays II, шаг слияния в Sort an Array.
