## Задача простыми словами

Нужно реализовать класс-итератор по **двоичному дереву поиска** (BST), который выдаёт значения в порядке **in-order** — то есть по возрастанию. Методы:

- `constructor(root)` — получает корень дерева;
- `next()` — возвращает следующее по величине значение;
- `hasNext()` — есть ли ещё значения.

Дополнительно: `next()` и `hasNext()` должны работать в среднем за `O(1)`, а память — `O(h)`, где `h` — высота дерева.

Пример: дерево `[7, 3, 15, null, null, 9, 20]`.

```
      7
     / \
    3   15
       /  \
      9    20
```

Вызовы `next()` по очереди дают `3, 7, 9, 15, 20`, после чего `hasNext()` возвращает `false`.

## Наивный подход

Сразу в конструкторе обойти дерево in-order, сложить значения в массив и дальше двигать по нему индекс:

```ts naive
class BSTIterator {
  private values: number[] = [];
  private i = 0;
  constructor(root: TreeNode | null) {
    const walk = (n: TreeNode | null) => {
      if (!n) return;
      walk(n.left);
      this.values.push(n.val);
      walk(n.right);
    };
    walk(root);
  }
  next(): number { return this.values[this.i++]; }
  hasNext(): boolean { return this.i < this.values.length; }
}
```

`next` и `hasNext` — `O(1)`, но память `O(n)`: все значения хранятся заранее, даже если пользователь вызовет `next()` всего пару раз. Кроме того, конструктор сразу тратит `O(n)` времени. Лишнее здесь — мы **материализуем весь обход**, хотя в каждый момент нужен только следующий элемент.

## Ключевое наблюдение

Итеративный in-order обход со стеком в любой момент хранит не больше одного пути от корня вниз — `O(h)` узлов. Сам обход — это цикл:

```ts naive
pushLeft(root);              // спуститься влево до упора, складывая узлы
while (stack.length) {
  const node = stack.pop()!; // посетить node
  pushLeft(node.right);      // затем — правое поддерево, снова влево до упора
}
```

Если **разрезать этот цикл на итерации** и выполнять по одной на каждый вызов `next()`, получим «обход на паузе»: состояние — только стек. Вершина стека всегда — наименьший ещё не выданный узел.

## Техники

### Итеративный in-order обход со стеком

**Что это.** Рекурсивный in-order «левое → узел → правое» можно переписать на явный стек: стек хранит узлы, у которых левое поддерево ещё обрабатывается, а сами они ещё не посещены. Спуск влево до упора кладёт в стек цепочку «отложенных» узлов; снятие узла означает «его левое поддерево готово — посещаем узел и переходим к правому».

**Когда применять.** Когда нужен обход без рекурсии (глубокие деревья), когда обход нужно **прерывать и продолжать** (итераторы, k-й наименьший, сравнение двух деревьев «в ногу»).

**Как применяется здесь.** Каждый вызов `next()` — один шаг цикла обхода.

### Свойство BST: in-order = сортировка

В BST все значения левого поддерева меньше узла, правого — больше. Поэтому in-order выдаёт значения строго по возрастанию, и «следующее по величине» — это просто «следующее в in-order». Подробнее — во вкладке «Теория» (двоичное дерево поиска).

### Амортизированный анализ

Отдельная операция может быть дорогой (спуск на `h` уровней), но если каждый узел за всю жизнь объекта кладётся в стек и снимается **ровно один раз**, суммарная работа за `n` вызовов — `O(n)`, то есть `O(1)` в среднем на вызов.

### Шаблон проектирования «итератор»

Класс скрывает структуру данных и даёт только `next`/`hasNext`. Внутреннее состояние (здесь — стек) должно позволять продолжить ровно с того места, где остановились.

## Разбор кода

```ts
class BSTIterator {
  // Стек «отложенных» узлов: путь влево от текущей позиции.
  // На вершине всегда лежит следующий по порядку (наименьший непосещённый) узел
  private stack: TreeNode[] = [];
```

Единственное поле — стек. Инвариант: на вершине лежит следующий узел для `next()`; под ним — его предки, к которым мы вернёмся после того, как пройдём их левые поддеревья.

```ts
  constructor(root: TreeNode | null) {
    this.pushLeft(root);
  }
```

Конструктор только спускается от корня влево до упора. На вершине оказывается самый левый узел — минимум BST. Работа `O(h)`, а не `O(n)`.

```ts
  next(): number {
    // Вершина стека — следующий элемент in-order обхода
    const node = this.stack.pop()!;
```

Снимаем вершину — это ответ. `!` — по условию `next()` вызывается только когда элемент есть, поэтому стек не пуст.

```ts
    // После узла в in-order идёт его правое поддерево, начиная с самого левого узла
    this.pushLeft(node.right);
    return node.val;
  }
```

Перед тем как вернуть значение, готовим стек к следующему вызову. В in-order после `node` идёт его правое поддерево, а в нём первым — самый левый узел. `pushLeft(node.right)` кладёт этот путь в стек. Если правого поддерева нет, ничего не кладём: следующим будет предок, уже лежащий в стеке.

```ts
  hasNext(): boolean {
    return this.stack.length > 0;
  }
```

Пустой стек означает, что непосещённых узлов не осталось: все отложенные предки выданы, и новых правых поддеревьев нет.

```ts
  // Спускаемся влево до упора, складывая узлы в стек
  private pushLeft(node: TreeNode | null): void {
    while (node !== null) {
      this.stack.push(node);
      node = node.left;
    }
  }
}
```

Вспомогательный метод: кладёт в стек `node`, его левого ребёнка, левого ребёнка того и так далее. Последним (на вершину) попадает самый маленький узел поддерева. Параметр `node` — локальная переменная, его перезапись не трогает дерево.

## Трассировка

Дерево `[7, 3, 15, null, null, 9, 20]`. Стек записан снизу вверх (справа — вершина):

```
constructor: pushLeft(7) -> кладём 7, 3          stack = [7, 3]
next():      pop 3; pushLeft(3.right = null)     stack = [7]        -> 3
next():      pop 7; pushLeft(15) -> 15, 9        stack = [15, 9]    -> 7
hasNext():   длина 2                                                -> true
next():      pop 9; pushLeft(null)               stack = [15]       -> 9
hasNext():   длина 1                                                -> true
next():      pop 15; pushLeft(20) -> 20          stack = [20]       -> 15
hasNext():   длина 1                                                -> true
next():      pop 20; pushLeft(null)              stack = []         -> 20
hasNext():   длина 0                                                -> false
```

Выход совпадает с ожидаемым: `3, 7, true, 9, true, 15, true, 20, false`. В стеке ни разу не было больше двух узлов — высота дерева `3`.

## Почему это работает

Инвариант: **стек содержит ровно те узлы, которые ещё не выданы и для которых всё их левое поддерево уже выдано (или пусто), упорядоченные так, что вершина — наименьший; все прочие невыданные узлы лежат в правых поддеревьях узлов стека.**

- После конструктора: в стеке левая цепочка от корня; все остальные узлы — в правых поддеревьях этих узлов. Вершина — минимум.
- `next()` снимает вершину `node` — наименьший невыданный узел. Следующий по величине — либо минимум правого поддерева `node` (если оно есть), либо ближайший предок в стеке. `pushLeft(node.right)` кладёт минимум правого поддерева поверх предков — и все его узлы меньше этих предков (правое поддерево `node` лежит в левом поддереве предка). Инвариант сохраняется.

Стек пуст ⇔ невыданных узлов нет — значит, `hasNext` корректен.

## Пограничные случаи

- **Один узел**: конструктор кладёт его, первый `next()` возвращает его, затем `hasNext()` — `false`.
- **Только левые дети** (палка вниз-влево): конструктор кладёт все `n` узлов, каждый `next()` — просто `pop`. Память `O(h) = O(n)` — это и есть высота.
- **Только правые дети**: в стеке всегда один узел; каждый `next()` кладёт следующего.
- **`root = null`**: по условию узлов минимум один, но код корректен — стек пуст, `hasNext()` вернёт `false`.

## Сложность

- **`next()` — `O(1)` амортизированно**: за всё время жизни итератора каждый узел ровно один раз кладётся (`pushLeft`) и один раз снимается (`pop`). `n` вызовов делают `O(n)` работы. Худший одиночный вызов — `O(h)`.
- **`hasNext()` — `O(1)`**: проверка длины.
- **Конструктор — `O(h)`**.
- **Память `O(h)`**: в стеке одновременно лежит только часть одного пути от корня (левые цепочки вдоль пути к текущему узлу).

## Типичные ошибки

1. **Полный обход в конструкторе** → память `O(n)`, требование follow-up не выполнено.
2. **Класть в стек и левого, и правого ребёнка** (как в pre-order) → порядок перестаёт быть возрастающим.
3. **`pushLeft(node.left)` вместо `node.right`** в `next()` → левые поддеревья уже в стеке, узлы выдаются повторно, а правые поддеревья теряются.
4. **`hasNext` через `node.right !== null` или подобные проверки** → забывают предков в стеке; правильный критерий — непустой стек.
5. **Считать, что `next()` всегда `O(1)`** → в худшем случае один вызов спускается на `h`; `O(1)` — только в среднем.

## Как узнать такую задачу

- Нужно выдавать элементы дерева **по одному**, «лениво», с ограничением памяти `O(h)` → итеративный обход со стеком, «поставленный на паузу».
- BST + «по возрастанию», «k-й наименьший», «следующий больший» → in-order.
- Требование «в среднем `O(1)`» → ищите амортизированное рассуждение «каждый элемент один раз входит и выходит».
- Родственные задачи: Kth Smallest Element in a BST, Binary Tree Inorder Traversal, Two Sum IV (два итератора навстречу), Flatten Nested List Iterator, Peeking Iterator.
