## Задача простыми словами

Даны два обхода одного двоичного дерева: **центрированный** `inorder` (левое → узел → правое) и **обратный** `postorder` (левое → правое → узел). Все значения различны. Нужно восстановить дерево и вернуть его корень.

Пример: `inorder = [9, 3, 15, 20, 7]`, `postorder = [9, 15, 7, 20, 3]`. Ответ:

```
    3
   / \
  9   20
     /  \
    15   7
```

## Наивный подход

Последний элемент `postorder` — корень. Находим его в `inorder` линейным поиском, режем оба массива `slice`-ами и рекурсивно строим поддеревья:

```ts naive
function build(ino: number[], post: number[]): TreeNode | null {
  if (post.length === 0) return null;
  const rootVal = post[post.length - 1];
  const root = new TreeNode(rootVal);
  const mid = ino.indexOf(rootVal);
  root.left = build(ino.slice(0, mid), post.slice(0, mid));
  root.right = build(ino.slice(mid + 1), post.slice(mid, post.length - 1));
  return root;
}
```

Работает, но каждый уровень рекурсии тратит `O(k)` на `indexOf` и ещё `O(k)` на копирование подмассивов. На вырожденном дереве (все узлы в одну линию) это `O(n²)` по времени и по выделенной памяти. Мы раз за разом ищем значения, позиции которых не меняются, и копируем числа, которые можно было бы просто адресовать индексами.

## Ключевое наблюдение

1. Значения различны → позиции в `inorder` один раз кладём в `Map` и находим корень за `O(1)`.
2. Если читать `postorder` **справа налево**, порядок становится «корень, правое, левое». Значит, если рекурсия строит **сначала корень, потом правое, потом левое**, корни понадобятся ровно в порядке чтения `postorder` с конца. Тогда хватит одного общего указателя `post`, идущего от конца к началу, и границ `[lo, hi]` в `inorder` — никаких копий.

## Техники

### Разделяй и властвуй

**Что это.** Делим задачу на независимые подзадачи меньшего размера, решаем рекурсивно, объединяем. Шаблон — рекурсия по отрезку `[lo, hi]` с базой «пустой отрезок».

**Когда применять.** Когда объект ответа рекурсивен по природе, и можно определить точку разреза. Дерево — это корень и два поддерева, а корень в `inorder` и есть точка разреза.

**Как применяется здесь.** Корень делит `inorder[lo..hi]` на левое `[lo, mid - 1]` и правое `[mid + 1, hi]`; каждое — та же задача. Объединение — присвоить детей. Подробнее — во вкладке «Теория» (разделяй и властвуй).

### Свойства обходов

```
postorder:          [ ...левое... | ...правое... | корень ]
postorder с конца:  [ корень | ...правое... | ...левое... ]
inorder:            [ ...левое... | корень | ...правое... ]
```

`postorder` с конца выдаёт корни, `inorder` разделяет узлы на стороны.

### Хеш-таблица для позиций и общий указатель

`Map` «значение → индекс» даёт поиск за `O(1)`. Указатель `post` в замыкании продвигается сквозь всю рекурсию — работает, только если порядок рекурсивных вызовов совпадает с порядком чтения массива.

## Разбор кода

```ts
function buildTree(inorder: number[], postorder: number[]): TreeNode | null {
  // Значение -> его индекс в inorder
  const inIndex = new Map<number, number>();
  inorder.forEach((v, i) => inIndex.set(v, i));
```

Предварительный проход: для каждого значения запоминаем его позицию в `inorder`. Ключи уникальны, потому что уникальны значения.

```ts
  // Идём по postorder с конца: там порядок «корень, правое, левое»
  let post = postorder.length - 1;
```

`post` — индекс следующего неиспользованного элемента `postorder`, если идти справа налево. Стартует с последнего элемента — корня всего дерева.

```ts
  // Строит поддерево из элементов inorder[lo..hi]
  const build = (lo: number, hi: number): TreeNode | null => {
    if (lo > hi) return null;
```

`build(lo, hi)` строит поддерево из узлов `inorder[lo..hi]`. Пустой отрезок — пустое поддерево; `post` при этом не трогаем.

```ts
    // Последний ещё не использованный элемент postorder — корень поддерева
    const rootVal = postorder[post--];
    const root = new TreeNode(rootVal);
    const mid = inIndex.get(rootVal)!;
```

Берём корень и сдвигаем указатель влево. Позиция корня в `inorder` — за `O(1)`; `!` сообщает TypeScript, что значение в `Map` есть.

```ts
    // Важно: сначала ПРАВОЕ поддерево — с конца postorder идут его узлы
    root.right = build(mid + 1, hi);
    root.left = build(lo, mid - 1);
    return root;
  };
```

Сердце решения. Сразу левее корня в `postorder` лежат узлы **правого** поддерева (их ровно `hi - mid`), а ещё левее — левого. Поэтому правый вызов идёт первым: он потребит свои элементы, и к началу левого вызова `post` будет указывать на корень левого поддерева.

```ts
  return build(0, inorder.length - 1);
}
```

Строим дерево на всём отрезке и возвращаем корень.

## Трассировка

`inorder = [9, 3, 15, 20, 7]`, `postorder = [9, 15, 7, 20, 3]`.
`inIndex = {9: 0, 3: 1, 15: 2, 20: 3, 7: 4}`, `post = 4`.

1. `build(0, 4)`: `rootVal = postorder[4] = 3`, `post = 3`, `mid = 1`.
2. → правое `build(2, 4)`: `rootVal = postorder[3] = 20`, `post = 2`, `mid = 3`.
3. → правое `build(4, 4)`: `rootVal = postorder[2] = 7`, `post = 1`, `mid = 4`; `build(5, 4)` и `build(4, 3)` → `null`.
4. → левое `build(2, 2)`: `rootVal = postorder[1] = 15`, `post = 0`, `mid = 2`; дети `null`.
5. Узел `20`: `right = 7`, `left = 15`.
6. → левое для `3`: `build(0, 0)`: `rootVal = postorder[0] = 9`, `post = -1`; дети `null`.
7. Узел `3`: `right = 20`, `left = 9`.

`post` прошёл массив от `4` до `-1` — каждый элемент использован ровно один раз.

Что было бы при неправильном порядке (сначала левое): на шаге 2 вызов `build(0, 0)` взял бы `postorder[3] = 20` как корень отрезка `[9]` — дерево сломалось бы сразу.

## Почему это работает

Инвариант: **при вызове `build(lo, hi)` с непустым отрезком `postorder[post]` — корень поддерева из узлов `inorder[lo..hi]`**, а само поддерево занимает в `postorder` ровно `hi - lo + 1` позиций, заканчивающихся на `post`.

- Для всего дерева это верно: последний элемент postorder — корень.
- Пусть верно для `build(lo, hi)`. После взятия корня `post` указывает на последний элемент правого поддерева, т.е. на его корень (postorder заканчивает поддерево корнем). Узлов правого поддерева ровно `hi - mid` — это отрезок `[mid + 1, hi]`. По индукции правый вызов потребит ровно их, и `post` окажется на корне левого поддерева — инвариант выполнен и для `build(lo, mid - 1)`.

Различие значений гарантирует, что `mid` определён однозначно.

## Пограничные случаи

- **Один узел**: `build(0, 0)` создаёт корень, оба дочерних отрезка пусты.
- **Дерево-«палка» влево**: каждый раз `mid = hi`, правый отрезок пуст; глубина рекурсии `n`.
- **Дерево-«палка» вправо**: каждый раз `mid = lo`, левый отрезок пуст.
- **Пустой отрезок** не сдвигает `post` — иначе нарушится синхронизация.
- **Отрицательные значения** — обычные ключи `Map`.

## Сложность

- **Время `O(n)`**: `Map` строится за `O(n)`; каждый непустой вызов создаёт один узел за `O(1)`, пустых вызовов не больше `n + 1`.
- **Память `O(n)`**: `Map` на `n` записей плюс стек рекурсии `O(h)` (до `n` на вырожденном дереве).

## Типичные ошибки

1. **Сначала левое поддерево** (по привычке из задачи с preorder) → корни берутся не те, дерево неверное.
2. **Читать `postorder` с начала** → первым окажется лист, а не корень.
3. **`indexOf` вместо `Map`** → `O(n²)` на вырожденных деревьях.
4. **Сдвигать `post` до проверки `lo > hi`** → пустой отрезок теряет чужой корень.
5. **Включать `mid` в один из дочерних отрезков** → корень попадает в дерево дважды или бесконечная рекурсия.

## Как узнать такую задачу

- Даны **два обхода**, один из которых `inorder` → корень из второго обхода делит `inorder` на стороны.
- Корень стоит **в конце** обхода → читаем с конца и строим в зеркальном порядке «корень, правое, левое».
- Родственные задачи: Construct Binary Tree from Preorder and Inorder Traversal (тот же приём, указатель идёт с начала и сначала строится левое), Construct Binary Tree from Preorder and Postorder Traversal, Serialize and Deserialize Binary Tree.
