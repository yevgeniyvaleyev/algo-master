## Задача простыми словами

Путь в дереве — цепочка узлов, соединённых рёбрами, без повторов; он может начинаться и заканчиваться где угодно и не обязан проходить через корень. Нужно найти **максимальную сумму значений** среди всех **непустых** путей. Значения бывают отрицательными.

Пример: `root = [-10, 9, 20, null, null, 15, 7]`.

```
     -10
     /  \
    9    20
        /  \
       15   7
```

Лучший путь — `15 → 20 → 7`, сумма `42`. Корень `-10` в него не входит: он только уменьшил бы сумму.

## Наивный подход

Любой путь имеет **самый верхний узел** — «вершину», где путь перегибается. Можно для каждого узла как вершины отдельно посчитать лучший луч вниз влево и вниз вправо:

```ts naive
const down = (node: TreeNode | null): number =>
  node === null ? 0 : node.val + Math.max(0, down(node.left), down(node.right));

let best = -Infinity;
const visit = (node: TreeNode | null) => {
  if (!node) return;
  best = Math.max(best, node.val + Math.max(0, down(node.left)) + Math.max(0, down(node.right)));
  visit(node.left);
  visit(node.right);
};
```

Это верно, но `down` для каждой вершины заново обходит всё её поддерево. Узел на глубине `d` пересчитывается `d` раз — на вырожденном дереве это `O(n²)` (при `n = 3·10⁴` — сотни миллионов операций). Лишняя работа: **лучший луч из поддерева вычисляется многократно**, хотя его можно получить один раз и переиспользовать для родителя.

## Ключевое наблюдение

Один post-order обход может делать две вещи одновременно:

1. **вернуть родителю** лучший «луч» из узла — путь, который начинается в узле и идёт вниз **только в одну сторону** (только такой путь родитель может продолжить);
2. **обновить глобальный ответ** путём с вершиной в этом узле: `левый луч + node.val + правый луч`.

Лучи детей уже посчитаны к моменту обработки узла, поэтому всё делается за `O(1)` на узел. Отрицательные лучи отбрасываем — брать их невыгодно.

## Техники

### Post-order DFS: «вернуть одно, посчитать другое»

**Что это.** Рекурсивная функция возвращает родителю величину, которую тот может **продолжить**, а настоящий ответ задачи собирается в отдельной переменной по ходу обхода. Это нужно, когда оптимальная структура (здесь — путь с перегибом) не может быть продолжена вверх, но строится из того, что можно продолжить (лучи).

**Типичный шаблон:**

```ts naive
let best = НАЧАЛЬНОЕ;
const f = (node) => {
  if (!node) return 0;
  const l = f(node.left), r = f(node.right);
  best = лучшее(best, объединить(l, node, r));   // ответ с вершиной в node
  return продолжаемое(l, node, r);              // то, что можно отдать наверх
};
```

**Как применяется здесь.** `f` — это `gain`: возвращает лучший луч, а `best` обновляется «перегибом» в узле. Так же решаются диаметр дерева и Longest Univalue Path. Подробнее — во вкладке «Теория» (DFS по дереву).

### Отбрасывание невыгодного (как в алгоритме Кадане)

`Math.max(gain(child), 0)` — «если продолжение вниз даёт минус, не продолжаем». Это та же логика, что в максимальной сумме подмассива: отрицательный префикс выгоднее отбросить.

### Сентинел `-Infinity` для максимума

Начальное значение `best = -Infinity` гарантирует, что первый же реальный путь его обновит — даже если все значения отрицательны.

```

  // и идёт вниз только в одно поддерево

    if (node === null) return 0;
```

`gain(node)` — лучший луч из `node` вниз. Пустое поддерево даёт `0`: «ничего не брать». Это безопасно, потому что ниже мы всё равно сравниваем лучи с нулём.

```ts
    // Отрицательный луч только уменьшает сумму — тогда лучше его не брать (0)
    const left = Math.max(gain(node.left), 0);
    const right = Math.max(gain(node.right), 0);
```

Сначала рекурсивно обрабатываем детей (post-order). Если лучший луч ребёнка отрицателен, заменяем его на `0` — путь просто не пойдёт в эту сторону.

```ts
    // Путь, «перегибающийся» в node: левый луч + node + правый луч
    best = Math.max(best, node.val + left + right);
```

Кандидат с вершиной в `node`. Он покрывает и случаи «только узел» (оба луча `0`), и «узел + одна сторона». `node.val` берём всегда — даже если он отрицателен: путь с вершиной в `node` обязан его содержать.

```ts
    // Наверх можно отдать только один луч — иначе путь раздвоится
    return node.val + Math.max(left, right);
  };
```

Родитель продолжит путь через `node`, а значит, из `node` путь может уйти вниз только в **одну** сторону: если взять обе, узел `node` станет развилкой, и с родителем получится «вилка», а не путь. Выбираем лучшую сторону (или ни одной, если обе `0`).

```ts
  gain(root);
  return best;
}
```

Возвращаемое значение `gain(root)` нам не нужно — это лучший луч из корня, а не лучший путь. Ответ накоплен в `best`.

## Трассировка

`root = [-10, 9, 20, null, null, 15, 7]`, обход в порядке завершения вызовов:

1. `gain(9)`: детей нет → `left = 0`, `right = 0`. `best = max(-∞, 9) = 9`. Возврат `9`.
2. `gain(15)`: `left = right = 0`. `best = max(9, 15) = 15`. Возврат `15`.
3. `gain(7)`: `best = max(15, 7) = 15`. Возврат `7`.
4. `gain(20)`: `left = 15`, `right = 7`. Перегиб `20 + 15 + 7 = 42` → `best = 42`. Возврат `20 + max(15, 7) = 35`.
5. `gain(-10)`: `left = 9`, `right = 35`. Перегиб `-10 + 9 + 35 = 34` → `best` остаётся `42`. Возврат `-10 + 35 = 25` (не используется).

Ответ `42`.

Пример с отрицательным ребёнком, `root = [2, -1]`:

1. `gain(-1)`: `best = max(-∞, -1) = -1`, возврат `-1`.
2. `gain(2)`: `left = max(-1, 0) = 0`, `right = 0`. `best = max(-1, 2) = 2`.

Ответ `2` — путь из одного узла, «минусовый» ребёнок отброшен.

## Почему это работает

**Луч.** По индукции `gain(node)` — максимальная сумма пути, который начинается в `node` и идёт только вниз. Такой путь — либо сам `node`, либо `node` плюс луч из одного ребёнка; формула `node.val + max(left, right)` с отсечением отрицательных перебирает ровно эти варианты.

**Ответ.** У любого непустого пути есть единственный самый высокий узел `v`. Путь состоит из `v` и не более чем двух лучей — по одному в левое и правое поддерево `v`. Лучшие такие лучи — это `left` и `right` (или `0`, если лучше не брать). Значит, лучший путь с вершиной `v` равен `v.val + left + right`, и `best` проверяет этот кандидат для каждого `v`. Максимум по всем вершинам — максимум по всем путям.

## Пограничные случаи

- **Все значения отрицательны** (`[-3]`, `[-2, -1]`): лучи обнуляются, `best` — максимальное одиночное значение (`-1` для второго примера); спасает `-Infinity` вместо `0`.
- **Один узел**: ответ — его значение.
- **Лучший путь не проходит через корень** — как в основном примере; `best` обновляется в каждом узле.
- **Лучший путь — луч вниз** (без перегиба): тоже кандидат, один из лучей просто `0`.
- **Глубокое дерево** (до `3·10⁴` узлов в линию): рекурсия глубиной `n` может упереться в лимит стека движка; на практике для LeetCode этого хватает, иначе — итеративный post-order.

## Сложность

- **Время `O(n)`**: каждый узел обрабатывается один раз, работа в узле — `O(1)`.
- **Память `O(h)`**: стек рекурсии по высоте дерева (`O(log n)` для сбалансированного, `O(n)` для вырожденного).

## Типичные ошибки

1. **`best = 0`** → для дерева из отрицательных чисел вернётся `0`, хотя пустой путь недопустим.
2. **Возвращать наверх `node.val + left + right`** → родитель «продолжит» путь с развилкой, сумма станет завышенной и некорректной.
3. **Не отсекать отрицательные лучи** → путь обязательно тащит невыгодные ветки, ответ занижен.
4. **Отсекать `node.val`** (например, `max(node.val, 0)`) → узел нельзя пропустить, если путь через него идёт; путь с вершиной в `node` обязан включать `node.val`.
5. **Возвращать `gain(root)` как ответ** → это лучший луч из корня, а не лучший путь вообще.

## Как узнать такую задачу

- «Путь **между любыми двумя узлами**», «не обязательно через корень» → путь с вершиной (перегибом) в каждом узле, post-order DFS.
- Нужна величина, которая **не продолжается вверх**, но собирается из продолжаемых частей → «вернуть одно, посчитать другое» с глобальным ответом.
- Отрицательные значения и максимум суммы → отсечение `max(x, 0)` в духе Кадане.
- Родственные задачи: Diameter of Binary Tree, Longest Univalue Path, Maximum Subarray, Binary Tree Cameras (тот же каркас «возврат + глобальный ответ»).
