## Задача простыми словами

В узлах двоичного дерева записаны цифры `0`–`9`. Каждый путь **от корня до листа** читается как число: цифры выписываются сверху вниз. Нужно вернуть сумму всех таких чисел. Лист — узел без детей.

Пример: `root = [4, 9, 0, 5, 1]`.

```
      4
     / \
    9   0
   / \
  5   1
```

Пути: `4→9→5 = 495`, `4→9→1 = 491`, `4→0 = 40`. Сумма `495 + 491 + 40 = 1026`.

## Наивный подход

Собрать все пути от корня до листьев как массивы цифр (или строки), а затем каждый превратить в число и сложить:

```ts naive
const paths: string[] = [];
const collect = (node: TreeNode | null, path: string) => {
  if (!node) return;
  const next = path + node.val;
  if (!node.left && !node.right) paths.push(next);
  collect(node.left, next);
  collect(node.right, next);
};
collect(root, '');
return paths.reduce((sum, p) => sum + Number(p), 0);
```

Это работает, но делает лишнее: на каждом шаге **копируется** весь префикс пути (строка длиной до `h`), список путей хранится целиком, а потом каждый путь ещё раз разбирается в число. Получается `O(n·h)` времени и памяти на строки. Между тем число на пути можно не хранить по цифрам — достаточно **одного числа-накопителя**.

## Ключевое наблюдение

Дописать цифру `d` справа к числу `x` — это `x * 10 + d` (`12` и `3` → `123`). Значит, при спуске от родителя к ребёнку число пути обновляется за `O(1)`, а всё, что нужно знать узлу, — **число, набранное на пути до него**. Передаём его аргументом вниз, а сумму собираем на возврате: ответ для узла = сумма ответов его поддеревьев, а для листа — само число пути.

## Техники

### DFS по дереву с параметром «сверху вниз»

**Что это.** Обход в глубину, при котором в рекурсивный вызов передаётся состояние, накопленное на пути от корня: сумма, глубина, допустимые границы, текущее число. Такой параметр живёт в стеке вызовов, поэтому при возврате из ветки он автоматически «откатывается» — ничего не нужно отменять вручную.

**Типичный шаблон:**

```ts naive
const dfs = (node, acc) => {
  if (!node) return НЕЙТРАЛЬНОЕ;
  const next = обновить(acc, node);
  if (лист(node)) return ответ(next);
  return объединить(dfs(node.left, next), dfs(node.right, next));
};
```

**Как применяется здесь.** `acc` — число на пути (`current`), обновление — `current * 10 + node.val`, нейтральное значение для пустого узла — `0`, объединение — сложение. Это pre-order (обновляем до спуска) в сочетании с post-order (складываем после). Подробнее — во вкладке «Теория» (DFS по дереву).

### Построение числа по цифрам (схема Горнера)

Приём `value = value * 10 + digit` превращает последовательность цифр в число слева направо без строк и степеней. Он встречается везде, где число «читается» по цифрам: разбор строки в число, пути в дереве, бор с цифрами.

## Трассировка

`root = [4, 9, 0, 5, 1]`:

1. `dfs(4, 0)`: `value = 0·10 + 4 = 4`, не лист → `dfs(9, 4) + dfs(0, 4)`.
2. `dfs(9, 4)`: `value = 49`, не лист → `dfs(5, 49) + dfs(1, 49)`.
3. `dfs(5, 49)`: `value = 495`, лист → `495`.
4. `dfs(1, 49)`: `value = 491`, лист → `491`.
5. Возврат в `dfs(9, 4)`: `495 + 491 = 986`.
6. `dfs(0, 4)`: `value = 40`, лист → `40`.
7. Возврат в `dfs(4, 0)`: `986 + 40 = 1026`.

Пример с одним ребёнком, `root = [1, 2]` (у `1` только левый ребёнок `2`):

1. `dfs(1, 0)`: `value = 1`, не лист → `dfs(2, 1) + dfs(null, 1)`.
2. `dfs(2, 1)`: `value = 12`, лист → `12`.
3. `dfs(null, 1)` → `0`.
4. Итог `12`. Число `1` отдельно не учтено — узел `1` не лист.

## Почему это работает

По индукции по высоте поддерева докажем: `dfs(node, current)` равно сумме чисел `current·10^k + (число пути от node до листа)` по всем листьям поддерева `node`, где `k` — длина этого пути в узлах.

- `node = null`: листьев нет, сумма `0` — верно.
- `node` — лист: единственный путь — сам узел, число `current·10 + node.val` — верно.
- Иначе: каждый путь из `node` в лист проходит через ровно одного ребёнка; для ребёнка префикс равен `value`, и по предположению индукции вызовы считают свои части верно. Сумма по двум детям — сумма по всем путям.

Для корня `current = 0`, значит, `dfs(root, 0)` — ровно сумма чисел всех путей корень → лист.

## Пограничные случаи

- **Один узел**: он же лист, ответ — его цифра.
- **Узел с одним ребёнком**: пустая сторона даёт `0`, сам узел не считается концом пути.
- **Нули в узлах**: `40`, `400` — умножение на 10 корректно учитывает нули в середине и в конце; ведущий ноль в корне (`0 → 5`) даёт `5`, как и положено числу.
- **Переполнение**: глубина не превышает `10`, а ответ гарантированно 32-битный — `number` в JS точен до `2^53`.

## Сложность

- **Время `O(n)`**: каждый узел посещается один раз, работа в узле — `O(1)`; вызовов для `null` не больше `n + 1`.
- **Память `O(h)`**: глубина стека рекурсии равна высоте дерева; по условию `h ≤ 10`. Никаких строк и списков путей.

## Типичные ошибки

1. **Суммировать на `null` вместо листа** (`if (!node) return current`) → узел с одним ребёнком добавит лишнее «оборванное» число.
2. **Глобальная переменная пути без отката** → после возврата из левой ветки правая получает испорченный префикс. Передача `value` аргументом решает это автоматически.
3. **Склеивать строки и парсить** → лишние `O(h)` на каждом шаге и риск ошибок с ведущими нулями.
4. **Начинать с `current = root.val`** и снова прибавлять `root.val` в первом вызове → цифра корня учитывается дважды.
5. **Считать каждый узел концом пути** → складываются префиксы, а не только числа до листьев.

## Как узнать такую задачу

- В условии **пути от корня до листа** и нужно что-то посчитать вдоль пути → DFS с параметром, передаваемым вниз.
- Значения узлов — **цифры**, путь «читается» как число или строка → накопление `x * 10 + d`.
- Родственные задачи: Path Sum, Path Sum II, Binary Tree Paths, Sum of Root To Leaf Binary Numbers (то же, но `x * 2 + bit`), Smallest String Starting From Leaf.
