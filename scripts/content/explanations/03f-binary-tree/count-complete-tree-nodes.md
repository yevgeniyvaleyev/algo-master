## Задача простыми словами

Дан корень **полного** двоичного дерева: все уровни заполнены целиком, кроме, возможно, последнего, а узлы последнего уровня прижаты влево. Нужно вернуть количество узлов — и сделать это **быстрее, чем за `O(n)`**.

Пример: `root = [1, 2, 3, 4, 5, 6]`.

```
        1
      /   \
     2     3
    / \   /
   4   5 6
```

Ответ `6`. Последний уровень заполнен частично (`4, 5, 6`), но без «дыр» слева.

## Наивный подход

Обойти дерево и посчитать каждый узел:

```ts naive
const count = (node: TreeNode | null): number =>
  node === null ? 0 : 1 + count(node.left) + count(node.right);
```

Это `O(n)` — каждый узел посещается. Работает для любого дерева, но именно поэтому не использует главную подсказку — дерево **полное**. В полном дереве большие куски устроены предсказуемо: целые поддеревья **идеальны** (заполнены полностью), и их размер известен по формуле `2^h - 1`. Обходить их узел за узлом — лишняя работа.

## Ключевое наблюдение

1. **Как узнать, что поддерево идеальное?** В полном дереве достаточно сравнить длину самого левого пути (только по `left`) и самого правого (только по `right`). Если они равны, последний уровень заполнен до конца — дерево идеальное, и узлов ровно `2^h - 1`. Замер стоит `O(h) = O(log n)`.
2. **Если не идеальное**, считаем `1 + count(left) + count(right)`. Но в полном дереве **хотя бы одно из двух поддеревьев корня идеальное**: граница заполнения последнего уровня проходит либо по левому поддереву (тогда правое — идеальное, на уровень ниже), либо по правому (тогда левое — идеальное). Идеальное поддерево вернёт ответ сразу после замера, и «настоящая» рекурсия продолжится лишь по одной ветке.

Итого: `O(log n)` уровней рекурсии по `O(log n)` на замер — `O(log² n)`.

## Техники

### Разделяй и властвуй с отсечением

**Что это.** Задача делится на подзадачи (здесь — левое и правое поддеревья), их ответы объединяются (`1 + L + R`). Сила приёма в том, что часть подзадач решается **сразу**, без дальнейшего деления — по формуле.

**Когда применять.** Когда структура данных гарантирует, что большие части «правильные» и их ответ вычисляется напрямую: полные деревья, отсортированные куски, однородные блоки.

**Как применяется здесь.** База-ускорение — идеальное поддерево (`2^h - 1`). Благодаря свойству полного дерева рекурсия по факту идёт только по одной ветке. Подробнее — во вкладке «Теория» (разделяй и властвуй).

### Свойства полного и идеального дерева

- **Идеальное** дерево высоты `h` (в узлах) содержит `1 + 2 + 4 + … + 2^(h-1) = 2^h - 1` узлов.
- В **полном** дереве самый левый путь — самый длинный (последний уровень заполняется слева), а самый правый — самый короткий. Их равенство означает, что все уровни заполнены.
- Любое поддерево полного дерева — тоже полное, поэтому рассуждение применимо рекурсивно.

### Подсчёт высоты спуском

Высоту полного дерева не нужно искать обходом: достаточно спуститься по одному краю — `O(log n)`.

## Разбор кода

```ts
function countNodes(root: TreeNode | null): number {
  if (root === null) return 0;
```

Пустое дерево — ноль узлов. Это же база рекурсии для отсутствующего ребёнка.

```ts
  // Высота по самому левому пути
  let leftHeight = 0;
  for (let n: TreeNode | null = root; n !== null; n = n.left) leftHeight++;
```

Спускаемся только влево и считаем узлы на пути. В полном дереве это настоящая высота (самый глубокий уровень всегда начинается слева).

```ts
  // Высота по самому правому пути
  let rightHeight = 0;
  for (let n: TreeNode | null = root; n !== null; n = n.right) rightHeight++;
```

То же по правому краю. Эта длина либо равна `leftHeight`, либо меньше на `1` (последний уровень не дошёл до правого края).

```ts
  // Высоты равны — дерево идеальное (все уровни заполнены): 2^h - 1 узлов
  if (leftHeight === rightHeight) {
    return 2 ** leftHeight - 1;
  }
```

Равенство краёв + полнота = идеальное дерево. Возвращаем ответ по формуле — без обхода. `2 ** h` — возведение в степень; при `n ≤ 5·10⁴` высота не больше `16`, переполнения нет.

```ts
  // Иначе считаем рекурсивно. Одно из поддеревьев обязательно идеальное
  // и посчитается сразу по формуле — поэтому рекурсия идёт вглубь только по одной ветке
  return 1 + countNodes(root.left) + countNodes(root.right);
}
```

Дерево не идеальное: считаем корень и оба поддерева. Одно из них идеальное — его вызов закончится на проверке высот за `O(log n)`. Второе может снова оказаться неидеальным, и рекурсия продолжится только в нём.

## Трассировка

`root = [1, 2, 3, 4, 5, 6]`:

1. `countNodes(1)`: левый путь `1 → 2 → 4` → `leftHeight = 3`; правый `1 → 3` → `rightHeight = 2`. Не равны → `1 + countNodes(2) + countNodes(3)`.
2. `countNodes(2)`: левый `2 → 4` = `2`, правый `2 → 5` = `2`. Равны → `2² - 1 = 3`. (Поддерево `2, 4, 5` — идеальное.)
3. `countNodes(3)`: левый `3 → 6` = `2`, правый `3` = `1`. Не равны → `1 + countNodes(6) + countNodes(null)`.
4. `countNodes(6)`: оба пути длины `1` → `2¹ - 1 = 1`.
5. `countNodes(null)` → `0`.
6. Возврат в `countNodes(3)`: `1 + 1 + 0 = 2`.
7. Возврат в `countNodes(1)`: `1 + 3 + 2 = 6`.

Обратите внимание: в узлы `4` и `5` рекурсия не заходила вообще — их посчитала формула на шаге 2.

## Почему это работает

**Формула.** В полном дереве все уровни, кроме последнего, полны, а последний заполнен слева направо. Самый левый путь доходит до последнего уровня всегда; самый правый — только если последний уровень заполнен до конца. Значит, `leftHeight === rightHeight` ⇔ дерево идеальное, и узлов `2^h - 1`.

**Рекурсия.** Если дерево не идеальное, `1 + count(left) + count(right)` — просто определение числа узлов; поддеревья полного дерева полны, так что рассуждение применимо к ним.

**Скорость.** Пусть высота дерева `h`. Если последний уровень заканчивается в левом поддереве, правое поддерево — идеальное высоты `h - 2`; если доходит до правого — левое идеальное высоты `h - 1`. В обоих случаях один из двух вызовов завершится на проверке. Неидеальный вызов на каждом уровне рекурсии максимум один, глубина — `h`.

## Пограничные случаи

- **Пустое дерево**: сразу `0`.
- **Один узел**: оба пути длины `1`, ответ `2¹ - 1 = 1`.
- **Идеальное дерево целиком**: ответ сразу на корне, `O(log n)`.
- **На последнем уровне один узел** (`[1, 2]`): `leftHeight = 2`, `rightHeight = 1` → `1 + countNodes(2) + countNodes(null) = 1 + 1 + 0 = 2`.
- **Последний уровень заполнен почти полностью**: правое поддерево неидеально, левое идеально — рекурсия уходит вправо.

## Сложность

- **Время `O(log² n)`**: глубина рекурсии — `O(log n)`, на каждом уровне два замера высот за `O(log n)` в неидеальном вызове и ещё столько же в идеальном (он сразу завершается). При `n = 5·10⁴` это порядка `16 · 16 · 4` ≈ тысячи шагов против `5·10⁴` у обхода.
- **Память `O(log n)`**: стек рекурсии, его глубина — высота дерева.

## Типичные ошибки

1. **Обычный обход** → `O(n)`, требование «быстрее, чем `O(n)`» не выполнено.
2. **Сравнивать высоты левого и правого поддерева через полную высоту** (`maxDepth`) → каждый замер становится `O(n)`.
3. **Мерить `rightHeight` спуском `n.left` в правом поддереве** → это высота другого пути, критерий идеальности ломается.
4. **Формула `2^h` вместо `2^h - 1`** или путаница «высота в рёбрах / в узлах» → ошибка на единицу. Здесь `h` считается в **узлах**.
5. **Применять приём к неполному дереву** → равенство краёв больше не гарантирует идеальность (в середине могут быть дыры).

## Как узнать такую задачу

- В условии **полное** или **идеальное** дерево и требование быстрее `O(n)` → ищите куски, считаемые по формуле, и логарифмическую рекурсию/бинарный поиск.
- Нужно «посчитать» что-то в структуре, где большие части однородны → отсечение подзадач, ответ для которых известен сразу.
- Альтернатива для того же условия — бинарный поиск по числу узлов на последнем уровне (существование узла с номером `k` проверяется спуском по битам `k`), тоже `O(log² n)`.
- Родственные задачи: Check Completeness of a Binary Tree, Complete Binary Tree Inserter, Maximum Depth of Binary Tree, задачи на кучу (heap хранится как полное дерево).
