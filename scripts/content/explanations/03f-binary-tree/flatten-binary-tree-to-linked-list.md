## Задача простыми словами

Дан корень двоичного дерева. Нужно **на месте** превратить дерево в «связный список» из тех же узлов: каждый узел указывает на следующий через `right`, а `left` у всех равен `null`. Порядок узлов — как в **прямом обходе** (pre-order: узел → левое → правое). Функция ничего не возвращает.

Пример: `root = [1, 2, 5, 3, 4, null, 6]`.

```
        1                1
       / \                \
      2   5      =>        2
     / \   \                \
    3   4   6                3 -> 4 -> 5 -> 6   (всё по right)
```

Pre-order исходного дерева: `1, 2, 3, 4, 5, 6` — именно в таком порядке узлы и выстраиваются.

## Наивный подход

Сделать pre-order обход, сложить узлы в массив, а потом перелинковать их подряд:

```ts naive
const order: TreeNode[] = [];
const dfs = (node: TreeNode | null) => {
  if (!node) return;
  order.push(node);
  dfs(node.left);
  dfs(node.right);
};
dfs(root);
for (let i = 0; i < order.length; i++) {
  order[i].left = null;
  order[i].right = order[i + 1] ?? null;
}
```

Время `O(n)`, но память `O(n)` на массив плюс `O(h)` на стек рекурсии. Где лишнее? Мы храним **все** узлы, чтобы помнить порядок, хотя сам pre-order устроен просто: после узла идёт его левое поддерево, а **сразу после последнего узла левого поддерева** — правое. Эту «точку стыковки» можно найти прямо в дереве, без внешнего хранилища.

## Ключевое наблюдение

Pre-order левого поддерева заканчивается поддеревом его **самого правого** узла (спуск по `right` от `node.left`, пока можно). У этого узла свободен указатель `right`, и всё, что к нему подвешено, pre-order поставит в самый конец левого поддерева — ровно туда, где должно начинаться правое. Значит, для узла с непустым левым поддеревом достаточно:

1. найти этот `rightmost`;
2. подвесить к нему текущее правое поддерево: `rightmost.right = node.right`;
3. перенести левое поддерево на место правого: `node.right = node.left`, `node.left = null`.

Порядок pre-order при этом не меняется, а левых детей у `node` больше нет. Дальше просто идём по `right` и повторяем для каждого узла — рекурсия и стек не нужны.

## Техники

### Перестройка дерева на месте (приём Морриса)

**Что это.** Обход Морриса и его родственники используют свободные указатели самого дерева (обычно `right` у самого правого узла поддерева), чтобы «запомнить», куда идти дальше, вместо стека. Это даёт обход за `O(1)` дополнительной памяти.

**Типичный шаблон:** для текущего узла найти его **предшественника** — самый правый узел левого поддерева — и через его `right` связать его с тем, что должно идти после.

**Как применяется здесь.** Предшественник правого поддерева в pre-order — `rightmost` левого. Мы не ставим временную связь, как в классическом Моррисе, а сразу делаем её постоянной: правое поддерево навсегда переезжает под `rightmost`.

### Pre-order обход и его структура

**Что это.** Pre-order — обход «узел → левое → правое». Для каждого узла его поддерево в pre-order занимает непрерывный отрезок: `[node, ...левое, ...правое]`.

**Когда применять.** Когда информация идёт сверху вниз или нужен порядок «родитель раньше детей» — копирование и сериализация деревьев, как здесь. Подробнее — во вкладке «Теория» (DFS по дереву).

### Итерация по списку, который строится на ходу

Указатель `node` двигается по `right`. Всё, что слева от `node` в будущем списке, уже окончательно выпрямлено; всё, что справа, ещё может иметь левых детей. Это классический «один указатель обрабатывает текущий элемент и шагает дальше».

## Разбор кода

```ts
/**
 Do not return anything, modify root in-place instead.

```

Сигнатура требует менять дерево на месте. `node` — текущий узел будущего списка; начинаем с корня — он в pre-order первый.

```ts
  while (node !== null) {
    if (node.left !== null) {
```

Идём, пока не дошли до конца списка. Если левого поддерева нет, узел уже в нужной форме: в pre-order после него сразу идёт правое поддерево, на которое и указывает `right`.

```ts
      // Ищем самый правый узел левого поддерева —
      // в pre-order он идёт последним перед правым поддеревом
      let rightmost = node.left;
      while (rightmost.right !== null) {
        rightmost = rightmost.right;
      }
```

Спуск по правым рёбрам левого поддерева, пока `right` не станет `null`. Почему именно этот узел? В любом поддереве pre-order заканчивается правым поддеревом, а в нём — снова правым, и так далее. У найденного `rightmost` правого ребёнка нет, поэтому его поддерево (он сам и, возможно, его левые потомки) завершает pre-order всего `node.left`. Тонкость: если у `rightmost` есть левый ребёнок, буквально последним будет узел из него, но это не важно — правое место у `rightmost` свободно, и всё, что туда подвесить, pre-order поставит **после** всего поддерева `rightmost`, то есть в самый конец левого поддерева.

```ts
      // Подвешиваем правое поддерево за этот узел
      rightmost.right = node.right;
```

У `rightmost` правый ребёнок был `null`, поэтому ничего не теряется. Теперь правое поддерево `node` «висит» в конце левого.

```ts
      // Переносим левое поддерево направо, слева оставляем null
      node.right = node.left;
      node.left = null;
    }
```

Левое поддерево становится продолжением списка сразу после `node` — ровно как в pre-order. `node.left = null` обязательно: этого требует формат ответа, и без этого получился бы цикл в структуре.

```ts
    // Двигаемся по «списку» дальше
    node = node.right;
  }
}
```

Переходим к следующему узлу. Он может ещё иметь левое поддерево — его обработает следующая итерация.

## Трассировка

`root = [1, 2, 5, 3, 4, null, 6]`:

```
        1
       / \
      2   5
     / \   \
    3   4   6
```

1. `node = 1`, `left = 2`. Спуск: `rightmost = 2` → `2.right = 4` → `rightmost = 4` (`4.right = null`).
   `4.right = 5`; `1.right = 2`; `1.left = null`.

```
    1
     \
      2
     / \
    3   4
         \
          5
           \
            6
```

2. `node = 2`, `left = 3`. `rightmost = 3` (`3.right = null`).
   `3.right = 4`; `2.right = 3`; `2.left = null`. Теперь `1 → 2 → 3 → 4 → 5 → 6`.
3. `node = 3`: `left = null`, шаг дальше.
4. `node = 4`: `left = null`, шаг.
5. `node = 5`: `left = null`, шаг.
6. `node = 6`: `left = null`, `node = null` → выход.

Результат: `1 → 2 → 3 → 4 → 5 → 6` по `right`, все `left = null`.

## Почему это работает

**Сохранение pre-order.** Рассмотрим одну операцию для узла `node` с поддеревьями `L` и `R`. Pre-order поддерева `node` до операции: `node, pre(L), pre(R)`. После операции у `node` нет левого, справа — `L`, а `R` подвешено к `rightmost` — самому правому узлу `L`. У `rightmost` раньше не было правого ребёнка, значит, его поддерево в pre-order было `rightmost, pre(его левого)` и оно стояло в самом конце `pre(L)`. Теперь его правое — `R`, и pre-order поддерева `rightmost` стал `rightmost, pre(его левого), pre(R)`. Итог: `node, pre(L), pre(R)` — порядок тот же.

**Завершённость.** Операция не меняет pre-order, но убирает левого ребёнка у `node`. Указатель идёт по `right` и посещает каждый узел будущего списка (все узлы попадают в правую цепочку, потому что в pre-order «следующий» после узла без левого ребёнка — его `right`). Когда `node` становится `null`, у всех узлов `left = null`, а цепочка `right` — это pre-order.

## Пограничные случаи

- **Пустое дерево**: `node = null`, цикл не выполняется.
- **Один узел**: левого нет, сразу `node = null`.
- **Уже «список» вправо**: ни одной перестройки, просто проход по `right`.
- **Только левые дети** (`1 → 2 → 3` влево): на каждом шаге `rightmost` — сам `node.left`, перенос за `O(1)`.
- **Отрицательные/повторяющиеся значения**: алгоритм работает с узлами, а не со значениями.

## Сложность

- **Время `O(n)`**: каждый узел один раз становится `node`. Спуск к `rightmost` идёт по правым рёбрам левого поддерева; после перестройки эти рёбра лежат в основной цепочке, и их больше не спускают как «поиск rightmost» — каждое ребро просматривается не более двух раз.
- **Память `O(1)`**: два указателя (`node`, `rightmost`), без рекурсии и стека.

## Типичные ошибки

1. **Забыть `node.left = null`** → в ответе остаются левые ссылки, проверка формата падает.
2. **Перенести `node.right = node.left` до сохранения правого поддерева** → старое `node.right` потеряно. В коде порядок такой: сначала `rightmost.right = node.right`, потом перезапись.
3. **Искать `rightmost` по `left`** вместо `right` → правое поддерево вставится в середину, порядок нарушится.
4. **Рекурсия в прямом pre-order с изменением указателей «на лету»** → `node.right` перезаписывается до того, как правое поддерево обработано.
5. **Построить новый список из новых узлов** → задача требует перестроить исходные узлы.
