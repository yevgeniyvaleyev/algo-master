## Задача простыми словами

Дан корень двоичного дерева. Нужно **на месте** превратить дерево в «связный список» из тех же узлов: каждый узел указывает на следующий через `right`, а `left` у всех равен `null`. Порядок узлов — как в **прямом обходе** (pre-order: узел → левое → правое). Функция ничего не возвращает.

Пример: `root = [1, 2, 5, 3, 4, null, 6]`.

```
        1                1
       / \                \
      2   5      =>        2
     / \   \                \
    3   4   6                3 -> 4 -> 5 -> 6   (всё по right)
```

Pre-order исходного дерева: `1, 2, 3, 4, 5, 6` — именно в таком порядке узлы и выстраиваются.

## Наивный подход

Рекурсивно сплющить левое и правое поддеревья, а потом склеить: левый список поставить справа от узла, дойти до **его хвоста** и подвесить туда правый список.

```ts naive
function flatten(node: TreeNode | null): void {
  if (!node) return;
  flatten(node.left);
  flatten(node.right);
  const right = node.right;
  node.right = node.left;
  node.left = null;
  let tail = node;
  while (tail.right) tail = tail.right; // идём до конца левого списка
  tail.right = right;
}
```

Код верный, но поиск хвоста каждый раз проходит весь уже сплющенный левый список. На дереве-«палке» влево (`1 → 2 → 3 → …` по `left`) это `1 + 2 + … + n = O(n²)`. К тому же в нём легко запутаться: что именно где висит после каждой перестановки указателей. Нужно что-то, где порядок узлов известен заранее.

## Ключевое наблюдение

Ответ — это просто узлы дерева **в порядке pre-order**, сцепленные через `right`. Порядок pre-order легко получить обычным рекурсивным обходом. Значит, задачу можно разделить на два независимых шага:

1. обойти дерево и записать **сами узлы** (ссылки) в массив в порядке pre-order;
2. пройти массив и перелинковать: `left = null`, `right = следующий элемент`.

Главное — менять указатели **после** обхода. Пока идёт DFS, он читает `left` и `right`; если их переписывать на ходу, обход потеряет ещё не посещённые поддеревья.

## Техники

### Pre-order обход (DFS)

**Что это.** Pre-order — обход «узел → левое → правое». Узел записывается **до** своих поддеревьев.

**Шаблон:**

```ts naive
const dfs = (node) => {
  if (node === null) return;
  visit(node);
  dfs(node.left);
  dfs(node.right);
};
```

**Как применяется здесь.** `visit` = `nodes.push(node)`. Получаем массив ровно в том порядке, в каком узлы должны идти в «списке». Подробнее — во вкладке «Теория» (DFS по дереву).

### Сначала собрать, потом перестроить

**Что это.** Когда структуру нужно изменить, а алгоритм обхода зависит от её текущего вида, удобно разделить чтение и запись: сначала записать нужный порядок во вспомогательный массив, потом менять указатели, уже ничего не обходя.

**Как применяется здесь.** Массив `nodes` хранит ссылки на узлы, поэтому вторая фаза меняет **исходные** узлы дерева — это и есть «на месте» с точки зрения задачи.

## Разбор кода

```ts
/**
 Do not return anything, modify root in-place instead.
 */
function flatten(root: TreeNode | null): void {
```

Сигнатура LeetCode: функция ничего не возвращает, проверяется само дерево по `root`.

```ts
  // Собираем узлы в порядке pre-order: узел → левое → правое
  const nodes: TreeNode[] = [];
  const dfs = (node: TreeNode | null): void => {
    if (node === null) return;
    nodes.push(node);
    dfs(node.left);
    dfs(node.right);
  };
  dfs(root);
```

Обычный рекурсивный pre-order. Базовый случай — пустое поддерево. Узел кладём в массив **до** рекурсивных вызовов — это и делает обход прямым. Указатели пока не трогаем. Если `root === null`, массив останется пустым.

```ts
  // Перелинковываем подряд: right — следующий узел, left — null
  for (let i = 0; i < nodes.length; i++) {
    nodes[i].left = null;
    nodes[i].right = nodes[i + 1] ?? null;
  }
}
```

Вторая фаза. У каждого узла обнуляем `left`, а `right` направляем на следующий в массиве. У последнего узла `nodes[i + 1]` — `undefined`, и `?? null` превращает его в `null`: список заканчивается. Корень — `nodes[0]`, так что `root` остаётся головой.

## Трассировка

`root = [1, 2, 5, 3, 4, null, 6]`.

```
        1
       / \
      2   5
     / \   \
    3   4   6
```

Фаза 1 — DFS:

| вызов    | действие         | nodes                |
| -------- | ---------------- | -------------------- |
| `dfs(1)` | push 1, влево    | `[1]`                |
| `dfs(2)` | push 2, влево    | `[1, 2]`             |
| `dfs(3)` | push 3, детей нет | `[1, 2, 3]`          |
| `dfs(4)` | push 4, детей нет | `[1, 2, 3, 4]`       |
| `dfs(5)` | push 5, вправо   | `[1, 2, 3, 4, 5]`    |
| `dfs(6)` | push 6           | `[1, 2, 3, 4, 5, 6]` |

Фаза 2 — перелинковка:

- `i = 0`: `1.left = null`, `1.right = 2`;
- `i = 1`: `2.left = null` (был `3`), `2.right = 3` (был `4`);
- `i = 2`: `3.right = 4`; `i = 3`: `4.right = 5`; `i = 4`: `5.right = 6`;
- `i = 5`: `6.right = nodes[6] ?? null = null`.

Итог: `1 → 2 → 3 → 4 → 5 → 6` по `right`, все `left = null`, что и даёт `[1,null,2,null,3,null,4,null,5,null,6]`.

## Почему это работает

- **Порядок верный.** DFS кладёт узел в массив раньше его поддеревьев, а левое поддерево — раньше правого. Это определение pre-order, значит, `nodes` — ровно нужный порядок.
- **Ничего не теряется.** Во время DFS указатели не меняются, поэтому обход видит исходное дерево целиком и посещает каждый узел ровно один раз.
- **Результат — нужный список.** После второй фазы у каждого узла `left = null`, а `right` указывает на следующий в pre-order; у последнего — `null`. Это в точности требуемая структура.

## Пограничные случаи

- **Пустое дерево**: `nodes = []`, цикл не выполняется, ничего не меняется.
- **Один узел**: `left = null`, `right = null` — уже готовый список.
- **Только левые дети** (`[1, 2, null, 3]`): pre-order `1, 2, 3`, все левые связи переезжают вправо.
- **Только правые дети**: дерево уже «список», перелинковка переписывает те же указатели.
- **Глубокое дерево** из 2000 узлов: глубина рекурсии до 2000 — для JavaScript безопасно.

## Сложность

- **Время `O(n)`**: DFS посещает каждый узел один раз, перелинковка — один проход по массиву.
- **Память `O(n)`**: массив `nodes` плюс стек рекурсии `O(h)`.

**Follow-up на собеседовании: `O(1)` памяти.** В pre-order последний узел левого поддерева — его **самый правый** узел. Для каждого узла с непустым `left` подвешиваем правое поддерево к этому `rightmost`, переносим левое поддерево направо и идём дальше по `right` — без массива и рекурсии (приём в духе обхода Морриса):

```ts naive
let node = root;
while (node !== null) {
  if (node.left !== null) {
    let rightmost = node.left;
    while (rightmost.right !== null) rightmost = rightmost.right;
    rightmost.right = node.right;
    node.right = node.left;
    node.left = null;
  }
  node = node.right;
}
```

## Типичные ошибки

1. **Менять указатели во время DFS** (`node.right = ...` до `dfs(node.right)`) → правое поддерево теряется. Сначала собрать, потом перелинковать.
2. **Забыть `left = null`** → LeetCode считает результат неверным: левые ссылки должны быть пустыми.
3. **Складывать значения вместо узлов** и создавать новые `TreeNode` → проверяется исходное дерево по `root`, новые узлы до него не дойдут.
4. **In-order вместо pre-order** (`push` между `dfs(left)` и `dfs(right)`) → порядок `3, 2, 4, 1, 5, 6` вместо `1, 2, 3, 4, 5, 6`.
5. **`nodes[i + 1]` без `?? null`** → у последнего узла `right = undefined`, а не `null`.

## Как узнать такую задачу

- Нужно **перестроить дерево в линейную структуру** в порядке какого-то обхода → соберите узлы этим обходом в массив и перелинкуйте.
- Слова «pre-order», «in-order» в условии прямо подсказывают обход.
- Follow-up «на месте, `O(1)` памяти» → ищите «самый правый узел левого поддерева» (Моррис).
- Родственные задачи: Increasing Order Search Tree, Convert BST to Sorted Doubly Linked List, Binary Tree Preorder Traversal, Flatten a Multilevel Doubly Linked List.
