## Задача простыми словами

Дано двоичное дерево, у каждого узла кроме `left` и `right` есть указатель `next`. Нужно для каждого узла направить `next` на **соседа справа на том же уровне**, а у самого правого узла уровня оставить `null`. Дерево **произвольное** (в отличие от версии I, где оно идеальное): у узлов может не быть любого из детей. Дополнительно (follow-up) просят обойтись `O(1)` памяти — об этом в конце.

Пример: `root = [1, 2, 3, 4, 5, null, 7]`.

```
        1 -> null
       / \
      2 -> 3 -> null
     / \    \
    4 -> 5 -> 7 -> null
```

Обратите внимание на связь `5 -> 7`: соседи по уровню могут быть детьми **разных** родителей, а между ними может зиять «дыра».

## Наивный подход

Для каждого узла отдельно искать его соседа: запомнить глубину каждого узла, потом для узла перебрать все узлы той же глубины в порядке слева направо и взять следующий за ним.

```ts naive
// depthOf — глубины, order — узлы в порядке «слева направо» внутри глубины
for (const node of allNodes) {
  const sameDepth = allNodes.filter((x) => depthOf.get(x) === depthOf.get(node));
  const i = sameDepth.indexOf(node);
  node.next = sameDepth[i + 1] ?? null;
}
```

Это `O(n²)`: для каждого узла заново перебираем всё дерево. Где лишнее? Мы раз за разом восстанавливаем **один и тот же** список «узлы уровня слева направо». Если получить этот список для каждого уровня один раз, сосед справа — просто следующий элемент.

## Ключевое наблюдение

Обход в ширину (BFS) как раз и выдаёт дерево **по уровням, каждый уровень — слева направо**. Если держать текущий уровень в массиве `level`, то:

- сосед справа узла `level[i]` — это `level[i + 1]`;
- у последнего узла уровня соседа нет — `null`;
- следующий уровень получается, если у каждого узла по очереди взять `left`, затем `right`.

Дети разных родителей (как `5` и `7`) оказываются в массиве рядом, поэтому «дыры» в дереве ничего не ломают.

## Техники

### Обход дерева по уровням (BFS)

**Что это.** BFS обрабатывает дерево слоями: корень, затем все узлы глубины 1, затем глубины 2 и т.д.

**Шаблон «массив уровня»:**

```ts naive
let level = [root];
while (level.length > 0) {
  // ...обработать уровень целиком...
  const next = [];
  for (const node of level) {
    if (node.left) next.push(node.left);
    if (node.right) next.push(node.right);
  }
  level = next;
}
```

Вместо одной очереди с подсчётом размера уровня держим два массива: текущий уровень и следующий. Границы уровня видны сразу — это массив целиком.

**Когда применять.** Когда ответ связан с уровнями: соседи по уровню, вид справа, средние по уровням, зигзаг-обход, минимальная глубина.

**Как применяется здесь.** «Обработать уровень» = связать соседей: `level[i].next = level[i + 1]`. Подробнее — во вкладке «Теория» (BFS по дереву).

## Разбор кода

```ts
/**
 * Definition for _Node.
 * class _Node {
 *     val: number
 *     left: _Node | null
 *     right: _Node | null
 *     next: _Node | null
 *     constructor(val?: number, left?: _Node, right?: _Node, next?: _Node) { ... }
 * }
 */
```

Определение узла: у `_Node` четыре поля, `next` изначально `null`.

```ts
function connect(root: _Node | null): _Node | null {
  if (root === null) return null;

  // Обходим дерево по уровням, каждый уровень — слева направо
  let level: _Node[] = [root];
```

Пустое дерево обрабатываем сразу — иначе в массив попал бы `null`. Первый уровень — один корень.

```ts
  while (level.length > 0) {
    // Соседи по уровню идут в массиве подряд: связываем каждый со следующим
    for (let i = 0; i < level.length; i++) {
      level[i].next = i + 1 < level.length ? level[i + 1] : null;
    }
```

Внешний цикл — по уровням. Внутри связываем соседей: каждый узел смотрит на следующий элемент массива, последний получает `null`. Явное `null` не обязательно (изначально `next` и так `null`), но так код честно описывает результат.

```ts
    // Собираем следующий уровень в том же порядке: слева направо
    const next: _Node[] = [];
    for (const node of level) {
      if (node.left !== null) next.push(node.left);
      if (node.right !== null) next.push(node.right);
    }
    level = next;
  }
```

Родители перебираются слева направо, у каждого сначала `left`, потом `right` — значит, дети попадают в `next` в порядке слева направо по всему уровню. Отсутствующих детей пропускаем. Когда у уровня детей нет, `next` пуст, и цикл завершается.

```ts
  return root;
}
```

Возвращаем исходный корень: дерево изменено на месте.

## Трассировка

`root = [1, 2, 3, 4, 5, null, 7]`.

| итерация | level       | проставленные next          | следующий уровень |
| -------- | ----------- | --------------------------- | ----------------- |
| 1        | `[1]`       | `1 → null`                  | `[2, 3]`          |
| 2        | `[2, 3]`    | `2 → 3`, `3 → null`         | `[4, 5, 7]`       |
| 3        | `[4, 5, 7]` | `4 → 5`, `5 → 7`, `7 → null` | `[]`              |

На итерации 2 у узла `2` берём `4` и `5`, у узла `3` левого ребёнка нет — сразу `7`. Поэтому `5` и `7` стоят в массиве рядом, и связь `5 → 7` (разные родители, дыра между ними) получается сама собой. На итерации 4 `level` пуст — выход.

## Почему это работает

Инвариант внешнего цикла: **в начале итерации `level` содержит ровно все узлы очередного уровня в порядке слева направо**.

- Для уровня корня это верно: `[root]`.
- Пусть верно для уровня `k`. Узлы уровня `k + 1` — это дети узлов уровня `k`, и порядок слева направо у них такой: сначала дети самого левого родителя (левый, потом правый), затем следующего и так далее. Ровно так мы и собираем `next`. Значит, инвариант верен и для уровня `k + 1`.

Раз массив уровня точно совпадает с уровнем слева направо, «следующий элемент массива» и есть «сосед справа на том же уровне», а у последнего элемента соседа нет.

## Пограничные случаи

- **Пустое дерево**: ранний выход, возвращаем `null`.
- **Один узел**: `1 → null`, следующий уровень пуст.
- **Дыры между соседями** (`5 → 7` в примере): в массиве уровня их просто нет.
- **Родитель без детей в начале уровня**: ничего не добавляет, следующий уровень начнётся с детей соседа.
- **Дерево-«палка»**: на каждом уровне один узел, его `next = null`.

## Сложность

- **Время `O(n)`**: каждый узел один раз попадает в массив уровня, один раз получает `next` и один раз отдаёт своих детей.
- **Память `O(w)`**: два массива — текущий и следующий уровень; `w` — ширина самого широкого уровня, в худшем случае около `n/2`, то есть `O(n)`.

**Follow-up на собеседовании: `O(1)` памяти.** Связанный уровень — это уже готовый односвязный список через `next`. Можно идти по нему без массива и дописывать детей в хвост списка следующего уровня через фиктивную голову `dummy`:

```ts naive
let levelStart = root;
while (levelStart !== null) {
  const dummy = new _Node(0);
  let tail = dummy;
  for (let node = levelStart; node !== null; node = node.next) {
    if (node.left) tail = tail.next = node.left;
    if (node.right) tail = tail.next = node.right;
  }
  levelStart = dummy.next;
}
```

## Типичные ошибки

1. **Решение из версии I** (`node.left.next = node.right; node.right.next = node.next.left`) → ломается, когда у узла нет детей или у соседа нет левого ребёнка.
2. **Связать последний узел уровня с первым узлом следующего** — бывает при одной общей очереди без учёта границ уровня. Шаблон «массив уровня» этого не допускает.
3. **Положить `null` в массив** — забыть проверку `root === null` или проверки детей; дальше `level[i].next` упадёт.
4. **Сначала `right`, потом `left`** → соседи свяжутся справа налево.
5. **`queue.shift()` в одной большой очереди** — работает, но каждый `shift` стоит `O(n)`; два массива уровней этого избегают.

## Как узнать такую задачу

- Нужно что-то сделать **для соседей на одном уровне** дерева → BFS по уровням, шаблон `let level = [root]`.
- Если просят **`O(1)` памяти** — ищите, нельзя ли использовать уже построенные указатели (`next` прошлого уровня) вместо массива.
- Родственные задачи: Populating Next Right Pointers in Each Node (версия I), Binary Tree Right Side View, Binary Tree Level Order Traversal, Average of Levels in Binary Tree.
