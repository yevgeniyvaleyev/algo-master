## Задача простыми словами

Дано двоичное дерево, у каждого узла кроме `left` и `right` есть указатель `next`. Нужно для каждого узла направить `next` на **соседа справа на том же уровне**, а у самого правого узла уровня оставить `null`. Дерево **произвольное** (в отличие от версии I, где оно идеальное): у узлов может не быть любого из детей. Дополнительно просят обойтись `O(1)` памяти.

Пример: `root = [1, 2, 3, 4, 5, null, 7]`.

```
        1 -> null
       / \
      2 -> 3 -> null
     / \    \
    4 -> 5 -> 7 -> null
```

Обратите внимание на связь `5 -> 7`: соседи по уровню могут быть детьми **разных** родителей, а между ними может зиять «дыра».

## Наивный подход

Стандартный обход в ширину с очередью: обрабатываем дерево уровень за уровнем и связываем каждый узел со следующим в очереди того же уровня.

```ts naive
const queue: _Node[] = root ? [root] : [];
while (queue.length) {
  const size = queue.length;
  for (let i = 0; i < size; i++) {
    const node = queue.shift()!;
    node.next = i < size - 1 ? queue[0] : null;
    if (node.left) queue.push(node.left);
    if (node.right) queue.push(node.right);
  }
}
```

Это `O(n)` времени, но очередь хранит целый уровень — до `n/2` узлов, то есть `O(n)` памяти. Где лишнее? Очередь нужна, чтобы «помнить порядок узлов уровня». Но как только уровень связан через `next`, этот порядок **уже записан в самом дереве** — очередь его дублирует.

## Ключевое наблюдение

Связанный через `next` уровень — это **готовый односвязный список**. Идя по нему от самого левого узла, мы видим всех родителей следующего уровня слева направо, а значит, и всех детей в правильном порядке. Остаётся по пути **дописывать детей в хвост нового списка** — так следующий уровень оказывается связанным, и по нему можно повторить то же самое.

Чтобы не обрабатывать особо «первого найденного ребёнка» (он может оказаться у любого родителя или не найтись вовсе), используем фиктивную голову списка `dummy`.

## Техники

### Обход дерева по уровням (BFS)

**Что это.** BFS обрабатывает дерево слоями: корень, затем все узлы глубины 1, затем глубины 2 и т.д. Обычно реализуется очередью.

**Когда применять.** Когда ответ связан с уровнями: соседи по уровню, вид справа, средние по уровням, минимальная глубина.

**Как применяется здесь.** Обход по уровням сохраняется, но роль очереди играет уже построенный список `next` текущего уровня. Подробнее — во вкладке «Теория» (BFS по дереву).

### Построение связного списка с фиктивной головой (dummy)

**Что это.** Заводим служебный узел `dummy` и указатель `tail = dummy`. Каждый новый элемент добавляется одинаково: `tail.next = x; tail = x`. В конце настоящая голова — `dummy.next` (или `null`, если ничего не добавили).

**Когда применять.** Везде, где список собирается по одному элементу и «первый» элемент неизвестен заранее: слияние списков, разбиение списка, фильтрация.

**Как применяется здесь.** `dummy` — голова списка следующего уровня, `tail` — его последний узел. После прохода уровня `dummy.next` — самый левый узел следующего уровня.

### Использование уже построенной структуры вместо вспомогательной

Общий приём для `O(1)`-памяти: результат предыдущего шага (указатели `next` уровня `k`) служит «навигацией» для следующего шага (уровня `k + 1`).

## Разбор кода

```ts
/**
 * Definition for _Node.
 * class _Node {
 *     val: number
 *     left: _Node | null
 *     right: _Node | null
 *     next: _Node | null
 *     constructor(val?: number, left?: _Node, right?: _Node, next?: _Node) { ... }
 * }
 */
```

Определение узла: у `_Node` четыре поля, `next` изначально `null`.

```ts
function connect(root: _Node | null): _Node | null {
  // levelStart — самый левый узел текущего уровня (он уже связан через next)
  let levelStart = root;
```

Уровень из одного корня тривиально «связан»: у корня `next = null`. Это стартовая точка.

```ts
  while (levelStart !== null) {
    // Фиктивная голова списка следующего уровня
    const dummy = new _Node(0);
    // tail — последний узел, уже подцепленный в список следующего уровня
    let tail = dummy;
```

Внешний цикл — по уровням. Для каждого уровня заводим новый пустой список: `dummy` и `tail`, указывающий на него. Значение `0` не важно — `dummy` никогда не попадает в дерево.

```ts
    // Идём по текущему уровню как по связному списку через next
    for (let node: _Node | null = levelStart; node !== null; node = node.next) {
```

Внутренний цикл — обычный проход по связному списку: от `levelStart` по `next` до `null`. Именно здесь работают указатели, проставленные на предыдущей итерации внешнего цикла.

```ts
      // Дописываем детей в хвост списка следующего уровня
      if (node.left !== null) {
        tail.next = node.left;
        tail = node.left;
      }
      if (node.right !== null) {
        tail.next = node.right;
        tail = node.right;
      }
    }
```

Сначала левый ребёнок, затем правый — это порядок слева направо внутри родителя, а родители перебираются слева направо — значит, дети попадают в список в правильном порядке. `tail.next = child` связывает предыдущего ребёнка уровня (возможно, от другого родителя) с текущим; `tail = child` сдвигает хвост. Отсутствующих детей просто пропускаем — «дыры» в дереве не мешают.

```ts
    // Следующий уровень полностью связан — переходим на него
    levelStart = dummy.next;
  }
```

`dummy.next` — первый добавленный ребёнок, то есть самый левый узел следующего уровня. Если детей не нашлось, это `null`, и внешний цикл завершается. У последнего добавленного ребёнка `next` остаётся `null` — так и нужно.

```ts
  return root;
}
```

Возвращаем исходный корень: дерево изменено на месте.

## Трассировка

`root = [1, 2, 3, 4, 5, null, 7]`.

1. `levelStart = 1`. Новый `dummy`, `tail = dummy`.
   - `node = 1`: `left = 2` → `dummy.next = 2`, `tail = 2`; `right = 3` → `2.next = 3`, `tail = 3`.
   - `node = 1.next = null` → конец уровня. `levelStart = dummy.next = 2`.
2. `levelStart = 2`. Новый `dummy`, `tail = dummy`.
   - `node = 2`: `left = 4` → `dummy.next = 4`, `tail = 4`; `right = 5` → `4.next = 5`, `tail = 5`.
   - `node = 2.next = 3`: `left = null` — пропуск; `right = 7` → `5.next = 7`, `tail = 7`.
   - `node = 3.next = null` → конец. `levelStart = 4`.
3. `levelStart = 4`. Узлы `4`, `5`, `7` детей не имеют → `dummy.next` остаётся `null`.
   `levelStart = null` → выход.

Итог: `2 -> 3`, `4 -> 5 -> 7`, у `1`, `3`, `7` — `null`. Связь `5 -> 7` (разные родители, дыра между ними) получилась сама собой благодаря `tail`.

## Почему это работает

Инвариант внешнего цикла: **в начале итерации все узлы уровня, начинающегося с `levelStart`, связаны через `next` слева направо, и последний указывает на `null`**.

- Для уровня корня инвариант верен изначально.
- Пусть он верен для уровня `k`. Проходя список уровня `k`, мы видим родителей слева направо; у каждого сначала `left`, потом `right`. Узлы уровня `k + 1` в порядке слева направо — это ровно такая последовательность детей. Каждый ребёнок дописывается в хвост, значит, `next` соседних детей связаны, а у последнего `next` остаётся `null` (изначальное значение). Значит, инвариант верен для уровня `k + 1`, начинающегося с `dummy.next`.

Цикл заканчивается, когда у очередного уровня нет детей, то есть на последнем уровне.

## Пограничные случаи

- **Пустое дерево**: `levelStart = null`, цикл не выполняется, возвращаем `null`.
- **Один узел**: на первом уровне детей нет, `dummy.next = null`, выход.
- **Дыры между соседями** (`5 -> 7` в примере): `tail` «перепрыгивает» через родителей без детей.
- **Родитель без детей в начале уровня**: `dummy` позволяет не искать специально первого ребёнка.
- **Дерево-«палка»**: на каждом уровне один узел, список из одного элемента.

## Сложность

- **Время `O(n)`**: каждый узел один раз проходит внутренний цикл как родитель и один раз дописывается в список как ребёнок.
- **Память `O(1)`**: только `levelStart`, `node`, `tail` и один `dummy` на уровень (предыдущий сразу становится мусором). Ни очереди, ни рекурсии.

## Типичные ошибки

1. **Решение из версии I** (`node.left.next = node.right; node.right.next = node.next.left`) → ломается, когда у узла нет детей или у соседа нет левого ребёнка.
2. **Без `dummy`** → нужна отдельная переменная «первый ребёнок уровня» и ветка `if (prev === null)`; легко забыть обновить начало уровня.
3. **Переход на `levelStart.left`** вместо `dummy.next` → если у самого левого узла нет левого ребёнка, уровень потеряется.
4. **Забыть сдвинуть `tail`** → все дети будут перезаписывать `next` одного и того же узла.
5. **Очередь ради «простоты»** → верно, но не выполняет требование `O(1)` памяти.

## Как узнать такую задачу

- Нужно что-то сделать **для соседей на одном уровне** дерева → BFS по уровням.
- Требование **`O(1)` памяти** при обходе по уровням → ищите, нельзя ли использовать уже построенные указатели вместо очереди.
- Собирается список из элементов, которые «появляются» непредсказуемо → фиктивная голова `dummy` + `tail`.
- Родственные задачи: Populating Next Right Pointers in Each Node (версия I), Binary Tree Right Side View, Binary Tree Level Order Traversal, Merge Two Sorted Lists (приём `dummy`).
