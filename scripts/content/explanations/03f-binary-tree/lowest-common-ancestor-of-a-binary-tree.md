## Задача простыми словами

Дано двоичное дерево (не BST) и два его узла `p` и `q`. Нужно найти их **наименьшего общего предка** (LCA) — самый нижний узел, у которого в поддереве есть и `p`, и `q`. Важная оговорка: узел считается потомком **самого себя**, поэтому если `q` лежит под `p`, ответ — `p`. Оба узла гарантированно есть в дереве.

Пример: `root = [3, 5, 1, 6, 2, 0, 8, null, null, 7, 4]`.

```
          3
        /   \
       5     1
      / \   / \
     6   2 0   8
        / \
       7   4
```

- `p = 5`, `q = 1` → ответ `3` (узлы в разных ветках корня).
- `p = 5`, `q = 4` → ответ `5` (`4` лежит под `5`).
- `p = 6`, `q = 4` → ответ `5`.

## Наивный подход

Найти путь от корня до `p` и путь от корня до `q`, а затем идти по ним одновременно, пока они совпадают; последний общий узел — LCA:

```ts naive
const pathTo = (node: TreeNode | null, target: TreeNode, path: TreeNode[]): boolean => {
  if (!node) return false;
  path.push(node);
  if (node === target) return true;
  if (pathTo(node.left, target, path) || pathTo(node.right, target, path)) return true;
  path.pop();
  return false;
};
const a: TreeNode[] = [], b: TreeNode[] = [];
pathTo(root, p, a);
pathTo(root, q, b);
let i = 0;
while (i < a.length && i < b.length && a[i] === b[i]) i++;
return a[i - 1];
```

Это `O(n)` времени, но дерево обходится **дважды**, и нужно хранить два пути — до `O(n)` памяти на вырожденном дереве. Лишняя работа: два обхода ищут почти одно и то же, а пути целиком нам не нужны — нужна только **точка, где они расходятся**.

## Ключевое наблюдение

Один post-order обход может «поднимать» найденные узлы снизу вверх. Пусть функция для поддерева возвращает:

- `null` — если в поддереве нет ни `p`, ни `q`;
- `p` или `q` — если найден только один из них (или поддерево начинается с одного из них);
- LCA — если в поддереве нашлись оба.

Тогда LCA — это **первый узел снизу, у которого результаты слева и справа оба непустые**: здесь `p` и `q` «встретились». Если же узел сам равен `p` или `q`, его можно сразу вернуть: второй узел либо ниже (и тогда ответ — этот узел), либо в другой ветке (и тогда встреча случится выше).

## Техники

### Post-order DFS с «подъёмом» результата

**Что это.** Обход в глубину, при котором узел сначала получает ответы от детей, а потом решает, что вернуть родителю. Информация движется **снизу вверх**.

**Когда применять.** Когда ответ для узла выражается через ответы для поддеревьев: высоты, суммы, «есть ли в поддереве X», поиск точки встречи двух объектов.

**Типичный шаблон:**

```ts naive
const f = (node) => {
  if (база(node)) return что-то;
  const l = f(node.left), r = f(node.right);
  return объединить(node, l, r);
};
```

**Как применяется здесь.** «Объединить» — правило: оба непустые → `node`; иначе — тот, что непустой. Подробнее — во вкладке «Теория» (DFS по дереву).

### Раннее завершение (отсечение)

Если `root === p` или `root === q`, глубже не спускаемся: что бы там ни было, ответ для этого поддерева — `root`. Это и корректно (узел — потомок самого себя), и экономит обход.

### Опора на гарантию из условия

Функция не проверяет, что найдены **оба** узла: если в дереве окажется только `p`, она вернёт `p`, будто это LCA. Это допустимо, потому что по условию `p` и `q` всегда есть в дереве.

## Разбор кода

```ts
function lowestCommonAncestor(
  root: TreeNode | null,
  p: TreeNode | null,
  q: TreeNode | null,
): TreeNode | null {
```

Сигнатура LeetCode: `p` и `q` — ссылки на узлы дерева, а не значения. Сравнивать будем ссылки (`===`).

```ts
  // Пустое поддерево ничего не содержит.
  // Если корень — p или q, он и есть ответ для этого поддерева:
  // либо второй узел ниже (тогда LCA — root), либо он в другой ветке выше
  if (root === null || root === p || root === q) {
    return root;
  }
```

Две базы сразу. Пустое поддерево возвращает `null` («никого не нашли»). Узел, совпавший с `p` или `q`, возвращает себя — и не спускается дальше. Если второй узел лежит ниже, ответ и так `root`; если он в другой части дерева, точку встречи найдёт кто-то из предков.

```ts
  // Ищем p и q в левом и правом поддеревьях
  const left = lowestCommonAncestor(root.left, p, q);
  const right = lowestCommonAncestor(root.right, p, q);
```

Post-order: сначала результаты детей. Каждый — `null`, один из узлов `p`/`q`, или уже найденный LCA.

```ts
  // p и q нашлись по разные стороны — root и есть самый нижний общий предок
  if (left !== null && right !== null) {
    return root;
  }
```

Если и слева, и справа что-то нашлось, то `p` в одной ветке, а `q` — в другой. Ни один потомок `root` не может быть их общим предком (он лежит только в одной ветке), значит, `root` — самый нижний.

```ts
  // Иначе оба узла (или единственный найденный) в одной ветке — пробрасываем её результат наверх
  return left !== null ? left : right;
}
```

Если нашлось только с одной стороны, пробрасываем этот результат наверх: это либо один из узлов (второй ищется выше), либо уже найденный LCA (тогда он доберётся до корня без изменений). Если обе стороны пусты, вернётся `right`, то есть `null`.

## Трассировка

Дерево из примера, `p = 6`, `q = 4`:

1. `lca(3)`: не `p`/`q` → спускаемся.
2. `lca(5)`: не `p`/`q` → спускаемся.
3. `lca(6)`: это `p` → возврат `6`.
4. `lca(2)`: не `p`/`q` → `lca(7)`: дети `null` → `left = right = null` → возврат `null`; `lca(4)`: это `q` → `4`. Итого `left = null`, `right = 4` → возврат `4`.
5. В `lca(5)`: `left = 6`, `right = 4` — оба непустые → возврат `5`.
6. `lca(1)`: `lca(0)` → `null`, `lca(8)` → `null` → возврат `null`.
7. В `lca(3)`: `left = 5`, `right = null` → пробрасываем `5`.

Ответ `5`.

Пример, где ответ — сам узел, `p = 5`, `q = 4`:

1. `lca(3)` → спускаемся.
2. `lca(5)`: это `p` → сразу `5`. Узел `4` ниже даже не просматривается.
3. `lca(1)` → `null` (как выше).
4. В `lca(3)`: `left = 5`, `right = null` → ответ `5`.

## Почему это работает

Утверждение: если в поддереве `root` есть оба узла, функция возвращает их LCA; если только один — возвращает его (или его предка, совпадающего с другим узлом); если ни одного — `null`.

- **Ни одного**: база `null` и правило «пробросить непустое» дают `null`.
- **`root` — один из узлов**: возвращается `root`. Если второй под ним — `root` и есть LCA (потомок самого себя). Если второго в поддереве нет — возвращаем найденный узел, как и требуется.
- **`p` и `q` в разных поддеревьях `root`**: по индукции левый вызов вернёт непустое, правый — тоже, и `root` возвращается как LCA. Ниже общего предка нет: любой потомок лежит только в одной ветке.
- **Оба в одном поддереве**: по индукции оттуда пришёл их LCA, другая сторона — `null`, LCA пробрасывается наверх.

Для корня всего дерева оба узла присутствуют (гарантия условия), значит, ответ — их LCA.

## Пограничные случаи

- **Один узел — предок другого** (`p = 5`, `q = 4`): ответ — предок, благодаря ранней базе `root === p`.
- **Узлы в разных ветках корня**: ответ — корень.
- **`p` или `q` — сам корень**: ответ сразу на первом вызове.
- **Глубокое вырожденное дерево** (до `10⁵` узлов в линию): глубина рекурсии `n`; в ограниченном стеке может понадобиться итеративный вариант (родители + множество предков).
- **Одинаковые значения не мешают** — сравниваются ссылки на узлы.

## Сложность

- **Время `O(n)`**: каждый узел посещается не более одного раза; поддеревья под найденным `p`/`q` пропускаются.
- **Память `O(h)`**: стек рекурсии по высоте дерева — `O(log n)` для сбалансированного, `O(n)` для вырожденного. Дополнительных структур нет.

## Типичные ошибки

1. **Сравнивать значения вместо ссылок** при задаче, где узлы заданы ссылками → в общем случае риск совпадений; здесь значения различны, но `===` по узлам — надёжнее.
2. **Продолжать спуск после `root === p`** → лишняя работа; а если при этом вернуть результат снизу вместо `root`, ответ станет неверным для случая «один узел — предок другого».
3. **Возвращать `true/false` вместо узлов** → теряется информация, где произошла встреча; приходится заводить глобальную переменную.
4. **Использовать решение для BST** (сравнение значений с `root.val`) → в обычном дереве нет порядка, спуск по значению ничего не гарантирует.
5. **Применять без гарантии присутствия обоих узлов** → функция вернёт единственный найденный узел как «LCA»; в таком варианте задачи нужен подсчёт найденных.

## Как узнать такую задачу

- «Общий предок», «где встречаются два узла», «расстояние между двумя узлами» в **двоичном дереве без порядка** → post-order DFS с подъёмом результата.
- Нужно найти **самый нижний** узел с некоторым свойством поддерева → проверяем свойство на возврате рекурсии, первый подходящий снизу — ответ.
- Родственные задачи: Lowest Common Ancestor of a Binary Search Tree (проще — по значениям), LCA of a Binary Tree II/III (без гарантии присутствия, с указателем `parent`), Lowest Common Ancestor of Deepest Leaves, Step-By-Step Directions From a Binary Tree Node to Another.
