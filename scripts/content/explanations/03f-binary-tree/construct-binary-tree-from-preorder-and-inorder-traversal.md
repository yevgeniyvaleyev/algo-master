## Задача простыми словами

Даны два обхода одного и того же двоичного дерева: **прямой** `preorder` (узел → левое → правое) и **центрированный** `inorder` (левое → узел → правое). Все значения различны. Нужно восстановить само дерево и вернуть его корень.

Пример: `preorder = [3, 9, 20, 15, 7]`, `inorder = [9, 3, 15, 20, 7]`. Ответ — дерево:

```
    3
   / \
  9   20
     /  \
    15   7
```

## Наивный подход

Рекурсия «в лоб»: первый элемент `preorder` — корень; находим его в `inorder` линейным поиском, **нарезаем** оба массива на левую и правую части через `slice` и рекурсивно строим поддеревья:

```ts naive
function build(pre: number[], ino: number[]): TreeNode | null {
  if (pre.length === 0) return null;
  const root = new TreeNode(pre[0]);
  const mid = ino.indexOf(pre[0]);
  root.left = build(pre.slice(1, mid + 1), ino.slice(0, mid));
  root.right = build(pre.slice(mid + 1), ino.slice(mid + 1));
  return root;
}
```

Идея верная, но лишней работы много. На каждом уровне рекурсии `indexOf` сканирует отрезок за `O(k)`, а `slice` **копирует** элементы — ещё `O(k)`. На вырожденном дереве («палка» из 3000 узлов) получаем `O(n²)` времени и `O(n²)` суммарно выделенной памяти. Мы много раз ищем одни и те же значения и переписываем одни и те же числа в новые массивы.

## Ключевое наблюдение

Два факта убирают обе траты:

1. Значения **различны**, поэтому позицию любого значения в `inorder` можно один раз записать в `Map` и дальше получать за `O(1)`.
2. Если строить дерево в порядке **«корень, затем левое, затем правое»**, то корни поддеревьев будут нужны ровно в том порядке, в котором они лежат в `preorder`. Значит, по `preorder` достаточно идти **одним общим указателем** `pre`, а для `inorder` передавать только границы отрезка `[lo, hi]` — без копий.

## Техники

### Разделяй и властвуй

**Что это.** Задача делится на независимые подзадачи меньшего размера, они решаются рекурсивно, а ответы объединяются. Типичный шаблон — рекурсия на отрезке `[lo, hi]` с базой «пустой отрезок».

**Когда применять.** Когда структура ответа сама рекурсивна: дерево — это корень плюс два дерева поменьше. Если можно определить, где проходит граница между частями, задача распадается.

**Как применяется здесь.** Корень делит отрезок `inorder` на левую часть (левое поддерево) и правую (правое поддерево). Каждая часть — та же задача меньшего размера. «Объединение» — просто присвоить `root.left` и `root.right`. Подробнее — во вкладке «Теория» (разделяй и властвуй).

### Свойства обходов дерева

```
preorder: [ корень | ...левое... | ...правое... ]
inorder:  [ ...левое... | корень | ...правое... ]
```

`preorder` говорит, **кто** корень, а `inorder` — **сколько и какие** узлы слева и справа от него. Вместе они задают дерево однозначно (при различных значениях).

### Индекс через хеш-таблицу

Предварительный проход строит `Map` «значение → индекс». Классический обмен `O(n)` памяти на `O(1)` поиск вместо `O(n)`.

### Общий указатель вместо нарезки

Вместо передачи подмассивов передаём границы, а «поток» корней читаем глобальным счётчиком. Это работает только потому, что порядок рекурсивных вызовов совпадает с порядком обхода.

## Разбор кода

```ts
function buildTree(preorder: number[], inorder: number[]): TreeNode | null {
  // Значение -> его индекс в inorder, чтобы находить корень за O(1)
  const inIndex = new Map<number, number>();
  inorder.forEach((v, i) => inIndex.set(v, i));
```

Один проход по `inorder` — и для каждого значения известна его позиция. Это корректно, потому что значения не повторяются: ключи `Map` уникальны.

```ts
  // Указатель на следующий корень в preorder: корни идут в порядке «корень, левое, правое»
  let pre = 0;
```

`pre` — индекс следующего неиспользованного элемента `preorder`. Он общий для всех вызовов `build` (замыкание), поэтому продвигается сквозь всю рекурсию.

```ts
  // Строит поддерево из элементов inorder[lo..hi]
  const build = (lo: number, hi: number): TreeNode | null => {
    if (lo > hi) return null; // пустой отрезок — пустое поддерево
```

`build(lo, hi)` строит поддерево, узлы которого — ровно `inorder[lo..hi]`. Если отрезок пуст, поддерева нет — возвращаем `null`. Важно: в этом случае `pre` **не** сдвигается, иначе мы «съели» бы корень чужого поддерева.

```ts
    // Очередной элемент preorder — корень текущего поддерева
    const rootVal = preorder[pre++];
    const root = new TreeNode(rootVal);
```

Берём следующий элемент `preorder` и сразу сдвигаем указатель. Почему это именно корень текущего отрезка? Потому что все узлы, обработанные до нас, уже забрали свои элементы, а preorder начинает любое поддерево с его корня.

```ts
    // Всё левее корня в inorder — левое поддерево, правее — правое
    const mid = inIndex.get(rootVal)!;
```

Позиция корня в `inorder` за `O(1)`. Отрезок делится на `[lo, mid - 1]` (левое) и `[mid + 1, hi]` (правое). `!` говорит TypeScript, что значение точно есть в `Map`.

```ts
    // Сначала левое: в preorder его узлы идут сразу после корня
    root.left = build(lo, mid - 1);
    root.right = build(mid + 1, hi);
    return root;
  };
```

Порядок вызовов критичен: сначала левое. После корня в `preorder` идут все узлы левого поддерева, затем все узлы правого. Рекурсивный вызов для левого «съест» ровно `mid - lo` элементов, и к началу правого вызова `pre` уже будет указывать на корень правого поддерева.

```ts
  return build(0, inorder.length - 1);
}
```

Запускаем на всём массиве. Возвращаемый узел — корень всего дерева.

## Трассировка

`preorder = [3, 9, 20, 15, 7]`, `inorder = [9, 3, 15, 20, 7]`.
`inIndex = {9: 0, 3: 1, 15: 2, 20: 3, 7: 4}`.

1. `build(0, 4)`: `rootVal = preorder[0] = 3`, `pre = 1`, `mid = 1`.
2. → левое `build(0, 0)`: `rootVal = preorder[1] = 9`, `pre = 2`, `mid = 0`.
   - `build(0, -1)` → `null`, `build(1, 0)` → `null`. Узел `9` — лист.
3. → правое `build(2, 4)`: `rootVal = preorder[2] = 20`, `pre = 3`, `mid = 3`.
4. → левое `build(2, 2)`: `rootVal = preorder[3] = 15`, `pre = 4`, `mid = 2`; оба ребёнка `null`.
5. → правое `build(4, 4)`: `rootVal = preorder[4] = 7`, `pre = 5`, `mid = 4`; оба ребёнка `null`.
6. Узел `20` получает `left = 15`, `right = 7`; узел `3` — `left = 9`, `right = 20`.

Указатель `pre` прошёл весь массив ровно один раз, а каждый `build` с непустым отрезком создал один узел. Результат совпадает с рисунком выше.

## Почему это работает

Инвариант: **в момент вызова `build(lo, hi)` с непустым отрезком `preorder[pre]` — корень поддерева, состоящего из `inorder[lo..hi]`**, и это поддерево занимает в `preorder` ровно `hi - lo + 1` элементов начиная с `pre`.

- Для `build(0, n - 1)` это верно: `pre = 0`, первый элемент preorder — корень дерева.
- Пусть верно для `build(lo, hi)`. Берём корень, `pre` сдвигается на 1. В preorder следом идут `mid - lo` узлов левого поддерева — это ровно узлы `inorder[lo..mid-1]`, значит, вызов `build(lo, mid - 1)` получает верный `pre`. Он по индукции потребляет ровно свои элементы, и после него `pre` указывает на корень правого поддерева — инвариант верен и для `build(mid + 1, hi)`.

Однозначность разбиения обеспечивает различие значений: корень встречается в `inorder` ровно один раз.

## Пограничные случаи

- **Один узел** (`[-1]`, `[-1]`): `build(0, 0)` создаёт корень, оба ребёнка — пустые отрезки.
- **Только левые дети** (`preorder = [3, 2, 1]`, `inorder = [1, 2, 3]`): каждый раз `mid = hi`, правый отрезок пуст. Глубина рекурсии — `n`.
- **Только правые дети**: каждый раз `mid = lo`, левый отрезок пуст.
- **Отрицательные значения**: ключи `Map` — любые числа, проблем нет.
- **Пустой отрезок не трогает `pre`** — это и обеспечивает синхронизацию.

## Сложность

- **Время `O(n)`**: построение `Map` — `O(n)`; каждый непустой вызов `build` создаёт один узел за `O(1)` (поиск в `Map` — `O(1)`), пустых вызовов не больше `n + 1`.
- **Память `O(n)`**: `Map` на `n` записей плюс стек рекурсии `O(h)`, где `h` — высота дерева (до `n` для «палки»). Сами узлы дерева — это ответ, их обычно не считают.

## Типичные ошибки

1. **Строить сначала правое поддерево** → `pre` указывает на корень левого, дерево получается неверным.
2. **Линейный `indexOf` в `inorder`** на каждом шаге → `O(n²)` на вырожденном дереве.
3. **`slice` для подмассивов** → лишние копии и `O(n²)` памяти в худшем случае.
4. **Сдвигать `pre` до проверки `lo > hi`** → пустое поддерево «съедает» чужой корень.
5. **Перепутать границы**: левое — `[lo, mid - 1]`, правое — `[mid + 1, hi]`; корень `mid` не входит ни в одно.

## Как узнать такую задачу

- Даны **два обхода** дерева (pre + in, post + in) и нужно восстановить дерево → корень из одного обхода делит другой.
- Нужно построить дерево из массива так, что некоторый элемент определяет «левую» и «правую» части (Convert Sorted Array to BST, Maximum Binary Tree) — та же схема разделяй и властвуй на отрезке.
- Родственные задачи: Construct Binary Tree from Inorder and Postorder Traversal (тот же приём, но `postorder` читается с конца и сначала строится правое), Construct BST from Preorder.
