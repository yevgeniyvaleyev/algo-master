## Project

AlgoMaster is a personal Android-only app (Expo SDK 57, Expo Router, TypeScript) for **refreshing** LeetCode "Top Interview 150" algorithms. The user reads the material and marks an algorithm as learned; there is no code input. A daily quota (`dailyGoal`) is planned to gate entertainment apps: each learned algorithm unlocks `minutesPerAlgo` minutes, and meeting the goal unblocks everything. There is no auth or backend. The UI language is Russian. The full roadmap is in `docs/ROADMAP.md` (phase 4 is the scraper and real content, phase 5 is native app blocking).

## Commands

```bash
npm test                      # jest (jest-expo preset); tests live in src/**/__tests__/*-test.ts
npx jest src/logic/__tests__/progress-test.ts -t streak   # single file / test name
npm run typecheck             # tsc --noEmit
npm run lint                  # expo lint
npm run format                # prettier (singleQuote, printWidth 120)
npx expo export --platform android   # quick JS bundle check without a native build
npm run android               # expo run:android — native dev build (needs JDK 17+, see below)

# content pipeline (phase 4)
npm run scrape                # LeetCode GraphQL -> scripts/out/{plan.json,problems/*.json} (resumable, --force to refetch)
npm run content:sync          # scraped data -> data/algos/*.json, data/manifest.json, data/content-index.ts
npm run content:validate      # zod schema + Russian text checks + tsc on every solutionTs
node scripts/content/apply.mjs scripts/content/generated/<batch>.mjs  # run a batch's tests, merge passing content into data/
```

The scraper uses Playwright's `request` API against `https://leetcode.com/graphql`, because the HTML pages are behind a Cloudflare bot check. Playwright 1.64 can't download browsers on macOS 12, so if a browser is ever needed, use `channel: 'chrome'`.

The system default Java is 9, which is too old. Native builds need `JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"`. `android/` is generated by `expo prebuild` and gitignored, so configure native behavior through `app.json` and config plugins.

## Architecture

- **Two data sources.** Read-only algorithm content is bundled JSON (`data/algos/<slug>.json`, `data/theory/<key>.json`, typed by `src/content/types.ts`). Metro needs static `require`s, so it is loaded through the lazy loader map in `data/content-index.ts`. User-mutable state lives in SQLite (`src/db/client.ts` holds the schema and migrations via `PRAGMA user_version`; `src/db/repo.ts` holds all queries).
- **Seeding.** `data/manifest.json` (topics + algos + `seedVersion`) is upserted into SQLite on startup by `runSeed`. The pure diff is `planSeed` in `src/logic/seed.ts`. Bump `seedVersion` whenever the manifest changes. Re-seeding never overrides the user's topic renames, algorithm moves or progress. Seeded topics the user deleted are remembered in kv `deletedSeedTopics` and not recreated. The built-in `__uncategorized__` ("Без темы") topic receives algorithms from deleted topics and cannot be deleted.
- **Progress semantics.** `progress` holds the current learned mark. `learn_log` is the history that drives the daily quota, streak and charts (`COUNT(DISTINCT slug)` per local `day`). Unmarking also deletes *today's* log rows for that slug, so the quota can't be gamed. Auto-unmark (`autoUnmark` + `expireDays`) deletes old `progress` rows only, never the log. It runs on startup and whenever the app returns to the foreground (`runExpiration`).
- **Reactivity.** There is no query library. Mutations go through `src/logic/actions.ts`, which bumps `useDataVersion`. `useQuery(fn, key)` (`src/hooks/use-query.ts`) re-runs on screen focus and on every bump. Call mutations from `actions`, not directly from `repo`, or screens won't refresh.
- **Settings** are a zustand store (`src/store/settings.ts`) persisted as one JSON blob in the `kv` table. The theme is applied through `Appearance.setColorScheme`, so `useColorScheme()` / `useColors()` (`src/theme`) reflect both the override and automatic system switching.
- **Navigation.** expo-router ships its own fork of react-navigation, so don't install `@react-navigation/*` packages. Use `expo-router/js-tabs` (bottom tabs in `src/app/(tabs)`) and `expo-router/js-top-tabs` (the 5 content tabs in `src/app/algo/[slug]/`; tab screens read `slug` via `useAlgoContent`).
- **Algorithm screen tabs** get the slug from `AlgoSlugContext` (`useAlgoSlug` / `useAlgoContent`), provided by `algo/[slug]/_layout.tsx`, because top-tab screens don't reliably receive the parent's `[slug]` param.
- **Learning order.** Suggestions (`getNextUnlearned`) follow `learningOrder` (`src/logic/learning-order.ts`): topics take turns round-robin, each giving its easiest remaining unlearned algorithm (easy → medium → hard), starting with the topic after the one most recently learned (latest `learn_log` row).
- **Marking from the list** only happens in bulk mode (the «Отметить» chip, then Save/Cancel via `setLearnedMany`), so a stray tap can't change stats.
- **Reminders.** Local notifications (`expo-notifications`, works in Expo Go). `planReminders` (`src/logic/reminders.ts`, pure, tested) produces date triggers every `reminderIntervalHours` between `reminderStartHour` and `reminderEndHour`: today's remaining slots only while the goal isn't met, plus 7 days ahead. `syncReminders` (`src/notifications/reminders.ts`) cancels all and reschedules. It runs on startup, on foreground, after marking (`actions`) and on reminder/goal setting changes (a `useSettings.subscribe` in the root layout); calls are serialized.
- **Code viewer.** `src/components/CodeViewer.tsx` tokenizes with `prism-react-renderer` (vsDark/vsLight themes) into RN `<Text>`. Zoom changes `fontSize` (pinch or +/-) rather than scaling, and is persisted as `codeFontSize`.

- **Custom solutions.** The user can paste their own solution per algorithm (`src/app/solution-editor/[slug].tsx`, table `custom_solutions`, DB v2). On save it is normalized and formatted with `prettier/standalone` + the TypeScript plugin (`src/logic/format-code.ts`), which runs inside the app. If parsing fails, the user may save the code as-is. The Решение tab switches between Моё and Эталон, and the bundled solution is never overwritten.

## Content conventions

Each algorithm JSON has `leetcodeId` (LeetCode problem number, shown as "88. Title"), `conditionMd` (original English from LeetCode; it is overwritten by `content:sync`), `descriptionRuMd` (Russian translation), `solutionTs` (TypeScript with inline **Russian** comments), `ideaRuMd` (solution idea in Russian) and `theory.topicKey`, which points to a shared Russian theory note. The four generated fields are optional, but an algorithm has either all of them or none; tabs without content show a placeholder. Generated content lives in batch modules `scripts/content/generated/*.mjs` (the source of truth; `apply.mjs` documents the contract: per-test `argTypes`/`resultType` for lists/trees, `inPlace`, `sortResult`, plus `cls` for design classes and `prelude`/`harness` for custom `_Node`s or answers with several valid forms). Re-running every batch is a full regression check. `content:sync` preserves generated fields, takes `theory.titleRu` from the theory note, and bumps `seedVersion` only when topics or algorithms change (`contentHash`). `scripts/mock/write-mock.js` produced the single mock algorithm (`merge-sorted-array`).
